# 知識庫 INDEX

AGENTS.md §1 進場握手第 2 步要求讀本檔——**前人踩過的坑，不要重踩**。

## 檔案

| 檔 | 內容 | 誰可以寫 |
|---|---|---|
| [`errors.md`](errors.md) | 踩過的錯誤，每條記「**錯誤 + 根因 + 解法**」 | **任何單元分支皆可寫**（在 `scope_check.py` 的 `COMMON` 白名單內） |
| 本檔 `INDEX.md` | 慣例說明與導覽 | 僅 infra CHG（**不在** `COMMON` 內，單元分支寫了會被 G1 擋） |

> 本檔刻意設計成**不隨每條錯誤更新**：新錯誤一律往 `errors.md` 追加即可，
> 不必回頭改 INDEX。否則單元分支會被 G1 `scope_check` 夾殺（`COMMON` 只放行 `errors.md`）。

## 寫入規則（AGENTS.md §4）

- 錯誤要記「**錯誤 + 根因 + 解法**」三件齊全。只記現象不記根因的條目沒有價值。
- **機密只記位置不記值**（記「憑證在哪個設定鍵」，不記憑證本身）。
- 新條目**追加在 `errors.md` 最前面**（新的在上），附日期與來源 CHG。

- **K-006** CI 釘死 VS 產生器版本 → 隨 runner 映像更新而壞；附一個「恰好符合預期但成因不同」的假線索（`CHG-20260803-08`）
- **K-007** 契約一接上真實後端就抓到 16 個單元踩在不可能成立的路徑上；過度寬容的測試替身會把 bug 養大（`CHG-20260803-10`；**已於 `-11` 對齊**，附 C++ 批次處理的三種「假宣告」陷阱）
- **K-008** PR 內文被 CI 當成指令執行——`${{ }}` 內插進 `run:` 就是命令注入；且那次執行是**綠燈**（`CHG-20260810-04`；**已修**，新增 G8 `workflow_lint` 防復發）
- **K-009** 釘住寫入端編碼只解決一半：讀取端沒釘，例外跑到 reader thread，只留下 `returncode=0` + `stdout=None`（`CHG-20260810-05`；**已修**，[[K-001]]/[[K-004]] 第三代）
- **K-010** CI 產物「上傳成功」不等於「拿得到」——artifact 只能由人在瀏覽器點下載，agent 取用回 403；失敗發生在下游，workflow 仍是綠的（`CHG-20260829-03`；**已修**，改推覆寫式分支）

- **K-012** 貪婪的 `sed 's/.*: *//'` 取到表頭最後一欄 → G5 的「不得自我驗收」從上線起空轉，而失效方向是**放過**、不產生輸出（`CHG-20261111-02`；**已修**，附偽造自我驗收的回歸測試）
