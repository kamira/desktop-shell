## NFR-02 覆核（相對佈局 + 具名 surface）

於型別層面即不提供絕對畫面座標與數字 z-order：

- `Glyph{ codepoint, x, advance, line }`：`x` 為版面盒內相對偏移（已含對齊位移），非螢幕座標。
- `LineBox{ begin, count, x, y, width, baseline, ellipsized }`：`y` = 行索引 × 行高（相對盒頂）、
  `baseline` = `y + ascent`；無任何絕對座標欄位。
- `LayoutResult{ lines, glyphs, size, truncated, surface }`：`surface` 型別為上游具名
  `ds::kernel::SurfaceId`（= `std::string`），非數字 handle / index / z-order。
- 全結構皆無 z-order 數值欄位（型別上即不提供）。

專屬測試 `E4_01_NFR02.PositionsAreRelativeOffsets` / `SurfaceDefaultsEmptyAndSettable` 斷言相對
偏移與具名 surface 綁定。判定：NFR-02 合規。

## 排版正確性覆核

逐項獨立確認實作行為與 CHG 設計一致：

- **詞界換行**（`WrapMode::Word`）：於空白處貪婪斷行；行尾待落地空白於換行時丟棄、不計入行寬；
  過長單詞自成一行溢出（相位 1 不硬斷字），對齊時負偏移夾為 0，不產生負座標。
- **硬換行**：以 `\n` 切段；`\r` 正規化丟棄（CRLF 視為單一斷行）；連續 `\n` 產生 count=0 空行。
- **對齊**：Left（x=0）/ Center（(盒寬-行寬)/2）/ Right（盒寬-行寬）；有界時對齊寬 = 盒寬，
  無界時 = 最寬行寬。
- **省略號**：no-wrap 過寬行依 `max_width - 省略寬` 預算裁切至末端加 `ellipsis_char`（預設 U+2026）；
  `max_lines` 超出裁切並於末行加省略號；未超界不加、不標 `truncated`。
- **行高**：`constraints.line_height > 0` 覆寫，否則取 `FontMetrics::line_height()`；`y`、`size.height`
  隨之變動。
- **UTF-8 解碼**：嚴格；非法起始位元組 / 截斷序列 / 非法續接位元組 / 過長編碼(overlong) / 碼位越界
  (> U+10FFFF) / 代理區(U+D800–DFFF) 一律擲 `std::invalid_argument`，不以 U+FFFD 靜默取代。
- **空字串**：回空結果（0 行、size{0,0}、無 glyph、truncated=false）。
- **無效輸入報錯**：非法 UTF-8、NaN `max_width`、非有限 `line_height`、`FontMetrics` 回非有限 / 負值
  advance / line_height / ascent、`FixedFontMetrics` 建構壞參 → 皆擲 `std::invalid_argument`。

判定：排版正確性符合設計，邊界情形明確。
