## E7-12 兩個已知限制的處理 — pass

`engine/format/writeback.hpp` 檔頭記載兩個限制，實測**兩個都踩到了**，處理如下：

  **一律視為空清單**，實作上有四處：`packages`（`install_store.cpp:250`）、
  `entries`（`:164`）、`requires` / `permissions`（共用 `optional_string_list`，`:95`）。
  自行 dump 確認空登錄序列化為 `format_version: 1.0\npackages:\n`（`packages` 下確實無項目），
  再讀回為空清單且**不拋錯**。釘住的測試：`EmptyRegistryRoundTripsAsEmptyRatherThanFailing`、
  `ManifestOnlyPackageRoundTripsWithEmptyLists`。本驗收另以探針獨立複驗（P5）。
  **關鍵區分已驗**：空登錄（合法）與損毀登錄（拋錯）不會混為一談。
- **map 鍵不支援引號**（鍵為裸 token）：實作**不把套件名當 map 鍵**，而是放在清單項目的
  `name` **值**位置（`install_store.cpp:118`），由 E7-12 自動引號化 / 轉義。

## 測試脆弱性覆核 — pass（附保留意見）

逐一檢查是否有測試依賴 E7-12 序列化輸出的**具體排版**（縮排 / 空白）而非語意。發現 **2 處**，
均為 pass 但附保留意見（不影響本次判定，但建議列為後續技術債）：

1. **`E9_10_Format.DuplicatePackageIdIsRejectedOnBothDirections`（較需留意）**：
   `const std::string two = one + one.substr(one.find("  -\n"));` ——
   依賴 E7-12 清單項目恰好輸出為「兩個空格 + `-` + 換行」。本驗收實測此刻
   `one.find("  -\n")` 回 **30**（找得到），且自寫探針確認該文字拋出的是
   **`E9-10: 已安裝登錄內出現重複的套件識別 'com.example.dup'`** ——
   即**此刻是為了正確的理由而通過**，測的真是重名偵測。
   但若上游日後微調縮排或改為 inline 清單樣式：`find` 回 `npos` →
   `substr(npos)` 會丟 **`std::out_of_range`**，而該行在 `EXPECT_THROW` **之外**，
   會變成莫名的測試中斷（紅得突然但至少是紅）；更差的情況是排版改動讓 `two` 成為
   另一種畸形文字，於是拋出的是**解析錯誤**而非重名錯誤——`EXPECT_THROW(..., std::runtime_error)`
   仍會**通過，但理由錯了**，重名偵測從此失去覆蓋而無人知曉。建議改以語意方式構造重複文件
   （例如直接組兩筆同名紀錄的 `Value` 樹，或以 E7-01 `parse` + E7-12 `set_value` 操作），
   不依賴輸出排版。
2. **`E9_10_Format.SerializedTextIsAValidE7_01DocumentCarryingFormatVersion`（輕微）**：
   `EXPECT_EQ(text.rfind("format_version: 1.0", 0), 0u)` 依賴首行的具體字面。
   嚴重度低：其**上一行**已有語意等價的
   `EXPECT_EQ(parsed.document().format_version, kInstallRegistryFormat)`，
   故若 E7-12 改了首行寫法，紅的會是這一行而語意檢查仍綠，失敗原因可正確歸因，不會誤導。

另有一處極輕微的一致性瑕疵（非脆弱性，僅記錄）：
`RecordIsWrittenThroughToTheBackendImmediately` 與 `ReloadPicksUpExternalBackendChanges`
以字面 `"installed"` 指涉 slot，而非使用公開常數 `kDefaultInstallSlot`。
