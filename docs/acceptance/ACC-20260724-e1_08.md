## 拖曳狀態機（begin / drag_to / end / cancel）— pass

覆核 `draggable_surface.cpp` 狀態機語意，與測試逐項對應：

- **begin_drag**：空 id / 未註冊（無記憶位置）/ 後端 `!has_surface` → `Invalid`；已在拖曳 →
  `AlreadyDragging`；成功記 `start = pending = 目前 committed`。
- **drag_to**：未拖曳 → `NotDragging`；無效 `AnchorSpec`（越界 anchor / 非有限 offset）→
  `Invalid` 且**不更新 pending**（不靜默）；可多次呼叫只更新 pending。
- **end_drag**：未拖曳 → `NotDragging`；成功把 `pending` 提交為 committed（「放開才記住」）並移除
  拖曳狀態。
- **cancel_drag**：未拖曳 → `NotDragging`；成功放棄 pending、committed 不變（等同還原到拖曳前）。
- **pending / committed 分離**：拖曳中 `remembered_position` 仍回上次提交、`live_position` 回
  pending；`set_position` 於拖曳中被拒（`Invalid`，避免與 pending 競態）；`forget` 同清 committed
  與進行中拖曳。
- **後端 has_surface 閘控**：`set_position` 與 `begin_drag` 皆以 `backend_.has_surface(id)` 閘控，
  只登錄 / 拖曳真實存在的 surface；測試 `InvalidDrag.BeginAfterBackendSurfaceGone` 實證後端銷毀
  surface 後 `begin_drag` 回 `Invalid`。
- **無效拖曳結構化回報**：`DragStatus{Ok, Invalid, NotDragging, AlreadyDragging}` 精確回報，不一律
  Invalid、不靜默、不崩潰（測試 `InvalidDrag.StructuredStatusesNotSilent` 全數覆蓋）。

## E7-12 持久化 round-trip 覆核 — pass

- **「存」**：`serialize_positions()` 以 E7-12 `set_value` 搭配**顯式 Path 段**
  （`PathSegment::of_key(r.id)`，非字串路徑）逐欄寫入設定樹，再以 `serialize(root, kSupportedFormat)`
  落回 E7-01 文字（首行 `format_version`）。顯式鍵段使含 `.` 的具名 SurfaceId 恆為**單一鍵段**、
  不被字串路徑的 `.` 誤拆。
- **「取」**：`load_positions()` 以 E7-01 `parse` 讀回，逐條驗證（id 非空、entry 為 map、
  anchor 為 string 且名有效、dx/dy 為 number、offset 有限）後**全有或全無**套用；任一條目不合即整批
  放棄、不留半套狀態、不靜默（回 `Invalid`）。
- **round-trip 不變式**：`serialize_positions()` 輸出即 `load_positions()` 能再讀回的合法輸入。
  測試 `Persistence.SerializeThenLoadRestoresPositions` / `DragThenPersistCapturesDraggedPosition`
  在全新服務實例上還原、anchor 與正規化 offset 逐值相符（模擬「下次啟動還原」）；
  `EmptySerializeRoundTrips` 確認空集合 round-trip 為零條目 Ok；
  `LoadRejectsInvalidAllOrNothing` 確認無法解析 / anchor 名無效 / 缺欄位 / 型別錯四種壞輸入
