## 3. 平台中立 / NFR-02 / NFR-03 覆核（獨立）

### 平台中立
- 對 `tests/contract/` 全目錄掃描 `#ifdef` / `_WIN32` / `__APPLE__` / `sys.platform` / `win32` /
  `cocoa`：命中皆位於**註解**（描述硬約束本身，或列舉「未來 win32/cocoa 後端」）——**無任何平台

- stub 為純記憶體實作，無真實系統呼叫；能力矩陣取上游 E1-21 `defaults()`。契約僅依賴介面與能力矩陣。

### NFR-02（具名 role、無絕對座標 / 數字 z-order）
- `SurfaceProfile` 僅含 `std::string role` 一個欄位。全檔無 pixel / (x,y) / 座標 / 數字層級 token
  （掃描 `z_index`/`zorder`/`absolute`/`pixel`/`coordinate` 皆無命中）。契約 4/5/8 皆以具名 role
  （`surface.character`/`surface.launcher`/`surface.overlay`）驅動。**合規。**

### NFR-03（能力查詢一律經 has()）
- 介面 `has(id)` 契約要求須與 `capabilities().has(id)` 完全一致、未宣告能力保守回 false。
- `invoke_capability` 以 `has(id)` 閘控（第二層保險）：不可用（含未宣告）回 `Unsupported` 且不改狀態。
- 契約 1 逐一比對 `has()` 與矩陣、並驗未知能力回 false；契約 7 驗閘控呼叫依 `has()` 回報。**合規。**

## 4. 契約涵蓋度覆核（獨立）

逐案覆核，判定涵蓋合理且前後條件保守、平台中立：

1. **能力查詢一致性**（`CapabilityQueryConsistentWithMatrix`）：對矩陣全部宣告比對 `has()` 一致 + 未知回 false。
2. **生命週期狀態轉移**（`LifecycleReadyStateTransitions`）：init 前 not ready → init 後 ready → shutdown 後 not ready。
3. **init/shutdown 冪等**（`InitializeAndShutdownAreIdempotent`）：重複 init/shutdown 皆 Ok、狀態不變壞。
4. **surface 前置條件**（`CreateSurfaceRequiresInitialized`）：未 init 建立回 Invalid、輸出 handle 覆寫為 kInvalidSurface。
5. **surface 生命週期往返**（`SurfaceCreateDestroyRoundTrip`）：建立→alive→銷毀→not alive；重複銷毀回 Invalid 不崩潰。
6. **無效輸入不崩潰**（`InvalidInputsRejectedNotCrash`）：空 role 回 Invalid；銷毀 kInvalidSurface 回 Invalid。
7. **能力閘控錯誤處理**（`GatedCapabilityInvocationHonoursHas`）：依 `has()` 回 Ok/Unsupported；未知能力回 Unsupported。
8. **shutdown 釋放 surface**（`ShutdownReleasesSurfaces`）：shutdown 後既有 surface 不得殘留。
9. **sanity**（`StubSatisfiesContractDirectly`）：非參數化直接冒煙，確認契約可套於實作。

涵蓋能力查詢一致性、生命週期（含冪等與後置釋放）、surface 前後條件、錯誤處理不崩潰——皆為
**跨平台皆應成立的最小共識**，未觸及任何平台專屬行為。以 `TestWithParam<BackendFactory>` +
`INSTANTIATE_TEST_SUITE_P` 落地「新增後端只加一個 factory、契約斷言不動」，符合契約組用途。
