# 結構註記 — E1-25 kernel 後端契約測試組（所有後端共用）

- 層級：engine（平台中立）／交付物為 `tests/contract/` 的跨後端契約測試組
- 目錄位置：`tests/contract/`
  - `kernel_backend.hpp` — kernel 後端抽象介面 `KernelBackend`（純虛）+ `Status` /
    `SurfaceProfile` / `SurfaceHandle`；引用上游 E1-21 `CapabilityMatrix`。相位 1 repo 內尚無
    現成後端介面實作，故介面由契約組自帶（規格：純抽象且無現成實作時 stub 由本測試檔提供）。
  - `stub_backend.hpp` — 測試本地最小 `StubBackend`（純記憶體實作介面，僅供跑契約，
    **不 link E1-24**，維持與 E1-24 的單元獨立）。
  - `test_contract_backend.cpp` — gtest 契約組（9 案例）。
  - `CMakeLists.txt` — `test_contract_backend`（link `e1_21` + `GTest::gtest_main`）+
    `add_test(NAME contract_backend)`。**CMakeLists 與測試 .cpp/.hpp 同在本目錄**（與其他單元
    不同）；根 CMakeLists 的 GLOB 已收 `tests/contract/CMakeLists.txt`（CHG-20260723-22）。
- 測試：`tests/contract/test_contract_backend.cpp`（gtest，8 parameterized 契約 + 1 sanity）
- 對外意義：一組**所有 kernel 後端都必須通過**的平台中立行為契約。以 gtest parameterized
  test（`TestWithParam<BackendFactory>` + `INSTANTIATE_TEST_SUITE_P`）對「任一符合
  `KernelBackend` 介面的後端」跑同一批斷言：能力查詢一致性（`has()` 與能力矩陣一致、未宣告
  保守回 false，NFR-03）、生命週期（init/shutdown 冪等、就緒狀態轉移、shutdown 釋放 surface）、
  surface 前後條件、錯誤處理（不可用能力回 Unsupported 不崩潰）。
  - 受測後端目前僅契約組自帶的測試本地 stub；未來 E1-24 null 後端 / win32 / cocoa 各加一個
    factory 即納入，契約斷言不動。
  - 相位 1 約束：無平台分支、不綁真實後端、surface 以具名角色表達（無絕對座標 / 數字 z-order）。
