  - `SnapResult` / `snap_to_work_area_edges()` / `kDefaultSnapThreshold`
- 另修改：`host/app/host_main.cpp`（拖曳結束時套用）

## 吸的是「邊對邊」，不是「左上角對左上角」

右緣吸附時 `x` 要算成 `area.right - width`，下緣同理。
若寫成左上角對右緣，widget 會整個跑到畫面外——這是這類功能最典型的錯法，已有測試釘住。

## 兩軸各自獨立

只有 x 在門檻內就只吸 x，y 維持原值；角落則兩軸都吸。
不做「整體吸附」是因為使用者常常只想靠一邊。

## 同一軸兩端都在門檻內時取較近者

視窗幾乎和工作區一樣寬時會發生。不處理的話會出現「明明靠左卻被吸到右邊」的跳動。

## 純函式的理由

吸附不需要視窗、不需要 Windows API，因此抽成純函式後可以把每一條規則直接釘死。
**負向案例與正向案例同樣重要**：這類「幫使用者調位置」的功能特有的失敗模式是
**在不該吸的時候吸**——widget 放在畫面中央卻被吸到邊上，使用者會覺得程式在跟他作對，
而且很難描述問題。故測試涵蓋：中央不吸、門檻外一格不吸、門檻 `<= 0` 停用、
退化工作區原樣回傳、以及**冪等**（已貼齊者再吸不得移動，否則每次拖曳結束都會抖一下）。

## 套用點：先吸附，再記憶

`host_main` 在 `poll_drag_finished` 之後、`remember_current` 之前套用。
**順序不能反**：反過來的話記下的是吸附前的座標，下次還原時 widget 會從邊上「彈開」一點。
