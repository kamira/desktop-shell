# 結構註記 — E1-19 顯示器熱插拔復原

- 層級：platform（相位 1 = Mac / null 期，僅介面 + 注入式來源，無真實顯示器後端）／子系統 kernel
- 目錄位置：`src/kernel/e1_19/`
  - `layout_recovery.hpp` — 平台中立介面：拓撲簽章導出 + `LayoutRecoveryManager<Layout>` 樣板
  - `layout_recovery.cpp` — `topology_key()` 實作（由具名 ScreenId 排序串接，與列舉順序無關）
  - `CMakeLists.txt` — `add_library(e1_19)` + `target_link_libraries(e1_19 PUBLIC e1_18 e5_08)`
    + `test_e1_19`（`tests/e1/test_e1_19.cpp`）+ `add_test(NAME e1_19)`
- 測試：`tests/e1/test_e1_19.cpp`（gtest，13 案例）
- 上游相依（可讀不可改）：E1-18 顯示器拓撲抽象（`ScreenRegistry` / `PerScreen<T>` / `ScreenId`）、
  E5-08 系統事件（`SystemEventSource` / `SystemEvent` / `DisplayChanged`）。
- 對外介面（`namespace ds::kernel`）：處理顯示器熱插拔後的佈局復原。
  - `topology_key(ScreenRegistry)`：由具名 ScreenId 導出的穩定拓撲簽章（排序後串接），
    與列舉順序無關，故「拔除後重接同一組螢幕」= 拓撲恢復可辨識（NFR-02：無座標 / index / z-order）。
  - `LayoutRecoveryManager<Layout>`：訂閱 E5-08，僅 `DisplayChanged` 觸發拓撲重算 + 可選 `on_recover`
    回呼；`record(id, layout)` 於當前組態記錄佈局、`layout_for(id)` 有記錄回記錄（復原）否則回預設
    （新顯示器 / 未知螢幕保守回預設，NFR-03 以 find/has 保護）；佈局以「拓撲簽章 → PerScreen<Layout>」
    多組態獨立記憶（拔除的螢幕記錄保留於原組態，重接即復原）。拓撲來源與事件源皆注入式。
  - 相位 1 約束：無平台分支、無真實顯示器 API（CGDisplay/EnumDisplayMonitors）、無 backend/win32|cocoa、
    無絕對座標 / 數字 z-order；狀態全存記憶體。
