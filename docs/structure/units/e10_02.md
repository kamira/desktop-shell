# 結構註記 — E10-02 低延遲同機通道

- 單元：E10-02（engine 層 / ipc / Risk: low）
- 目錄位置：`engine/ipc/e10_02/`（平台中立引擎邏輯，換平台一行不動）
- 測試：`tests/e10/test_e10_02.cpp`（CTest 名 `e10_02`）
- 相依：E10-01 本機 IPC 訊息通道（`target_link_libraries(e10_02 PUBLIC e10_01)`）——沿用其 `Message`（酬載重用 E6-01 `CommandArgs`）。

## 放了什麼
- `low_latency_channel.hpp`：低延遲同機通道契約 —— `LogicalClock`（可注入邏輯時脈）、`Priority`、
  `SendStatus`、`BackpressurePolicy`、`Envelope`（E10-01 `Message` + 優先/入列 tick/序號）、`LatencyStats`、
  `LowLatencyChannel`。相位 1 為「記憶體內佇列 + 邏輯時脈」，不綁真實 IPC（無 shared memory/socket/mmap/`#ifdef`）。
- `low_latency_channel.cpp`：`low_latency_contract_version()` 契約版本標記（"e10_02/1.0.0"）；其餘邏輯 header-only inline。
- `CMakeLists.txt`：`add_library(e10_02)` + `PUBLIC e10_01` + `test_e10_02` + `add_test(NAME e10_02)`。

## 對外介面（一句話）
`ds::ipc::LowLatencyChannel` 在 E10-01 訊息通道之上提供低延遲同機抽象：優先佇列點對點
（`send(msg,prio)` / `try_receive()→optional<Envelope>`，高優先先出、同級 FIFO）、有界背壓
（`capacity` + `BackpressurePolicy`：Reject / DropOldestLowPriority，滿載不阻塞不崩潰）、批次收送
（`send_batch` / `receive_batch`）、快速請求-回應（`request_response`），並以可注入 `LogicalClock`
量測邏輯延遲（last/max/average）——供延遲敏感的同機訊息 / 命令傳遞。
