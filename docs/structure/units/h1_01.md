## 為什麼繪製橋接在 `host/` 而不在 win32 後端裡

兩個獨立理由，任一都足以決定：

1. **分層**：它吃 E4-03 的 `ds::elements::RenderModel`（engine / module 層型別）。
   放進 `src/kernel/backend/win32/`（platform 層）會造成 **platform 反向依賴 engine**。
2. **NFR-02**：繪製必然涉及座標，而 kernel 契約硬性禁止絕對座標——
   所以繪製**不可能**成為 kernel 契約的一部分，只能活在契約之外。

後端因此只負責「視窗、圖層、輸入」，並額外提供 win32 專屬的 `hwnd_for()` 讓 host 取得原生視窗。

## 可測試性設計

版面計算（`row_layout` / `fill_rect`）刻意抽成**不碰 GDI 的純函式**，可直接斷言幾何；
繪製本體以**記憶體 DIB**（`CreateDIBSection`）測試，能真的讀像素——
因此測試斷言的是「量表長度真的跟著 fill_ratio 走」，而不只是「函式沒有崩潰」。

## 與 `examples/cpu_gpu_validator` 的關係

兩者組裝 widget 與指標的路徑**完全相同**（同一組擴充點、同一份 render_model），
差別只在最外層呈現：驗證器畫成主控台 ASCII，本單元畫成桌面視窗像素。
這正是重點——換掉呈現層時，擴充點一個都沒改。
