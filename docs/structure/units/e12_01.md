# 結構註記 — E12-01 idle 記憶體與 CPU 門檻

- 層級：engine（平台中立純邏輯）／子系統 common／相依 E2-02（`PUBLIC e2_02`）／對應 NFR-01
- 目錄位置：`engine/common/e12_01/`
  - `idle_threshold.hpp` / `idle_threshold.cpp` — 閒置資源門檻管理器 + 活動等級 + tier 降級
  - `CMakeLists.txt` — `add_library(e12_01)` + `target_link_libraries(e12_01 PUBLIC e2_02)` +
    `test_e12_01`（`tests/e12/test_e12_01.cpp`）+ `add_test(NAME e12_01)`
- 測試：`tests/e12/test_e12_01.cpp`（gtest，22 案例）
- 對外介面（`namespace ds::common`）：依當前 CPU / 記憶體用量判定系統**閒置(Idle)**或
  **活躍(Active)**，據此建議採集活動等級，並與 E2-02 的 `SamplingTier` 整合（閒置時把採集
  分級降頻）。直接關係 NFR-01「閒置時低資源占用」。
  - 型別：`ActivityLevel`（active / idle）。自由函式：`to_string`、`lower_tier`（把
    `ds::metrics::SamplingTier` 降一階：High→Normal→Low 夾底、OnDemand 維持）。
  - `IdleThresholdPolicy`：`set_thresholds(cpu%, mem%)`（夾 [0,100] 驗證）、`set_hysteresis`
    （遲滯帶寬，夾 >=0）、`set_tier_mapping`（等級→分級，預設 Active→High / Idle→Low）；
    `evaluate(cpu%, mem%)->ActivityLevel`（OR 進活躍、AND 出閒置、死區維持現態的雙門檻遲滯）；
    `recommended_tier()`（等級→分級）、`adjust_tier(base)`（閒置時把基準分級降頻）。
  - 核心性質：**雙門檻遲滯**防臨界抖動（thrashing）；閒置降頻護 idle 門檻，活躍維持即時性。
    純邏輯、資源讀值由呼叫端注入、無平台分支 / 無真實資源 API / 無真實時鐘。
