# 結構註記 — C1-03 氣球 profile

- 單元：C1-03（artifact 層 / 應用 profile / Risk: low）
- 目錄位置：`content/profiles/c1_03/`
- 測試：`tests/c1/test_c1_03.cpp`（CTest 名 `c1_03`，21 個 gtest 案例）

## 放了什麼
- `balloon_profile.hpp` / `.cpp`：**組裝型**單元（非新引擎邏輯）——把三個已合併的擴充點
  組成「角色對話氣球 / 氣泡通知」應用 profile：
  - E4-11 `TypewriterElement`：逐字顯示文字內容（注入式 `advance(dt)` 推進）。
  - E1-14 `TransientProfileManager`：短暫生命週期（ttl 個 tick 後自動消失，或手動
    `dismiss()`），本氣球專屬的 E5-10 `TimeoutTimer`（不與其他氣球共用）。
  - E1-11 `SubordinateLayout`：依附一個 C1-02 `PortraitProfile` 角色 surface 的具名 anchor
    相對定位（預設角色頭頂上方），角色移動時氣球跟隨（`resolve()` 每次依呼叫端提供的角色
    當下矩形重新計算）。
  - `class BalloonProfile`：`show_balloon(character, text, ttl, spec)` / `advance(dt)` /
    `dismiss()` / `resolve(...)` / 各類查詢（`visible_count` `total_count`
    `is_text_complete` `render_model` `remaining` `anchor_parent`）。
- `character_bridge.hpp` / `.cpp`：**內部橋接層**——隔離 C1-02 `PortraitProfile` 的實際串接到
  獨立翻譯單元，理由：E1-14 經 `input_strategy.hpp`（E1-02）宣告 `enum class
  ds::kernel::HitResult`，C1-02 經 E5-14 → E5-01 → `hit_test.hpp`（E1-04）宣告**另一個不同
  型別**的 `struct ds::kernel::HitResult`——兩者標頭同時出現在同一翻譯單元會編譯失敗（本機
  以 g++ 實測重現，與已合併的 `content/profiles/c1_06/dock_hot_zone_bridge.*` 相同手法）。
  `balloon_profile.hpp`/`.cpp` 因此不直接 `#include "portrait_profile.hpp"`（改經此橋接層的
  中立函式 `detail::character_snapshot()` 讀取角色狀態），E1-14 `TransientProfileManager` 的
  實際串接則以 pimpl（`BalloonProfile::Impl`）隔離於 `balloon_profile.cpp`。
- `CMakeLists.txt`：`add_library(c1_03 STATIC balloon_profile.cpp character_bridge.cpp)` +
  `target_link_libraries(c1_03 PUBLIC e1_11 e1_14 e4_11 c1_02)` + `test_c1_03`
  （`tests/c1/test_c1_03.cpp`）+ `add_test(NAME c1_03)`。

## 對外介面（一句話）
`ds::profiles::BalloonProfile`：`show_balloon(character, text, ttl, spec)` 依附角色顯示逐字
氣球 / `advance(dt)` 推進逐字進度與存活倒數（跨過 ttl 自動消失）/ `dismiss()` 手動提早結束 /
`resolve(character_placement, balloon_size, out)` 依角色目前矩形解析氣球絕對佈局（跟隨）/
`remaining()` `visible_count()` `total_count()` `is_text_complete()` `render_model()` 查詢。
相位 1：純資料 / 邏輯組裝，無真實 GUI、無平台分支（無 `#ifdef` / win32 / cocoa）、無絕對座標 /
數字 z-order（NFR-02）。
