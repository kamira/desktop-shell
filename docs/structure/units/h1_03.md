## 本單元不含任何狀態機

拖曳狀態機、記憶位置、序列化 / 還原**全部在 E1-08 `DraggableSurface` 裡**（相位 1 已完成）。
本單元只做三件事：像素 ↔ `AnchorSpec` 換算、檔案存取、在對的時機呼叫對的東西。

`remember_current()` 走的是完整的 `begin_drag` → `drag_to` → `end_drag`，
讓 E1-08 的狀態機是位置的唯一真相來源，而不是在 host 這裡另存一份座標。

## 像素 ↔ AnchorSpec

```
dx = (x - 工作區左緣) / 工作區寬
dy = (y - 工作區上緣) / 工作區高        anchor 固定為 TopLeft
```

反向委由 E1-07 `resolve()`，再加回工作區原點得到螢幕絕對座標。

**為什麼固定用 `TopLeft` 而不挑最近的錨點**：挑錨點會讓「同一個位置」有多種合法表達，
round-trip 不再唯一，測試與除錯失去依據。邊緣吸附屬更上層的產品決策，不在這一層做。

**為什麼工作區原點要一起帶著走**：工作列擺在上方或左側時，工作區原點不是 (0,0)。
只存尺寸會讓位置在那些機器上整體偏移。已有測試釘住。

## 這個設計的直接紅利：解析度無關

存下來的是**比例**而非像素。換螢幕、改工作列高度、改縮放之後，
widget 落在對應的相對位置，而不是跑到畫面外。
這是 NFR-02（禁絕對座標）帶來的，不是額外做的工。

## 存檔時機

**拖完當下就寫檔**，不是等關閉時才寫。理由：這支程式沒有「正常關閉」以外的收尾機會——
工作管理員結束、當機、登出都不會走到結尾。關閉時再寫一次只是保險。

檔案位置 `%LOCALAPPDATA%\desktop-shell\positions.conf`，內容為 E7-01 宣告式文字
（`serialize_positions()` 的輸出，可被 `load_positions()` 讀回）。

## 失敗一律不影響 widget

沒有檔案（第一次執行）、檔案壞掉、取不到 `LOCALAPPDATA` —— 全部安靜略過，
widget 留在後端的預設幾何。**持久化失敗不該讓桌面元件掛掉。**
E1-08 的 `load_positions` 是全有或全無，壞檔不會留半套狀態，已有測試釘住。
