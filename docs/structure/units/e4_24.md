# 結構註記 — E4-24 反鋸齒與內距

- 層級：engine（phase 1，平台中立純渲染設定邏輯）／子系統 render／單元 e4_24
- 目錄位置：`engine/render/e4_24/`（根 CMakeLists 以層級 GLOB `engine/*/*/CMakeLists.txt` 自動收入）
  - `render_style.hpp` — 介面：`AntiAliasMode`{None, Grayscale, Subpixel}；
    `RenderQuality`{Low, Medium, High}；`SpacingToken`{None, XSmall, Small, Medium, Large,
    XLarge}；`InsetUnit`{Proportion, Named}；各自的 `is_valid(...)`；`InsetValue`{unit,
    proportion, token} + `from_proportion()`/`from_token()`；`Insets`{top, right, bottom,
    left} + `none()`/`uniform()`/`symmetric()`；`RenderStyle`{aa, quality, insets}（輸入）；
    `RenderConfigStatus`{Ok, Invalid}；`RenderModel`{aa, quality, inset_top/right/bottom/left}
    （輸出，內距已解析為正規化比例）；`resolve_spacing_token(SpacingToken)`；類別
    `RenderStyleService`（`apply()` / `render_model()` / `has_model()`）。
  - `render_style.cpp` — 列舉合法性檢查、內距單側解析（具名查表 / 比例有限性 + 夾限）、
    `RenderStyleService::apply()` 之實作。
  - `CMakeLists.txt` — `add_library(e4_24 STATIC render_style.cpp)` +
    `target_link_libraries(e4_24 PUBLIC e1_03)` + `test_e4_24`（`tests/e4/test_e4_24.cpp`）+
    `add_test(NAME e4_24)`
- 測試：`tests/e4/test_e4_24.cpp`（gtest，31 案例）
- 上游相依（可讀不可改）：E1-03（逐像素 alpha surface / surface 幾何模型）——本單元的反鋸齒 /
  內距渲染設定承其具名鍵 / 正規化比例 / 明確狀態回報不靜默的服務層設計精神，宣告於同一
  surface 渲染語境之上（PUBLIC 連結傳遞，同 E4-22 樣式）。
- 對外介面（`namespace ds::render`）：反鋸齒與內距的宣告式渲染設定（純邏輯，不執行實際繪製）。
  - 輸入 `RenderStyle{aa, quality, insets}` → `RenderStyleService::apply()` 驗證 + 正規化
    → 輸出 `RenderModel`（可經 `render_model()` 唯讀查詢，失敗時保留前一份合法設定）。
  - 內距（`Insets`）四側皆可為正規化比例 [0,1] 或具名間距權杖（`SpacingToken`，經
    `resolve_spacing_token()` 查表換算），兩者皆與絕對畫面座標無關（NFR-02 合規，無硬編像素 /
    無數字 z-order）。
  - phase 1 約束：純邏輯，無平台分支（無 `#ifdef`）、無真實繪圖 API / OS；未知列舉值
    （含 `static_cast` 硬轉出範圍）與非有限值（NaN/Inf）→ `RenderConfigStatus::Invalid`
    明確回報不靜默；有限但越界的比例 → 明確夾限至 [0,1]（非錯誤）。
