# 結構註記 — E7-17 `parse()` 不得讓行程結束（例外外洩 + 深層巢狀爆堆疊）

- 層級：engine(平台中立純邏輯)；修的是描述子系統**根契約** E7-01 的既有檔（相依已合併的 E7-01）。
- 目錄位置：`engine/format/`（CHG-20260730-03 扁平化後無 per-unit `<slug>/` 層）
  - **本單元不新增原始碼檔**：它改的是 `document.hpp` / `document.cpp`
    （二者皆在本單元 `write_scope` 內），故 `CMakeLists.txt` **無 `add_library`**。
  - `CMakeLists.txt`（追加 `e7_17` 區塊）— `add_executable(test_e7_17)` 連 `e7_01`
    （被修的就是該 library 本身）+ `add_test(NAME e7_17)`。`platform: neutral`，
    刻意**不**包在 `if(WIN32)` 內（neutral 單元須在 ubuntu 留下註冊測試）。
- 測試：`tests/e7/test_e7_17.cpp`（gtest，15 案例；CTest 名 `e7_17`）
- 對外介面（`namespace ds::format`）：補強 `parse()` 既有契約的兩個破口——
  改動前有兩類輸入**走不到任何錯誤回報路徑**，而是終結行程。
  - 新增公開常數 `kMaxNestingDepth`（`inline constexpr std::size_t`，值 **64**）：
    `parse()` 接受的最大巢狀區塊層數，**根 map 為深度 1**。這是**契約的一部分**而非實作細節，
    超限一律回傳帶行號的 `ParseError`（**不是**例外、**不是** SIGSEGV）。
  - `parse()` 的行為契約收緊為**不丟出任何例外**（唯一例外來源 `std::bad_alloc`，非輸入可控）：
    數值超出 `double` 可表示範圍（`1e400` / `-1e400` / `1e-400` / 超長數字串）與
    `format_version` 版號超出 `int`，一律回傳帶**該值所在行號**的 `ParseError`。
  - `parse_scalar()` 新增一種回 `false` 的情形：數值語法正確但超出可表示範圍
    （不退化成裸字串——壞掉的數值不得偽裝成正常的字串值）。
  - **既有合法輸入的解析結果未變**：libstdc++ 的 `std::stod` 本就是「`strtod` 後
    `errno == ERANGE` 即丟」，本實作檢查同一條件後改為回報，故「拒絕的輸入集合」
    與改動前「會丟例外的輸入集合」對齊。
- 實作要點（三處成因修正，**無 try/catch 包裹、無 signal handler**）：
  - `numeric_token()`：`std::stod` → `errno = 0` + `std::strtod` + `errno == ERANGE`；
    回傳值由 `bool` 升為 `NumericResult{NotNumeric, Ok, OutOfRange}`——
    「不是數字」與「是數字但超出範圍」必須分開，否則後者只能靜默退化成字串。
  - `parse_version()`：`std::stoi` → 新增 `digits_to_int()`（乘加前先驗上界，不觸發有號溢位 UB）；
    回傳值由 `bool` 升為 `VersionResult{Ok, Malformed, OutOfRange}`。
  - 遞迴下降四函式（`parse_block` / `parse_map_block` / `parse_list_block` /
    `parse_child_or_null`）新增 `std::size_t depth` 參數；上限檢查置於 `parse_block`
    **最前面**，也就是**建任何 `Value` 之前**——`Value` 樹的解構也是遞迴的，
    故已建成的樹必須永不深於上限，這個位置是必要的而非美觀考量。
- 平台中立：無 `#ifdef`、無平台分支、無系統呼叫；`strtod` / `errno` 為 C 標準程式庫，換平台一行不動。
- 相關 NFR：
  - **NFR-04**（描述格式錯誤須定位到行，不得靜默失敗）：本單元是這條的直接補強。
  - NFR-02 / NFR-03 不適用：不含座標 API，也不含能力閘控呼叫。
- 定位：本單元不擴充格式，只讓 E7-01 的根契約對**惡意 / 損毀輸入**也成立——
  消費 `parse()` 的八個生產呼叫端因此不需要（也不應該）用 `try`/`catch` 包住它。
