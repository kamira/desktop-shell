# 結構註記 — E9-05 佈局存檔與還原

- 目錄位置：`engine/package/e9_05/`（engine 層 / package 子系統）。
- 放了什麼：
  - `layout_store.hpp` / `layout_store.cpp` — 桌面元件佈局的存檔 / 還原：
    - `LayoutState` / `LayoutElement`（`id` / `type` / 宣告式 `properties`）— 抽象佈局資料模型。
    - `serialize_layout` / `deserialize_layout` — 透過 E7-12 `serialize` 與 E7-01 `parse` 的往返。
    - `LayoutStorage`（可注入抽象後端）+ `MemoryLayoutStorage`（相位 1 純記憶體實作）。
    - `LayoutStore` — 多具名 profile 的 `save` / `load` / `list` / `remove` / `contains`。
  - `CMakeLists.txt` — `add_library(e9_05 STATIC layout_store.cpp)`，
    `target_link_libraries(e9_05 PUBLIC e7_12)`；契約測試 `tests/e9/test_e9_05.cpp` 註冊為 CTest `e9_05`。
- 對外介面一句話：把「目前桌面佈局」擷取為抽象 `LayoutState`、以 E7-12 序列化為宣告式格式、
  存於可注入後端並支援具名存 / 取 / 列舉 / 刪除；查無佈局明確報錯、不靜默。
- 平台中立：無 `#ifdef`、無系統呼叫、無真實檔案 I/O（儲存為可注入記憶體後端）；換平台一行不動。
- NFR-02：核心 API 不出現絕對座標欄位與數字 z-order——位置 / 大小 / 設定皆收進宣告式 `properties`。
