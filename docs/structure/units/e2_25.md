# 結構註記 — E2-25 剪貼簿監看

- 層級：module（平台無關指標提供者）／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_25/`
  - `clipboard_monitor.hpp` / `clipboard_monitor.cpp` — 介面 + null 後端 + 變更偵測器 + 提供者實作
  - `CMakeLists.txt` — `add_library(e2_25)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_25`
    （`tests/e2/test_e2_25.cpp`）+ `add_test(NAME e2_25)`
- 測試：`tests/e2/test_e2_25.cpp`（gtest，24 案例）
- 上游相依：
  - E2-01 統一指標介面（`engine/metrics/e2_01`，可讀不可改）——消費 `MetricProvider` 契約。
  - E2-02 採集頻率分級（`engine/metrics/e2_02`，可讀不可改）——以 `SamplingScheduler` 登記
    低頻採集需求，不自造排程。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「剪貼簿內容／變更」
  透過 **E2-01 的 `MetricProvider`** 掛成指標 `clipboard.content`（單一實例：
  value.number=累計變更次數、value.text=目前內容、history=變更活動時序）。
  - `ClipboardSnapshot`（present/text）、`ClipboardSource`（抽象後端 `read()`）、
    `NullClipboardSource`（相位 1 null 後端：不讀系統剪貼簿，回空內容或注入的假內容）。
  - `ClipboardMonitor`：純邏輯變更偵測器（比對前後快照、累計變更次數），可完全單元測試。
  - `ClipboardMonitorProvider : ds::metrics::MetricProvider`：`register_metrics()` 掛上指標；
    `sample()` 讀來源→偵測→更新 value/歷史；`register_demand()` 以 `SamplingTier::Low`
    把本指標登記進 E2-02 排程器（除頻沿用 E2-02）。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / 真實 OS 剪貼簿；
    消費者只透過 E2-01 抽象介面走訪，新增此指標掛件一行不動。
