- 單元：C2-11（artifact 層 / widget / Risk: low / 承重 0x）
- 目錄位置：`content/widgets/`（目錄已扁平化，CHG-20260730-03：無 per-unit slug 子目錄）
- 測試：`tests/c2/test_c2_11.cpp`（CTest 名 `c2_11`，43 個 gtest 案例）

## 放了什麼

- `process_top_widget.hpp` / `.cpp`：`namespace ds::widgets`。**組裝型**單元（非新引擎邏輯）
  ——桌面「行程 top-N」widget，把四個已合併的擴充點組成一個具名 widget：
  - E2-19 `ProcessSortKey` / `ProcessMonitorProvider` 的指標身分常數：**排序維度 ↔ 指標 id ↔
    單位的唯一對照來源**（`proc.cpu`/`%` ↔ `proc.memory`/`MB`）。widget **不持有、不建立、
    不重建 provider**；維度只決定 `refresh()` 去 registry 要哪一個 id（CHG-20260829-05 Q-A）。
    E2-01（`MetricRegistry`/`Metric`/`MetricInstance`）經 E2-19 的 PUBLIC 相依透傳而來，是
    唯一的讀值入口；行程指標是**多實例**的（每個行程一個實例，instance_id = pid、label = 行程名）。
  - E4-03 `BarElement`/`GaugeElement`/`ProgressElement`：每列的視覺渲染描述（`RenderModel`）。
  - E7-01 `Value`/`parse`/`Document`：宣告式設定的資料模型；`configure_text()` 走其文字解析
    **並由其驗證 `format_version` 版本欄位相容性**。
  - E7-05 `is_formula`/`Evaluator`：`min`/`max` 靜態公式（configure 時求值，作用域不含
    `value`）+ `transform` 動態公式（refresh 時以 `value` 綁定當列原始值求值）。
- `CMakeLists.txt`（子系統合併建置檔）：追加 `add_library(c2_11)` +
  `target_link_libraries(c2_11 PUBLIC e2_19 e4_03 e7_01 e7_05)` + `test_c2_11`
  （`tests/c2/test_c2_11.cpp`）+ `add_test(NAME c2_11)`。

## 對外介面（一句話）

`ds::widgets::ProcessTopWidget`（只需一個具名 id，無其他建構相依）：
`configure(Value)` / `configure_text(E7-01 文字)` 宣告式決定 **排序維度**（`sort_by`:
cpu/memory）與 **N**（`top_n`: 0=全部/3/5/10）以及呈現方式（`kind` / `min`/`max` / `transform`）
→ `refresh(MetricRegistry)` 以**維度決定的指標 id** 讀值、每個行程實例一列、依維度值由高到低
取前 N（指標不存在 / 單位不符 / 無實例 → 具名 `ProcessMetricState`，列清空；個別實例無讀值或
公式失敗 → 該列降級，不中止其餘列，NFR-03）→ `render()` 組裝 E4-03 元素 + 格式化文字
（`render_model()` 查詢）。

## 兩個刻意的設計約束

- **切換排序維度 = 換掉註冊的指標**（Q-A 停點裁定）：維度改了就去要另一個 id；舊 id 的指標
  即使還在 registry 也不讀（否則單位會從 `%` 悄悄變成 `MB`）。歷史不保留；provider 由 host
  （H1-11）重建，**本單元不重建**。在重建之前 `refresh()` 回報 `ProcessMetricState::Missing`。
- **沒有顯示範圍就不畫長條**（知識庫 K-002）：`proc.memory` 的 range 是 `at_least(0)`（無上界）。
  未宣告 `min`/`max` 時該列 `has_range=false`、不掛 E4-03 元素，只出文字——憑空給一個上界會把
  「8 GB」與「100 MB」畫成一樣滿，值域檢查全過而畫面說謊。

相位 1 / 2 約束：純資料 / 邏輯組裝，無真實行程 API（行程資料一律經注入的 E2-01 registry
流入）、無平台分支（無 `#ifdef` / win32 / cocoa）、無絕對座標 / 數字 z-order（NFR-02：E4-03
具名 `surface`（`<id>.rows`）+ `slot`（pid）+ 比例 / 角度）。
