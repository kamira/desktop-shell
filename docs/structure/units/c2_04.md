# 結構註記 — C2-04 天氣 widget

- 單元：C2-04（artifact 層 / widget / Risk: low）
- 目錄位置：`content/widgets/c2_04/`
- 測試：`tests/c2/test_c2_04.cpp`（CTest 名 `c2_04`，20 個 gtest 案例）

## 放了什麼

- `weather_widget.hpp` / `.cpp`：`namespace ds::widgets`。**組裝型**單元（非新引擎邏輯）——
  桌面「天氣」widget，把五個已合併的擴充點組成一個具名 widget：
  - C1-01 `SkinProfile`：桌面基底（具名圖層歸屬 / 輸入策略 / 透明外形 / 自由拖曳皆透傳，
    以 `base()` 存取，本單元不重造）。
  - E2-14：注入式 `HttpTransport`（相位 1 為 `NullHttpTransport`）對端點發 GET，回應以其
    自帶的 `parse_json` / `JsonPath` / `seek` 解析出 `temp_c`（數值，必填）/ `description`
    （字串，必填）/ `icon`（字串，選填）三個欄位。
  - E7-10：`strings::format()` 依樣板組出可讀顯示文字（"22°C Cloudy"）；`strings::concat()`
    組請求 URL（端點 + 地點查詢字串）。
  - E4-01 `TextLayout`：把格式化文字排版為渲染描述（相對佈局，NFR-02）。
  - E4-02 `ImageElement`：把 icon 代碼組裝為圖片渲染描述（`MemoryImageSource`，固有尺寸為
    描述性常數 `kIconSize`；icon 代碼缺失則 `has_source=false`）。
- `CMakeLists.txt`：`add_library(c2_04)` + `target_link_libraries(c2_04 PUBLIC c1_01 e2_14
  e4_01 e4_02 e7_10)` + `test_c2_04`（`tests/c2/test_c2_04.cpp`）+ `add_test(NAME c2_04)`。

## 對外介面（一句話）

`ds::widgets::WeatherWidget`（注入 `KernelBackend&` + `LayerStack&` + `shared_ptr<HttpTransport>`
+ endpoint URL + `FontMetrics&`）：`configure(Value: location/unit)` 設定地點與溫度單位 →
`refresh()` 經注入 transport 擷取 + 結構化解析天氣資料（`FetchFailed` / `ParseFailed` 皆保留
既有資料，供降級顯示）→ `display()` 依單位換算、格式化並組裝 `WeatherRenderModel`（E4-01 文字
排版 + E4-02 圖示渲染描述）。相位 1：純資料 / 邏輯組裝，無真實網路 / 影像解碼 / 字型光柵化、
無平台分支（無 `#ifdef` / win32 / cocoa）、無絕對座標 / 數字 z-order（NFR-02）。
