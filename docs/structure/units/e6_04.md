# 結構註記 — E6-04 延遲與批次執行

- 層級：engine(平台中立純邏輯)；命令子系統的**延遲執行 + 批次執行**（相依已合併的 E6-01）。
- 目錄位置：`engine/command/e6_04/`
  - `deferred_batch.hpp` / `deferred_batch.cpp` — 實作
  - `CMakeLists.txt` — `add_library(e6_04)` + `target_link_libraries(e6_04 PUBLIC e6_01)`（消費上游）
    + `test_e6_04`（`tests/e6/test_e6_04.cpp`）+ `add_test(NAME e6_04)`
- 測試：`tests/e6/test_e6_04.cpp`（gtest，19 案例）
- 對外介面（`namespace ds::command`，擴充 E6-01 匯流排）：
  - **延遲執行** `DeferredScheduler`（綁定一個 `CommandBus`）：
    - `Tick`（邏輯時間單位）/ `DeferredId`（排程識別碼；`kInvalidDeferredId` 為失敗哨兵）。
    - `schedule(delay, cmd)` / `schedule(delay, id, args)`：排在 `now()+delay` 執行；`delay` 須 >= 1，
      否則回 `kInvalidDeferredId`（不排入、不靜默）。
    - `advance(ticks)`：推進邏輯時鐘並依序分派所有到期（`due <= now`）命令，回 `vector<DeferredDispatch>`
      （執行順序）；`ticks < 0` 為 no-op（不倒轉、不執行）。`advance_to(target)` 為絕對版。
    - `cancel(id)` / `has(id)` / `pending()` / `now()`。
    - `DeferredDispatch{id, due, command_id, result}`：單一到期命令的分派結果（沿用 E6-01 `CommandResult`）。
  - **批次執行** `Batch`（建構器：`add(cmd)` / `add(id, args)`）+ 自由函式
    `run_batch(bus, cmds/batch, mode)`：
    - `BatchMode{Atomic, Continue}`：Atomic 遇首個失敗即中止後續並回報 `failed_index`（「全成功或回報哪一步失敗」）；
      Continue 跑完全部、逐步回報。
    - `BatchResult{ok, executed, total, failed_index, steps, aborted()}` + `BatchStepResult{index, command_id, result}`。
- 時鐘語意：時間僅由 `advance()` 推進——**注入式邏輯 tick，不用真實 wall-clock / sleep / thread**；
  到期順序決定性（先到期先執行；同 tick 依排程 FIFO）。相位 2 若要真實計時，只需由外部驅動 `advance()`，
  本邏輯一行不動。
- 失敗處理：未知命令沿用 E6-01 回 `CommandStatus::NotFound`（不崩潰），批次視為失敗步、延遲亦如實回報（不靜默）。
- 定位：消費 E6-01 的 `CommandBus` / `Command` / `CommandResult` / `dispatch`；為命令子系統補上延遲與批次
  執行語意。平台中立、無 `#ifdef` / 平台分支 / 後端。
