# 結構註記 — C2-05 圖片 widget

- 單元：C2-05（artifact 層 / widgets 子系統 / Risk: low）
- 目錄位置：`content/widgets/c2_05/`
- 測試：`tests/c2/test_c2_05.cpp`（CTest 名 `c2_05`，19 個 gtest 案例）

## 放了什麼
- `image_widget.hpp` / `.cpp`：**組裝型**單元（非新引擎邏輯）——桌面小工具「圖片」：把已合併
  的 C1-01（掛載基底）與 E4-02（單張圖片本體）組起來，並在 widget 層自持多圖清單與目前索引
  （E4-02 本身只認識單張）。
  - `ImageWidget`：注入式相依 `ds::profiles::SkinProfile&`（C1-01，不取得其所有權，須比本
    物件活得久）。建構時立即把渲染輸出目標綁定為所掛載 skin 的具名 id（`skin.id()`，
    NFR-02：具名，非數字 handle）。內部自持一個 `ds::elements::ImageElement`（E4-02）+
    `vector<string>`（圖片來源參照清單）+ `vector<ImageDimensions>`（對應固有尺寸）+
    `current_`（目前所選索引）。
  - `configure(const ds::format::Value&)`：宣告式設定（E7-01 Map）——`images`（List，必填，
    每項 `{ref, width, height}`）/ `fit`（選填具名縮放模式字串："fill"/"fit"/"stretch"/
    "center"/"tile"）。先整批驗證再提交新清單、重置索引至第 0 張、委派 E4-02 `set_source` /
    `set_scale_mode`（不部分套用，具名結果 `ImageWidgetStatus` Ok/Invalid）。
  - `set_image(std::size_t index)`：以索引直接選取一張（越界或空清單 → `Invalid`，不改變
    目前所選）。
  - `next()`：依序前進到下一張，抵尾循環繞回第 0 張；空清單或僅一張 → 安全 no-op。
  - `image_count()`/`current_index()`/`fit_mode()`/`render_model()`：查詢與渲染輸出（委派
    E4-02）。`skin()`：唯讀存取所掛載的 C1-01 基底。
- `CMakeLists.txt`：`add_library(c2_05)` + `target_link_libraries(c2_05 PUBLIC c1_01 e4_02)` +
  `test_c2_05`（`tests/c2/test_c2_05.cpp`）+ `add_test(NAME c2_05)`。

## 對外介面（一句話）
`ds::widgets::ImageWidget`（注入 `SkinProfile&`）：`configure(Value)` 宣告式設定圖片來源清單
/ fit 縮放模式（全有或全無）/ `set_image(index)`·`next()` 切換所選圖片 / `image_count`·
`current_index`·`fit_mode` 查詢 / `render_model()` 產出目前所選圖片的渲染描述（目標綁定所
掛載 C1-01 基底的具名 surface id）。相位 1：純資料 / 邏輯組裝，無真實 GUI、無平台分支（無
`#ifdef` / win32 / cocoa）、無絕對座標 / 數字 z-order（NFR-02）、無真實影像解碼；未設定圖片
（空清單）時所有查詢 / 切換操作安全降級。
