# 結構註記 — E7-08 設定遷移與版本相容

- 層級：engine(平台中立純邏輯)；描述子系統的**版本升級鏈**（相依已合併的 E7-01 / E9-02）。
- 目錄位置：`engine/format/e7_08/`
  - `migration.hpp` / `migration.cpp` — 實作
  - `CMakeLists.txt` — `add_library(e7_08)` + `target_link_libraries(e7_08 PUBLIC e7_01 e9_02)`（消費上游）
    + `test_e7_08`（`tests/e7/test_e7_08.cpp`）+ `add_test(NAME e7_08)`
- 測試：`tests/e7/test_e7_08.cpp`（gtest，12 案例）
- 對外介面（`namespace ds::format`）：當宣告式設定文件的 `format_version` 落後時，套用遷移鏈把舊版
  結構升級到目標版本。
  - `Migration{from, to, transform}`：單一遷移步驟（`transform: Value -> Value`，純結構轉換，可為空 =
    恆等僅升版本標記）。步驟須嚴格上升（`from < to`）。
  - `MigrationRegistry`：`register_migration` / `add`（拒絕非上升步驟）、`has_path`、
    `migrate(root, current, target)` 與 `migrate(Document, target)` 重載。
  - `MigrateResult{ok, value, version, migrated, error}` + `MigrateStatus{Ok, NoPath, TooNew, Invalid}` +
    `MigrateError{status, message, from, target}`。
  - 版本序輔助：`version_less` / `version_to_string`（`FormatVersion` 僅有 `==`/`!=`，此處補排序）。
- 語意：以註冊步驟為有向邊（節點 = `FormatVersion`），由 `current` BFS 找抵達 `target` 的**最短鏈**，
  依序套用 `transform`，產出升級後 `Value` + 目標版本標記。`current == target` → no-op（`migrated()==false`）；
  `current > target` → `TooNew`（過新，不降級）；找不到鏈 → `NoPath`。全部明確報錯、不靜默（NFR-04 精神）。
- 定位：消費 E7-01 的 `Value` / `FormatVersion` / `Document`；與 E9-02（帶版本欄位的 manifest）同屬
  描述子系統的版本相容策略。平台中立、無 `#ifdef` / 平台分支。
