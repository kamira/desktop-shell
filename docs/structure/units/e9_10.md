# 結構註記 — E9-10 已安裝套件登錄的持久化

- 目錄位置：`engine/package/`（engine 層 / package 子系統）。
  CHG-20260730-03 目錄扁平化後**無 per-unit 子目錄**，本單元源碼直接置於該目錄。
- 放了什麼：
  - `install_store.hpp` / `install_store.cpp` — 已安裝套件登錄的持久化：
    - `InstallRecord` — 持久化單位，持有 E9-01 `Package`（manifest 中繼資料 + 內含項目邏輯
      路徑清單）；**不含套件本體**，故列舉已安裝套件永不需要載入套件。
    - `serialize_install_records` / `deserialize_install_records` — 透過 E7-12 `serialize`
      與 E7-01 `parse` 的往返；自身格式版本欄位 `kInstallRegistryFormat{1,0}`。
    - `InstallStorage`（可注入抽象後端）+ `MemoryInstallStorage`（**相位 1 純記憶體替身**，
      真實磁碟後端留待後續相位）。
    - `InstalledPackageStore` — 登錄門面：**建構即自後端重讀（rehydrate）**、`record()`
      **寫入即落盤（write-through）**；`record` / `forget` / `contains` / `find` / `list` /
      `records` / `size` / `reload` / `serialized`；slot 可指定（預設 `kDefaultInstallSlot`）。
    - `mirror_into(store, InstallRegistry&)` — 把持久化紀錄重播進一個全新的 E9-07
      `InstallRegistry`（重啟後回填的接點；只讀 E9-07 的公開 `add`，未改其一行）。
  - `CMakeLists.txt`（追加 `e9_10` 區塊）— `add_library(e9_10 STATIC install_store.cpp)`，
    `target_link_libraries(e9_10 PUBLIC e7_12 e9_07)`（E7-01 經 e7_12 傳遞；E9-01 / E9-02 /
    E5-08 經 e9_07 傳遞）；契約測試 `tests/e9/test_e9_10.cpp` 註冊為 CTest `e9_10`。
- 對外介面一句話：把「已安裝了哪些套件」的中繼資料以 E7-12 序列化為 E7-01 宣告式文字、存於
  可注入後端，**登錄物件解構後重新建構仍列得出該套件，且全程不需載入套件本體**；
  後端文字損毀一律明確報錯，絕不靜默當成空登錄。
- 平台中立：無 `#ifdef`、無平台分支、無系統呼叫、無真實檔案 I/O（持久化為可注入後端，
  相位 1 實作為記憶體替身）；換平台一行不動，相位 2 只需實作 `InstallStorage`。
- 相關 NFR：
  - NFR-02：API 面不出現絕對座標欄位與數字 z-order（本單元只承載套件中繼資料）。
  - NFR-04：解析 / 結構違反一律 `throw std::runtime_error`，解析錯誤附來源行號，不靜默失敗。
  - NFR-03 不適用：本單元不含能力閘控呼叫，無 `has()` 降級路徑需求。
