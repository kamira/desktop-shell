# 結構註記 — E7-16 設定分頁登錄（核心分頁 + 每套件一頁，append-only）

- 目錄位置：`engine/format/`（engine 層 / 描述子系統）。
  CHG-20260730-03 目錄扁平化後**無 per-unit 子目錄**，本單元源碼直接置於該目錄。
- 放了什麼：
  - `settings_pages.hpp` / `settings_pages.cpp` — 設定分頁登錄：
    - `PageOrigin{Core, Package}` + `to_string` — 分頁從何而來；決定它是否可被 `refresh()`
      重建 / 移除（核心分頁永不被動）。
    - `kCorePageId`（`"core"`，**保留** page id）/ `kCorePageTitle`。
    - `SettingsPage` — 一個分頁：`id` / `title` / `origin` / `owner_package_id` /
      `values`（設定樹，**唯一事實來源**）/ `fields`（**E7-14 `EditableField`**，由 values 算出）/
      `schema`（E7-14 `EditorSchema`）；`field(path)` 轉呼 E7-14 `find_field`。
    - `SettingsContribution` — 一個套件的貢獻：`package_id` / `title` / `declared`（宣告的設定樹）/
      `schema`。
    - `SettingsContributionSource`（可注入抽象後端：`contributing_package_ids` / `contribution`）
      + `MemorySettingsContributions`（**相位 1 純記憶體替身**，無真實檔案 I/O、無跨行程持久化；
      `declare` / `withdraw` / `clear`，字典序列舉）。
    - `SettingsPageRegistry` — 登錄門面：建構即建核心分頁並自來源建套件分頁；
      `refresh`（**只重建套件分頁集合，核心分頁完全不被觸碰**；全有全無）/ `size` /
      `package_page_count` / `page_ids`（**核心恆首位 + 套件字典序**）/ `pages` / `core_page` /
      `page` / `contains` / `core_values` / `package_values` /
      `apply_page_edit`（經 **E7-14 `apply_edit`** 驗證與寫回後重算欄位）。
  - `CMakeLists.txt`（追加 `e7_16` 區塊）— `add_library(e7_16 STATIC settings_pages.cpp)`，
    `target_link_libraries(e7_16 PUBLIC e7_14)`（E7-12 `Path` / `set_value` 與 E7-01 `Value` /
    `Document` 經 e7_14 傳遞）；契約測試 `tests/e7/test_e7_16.cpp` 註冊為 CTest `e7_16`。
    **刻意不連結 `e9_10`**：E9-10 回答「安裝了哪些套件」，但 E9-02 `Manifest` 不含設定宣告欄位、
    E9-01 `Package` 不含資源內容，故「套件宣告了哪些設定欄位」不在其回答範圍內；改以可注入
    抽象 `SettingsContributionSource` 表達，host 層組裝時才決定來源（理由詳見
    `settings_pages.hpp` 檔首與 `CHG-20261112-e7_16.md` 設計決定 1）。
- 對外介面一句話：把「設定面板」描述成**核心分頁 + 每個已安裝套件各一頁**，套件的貢獻是
  **append-only**——套件宣告與核心**同名**的欄位時，核心分頁的值**原封不動**
  （不是「檢查後拒絕覆寫」，而是**連覆寫的管道都不存在**：核心分頁的欄位只由核心 `Value` 樹
  算出，套件貢獻一律產生另一個持有自己 `Value` 樹的分頁物件）；卸載後該分頁消失，
  核心分頁與其他套件分頁不受影響。欄位模型一律**消費 E7-14**，不重造。
- 平台中立：無 `#ifdef`、無平台分支、無系統呼叫、無真實檔案 I/O、無 GUI 後端
  （本單元是分頁的**資料模型**，不是真實 GUI；貢獻來源為可注入抽象，相位 1 實作為記憶體替身）；
  換平台一行不動，相位 2 只需實作 `SettingsContributionSource`。
- 相關 NFR：
  - NFR-02：API 面不出現絕對座標欄位與數字 z-order（本單元只承載設定分頁模型）。
  - NFR-04：保留 page id 被佔用、貢獻 id 為空、重複 id、宣告根非 Map、來源列出 id 卻取不到貢獻、
    對不存在的分頁 / 欄位編輯、E7-14 驗證違反 —— 一律 `throw std::runtime_error`，
    訊息可定位到 page id 與欄位路徑，不靜默失敗；被拒絕的編輯與失敗的 `refresh` 不留半套狀態。
  - NFR-03 不適用：本單元不含能力閘控呼叫，無 `has()` 降級路徑需求。
