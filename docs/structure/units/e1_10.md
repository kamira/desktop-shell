# 結構註記 — E1-10 保持在螢幕內

- 層級：platform（相位 1 = Mac / null 期，純計算邏輯，無真實平台後端）／子系統 kernel
- 目錄位置：`src/kernel/e1_10/`
  - `keep_on_screen.hpp` / `keep_on_screen.cpp` — 把 E1-07 `ResolvedPlacement` 夾回
    E1-18 具名螢幕可視範圍的純計算邏輯
  - `CMakeLists.txt` — `add_library(e1_10)`（link e1_07 + e1_18）+ `test_e1_10`
    （`tests/e1/test_e1_10.cpp`）+ `add_test(NAME e1_10)`
- 測試：`tests/e1/test_e1_10.cpp`（gtest，17 案例）
- 對外介面（`namespace ds::kernel`）：
  - `KeepOnScreenStatus`{ Ok, Invalid } —— 結構化結果碼，同 E1-07 `AnchorStatus` 風格。
  - `is_within_screen(placement, screen) -> bool` —— 是否已完全落在螢幕範圍內；無效輸入
    保守回 false。
  - `constrain(placement, screen, out) -> KeepOnScreenStatus` —— 純函式：把 `ResolvedPlacement`
    每軸獨立夾至 `[0, max(0, screen尺寸 - 元件尺寸)]`；不縮放 / 裁切元件，元件大於螢幕時貼齊
    起邊（0）；非有限 / 負值尺寸 → Invalid、不寫 out。
  - `KeepOnScreen`（類別）：綁定 E1-18 `ScreenRegistry`；`constrain_on(screen_id, screen_size,
    placement, out)` 先以具名 `ScreenId` 查 `is_known()`（未知回 Invalid，不猜測其尺寸）再委派
    給 `constrain()`；`knows_screen(screen_id)` 便利查詢。
  - 相依：`anchor_model.hpp`（E1-07：`Size` / `ResolvedPlacement` / `is_finite_size`）、
    `named_screens.hpp`（E1-18：`ScreenId` / `ScreenRegistry`）。
  - NFR-02：核心 API 無硬編絕對座標——`Size` 由呼叫端於計算邊界提供（同 E1-07 `resolve()`
    container 尺寸來源模式）；螢幕一律以 E1-18 具名 `ScreenId` 指涉，不以數字 index。
  - 相位 1 約束：無平台分支、無真實後端、無 `src/kernel/backend/win32|cocoa/`。
