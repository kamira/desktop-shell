# 結構註記 — E2-09 電源與電池狀態

- 層級：module(平台無關指標提供者)／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_09/`
  - `power_status.hpp` / `power_status.cpp` — 充電狀態列舉 + 狀態值模型 + 抽象/注入式來源 +
    提供者實作
  - `CMakeLists.txt` — `add_library(e2_09)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_09`
    (`tests/e2/test_e2_09.cpp`) + `add_test(NAME e2_09)`
- 測試：`tests/e2/test_e2_09.cpp`（gtest，27 案例）
- 上游相依：E2-01 統一指標介面（`engine/metrics/e2_01`）＋ E2-02 採集頻率分級
  （`engine/metrics/e2_02`），皆可讀不可改——消費 `MetricProvider` 契約與 `SamplingTier`
  分級，不自造指標模型或排程器。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「電源 / 電池狀態」透過
  **E2-01 的 `MetricProvider`** 掛成一組指標，並以 **E2-02 的頻率分級**（預設 Low，電源變動
  慢）決定採樣節奏。本單元是最終電池 / 電源 Widget 的核心資料來源。
  - 充電狀態：`ChargeState`（NoBattery/Discharging/Charging/Full，含穩定碼）；`to_string`
    （穩定字串）、`charge_state_label`（顯示標籤）、`charge_state_code`（數值碼）。
  - 狀態值模型：`PowerStatus`（`valid` + `on_ac_power` + `state` + optional 的 `percent` /
    `minutes_remaining` / `cycle_count` / `health_percent`）；工廠 `unknown` / `no_battery` /
    `battery`。以 optional 表達電池專屬讀值有無，無電池桌機即 `valid=true` + `NoBattery` +
    其餘 nullopt。
  - 狀態來源：抽象 `PowerStatSource::sample()→PowerStatus`；`NullPowerStatSource`（相位 1
    null/假「固定狀態」來源，可注入固定狀態，預設無讀值）；`SequencedPowerStatSource`（注入
    狀態序列，模擬狀態演變 / 轉換，列盡回最後一份、空列回無讀值）。**不接真實電源 API**。
  - `PowerProvider : ds::metrics::MetricProvider`：`register_metrics()` 掛上六個**單一實例**
    指標——`power.battery.level`(%, `bounded[0,100]`)、`power.battery.state`(碼+text、無界)、
    `power.ac.online`(1/0、`bounded[0,1]`)、`power.battery.time_remaining`(min、`at_least(0)`)、
    `power.battery.cycles`(可選、`at_least(0)`)、`power.battery.health`(%、`bounded[0,100]`、
    可選)；各保留歷史環。`sample()` 重新讀來源更新各指標（有效值推入歷史、無讀值/缺可選欄位
    設未知）；`sampling_tier()` 回建議採集分級（預設 Low），供 `SamplingScheduler::add_demand`。
  - 核心性質：相位 1（Mac/null 期）平台中立、**無 `#ifdef` / IOKit / IOPowerSources /
    GetSystemPowerStatus / win32 / cocoa** 等真實電源 API；無讀值時以 valid==false（未知）
    誠實表達、不謊報 0；消費者只透過 E2-01 抽象介面走訪，新增此指標掛件一行不動。
