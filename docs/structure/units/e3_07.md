# 結構註記 — E3-07 剪貼簿寫入

- 層級：module(動作層致動器)／子系統 actuators
- 目錄位置：`modules/actuators/e3_07/`
  - `clipboard_write_actuator.hpp` / `clipboard_write_actuator.cpp` — 介面 + null 後端
    + 資料 / 型別模型 + 致動器實作
  - `CMakeLists.txt` — `add_library(e3_07)` **PUBLIC 連上游 `e6_01`**；`test_e3_07`
    (`tests/e3/test_e3_07.cpp`) + `add_test(NAME e3_07)`
- 測試：`tests/e3/test_e3_07.cpp`（gtest，24 案例）
- 上游相依：E6-01 命令匯流排（`engine/command/e6_01`），可讀不可改——消費擴充點 3
  「動作」契約（`CommandBus` / `CommandArgs` / `CommandResult` / `CommandValue`），
  不自造匯流排或值型別。範式與已合併的 E3-05（注入式後端 + null 樣式）一致。
- 對外介面（`namespace ds::actuators`）：一個系統剪貼簿寫入致動器，把「寫入剪貼簿
  （純文字 / HTML / 影像參照）／清空剪貼簿／回讀目前內容」透過 **E6-01 具名命令**掛上
  匯流排（`clipboard.write` / `clipboard.clear` / `clipboard.read`），呼叫端只需 命令 id
  + 具名參數即可觸發，不需相依本致動器。
  - `ClipboardContentType`（Empty / PlainText / Html / ImageRef）+ `clipboard_type_name()`
    / `clipboard_type_from_string()`：多資料型別，平台中立，不含 OS UTI / 格式碼。
  - `ClipboardData`（type + content 字串；含相等運算子、`empty()`、`empty_data()`）。
  - `ClipboardBackend`（抽象後端：`write`/`clear`/`read`——read 可回讀供驗證）、
    `NullClipboardBackend`（相位 1 null / 假後端：**不接真實剪貼簿 API**，純記憶體狀態模擬、
    初值可注入、read 回讀）。
  - `ClipboardWriteActuator`：`register_on(bus)` 掛三命令（回滾語意）、`unregister_from(bus)`、
    三個處理器（缺 / 型別錯 / 空 / 無效必填參數回 Failed，`has()`/`get_string` 保護；成功
    回寫入 / 目前內容）、`current_data()` 內省。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / NSPasteboard /
    OpenClipboard 等真實剪貼簿 API；致動器邏輯（型別 / 內容驗證 / 經 E6-01 分派 / 結果回報）
    與後端完全解耦，換後端不動致動器；空內容視為無效寫入（清空用 clipboard.clear）；
    null 後端狀態一致（read 驗證）。
