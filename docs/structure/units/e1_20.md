# 結構註記 — E1-20 睡眠喚醒復原

- 層級：platform（相位 1 = Mac / null 期，僅介面 + 事件驅動復原，無真實電源 API）／子系統 kernel
- 目錄位置：`src/kernel/e1_20/`
  - `sleep_wake_recovery.hpp` — 平台中立介面：`SleepWakeRecovery` 類別
  - `sleep_wake_recovery.cpp` — 事件處理 / 快照 / 復原邏輯實作
  - `CMakeLists.txt` — `add_library(e1_20)` + `target_link_libraries(e1_20 PUBLIC e1_01 e5_08)`
    + `test_e1_20`（`tests/e1/test_e1_20.cpp`）+ `add_test(NAME e1_20)`
- 測試：`tests/e1/test_e1_20.cpp`（gtest，12 案例）
- 上游相依（可讀不可改）：E1-01 具名圖層堆疊（`LayerStack` / `SurfaceId` / `SurfaceLayer`）、
  E5-08 系統事件（`SystemEventSource` / `SystemEvent` / `SystemSleep` / `SystemWake`）。
- 對外介面（`namespace ds::kernel`）：系統睡眠 / 喚醒後的狀態復原。
  - `SleepWakeRecovery`：訂閱 E5-08，僅 `SystemSleep` / `SystemWake` 觸發（其餘事件忽略）。
    `SystemSleep` 到達時保存目前 `LayerStack` 的具名圖層指派 + 可選 `VisibilityProvider`
    查得的可見性快照（取代前一輪，每輪 sleep 皆全新快照）；`SystemWake` 到達時以
    `LayerStack::assign()` 逐一重建指派（NFR-03：assign 內部已 has(kernel.surface) 閘控，
    能力不可用時保守略過、不崩潰），並對每個「仍有效」的 surface 呼叫可選 `on_wake`
    回呼帶回其應恢復的可見性；若注入 `ResourceValidator` 判定某 surface 於喚醒當下已失效，
    則不重建其指派，改呼叫 `on_invalidated` 通知消費者處理殘留資源。`has()` 代理至注入的
    `LayerStack`。無先前睡眠即收到喚醒：保守 no-op。
  - 相位 1 約束：無平台分支、無真實電源 API（IOKit / SetThreadExecutionState）、無
    backend/win32|cocoa、無絕對座標 / 數字 z-order；狀態全存記憶體。
