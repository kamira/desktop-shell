# 結構註記 — C3-03 角色外觀組

- 單元：C3-03（artifact 層 / 角色外觀 / 皮膚資源組合包 / Risk: low）
- 目錄位置：`content/c3_03/`（C3 系列慣例路徑，深度 2——與 C1/C2 的
  `content/profiles|widgets/<slug>/`（深度 3）不同，見根 CMakeLists GLOB 註解）
- 測試：`tests/c3/test_c3_03.cpp`（CTest 名 `c3_03`，21 個 gtest 案例）

## 放了什麼

- `appearance_set.hpp` / `.cpp`：**組裝型**單元（非新引擎邏輯）——把四個已合併的擴充點組成
  「角色外觀組」：
  - E9-01（`ds::package::Package` / `parse_package` / `validate_package`）：**套件管理**——
    外觀組的宣告式定義即一份 E9-01 套件描述文字；內容清單中 `kind == "look"` 的項目其
    `logical_path` 成為一個具名外觀，其餘 kind 本單元不解讀、原樣保留於 `package()` 供內省。
  - E4-06 `SurfaceSwitcher`：具名外觀的註冊 / 切換（`switch_look` 純委派 `switch_to`，保留
    其精確結果碼）。
  - E1-05 `NamedRegionMap`：各具名外觀個別登記一組互動區域（`set_regions(look, ...)`，以
    具名鍵線性配對，永不以數字 index 對外暴露）。
  - C1-02 `PortraitProfile`：掛載目標——`apply_to(profile)` 把「目前外觀」的互動區域套用到
    一個已載入的立繪 profile，並在該 profile 已註冊同名具名表情時一併切換（儘力而為，不因
    表情不存在而整體失敗）。
  - `AppearanceSet`：本單元加上四個擴充點都沒有的一層行為——把「套件內容清單 → 具名外觀
    註冊」「具名外觀 → 各自互動區域」「目前外觀 → 套用到立繪 profile」串接起來，具名結果
    `AppearanceStatus`（`Ok` / `Invalid` / `AlreadyLoaded`）+ `ApplyStatus`（`Ok` /
    `NoCurrentLook` / `NoRegions` / `ProfileNotLoaded`）。
- `CMakeLists.txt`：`add_library(c3_03 STATIC appearance_set.cpp)` +
  `target_link_libraries(c3_03 PUBLIC c1_02 e1_05 e4_06 e9_01)` + `test_c3_03` +
  `add_test(NAME c3_03)`。不改根 CMakeLists、不自造套件格式或切換狀態機。

## 對外介面（一句話）

`ds::content::AppearanceSet`：`load_appearance_set(套件描述文字)` 解析 / 驗證（E9-01）後
註冊各具名外觀（E4-06）/ `switch_look(name)` 切換目前外觀 / `set_regions(look, NamedRegionMap)`
`regions_for(look)` `current_regions()` 依外觀個別登記互動區域（E1-05）/ `package()` 套件
內省 / `apply_to(PortraitProfile&)` 把目前外觀套用到已載入的 C1-02 立繪 profile（區域 +
儘力而為的表情切換）。相位 1：純資料組合，無真實 GUI、無平台分支（無 `#ifdef` / win32 /
cocoa）、無絕對座標 / 數字 z-order（NFR-02）。
