# 結構註記 — E10-01 本機 IPC 訊息投遞

- 單元：E10-01（engine 層 / ipc / Risk: low）
- 目錄位置：`engine/ipc/e10_01/`（平台中立引擎邏輯，換平台一行不動）
- 測試：`tests/e10/test_e10_01.cpp`（CTest 名 `e10_01`）
- 相依：E6-01 命令匯流排（`target_link_libraries(e10_01 PUBLIC e6_01)`）——重用穩定值型別、可攜命令。

## 放了什麼
- `message_channel.hpp`：本機 IPC 契約 —— `Message`（型別 + 酬載，酬載重用 E6-01 `CommandArgs`；
  `from_command()` 便捷建構）、`MessageType`、`SubscriberId`、`Subscriber`、`MessageChannel`。
  相位 1 為「行程內佇列模型」，不綁真實 socket/pipe/OS IPC。
- `message_channel.cpp`：`contract_version()` 契約版本標記（"e10_01/1.0.0"）；其餘邏輯 header-only inline。
- `CMakeLists.txt`：`add_library(e10_01)` + `PUBLIC e6_01` + `test_e10_01` + `add_test(NAME e10_01)`。

## 對外介面（一句話）
`ds::ipc::MessageChannel` 提供兩種投遞模型：發布訂閱（`subscribe(type,cb)` / `subscribe_all` /
`publish(msg)→投遞數` / `unsubscribe` / `subscriber_count`，依註冊序投遞、無訂閱者回 0 不崩潰）與
點對點佇列（`send` / `receive()→optional`（FIFO，空佇列回 nullopt） / `pending` / `has_pending`）；
兩模型互不干擾，供獨立行程 widget 宿主等以行程內訊息傳遞、並可承載 E6-01 具名命令。
