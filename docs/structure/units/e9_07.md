# 結構註記 — E9-07 拖放安裝

- 目錄位置：`engine/package/e9_07/`（engine 層 / package 子系統）。
- 放了什麼：
  - `drop_install.hpp` / `drop_install.cpp` — 把「拖放一個套件來源 → 安裝」的流程模型化：
    - `InstallSource`（可注入來源抽象）+ `MemoryInstallSource`（相位 1 記憶體實作，可表達「可用」
      或「無效/無法讀取」來源）；`DropEvent`（純資料拖放事件，攜帶套件來源參照）。
    - `InstallRegistry`（記憶體安裝目標，以 manifest.name 為鍵，不覆寫）。
    - `DropInstaller::handle_drop(DropEvent) -> InstallResult`：跑完安裝生命週期
      Received → Resolved → Parsed（E9-01 `parse_package`）→ Validated（E9-01 `validate_package`）
      → Registered，逐階段可回報（`InstallLifecycleListener`），失敗明確報錯不靜默。
  - `CMakeLists.txt` — `add_library(e9_07 STATIC drop_install.cpp)`，
    `target_link_libraries(e9_07 PUBLIC e9_01 e5_08)`；契約測試 `tests/e9/test_e9_07.cpp`
    註冊為 CTest `e9_07`。
- 對外介面一句話：接收拖放事件、解析為 E9-01 套件、跑完安裝生命週期並登錄到記憶體，
  平台中立且錯誤可定位。
- 與 E5-08 的關係：`DropEvent` 沿用 E5-08「純資料、平台中立」的事件風格；`DropInstaller` 於建構時
  訂閱 E5-08 `SystemEventSource`，以 `SessionLocked`/`SystemSleep` 關閉、`SessionUnlocked`/`SystemWake`
  開啟「安裝閘門」——閘門關閉時拒絕拖放安裝（不靜默丟棄）。此路徑實際使用 E5-08 分派實作。
- 平台中立：無 `#ifdef`、無 `win32`/`cocoa`、不接真實 OS 拖放或檔案系統；換平台一行不動。
