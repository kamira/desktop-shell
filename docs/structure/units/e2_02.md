# 結構註記 — E2-02 採集頻率分級與除頻

- 層級：engine（平台中立純邏輯）／子系統 metrics／相依 E2-01（`PUBLIC e2_01`，承重 20x）
- 目錄位置：`engine/metrics/e2_02/`
  - `sampling.hpp` / `sampling.cpp` — 分級 / policy / 排程器 + 除頻合併
  - `CMakeLists.txt` — `add_library(e2_02)` + `target_link_libraries(e2_02 PUBLIC e2_01)` +
    `test_e2_02`（`tests/e2/test_e2_02.cpp`）+ `add_test(NAME e2_02)`
- 測試：`tests/e2/test_e2_02.cpp`（gtest，33 案例）
- 對外介面（`namespace ds::metrics`）：在「一個指標是什麼」（E2-01）之上，決定「一個指標
  **多久採一次**、多消費者要同一指標時**如何合併採集**」。直接關係 NFR-01 idle 門檻。
  - 型別：`Tick`（邏輯時間，非真實時鐘）、`DemandId`（需求票根）、`SamplingTier`
    （high/normal/low/on-demand）。
  - 自由函式：`tier_rank` / `higher_tier` / `is_periodic` / `to_string`。
  - `SamplingPolicy`：分級 → 採集間隔（tick）映射；預設 High=1 / Normal=8 / Low=64，
    OnDemand 非週期；`set_interval` 可調（夾值 >=1）。
  - `SamplingScheduler`：登記需求（`add_demand`/`remove_demand`）、**除頻**（`effective_tier`/
    `effective_interval` = 同一指標所有需求中最高頻者）、tick 排程（`advance(now)` 回此刻
    該採集的指標、決定性順序、跨多間隔不補採）、隨需觸發（`request_now`）。
  - 核心性質：多消費者同一指標**合併成一次採集、按最高需求頻率供給**；閒置久了醒來不補採
    以護 idle 門檻。純邏輯、注入邏輯 tick、無平台分支 / 無真實時鐘。
