# 結構註記 — E7-14 圖形化設定與就地編輯（描述子系統 / E7-12 的應用）

- 單元：E7-14（engine 層 / format / Risk: low / 相依 E7-12，經其相依 E7-01）
- 目錄位置：`engine/format/e7_14/`（平台中立引擎邏輯，換平台一行不動）
- 測試：`tests/e7/test_e7_14.cpp`（CTest 名 `e7_14`）

## 放了什麼
- `editor_model.hpp` / `editor_model.cpp`：把宣告式設定描述成「可編輯欄位模型」並就地套用變更——
  - `EditKind`（Text / Integer / Number / Boolean / Enum / Color）：控制項型別。
  - `EditableField{ path, label, kind, current, constraints }`：單一設定葉節點的完整描述。
  - `EditConstraints`（數值範圍 min/max、列舉選項）+ `FieldHint` / `EditorSchema`：外加語意（Enum /
    範圍 / 自訂標籤）的 schema 覆寫。
  - `build_editor_model(Value/Document[, schema])`：前序走訪 Value 樹，把每個純量葉攤平成欄位清單。
  - `validate_edit(field, new_value)`：型別 / 範圍 / 列舉驗證，違反 → throw（不靜默）。
  - `apply_edit(root, field 或 path, new_value)`：驗證後經 **E7-12 `set_value`** 就地寫回，回傳新樹。
  - `find_field(model, path)`：由路徑回查欄位描述。
- `CMakeLists.txt`：`add_library(e7_14 STATIC editor_model.cpp)` + `target_link_libraries(e7_14 PUBLIC e7_12)`
  + `test_e7_14` + `add_test(NAME e7_14)`。不改根 CMakeLists、不自造格式模型。

## 對外介面（一句話）
`ds::format`：以 `build_editor_model(doc)` 把設定攤平成可編輯欄位（帶控制項型別 / 當前值 / 約束），
使用者編輯後以 `apply_edit(root, field, new_value)` 驗證並經 E7-12 就地寫回（回傳新樹、原樹不動），
再 `serialize` 回文字即保留格式；無效編輯（型別 / 範圍 / 列舉）一律 throw，不靜默失敗。
