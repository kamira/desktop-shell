# 結構註記 — E2-27 螢幕像素取樣

- 層級：module（平台無關指標提供者）／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_27/`
  - `screen_pixel.hpp` / `screen_pixel.cpp` — 介面 + null 後端 + 提供者實作
  - `CMakeLists.txt` — `add_library(e2_27)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_27`
    （`tests/e2/test_e2_27.cpp`）+ `add_test(NAME e2_27)`
- 測試：`tests/e2/test_e2_27.cpp`（gtest，18 案例）
- 上游相依：E2-01 統一指標介面（`engine/metrics/e2_01`）+ E2-02 採集分級與除頻
  （`engine/metrics/e2_02`），皆可讀不可改——消費 `MetricProvider` / `SamplingTier`
  契約、不自造指標模型、不自造時鐘。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「某螢幕位置的像素顏色」
  透過 **E2-01 的 `MetricProvider`** 掛成指標 `screen.pixel`（供環境光 / 取色）。
  - `PixelColor`（r/g/b/a；`luminance()` 正規化 [0,1]、`hex()` "#RRGGBB"）、
    `ScreenAnchor`（**具名取樣位置九宮格，無絕對座標**，NFR-02；`to_string`/`to_label`）、
    `PixelSampleSource`（抽象後端 `sample(anchor)→optional<PixelColor>`）、
    `NullPixelSampleSource`（相位 1 null 後端：不抓螢幕，回無讀值或注入的假像素）。
  - `ScreenPixelProvider : ds::metrics::MetricProvider`：`register_metrics()` 把每個具名
    取樣 anchor 建成一個 `MetricInstance`（value=相對亮度+色碼文字、history=亮度環）；
    `sampling_tier()`（E2-02 分級，預設 Low）、`register_demand(scheduler)` 把採集需求掛進
    E2-02 `SamplingScheduler`（多消費者除頻合併）。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / 真實螢幕擷取；
    核心 API 無絕對座標 / 數字 z-order（NFR-02）；消費者只透過 E2-01 抽象介面走訪，新增此
    指標掛件一行不動。
