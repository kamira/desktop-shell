- 層級：platform（相位 2 = Windows 期）／子系統 host
- 目錄位置：`src/host/win32/`
  - `tray_win32.hpp` / `.cpp` — `Win32TrayBackend`（實作 E11-01 的 `ds::host::TrayBackend`）
    + 自由函式 `build_native_menu()` / `destroy_built_menu()`
  - `CMakeLists.txt` — 整份 `if(WIN32)`；`add_library(w1_02 STATIC tray_win32.cpp)`

- 測試：`tests/e11/test_tray_win32.cpp`（gtest，13 案例；僅 Windows 建置）
- 上游相依（可讀不可改）：E11-01（`TrayBackend` / `TrayMenu` / `TrayMenuItem`，透遞 E6-01）。

## 契約對映

| E11-01 契約 | win32 |
|---|---|
| `set_icon` / `set_tooltip` | `Shell_NotifyIcon(NIM_ADD / NIM_MODIFY)` |
| `set_menu` | `TrayMenu` 模型遞迴轉成 `HMENU`（`AppendMenuW`） |
| `show` / `hide` | `NIM_ADD` / `NIM_DELETE` |
| `has()` | `true`（相位 1 的 `NullTrayBackend` 回 `false`） |
| Checkbox 勾選 | `MF_CHECKED` |
| 停用項 | `MF_GRAYED` |
| 子選單 | `MF_POPUP` + 巢狀 `HMENU` |
| 使用者右鍵 | `TrackPopupMenu(TPM_RETURNCMD)` |

## 兩個設計決定

**自建 message-only 視窗，不借用 W1-01 的 HWND。** 系統匣回呼需要一個視窗收訊息；
本後端自建 `HWND_MESSAGE` 子視窗，因此與 kernel 後端**完全解耦**——托盤能獨立運作，
kernel 後端也不必知道托盤存在。

**只回報「選了哪一項」，不解釋語意。** 契約只有「推送選單給後端」這個方向，
沒有「使用者選了什麼」的回呼（相位 1 的 null 後端沒有真實使用者，不需要）。
真實後端需要，故以**非虛擬**的 `poll_selection()` 提供，回傳**索引路徑**。
Checkbox 切換、命令分派、邊界情形（分隔線 / 停用項 / 未綁命令 / 無匯流排）
全部留給 E11-01 `SystemTray::click(path)`——**選單邏輯一行都不重寫**。

## 可測試性

`build_native_menu()` 抽成自由函式而非私有方法：它不需要匣圖示、不需要使用者互動，
測試可以直接建出 `HMENU` 再用 `GetMenuItemCount` / `GetMenuState` / `GetSubMenu`
斷言結構、勾選狀態、停用狀態、巢狀關係，以及**命令 id → 索引路徑**的對照正確性。

## 測不到的部分

「使用者真的用滑鼠點在托盤圖示上」需要 UI 自動化，單元測試不涵蓋，由操作驗收負責
（CHG-20260803-06）。這裡不寫「呼叫沒崩潰」式的假斷言充數。

## ⚠ 閘門涵蓋缺口

`backend_guard` 的相位閘門只掃 `src/kernel/backend/*`，**不涵蓋 `src/host/win32/`**。
也就是說本目錄的存在不受相位白名單機械保護。加上 `if(WIN32)` 讓 ubuntu CI 看不到本單元，
**本單元的正確性目前完全不在任何閘門守備範圍內**。
