# 結構註記 — E2-03 CPU 負載（總體與每核心）

- 層級：module(平台無關指標提供者)／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_03/`
  - `cpu_load.hpp` / `cpu_load.cpp` — 差分演算法 + 抽象/注入式來源 + 值模型 + 提供者實作
  - `CMakeLists.txt` — `add_library(e2_03)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_03`
    (`tests/e2/test_e2_03.cpp`) + `add_test(NAME e2_03)`
- 測試：`tests/e2/test_e2_03.cpp`（gtest，26 案例）
- 上游相依：E2-01 統一指標介面（`engine/metrics/e2_01`）＋ E2-02 採集頻率分級
  （`engine/metrics/e2_02`），皆可讀不可改——消費 `MetricProvider` 契約與 `SamplingTier`
  分級，不自造指標模型或排程器。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「CPU 使用率」（總體 %
  ＋每邏輯核心 %）透過 **E2-01 的 `MetricProvider`** 掛成指標 `cpu.usage`（一個總體實例
  + 每核心可列舉實例），並以 **E2-02 的頻率分級**決定採樣節奏。本單元是最終 CPU/GPU
  Usage Widget 的核心資料來源，介面刻意乾淨易組合。
  - 值模型：`CpuCoreTicks`（單核累積 busy/total tick）、`CpuTicksSample`（全 CPU 累積
    tick 快照）、`CpuUsageSample`（overall + per_core 使用率比率 [0,1] + valid）。
  - 差分演算法（自由函式，獨立可測）：`core_usage_ratio(prev,curr)`＝busyΔ/totalΔ 夾
    [0,1]（防重置/無經過時間/溢位）；`usage_from_delta(prev,curr)`＝每核比率 + **聚合**
    總體（sum busyΔ / sum totalΔ，以 totalΔ 加權，非算術平均），核心數以共同數對齊。
  - 使用率來源：抽象 `CpuStatSource::sample()→CpuUsageSample`；`NullCpuStatSource`（相位 1
    null/假「直接比率」來源，可注入固定/每核比率，預設無讀值）。
  - tick 來源 + 差分轉接：抽象 `CpuTickSource::read()→CpuTicksSample`；`NullCpuTickSource`
    （注入累積 tick 序列，列盡回最後一份）；`DifferencingCpuStatSource`（把 tick 來源以
    「兩次取樣差分」轉成 `CpuStatSource`，首次取樣回未知——差分至少需兩份）。
  - `CpuLoadProvider : ds::metrics::MetricProvider`：`register_metrics()` 掛上 `cpu.usage`
    （unit="%"、range=`bounded[0,100]`），總體實例 `total`(label "CPU Total") 恆存在，
    每核心實例 `cpu0`/`cpu1`/…(label "Core 0"/…) 依取樣核心數建立（各保留歷史環）；
    `sample()` 重新讀來源更新各實例（使用率推入歷史，核心數增則動態新增實例、減則多出
    者設未知）；`sampling_tier()` 回建議採集分級（預設 High），供 `SamplingScheduler::
    add_demand`。
  - 核心性質：相位 1（Mac/null 期）平台中立、**無 `#ifdef` / host_processor_info /
    /proc/stat / mach / win32 / cocoa** 等真實 CPU API；無讀值時以 valid==false（未知）
    誠實表達、不謊報 0；消費者只透過 E2-01 抽象介面走訪，新增此指標掛件一行不動。
