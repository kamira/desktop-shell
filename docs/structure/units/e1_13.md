# 結構註記 — E1-13 多 profile 實例並存

- 層級：platform（相位 1 = Mac / null 期）／子系統 kernel；建於 E1-01（具名圖層與 z-order
  `LayerStack`）之上（組合，非繼承）。
- 目錄位置：`src/kernel/e1_13/`
  - `profile_instance_registry.hpp` — `ProfileDefinitionId` / `InstanceId`（皆具名字串）、
    `ProfileDefinition`（定義 id + E1-24 `SurfaceProfile`）、`InstantiateStatus`（四態）+
    `to_string`、`InstantiateOutcome`、`ProfileInstance`（單筆實例的獨立狀態）、
    登記表 `ProfileInstanceRegistry`。
  - `profile_instance_registry.cpp` — 登記表全方法（記憶體狀態；組合一個 E1-01 `LayerStack`
    做具名圖層指派）。
  - `CMakeLists.txt` — `add_library(e1_13 STATIC profile_instance_registry.cpp)` +
    `target_link_libraries(e1_13 PUBLIC e1_01)` + `test_e1_13`
    （`tests/e1/test_e1_13.cpp`）+ `add_test(NAME e1_13)`。
- 測試：`tests/e1/test_e1_13.cpp`（gtest，19 案例）。
- 上游相依（可讀不可改）：E1-01 `LayerStack` / `has()` / `layer_of` / `SurfaceLayer`（並間接
  透傳 E1-21 `CapabilityMatrix` 與 E1-24 `SurfaceProfile`）。
- 對外介面（`namespace ds::kernel`）：多 profile 實例並存管理。
  - `ProfileInstanceRegistry`（組合 `LayerStack`，能力矩陣單一資料來源即該 `LayerStack`）：
    `instantiate(definition) -> InstantiateOutcome{status, id}`（自動生成全新具名 id、經
    E1-01 指派圖層、複製獨立 `SurfaceProfile`）/ `get(id)` / `contains(id)` / `list()`
    （建立序）/ `size()` / `empty()` / `max_instances()` / `count_of_definition(id)` /
    `layer_of(id)`（透傳 E1-01）/ `destroy(id)`（先經 `LayerStack.remove` 之 `has()` 閘控）/
    `show(id)` / `hide(id)` / `is_visible(id)`（純本地獨立可見狀態，不涉能力）。
  - 語意：同一 `ProfileDefinition` 可重複 `instantiate` 任意次，每次皆為彼此獨立、互不影響
    的一份新實例（獨立 `SurfaceProfile` 複製 + 獨立 `visible` + 獨立圖層指派）；未知 / 重複
    id、能力不可用、實例額滿皆明確回 `false` / 對應拒絕狀態，不靜默、不崩潰。
  - 相位 1 約束：無平台分支（無 `#ifdef` / win32 / cocoa）、無真實 OS API；`InstanceId` /
    `ProfileDefinitionId` 皆具名指涉，無絕對座標 / 數字 z-order（NFR-02）；`instantiate` /
    `destroy` 皆經 E1-01 `has(kernel.surface)` 閘控（NFR-03）。
