## 契約對映（具名概念 → win32 原語）

| 契約 | win32 |
|---|---|
| `SurfaceId`（具名字串） | 一個 `HWND`（數字 handle 永不對外暴露，NFR-02） |
| `SurfaceLayer::Topmost` / `Overlay` | `SetWindowPos(..., HWND_TOPMOST, ...)` |
| `SurfaceLayer::Wallpaper` / `BelowNormal` | `HWND_BOTTOM` |
| `SurfaceLayer::Normal` | `HWND_NOTOPMOST` |
| `InputPolicy::PassThrough` / `HitPolicy::Transparent` | `WS_EX_TRANSPARENT`（點擊穿透） |
| `show_surface` / `hide_surface` | `ShowWindow(SW_SHOWNOACTIVATE / SW_HIDE)` |
| `poll_input` | `PeekMessage` 迴圈 → 具名 `InputEvent` |
| 「不搶焦點的面板」 | `WS_EX_NOACTIVATE` + `SW_SHOWNOACTIVATE` |

## 兩個要記住的邊界

**NFR-02 怎麼守住**：對外介面一個座標都沒有。`CreateWindowEx` 必須要有 x/y/w/h，
那是**平台實作的內部細節**——由本後端自行選定預設幾何（工作區右上角），
不經 API 傳入、不對外暴露。圖層一律具名，不接受數字層級。

**win32 專屬擴充不屬於契約**：`hwnd_for()` / `pump()` 是非虛擬的額外成員。
kernel 契約刻意沒有繪製 API（繪製必然涉及座標，放進契約會直接違反 NFR-02），
所以「把 render_model 畫上去」只能由 host 拿到原生視窗自己做。
跨平台的上層邏輯不碰這兩個方法；碰它們的程式碼本來就只能在 Windows 上跑。

## ⚠ 未通過 E1-25 契約測試（且目前無法通過）

`tests/contract/` 測的是 `ds::kernel::contract::KernelBackend`——與本後端實作的
`ds::kernel::KernelBackend` 是**兩個不相容的型別**（見 CHG-20260803-03 §契約缺口、知識庫 K-003）。
本單元以 `tests/e1/test_backend_win32.cpp` 自有測試驗證，**不宣稱通過契約測試**。

## ⚠ 不在任何 CI 閘門的守備範圍

`if(WIN32)` 守衛讓 ubuntu CI 完全看不到本單元（否則 G3 必紅）。代價是
**本後端的正確性只有本機 Windows 證據**。要進閘門需加 windows runner
（`docs/backlog/phase2-desktop-runtime.md` §6 checklist 步驟 3）。
