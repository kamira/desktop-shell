# 結構註記 — E9-06 套件卸載流程

- 目錄位置：`engine/package/e9_06/`（engine 層 / package 子系統）。
- 放了什麼：
  - `uninstall.hpp` / `uninstall.cpp` — 把「卸載一個已安裝套件」的流程模型化（E9-07 安裝的逆操作）：
    - `PackageRegistry` — 記憶體套件登錄（E9-07 `InstallRegistry` 的對稱體）：以 manifest.name 為鍵、
      不覆寫；額外持有套件間相依邊（`add(pkg, depends_on)`），支援 `dependents_of()` 反向相依查詢
      與（供 `Uninstaller` 用的）移除。
    - `Uninstaller::uninstall(registry, package_id, force=false) -> UninstallResult`：跑完卸載生命週期
      Located → DependencyChecked → Cleaned → Deregistered，逐階段可回報（`UninstallLifecycleListener`）。
    - `UninstallResult{ status, outcome(Removed/NotFound/BlockedByDependents), stage, removed{package_id,
      components[]}, blocked_by_dependents[], message }`：成功回報被移除套件與其被清理的元件/資源；
      查無套件（含重複卸載第二次）報 NotFound；仍有他人相依則拒絕並列出相依者——皆明確不靜默。
  - `CMakeLists.txt` — `add_library(e9_06 STATIC uninstall.cpp)`，
    `target_link_libraries(e9_06 PUBLIC e9_01)`；契約測試 `tests/e9/test_e9_06.cpp` 註冊為 CTest `e9_06`。
- 對外介面一句話：給定記憶體登錄與 package_id，卸載該套件——相依阻擋/查無套件明確回報、
  回傳被移除項目，平台中立且錯誤可定位。
- 與 E9-07 的關係：E9-07 以 `InstallRegistry` 跑安裝生命週期；E9-06 為其逆操作，僅相依 E9-01
  （套件格式），自帶一個支援「移除 + 相依查詢」的對稱記憶體登錄，不改動已合併的 E9-07。
- 平台中立：無 `#ifdef`、無 `win32`/`cocoa`、無系統呼叫、**無真實檔案系統刪除**；登錄為記憶體模型，
  「清理資源/元件」相位 1 即自登錄登出其內含項目清單；換平台一行不動。
