# 結構註記 — E1-23 分層失敗的手動降級路徑

- 層級：platform（相位 1 = Mac / null 期）／子系統 kernel／單元 slug `e1_23`
- 目錄位置：`src/kernel/e1_23/`
  - `layer_fallback.hpp` — `FallbackReason`（降級原因：None / CapabilityUnavailable /
    AssignRejected / StrategyForced）、`FallbackStrategy`（可注入降級策略：
    `layered_available()` / `flatten_target()`）、`LayerFallbackResult`（結果 struct）、
    `LayerFallback`（`try_layered()` 先試分層失敗自動降級、`fallback_flatten()` 直接
    手動降級、`degrade_reason()` / `last_degraded()` 可見回報）。
  - `layer_fallback.cpp` — 上述介面的純記憶體實作。
  - `CMakeLists.txt` — `add_library(e1_23 STATIC layer_fallback.cpp)`
    + `target_link_libraries(e1_23 PUBLIC e1_01 e1_21)` + `test_e1_23`
    （`tests/e1/test_e1_23.cpp`）+ `add_test(NAME e1_23)`。
- 測試：`tests/e1/test_e1_23.cpp`（gtest，12 案例）。
- 上游相依（可讀不可改）：E1-01 `LayerStack` / `LayerAssign` / `layer_capability()`；
  E1-21 `CapabilityMatrix` / `has()` 能力閘控。
- 對外介面（`namespace ds::kernel`）：分層失敗時的手動降級路徑。
  - `LayerFallback::try_layered(stack, id, requested_layer)`：分層能力不可用或
    `assign()` 失敗時自動降級扁平化；否則正常路徑不降級。
  - `LayerFallback::fallback_flatten(stack, id)`：直接手動降級，忽略請求圖層，
    扁平化到策略決定的具名圖層（預設 `SurfaceLayer::Normal`，無 overlay）。
  - 降級可見性：回傳的 `LayerFallbackResult` 與 `degrade_reason()` / `last_degraded()`
    一律回報是否降級、降級原因、實際 assign 結果與生效圖層，不靜默吞掉。
  - 硬約束：NFR-03 精神——降級決策由 `FallbackStrategy::layered_available()`（預設即
    `has(kernel.surface)`）驅動；NFR-02——全程只用具名圖層 / 具名 surface，無數字
    z-order / 絕對座標；相位 1 無平台分支（無 `#ifdef` / win32 / cocoa）、無真實 OS API。
