# 結構註記 — E1-02 輸入策略四態

- 層級：platform（相位 1 = Mac / null 期）／子系統 kernel；建於 E1-24 K3 輸入原語之上。
- 目錄位置：`src/kernel/e1_02/`
  - `input_strategy.hpp` — 四態具名列舉 `InputStrategy`（Interactive / Capture / ClickThrough /
    Inert）+ `HitResult` / `RouteDecision`；純函式 `hit_result` / `route_decision` /
    `to_backend_policy`（對齊 E1-24 三態 `InputPolicy`）/ `to_string`；`kDefaultStrategy`；
    `capture_capability_id()`；管理器 `InputStrategyController`。
  - `input_strategy.cpp` — 純函式對映 + `InputStrategyController` 全方法（記憶體狀態）。
  - `CMakeLists.txt` — `add_library(e1_02 STATIC input_strategy.cpp)` +
    `target_link_libraries(e1_02 PUBLIC e1_21 backend_null)` + `test_e1_02`
    （`tests/e1/test_e1_02.cpp`）+ `add_test(NAME e1_02)`。
- 測試：`tests/e1/test_e1_02.cpp`（gtest，23 案例）。
- 上游相依（可讀不可改）：E1-24 `KernelBackend` / `InputPolicy` / `InputEvent` / `SurfaceId`
  （K3 輸入原語）；E1-21 `CapabilityId` / `has()`（NFR-03 閘控）。
- 對外介面（`namespace ds::kernel`）：surface 的輸入處理策略四態模型。
  - 四態：`Interactive`（正常接收）/ `Capture`（獨占捕捉）/ `ClickThrough`（點擊穿透到其下）/
    `Inert`（實心命中但吞掉、不下傳）。E1-24 K3 只有三態，本單元多出 `Inert` 並以路由層補足。
  - `InputStrategyController`（持 `KernelBackend&`）：`set_strategy`（含 `has_surface` 前置 +
    `Capture` 能力閘控 + 下推 K3 `set_input_policy`）/ `strategy` / `has_strategy` / `forget` /
    `capture_active` / `route`（跨 surface 逐層解析）/ `poll_and_route`（走 K3 `poll_input`）。
  - 純函式 `hit_result(InputStrategy) -> InputHitResult`（`Solid` / `Transparent`）：該策略下的
    命中測試結果。**型別名為 `InputHitResult`**（CHG-20260730-02 由 `HitResult` 改名）——避免與
    E1-04 幾何命中的 `struct ds::kernel::HitResult` 於同一 `ds::kernel` 命名空間同名不同型別而
    碰撞（下游同時組裝輸入策略側與幾何/E1-16 熱區側的單元原須橋接繞過，改名後根因消除）。
  - 相位 1 約束：無平台分支（無 `#ifdef` / win32 / cocoa）、無真實 OS API、無絕對座標 / 數字
    z-order（surface 具名指涉、堆疊為登記序且不對外暴露數字 index，NFR-02）；Capture 全域獨占
    經 `has(input.capture)` 閘控（NFR-03，null 預設保守不可用）；狀態全存記憶體。
