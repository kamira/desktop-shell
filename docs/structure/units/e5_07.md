# 結構註記 — E5-07 區域內連續拖曳判定

- 層級：engine（平台中立純邏輯，建於上游 E5-14 之上）
- 目錄位置：`engine/events/e5_07/`
  - `region_drag_recognizer.hpp` / `region_drag_recognizer.cpp` — 實作
  - `CMakeLists.txt` — `add_library(e5_07)`（`PUBLIC` 連上游 `e5_14`）+
    `test_e5_07`（`tests/e5/test_e5_07.cpp`）+ `add_test(NAME e5_07)`
- 測試：`tests/e5/test_e5_07.cpp`（gtest，12 案例）
- 對外介面（`namespace ds::events`）：`RegionDragRecognizer` —— 綁定一個 E5-14 具名
  surface（`HitSurface`）+ 其 E1-05 具名子區域集合（`NamedRegionMap`，建構時移交持有；內部
  私有持有一個專屬的 E5-14 `RegionEventDispatcher` 實例，不與外部共用）。呼叫端以
  `feed_down()` / `feed_move()` / `feed_up()`（或統一入口 `feed(PointerAction, position)`）
  逐一注入指標事件序列，判定是否構成「在該具名區域內的連續拖曳」：按下落在區域內 → 起拖
  （分派 `DragEventKind::Begin`）；移動持續落在同一具名區域內 → 分派 `Move`（可多次）；放開
  仍在同一區域內 → 分派 `End`，拖曳正常結束；中途移動離開該區域（或落到別的區域 / 離開整個
  surface）→ 分派 `Cancel`，拖曳中斷；放開時已離開區域 → 同樣分派 `Cancel`（而非 `End`）。
  `subscribe()` / `unsubscribe()` / `listener_count()` 訂閱拖曳語意事件（`DragEvent`）；
  `dragging()` / `active_region()` 查詢目前狀態。狀態機不亂序：非拖曳中的 `feed_move()` /
  `feed_up()` 為 no-op；拖曳中重複 `feed_down()` 為 no-op（不重新起拖）。區域命中判定 /
  具名子區域查詢完全委派上游 E5-14（其再委派 E5-01 + E1-05），本單元只新增「連續拖曳」這一
  層狀態機語意（Begin/Move/End/Cancel 轉移判定）。
