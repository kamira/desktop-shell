# 結構註記 — E3-05 音量設定

- 層級：module(動作層致動器)／子系統 actuators
- 目錄位置：`modules/actuators/e3_05/`
  - `volume_actuator.hpp` / `volume_actuator.cpp` — 介面 + null 後端 + 狀態模型 + 致動器實作
  - `CMakeLists.txt` — `add_library(e3_05)` **PUBLIC 連上游 `e6_01`**；`test_e3_05`
    (`tests/e3/test_e3_05.cpp`) + `add_test(NAME e3_05)`
- 測試：`tests/e3/test_e3_05.cpp`（gtest，21 案例）
- 上游相依：E6-01 命令匯流排（`engine/command/e6_01`），可讀不可改——消費擴充點 3
  「動作」契約（`CommandBus` / `CommandArgs` / `CommandResult` / `CommandValue`），
  不自造匯流排或值型別。範式與已合併的 E3-02（注入式後端 + null 樣式）一致。
- 對外介面（`namespace ds::actuators`）：一個系統音量致動器，把「設定音量 0–100 /
  靜音 / 取消靜音 / 相對增減 / 查詢目前音量」透過 **E6-01 具名命令**掛上匯流排
  （`volume.set` / `volume.get` / `volume.mute` / `volume.unmute` / `volume.adjust`），
  呼叫端只需 命令 id + 具名參數即可觸發，不需相依本致動器。
  - `kVolumeMin=0` / `kVolumeMax=100` / `clamp_volume(int)`：致動器層唯一的夾限點
    （相對值域，非絕對座標 / z-order）。
  - `VolumeState`（level 恆在 [0,100] + muted；含相等運算子）。
  - `VolumeBackend`（抽象後端：`set`/`get`/`set_muted`/`is_muted`）、`NullVolumeBackend`
    （相位 1 null / 假後端：**不接真實系統音訊 API**，純記憶體狀態模擬、初值可注入、
    `set()` 自夾限）。
  - `VolumeActuator`：`register_on(bus)` 掛五命令（回滾語意）、`unregister_from(bus)`、
    五個處理器（缺 / 型別錯必填參數回 Failed，`has()`/`get_int` 保護；成功回夾限後音量）、
    `current_state()` 內省。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / CoreAudio 等
    真實音訊 API；致動器邏輯（夾限 / 經 E6-01 分派 / 結果回報）與後端完全解耦，換後端不動
    致動器；靜音不改變音量位階；null 後端狀態一致。
