# 結構註記 — E8-01 腳本引擎（QML/JS）

- 層級：engine(平台中立純邏輯)；描述子系統的**腳本引擎抽象與嵌入介面**（相依已合併的
  E6-01；`ScriptValue` 沿用其 `CommandValue`，命令橋接分派其 `CommandBus`）。
- 目錄位置：`engine/script/e8_01/`
  - `script_engine.hpp` / `script_engine.cpp` — 實作
  - `CMakeLists.txt` — `add_library(e8_01)` + `target_link_libraries(e8_01 PUBLIC e6_01)`（消費上游）
    + `test_e8_01`（`tests/e8/test_e8_01.cpp`）+ `add_test(NAME e8_01)`
- 測試：`tests/e8/test_e8_01.cpp`（gtest，35 案例）
- 對外介面（`namespace ds::script`）：讓概念上 QML/JS 風格的腳本能載入、執行、與宿主互動。
  - `ScriptEngine`：**可插拔的純虛抽象介面**——`evaluate(script)`（載入 / 執行腳本文字）、
    `bind_function(name, fn)`（綁定宿主函式）、`set_global` / `get_global`（暴露 / 讀寫全域）、
    `call(name, args)`（宿主驅動呼叫已綁定函式）、`has_function`、`backend_name`。
  - `MiniScriptEngine`：相位 1 **最小內建直譯器**，支援逐行腳本（`set <name>=<expr>` /
    `<name>=<expr>` / `<call>` / 裸 `<expr>` / `#` 註解；字面值 int/double/string/bool/null +
    全域參照 + 具名呼叫）——足以驗證嵌入契約。
  - `NullScriptEngine`：相位 1 **null/mock 後端**，實作同一介面（保存全域 / 綁定 / 可 `call`），
    但 `evaluate` 明確回 `Unsupported`（不執行腳本文字，不靜默）——示範可插拔替換。
  - `ScriptValue`（= E6-01 `CommandValue`）；`HostResult` / `HostFunction`（腳本 → 宿主回呼）；
    `EvalResult`（二選一：值 / `ScriptError{None,Syntax,Runtime,NotFound,Unsupported}` + 訊息 + 行號）。
  - `make_command_binding` / `bind_command`：把 E6-01 命令一行式暴露為腳本函式（位置引數對映
    具名參數 → `CommandBus::dispatch` → `CommandResult` 轉 `HostResult`）。
- 定位：把腳本引擎的**抽象與嵌入 API** 先立好（載入 / 執行 / 綁宿主函式 / 讀寫全域 / 呼叫 /
  經 E6-01 分派命令），相位 1 以最小 / mock 後端完整驗證契約；真實 QML/JS 後端（V8/QuickJS/
  QJSEngine）留待相位 2 掛上同一 `ScriptEngine` 介面。
- **語法 / 執行期錯誤（未定義全域 / 未綁定函式 / 宿主函式失敗 / 命令分派失敗 / 後端不支援）
  一律帶種類 + 訊息 + 行號明確回報、不靜默**（NFR-04 精神）。平台中立、無 `#ifdef`、
  無真實 JS 後端。
