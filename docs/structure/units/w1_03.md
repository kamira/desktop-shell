## 拖曳如何實作

`WM_NCHITTEST` 在命中客戶區且該 surface 可拖時回 **`HTCAPTION`**——
等於告訴 Windows「整個視窗本體就是標題列」。`DefWindowProc` 收到 `HTCAPTION` 的
`WM_NCLBUTTONDOWN` 後會**自行進入系統的移動迴圈**。

因此不必自己算滑鼠位移，也**自動獲得系統既有的拖曳行為**（邊緣吸附、跨螢幕、DPI 切換）。
自己實作位移追蹤會失去這些，而且必然寫得比系統差。

拖曳結束由 `WM_EXITSIZEMOVE` 判定（系統移動迴圈退出 = 使用者放開滑鼠），
以具名 SurfaceId 推入佇列供 `poll_drag_finished()` 取走。

## 新增的 win32 專屬擴充（皆非契約的一部分）

| 方法 | 用途 |
|---|---|
| `set_draggable` / `is_draggable` | 可拖曳性閘控。**新建 surface 預設不可拖**（保守） |
| `surface_origin` / `set_surface_origin` | 讀 / 寫視窗左上角螢幕座標 |
| `surface_size` | 讀視窗外框尺寸（AnchorSpec 換算需要元件尺寸） |
| `work_area` | 工作區原點與尺寸（AnchorSpec 換算需要容器尺寸） |
| `poll_drag_finished` | 取走「使用者剛拖完」的通知 |

**為什麼位置 API 只能是擴充**：`KernelBackend` 硬性禁止絕對座標（NFR-02），
契約層永遠不會有 `set_position(x, y)`。位置在系統中的正規表達是 E1-08 的 `AnchorSpec`
（具名錨點 + 容器尺寸的正規化分數），像素只在**佈局邊界**出現——
而平台實作內部正是那個邊界。AnchorSpec ↔ 像素的換算由 host（H1-03）負責。

## 兩個容易錯的細節

- `set_surface_origin` 帶 **`SWP_NOZORDER`**：搬位置不得順手改變圖層，
  否則「還原位置」會把最上層設定弄掉。已有測試釘住。
- 點擊穿透（`WS_EX_TRANSPARENT`）開啟時視窗**收不到滑鼠訊息**，
  因此自動不可拖，不需在 `WM_NCHITTEST` 另外判斷輸入策略。
