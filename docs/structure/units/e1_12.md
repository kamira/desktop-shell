# 結構註記 — E1-12 多重從屬 surface 並存

- 層級：platform（相位 1 = Mac / null 期）／子系統 kernel／單元 e1_12
- 目錄位置：`src/kernel/e1_12/`（根 CMakeLists 以層級 GLOB `src/*/*/CMakeLists.txt` 深度 2 自動收入）
  - `multi_subordinate_manager.hpp` — 介面：`MultiSubordinateManager`（一個父同時掛多個從屬
    surface 的管理層）：`attach_child(parent, child, spec, child_element)` /
    `children_of(parent)` / `reposition_all(parent, parent_placement)` / `detach_child(child)` /
    `detach_all(parent)`；查詢 `has_children` / `child_count` / `is_attached` / `parent_of` /
    `spec_of` / `element_size_of` / `attachment_count`
  - `multi_subordinate_manager.cpp` — 多子並存的列舉 / 批次操作實作，以組合方式持有一個 E1-11
    `SubordinateLayout` 作父子附著 + 相對定位的唯一真實來源，額外維護每子的元件尺寸記錄
  - `CMakeLists.txt` — `add_library(e1_12 STATIC multi_subordinate_manager.cpp)` +
    `target_link_libraries(e1_12 PUBLIC e1_11)` + `test_e1_12`（`tests/e1/test_e1_12.cpp`）+
    `add_test(NAME e1_12)`
- 測試：`tests/e1/test_e1_12.cpp`（gtest，18 案例）
- 上游相依（可讀不可改）：E1-11（`PUBLIC` 連結）→ 傳遞取得 `SubordinateLayout` / `AnchorSpec` /
  `Size` / `ResolvedPlacement` / `AnchorStatus` 及具名 `SurfaceId` 模型（經 E1-07 / E1-03 / E1-24
  傳遞）。
- 對外介面（`namespace ds::kernel`）：**一個父 surface 可同時掛多個從屬（子）surface 並存的
  管理層**——tooltip + 下拉選單 + 標註等可同時依附於同一個父，各自以 E1-11 定位、獨立管理、
  避免衝突：
  - `attach_child`：附著一個子到 parent（同 E1-11 `attach` 語意：空 id / 自附 / 循環 / spec
    無效 → `Invalid` 不記錄；同 child 再次呼叫為就地更新，不產生第二筆並存記錄），並記錄其元件
    尺寸（非有限 / 負值 → `Invalid`，不留半吊子附著）供 `reposition_all` 批次使用。
  - `children_of`：列舉 parent 目前所有直接子，依附著順序回傳（具名 `vector<SurfaceId>`，不以
    數字 index 對外暴露）。
  - `reposition_all`：給定 parent 的新已解析矩形，一次性批次重新解析其下所有子的絕對佈局
    （「父移動時全部跟隨」的便利入口；底層 E1-11 本就不快取座標，本方法只是包一層「對每個子
    呼叫一次 `resolve_child`」）。
  - `detach_child`：個別關閉單一子（不影響同 parent 下其餘子），成功時同步清除該子的元件尺寸
    記錄。
  - `detach_all`：委由 E1-11 `close_parent` 一次關閉 parent 底下所有直接 / 間接子（含巢狀從屬
    鏈），回傳清除筆數；一併清除所有隨之連帶移除之子的元件尺寸記錄，不留孤兒資料。
  - 錯誤：復用 E1-11 / E1-07 `AnchorStatus`（不新增列舉），不靜默、不崩潰。
  - 相位 1 約束：無平台分支（無 `#ifdef`）、無真實 OS / 視窗 / 繪圖 API、
    無 `src/kernel/backend/win32|cocoa/`；純記憶體 / 純管理邏輯。
