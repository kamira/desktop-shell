## E11-02 已經做完的部分

模型、排版、相對幾何、鍵盤與滑鼠巡覽全在 E11-02，且**平台中立**。
本單元只補兩件事：把渲染描述用 GDI 畫進真實視窗、把真實輸入路由回 `hover()` / `select()`。

## 兩個模型之間的轉換

E11-01 `TrayMenu` 與 E11-02 吃的 E7-13 `Item` 森林是不同模型，故需 `tray_menu_to_items()`。
兩者都是既有契約，**不新增第三個模型**。

兩個容易錯的地方：
- **分隔線沒有命令 id**，但 E11-02 要求 id 唯一 → 以索引合成穩定 id
- **`checked` 只有 checkbox 項可用**（E11-02 檔頭明載）→ 對其他種類帶上會讓
  `build_menu` 整份失敗。初版對每一項都塞，`set_menu` 直接回 `false`

## ⚠ 與原生 HMENU 的取捨

原生選單**免費**提供：鍵盤巡覽、螢幕閱讀器無障礙、IME、DPI 縮放、邊緣翻轉、子選單定位。
自繪要自己重做。本單元做了鍵盤巡覽（委由 E11-02）與邊緣翻轉，
**但沒有做無障礙（UI Automation / MSAA）——螢幕閱讀器讀不到這個選單。**

這是真實的功能退步，不是尚未測試的細節。`Win32TrayBackend::set_owner_drawn()`
預設為 **false**（保守），由 host 明確開啟；要退回原生選單只需拿掉 host 的那一行。

**子選單目前不展開子面板**（僅以右側箭頭示意）。托盤選單沒有子選單，故不影響現況。

## 可測試性

`tray_menu_to_items` / `place_menu_popup` / `paint_menu_panel` 皆為自由函式：
轉換與幾何是純邏輯，繪製以記憶體 DIB 讀像素驗證（分隔線有畫、未巡覽時無高亮）。
「使用者真的用滑鼠點選單」需要 UI 自動化，由操作驗收負責。
