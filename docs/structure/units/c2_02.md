# 結構註記 — C2-02 系統狀態 widget

- 單元：C2-02（artifact 層 / widget / Risk: low）
- 目錄位置：`content/widgets/c2_02/`
- 測試：`tests/c2/test_c2_02.cpp`（CTest 名 `c2_02`，27 個 gtest 案例）

## 放了什麼

- `system_status_widget.hpp` / `.cpp`：`namespace ds::widgets`。**組裝型**單元（非新引擎
  邏輯，亦是最終 CPU/GPU Usage 驗證器的核心前身）——桌面「系統狀態」widget，把七個已合併的
  擴充點組成一個具名 widget：
  - C1-01 `SkinProfile`：桌面基底（具名圖層歸屬 / 輸入策略 / 透明外形 / 自由拖曳皆透傳，
    以 `base()` 存取，本單元不重造）。
  - E2-01：**唯一的指標讀取入口**——`MetricRegistry::get(id)` / `Metric` / `MetricInstance`
    抽象契約；消費者不寫死任何具體感測器（CPU/GPU/RAM/儲存/網路/電池/IO…皆可選，新增指標
    只需在宣告式 `metrics:` 清單多加一筆）。
  - E2-02：`SamplingScheduler` 除頻排程——`sync_demands()`/`release_demands()` 依各指標
    宣告式 `tier` 登記 / 撤銷取樣需求。
  - E7-03：`build_scope()` 由宣告式設定的 `vars:` 段落建立具名常數作用域。
  - E7-05：`Evaluator` 求值 min/max 靜態公式（configure 時）與 transform 動態公式（refresh
    時，`value` 綁定為當次指標原始值），供單位換算等格式化。
  - E4-03：把指標值依範圍組裝為 `Bar`/`Gauge`/`Progress` 渲染描述（`RenderModel`）。
  - E4-01：把「標籤: 格式化值」文字排版為渲染描述（相對佈局，NFR-02）。
- `CMakeLists.txt`：`add_library(c2_02)` + `target_link_libraries(c2_02 PUBLIC c1_01 e2_01
  e2_02 e4_01 e4_03 e7_03 e7_05)` + `test_c2_02`（`tests/c2/test_c2_02.cpp`）+
  `add_test(NAME c2_02)`。

## 對外介面（一句話）

`ds::widgets::SystemStatusWidget`（注入 `KernelBackend&` + `LayerStack&` + `FontMetrics&`）：
`configure(Value: vars/metrics)` 宣告式選一組指標與其呈現方式（種類 / 範圍 / 單位換算公式 /
取樣分級）→ 選擇性 `sync_demands(scheduler)` 登記取樣需求 → `refresh(MetricRegistry)` 經注入
指標來源讀值（**指標不存在 / 值無效 / 公式失敗一律優雅降級，NFR-03，不中止其餘指標**）→
`render()` 組裝 E4-03 元素 + E4-01 文字渲染描述（`render_model()` 查詢）。相位 1：純資料 /
邏輯組裝，無真實感測器讀取、無真實字型光柵化、無平台分支（無 `#ifdef` / win32 / cocoa）、
無絕對座標 / 數字 z-order（NFR-02）。
