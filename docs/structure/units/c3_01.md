# 結構註記 — C3-01 啟動器選單樹

- 單元：C3-01（artifact 層 / 啟動器 launcher / Risk: low）
- 目錄位置：`content/c3_01/`（C3 系列慣例路徑，深度 2——與 C1/C2 的
  `content/profiles|widgets/<slug>/`（深度 3）不同，見根 CMakeLists GLOB 註解）
- 測試：`tests/c3/test_c3_01.cpp`（CTest 名 `c3_01`，19 個 gtest 案例）

## 放了什麼

- `launcher_menu_tree.hpp` / `.cpp`：**組裝型**單元（非新引擎邏輯）——把三個已合併的擴充
  點組成「啟動器選單樹」：
  - C1-05（`ds::profiles::SummonPanelProfile&`，本單元掛載其上）：重用其選項森林儲存
    （`set_items()` / `items()`，本身即透傳 E7-13 `build_forest`），本單元不另存一份樹。
  - E7-13（`ds::format::Item` / `Value`，經 C1-05 透傳，亦直接 include）：選單的階層式
    資料模型。
  - E3-02（經 E6-01 `CommandBus&` 注入式分派）：葉節點選取時的啟動後端——相位 1「注入式
    啟動後端」，本單元不建立 / 擁有匯流排或致動器，只消費呼叫端已掛好的具名命令。
  - `LauncherMenuTree`：本單元加上 C1-05 / E7-13 都沒有的兩層行為——
    1. 展開 / 收合狀態追蹤（`expand` / `collapse` / `is_expanded` / `expanded_count`，
       純資料 `std::set<std::string>`，對不存在 id / 葉節點 / 重複操作一律回 false）。
    2. 「選取葉節點 = 透過 E3-02 啟動」（`select` / `activate`，具名結果 `SelectOutcome`：
       `Activated` / `ActivationFailed` / `NotLeaf` / `NotFound`）。
  - `make_launch_program_value` / `make_open_file_value` / `make_web_search_value`：便捷
    工廠，直接对齐 E3-02 三個具名命令 id 與參數鍵名，供組宣告式選單樹使用。
- `CMakeLists.txt`：`add_library(c3_01 STATIC launcher_menu_tree.cpp)` +
  `target_link_libraries(c3_01 PUBLIC c1_05 e7_13 e3_02)` + `test_c3_01` + `add_test(NAME c3_01)`。
  不改根 CMakeLists、不自造項目樹模型。

## 對外介面（一句話）

`ds::content::LauncherMenuTree(SummonPanelProfile&, CommandBus&)`：`load_menu(Value / vector
<Item>)` 委派 C1-05 建構選單森林 / `expand(id)` `collapse(id)` `is_expanded(id)` 展開狀態
（本單元自有）/ `select(id)` `activate(id)` 選取或直接啟動葉節點（葉節點 `value` 以保留鍵
`command` + `args` 描述啟動意圖，經 E6-01 `CommandArgs` 轉譯後分派到注入的 `CommandBus`，
典型掛了 E3-02 `LaunchActuator`）；非葉節點選取回 `NotLeaf`，不啟動；不存在 id 回
`NotFound`。相位 1：純資料結構 + 注入式啟動後端，無真實 GUI、無真實啟動、無平台分支
（無 `#ifdef` / win32 / cocoa）、無絕對座標 / 數字 z-order（NFR-02）。
