# 結構註記 — E3-03 媒體播放控制

- 層級：module(動作層致動器)／子系統 actuators
- 目錄位置：`modules/actuators/e3_03/`
  - `media_control_actuator.hpp` / `media_control_actuator.cpp` — 介面 + null 後端 +
    狀態模型 + 致動器實作
  - `CMakeLists.txt` — `add_library(e3_03)` **PUBLIC 連上游 `e6_01` 與 `e2_13`**；
    `test_e3_03`（`tests/e3/test_e3_03.cpp`）+ `add_test(NAME e3_03)`
- 測試：`tests/e3/test_e3_03.cpp`（gtest，18 案例）
- 上游相依（皆可讀不可改）：
  - E6-01 命令匯流排（`engine/command/e6_01`）——消費擴充點 3「動作」契約
    （`CommandBus` / `CommandArgs` / `CommandResult` / `CommandValue`），不自造匯流排或值型別。
  - E2-13 媒體播放中繼資料（`modules/sysinfo/e2_13`）——重用平台中立播放狀態詞彙
    `ds::sysinfo::PlaybackState` / `state_rank` / `to_string`；與讀取端**對稱**
    （E2-13 讀狀態、E3-03 下控制），不自造播放狀態模型。
  - 範式與已合併的 E3-05（注入式後端 + null 樣式）一致。
- 對外介面（`namespace ds::actuators`）：一個媒體控制致動器，把「播放 / 暫停 / 上一首 /
  下一首 / 停止 / 切換播放暫停 / 設定音量」透過 **E6-01 具名命令**掛上匯流排
  （`media.play` / `media.pause` / `media.next` / `media.prev` / `media.stop` /
  `media.toggle` / `media.volume`），呼叫端只需 命令 id + 具名參數即可觸發，不需相依本致動器。
  - `kMediaVolumeMin=0` / `kMediaVolumeMax=100` / `kMediaVolumeUnset=-1` /
    `clamp_media_volume(int)`：致動器層唯一的音量夾限點（相對值域，非絕對座標 / z-order）。
  - `MediaControlState`（playback 詞彙同 E2-13 + track_index>=0 + volume；含相等運算子）。
  - `MediaControlBackend`（抽象後端：`play`/`pause`/`next`/`prev`/`stop`/`set_state` +
    `set_volume`/`volume`）、`NullMediaControlBackend`（相位 1 null / 假後端：**不接真實
    媒體控制 API**，純記憶體狀態模擬、初值可注入、prev 於 0 夾住、`set_volume` 自夾限）。
  - `MediaControlActuator`：`register_on(bus)` 掛七命令（回滾語意）、`unregister_from(bus)`、
    七個處理器（toggle 在致動器層依 state 判定切換；缺 / 型別錯必填參數回 Failed，
    `has()`/`get_int` 保護；播放類回 state_rank + to_string，volume 回夾限後音量）、
    `current_state()` / `playback_state()` 內省。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / MediaRemote /
    MPRIS / SMTC 等真實媒體控制 API；致動器邏輯（命令 / 經 E6-01 分派 / toggle 判定 /
    結果回報 / 音量夾限）與後端完全解耦，換後端不動致動器；與 E2-13 共用播放狀態詞彙。
