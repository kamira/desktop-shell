# 結構註記 — C2-10 網頁 widget

- 單元：C2-10（artifact 層 / widgets / Risk: low / lb=0 / 相依 C1-01、E10-05）
- 目錄位置：`content/widgets/c2_10/`
- 測試：`tests/c2/test_c2_10.cpp`（CTest 名 `c2_10`，29 個 gtest 案例）

## 放了什麼

- `web_widget.hpp` / `.cpp`（`namespace ds::widgets`）：**組裝型**單元（非新引擎邏輯）——把
  兩個已合併的擴充點組成「網頁」桌面 widget：
  - C1-01 `SkinProfile`：本 widget 的桌面殼層基底（圖層 / 定位 / 拖曳），透過 `shell()` 暴露，
    由呼叫端直接驅動。
  - E10-05 `WidgetHost`：本 widget「網頁內容」的隔離行程宿主（相位 1 無真實瀏覽器引擎）——
    `configure`/`load`/`reload` 皆委派其 `start`/`restart`/`stop`；是否嘗試橋接畫面
    surface 一律先經 `surface_capable()`（NFR-03，`has()`/`supported()` 保護，從不盲目呼叫）。
  - `WebWidget`：`configure(Value)` 消費 E7-01 宣告式 `{url: string}` 設定目標 URL、
    `load(injected_content)` 以呼叫端注入的內容模擬一次載入、`reload()` 重啟內容行程、
    `loading_state()` 具名狀態機（Idle/Configured/Loading/Loaded/Degraded/Failed）、
    `render_model()` 純文字模型。
- `CMakeLists.txt`：`add_library(c2_10)` + `target_link_libraries(c2_10 PUBLIC c1_01 e10_05)` +
  `test_c2_10`（`tests/c2/test_c2_10.cpp`）+ `add_test(NAME c2_10)`。

## 對外介面（一句話）

`ds::widgets::WebWidget`（注入 `KernelBackend&` + `LayerStack&` + `ProcessLauncher&` +
`MessageChannel&` + 選填 `AlphaSurfaceService*`）：`configure(Value{url})` 設定 URL（無效 →
`Invalid`，不改動狀態）/ `load(content)` 注入內容模擬載入（依 `surface_capable()` 閘控結果
分為完整 `Loaded` 或降級 `Degraded`，NFR-03，能力後端缺席或不支援皆優雅降級不崩潰）/
`reload()` 重啟內容行程並等待重新 `load()` / `loading_state()` 具名狀態 / `render_model()`
文字呈現；`shell()` 存取 C1-01 桌面殼層、`host()` 存取 E10-05 行程宿主。無效操作一律回具名
`WebWidgetStatus`（Invalid / Unsupported / NotConfigured / HostError），不靜默。相位 1：純
資料 / 邏輯組裝，無真實 GUI、無平台分支、無真實瀏覽器引擎、無絕對座標 / 數字 z-order
（NFR-02）。
