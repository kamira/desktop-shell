# 結構註記 — E2-19 行程監看

- 層級：module（平台無關指標提供者）／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_19/`
  - `process_monitor.hpp` / `process_monitor.cpp` — 值模型 + 排序邏輯 + 來源抽象 +
    null 後端 + 提供者實作
  - `CMakeLists.txt` — `add_library(e2_19)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_19`
    （`tests/e2/test_e2_19.cpp`）+ `add_test(NAME e2_19)`
- 測試：`tests/e2/test_e2_19.cpp`（gtest，23 案例）
- 上游相依：E2-01 統一指標介面（`engine/metrics/e2_01`）+ E2-02 採集頻率分級
  （`engine/metrics/e2_02`），皆可讀不可改——消費 `MetricProvider` / `SamplingTier` 契約、
  不自造指標模型或排程器。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「執行中行程列表」透過
  **E2-01 的 `MetricProvider`** 掛成指標（依排序維度 `proc.cpu` / `proc.memory`），支援
  top-N 排序、E2-02 週期採樣。
  - `ProcessStatus`（狀態列舉）/ `ProcessSortKey`（Cpu/Memory）、`ProcessInfo`（pid / 名稱 /
    CPU% / 記憶體 / 狀態五欄位）、`ProcessSample`（快照 + valid=無讀值旗標）。
  - 自由函式 `process_sort_value` / `top_processes`（依維度由高到低、pid 決定性、top_n）。
  - `ProcessSource`（抽象後端 `sample()`）、`NullProcessSource`（相位 1 null 後端：不列舉
    系統，回無讀值或注入的假快照 / 快照序列）。
  - `ProcessMonitorProvider : ds::metrics::MetricProvider`：`register_metrics()` 把 top-N
    每個行程建成一個 `MetricInstance`（pid=id、名稱=label、排序維度值=value、狀態=text）；
    `sample()` 重讀更新（動態新增新 pid、缺席 pid 設未知）。
  - 核心性質：相位 1（Mac/null 期）平台中立、無 `#ifdef` / win32 / cocoa / sysctl / /proc /
    EnumProcesses / 真實行程 API；無讀值誠實 invalid；消費者只透過 E2-01 抽象介面走訪，
    新增此指標掛件一行不動。
