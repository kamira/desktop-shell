# 結構註記 — E7-09 缺席模組的降級解析

- 層級：engine（平台中立純邏輯）；stage A / risk low；depends_on = [E7-01, E9-02]。
- 目錄位置：`engine/format/e7_09/`
  - `fallback.hpp` / `fallback.cpp` — 實作
  - `CMakeLists.txt` — `add_library(e7_09)` + `target_link_libraries(e7_09 PUBLIC e7_01 e9_02)`
    + `test_e7_09`（`tests/e7/test_e7_09.cpp`）+ `add_test(NAME e7_09)`
- 測試：`tests/e7/test_e7_09.cpp`（gtest，11 案例）
- 對外介面（`namespace ds::format`）：宣告式文件引用缺席模組時的優雅降級解析。
  - `ModuleAvailability`（可注入介面，`has(id)`）；`ModuleSet`（明確集合）、`FnAvailability`（函式）、
    `available_from_manifests(installed)`（由 E9-02 `Manifest.name` 清單建立可用集合）。
  - `DegradeNote{module_id, path, message}`、`DegradeResult{value, missing[], notes[], degraded()}`。
  - `resolve_with_fallback(Value, const ModuleAvailability&) -> DegradeResult`：走訪 `Value` 樹，
    以慣例欄位 `module`（`kModuleKey`）辨識模組區塊；缺席者以**停用佔位節點**取代
    （保留 module id + `disabled: true` + `degraded_reason`），可用者原樣保留並續遞迴巢狀引用；
    所有缺席決策**可見、不靜默**（去重 `missing` + 逐次 `notes`，含巢狀）。
- 定位：消費 E7-01 根契約（`Value`）與 E9-02 模組清單（`Manifest`）；把「引用缺席模組」從硬失敗
  轉為可用的降級結果 + 可顯示的決策清單。平台中立、無 `#ifdef`、無絕對座標 / z-order。
