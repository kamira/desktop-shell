# 結構註記 — E2-15 音訊峰值與頻譜

- 層級：module(平台無關指標提供者)／子系統 sysinfo
- 目錄位置：`modules/sysinfo/e2_15/`
  - `audio_levels.hpp` / `audio_levels.cpp` — 電平計算（自由函式）+ 抽象/注入式來源 + 值模型
    + 提供者實作
  - `CMakeLists.txt` — `add_library(e2_15)` **PUBLIC 連上游 `e2_01` `e2_02`**；`test_e2_15`
    (`tests/e2/test_e2_15.cpp`) + `add_test(NAME e2_15)`
- 測試：`tests/e2/test_e2_15.cpp`（gtest，28 案例）
- 上游相依：E2-01 統一指標介面（`engine/metrics/e2_01`）＋ E2-02 採集頻率分級
  （`engine/metrics/e2_02`），皆可讀不可改——消費 `MetricProvider` 契約與 `SamplingTier`
  分級，不自造指標模型或排程器。
- 對外介面（`namespace ds::sysinfo`）：一個 sysinfo 指標提供者，把「音訊視覺化資料」（峰值
  電平、RMS、頻譜頻段能量）透過 **E2-01 的 `MetricProvider`** 掛成三個指標，並以 **E2-02 的
  頻率分級**決定採樣節奏。本單元是最終音訊等化器 / 電平表 Widget 的核心資料來源，介面刻意
  乾淨易組合。
  - 值模型：`AudioLevelSample`（`peak` 峰值 + `rms` RMS，皆線性振幅 [0,1]；`bands` 各頻段
    能量 [0,1]；`valid`；`unknown()` = 無讀值）。頻段數可在取樣間變動。
  - 電平計算（自由函式，獨立可測、純算術）：`peak_of(pcm)`＝max|x| 夾 [0,1]；`rms_of(pcm)`＝
    sqrt(mean x^2) 夾 [0,1]；`linear_to_db(amp, floor_db=-120)`＝20*log10，靜音 / 極小值夾到
    下限（避免 -∞）。
  - 電平來源：抽象 `AudioLevelSource::sample()→AudioLevelSample`；`NullAudioLevelSource`（相位
    1 null / 假來源，持注入電平序列，列盡回最後一份、空列回無讀值；`set_sample` / `set_sequence`
    / `push_sample` / `set_pcm`（由 PCM 如正弦樣本算 peak/rms + 注入頻段）/ `reset` / `clear`）。
  - `AudioLevelProvider : ds::metrics::MetricProvider`（`provider_id`="sysinfo.audio"）：
    `register_metrics()` 掛上三個指標——`audio.peak`（單一實例 `peak`，label "Peak"）、
    `audio.rms`（單一實例 `rms`，label "RMS"）、`audio.spectrum`（每頻段可列舉實例
    `band0`/`band1`/…，label "Band 0"/…），三者 range=`bounded[0,1]`、各保留歷史環；peak / rms
    的 value.number=線性 [0,1]、value.text=dB 表述（如 "-6.0 dB"）；`sample()` 重新讀來源更新
    各實例（推入歷史，值夾 [0,1]，頻段數增則動態新增實例、減則多出者設未知）；`sampling_tier()`
    回建議採集分級（預設 High），供 `SamplingScheduler::add_demand`；`band_count()` 回頻段實例數。
  - 核心性質：相位 1（Mac/null 期）平台中立、**無 `#ifdef` / CoreAudio / AudioUnit / WASAPI /
    win32 / cocoa** 等真實音訊 API；相位 1 不做 FFT（頻段能量直接注入，FFT 留待相位 2+）；
    無讀值時以 valid==false（未知）誠實表達、與「靜音有讀值 peak=0」明確區分、不謊報 0；
    消費者只透過 E2-01 抽象介面走訪，新增此指標掛件一行不動。
