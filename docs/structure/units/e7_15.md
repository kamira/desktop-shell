# 結構註記 — E7-15 拖放產生設定項(描述子系統 / E7-12 + E5-08 的應用)

- 單元：E7-15（engine 層 / format / Risk: low / 相依 E7-12、E5-08）
- 目錄位置：`engine/format/e7_15/`（平台中立引擎邏輯，換平台一行不動）
- 測試：`tests/e7/test_e7_15.cpp`（CTest 名 `e7_15`）

## 放了什麼
- `dropgen.hpp` / `dropgen.cpp`：把拖放進來的抽象內容轉成設定項並經 E7-12 寫入宣告式文件——
  - `DropContent`（`DropKind` = File / Url / Text / Color / Unknown）+ 明確工廠（`file/url/text/color`）
    與推斷工廠（`detect`）；`detect_drop_kind` / `is_image_path` 內容類型偵測。
  - `ConfigItem{ path, value }` + `generate_config_item(drop)`：內容→設定映射的單一事實來源
    （圖片→`background.image`、一般檔→`file.path`、URL→`link.url`、顏色→`color`、文字→`text`；
    Unknown → throw，不靜默）。
  - `apply_drop(root/doc, drop)` / `apply_drops(doc, drops)`：經 E7-12 `set_value` 純函式寫回（回傳新樹）。
  - `drop_from_system_event` / `subscribe_drops`：與 E5-08 事件分派整合（相位 1 內容由事件注入）。
- `CMakeLists.txt`：`add_library(e7_15 STATIC dropgen.cpp)` + `target_link_libraries(e7_15 PUBLIC e7_12 e5_08)`
  + `test_e7_15` + `add_test(NAME e7_15)`。不改根 CMakeLists、不自造格式模型或事件模型。

## 對外介面（一句話）
`ds::format`：`apply_drop(doc, DropContent::detect("/pics/bg.png"))` 把拖入的圖片推斷為背景設定並
經 E7-12 寫回文件；`subscribe_drops(source, handler)` 把 E5-08 注入的拖放事件轉成設定項——無法辨識
內容以 `DropKind::Unknown` 明確回報、產生時 throw，不靜默失敗。
