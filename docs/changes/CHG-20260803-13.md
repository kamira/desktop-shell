# CHG-20260803-13 — H1-05 邊緣吸附

- Date: 2026-08-03 (UTC+0) | Branch: claude/feat-edge-snap | Risk: low | Implemented by: I1
- Unit: **H1-05**（artifact / host）
- Skill: ai-sdlc-autopilot v1.1
- 前置：`CHG-20260803-09`（W1-03 拖曳 + H1-03 位置）、`-12`（H1-04）

## Motivation

使用者指定的四個功能之二。拖曳已可用，但要把 widget 精準對齊螢幕邊緣得靠手感；
吸附讓「靠邊放」變成一個動作就成。

## Impact

`host/position/position_store.*` 新增純幾何函式：

```cpp
SnapResult snap_to_work_area_edges(int x, int y, int w, int h,
                                   const WorkArea& area, int threshold);
```

`host_main` 在 `poll_drag_finished` 之後、`remember_current` 之前套用，門檻 16px。

### 三個容易寫錯的地方

**① 吸的是「邊對邊」，不是「左上角對左上角」。** 右緣吸附時 `x` 要算成
`area.right - width`。寫成左上角對右緣的話 widget 會整個跑到畫面外。

**② 兩軸各自獨立。** 只有 x 在門檻內就只吸 x；使用者常常只想靠一邊。

**③ 同一軸兩端都在門檻內時取較近者。** 視窗幾乎和工作區一樣寬時會發生，
不處理會出現「明明靠左卻被吸到右邊」的跳動。

### 套用順序：先吸附，再記憶

**順序不能反。** 反過來的話記下的是吸附前的座標，下次還原時 widget 會從邊上「彈開」一點——
使用者會看到「每次開機都差一點點」，而且極難歸因。

## 明確不改

- 未改 W1-03 / H1-03 / E1-08 的任何既有行為，只新增純函式與一個套用點。
- 未做：吸附到其他 widget 的邊、對齊格線、吸附開關（門檻為編譯期常數）。

### 單元測試的取向：負向案例與正向案例同樣重要

這類「幫使用者調整位置」的功能有個特有的失敗模式：**在不該吸的時候吸**。
widget 放在畫面中央卻被吸到邊上，使用者會覺得程式在跟他作對，而且很難描述問題。

故涵蓋：中央不吸、**門檻外一格不吸**、門檻剛好等於時要吸（閉區間）、
門檻 `<= 0` 停用、退化工作區原樣回傳、非零工作區原點正確、
**冪等**（已貼齊者再吸不得移動，否則每次拖曳結束都會抖一下）。

### 操作驗收：確定性路徑，不用合成拖曳

`CHG-20260803-12` 已記錄合成滑鼠拖曳在本機不穩定。改為從外部把視窗移到指定位置，
再直接送 **`WM_EXITSIZEMOVE`**——那正是系統移動迴圈在使用者放開滑鼠時送出的訊息，
因此走的是 host 完全相同的真實路徑（`poll_drag_finished` → 吸附 → `set_surface_origin`）。

工作區 `(0,0)-(1920,1032)`、widget `320x132`：

| 案例 | 放置 | 實際 | 預期 |
|---|---|---|---|
| 左緣附近 | (5,600) | **(0,600)** | (0,600) |
| 上緣附近 | (700,6) | **(700,0)** | (700,0) |
| 右緣附近 | (1596,600) | **(1600,600)** | (1600,600) |
| 下緣附近 | (700,897) | **(700,900)** | (700,900) |
| 左上角 | (7,7) | **(0,0)** | (0,0) |
| **畫面中央（不該吸）** | (800,500) | **(800,500)** | (800,500) |
| **門檻外一格（不該吸）** | (17,500) | **(17,500)** | (17,500) |

7/7。右緣與下緣的實際值證實了「邊對邊」而非「左上角對邊」。

## 已知限制

- 吸附門檻為編譯期常數（16px），沒有 UI 開關也不隨 DPI 縮放調整。
- 只吸工作區四邊，不吸螢幕中線、不吸其他 widget 的邊、無對齊格線。
- 多螢幕：`work_area` 取的是主要顯示器的工作區，副螢幕上的吸附行為未驗證。
