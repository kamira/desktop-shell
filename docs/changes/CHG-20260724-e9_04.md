# CHG-20260724-e9_04 — 主題切換（E9-04）

- Date: 2026-07-24 | Branch: feat/e9_04 | Risk: low | Implemented by: I1.82

- Unit: E9-04（主題切換，engine 層 / 套件子系統 / low；相依已合併的 E9-03、E7-07）

## Motivation

E9-03 讓多個元件能以**可互換方式組合**進具名插槽；E7-07 提供宣告式文件的**熱重載**生命週期。
但兩者都沒有回答一個常見的桌面需求：**視覺主題如何在執行期整體切換**——把一組顏色 / 樣式 /
資源集（宣告式資料）註冊為具名「主題」，於執行期切換「當前主題」，並讓相依元件**收到通知後
套用新主題**（含可互換的主題元件）。

**主題切換**單元把這件事封裝為一層薄而明確的管理器 API：
- 以宣告式資料（E7-01 `Value`）承載主題屬性，不重造資料模型；
- 以 E9-03 `Composition` 承載主題的可互換元件集合，切換主題即切換其元件；
- 以變更回呼作為「相依元件套用新主題」的機制；
- 與 E7-07 熱重載橋接：一份熱重載後的主題文件可即時套用到當前主題並通知；
- 查無主題一律**明確報錯、不靜默**（帶人類可讀原因，或取當前主題而無當前主題時 throw）。

平台中立、純邏輯：無任何 `#ifdef` / 系統呼叫 / 平台分支。屬 engine 層，可完全單元測試。

## 設計（可覆核可改）

主題資料 `ThemeData{name, attributes, components}`：`attributes` 是宣告式顏色 / 樣式 / 資源表
（E7-01 `Value`，通常為 Map；Null = 空）；`components` 是該主題的可互換元件組合（E9-03
`Composition`，可空）。本單元只搬運這兩者、不解讀其欄位語意。

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::package` | 與 E9-01/E9-02/E9-03 一致；主題直接消費同子系統的 `Composition` |
| 主題資料 | `ThemeData{name, Value attributes, Composition components}` | 顏色 / 樣式 / 資源以宣告式 `Value` 承載（沿用 E7-01），元件以 E9-03 組合承載，皆不重造 |
| 註冊 | `register_theme(name, data)`：非空且未註冊 | 空名 / 重複 → failure(帶原因)，不新增；`data.name` 以註冊鍵為權威 |
| 更新（upsert） | `set_theme(name, data)`：不存在則新增、存在則取代 | 若取代者為**當前主題** → 自動通知（= 熱重載一份主題文件即時重新套用） |
| 切換 | `switch_to(name)`：未知 → failure(不靜默) 且當前不變；同名 → no-op success | 切換到「不同」主題才更新當前並通知 |
| 當前查詢 | `current()` / `current_name()` / `has_current()` | 無當前主題時 `current()`/`current_name()` throw std::runtime_error（明確報錯，不回可疑預設） |
| 查詢 | `has_theme` / `find_theme`（未知回 nullptr）/ `list_themes`（註冊序）/ `size` | 未知主題查詢一律安全 |
| 變更通知 | `on_theme_change(cb)`：可註冊多個，依序觸發 | 相依元件於回呼中讀取新 `ThemeData` 套用（顏色 / 樣式 / 可互換元件一併切換） |
| E7-07 橋接 | `theme_from_document(name, doc)`：attributes = `doc.root` | 熱重載新文件 → 轉主題資料 → set_theme 即時套用 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端。engine 層與平台無關
（非 `src/kernel/backend/`，不涉 backend_guard）。API 面以不透明 `Value` 承載屬性，
**不出現絕對座標與數字 z-order**（NFR-02）。本單元不含能力閘控呼叫（純邏輯註冊 / 切換），
無 `has()` 降級路徑需求（NFR-03 不適用）。
