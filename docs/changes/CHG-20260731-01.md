# CHG-20260731-01 — Windows 轉移準備：驗證器跨平台化 + 交接文件面向 Windows

- Date: 2026-07-31 (UTC+0) | Branch: chore/windows-portability | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
使用者確認：**本次交接的目的即為轉移到 Windows 開發**。這等於選定 `docs/backlog/phase2-desktop-runtime.md`
的 **B 案（Windows 優先）**——與 `PHASE-PLAN.md` 原定案（Q1 Windows 優先、相位 2 = win32）一致，非方向翻案。

全庫平台相依審計結果：**176 個核心單元全部平台中立 C++17**（相位 1 null 後端，`backend_guard` 強制無平台碼），
MSVC 可編。**唯一的 POSIX 相依是 `examples/cpu_gpu_validator/main.cpp`**（`getloadavg` / `<unistd.h>` / `sysconf`）——
這些在 MSVC 不存在，**Windows 上會編譯失敗**；而 CI 是 ubuntu，抓不到此問題。這是 Windows day-1 會踩的雷。

## Impact
### 1) 驗證器跨平台化（`examples/cpu_gpu_validator/main.cpp`）
`real_cpu_percent()` 改為 `#ifdef _WIN32` 分平台：
- **Windows**：`GetSystemTimes()` 兩次取樣差分算瞬時 CPU%（kernel 時間含 idle；首次呼叫回 0，之後每幀差分）。`#include <windows.h>`。
- **Mac / Linux**：維持原 POSIX `getloadavg` + `sysconf(_SC_NPROCESSORS_ONLN)`（一字未改）。
- 說明：example 非治理 src/ 單元，容許 `#ifdef _WIN32` 平台分支；176 核心單元維持平台中立。

### 2) 交接文件面向 Windows（見下述兩檔）
- `docs/backlog/phase2-desktop-runtime.md`：標記 **B 案（Windows 優先）已選定**，新增「Windows 接手 checklist」。
- `docs/backlog/HANDOFF.md` §0：加註 Windows 轉移、驗證器已跨平台、**MSVC 嚴格度 caveat**。

## MSVC 嚴格度 caveat（Windows 接手第一件事）
176 單元雖平台中立，但以 clang/g++ 撰寫測試，**未曾在 MSVC 實編**。MSVC 較嚴格，首次 Windows 全建可能踩到
（皆為機械修正、非邏輯錯）：two-phase name lookup、`min`/`max` 巨集（`windows.h`）撞 `std::min/max`（用 `NOMINMAX`）、
clang 遞移可得但 MSVC 需顯式的 `#include`、`and`/`or` 替代 token。**建議 Windows day-1 先跑一次完整 MSVC 建置，
把這類 warning/error 一次修掉**（多半是補 include / 加 `NOMINMAX`），再開始 win32 後端工作。

## 明確不改
- 未改任何 `src/`/`engine/`/`modules/`/`content/`/`apps/` 核心單元（維持平台中立）。
- 未改 `phase.json`（相位翻轉留給 Windows day-1 的治理動作，見 PHASE-PLAN §切換程序）。
- 未改 `units.json`；未實作任何 win32 後端（純準備 + 規劃）。
