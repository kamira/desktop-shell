# CHG-20260724-e1_05 — 具名碰撞區域 → 事件參數（E1-05）

- Date: 2026-07-24 | Branch: feat/e1_05 | Risk: low | Implemented by: I1.126
- Skill: ai-sdlc-autopilot
- Unit: E1-05（具名碰撞區域 → 事件參數，platform 層 / phase=1 / risk=low / depends_on=[E1-04] / load_bearing=2）

## Motivation

E1-04 已交付「某點是否落在一個 surface 形狀內」的幾何命中測試，但一個 surface 常常不只是單一
可互動範圍——按鈕有圖示區、文字區；地圖 surface 有多個可點擊區塊；面板有不同功能熱區。這些
子區域需要各自的**具名 id**與**相關參數**，才能在命中後把正確的語意（要觸發什麼、帶什麼資料）
交給事件系統。

E1-05 在 E1-04 之上加一層「**具名碰撞區域集合**」：呼叫端在單一 surface 的本地座標系內登記一組
具名區域（形狀 + 參數），命中查詢即回傳命中之具名區域的 id + 參數，供上層事件系統組裝事件負載。
本單元不引入新的幾何演算法——直接複用 E1-04 `HitTester::hit_test` 逐一判定，聚焦在「具名登記 /
查詢 / 移除」的集合語意與重疊優先規則。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建構位置 | 新服務 `NamedRegionMap`（`src/kernel/e1_05/`），內部持有 `HitTester` 實例 | 集合狀態（具名區域清單）屬本層新增；幾何判定完全委派 E1-04，不重造輪子 |
| 座標 / 幾何 | 沿用 E1-04 `LocalPoint` / `Shape`（本地 / 相對座標），不新增座標型別 | NFR-02：延續上游已確立的「本地座標」表達，跨層一致 |
| 具名指涉 | 區域以 `std::string` 具名 id 登記 / 查詢 / 移除，無數字 index / handle | NFR-02：與 E1-24 `SurfaceId`、E1-04 具名圖層一致的「具名指涉」慣例 |
| 重疊優先 | 無圖層概念，僅**加入序**（後加入者為上），逐一 `hit_test` 覆寫命中結果 | NFR-02：無數字 z-order；比 E1-04 `topmost_hit` 簡單（E1-04 有具名圖層主序 + 宣告序次序，E1-05 場景是單一 surface 內的子區域，不需圖層維度，只需宣告序） |
| 參數表達 | 自有 `RegionParamValue`（`std::variant<monostate, bool, int64_t, double, string>`）+ `RegionParams`（`std::map<string, RegionParamValue>`）| 封閉型別集合、具名鍵，型別安全且非任意 blob；**不**依賴 `engine/command/e6_01` 的 `CommandArgs`——platform 層（kernel）不得反向依賴 engine/command 層，且 units.json 的 `depends_on` 僅列 E1-04，故本層自有一份同構但獨立的型別 |
| 新增時驗證 | `add_region` 立即以 `HitTester::is_valid` 驗證形狀，無效 / 空具名 / 重複具名一律拒絕（回 `false`，不新增）| 把「報錯不靜默」收斂在寫入邊界，讓 `hit()` 的多數路徑不必再處理形狀無效；呼叫端可由回傳值立即得知失敗，不悄悄忽略 |
| 查詢結果 | `RegionHit{HitStatus status, bool hit, std::string name, RegionParams params}`，與 E1-04 `TopmostHit` 同慣例（結構化欄位，非例外 / 非 `std::optional`）| 沿用 E1-04 已確立的「狀態碼 + 結構化結果」慣例；`status=Invalid` 保留給查詢點非有限值（`add_region` 已擋下形狀類錯誤，`hit()` 內仍防禦性複查一次，理論不可達但不留死角） |
| 移除 | `remove_region(name)`；未知具名回 `false`，不崩潰；移除後同名可重新新增 | 比照 E1-24 `NullKernelBackend::destroy_surface` 的「未知 id 回 false、冪等安全」慣例 |

## Impact

### 影響分析（low 風險，load_bearing=2 —— 影響有限）

- **新增、非修改**：`src/kernel/e1_05/` 為全新目錄，未觸碰 E1-04 / E1-03 / E1-21 / E1-24（backend_null）
  任一上游檔案。`NamedRegionMap` 以**組合**方式持有一個 `HitTester` 成員呼叫其既有 public 方法，
  未對上游新增任何介面、未修改其行為。

- **下游影響面小（load_bearing=2）**：本單元提供的是「具名區域登記 + 查詢」的工具型服務，
  下游若要用具名子區域表達事件參數，可選用本單元；未選用者完全不受影響。命中測試本身的核心
  契約（E1-04 `HitTester`）維持不變。

- **參數型別的獨立性**：刻意不依賴 `engine/command/e6_01` 的 `CommandArgs`/`CommandValue`——
  两者所在層級不同（kernel/platform vs engine/command），`depends_on` 亦未宣告該相依，貿然
  引入會造成 platform 層反向依賴上層單元。`RegionParamValue`/`RegionParams` 為本層自有、型別
  結構相近但物理獨立的型別；未來若需要與 `CommandArgs` 互通，可在更上層（有權同時看到兩者的
  單元）做轉換，不在本層引入耦合。

- **建置面**：新增靜態庫 `e1_05`（`PUBLIC` 連 `e1_04`；經 e1_04 傳遞取得 e1_03 / e1_21 /
  backend_null 的 include）與可執行檔 `test_e1_05` + CTest `e1_05`。根 CMakeLists 既有層級 GLOB
  （`src/*/*/CMakeLists.txt`，深度 2）已涵蓋 `src/kernel/e1_05/CMakeLists.txt`，**無需**改根
  建置檔。

- **回溯相容**：純新增單元，未改任何既有 `src` / 上游單元 / `units.json` / 根 CMakeLists /
  共用 `directory.md`；對既有單元零影響。

- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **測試初稿混淆「不重疊」與「加入序覆寫」語意**：`MultipleNonOverlappingRegions` 首版誤用兩個
  皆以本地原點 (0,0) 為起點的矩形（僅寬度不同）試圖表達「不重疊的按鈕部位」，但两者其實在
  (2,5) 處重疊，導致測試意圖（各自命中對應具名）與實際行為（加入序後者為上）矛盾。根因：
  未注意到「形狀本地原點皆固定在 (0,0)」時兩個矩形只要有寬高交集就必重疊，不會因為各自代表
  「不同部位」就自動不相交。解法：拆成兩個獨立案例——`MultipleRegionsCarryDistinctParams`
  改用空間上明確分離的圓（圓心相距 18 單位，半徑 2，不重疊）驗證多區域各自攜帶不同具名參數；
  `OverlappingRegionsLaterAddedWins` 專門驗證加入序覆寫規則。重編後零警告 19/19 全綠。
- 其餘：實作首次編譯即零警告，未遇其他邏輯錯誤。
