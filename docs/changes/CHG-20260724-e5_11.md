# CHG-20260724-e5_11 — 可點區段選取事件（E5-11）

- Date: 2026-07-24 | Branch: feat/e5_11 | Risk: low | Implemented by: I1.158
- Skill: ai-sdlc-autopilot
- Unit: E5-11（可點區段選取事件，engine 層 / 角色 / low，depends_on=[E4-12, E5-01]）

## Motivation

E4-12 已交付「可點文字區段」——標記文字中的字元範圍為具名可點區段，並提供 `hit_span(point)`
判定本地點命中哪個區段。E5-01 已交付「基本滑鼠按鍵事件」——注入 / 命中路由 / 訂閱派發，判定
點擊落在哪個具名 surface。但兩者目前互不相通：訂閱 E5-01 事件的一方只知道「點了哪個 surface」，
不知道 surface 內部的可點文字區段是否被點中；E4-12 的 `hit_span()` 也需要呼叫端自行接上滑鼠
事件才能用起來。

E5-11 把兩者橋接起來：滑鼠點擊命中某具名 surface 後，若該 surface 綁定了一個 E4-12
`ClickableTextElement`，就以事件本地座標對其做 `hit_span()` 查詢；命中已標記區段時，發出
「該區段被選取」事件（帶區段具名 id）給訂閱者。**無區段命中的點擊不發選取事件**——不悄悄發一
個空 id 的事件，不存在的選取語意不應該被觀察到。

本單元**不重新實作任何按鍵狀態機或幾何命中邏輯**——命中判定、多擊追蹤、底層訂閱派發完全委派
已合併的 E5-01 `MouseEventRouter`；區段標記 / 排版 / 命中查詢完全委派已合併的 E4-12
`ClickableTextElement`。新增的邏輯只有「橋接」本身：對照表（surface → 區段來源）+ 僅於
`MouseAction::Click` 做查詢 + 命中才組裝並分派新事件型別。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 橋接方式 | `SpanSelectionDispatcher` 內部持有一個 E5-01 `MouseEventRouter` 實例，`set_surfaces()` 換手時對每個具名 surface（去重）各訂閱一次內部橋接回呼 `bridge()` | 與 E5-14 `RegionEventDispatcher` 同慣例：E5-01 的 `subscribe()` 綁定特定具名 surface，要攔截「任一具名 surface 命中的事件」只能對清單裡每個 surface 各訂閱一次，完全透過既有 public API 達成，不修改 / 派生上游 E5-01 |
| 觸發動作 | 僅 `MouseAction::Click` 觸發區段命中判定；`Down`/`Up` 一律略過 | E5-01 對一次 down/up 會分派 Down、Up、與（相符游標時）合成的 Click 三個事件；「選取」是使用者完成一次點擊的意圖，只在 Click 判定一次，避免同一次點擊因 Down+Up+Click 三個事件而重複判定 / 誤發 |
| 事件型別 | `SpanSelectionEvent{ MouseButtonEvent mouse, std::string span_id }`；**只在命中時才建構並分派**，不像 E5-14 `RegionEvent` 帶 `region_hit` 旗標讓未命中也正常派發 | 規格明定「無區段命中的點擊不發選取事件」——與 E5-14「未命中仍正常派發原始事件」的語意不同：本單元的訂閱者只關心「選取發生」這個事實，不需要一個「未選取」的事件；`span_id` 因此保證恆非空 |
| 區段來源對照 | `std::map<SurfaceId, const ClickableTextElement*>`：`bind_span_source(surface, element)` 逐 surface 綁定，**不取得所有權** | 一個 surface 對應一個可點文字區段來源；不取得所有權承 E4-12 對外部 `FontMetrics` 的既有慣例（呼叫端負責生命週期），避免複製一個持有 `FontMetrics&` 參照成員、語意複雜的重量級物件；未綁定的 surface 視為「無區段來源」，查詢時直接落到「不分派」分支 |
| 未命中 / 未綁定語意 | 命中 surface 但未綁定區段來源、綁定了但未命中任何已標記區段、或未命中任何 surface —— 皆**不分派**任何事件 | 呼應題目「無區段命中的點擊不發選取事件」；三種「無選取」情形一致處理，不特別報錯（合法情形，非缺陷），也不用旗標偽裝出一個空事件 |
| 轉呼注入介面 | `inject_button()` / `inject_down()` / `inject_up()` / `inject_click()` 皆透傳給內部 router 同名方法，回傳同一個 `RouteStatus` | 呼叫端使用體驗與 E5-01 一致；命中判定 / 多擊游標狀態機完全在內部 router，本單元不重複維護任何按鍵狀態 |
| 自身訂閱表 | 本類別維護獨立的 `subscribe()` / `unsubscribe()` / `listener_count()`（`SpanSelectionEvent` 訂閱者），與內部 router 的訂閱表（`MouseButtonEvent`，僅供橋接回呼使用）分離 | 呼叫端只看得到 / 訂閱得到橋接後的 `SpanSelectionEvent`，不會意外拿到原始 Down/Up 事件；兩張表各自的空 target / 空 listener 拒絕規則、快照分派慣例與 E5-01 / E5-14 一致 |
| `set_surfaces()` 換手 | 每次呼叫先取消先前對內部 router 的全部橋接訂閱，再對新清單重新訂閱 | 整組取代語意（比照 E5-01 `set_surfaces` 本身、E5-14 同作法）；避免舊 surface 訂閱殘留造成重複橋接或洩漏 |
| 命名空間 | `ds::events`（同 E5-01 / E5-14），透過 include 取得 `ds::elements::ClickableTextElement`（E4-12） | 本單元屬 engine/事件層；沿用既有事件系統的命名空間慣例 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實滑鼠後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。**NFR-02**：事件位置沿用
E1-04 `LocalPoint`（本地 / 相對），surface / 區段一律具名字串，無絕對座標、無數字 z-order。

## Impact

### 1. `engine/events/e5_11/span_selection_dispatcher.hpp`（新增）
- `SpanSelectionEvent{ mouse, span_id }`、`SpanSelectionListener`。
- `SpanSelectionDispatcher`：`set_surfaces()` / `surfaces()`（轉呼 E5-01）、
  `bind_span_source()` / `has_span_source()` / `unbind_span_source()`（本單元新增的 surface →
  區段來源對照）、`subscribe()` / `unsubscribe()` / `listener_count()`（`SpanSelectionEvent`
  訂閱）、`inject_button()` / `inject_down()` / `inject_up()` / `inject_click()`（轉呼 E5-01
  注入介面）。

### 2. `engine/events/e5_11/span_selection_dispatcher.cpp`（新增）
- `bridge()`：內部 router 命中分派出 `MouseButtonEvent` 時，僅處理 `MouseAction::Click`；以
  `event.target` 對照的 `ClickableTextElement`（若有綁定）呼叫 `hit_span(event.position)`，
  命中則組成 `SpanSelectionEvent` 分派給本類別訂閱者，否則不分派。
- `resubscribe_router()`：`set_surfaces()` 換手時整組取代對內部 router 的橋接訂閱（去重）。
- 無任何平台分支。
