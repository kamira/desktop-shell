# CHG-20260724-e6_01 — 命令匯流排與分派（E6-01）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e6_01 | Risk: medium | Implemented by: I1.13
- Skill: ai-sdlc-autopilot v1.1
- Unit: E6-01（命令匯流排與分派，engine 層 / command / medium / 承重 20x）
- 擴充點：#3「動作」的契約（`docs/architecture.md`）—— 致動器（modules/actuators）與更上層的
  動作系統都消費本契約，故 API 面刻意最小、穩定、可長期承重。

## Motivation

平台的第三個擴充點是「動作」：讓任意致動器（音量、電源、任意副作用）以具名命令掛上匯流排，
呼叫端只需 命令 id + 參數 即可觸發，**不需相依任何具體致動器**。若呼叫端直接相依個別致動器，
每加一個動作就要改呼叫端——那不是擴充點，是寫死。

E6-01 提供平台中立的命令匯流排：致動器 `register_command(id, handler)` 掛上，呼叫端
`dispatch(id, args)` 觸發。時機、副作用的真實實現全在呼叫端註冊的處理器中，engine 層只負責
註冊表與分派，因此可完全以單元測試驗證，且換平台一行不動。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命令識別 | 具名字串 `CommandId`（非數字 opcode） | 穩定、可讀、跨模組邊界不變形、不耦合編號 |
| 參數 / 回傳值型別 | `CommandValue`：null/bool/int64/double/string 的封閉集合 | 跨致動器邊界不變形；複合結構以多個具名參數表達，而非塞任意型別 |
| 參數容器 | `CommandArgs`：有序字典 + 型別安全 getter（缺鍵 / 型別不符回 nullopt） | 決定性遍歷、存取不 UB、不丟例外 |
| 結果模型 | `CommandResult`{ status, value, message }，status ∈ {Ok, NotFound, Failed} | NotFound 由匯流排產生（未知命令不崩潰）；Ok/Failed 由處理器決定 |
| 重複註冊 | 拒絕、回 false、**不覆蓋** | 承重契約：避免致動器被無聲遮蔽（silent shadowing） |
| 無效輸入 | 空 id / 空 handler 拒絕；未知命令回 NotFound；皆不崩潰 | 保守、可預期，契約邊界清楚 |
| 契約版本 | `contract_version()` = "e6_01/1.0.0" | 承重 API（見 architecture.md「Q3」）需版本欄位供相容判斷 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實副作用 / OS 後端。
