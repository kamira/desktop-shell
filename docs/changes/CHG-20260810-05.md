## Motivation

`CHG-20260810-03` 實作 G7 時查出：**CI 從來沒有跑過任何一個 Python 測試。**

`tests/e1/test_backend_guard.py` 有 14 個測試，守的是相位閘門 G1b
（`backend_guard.py`——「Mac 期不准寫真實後端」那道機器強制）。但是：

- `tests/e1/` 底下沒有 `CMakeLists.txt`，根 CMake 的 GLOB 收不到 → 不在 CTest 清單
- `governance.yml` 全檔 `grep -c 'unittest\|pytest'` = **0**

**守閘門的測試自己沒人守。** `-03` 讓 `tests/gates/` 進了 CI，但那是逐目錄點名，
`tests/e1/` 仍在外面；`-03` 與 `-04` 都明載這條缺口未解決。本 CHG 關掉它。

## 實作時撞到的兩件事（都比原本的任務更值得記）

### 一、`unittest discover` 會跑 0 個測試然後回綠

最直覺的做法是把 G7 那行 `discover -s tests/gates` 改成 `-s tests`。實測：

```
$ python -m unittest discover -s tests -p 'test_*.py'
Ran 0 tests in 0.000s
OK
```

`discover` 只遞迴進**套件**（有 `__init__.py` 的目錄）。本 repo 的
`tests/e1`…`e12`、`c1`…`c4`、`gates`、`contract` 沒有一個是套件——
`-s tests` 一個都收不到，`-t .` 則直接 `ImportError`。

**「跑 0 個測試 = OK」正是本 repo 已在 G3 防過兩次的真空綠燈。**
把那一行接進 CI，等於接了一道永遠不會叫的警報，而且從此沒有人會再檢查它。

所以改成 `scripts/run_python_tests.py`：自己走檔案樹、以路徑載入，
**收到 0 個檔或 0 個測試時紅燈**。加 `__init__.py` 的做法沒有採用——
那會把 `tests/` 變成 Python 套件樹，而它底下絕大多數是 C++ 測試。

### 二、釘住寫入端編碼只解決一半（K-009）

先在本機跑 `test_backend_guard.py`，紅 1 個：`UnicodeEncodeError`，
出在 `backend_guard.py` 印 CJK（[[K-001]] / [[K-004]] 同族，第三次現身）。
依既有解法補上 `sys.stdout.reconfigure(encoding="utf-8")` 後，**還是紅的**，
但換了一張臉：

```
TypeError: unsupported operand type(s) for +: 'NoneType' and 'str'
    self.assertEqual(proc.returncode, 0, proc.stdout + proc.stderr)
```

`returncode == 0`，`stdout` 卻是 `None`。根因是測試自己的
`subprocess.run(..., text=True)` 沒指定 `encoding`，**父行程**用 cp1252 去解碼
子行程的 UTF-8 輸出，`UnicodeDecodeError` 在 subprocess 的 **reader thread** 裡拋出——
不會傳播到呼叫端，`run()` 正常回傳，只有 `stdout` 悄悄變 `None`。

呼叫端看到的是「這個指令沒有輸出」，不是「解碼失敗」。**修好寫入端會讓讀取端的
問題換一張臉出現**，這一段值得單獨收錄，故立 K-009。

### 為什麼動得了 `backend_guard.py`（E1-26 的檔）

本 CHG 走 infra 分支（`chore/`，`is_unit=false`），G1 `scope_check` 不適用——
與 `CHG-20260810-04` 動 `governance.yml` 同一類。改動限於**補 6 行編碼釘死**，
不碰任何判定邏輯；`backend_guard.py` 的 14 個既有測試全數通過即為佐證。
E1-26 的行為未變，不需要重開該單元。

### 代使用者決定（供覆核）

- **G0 排在所有閘門最前面**：`tests/` 底下的 Python 測試守的就是 `scripts/` 底下
  這些閘門。先證明裁判的邏輯是對的，再讓它去判 PR。
- **G7 不再自帶 `discover`**：同一組測試跑兩次沒有意義，而「跑兩次」很容易在其中
  一處被改動後產生兩套行為。
- **五支腳本一起釘，不只 `backend_guard.py`**：同一個缺陷類別，其餘四支只是還沒被
  任何測試踩到。等它們各自被撞出來一次，代價是各自再查一輪。

## 不含（避免越界）

- 不把 `tests/` 變成 Python 套件樹（不加 `__init__.py`）。
- 不處理 `docs/backlog/HANDOFF.md` §0-B 的 6 項待補操作驗收——
  那需要一台沒有防毒封鎖執行檔的機器，不是程式碼問題。
- 不改 C++ 測試的收法（CTest 那條路徑未動）。

### 3. G0 的紅燈可達性（8 條）

四種紅：測試失敗、掃到 0 個檔、有檔但 0 個測試、匯入失敗。
三種綠：正常通過、遞迴進非套件子目錄、兩個目錄下同名檔都要跑到
（模組名不帶目錄會互相覆蓋，而覆蓋不會有任何錯誤訊息）。

第 8 條 `TestWhyNotPlainDiscover` 把「為什麼不直接用 discover」釘成測試：
它實際跑一次 `unittest discover`，斷言那一行**回報 `Ran 0 tests` 且 exit 0**。
日後有人想把 G0 簡化成一行，這條會告訴他那一行跑不到任何東西。
