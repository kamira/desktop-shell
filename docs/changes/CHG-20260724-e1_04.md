# CHG-20260724-e1_04 — 幾何命中測試（E1-04）

- Date: 2026-07-24 | Branch: feat/e1_04 | Risk: medium | Implemented by: I1.118
- Skill: ai-sdlc-autopilot
- Unit: E1-04（幾何命中測試，platform 層 / phase=1 / risk=medium / depends_on=[E1-03] / load_bearing=8）

## Motivation

桌面外殼的輸入路由需要一個**確定性的命中測試（hit testing）**：滑鼠 / 指標事件發生時，判定它
落在哪一個 surface（或其形狀）上，才能把事件路由給正確的元件。桌面元件不全是矩形——桌寵、羽化
浮層、圓角面板、不規則形狀都要能被精確命中，而**逐像素透明處**（如桌寵四周的透明邊）點擊時應該
**穿透**到其後的視窗，而非被透明像素攔截。多個 surface 重疊時，還要能決定「最上層」的命中者。

E1-04 於相位 1（Mac / null 期）交付**純幾何命中邏輯 + 注入式 alpha 查詢**：矩形 / 圓角 / 圓 /
多邊形 / path 的點內判定、逐像素 alpha 命中（透明處不命中，語意接 E1-03）、命中優先（依具名圖層
+ 宣告順序）。不含任何真實視窗系統 / OS / 繪圖 API；per-pixel alpha 的逐像素值由呼叫端注入的
oracle 供給，保持平台中立、與真實合成器解耦。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建構位置 | 新無狀態服務 `HitTester`（`src/kernel/e1_04/`），方法皆 const | 命中測試為純函式計算，無需持有狀態；與具體後端解耦，可安全併發呼叫 |
| 座標表達 | `LocalPoint`（元件本地 / 相對，原點為元件自身本地原點）；形狀在本地座標系內定義 | NFR-02：核心 API 不得出現**畫面絕對座標**。命中測試本質需點座標，故一律用本地 / 相對座標；surface 螢幕絕對位置不進本層 |
| 命中優先 | 具名圖層 `SurfaceLayer`（上游 E1-24）為主序 + 宣告順序為次序（後者為上） | NFR-02：不得用**數字 z-order**。`layer_rank()` 僅為內部具名列舉比較，不對外暴露數字 |
| 形狀模型 | 單一 `Shape`（tagged struct + `ShapeKind`{Rect, RoundedRect, Circle, Polygon, Path}）+ 工廠函式 | 讓 `hit_test(point, shape)` 為單一入口；工廠確保各 kind 欄位一致 |
| 多邊形 / path 判定 | Polygon 恆 even-odd（射線交點奇偶）；Path 帶顯式 `FillRule`{EvenOdd, NonZero winding} | 兩者提供實質差異；NonZero 環繞數處理自重疊 / 方向性填充。邊界（`on_segment` 容差）一律視為命中 |
| 圓角矩形 | extent (w,h) + corner_radius；角落區以四分圓判定，corner_radius clamp 至 min(w,h)/2 | 過大半徑 clamp 為退化（stadium），非錯誤；十字核心區直接在內 |
| alpha 命中 | 用 E1-03 `AlphaMode` / `AlphaProfile`（模式 + 整體 opacity）+ **注入式** `AlphaQuery` oracle 供逐像素值 | E1-03 只存模式 + 整體 opacity（相位 1 無逐像素資料）；per-pixel 值由呼叫端注入，平台中立。有效 alpha = oracle(point) × opacity，低於門檻（透明）不命中 |
| 命中穿透 | `HitPolicy::Transparent`（上游 E1-24）之 surface 永不命中本 surface | 對應「點擊穿透」語意；與 alpha 透明不命中互補（一為 surface 級策略、一為逐像素） |
| 結果碼 | `HitStatus`{Ok, Invalid}（與 E1-03 `AlphaStatus` 同語意，不用例外） | 跨後端一致；無效形狀 / 座標 / oracle 回非有限值 → `Invalid`（報錯不靜默） |
| 穩健性 | 負範圍 / 負半徑 / 非有限值 / 頂點數 < 3 / 非有限查詢點 → `Invalid`；零面積 extent 為退化但有效 | 保守、可預期的錯誤處理契約，絕不崩潰、絕不悄悄當作未命中 |

## Impact

### 影響分析（medium 風險，load_bearing=8 —— 高影響，謹慎覆核）

- **命中測試是輸入路由的地基**：load_bearing=8 代表多個下游單元（輸入分派 / 點擊路由 / 元件
  互動 / 焦點管理波次）將依賴 E1-04 的判定結果決定事件流向。因此本單元的**語意契約**須保守且
  明確：`hit_test`（純幾何）、`hit_test_alpha`（幾何 + 逐像素 alpha）、`topmost_hit`（多 surface
  優先）三者的邊界行為（含邊界視為命中、透明不命中、命中穿透、無效報錯）一旦定名即成下游共同
  依賴，故以 21 個 gtest 案例鎖定，避免日後語意漂移。

- **座標與 z-order 的表達是跨層契約**：本單元確立「命中測試用**元件本地 / 相對座標** +
  **具名圖層優先**」的表達方式（NFR-02）。下游若要做命中，須沿用 `LocalPoint` + `SurfaceLayer`
  的語彙，不得引入畫面絕對座標或數字 z-order。這與上游 E1-24 surface 模型（具名 `SurfaceId` /
  具名 `SurfaceLayer` / `HitPolicy`）一致，形成 platform 層一貫的「無絕對座標 / 無數字 z」風格。

- **alpha 命中的注入式設計是相位 1↔2 的演進點**：per-pixel alpha 的逐像素值以注入式 `AlphaQuery`
  oracle 供給，因相位 1 無真實像素 / 繪圖後端。**已知後續演進**：真實後端（相位 2+）上線後，
  逐像素 alpha 可改由後端 surface 的實際 alpha 通道（或 E1-03 未來納入的逐像素資料）供給；
  屆時 `HitTester` 的公開 API（`hit_test_alpha` / `HitSurface`）可維持不變（換注入來源即可），
  下游不受影響。已於 header 註記。與 E1-03 的耦合僅止於**型別**（`AlphaMode` / `AlphaProfile`），
  不觸碰 E1-03 的服務層或狀態，耦合面小。

- **透明穿透的兩條路徑須語意分明**：surface 級的 `HitPolicy::Transparent`（整片穿透）與逐像素的
  `PerPixel` + 低 alpha（局部透明處穿透）是**兩個互補機制**，本單元對兩者分別測試，避免下游混淆
  「這個 surface 不吃輸入」與「這個點恰好透明」。`topmost_hit` 中「最高層透明處落到底層」的
  情境（`TransparentTopFallsToLower`）已專門覆蓋——這是桌寵透明邊點擊穿透到桌面的核心情境。

- **不修改上游的耦合取捨**：因 E1-03 / E1-24 為固定（可讀不可改），本層以**組合 / 型別複用**
  擴充，不在上游加任何方法。`HitSurface` 聚合 surface 的命中相關屬性（形狀 + 具名圖層 +
  `HitPolicy` + `AlphaProfile` + 注入 oracle），是本層自有的命中檢視模型，不回寫上游 surface 表。

- **建置面**：新增靜態庫 `e1_04`（`PUBLIC` 連 `e1_03`；經 e1_03 傳遞取得 backend_null / e1_21 的
  include）與可執行檔 `test_e1_04` + CTest `e1_04`。根 CMakeLists 既有層級 GLOB
  （`src/*/*/CMakeLists.txt`，深度 2）已涵蓋 `src/kernel/e1_04/CMakeLists.txt`，**無需**改根建置檔。

- **回溯相容**：純新增單元，未改任何既有 `src` / 上游單元（E1-03 / E1-21 / E1-24）/ `units.json`
  / 根 CMakeLists / 共用 `directory.md`；對既有單元零影響。

- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **凹多邊形測試取樣點錯誤**：首版凹多邊形（箭頭形）取樣點落在與頂點對齊的掃描線且對凹口位置
  判斷相反，2 斷言失敗。根因：手推凹多邊形內外時取樣點在退化掃描線上。解法：改用軸對齊 L 形
  凹多邊形，取樣 y 不與任何頂點重合，內 / 外 / 凹處三點明確；重編零警告 21/21 全綠。
- 其餘：實作 / 測試首次編譯即零警告，未遇其他邏輯錯誤。
