# CHG-20260724-e2_25 — 剪貼簿監看（E2-25）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e2_25 | Risk: low | Implemented by: I1.28
- Skill: ai-sdlc-autopilot

## Motivation
E2-25「剪貼簿監看」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01
統一指標介面**（擴充點 1 契約）把「剪貼簿內容／變更」掛成一個指標，並以 **E2-02 採集頻率
分級**把它歸為低頻採集（剪貼簿變動慢、非前景動畫，屬 Low 級）。這正是「新增指標 = 新增
`MetricProvider`、掛件一行不動」機制的一個具體實例——它**消費 E2-01 / E2-02 契約、不自造
指標模型、不自造排程**。相位 1（Mac / null 期）只提供平台中立介面 + null 後端，**不真的讀
系統剪貼簿**（回空內容，或回注入的假內容供測試）；真實 OS 剪貼簿存取留待後端相位。變更偵測
為純邏輯，可完全單元測試。

## Impact

### 新增 `modules/sysinfo/e2_25/`（module 層 / 子系統 sysinfo）
- `clipboard_monitor.hpp` / `clipboard_monitor.cpp`（`namespace ds::sysinfo`）：
  - `ClipboardSnapshot` struct：剪貼簿某刻的平台中立快照 —— `present`（是否有文字項）＋
    `text`（內容）；含 `empty()` / `of()` 工廠與相等運算子。刻意不含平台專屬欄位
    （NSPasteboard changeCount / Win32 sequence 等）。
  - `ClipboardSource` 抽象後端：`read() → ClipboardSnapshot`（決定性）。真實平台後端於
    相位 2+ 實作；提供者只依賴此抽象介面。
  - `NullClipboardSource` null 後端：**不讀系統剪貼簿**，預設回空內容；
    `set_snapshot` / `set_text` / `clear` 注入假內容供測試與假感測器情境。
  - `ClipboardMonitor`：**純邏輯變更偵測器**——記住上一份快照，比對新快照判定「是否變更」
    並累計變更次數。起始「前一份」為空剪貼簿，故首次觀察到非空內容即算一次變更；清空亦為
    變更；相同內容重複觀察不累計。`observe()` / `change_count()` / `current()` /
    `observed_count()` / `reset()`，可完全單元測試（注入快照序列驗旗標與次數）。
  - `ClipboardMonitorProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.clipboard"`；`register_metrics(registry)` 向 E2-01 註冊表掛上
    單一指標 `"clipboard.content"`（name="Clipboard"、unit=""、range=`at_least(0)`、
    單一實例）。`sample()` 讀來源 → 經 `ClipboardMonitor` 偵測變更 → 更新實例
    value（number=累計變更次數、text=目前內容、valid=已採集）與歷史環。採集前 value 為
    unknown（不把 0 誤當真實讀值）。`register_demand(scheduler)`（消費 **E2-02**）以建議
    分級 `SamplingTier::Low` 把本指標登記為一筆需求，除頻合併沿用 E2-02、不自造排程。
  - 保守設計：source 為 null 或未 register 時 `sample()` 為 no-op、不崩；重複 id 由 E2-01
    註冊表保守拒絕，掛上失敗時不保留參照（`sample()` 隨即 no-op）。
  - `CMakeLists.txt`：`add_library(e2_25)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_25` + `add_test(NAME e2_25)`。
- 上游相依：E2-01 統一指標介面、E2-02 採集頻率分級（皆可讀不可改）。
- **無** `#ifdef` / win32 / cocoa / 真實 OS 剪貼簿存取（backend_guard 綠燈）。純邏輯、平台中立。

### 測試 `tests/e2/test_e2_25.cpp`（gtest，24 案例）
- 快照型別（2）：`empty()`/`of()` 工廠、相等性（present 與 text 皆納入比較）。
- 變更偵測器純邏輯（6）：初始態；首次非空為變更；首次空非變更；偵測變更並合併重複；
  空字串 vs 空剪貼簿相異；reset。
- null 後端注入 API（3）：預設空、set_text/set_snapshot/clear、建構子注入。
- 提供者身分（2）：`provider_id`/`kMetricId`/`kSuggestedTier` 穩定；可上轉為 E2-01 `MetricProvider`。
- 註冊（2）：`add_provider` 掛上單一實例指標、範圍 `at_least(0)`；採集前 value 為 unknown。
- 注入內容採集驗值（2）：首採反映內容與變更次數；多次採集追蹤變更並累積歷史。
- null / 保守（3）：null 後端空剪貼簿、null source 指標、未 register 就 sample 皆 no-op 不崩。
- E2-02 排程整合（2）：`register_demand` 登記 Low 級需求（有效間隔 64 tick）；排程到期驅動採集。
- 消費者範式（1）：掛件風格消費者只走 E2-01 registry / Metric 介面，全程無 sysinfo 型別。
- 重複註冊（1）：同 id 第二次掛上被保守拒絕、失敗提供者 sample() 為 no-op。
