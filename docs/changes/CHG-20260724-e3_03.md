# CHG-20260724-e3_03 — 媒體播放控制（E3-03）

- Date: 2026-07-24 | Branch: feat/e3_03 | Risk: low | Implemented by: I1.81
- Skill: ai-sdlc-autopilot

## Motivation
E3-03「媒體播放控制」是 modules/actuators（動作層 / 子系統 actuators）的一個**媒體控制
致動器**：把「控制媒體播放（播放 / 暫停 / 上一首 / 下一首 / 停止 / 切換播放暫停 / 設定
音量）」這組副作用，以具名命令掛上 **E6-01 命令匯流排**（擴充點 3「動作」契約）。呼叫端
只需 命令 id + 具名參數即可觸發，**不需相依本致動器或任何 OS 媒體控制 API**——與已合併
的 E3-05（音量設定致動器）採同一「注入式後端 + null 樣式」範式。

本單元與 **E2-13（媒體播放中繼資料 provider）對稱**：**E2-13 讀狀態、E3-03 下控制**。
兩者共用同一份平台中立播放狀態詞彙 `ds::sysinfo::PlaybackState`（Stopped / Paused /
Playing），故控制動作產生的狀態，與 E2-13 回報的狀態說的是同一種語言（消費者可直接對照）。
本致動器**消費** E2-13 的 `PlaybackState` / `state_rank` / `to_string`，不自造播放狀態模型。

相位 1（Mac / null 期）**絕不呼叫真實 OS 媒體控制 API**（不含 MediaRemote /
MPRemoteCommandCenter / MPRIS / SMTC 等），只提供**平台中立介面 + null / 假後端（純記憶體
狀態模擬）+ 契約測試**；真實平台後端留待相位 2，屆時致動器與命令契約一行不動。

## Impact

### 新增 `modules/actuators/e3_03/`（module 層 / 子系統 actuators）
- `media_control_actuator.hpp` / `media_control_actuator.cpp`（`namespace ds::actuators`，
  與 e3_05 一致）：
  - 七個具名命令 id（穩定可讀字串，不用數字 opcode）：`media.play` / `media.pause` /
    `media.next` / `media.prev` / `media.stop` / `media.toggle` / `media.volume`（音量為
    可選命令）。
  - `kMediaVolumeMin=0` / `kMediaVolumeMax=100` / `kMediaVolumeUnset=-1` +
    `clamp_media_volume(int)`：致動器層唯一的音量「合法化」點（相對值域 0–100，非絕對
    座標 / z-order）。
  - `MediaControlState` struct：`playback`（詞彙同 E2-13 的 `PlaybackState`）+
    `track_index`（>=0 相對序）+ `volume`（-1 = 未設定）；含相等運算子，供查詢 / 內省。
  - `MediaControlBackend` 抽象後端：最小介面 `play` / `pause` / `next` / `prev` / `stop` /
    `set_state(PlaybackState)` 六組播放原語 + `set_volume(int)` / `volume()`。相位 2+ 由
    平台後端以真實媒體控制 API 實作；致動器只依賴此抽象。契約：傳入 `set_volume()` 的
    level 已由致動器夾限至 [0,100]（後端可信任）；toggle 語意由致動器判定後改呼
    play/pause（後端不需懂 toggle）。
  - `NullMediaControlBackend`（相位 1 預設後端）：**不接真實媒體控制 API**，以純記憶體
    狀態（播放狀態 + 曲目索引 + 音量）模擬；初值可注入（預設停止、曲目 0、音量未設定）；
    `next()`/`prev()` 移動曲目相對索引（prev 於 0 夾住），`set_volume()` 自夾限；
    `snapshot()`/`track_index()` 內省。讓致動器在無真實後端時仍可完整跑通、狀態一致。
  - `MediaControlActuator`：建構綁定一個 `MediaControlBackend`（預設 NullMediaControlBackend）。
    `register_on(bus)` 把七個具名命令註冊到 E6-01 匯流排（全成功才 true；任一失敗回滾
    已掛者、不遮蔽既有致動器；無後端回 false）；`unregister_from(bus)` 回移除數（0..7）。
    處理器亦可直接呼叫（測試不經匯流排也能驗證語意）：
    - `media.play` / `pause` / `next` / `prev` / `stop`：無參數；施作對應原語；回目前播放狀態。
    - `media.toggle`：無參數；Playing → pause()、其餘（Paused / Stopped）→ play()；回切換後狀態。
    - `media.volume`：必填 `level`（int）；超出 [0,100] 自動夾限（不失敗）；回夾限後音量。
    缺 / 型別錯的必填參數 → `CommandResult{Failed}`（以 `has()` / `get_int` 保護，不崩潰、
    不改後端狀態、不丟例外）。播放類成功結果的 `value` = 播放狀態位階（int，`state_rank`；
    同 E2-13 語意）、`message` = 狀態字串（`to_string`）；`media.volume` 成功結果的 `value`
    = 夾限後音量（int）。另有 `current_state()` / `playback_state()` 內省（後者供與 E2-13
    讀取端對照）。
  - `media_control_contract_version()`：契約版本標記 `"e3_03/1.0.0"`（定義在 .cpp，使
    STATIC 程式庫非空並集中版本字串；命名加 `media_control_` 前綴避免與同命名空間其他
    致動器的版本函式衝突）。
  - `CMakeLists.txt`：`add_library(e3_03 STATIC media_control_actuator.cpp)` **PUBLIC 連
    上游 `e6_01` 與 `e2_13`**（標頭 include `command_bus.hpp` 與 `media_metadata.hpp`，須
    傳遞 include 目錄）；`test_e3_03`（`tests/e3/test_e3_03.cpp`）+ `add_test(NAME e3_03)`。
- 上游相依：
  - E6-01 命令匯流排（`ds::command::CommandBus` / `CommandArgs` / `CommandResult` /
    `CommandValue`），可讀不可改——消費擴充點 3「動作」契約，不自造匯流排或值型別。
  - E2-13 媒體播放中繼資料（`ds::sysinfo::PlaybackState` / `state_rank` / `to_string`），
    可讀不可改——重用平台中立播放狀態詞彙，與讀取端對稱、不自造播放狀態模型。
- **無** `#ifdef` / win32 / cocoa / MediaRemote / MPRIS / SMTC 等真實媒體控制 API
  （backend_guard 綠燈）。致動器邏輯（命令、分派、toggle 判定、結果回報、音量夾限）與
  後端完全解耦、純邏輯、平台中立、可注入。

### 測試 `tests/e3/test_e3_03.cpp`（gtest，18 案例）
- 註冊 / 反註冊（4）：七命令全掛、重複註冊回滾且不改既有、null 後端不可註冊、
  unregister 移除全七個且再呼叫回 0。
- 分派狀態轉換（1）：經匯流排 play → Playing / pause → Paused / stop → Stopped，回傳值 =
  state_rank、訊息 = to_string。
- next / prev（1）：曲目索引移動、於 0 夾住、換曲不改播放狀態。
- toggle（2）：三態間切換（Stopped → Playing → Paused → Playing）、直接呼叫從 Stopped 到
  Playing。
- media.volume（3）：設定與夾限（上下界）、缺 / 型別錯 level → Failed 且不改後端、
  `clamp_media_volume` 邊界。
- 未知命令（1）：匯流排回 NotFound（不崩潰）。
- null 後端一致（2）：狀態轉換序列 + 內省快照一致、注入初值（含負曲目夾 0 / 超界音量夾限）。
- 直接呼叫處理器（2）：語意等價；無後端各處理器回 Failed、內省回預設。
- 與 E2-13 對照（1）：控制端與讀取端（NullMediaSource）共用同一 PlaybackState 詞彙。
- 契約版本標記（1）。
