## 第二類缺陷：深層巢狀打爆堆疊（I1 自行量測，非採信回報）

自寫 probe 直接呼叫 `ds::format::parse()`，預設 8 MiB 堆疊：

```
深度  1000（1,006,918 bytes）  → 回傳 ParseResult：成功
深度  4000（16,030,918 bytes） → 成功
深度  8000（64,062,918 bytes） → 成功
深度 14000（196,114,918 bytes）→ Segmentation fault，行程退出碼 139
```

成因：遞迴下降解析（`parse_child_or_null` 等）沒有深度上限，而 `Value` 樹的**解構也是遞迴的**
——所以即使解析成功，釋放時同樣會爆。

**嚴重性與第一類不同，已在驗收標準裡寫明**：這一類需要很大的檔案（196 MB），
手打不出來，屬惡意／損毀檔情境。但它與第一類同屬「**`parse()` 可以讓行程結束**」，
而行程結束比任何解析失敗都糟，所以一併修。

`V1.8` 另指出一個放大效應：修訂 2 的 `H1-09` 讓 `save()` 在提交前**重讀目標存檔**，
於是這條 SIGSEGV 多了一個入口（存檔路徑也會解析）。**那是上游的根因，不是 `H1-09` 的缺陷**，
I1 已明確告知實作者不必修它。

1. **根因同檔、同函式族**，`write_scope` 不需要動；分成兩個單元會讓兩者在同一份
