# CHG-20260723-12 — layer 由 core 拆為 platform / engine 兩個值

- Date: 2026-07-24 (UTC+0) | Branch: claude/ai-sdlc-handshake-validation-380ada | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
CHG-10/11 把平台本身依「對系統的操作 vs 平台中立邏輯」切成 `src/` 與 `engine/` 兩個目錄後，
`layer=core` 就橫跨兩個目錄，「core」不再對應單一目錄。把 layer 拆成 `platform` / `engine`
兩值，使**分層欄位與目錄一一對應**，「換平台要改哪裡」在資料層面即可直接查得。

## Impact

### `units.json` `layer` 值域
`{core, module, artifact}` → **`{platform, engine, module, artifact}`**

判定規則（機械可複算）：
| 條件 | → layer |
|---|---|
| `write_scope` 有 `engine/**` 路徑 | **engine** |
| `write_scope` 有 `src/**` 路徑 | **platform** |
| 皆無（`E1-25` tests/contract、`E1-26` scripts）| **platform**（後端契約基礎設施） |

`module` / `artifact` 不動；`subsystem` 欄位不動。`totals.by_layer` 改為 4 鍵。

### 分佈
| layer | 項 | 平台耦合 | 位置 |
|---|---|---|---|
| **platform** | **32** | 語意分歧 29 + 中立 3 | `src/**` + `E1-25`/`E1-26` |
| **engine** | **62** | 全中立 | `engine/**` |
| module | 58 | 語意分歧 0 | `modules/**` |
| artifact | 24 | 語意分歧 0 | `content/`、`apps/` |

`platform` 的 3 個中立項 = `E1-24` null 後端、`E1-25` 契約測試組、`E1-26` 白名單 lint ——
皆為**後端契約基礎設施**，定義/實作/強制平台適配的邊界，故歸 `platform` 而非 `engine`。

**`platform` + `engine` = 平台本身（原 core 94）。** 概念上仍是
「平台（platform+engine）／提供者（module）／驗證器（artifact）」三分，
只是平台本身再依平台耦合細分為二。

### 更強的結構不變量
| 層 | 語意分歧 | API 分歧 | 平台中立 |
|---|---|---|---|
| platform | **29** | 0 | 3 |
| engine | **0** | 0 | 62 |
| module | 0 | 34 | 24 |
| artifact | 0 | 0 | 24 |

29 項語意分歧**全部落在 `platform`**；`engine` / `module` / `artifact` 三層合計 **144 項零語意分歧**。
換平台需重寫的收斂為 `platform` 32 項（實則 29 項語意分歧 + null 後端）。

### 文件同步
`architecture.md` / `requirements.md` / `ai-guideline.md` / `structure/directory.md`：
分層表改 4 列、階段表 `core` 欄拆為 `platform` / `engine` 兩欄、平台耦合表拆列、
相關敘述改用新術語。全 repo 已無把 `core` 當 layer 值使用之處（歷史 CHG 與「拆分說明」註記除外）。

### 未受影響
`plan.py` / `scope_check.py` / `stage_check.py` / `backend_guard.py` 均不讀 `layer` 欄位
（用 `module` / `write_scope` / `stage`），機制完全不受影響。
