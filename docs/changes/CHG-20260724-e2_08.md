# CHG-20260724-e2_08 — 網路流量（E2-08）

- Date: 2026-07-24 | Branch: feat/e2_08 | Risk: low | Implemented by: I1.61
- Skill: ai-sdlc-autopilot

## Motivation
E2-08「網路流量」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一
指標介面**（擴充點 1 契約）把「網路流量」——每個網路介面的**上傳/下載速率**（bytes/sec）、
**累積收發位元組**、**收發封包數**，並支援**多介面**——掛成指標，並以 **E2-02 採集頻率
分級**決定採樣節奏。這是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的又一個
具體實例——它**消費 E2-01 / E2-02 契約、不自造指標模型或排程器**（範式與 E2-03 CPU 負載
一致）。相位 1（Mac / null 期）**絕不接任何真實網路 API**（不含 `getifaddrs` /
`/proc/net/dev` / mach / `#ifdef`）；改為**可注入的網路統計來源抽象** + null / 假來源。
**速率由累積計數差分**得出（來源給兩次累積 rx/tx 位元組 + 時戳 → 除時間差）；真實平台
後端留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_08/`（module 層 / 子系統 sysinfo）
- `network_traffic.hpp` / `network_traffic.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `NetInterfaceCounters`：單一介面的**累積**計數（rx/tx 位元組 + rx/tx 封包；含相等
      運算子）。單一時刻累積值無速率意義——速率須由兩次取樣差分得出，但累積計數本身即
      有意義（可直接呈現）。
    - `NetInterfaceCounterEntry`：某介面在快照中的一筆計數（含介面名，供差分**按名對齊**）。
    - `NetCountersSample`：某時刻全介面的累積計數快照 + **單調秒數時戳**（平台中立注入值；
      差分時以時戳差為分母算速率）。介面集合可在取樣間變動（上/下線）。
    - `NetTrafficSample`：提供者面對的統一流量形狀（每介面 速率 bytes/sec + 累積計數 +
      `rate_valid`；整體 `valid`；`unknown()` = 無讀值；`find(name)`）。`rate_valid`==false
      表速率無讀值（首次差分/無前份/dt<=0），此時累積仍可有效。
  - **差分演算法**（自由函式，獨立可測、純算術）：
    - `rate_from_delta(prev, curr, dt_seconds)`：單面向速率 = 位元組Δ / dt。防護：
      dt<=0（無經過時間）→0、計數器重置（curr<prev）→0（保守，避免負值/爆量）。
    - `traffic_from_snapshot(curr)`：由單一快照建流量（累積直接填、速率 0 且
      `rate_valid`==false、整體 `valid`==true）。供差分來源首次取樣。
    - `traffic_from_delta(prev, curr)`：逐介面（以 curr 為準、於 prev 按名尋對應）算
      rx/tx 速率；累積取自 curr；新上線介面（prev 無對應）或 dt<=0 → 只有累積、速率
      `rate_valid`==false。整體 `valid`==true（已有兩份取樣）。
  - **流量來源**（提供者只依賴此抽象）：
    - `NetworkStatSource`（抽象 `sample()→NetTrafficSample`；非 const，差分型來源取樣有
      副作用）。
    - `NullNetworkStatSource`：相位 1 null/假「直接流量」來源——**不接真實網路 API**，
      預設回無讀值；`set_traffic` / `set_interface`（新增/覆寫一個介面完整讀值）/ `clear`
      注入，供測試與假感測器情境。
  - **累積計數來源 + 差分轉接**（「來源給累積計數、提供者以兩次取樣差分算速率」路徑）：
    - `NetCounterSource`（抽象 `read()→NetCountersSample`，給累積計數 + 時戳，尚未差分）。
    - `NullNetCounterSource`：注入累積計數序列（模擬時間推進），`read()` 回下一份、列盡
      持續回最後一份、空列回空快照。
    - `DifferencingNetworkStatSource`：把計數來源以「兩次取樣差分」轉成 `NetworkStatSource`；
      內部保存上一份基準，首次 sample()（或 reset 後）速率回未知（累積仍有效）——**速率**
      差分至少需兩份取樣。
  - **提供者** `NetworkTrafficProvider : ds::metrics::MetricProvider`（provider_id
    "sysinfo.net"）：`register_metrics()` 掛上**六個**指標：
    - `net.rx.rate` / `net.tx.rate`（"Network RX/TX Rate"，unit "B/s"）
    - `net.rx.bytes` / `net.tx.bytes`（"Network RX/TX Bytes"，unit "B"）
    - `net.rx.packets` / `net.tx.packets`（"Network RX/TX Packets"，unit "packets"）
    值域皆 `at_least(0)`（速率/累積量非負、上無界）。六個指標**共用同一組介面實例**
    （同名、首見序列舉，各保留歷史環容量 `kDefaultHistory=64`）。`sample()` 重新讀來源、
    把各面向寫入各介面實例（有效值推入歷史）：新介面**動態新增**於全部六個指標（既有參照
    不失效）、本次消失的介面設未知（不縮減、不污染歷史）。`sampling_tier()` 回建議採集
    分級（預設 `Normal`，可由建構子覆寫），供 E2-02 `SamplingScheduler::add_demand`。
    source 為 null 時仍掛上六個指標、無介面實例、`sample()` 為安全 no-op（保守不崩、不謊報 0）。

### 新增測試 `tests/e2/test_e2_08.cpp`（gtest，28 案例）
涵蓋：提供者身分與六個 metric id、六指標註冊、多介面實例列舉、來源直接給流量讀值、
`rate_from_delta`（bytes/sec、無經過時間、計數器重置）、`traffic_from_delta` 逐介面速率、
經提供者兩次取樣差分（累積計數來源→差分轉接）、**首次差分速率 invalid 而累積有效**、
**時間差為零** → 速率 invalid 累積有效、計數器重置 guard、新介面只有累積暫無速率、
介面上線/下線（下線設未知不縮減）、經 **E2-02** 頻率採樣（Normal 間隔 8）與除頻合併、
null 來源保守、無讀值誠實 invalid、`NullNetCounterSource` 列盡/空列、範圍 `at_least(0)`、
消費者只走 E2-01 抽象介面、重複註冊保守拒絕、值模型單元。相位 1：只驗介面 + 注入式來源
行為，不含任何平台分支。
