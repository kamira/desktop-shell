### 2. 滑鼠 hover / 點選 / Esc / 點外面關閉 — 通過

**hover 高亮**用像素量，不用眼睛判斷（我第一次用看的判斷錯了）。
逐列送 `WM_MOUSEMOVE` 後量各列平均亮度：

| hover 的列 | 最上層顯示 | 點擊穿透 | 鎖定位置 | 分隔線 | 結束 |
|---|---|---|---|---|---|
| 最上層顯示 | **126.3** | 53.4 | 52.3 | 38.1 | 42.9 |
| 點擊穿透 | 55.2 | **124.8** | 52.3 | 38.1 | 42.9 |
| 鎖定位置 | 55.2 | 53.4 | **124.2** | 57.2 | 42.9 |
| 結束 | 55.2 | 53.4 | 52.3 | 38.1 | **117.2** |

高亮嚴格跟著游標所在列（126 vs 基準 ~53），沒有殘留、沒有錯位。

| 項目 | 結果 |
|---|---|
| Esc → 選單消失 | ✓ |
| 在選單外按左鍵（`mouse_event` 走系統輸入佇列）→ 選單消失 | ✓ |
| 點選「鎖定位置」→ 選單關閉 | ✓ |
| 點選後 `ui-state.conf` 由 `locked: false` → `locked: true` | ✓ |

最後一條是最強的證據：它證明點擊不是被吃掉，而是走完了
**命令 id → `widget_controls` → 持久化**整條路。

### 6. 合成滑鼠拖曳為何時好時壞 — **重現不出，原因仍未查明**

這一項要誠實分成兩半，因為前半很容易被拿來冒充後半：

**前半（可不可拖）— 通過。** `WM_NCHITTEST` 是拖曳能否發生的唯一判準
（W1-03 就是靠 `HTCAPTION` 讓系統進入移動迴圈）：

| `ui-state.conf` | `WM_NCHITTEST` | 期望 |
|---|---|---|
| `locked: false` | `2` (HTCAPTION) | HTCAPTION ✓ |
| `locked: true` | `1` (HTCLIENT) | HTCLIENT ✓ |

**後半（合成拖曳穩不穩）— 這台重現不出。** `mouse_event` 真實下壓、
分 12 步移動、放開，重複 10 次：

```
第 1..10 次：起點 (600,300) → 落點 (660,340)  位移 (60,40)   全部 ✓
成功 10 / 10
```

**10/10，每次位移精確相同，完全確定性。**

所以：`CHG-20260803-12` 記載的不穩定**在這台機器上不存在**。
但這**不等於查明了原因**——只是多一個資料點：另一台機器上的不穩定是
環境相依的，不是程式邏輯本身的問題。原機器裝的是 PC-cillin，
而防毒掛鉤輸入是一個**合理懷疑**，但本次沒有任何證據支持它，故不寫成結論。
`HANDOFF` 的這一項改記為「本機不重現；原因仍未查明」，不改記為已解決。
