# CHG-20260724-e2_15 — 音訊峰值與頻譜（E2-15）

- Date: 2026-07-24 | Branch: feat/e2_15 | Risk: low | Implemented by: I1.67
- Skill: ai-sdlc-autopilot

## Motivation
E2-15「音訊峰值與頻譜」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一
指標介面**（擴充點 1 契約）把「音訊視覺化資料」——目前輸出/輸入音訊的**峰值電平**（peak）、
**RMS 電平**、以及**頻譜頻段能量**（N 個 band 的強度，供等化器類視覺化）——掛成指標，並以
**E2-02 採集頻率分級**決定採樣節奏（音訊電平快速變動、視覺化宜跟手，屬週期高頻採集）。這是
「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 /
E2-02 契約、不自造指標模型或排程器**。本單元是最終「音訊等化器 / 電平表 Widget」的核心資料
來源，故介面刻意乾淨、易組合。相位 1（Mac / null 期）**絕不接任何真實音訊 API**（不含
CoreAudio / AudioUnit / WASAPI / `#ifdef`）；改為**可注入的音訊電平來源抽象** + null / 假來源，
峰值 / RMS 由 PCM 樣本（如注入的正弦樣本）以純算術算出、頻段能量直接注入（相位 1 不做 FFT）；
真實平台後端留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_15/`（module 層 / 子系統 sysinfo）
- `audio_levels.hpp` / `audio_levels.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `AudioLevelSample`：統一電平形狀（`peak` 峰值 + `rms` RMS，皆線性振幅 [0,1]；
      `bands` 各頻段能量 [0,1]；`valid`）。`unknown()` = 無讀值；含相等運算子。頻段數可在
      取樣間變動。
  - **電平計算**（自由函式，獨立可測、純算術）：
    - `peak_of(pcm)`：一塊 PCM 樣本中絕對值最大者，夾到 [0,1]（空塊 → 0）。
    - `rms_of(pcm)`：均方根 sqrt(mean(x^2))，夾到 [0,1]（空塊 → 0）。
    - `linear_to_db(amplitude, floor_db=-120)`：線性振幅 → 分貝（20*log10）；full-scale 1.0
      → 0 dB；靜音 / 極小值以 `floor_db` 為下限（避免 -∞）。
  - **電平來源**（提供者只依賴此抽象）：
    - `AudioLevelSource`（抽象 `sample()→AudioLevelSample`；非 const，序列型來源取樣有副作用）。
    - `NullAudioLevelSource`：相位 1 null / 假來源——**不接真實音訊 API**，持一列注入電平快照，
      `sample()` 回下一份、列盡持續回最後一份、空列回無讀值（誠實預設）；`set_sample`（固定
      單值）/ `set_sequence` / `push_sample` / `reset` / `clear` 注入；`set_pcm(pcm, bands)`
      便利：由 PCM（如正弦樣本）算 peak / rms + 注入頻段（此即「注入固定 / 序列，如正弦樣本」
      路徑）。
  - **提供者** `AudioLevelProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.audio"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**三個
    指標**：
    - `"audio.peak"`（name="Audio Peak"）**單一實例** `"peak"`(label "Peak")：峰值電平，
      number=線性 [0,1]、text=dB 表述（如 "-6.0 dB"）。
    - `"audio.rms"`（name="Audio RMS"）**單一實例** `"rms"`(label "RMS")：RMS 電平，同附 dB。
    - `"audio.spectrum"`（name="Audio Spectrum"）**每頻段可列舉實例** `"band0"`/`"band1"`/…
      (label "Band 0"/…)：各頻段能量 [0,1]，依取樣頻段數建立。
      三指標 range 皆 `bounded(0,1)`（可正規化到 [0,1] 供長條 / 等化器類元件）。各實例保留
      歷史環（`kDefaultHistory=64`），配合 E2-02 週期採集鋪成波形 / 等化器序列。
    - `sample()`：重新讀來源、把新電平寫入各實例（推入歷史，值夾到 [0,1]）；頻段數增加則
      **動態新增**頻段實例（既有參照不失效，unique_ptr 持有），減少則多出者設未知（不污染
      歷史）。register 尚未呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::High`，建構子
      可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
    - `band_count()`：目前的頻段實例數。
  - 無讀值語意：三指標仍掛上；峰值 / RMS / 各頻段以 `valid==false`（未知）誠實表達，而非塞
    假值。靜音（peak=rms=0、valid==true）與無讀值（valid==false）明確區分。source 為 null
    亦保守不崩（三指標皆未知、無頻段實例）。
  - `CMakeLists.txt`：`add_library(e2_15)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_15` + `add_test(NAME e2_15)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）＋ E2-02 採集頻率分級
  （`ds::metrics::SamplingTier` / `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / CoreAudio / AudioUnit / WASAPI 等真實音訊 API
  （backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_15.cpp`（gtest，28 案例）
- 提供者身分（3）：`provider_id`/三個 metric id 穩定；可上轉為 E2-01 `MetricProvider`；
  預設採集分級 = High（可覆寫）。
- 註冊 / 列舉（4）：`add_provider` 掛上三個指標；peak / rms 各單一實例（id/label 正確、讀值）；
  頻譜每頻段可列舉實例（band0…、讀值）；電平實例附 dB 文字表述。
- **peak_of / rms_of 純算術**（4）：絕對值最大 / 空塊 / 超界夾；RMS / 空塊；**滿幅正弦**
  peak≈1、rms≈0.707；`set_pcm`（正弦）算 peak / rms + 注入頻段。
- **linear_to_db**（1）：full-scale→0 dB、半幅≈-6 dB、靜音→下限、可調下限、極小值夾下限。
- **頻段數變動**（2）：頻段數增 → 動態新增實例（既有參照不失效）；頻段數減 → 多出者設未知
  （不縮減、誠實表達消失）。
- **0 / 靜音邊界**（1）：靜音（peak=rms=0、頻段全 0）為 `valid==true` 真實讀值（非未知），
  dB 為下限。
- **無讀值 invalid**（3）：null 來源預設未知（非 0）、注入後可讀；`AudioLevelSample::unknown`；
  無讀值不污染歷史。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（High 間隔 1）登記需求、推進 tick 於到期
  時呼叫 `sample()` → 歷史累積；除頻合併多消費者（最高頻者供給、撤銷後仍追蹤）。
- **null 來源行為 / 序列來源**（4）：source 為 null 指標 → 三指標未知、無頻段、不崩、`sample()`
  no-op；`sample()` 未註冊 no-op；序列逐份推進 / 列盡回最後 / 空列無讀值 / reset；`clear` 回未知。
- 範圍 / 消費者範式 / 重複註冊 / 夾界（4）：三指標皆 `bounded[0,1]`（0.5 正規化到 0.5）；掛件
  風格消費者只走 E2-01 registry / Metric 抽象走訪頻段；同組 id 第二次掛上三個皆保守拒絕；
  來源給超界值時提供者夾到 [0,1]。
