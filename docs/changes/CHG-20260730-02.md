# CHG-20260730-02 — 解除 ds::kernel::HitResult 上游命名碰撞（E1-02 改名 InputHitResult）

- Date: 2026-07-30 (UTC+0) | Branch: chore/hitresult-fix | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
兩個已合併的平台單元在**同一** `ds::kernel` 命名空間各自宣告**同名不同型別**的 `HitResult`：
- **E1-02**（`src/kernel/e1_02/input_strategy.hpp`）：`enum class HitResult { Solid, Transparent }`——輸入策略的命中測試結果（表面是否吃輸入）。
- **E1-04**（`src/kernel/e1_04/hit_test.hpp`）：`struct HitResult { HitStatus, bool }`——幾何命中測試結果。

兩份標頭若 transitively 進入**同一翻譯單元**即編譯失敗（`use of 'HitResult' with tag type that does not match previous declaration`）。任何需同時組裝「輸入策略側」與「幾何命中/E1-16 熱區側」的下游單元都會踩到：施工期間 **C1-06（Dock）、C2-07（媒體控制）、C1-03（氣球）** 三個單元先後撞上，各自以 pimpl / 中性鏡像型別橋接（把衝突的兩棵 include 樹隔到不同 TU）繞過。這是**根因未除**的權宜——未來每個同時觸及兩側的單元都得重複橋接。

本 CHG 從根本解除碰撞。屬跨單元的上游 API 修正，非任一單元 write_scope 內，由 I1 以 infra CHG 處理（走 CHG-20260730-01 啟用的 infra 分支 G3 建置閘）。此修正原規劃與目錄扁平化合併，但因修正**移除/解耦了橋接**、扁平化只剩純機械搬檔，兩者已無「同一檔改兩次」的耦合，故拆為先修復（本 CHG，語意變更、測試覆蓋）、後扁平化（CHG-20260730-03，純結構）兩步，各自獨立以 CI G3 驗證，較單一巨型不可本機驗證的變更安全。

## 決策：改哪一個？
改 **E1-02 的 `enum class HitResult` → `InputHitResult`**（使用者確認）。理由：
- E1-02 的型別語意是「輸入命中（是否吃輸入）」，`InputHitResult` 更精確；E1-04 的 `struct HitResult`（幾何命中結果）維持不動，其消費者較多（e1_05/e1_06/e1_16/e4_04/e4_12），blast radius 較小。
- E1-02 enum 的真實符號消費者僅 4 個 profile 的 `hit_result()` 透傳方法（C1-01/C1-04/C1-05/C1-06）+ E1-02 自身 + 對應測試。
