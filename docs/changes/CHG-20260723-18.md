# CHG-20260723-18 — 修正 workflow 自動合併自我死鎖（改用 --auto）

- Date: 2026-07-24 (UTC+0) | Branch: chore/autopilot-automerge-fix | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
第一個工作單元 PR（E1-21，#5）暴露治理 workflow 的結構性 bug：
八道閘門 G1–G6 **全部通過**（G3 在 CI 上實建 C++ + 跑 gtest 成功、G6 判 AUTO），
但「自動合併」步驟 `gh pr merge --squash` **立即合併**失敗：
`the base branch policy prohibits the merge` —— 因為此刻 `gate` check 仍 pending
（該步驟就在 `gate` job 內，job 尚未回報成功），branch protection 要求 `gate` 綠才准合，
形成**自我死鎖**：要合併就得 gate 綠，但 gate 綠又要這步先跑完。此步失敗連帶讓整個
gate job 紅，於是每個單元都卡住。

## Impact
`.github/workflows/governance.yml` 自動合併步驟：
```diff
- run: gh pr merge <PR> --squash --delete-branch
+ run: gh pr merge <PR> --auto --squash --delete-branch
```
`--auto` 只是**排隊啟用 auto-merge**（指令立即成功、不阻塞 job），待 gate job 跑完轉綠、
所有 required check 滿足後，GitHub 才真正合併。死鎖解除。

**效果**：low 風險單元（G6=AUTO）在八道閘門全綠後由 GitHub 自動 squash-merge + 刪分支，
**不需人工 admin**。medium（G6=HALT）走既有的「貼 halt 標籤等人」路徑，不受影響。

## 驗證計畫
本 CHG 併入 main 後，重觸發 E1-21（#5）的 check，應在 gate 綠後自動合併完成
——即證明 autopilot 對 low 單元的自主合併鏈路真正打通。
