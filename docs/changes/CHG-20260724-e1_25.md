# CHG-20260724-e1_25 — kernel 後端契約測試組（所有後端共用）（E1-25）

- Date: 2026-07-24 | Branch: feat/e1_25 | Risk: medium | Implemented by: I1.93
- Skill: ai-sdlc-autopilot
- Unit: E1-25（kernel 後端契約測試組，P0 / 核心 / engine 層 / depends_on=[E1-21]）

## Motivation

相位 2 起將出現多個 kernel 後端實作（E1-24 null 參考實作，其後 win32 / cocoa）。若每個
後端各自為政，「後端該有什麼行為」就散落在各實作裡、無單一可執行的判準，換平台時 kernel
抽象會安靜地長成某個平台的形狀，且沒有任何測試能同時擋住所有後端的行為漂移。

E1-25 提供一組**所有 kernel 後端都必須通過的平台中立行為契約**：針對 kernel 後端抽象介面
撰寫「對任一符合介面的後端跑同一批斷言」的契約測試（能力查詢一致性、介面方法前後條件、
生命週期、錯誤處理）。任何後端（null / 未來 win32 / cocoa）都套同一組測試驗證其符合契約，
契約本身不隨後端而變。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 介面歸屬 | 抽象介面 `KernelBackend` 由契約組自帶（`tests/contract/kernel_backend.hpp`） | 相位 1 repo 內尚無現成後端介面實作；依單元規格「介面純抽象且無現成實作時 stub 由本測試檔提供」。write_scope 僅 `tests/contract/**`，不得於 `src/kernel/` 落地介面 |
| 受測後端 | 契約組自帶測試本地 `StubBackend`，**不 link E1-24** | 維持與 E1-24 的單元獨立（units.json 中兩者只相依 E1-21、不互相依）。stub 與未來各後端各自獨立實作同一契約——正是契約組用途 |
| 套用方式 | gtest parameterized test（`TestWithParam<BackendFactory>` + `INSTANTIATE_TEST_SUITE_P`） | 「對任一符合介面的後端跑同一批斷言」的落地：新增後端只加一個 factory，契約斷言不動 |
| 能力查詢契約 | `has(id)` 須與 `capabilities().has(id)` 完全一致；未宣告能力保守回 false | NFR-03 能力閘控語意；資料來源為上游 E1-21 `CapabilityMatrix` |
| 錯誤處理契約 | 對不可用（含未宣告）能力的操作回 `Unsupported` 且不改狀態 | 能力閘控第二層保險：未 `has()` 保護的操作也不得崩潰 |
| surface 表示 | 具名角色 `SurfaceProfile.role`（非像素 / 座標 / 數字層級） | NFR-02：介面不得出現絕對座標與數字 z-order |
| 平台中立 | 契約與 stub **不含** 任何平台分支 | E1-25 acceptance：測試僅依賴介面與能力矩陣，不得包含任何平台分支 |

## Impact

### 影響分析（medium 風險）

- **契約是所有後端的共同判準**：本組斷言一旦定案，會成為 E1-24 null 後端及未來 win32 /
  cocoa 後端的驗收門檻（E1-24 的 acceptance 即「契約測試組（E1-25）全綠」）。因此契約的
  前後條件語意須保守且平台中立——過嚴會擋掉合理實作，過鬆則失去防漂移作用。本組取「能力
  查詢一致性 / 生命週期冪等 / surface 前後條件 / 錯誤處理不崩潰」等**跨平台皆應成立**的最小
  共識，不觸及任何平台專屬行為。
- **介面由契約組自帶的耦合風險**：相位 1 尚無 `src/kernel/` 內的後端介面 target，故抽象介面
  暫置於 `tests/contract/`。未來若 kernel 後端抽象介面在 `src/kernel/` 正式落地，應改為由契約
  測試 include 該正式 header、並讓各後端 target 實作之；屆時本檔自帶的 `KernelBackend` 收斂為
  對正式介面的引用。此為已知的後續演進點，已於 header 註記。
- **不 link E1-24**：確保 E1-25 可獨立於 E1-24 完成與合併，兩單元並行不互鎖；stub 承擔
  「讓契約可跑」的責任，與 E1-24 的 null 後端各自獨立。
- **建置面**：新增可執行檔 `test_contract_backend` 與 CTest `contract_backend`，link 上游
  `e1_21`。根 CMakeLists 既有 GLOB（CHG-20260723-22）已涵蓋 `tests/contract/CMakeLists.txt`，
  無需改根建置檔。
- **回溯相容**：純新增測試交付物，不改任何既有 `src` / `engine` / `modules` / 上游單元 /
  units.json；對既有單元零影響。

### 1. `tests/contract/kernel_backend.hpp`（新增）
- kernel 後端抽象介面 `KernelBackend`（純虛）：`capabilities()` / `has()`、生命週期
  `initialize()` / `is_ready()` / `shutdown()`、surface 基元 `create_surface()` /
  `destroy_surface()` / `surface_alive()`、能力閘控操作 `invoke_capability()`。
- 統一結果碼 `Status`{ Ok, Unsupported, Invalid }；`SurfaceProfile`{ role（具名角色）}；
  `SurfaceHandle`（不透明控制碼，`kInvalidSurface`=0）。
- 引用上游 E1-21 `CapabilityMatrix` / `CapabilityId`。平台中立、無平台分支、無絕對座標。

### 2. `tests/contract/stub_backend.hpp`（新增）
- 測試本地最小 `StubBackend`：以純記憶體狀態實作 `KernelBackend`，能力矩陣取 E1-21
  `defaults()`。不 link E1-24、無真實系統呼叫、無平台分支。

### 3. `tests/contract/test_contract_backend.cpp`（新增）
- gtest 契約組。8 個 parameterized 契約 + 1 個非參數化 sanity，共 9 個可跑測試案例：
  能力查詢一致性、生命週期狀態轉移、init/shutdown 冪等、surface 建立前置條件、surface
  生命週期往返、無效輸入不崩潰、能力閘控錯誤處理、shutdown 釋放 surface、stub 直接冒煙。
- 以 `INSTANTIATE_TEST_SUITE_P` 註冊受測後端（目前僅 stub）；未來後端各加一 factory。

### 4. `tests/contract/CMakeLists.txt`（新增）
- `add_executable(test_contract_backend test_contract_backend.cpp)` +
  `target_link_libraries(... PRIVATE e1_21 GTest::gtest_main)` +
  `add_test(NAME contract_backend COMMAND test_contract_backend)`。
- 路徑注意：本 CMakeLists 與測試 .cpp/.hpp 同在 `tests/contract/`，故 .cpp 以相對本目錄的
  檔名指向（與「測試在 tests/<m>/、CMakeLists 在單元目錄」的其他單元不同）。根 CMakeLists
  的 GLOB 已收 `tests/contract/CMakeLists.txt`（CHG-20260723-22），無需改根檔。

### 5. `docs/worklog/I1.93-e1_25.md`、`docs/structure/units/e1_25.md`（新增）
- 施工紀錄與單元結構註記（G4：每單元獨立結構檔，不動共用 `directory.md`）。

## 本機驗證

`g++ -std=c++17 -Wall -Wextra` 以 scratchpad gtest 墊片（不進 repo）編譯**未經改動的**
`tests/contract/test_contract_backend.cpp` + 上游 `src/kernel/e1_21/capability_matrix.cpp`，
零警告通過，9/9 測試案例全綠。墊片巨集單次求值（EXPECT_/ASSERT_ 引數只求值一次），故
生命週期 / surface 計數斷言成立即證明契約邏輯正確。正式 CTest 於 CI 以真 GoogleTest 執行。

## 相位 1 約束遵循

- 僅新增契約測試 + 測試本地 stub，**不寫任何真實平台後端**、不建 `src/kernel/backend/win32|cocoa/`。
- 契約與 stub 平台中立、無平台分支（backend_guard 對 `tests/contract/**/*.py` 掃描；本組為
  C++，且不含任何平台分支 token 作為分支邏輯）。
- surface 以具名角色表達，無絕對座標 / 數字 z-order（NFR-02）；能力查詢一律經 `has()`（NFR-03）。
