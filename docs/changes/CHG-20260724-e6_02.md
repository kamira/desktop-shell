# CHG-20260724-e6_02 — 動作註冊表與前綴/模糊分派（E6-02）

- Unit: E6-02（動作註冊表與前綴/模糊分派，engine 層 / command / low / depends_on E6-01）
- 擴充點：#3「動作」契約之**查詢層**（`docs/architecture.md`）—— 在 E6-01 命令匯流排上
  建可查詢的動作索引，讓不完整 / 有錯字的輸入也能找到最相近命令，再經匯流排實際分派。

## Motivation

E6-01 提供具名命令的匯流排（id → handler）與精確 `dispatch(id, args)`。但真實使用中，
使用者輸入常是不完整（`vol`）或有錯字（`volme`）。若只有精確比對，稍有出入即 NotFound。
E6-02 在匯流排之上補一層「動作註冊表 + 前綴/模糊分派」：維護已知命令的可查詢索引，
把使用者輸入解析成依相關度排序的候選，於唯一最佳候選時才經 E6-01 匯流排觸發。

關鍵原則：**歧義不亂猜、找不到明確回報**。多個並列最佳候選時回候選清單而非任選其一；
無候選時回結構化 NotFound。查詢層與執行層鬆耦合——註冊表只管「有哪些命令」，真正的
處理器與副作用仍由 E6-01 CommandBus 承擔，兩者可各自單元測試。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 比對種類 | Exact > Prefix > Substring > Fuzzy（`MatchKind`） | 相關度分級，最貼近輸入者優先 |
| 相關度分數 | 整數編碼（種類權重拉開量級 + 種類內完成度/距離細排） | 決定性；歧義判斷以整數相等比較，不受浮點誤差影響 |
| 前綴 | id 以 query 起頭（`vol` → `volume.set`） | 命令補全的最常見情境 |
| 子字串 | query 出現在 id 之中（`volume` → `audio.volume.set`） | 讓命名空間化命令仍可由中段詞找到 |
| 模糊 | Levenshtein 編輯距離；對整串 id 與各 `.` 段取最小距離 | 錯字容錯；對段比對讓 `volme` 對上 `volume.set`（整串距離大、段距離僅 1） |
| 模糊上限 | `set_fuzzy_max_distance`（預設 2；設 0 關閉） | 可調容錯強度、可完全關閉 |
| 歧義 | 並列最佳（同分）> 1 → `Ambiguous` + candidates，**不分派** | 不亂猜，交回呼叫端決定 |
| 找不到 | 無候選 → `NotFound`，不分派 | 邊界結構化、可預期 |
| 執行 | `dispatch_best` 取唯一最佳候選，經傳入的 E6-01 `CommandBus` 分派 | 查詢層/執行層鬆耦合；漂移時如實回 bus 的 NotFound，不靜默 |
| 註冊來源 | 手動 `add(id, title?)` 或 `sync_from(bus)` 匯入 bus 既有命令 | 註冊表可獨立填充或與匯流排同步 |

介面平台中立：無 `#ifdef` 等平台分支、不綁任何真實副作用 / OS 後端。
