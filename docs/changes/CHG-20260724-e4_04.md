# CHG-20260724-e4_04 — 按鈕三態（E4-04）

- Date: 2026-07-24 | Branch: feat/e4_04 | Risk: low | Implemented by: I1.135
- Skill: ai-sdlc-autopilot
- Unit: E4-04（按鈕三態，module 層 / 子系統 elements / phase 1 / risk=low）
- depends_on: E4-02（圖片元件）、E1-04（幾何命中測試）、E5-02（懸停進出事件）

## Motivation

桌面 shell 的按鈕需要依互動狀態（常態 / 懸停 / 按下）切換外觀，並在「按下後於按鈕範圍內
放開」時觸發點擊回呼——這是所有可點擊桌面元件（面板按鈕、桌寵互動、工具列）的共同基礎行為。

若在相位 1 就直接綁真實滑鼠 / 視窗系統事件來判定懸停與按下，邏輯將無法在單元測試中重現，
也違反 module 層「平台中立、換平台不動邏輯」的分層要求。因此 E4-04 完全**組合**既有上游能力
而不重造輪子：懸停狀態委由上游 E5-02 `HoverTracker` 的 Enter/Leave 事件驅動；按下 / 放開的
「是否命中按鈕」判定委由上游 E1-04 `HitTester` 對按鈕自身本地形狀做幾何命中；各態要顯示的
視覺內容以上游 E4-02 `ImageElement` 表達，`render_model()` 直接消費其 `ImageRenderModel`。
本單元只新增「三態狀態機 + 各態視覺對應表 + 點擊回呼」這一層薄邏輯。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 三態顯示優先序 | Pressed > Hover > Normal；`hover_`/`pressed_` 各自獨立追蹤，`state()` 每次即時推導 | 按住時即使仍懸停也顯示 Pressed；放開後若仍懸停正確回到 Hover，不因按下而遺失懸停旗標 |
| 各態視覺 | `set_visual(ButtonState, const ImageElement&)` 值複製進 `std::array<ImageElement,3>` | 不持有外部 `ImageElement` 的參照，來源可於設定後即銷毀 / 變動，與 E4-02 `set_source` 值語意一致 |
| 懸停整合 | `attach(HoverTracker&)` 向追蹤器登記本按鈕的 `HitSurface`（id/shape/layer）並訂閱，內部 `handle_hover_event` 依 `event.surface==id()` 過濾、Enter→開/Leave→關/Move→不變 | 不重新實作懸停判定，完全委由 E5-02；`handle_hover_event` 亦公開供測試直接驅動，無需真實 `HoverTracker` |
| 按下 / 放開 | `press`/`release` 各自呼叫 `HitTester::hit_test(point, shape_)` 對按鈕自身形狀做命中判定 | 不重新實作幾何邏輯，完全委由 E1-04；座標沿用其 `LocalPoint`（本地 / 相對，NFR-02） |
| 按下語意 | 命中→`pressed_=true`；未命中→無動作（非錯誤） | 按下動作落於按鈕外是常見情境（如多按鈕重疊區域判定由上層 topmost_hit 處理），非本單元要報的錯誤 |
| 放開語意 | 先前為 Pressed 且本次命中→觸發 `on_click`；先前非 Pressed 或本次未命中（拖出範圍再放開）→僅結束按下、不觸發 | 「拖出範圍取消點擊」是標準 GUI 按鈕語意，非錯誤路徑，與「無效輸入」明確區分 |
| 點擊回呼 | `ClickCallback = std::function<void()>`，`set_on_click` 設定；未設定時 `release` 仍正常運作（no-op 呼叫） | 呼叫端可選擇是否關心點擊；不因未設定回呼而報錯 |
| 渲染描述 | `ButtonRenderModel{state, ImageRenderModel visual}`；`visual` 為目前態對應 `ImageElement::render_model()` | NFR-02：完全承襲 E4-02 已合規的具名目標 / 正規化裁切 / 比例透明度描述，本單元不新增任何座標 / z-order 欄位 |
| 無效態防禦 | `set_visual`/`visual` 對超出三個合法 `ButtonState` 列舉值（如整數 `static_cast`）回 `Invalid`/`nullptr` | 「無效態處理不靜默」——即使公開 API 型別上不太可能誤用，仍以顯式檢查防禦邊界情況 |
| 無效輸入防禦 | `press`/`release` 遇非有限座標或按鈕自身形狀無效（沿用 E1-04 `HitTester::is_valid`）→ `Invalid`，不改變任何狀態、不觸發 `on_click` | 「無效輸入處理不靜默」；與 E1-04/E5-02 一致的報錯風格 |
| 建構子防禦 | 空 `SurfaceId` → 擲 `std::invalid_argument` | 不可指涉的按鈕沒有意義；與 E4-15 `TextInputElement` 對程式錯誤使用例外的慣例一致（區別於執行期資料錯誤用狀態碼） |

平台中立：無 `#ifdef` / `win32` / `cocoa` / 真實視窗系統 / 滑鼠鉤子 API；NFR-02 全面沿用 E1-04
本地座標 + E4-02 具名目標 / 正規化裁切 / 比例透明度 + 具名 `SurfaceLayer`，無絕對座標、無數字
z-order。

## 風險與緩解（low）

- **懸停/按下狀態不同步風險**：`hover_` 與 `pressed_` 各自獨立追蹤，可能被誤以為需要互斥 →
  設計上明確定義顯示優先序（`state()` 推導）並以 `PressedStateTakesPriorityOverHoverForDisplay`
  測試鎖定「按下時仍懸停 → 顯示 Pressed；放開後回到 Hover」。
- **靜默失敗風險**：非有限座標 / 無效形狀 / 無效態 → 一律回 `Invalid`/`nullptr`，不改變任何
  既有狀態、不觸發 `on_click`；對應測試（`PressWithNonFiniteCoordinateIsInvalid` 等）守衛。
- **拖出範圍語意混淆**：「放開於按鈕外」是正常取消點擊而非錯誤，特別以 `ButtonStatus::Ok` +
  不觸發回呼與「無效輸入」的 `Invalid` 明確區分，並各有專屬測試。
- **NFR-02 誤用風險**：本單元完全承襲上游已合規的具名 / 相對表達（id 為字串、layer 為具名
  列舉、座標為 `LocalPoint`、視覺描述沿用 `ImageRenderModel`），無新增座標 / z-order 欄位；
  `UsesNamedIdAndNamedLayerNotNumericZOrder` 測試守衛。
