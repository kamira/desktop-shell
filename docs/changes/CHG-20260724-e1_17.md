# CHG-20260724-e1_17 — DPI 感知與混合 DPI（E1-17）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e1_17 | Risk: low | Implemented by: I1.5
- Skill: ai-sdlc-autopilot v1.1
- Unit: E1-17（DPI 感知與混合 DPI，platform 層 / kernel / low / 承重 1x）

## Motivation

多螢幕環境下，各螢幕的邏輯縮放（scale factor，如 1.0 / 1.5 / 2.0）可能不同（混合 DPI）。
上層若以絕對像素座標處理縮放，換螢幕 / 換平台時內容會誤放大或誤縮小。E1-17 提供一組
平台中立介面，讓縮放一律以**每螢幕的縮放係數**與**具名螢幕**表達，成為 DPI 感知與混合
DPI 處理的單一資料來源。

相位 1（Mac / null 期）尚無真實 per-monitor DPI 探測：只寫介面 + null 後端，回傳宣告的
預設縮放；真實後端上線後由後端以實際探測覆寫。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 螢幕指涉 | 具名 `ScreenId`（字串），非 index / 座標 | NFR-02 禁止絕對座標與數字 z-order；具名跨平台一致、與實體排列無關 |
| 縮放表達 | 無單位 `scale_factor`（比值），非像素尺寸 | 換平台不動；比值天然可組合（`relative_scale`） |
| 混合 DPI | 多個 scale 不同的 `ScreenDpi` 並存，各螢幕獨立查詢 | 查某螢幕的縮放不受其他螢幕影響 |
| 未知螢幕語意 | `scale_of()` 回 `kDefaultScaleFactor`（1.0） | 保守：中性縮放（不縮放），呼叫端永遠安全 |
| 非法縮放（<= 0） | 建構時正規化為 1.0 | 拒絕不合法縮放，退回中性值 |
| 重複 id | 後定義者為準 | 讓後端能覆寫先前宣告的縮放 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端、無 `setPosition(x,y)` 式
API，符合相位 1（Mac/null）與 NFR-02 約束。

## Impact

### 1. `src/kernel/e1_17/dpi_awareness.hpp`（新增）
- `ScreenId`（具名字串識別碼別名）、`kDefaultScaleFactor`（1.0，null 期與未知螢幕的中性預設）。

## 不含（避免越界）

- **不實作任何真實平台後端**（win32/cocoa）；相位 1 僅介面 + null 宣告行為。
- **無任何絕對座標 / (x,y) / 數字 z-order API**（NFR-02）；縮放只以比值與具名螢幕表達。
- 未動 `units.json`、根 `CMakeLists.txt` 或任何鎖定範圍以外的檔案。
