## Motivation

E8-02 的對話腳本直譯器能依序執行 `set` / `say` / `if` / `goto` / `label` 五個 opcode，但
腳本要編排的是「畫面上發生什麼」——切到哪個畫面、哪個元件要出現 / 消失、播一段轉場、
等待多久——這些字彙不在直譯器的 opcode 之列，也不該塞進 E8-02（它是通用直譯器，不該
認識任何具體的「表現」語意）。

E8-03 在不修改、不擴充 E8-02 opcode 的前提下，疊一層**表現控制指令集**：

1. `PresentationController` 把 `show` / `hide` / `switch_surface` / `transition` /
   `wait` 五個具名指令註冊到 E6-01 `CommandBus`——任何呼叫端（腳本、測試、未來的動作
   系統）一律以「命令 id + 具名參數」分派，不需相依這裡的具體型別。`switch_surface`
   的實際切換委派給 E4-06 `SurfaceSwitcher`；其餘四個為 phase 1 的純記憶體描述 /
   分派，不做真實繪製。
2. `PresentationSink` 實作 E8-02 的 `OutputSink`：把 `say` 產生的一行文字（如
   `"show hero"` / `"switch_surface main"` / `"transition fade a b 0.5"` / `"wait
   1.0"`）解析為具名命令並經 `CommandBus::dispatch` 分派——腳本完全不需要知道背後是
   E4-06 / CommandBus，E8-02 本身完全不被修改。

依 NFR-04 精神「不靜默失敗」：未知指令（不在五個之列）交給 CommandBus 分派一個未註冊
的 id，沿用其既有契約回 `NotFound`；無效參數（缺參數、空字串目標、非有限 / 負值秒數、
未知 surface）各處理器回 `Failed` 並帶訊息，不套用、不部分套用。`PresentationSink` 忠實
記錄每一行的分派結果（`results()`），不吞任何錯誤。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 與 E8-02 整合方式 | 不擴充 Step/opcode，改以 `OutputSink` 子類 `PresentationSink` 攔截 `say` 文字 | E8-02 已合併不可改；`say`+可注入 sink 本就是為「副作用交給呼叫端」設計的擴充點 |
| 指令表 | `show` / `hide` / `switch_surface` / `transition` / `wait` 五個具名 id（`ds::script.` 前綴） | 對齊需求語意；具名前綴避免與其他子系統在同一 bus 上撞名 |
| 分派管道 | 全部經 E6-01 `CommandBus::register_command` / `dispatch` | 契約統一：呼叫端只需「命令 id + 參數」，不需相依具體 handler |
| switch_surface 落地 | 委派 E4-06 `SurfaceSwitcher::switch_to`，`NotFound` 轉 `CommandStatus::Failed` | 不重造 surface 定址；沿用既有具名 id / 不靜默契約 |
| show/hide/transition/wait 落地 | phase 1 純記憶體描述（visibility map / 紀錄 vector），不做真實繪製 | 符合相位 1 約束；行為可完全單元測試 |
| 未知指令判定 | 不特判：組出未註冊 id 交給 bus，自然得到 `NotFound` | 不重造「未知」邏輯，直接沿用 CommandBus 既有的不靜默契約 |
| 文字解析 | 空白分隔 token；數值 token 嘗試整段解析為 `double`，失敗則原樣以字串帶入 | 非數值文字不特判也能被處理器的型別檢查自然拒為 Invalid |
| 註冊生命週期 | 建構期嘗試註冊五個 id；任一衝突 → `ready()==false` + 訊息；解構自動 unregister | 同一 bus 多個 controller 情境不崩潰、不靜默；資源可清楚歸還 |
| 轉場 / 等待模型 | `TransitionRecord{kind, from, to, duration_seconds}` / `WaitRecord{seconds}` | 具名端點 + 具名種類（非數字係數），秒數為浮點需求 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）
約束。engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。副作用一律走
`CommandBus` 分派 + phase 1 記憶體描述，不含能力閘控呼叫（純邏輯），無 `has()` 降級路徑
需求。全程具名字串（surface id / 元件 target / 轉場 kind），無絕對座標 / 數字 z-order
（NFR-02）。
