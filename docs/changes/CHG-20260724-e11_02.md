## Motivation

多數桌面應用（尤其自訂外觀的桌面殼層）需要以**自己的渲染**呈現選單 / 內容選單，而非依賴
OS 原生選單 API——後者無法客製字型、配色、動畫或非矩形外觀。E11-02 提供這種「自繪
（owner-drawn）選單呈現」的平台中立骨架：以 E7-13 階層式項目結構描述選單樹、以 E4-01 文字
排版產出每列標籤的渲染描述、以 E1-03 具名 surface 表達展開層的呈現目標；巡覽（鍵盤 / 滑鼠）
與致動邏輯與任何真實繪製 / 輸入後端解耦，可在相位 1（Mac / null 期）先行成形並以純單元測試
驗證，真實繪製層於後續相位消費 `render_model()` 即可、邏輯不變。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 選單樹來源 | 消費 E7-13 `Item` 森林；`Item::value()`（Map）宣告 `kind`/`checked`/`enabled` | 不重造樹狀結構；`kind` 省略時依有無子項推斷（有子項→submenu，否則→action） |
| 節點型別 | `MenuNodeKind`：Action / Separator / Checkbox / Submenu | 鏡射 E11-01 TrayMenuItem 慣例，職責清楚（分隔線不可巡覽、submenu 走 enter 而非直接致動） |
| 建構結果 | `MenuBuildResult` / `MenuBuildError`：可定位訊息，不靜默失敗 | 承 E7-13 NFR-04 精神；未知 kind、型別不符、非 submenu 帶子項等皆結構化回報 |
| 標籤排版 | `CustomMenuRenderer` 綁定 E4-01 `FontMetrics`，`render_model()` 時逐列呼叫 `TextLayout::layout()` | 排版與模型建構分離；換字型引擎（相位 2+）只換注入的 FontMetrics |
| 面板呈現目標 | 每個展開層一個具名 `SurfaceId`；子層尾碼取自擁有者子選單項的**具名 id**（如 `root.menu:file`），非數字深度 | NFR-02：不得以數字 z-order / 深度指涉 |
| 巡覽狀態 | 單一游標路徑 `cursor_`（vector<size_t>）；其長度即目前展開面板數，各層祖先索引即該層高亮列 | 免維護「開啟鏈」與「高亮列」兩份平行狀態；render_model 直接從游標推得可見面板 |
| 鍵盤巡覽 | `move_next/move_prev`（跳過分隔線 / 停用項，循環）、`enter`（進入子選單）、`exit`（收合）、`activate`（致動；Submenu 等同 enter，Checkbox 切換勾選） | 完整覆蓋標準選單鍵盤語意 |
| 滑鼠巡覽 | `hover(path)`（僅限目前展開鏈可見的列，否則 Invalid）、`select(path)`（hover + activate） | 滑鼠只能命中「目前渲染中」的列，避免游標跳到未展開的分支 |
| 邊界情形 | `MenuNavStatus{Moved/Entered/Exited/Selected/NotSelectable/Invalid/Empty}` | 空選單、無效路徑、命中分隔線 / 停用項 / 空子選單，一律結構化回報，絕不崩潰 |

平台中立：無 `#ifdef` / win32 / cocoa / NSMenu 分支，未建立 `src/**/backend/win32|cocoa/`，
符合相位 1 與 `backend_guard` 約束。核心 API 無絕對座標 / 數字 z-order（NFR-02）。
