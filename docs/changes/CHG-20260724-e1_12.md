# CHG-20260724-e1_12 — 多重從屬 surface 並存（E1-12）

- Date: 2026-07-24 | Branch: feat/e1_12 | Risk: low | Implemented by: I1.145
- Skill: ai-sdlc-autopilot
- Unit: E1-12（多重從屬 surface 並存，platform 層 / kernel 子系統 / phase=1 / risk=low / depends_on=[E1-11]）

## Motivation

E1-11 `SubordinateLayout`已解決「單一父 → 單一子」的相對定位（父移動子跟隨、父關閉子連帶），
但真實桌面情境中，**一個父 surface 常常同時掛多個從屬 surface**——例如同一個輸入框同時有
tooltip、下拉選單、驗證提示三個子並存；同一個工具列上多個按鈕各自的提示泡泡同時存在。若沒有
專門的「多子並存」管理層，呼叫端得自行追蹤「這個 parent 底下目前有哪些子」、自行迴圈呼叫
`resolve_child`、自行確保個別 detach 不誤刪其他子——這類手寫協調邏輯容易漏寫，也容易在「父移動
時只更新了部分子」這種情境產生視覺不同步的 bug。

E1-12 在 E1-11 之上加一層 **`MultiSubordinateManager`**：列舉某 parent 目前所有直接子
（`children_of`）、一次性批次重新解析其下所有子（`reposition_all`，「父移動時全部跟隨」）、
個別關閉（`detach_child`）或全部關閉（`detach_all`），並確保多個子並存時互不覆寫、互不衝突。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 與 E1-11 的關係 | 以**組合**（composition）持有一個 `SubordinateLayout` 實例作為父子附著 + 相對定位的**唯一真實來源**；本單元不重寫附著記錄或佈局計算 | 不重新發明 E1-11 已解決的問題；`attach_child`/`detach_child`/`detach_all` 直接委由 E1-11 `attach`/`detach`/`close_parent`，行為（含就地更新、循環偵測、父關閉連帶）完全繼承其正確性 |
| 元件尺寸的額外記錄 | E1-11 `resolve_child` 每次呼叫都需呼叫端傳入子元件尺寸（設計成不快取）；本單元為了讓 `reposition_all(parent, new_placement)` 只憑一個新父矩形就能批次重解析*全部*子，額外以 `element_sizes_`（具名鍵配對，與 E1-11 的 `Record` 同風格）記住每個子的元件尺寸，與底層附著記錄保持同步 | 若不記錄，`reposition_all` 無法在只有一個「新父矩形」參數的情況下批次求解——呼叫端仍得為每個子額外準備元件尺寸，失去「一次性批次」的意義 |
| `children_of` 列舉順序 | 依 `element_sizes_` 的登錄順序（= 附著順序）過濾出 `parent_of(child) == parent` 者 | 順序即附著順序，永不以數字 index 對外暴露（NFR-02 一貫風格）；具名 vector 回傳，呼叫端可直接迭代 |
| `attach_child` 提前驗證元件尺寸 | 非有限 / 負值元件尺寸在附著當下即拒絕（`is_finite_size`，複用 E1-07 公開函式），不待日後 `reposition_all` 才發現無法解析 | 避免留下「附著記錄存在、但永遠無法批次重解析」的半吊子狀態；與 E1-07 `resolve()` 對元件尺寸的既有判定一致，不重寫邏輯 |
| `reposition_all` 對個別解析失敗的處理 | 略過該子、不中斷其餘子的批次重解析（結構化省略，不崩潰） | 理論上不會發生（`attach_child` 已驗證過 spec 與元件尺寸），但仍以防禦性寫法避免單一子的例外狀況拖垮整批重解析 |
| `detach_all` 的元件尺寸同步 | 呼叫底層 `close_parent`（遞迴清除該 parent 下所有直接 / 間接子）後，掃描 `element_sizes_`，移除所有「已不在底層附著記錄中」的項目 | `close_parent` 只回傳清除筆數，不回傳被清除的 id 列表；以「事後比對底層真實狀態」同步，簡單且對任意深度巢狀從屬鏈皆正確，不需底層額外開介面 |
| 避免衝突 | 多個子各自以獨立的具名 `SurfaceId` 為鍵存在——同一 parent 掛第二個 child 時，因為 key 是 child 本身（非 parent），天然不會覆寫彼此；只有「同一 child 再次附著」才視為就地更新（繼承 E1-11 既有語意） | 「多重從屬並存避免衝突」的核心即「以 child 具名鍵區分」，非本單元新發明的機制，而是 E1-11 附著記錄模型的自然延伸 |
| 結果碼 / 型別 | 全部復用 E1-11 / E1-07 的 `AnchorStatus` / `AnchorSpec` / `Size` / `ResolvedPlacement` / `SurfaceId`，不新增列舉或型別 | 與上游同風格；本單元純屬「多子並存」的管理便利層，不引入新概念 |

## Impact

### 影響分析（low 風險）

- **回溯相容**：純新增單元。未改任何既有 `src` / `engine` / `modules` / 上游單元（E1-11 及其傳遞
  依賴 E1-07 / E1-03 / E1-21 / backend_null）/ `units.json` / 根 CMakeLists / 共用 `directory.md`；
  對既有單元零影響。
- **上游耦合**：僅**唯讀**依賴 E1-11（`target_link_libraries(e1_12 PUBLIC e1_11)`），透過其 include
  鏈取得 `SubordinateLayout` / `AnchorSpec` / `Size` / `ResolvedPlacement` / `AnchorStatus` 及傳遞的
  `SurfaceId`。不觸碰上游任何符號實作，不繼承、不加虛擬方法；純以組合（持有 `SubordinateLayout`
  成員）複用。
- **NFR-02（核心 API 不得絕對座標 / 數字 z-order）**：`MultiSubordinateManager` 的公開 API 全數以
  具名 `SurfaceId` 指涉、`AnchorSpec`（具名 anchor + 相對偏移）表達定位；`children_of` 回傳
  `vector<SurfaceId>`（具名值，非數字 index）；具體像素只在 `attach_child` 的元件尺寸輸入與
  `reposition_all` 的解析輸出出現，非宣告式附著 API 的一部分。
- **下游意義**：`MultiSubordinateManager` 讓「一個父同時掛多個從屬 surface」（tooltip + 下拉 +
  標註等同時並存）的場景有現成的列舉 / 批次操作入口，供未來 UI 層（如工具列、輸入框元件）直接
  使用，不需自行手寫「追蹤某 parent 底下有哪些子」的協調邏輯。
- **建置面**：新增靜態庫 `e1_12`（`PUBLIC` 連 `e1_11`）與可執行檔 `test_e1_12` + CTest `e1_12`。
  根 CMakeLists 既有層級 GLOB（`src/*/*/CMakeLists.txt`，深度 2）已涵蓋
  `src/kernel/e1_12/CMakeLists.txt`，**無需**改根建置檔。
- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發；純記憶體 / 純管理邏輯無平台分支。

### 測試（gtest，18 案例）

多子並存（同一 parent 下多個 child 各自附著、各自以 E1-11 定位互不覆寫）；`children_of`（依附著
順序列舉、未知 / 無子 parent 回空）；`reposition_all`（父移動時批次重解析所有子、每子整體平移
相同量、無子 parent 回空）；`detach_child`（個別關閉不影響其餘子、元件尺寸記錄同步清除、未知
child 結構化回報）；`detach_all`（全部關閉 parent 底下所有直接子、遞迴清除巢狀從屬鏈 + 自身且
不影響無關附著、元件尺寸記錄同步清除、無附著回 0）；多父多子（不同 parent 各自管理各自的子，
互不干擾，重解析 / 全部關閉一個 parent 不影響另一個）；無效附著（空 id、自附、循環、無效 anchor
spec、非有限 / 負值元件尺寸 → Invalid 不記錄；同 child 再次附著視為就地更新，不產生第二筆並存
記錄）。
