## Motivation

C3-01「啟動器選單樹」：階層式選單（E7-13 宣告式定義的樹狀結構）——節點可展開 / 收合、可
選取；選中**葉節點**時透過 E3-02（啟動程式 / 開檔 / 網頁搜尋致動器，經其上游 E6-01 命令
匯流排）觸發對應的啟動動作；選中**非葉節點**則不啟動。這是一個**組裝型 artifact 單元**：
不新增引擎邏輯，而是把三個已合併的擴充點（C1-05 召喚面板基底 profile、E7-13 階層式項目
結構、E3-02 啟動致動器）組成單一 launcher + 行為（load_menu / expand / collapse / select /
activate）。相位 1：純資料結構 + 注入式啟動後端，無真實 GUI、無真實啟動。

## Impact

### 新增 `content/c3_01/`

- `launcher_menu_tree.hpp` / `.cpp`：`namespace ds::content`。
  - `LauncherMenuTree`：注入式相依 `ds::profiles::SummonPanelProfile&`（C1-05，本單元**掛載**
    其上，重用其選項森林儲存 `set_items()` / `items()`，本身即透傳 E7-13 `build_forest` /
    `Item`）+ `ds::command::CommandBus&`（E6-01，經 E3-02 透傳，葉節點啟動時的注入式分派
    目標——相位 1「注入式啟動後端」，本單元不建立匯流排或致動器，只消費呼叫端已掛好的
    具名命令）。
  - `load_menu(Value)` / `load_menu(vector<Item>)`：委派 C1-05 `set_items()`；成功後清空
    展開狀態集合（避免殘留指向新樹中不存在 id 的展開紀錄）；失敗（結構違反）不動現有選單。
  - `expand(id)` / `collapse(id)` / `is_expanded(id)` / `expanded_count()`：**本單元自有**
    的展開 / 收合狀態追蹤（純資料 `std::set<std::string>`——C1-05 / E7-13 皆無此概念）。
    對不存在 id、葉節點（無子項目，展開無意義）、或重複展開 / 收合（no-op）一律回 false，
    不靜默。
  - `select(id)`：找不到 → `NotFound`；找到但非葉節點 → `NotLeaf`（不啟動，不影響展開
    狀態）；找到且為葉節點 → 委派 `activate(id)`。
  - `activate(id)`：語意與 `select()` 對葉節點的分支一致，供直接呼叫驗證 E3-02 組裝。
    葉節點 `value()`（E7-01 `Value`）以保留鍵 `command`（命令 id 字串）+ 選填 `args`
    （字串到字串的 Map）描述啟動意圖，轉譯為 E6-01 `CommandArgs` 後交由注入的 `CommandBus`
    分派：value 非 Map / 缺合法 `command` / `args` 型別不符 → `ActivationFailed`（不觸及
    匯流排）；分派後 `CommandResult.ok()` → `Activated`，否則（含匯流排 `NotFound`）→
    `ActivationFailed`。`last_command_result()` 供內省。
  - `make_launch_program_value` / `make_open_file_value` / `make_web_search_value`：便捷
    工廠，直接对齐 E3-02 三個具名命令 id（`launch.program` / `open.file` / `web.search`）
    與其參數鍵名（program/args、path、query/engine），呼叫端組宣告式選單樹時不需自行記住
    保留鍵。
  - 具名結果 `SelectOutcome`（`Activated` / `ActivationFailed` / `NotLeaf` / `NotFound`），
    附 `to_string()`（NFR-02：具名，非數字）。
- `CMakeLists.txt`：`add_library(c3_01 STATIC launcher_menu_tree.cpp)` +
  `target_link_libraries(c3_01 PUBLIC c1_05 e7_13 e3_02)` + `test_c3_01`
  （`tests/c3/test_c3_01.cpp`）+ `add_test(NAME c3_01)`。不改根 CMakeLists。

### 新增 `tests/c3/test_c3_01.cpp`

`SummonPanelProfile` + `CommandBus` + 掛了 `NullLaunchBackend` 的 `LaunchActuator`）：
- 載入選單樹：宣告式 Value 建構 3 層森林、非 List 失敗且不動現有選單、程式化 `vector<Item>`
  多載。
- 展開 / 收合：非葉節點展開 / 收合 / 重複操作拒絕、葉節點拒絕展開、不存在 id 拒絕、多層
  節點各自獨立的展開狀態、`load_menu` 換樹清空展開狀態。
- 選取葉節點透過 E3-02 啟動：`launch.program` / `open.file` / `web.search` 三種，經
  `NullLaunchBackend::records()` 驗證實際分派到後端的 `LaunchRequest`（kind / target /
  arguments / engine）。
- `activate()` 直接呼叫：與 `select()` 對葉節點分支等價；對非葉節點回 `NotLeaf`。
- 選取非葉節點不啟動：驗證 `NullLaunchBackend` 全程無記錄。
- 無效節點 / 無效啟動宣告：不存在 id（`NotFound`）、葉節點 value 非 Map、缺 `command`、
  `args` 型別不符（皆 `ActivationFailed`，且從未觸及匯流排）、`command` 指向未掛上匯流排
  的命令 id（`ActivationFailed`，`last_command_result().status == NotFound`，仍未觸及
  `NullLaunchBackend`——區分「解析失敗」與「匯流排找不到命令」兩種失敗路徑）。
