# CHG-20260724-e4_26 — 音效播放（E4-26）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e4_26 | Risk: low | Implemented by: I1.11
- Skill: ai-sdlc-autopilot v1.1
- Unit: E4-26（音效播放，module 層 / 子系統 elements / 非視覺 / low）

## Motivation

桌面外殼的 UI 元件（按鈕點擊、通知、錯誤提示、拖放回饋等）需要播放短音效以提供聽覺回饋。
若直接綁真實音訊裝置（CoreAudio / WASAPI 等），播放邏輯將無法在單元測試中重現——
無法斷言「誰正在播放、音量多少、呼叫序列」，也違反 module 層「平台中立、換平台不動邏輯」。

E4-26 提供平台中立的音效播放抽象：以 `SoundId` / `SoundClip` 為音效資源引用（由 `SoundLibrary`
註冊配發），`AudioPlayer` 為播放介面，並附一個 `NullAudioPlayer` null 後端——記錄呼叫並維護
純播放狀態，但**不出聲、不碰任何真實音訊裝置**。真實輸出後端於後續相位另實作同一介面。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 資源模型 | `SoundId`（uint64，0 保留無效）+ `SoundClip`{ id, name } | 音效以邏輯資源鍵引用；實際位元組來源由真實後端後續解析 |
| 登錄簿 | `SoundLibrary::register_clip(name)` 配發遞增 id；空名回 0 | 純資料操作、id 單調不重用；播放器據此驗證 id 是否已註冊 |
| 播放介面 | `AudioPlayer`：play / stop / stop_all / set_volume / volume / is_playing | 純虛介面；真實與 null 後端共用，換後端不動呼叫端 |
| null 後端 | `NullAudioPlayer`：維護播放集合、累計計次、主音量、呼叫記錄 | 完全可單元測試狀態轉換；不驅動任何音訊 API |
| play 語意 | 未註冊 / 無效 id 回 false 不改狀態；重播同 id 計次 +1 仍算一個播放中 | 保守可預期；重播對應真實「重新觸發」 |
| 音量 | `set_volume` 夾到 [0,1]，預設 1.0 | 越界輸入永遠安全 |
| 內省 | `play_count` / `playing_count` / `call_log`（含 accepted 標記） | 供測試斷言狀態轉換與呼叫序列 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支、不綁任何真實音訊裝置或後端。
