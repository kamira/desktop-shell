# CHG-20260724-e1_03 — 逐像素 alpha surface（E1-03）

- Date: 2026-07-24 | Branch: feat/e1_03 | Risk: medium | Implemented by: I1.95
- Skill: ai-sdlc-autopilot
- Unit: E1-03（逐像素 alpha surface，P0 / 核心 / platform 層 / phase=1 / depends_on=[E1-25] / load_bearing=20）

## Motivation

桌面外殼要能放置**不規則形狀 / 半透明**的桌面元件（非矩形桌寵、羽化邊緣浮層、玻璃感面板），
其前提是 surface 能帶**逐像素 alpha（per-pixel alpha）透明度**——每個像素各自決定透明程度，而非
整塊矩形不透明。但這是**平台相依**能力：部分桌面環境 / 合成器不提供逐像素透明視窗（或需特定
合成器旗標）。若上層直接假設此能力存在，換平台時會安靜地退化成黑底方框或直接失效。

E1-03 於相位 1（Mac / null 期）**只交付介面擴充 + null 行為**：在上游 E1-24 `KernelBackend`
surface 模型之上，提供「建立支援 per-pixel alpha 的具名 surface、查詢 / 設定 alpha、生命週期」
的能力閘控服務層，並以 null 後端記憶體模擬其狀態。per-pixel alpha 表述為一項**可選能力**
（NFR-03），使用前一律經 `has()` 閘控且備妥降級路徑；不寫任何真實平台後端 / 繪圖 API。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建構位置 | 新服務層 `AlphaSurfaceService`（`src/kernel/e1_03/`），持 `KernelBackend&` 參考 | 上游 `KernelBackend` 介面為固定（可讀不可改），不得在其上加虛擬方法；以組合（wrap 後端）擴充，實體 surface 委由後端 K1 原語，本層只加 alpha 語意 |
| 能力表述 | 新可選能力鍵 `surface.per_pixel_alpha`（`kPerPixelAlphaCapability`） | NFR-03：per-pixel alpha 平台相依，屬可選能力，使用前 `has()` 閘控 + 降級 |
| 能力來源 | 上游 E1-21 `CapabilityMatrix`；`defaults()` **未**宣告該鍵 → 保守回 false | 不改上游；預設（保守）矩陣下能力不可用，符合「相位 1 可選能力一律不可用」 |
| 「具備能力」情境 | 提供 `alpha_capable_matrix()`：以 `defaults().all()` 為基礎**追加**該能力宣告（default_available=true, optional=true），注入 `NullKernelBackend` | 「後定義者為準」的矩陣語意讓追加項生效；不修改 E1-21，即可在相位 1 模擬「支援逐像素透明」的平台 |
| alpha 資料模型 | `AlphaProfile{ AlphaMode mode; float opacity }`；`AlphaMode`{Opaque, PerPixel} | 逐像素 alpha 以**具名模式**表達；opacity 為**正規化** [0,1] 整體不透明度乘數（比例值，非座標 / 非數字 z-order，不違反 NFR-02）；相位 1 無法逐像素 (x,y) 設值（那會引入絕對座標），故以「模式 + 正規化不透明度」承載 |
| 結果碼 | `AlphaStatus`{Ok, Unsupported, Invalid}，與 E1-25 契約 `Status` 同語意 | 跨後端一致；`Unsupported`=能力閘控擋下（降級路徑），`Invalid`=前置條件不滿足 |
| null 記憶體模擬 | 服務層自持 `vector<Record{SurfaceId, AlphaProfile}>`（上游 `SurfaceProfile` 無 alpha 欄位） | 相位 1「null 後端記憶體模擬」：alpha 通道狀態存記憶體，與後端 surface 表同步建立 / 銷毀 |
| 具名指涉 | surface 一律以具名 `SurfaceId` 指涉；線性掃描、順序即建立順序 | NFR-02：無數字 handle / index / 絕對座標 / 數字 z-order |
| 穩健性 | opacity 非有限值（NaN/Inf）拒為 Invalid、越界 clamp 至 [0,1]；未知 / 空 / 重複 id 結構化回 Invalid，絕不崩潰 | 保守、可預期的錯誤處理契約 |

## Impact

### 影響分析（medium 風險，load_bearing=20 —— 高影響，謹慎覆核）

- **高承載的下游意義**：units.json 中多個單元 `depends_on` E1-03（波次 3+ 的視覺 / 合成 /
  元件單元）。E1-03 定義的**能力鍵 `surface.per_pixel_alpha`** 與 **`AlphaProfile` / `AlphaStatus`
  型別**會成為這些下游表達「這個 surface 要逐像素透明」的共同詞彙。因此本單元的 API 面須保守且
  平台中立：只承載「能力查詢 + 具名模式 + 正規化不透明度 + 生命週期」，**不觸及**任何平台專屬的
  合成細節（premultiplied vs straight alpha、色彩空間、混合方程式），那些留給真實後端相位 2+ 決定。
- **能力鍵是跨後端契約的一部分**：`surface.per_pixel_alpha` 一旦定名，未來 win32 / cocoa 後端
  須以相同鍵回報實際探測結果（DWM 合成開關 / `NSWindow` 透明設定）。相位 1 以 `defaults()` 保守
  預設不可用、以 `alpha_capable_matrix()` 表達「可用」情境，兩者皆不改上游 E1-21 資料來源。
- **降級路徑是驗收硬項**（acceptance：「能力閘控項須附降級路徑測試」）：`supported()==false` 時
  所有變更操作回 `Unsupported` 且**零副作用**（不建 surface、不改狀態），已有專門測試覆蓋。呼叫端
  據此走降級（例如改用不透明矩形 surface 或整體半透明近似）。
- **不修改上游介面的耦合取捨**：因 `KernelBackend` 固定、其 `SurfaceProfile` 不含 alpha 欄位，
  本層以**組合**擴充並另存 alpha 狀態。已知後續演進點：真實後端上線後，若 kernel surface 模型
  正式納入 alpha 通道欄位，本服務的記憶體 alpha 記錄應收斂為對後端 surface 屬性的讀寫；屆時
  `AlphaSurfaceService` 的公開 API 可維持不變（實作換底），下游不受影響。已於 header 註記。
- **建置面**：新增靜態庫 `e1_03`（`PUBLIC` 連 `e1_21` + `backend_null`）與可執行檔 `test_e1_03`
  + CTest `e1_03`。根 CMakeLists 既有層級 GLOB（`src/*/*/CMakeLists.txt`，深度 2）已涵蓋
  `src/kernel/e1_03/CMakeLists.txt`，**無需**改根建置檔。
- **回溯相容**：純新增單元，未改任何既有 `src` / `engine` / `modules` / 上游單元（E1-21 /
  E1-24 / E1-25）/ `units.json` / 根 CMakeLists / 共用 `directory.md`；對既有單元零影響。
- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發。
