## Motivation
C4-02「截圖與標註」（screenshot & annotate）：擷取螢幕指定區域後在其上標註箭頭 / 框 / 文
字，匯出含影像參照（或存檔路徑）與標註數量的結果 bundle。這是一個**組裝型 artifact
app**：不新增引擎邏輯，而是把三個已合併的擴充點組成單一應用 + 行為
（`capture(region)` / `annotate_*(shape)` / `export_result()`）：

- **E3-11**（`ds::actuators::ScreenCaptureBackend` / `CaptureSpec` / `CaptureRegion` /
  `CaptureResult`）：以**注入式**擷取後端擷取指定區域。
- **E4-20**（`ds::elements::VectorGraphic` / `Shape` / `build_shape_path`）：把箭頭
  （相位 1 簡化為直線）/ 框（矩形）標註轉為向量渲染描述；文字標註不經向量路徑。
- **E4-30**（`ds::elements::DimOverlayElement`）：全螢幕調光覆蓋，本單元借它組出**選取框
  覆蓋**——顯示覆蓋層並在擷取區域挖一個具名「不調光」框選區域，凸顯剛截取的畫面。

相位 1：純資料 / 邏輯組裝，無真實螢幕擷取（僅注入式擷取後端）、無真實影像合成 / 檔案
匯出。

## Impact

### 新增 `apps/c4_02/`
- `screenshot_annotator.hpp` / `.cpp`：`namespace ds::apps`。
  - `ScreenshotAnnotatorApp`：以 `shared_ptr<ds::actuators::ScreenCaptureBackend>`（可
    null，相位 1 注入式擷取後端，沿用 E3-11 `ScreenCaptureBackend` 抽象）+
    `ds::elements::DimOverlayElement&`（不取得所有權，沿用 E4-30/C4-03 的組裝相依風格）
    建構。
  - `capture(CaptureRegion, save_path="")`：直接組出 `CaptureSpec{kind=Region}` 呼叫
    `backend_->capture()` → `CaptureStatus::Ok`（成功，`current_capture()` 更新、清空既有
    標註、若選取框覆蓋作用中一併收起）/ `InvalidRegion`（區域寬 / 高非正）/
    `NoBackend`（backend 為 null）。失敗一律**不動**既有擷取狀態（不靜默清空已成功擷取
    過的畫面）。
  - `annotate_arrow(from, to)` / `annotate_box(origin, width, height)`：委派 E4-20
    `build_shape_path`（`Shape::make_line` / `Shape::make_rect`）建路徑，包成
    `VectorGraphic`（描邊啟用，寬度 = `kAnnotationStrokeWidth`）產出 `render_model()`，
    存為 `Annotation{kind, render, anchor}`。退化形狀（零長度線段 / 零負寬高矩形）/
    非有限座標 → `AnnotateStatus::Invalid`，不追加。
  - `annotate_text(position, text)`：不建向量路徑（本層無字形渲染），僅記錄
    `Annotation{kind=Text, anchor, text}`（`render.empty` 恆 true）。空字串 / 非有限位置
    → `Invalid`。
  - 三者尚未成功擷取過（`has_capture()` 為 false）一律先回 `AnnotateStatus::NoCapture`。
  - `annotation_count()` / `annotations()` / `clear_annotations()`：內省與清空；新一次
    `capture()` 成功時自動清空既有標註（新擷取開新標註 session）。
  - `show_selection()` / `hide_selection()`：組裝 E4-30 ——`show()` +
    `add_cutout(kSelectionRegionName)`（固定具名區域，NFR-02 具名而非座標）；尚未擷取即
    框選 → `DimStatus::Invalid`；能力不可用時委派 E4-30 降級為 `Unsupported`（標註 / 匯出
    不受影響）；`hide_selection()` 移除挖洞並 `hide()`，恆安全。新一次 `capture()` 成功時
    若選取框作用中，一併收起（挖洞名對應前次擷取，換畫面後不再有效）。
  - `export_result()`：彙整 `ExportResult{ok, width, height, image_ref, path,
    annotation_count}`（相位 1：純描述性 bundle，不做真實影像合成 / 檔案寫入）；尚未
    成功擷取過 → `ok=false`，其餘欄位維持預設值。
  - 具名結果 `CaptureStatus`（Ok / NoBackend / InvalidRegion）、`AnnotateStatus`（Ok /
    NoCapture / Invalid）、`AnnotationKind`（Arrow / Box / Text）皆附 `to_string()`
    （NFR-02）。
- `CMakeLists.txt`：`add_library(c4_02 STATIC)` +
  `target_link_libraries(c4_02 PUBLIC e3_11 e4_30 e4_20)` + `test_c4_02`
  （`tests/c4/test_c4_02.cpp`）+ `add_test(NAME c4_02)`。

### 新增 `tests/c4/test_c4_02.cpp`（gtest，25 案例）
涵蓋：`capture` 擷取成功（含 save_path）、無效區域（寬 / 高非正，不動既有擷取狀態）、
無後端、尚未擷取即標註（`NoCapture`）、箭頭標註（成功 / 零長度 `Invalid`）、框標註
（成功 / 退化 `Invalid`）、文字標註（成功 / 空字串 `Invalid`）、多標註累加順序、清空
標註、新擷取重置標註、選取框覆蓋（尚未擷取 `Invalid` / 顯示 + 挖洞 / 收起移除挖洞並
隱藏 / 未曾顯示即收起安全 / 新擷取重置選取框 / NFR-03 降級）、匯出結果 bundle（擷取前
`ok=false` / 擷取 + 標註後欄位正確 / save_path 反映於 path）、四組列舉 `to_string()`
穩定字串。

### 相位 1 約束遵循
- 純資料 / 邏輯組裝，無真實螢幕擷取（僅注入式 `NullScreenCaptureBackend`）、無真實影像
  合成 / 檔案匯出；無平台分支（無 `#ifdef` / win32 / cocoa）。
- 核心 API 無數字 z-order（NFR-02）：選取框覆蓋以固定具名挖洞區域
  `kSelectionRegionName` 表達，非疊放層級；擷取區域沿用 E3-11 既有 `CaptureRegion`
  （已合併定案的擷取請求語意，非 surface 疊放座標）；標註座標沿用 E4-20 `Point`（元件
  本地座標系，非螢幕像素）。
- 能力閘控（`show_selection()` 建立 / 改動半透明覆蓋層）委派 E4-30 既有的
  `AlphaSurfaceService::supported()` 閘控（NFR-03），本單元不重造閘控邏輯。
- 無效操作一律明確回具名結果，不靜默（無效區域、無後端、尚未擷取即標註 / 框選、退化
  標註形狀、空文字標註）。
