# CHG-20260724-e2_24 — Wi-Fi 狀態（E2-24）

- Date: 2026-07-24 | Branch: feat/e2_24 | Risk: low | Implemented by: I1.72
- Skill: ai-sdlc-autopilot

## Motivation
E2-24「Wi-Fi 狀態」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一指標
介面**（擴充點 1 契約）把「Wi-Fi 連線狀態」（SSID、訊號強度、連線速率、頻道/頻段、安全類型、
是否已連線）掛成一組指標，並以 **E2-02 採集頻率分級**決定採樣節奏（連線狀態會變動，屬週期
採集）。這是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它
**消費 E2-01 / E2-02 契約、不自造指標模型或排程器**（範式與已合併的 E2-03 CPU 負載、E2-08
網路流量一致）。相位 1（Mac / null 期）**絕不接任何真實 Wi-Fi API**（不含 CoreWLAN /
`CWInterface` / `airport` / `#ifdef` / win32 / cocoa）；改為**可注入的 `WifiSource` 抽象** +
null / 假來源（注入固定一份或整條序列，可模擬未連線 / 掉線）。與 CPU / 網路不同，Wi-Fi 狀態
是**直接讀**的瞬時快照，**無累積差分**。真實平台後端留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_24/`（module 層 / 子系統 sysinfo）
- `wifi_status.hpp` / `wifi_status.cpp`（`namespace ds::sysinfo`）：
  - **列舉**（平台中立）：
    - `WifiBand`：`Unknown` / `Band2_4GHz` / `Band5GHz` / `Band6GHz`，附 `to_string`
      （"unknown"/"2.4 GHz"/"5 GHz"/"6 GHz"）。
    - `WifiSecurity`：`Unknown` / `Open` / `WEP` / `WPA` / `WPA2` / `WPA3` / `Enterprise`
      （由弱到強粗略排序，ordinal 供數值維度），附 `to_string`。
  - **純算術自由函式**（獨立可測）：`rssi_to_percent(dbm)` = `clamp(2*(dbm+100), 0, 100)`
    （-100 dBm→0%、-50 dBm→100%，其間線性、超界夾住），供來源未直接給百分比時換算。
  - **值模型** `WifiStatus`（平台中立）：`connected` / `ssid` / `rssi_dbm` / `signal_percent`
    / `link_rate_mbps` / `channel` / `band` / `security` + `valid`（含相等運算子）。工廠：
    `unknown()`（無讀值，保守預設）、`connected_to(ssid, rssi, rate, channel, band, security)`
    （已連線，signal_percent 由 `rssi_to_percent` 換算）、`not_connected()`（有讀值但未連線）。
  - **Wi-Fi 來源**（提供者只依賴此抽象）：
    - `WifiSource`（抽象 `sample()→WifiStatus`；非 const，序列型來源取樣有副作用）。
    - `NullWifiSource`：相位 1 null / 假來源——**不接真實 Wi-Fi API**，預設回無讀值；可注入
      **固定**一份（`set_status` / 單參建構）或整條**序列**（`set_sequence` / `push_status` /
      向量建構），`sample()` 回下一份、列盡持續回最後一份、空列回 `unknown()`；`reset` /
      `clear` 重置。序列即「模擬連線狀態隨時間變動 / 掉線」的手段。
  - **提供者** `WifiStatusProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.wifi"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**七個
    面向指標**，各以單一 Wi-Fi 介面實例（`instance_id="wifi0"`、label "Wi-Fi"）列舉：
    - `wifi.connected` / "Wi-Fi Connected" / unit "" / `bounded[0,1]`（1|0 + 文字
      "Connected"/"Disconnected"）
    - `wifi.ssid` / "Wi-Fi SSID" / unit "" / `unbounded`（文字表述）
    - `wifi.rssi` / "Wi-Fi Signal (RSSI)" / unit "dBm" / `bounded[-100,0]`
    - `wifi.signal` / "Wi-Fi Signal" / unit "%" / `bounded[0,100]`
    - `wifi.rate` / "Wi-Fi Link Rate" / unit "Mbps" / `at_least(0)`
    - `wifi.channel` / "Wi-Fi Channel" / unit "" / `at_least(0)`（頻道 + 頻段文字）
    - `wifi.security` / "Wi-Fi Security" / unit "" / `unbounded`（ordinal + 文字）
    - `sample()`：重新讀來源、把新狀態寫入各實例。**數值面向**（RSSI / 訊號 % / 速率 /
      頻道 / connected）有效值推入歷史（`kDefaultHistory=64`），配合 E2-02 週期採集鋪成時序；
      **categorical 面向**（ssid / security）只設值、不污染歷史。register 尚未呼叫時為
      no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Normal`，
      建構子可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
    - `metric_ids()`：回七個面向 id（註冊順序）。`current_status()`：回目前一份狀態（診斷）。
  - **無讀值 / 未連線語意**（誠實不謊報）：整體無讀值（source 為 null / 回 `unknown`）→ **所有
    面向** `valid==false`（未知）。**未連線**（`connected==false` 但有讀值）→「是否已連線」
    面向有效（值 = 未連線），但 SSID / RSSI / 訊號 / 速率 / 頻道 / 安全等**連線相依面向**誠實
    未知（無連線即無這些讀值可言，不塞假值）。source 為 null 亦保守不崩（七指標皆未知）。
  - `CMakeLists.txt`：`add_library(e2_24 STATIC)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭
    include `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_24` +
    `add_test(NAME e2_24)`。

### 新增測試 `tests/e2/test_e2_24.cpp`（gtest，26 案例）
覆蓋：提供者身分 / 為 `MetricProvider` / 預設分級 Normal 可覆寫；七指標與單一 Wi-Fi 實例
列舉；各指標 range / unit 正確；已連線各欄位讀值（SSID / RSSI / 訊號 % / 速率 / 頻道+頻段 /
安全類型 / 已連線）；未連線→連線相依面向誠實未知；無讀值（空來源）與 null source 指標→全
未知；`rssi_to_percent` 邊界夾 [0,100]；已連線工廠換算 signal_percent；訊號邊界經 range 正規化；
`WifiBand` / `WifiSecurity` 的 `to_string`；null / 固定 / 序列來源行為；`sample()` 掉線重讀；
register 前 sample no-op；數值面向歷史累積（1+採樣次數）/ categorical 面向不累積；經 E2-02
`SamplingScheduler` 週期採樣（Normal=每 8 tick）與除頻合併（High 覆蓋 Normal）；重複註冊保守拒絕。
