## Motivation

使用者指定的四個功能之四。E11-02「自繪選單呈現」在相位 1 已完成模型、排版、
相對幾何與巡覽（全平台中立），但從未有平台實作把它畫出來。

## Impact

`host/menu/` 新目錄：

- `tray_menu_to_items()`：E11-01 `TrayMenu` → E7-13 `Item` 森林（E11-02 的輸入）
- `place_menu_popup()`：邊緣翻轉，純幾何
- `paint_menu_panel()`：把 E11-02 的渲染描述用 GDI 畫出來
- `OwnerDrawnMenu`：彈出視窗 + 小型 modal 迴圈 + 輸入路由

`W1-02` 新增 `set_owner_drawn()` / `poll_menu_request()`：開啟後右鍵不再呼叫
`TrackPopupMenu`，而是把「使用者要開選單」交給 host。**預設為 false**（保守）。

### 兩個模型之間的轉換（兩個容易錯的地方）

- **分隔線沒有命令 id**，但 E11-02 要求 id 唯一 → 以索引合成穩定 id
- **`checked` 只有 checkbox 項可用**（E11-02 檔頭明載）→ 對其他種類帶上會讓
  `build_menu` **整份失敗**。初版對每一項都塞，`set_menu` 直接回 `false`，
  而且錯誤訊息被 `bool` 吃掉——是逐條比對契約文件才找到的

## ⚠ 明確的功能退步：無障礙

原生 `HMENU` **免費**提供鍵盤巡覽、螢幕閱讀器無障礙、IME、DPI 縮放、邊緣翻轉、子選單定位。

本單元做了鍵盤巡覽（委由 E11-02）與邊緣翻轉，
**但沒有做無障礙（UI Automation / MSAA）——螢幕閱讀器讀不到這個選單。**

這不是「尚未測試」，是**真的沒有**。因此：
- `set_owner_drawn()` 預設 **false**
- host 明確開啟，且原生路徑完整保留
- 要退回原生選單只需拿掉 `host_main.cpp` 的那一行

**子選單目前不展開子面板**（僅以右側箭頭示意）。托盤選單無子選單，不影響現況。

## 明確不改

- 未改 E11-02 / E11-01 / E7-13 的任何一行——E11-02 的模型與巡覽原封不動使用。
- 未移除原生 `TrackPopupMenu` 路徑。
