## Motivation

角色對話 / 提示文字常見「逐字打字機效果」(typewriter effect)：文字不是一次全顯，而是隨時間
一個字一個字漸次浮現。此效果需要兩件事：一個「時間 → 顯示進度」的推進來源，與一個把「目前
已顯示的前綴」轉成可繪製渲染描述的排版器。E4-09 已提供平台中立的動畫驅動源（把心跳脈衝轉為
時間推進），E4-01 已提供文字排版（把字串轉成相對佈局的渲染描述）。E4-11 是把兩者組起來的
elements 層元件：`TypewriterElement` 以注入式 tick 推進「已顯示碼位數」，並委由 E4-01 對
「目前已顯示前綴子字串」排版，產出 `LayoutResult`。相位 1 不接真實時鐘，一切時間由外部注入
（手動 `advance(dt)` 或 `attach()` 一個 E4-09 `AnimationDriver`）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 進度單位 | 以 **碼位（codepoint）** 計數，非位元組 | 多位元組 UTF-8 字元（如中文、重音字母）需視為一個「字」逐字顯示，非逐位元組 |
| 進度累計 | `progress_`（double）累計 `speed * dt`，`visible_count()` 回傳其整數部分並夾在 `[0, total_count()]` | 支援小數速度（< 1 字元/tick）：殘餘進度保留累計，累計滿一整字才前進，不卡住也不漂移 |
| 速度 | `set_speed(chars_per_tick)`：每 tick 顯示幾個字元（可小數） | 對外用「速度」而非「每字元 tick 數」更直覺；`<=0` 或非有限 → 擲例外 |
| 推進來源 | `advance(Tick dt)` 手動注入；`attach(AnimationDriver&)` 把該驅動源的每次脈衝自動轉呼 `advance(frame.dt)`，回傳其 `AnimationId` | 相位 1 平台中立注入式 tick；`attach` 是 E4-09 整合的薄封裝，不侵入其派發邏輯 |
| 完成判定 | `is_complete()` = `visible_count() >= total_count()`（含空文字 = 立即完成） | 直觀；完成後再 `advance` 為安全 no-op（維持在總字數，不需呼叫端另行判斷） |
| 排版整合 | `render_model()` 對「已顯示前綴子字串」（依 UTF-8 邊界表切出）呼叫 E4-01 `TextLayout::layout()` | 逐字打字機的渲染描述即「目前前綴」的完整排版結果——不重新發明排版邏輯，直接委派 E4-01 |
| UTF-8 邊界表 | `set_text` 先以 E4-01 `decode_utf8()` 驗證並取得碼位序列，再依已驗證合法的位元組自行掃描前導位元組樣式建構「碼位 → 位元組偏移」邊界表 | `decode_utf8` 只回碼位不回位元組偏移；已知合法 UTF-8 後，重掃前導位元組即可安全切出任意前綴子字串 |
| 錯誤處理 | 非法 UTF-8（`set_text`）、非正 / 非有限速度（`set_speed`）→ `std::invalid_argument`（不靜默） | 承 E4-01 對非法輸入不靜默的精神 |
| reset / 換文字 | `reset()` 只歸零進度（保留文字與速度）；`set_text()` 換新文字時一併歸零進度 | 換新文字理應重新從頭逐字顯示；`reset()` 供「重播同一段文字」情境 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支、不綁真實時鐘 / 計時器 / 繪製
後端。**NFR-02**：`render_model()` 直接回傳 E4-01 的相對佈局渲染描述（相對偏移 x/y、行內
advance、具名 `SurfaceId`），本單元未新增任何絕對座標或數字 z-order。
