# CHG-20260724-e9_01 — 統一套件格式定義（E9-01）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e9_01 | Risk: low | Implemented by: I1.18
- Skill: ai-sdlc-autopilot
- Unit: E9-01（統一套件格式定義 / 核心 / engine 層 / 子系統 package）
- Depends on: E9-02（manifest，已合併）— `target_link_libraries(e9_01 PUBLIC e9_02)`

## Motivation

E9-02 已定義「manifest」（套件中繼資料：格式版本 + `requires`/`permissions`）。但一個
可進場的**組件套件**不只是 manifest —— 它還包含資源檔佈局與內含項目清單。E9-01 把這三者
統一成一個「套件」概念：manifest（複用 E9-02）+ 資源引用清單，並提供**結構完整性 + manifest
有效性**的解析與驗證，作為後續打包/載入/沙箱佈局的單一格式來源。平台中立、純邏輯。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 套件結構 | `Package`{ `Manifest` manifest, `vector<PackageEntry>` entries } | manifest + 內含項目清單/資源引用，恰為「一個組件套件的整體結構」 |
| manifest | 直接複用 E9-02 `parse_manifest` | 不重造；欄位/版本/requires/permissions 一律走 E9-02 |
| 文字格式 | manifest 區段 + `---` 分隔線 + 內容清單區段（`kind: logical_path`） | 自足、無外部相依；分隔線前原樣交 E9-02，避免 E9-02「未知 key」誤判 |
| 資源引用 | `PackageEntry`{ kind, logical_path } | kind 為資源類別（對格式不透明）；logical_path 為套件內相對路徑 |
| 路徑合法性 | 相對、不得以 '/' 開頭、不含 '..' 區段、無空區段 | 佈局完整性：禁止絕對路徑與逃逸套件根 |
| 錯誤模型 | `PackageResult`（success \| `ParseError`{line,message}，複用 E9-02 型別） | 可定位、不得靜默；manifest 區段錯誤含行號原樣傳出（區段在頂部，行號對齊） |
| 缺 manifest | 分隔線前無實質內容 → 明確套件級錯誤（定位分隔線 / line 0） | 「缺 manifest」給出清楚訊息，而非落到 E9-02 的必填欄位錯誤 |
| 驗證雙入口 | `parse_package`（文字，就地定位）+ `validate_package`（記憶體 Package，line 0） | 解析即驗證；另供對已構成 Package 的獨立結構完整性檢查 |

平台中立：無 `#ifdef`、無系統呼叫、無真實後端，符合 engine 層「換平台一行不動」約束。

## Impact

### 1. `engine/package/e9_01/package.hpp`（新增）
- `PackageEntry`{ kind, logical_path }、`Package`{ manifest, entries }。
- `PackageResult`（success/failure 互斥；複用 E9-02 `ParseError`）。
- `is_valid_logical_path()`、`parse_package(text)`、`validate_package(pkg)`。

### 2. `engine/package/e9_01/package.cpp`（新增）
- 第一遍以 `---` 分隔線切 manifest 區段 / 內容清單並記錄絕對行號；manifest 區段交 E9-02。
- 第二遍逐條 `kind: logical_path` 解析為 `PackageEntry`，就地做可定位驗證（缺冒號、空 kind/
  path、非法路徑、重複路徑）。缺 manifest 給明確套件級錯誤。

### 3. `engine/package/e9_01/CMakeLists.txt`（新增）
- `add_library(e9_01 STATIC package.cpp)` + `target_link_libraries(e9_01 PUBLIC e9_02)`
  + `test_e9_01` executable + `add_test(NAME e9_01)`，依 BUILD.md 樣板；根 CMakeLists 自動 glob 收入。

### 4. `tests/e9/test_e9_01.cpp`（新增）
- 18 個 gtest 案例：完整套件解析（manifest + 內容清單各項）、僅 manifest / 空清單合法、
  缺 manifest 定位、manifest 錯誤原樣傳遞與行號對齊、內容清單缺冒號/空 kind/空 path/非法路徑/
  重複路徑定位、`is_valid_logical_path` 邊界、`validate_package` 對記憶體 Package 的接受/拒絕、
  value 只切第一個冒號。

### 5. `docs/structure/units/e9_01.md`（新增；G4 要求）
- 每單元獨立結構註記（不動共用的 `directory.md`，避免並行合併衝突）。

## 不含（避免越界）

- **不做打包/解包 I/O、不做真實檔案系統存取**：本單元只定義並解析/驗證套件格式（純邏輯）。
- **不做能力閘控/權限強制**：`requires`/`permissions` 的語意執行屬其他單元。
- **不重造 manifest**：一律複用 E9-02。
- 未動 `units.json`、根 `CMakeLists.txt`、`docs/structure/directory.md` 或任何鎖定範圍外檔案。
