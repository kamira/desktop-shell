# CHG-20260724-e3_09 — 系統旗標切換（E3-09）

- Date: 2026-07-24 | Branch: feat/e3_09 | Risk: low | Implemented by: I1.54
- Skill: ai-sdlc-autopilot

## Motivation
E3-09「系統旗標切換」是 modules/actuators（動作層 / 子系統 actuators）的一個**系統層級布林
旗標 / 模式致動器**：把「切換具名系統開關（勿擾模式 Do-Not-Disturb、深色模式、夜覽 /
Night Shift、飛航模式、螢幕自動旋轉鎖 等）」這組副作用，以具名命令掛上 **E6-01 命令匯流排**
（擴充點 3「動作」契約）。每個具名旗標 `<name>` 對外提供四個動詞命令
`flag.<name>.on` / `flag.<name>.off` / `flag.<name>.toggle` / `flag.<name>.status`；呼叫端只需
命令 id 即可觸發，**不需相依本致動器或任何 OS 系統設定 API**——與已合併的 E3-05（音量致動器）
採同一「注入式後端 + null 樣式」範式。相位 1（Mac / null 期）**絕不呼叫真實 OS 系統設定 API**
（不含 `defaults` / NSUserDefaults / 任何 cocoa / win32 開關 API），只提供**平台中立介面 +
null 後端（純記憶體 map 模擬）+ 契約測試**；真實平台後端留待相位 2，屆時致動器與命令契約一行不動。

## Impact

### 新增 `modules/actuators/e3_09/`（module 層 / 子系統 actuators）
- `system_flag_actuator.hpp` / `system_flag_actuator.cpp`（`namespace ds::actuators`，與 e3_05 一致）：
  - `FlagVerb`（On / Off / Toggle / Status）+ `flag_verb_suffix()`：四個動詞 → 命令後綴。
  - `is_valid_flag_key(const std::string&)`：致動器層唯一的旗標鍵「合法化」點——非空且僅
    `[a-z0-9_]`（排除點號 `.`，因其為 `flag.<name>.<verb>` 命令分隔符；排除空白 / 大寫）。
  - `flag_command_id(name, verb)`：組裝穩定可讀命令 id `flag.<name>.<verb>`（不用數字 opcode）。
  - `SystemFlagBackend` 抽象後端：最小介面 `set(flag,bool)` / `get(flag)`（字串鍵）。相位 2+
    由平台後端以真實系統設定 API 實作；致動器只依賴此抽象。契約：傳入的 flag 已由致動器
    驗證為合法且已登記（後端可信任）。
  - `NullSystemFlagBackend`（相位 1 預設後端）：**不接真實系統設定 API**，以純記憶體
    `std::map<std::string,bool>` 模擬；未曾設定的旗標查詢回 false（預設關）；初值可注入；
    `has()` / `size()` 內省。讓致動器在無真實後端時仍可完整跑通、狀態一致。
  - `SystemFlagActuator`：建構綁定一個 `SystemFlagBackend`（預設 NullSystemFlagBackend）。
    `add_flag(name)` 登記已知具名旗標（旗標鍵須通過 `is_valid_flag_key`；非法 / 重複回 false）。
    `register_on(bus)` 為每個已登記旗標把四動詞命令註冊到 E6-01 匯流排（全成功才 true；任一
    失敗回滾本次已掛者、不遮蔽既有致動器；無後端或無登記旗標回 false）；`unregister_from(bus)`
    回移除的命令數。處理器亦可直接呼叫（測試不經匯流排也能驗證語意）：
    - `flag.<name>.on` / `.off`：設旗標為開 / 關（**冪等**：重複設同值不變）；回操作後狀態（bool）。
    - `flag.<name>.toggle`：翻轉旗標（**自逆**：切換兩次回原狀態）；回操作後狀態。
    - `flag.<name>.status`：**唯讀**查詢目前狀態（不改變）；回目前狀態（bool）。
    未登記 / 非法旗標鍵：命令從未掛上匯流排 → `dispatch` 回 `CommandResult{NotFound}`（不崩潰）；
    直接呼叫處理器時以 `has_flag()` 保護，未登記旗標鍵回 `CommandResult{Failed}`（不丟例外、
    不改後端狀態）。`current(flag)` 內省；`flag_names()` 回有序已登記旗標鍵。所有成功結果的
    `value` 皆為操作後旗標布林狀態，訊息帶 `flag=on/off`。
  - `system_flag_contract_version()`：契約版本標記 `"e3_09/1.0.0"`（定義在 .cpp，使 STATIC
    程式庫非空並集中版本字串；命名加 `system_flag_` 前綴避免與同命名空間其他致動器的版本
    函式衝突）。
  - `CMakeLists.txt`：`add_library(e3_09 STATIC system_flag_actuator.cpp)` **PUBLIC 連上游
    `e6_01`**（標頭 include `command_bus.hpp`，須傳遞 include 目錄）；
    `test_e3_09`（`tests/e3/test_e3_09.cpp`）+ `add_test(NAME e3_09)`。
- 上游相依：E6-01 命令匯流排（`ds::command::CommandBus` / `CommandArgs` / `CommandResult` /
  `CommandValue`），可讀不可改——消費擴充點 3「動作」契約，不自造匯流排或值型別。
- **無** `#ifdef` / win32 / cocoa / `defaults` / NSUserDefaults 等真實系統設定 API
  （backend_guard 綠燈）。致動器邏輯（旗標鍵驗證、命令 id 組裝、分派、結果回報）與後端
  完全解耦、純邏輯、平台中立、可注入。

### 測試 `tests/e3/test_e3_09.cpp`（gtest，22 案例）
- 旗標鍵驗證 + 命令 id 組裝（2）：合法 / 非法鍵、四動詞命令 id 字串。
- 登記 / 註冊 / 反註冊（7）：每旗標四命令全掛、add_flag 拒非法 / 重複、無旗標 / 無後端不可
  註冊、重複註冊回滾、部分衝突整批回滾（不留半掛）、unregister 移除全部且再呼叫回 0。
- 分派 + null 後端一致（3）：on/off 經匯流排更新後端、status 唯讀、訊息帶狀態。
- 切換 + 冪等（2）：toggle 翻轉且自逆、on/off 冪等。
- 多旗標互不干擾（1）。
- 未註冊 / 非法旗標鍵報錯（3）：未登記命令 dispatch 回 NotFound、直接呼叫未登記旗標回 Failed
  且不改後端、無後端處理器回 Failed。
- 直接呼叫處理器（1）：語意等價。
- null 後端狀態一致（1）：注入初值 + 直接操作 + 內省。
- 內省有序（1）：flag_names 排序。
- 契約版本標記（1）。
