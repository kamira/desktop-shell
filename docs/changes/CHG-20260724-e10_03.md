## Motivation

HTTP 端點：讓外部可經 HTTP 與本應用互動的抽象——路由註冊（method + path → handler）、請求解析、
回應建構、以及把請求映射到既有的 E10-01 訊息通道 / E6-01 命令。若一開始就綁真實 socket / listen，
路由語意會被平台傳輸細節污染，且無法以單元測試驗證。

E10-03 於相位 1 採「可注入的請求輸入」——只實現純邏輯的路由匹配與分派：外部把一個 `HttpRequest`
值餵入 `HttpRouter::handle(request) -> HttpResponse`。**絕不開真實 socket、不 listen、不綁 port**，
也無任何 `#ifdef` / win32 / cocoa / libmicrohttpd 傳輸後端。等真實網路綁定（相位 2）到位時，只需在
socket 接受迴圈把位元組解析成 `HttpRequest`、再把 `HttpResponse` 序列化回位元組——路由語意不動。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::ipc::http`（巢狀於 E10-01 `ds::ipc`） | 與 E10-01 一致，且不與其 `contract_version` 等符號相撞 |
| 請求輸入 | 可注入的 `HttpRequest` 值 → `handle()` | 相位 1 平台中立；不開真實 socket，路由邏輯可全單元測試 |
| 方法 | 具名列舉 `HttpMethod` + 字串互轉 | 避免裸字串大小寫 / 拼寫歧義；相位 2 可從請求列解析 |
| 路徑樣式 | `/seg/:name`，`:name` 段擷取為路徑參數 | 常見 REST 路由；擷取值以 E6-01 `CommandArgs` 承載 |
| 請求 / 回應酬載 | 重用 E6-01 `CommandArgs`（query / params / headers） | 跨模組邊界不變形；可直接轉命令參數 / 封成訊息 |
| 請求解析 | `HttpRequest::parse(method, target, body)` 切 path?query | 純邏輯；百分號解碼留待相位 2 傳輸層 |
| 回應建構 | `HttpResponse` + 具名工廠（make_ok/not_found/...） | 狀態碼以具名常數集中，不散落裸數字 |
| 註冊語意 | `route(method, pattern, handler)`；重複 (method,pattern) 回 false 不覆蓋 | 與 E6-01 / E10-01 契約一致，不靜默遮蔽 |
| 404 | 無任何樣式路徑相符 → 404（明確） | 邊界明確、不靜默、不崩潰 |
| 405 | 路徑相符但方法不符 → 405 + `Allow` 標頭列允許方法 | 遵 HTTP 規範，回應明確 |
| 映射命令 | `to_command` / `dispatch_request` / `command_dispatcher` | 把請求轉 E6-01 具名命令並分派，重用命令匯流排 |
| 映射訊息 | `to_message` → E10-01 `Message`（可 send/publish） | 把請求封成本機 IPC 訊息，重用訊息通道 |
| 命令結果映射 | Ok→200 / NotFound→404 / Failed→400 | 分派結果轉 HTTP 回應，明確不靜默 |
| 契約版本 | `contract_version()` = "e10_03/1.0.0" | 承重抽象，供相位 2 換傳輸時相容判斷 |

介面平台中立：無 `#ifdef _WIN32` / `cocoa` / `__APPLE__` 等平台分支、不綁任何真實 socket / listen / port。
