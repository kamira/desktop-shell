## 四條的來歷與承重證據

**K-017 — `std::stod` 丟的 `out_of_range` 是 `logic_error`，而它丟的值常常在範圍內。**
兩個尖角。其一：`layout_store.hpp:131` 文件上承諾呼叫端接 `runtime_error`，
而 `out_of_range` 走 `logic_error` 分支，所以那道防線**沒接上**。
其二：`std::stod` 的丟出判據就是 `strtod` + `errno == ERANGE`，**包含次正規數**。

I1 自量（g++ 13.3，探針在 scratchpad，未入倉庫），十個案例兩欄逐例同步：

```
                          std::stod            strtod errno==ERANGE   strtod 的值
1e400                     丟 out_of_range      1                      inf
1e-400                    丟 out_of_range      1                      0
1e-320                    丟 out_of_range      1                      9.99989e-321   ← 真的用得的值
5e-324                    丟 out_of_range      1                      4.94066e-324
1.7976931348623157e308    成功                 0                      1.79769e+308
std::out_of_range         is_logic_error=1     is_runtime_error=0
```

`1e-320` 那一列是重點：`strtod` 成功轉出一個次正規數，`std::stod` 卻丟「超出範圍」。
這也是為什麼 `E7-17` 的改寫（`std::stod` → `strtod` + `errno`）是**行為等價**而非猜測：
判據同一個。`V1.14` 以語法產生器語料做差分實測，1784 列差異無一例外都是
「老版丟例外 → 新版回 `ParseError`」，零列是老版成功而新版失敗。

**K-018 — 突變「死在編譯器」不是承重證明，失效方向是假通過。**
`I1.1` 自查自報：兩條突變錨點各命中一次、套件也紅了，但紅因是
`-Werror=unused-function` / `-Werror=unused-parameter`，不是任何斷言失敗。
改寫成保持符號仍被使用的等價突變後重跑，確認是測試殺的；`V1.14` 獨立複核兩條改寫後
**編譯零警告**、確為測試殺死。`V1.14` 另示範更強的做法：設計一條只有待證那一支殺得死的突變。

**K-019 — 遞迴解析加上限，只擋解析不管解構是半套。**
`Value` 樹的解構也是遞迴的，所以上限檢查必須在建任何節點之前。
只有縮小 `ulimit -s` 才量得到：`V1.14` 夾擊出 80 / 96 KiB 通過、72 KiB SIGSEGV，
並以「同一二進位不呼叫 parse 時 72 / 64 KiB 都正常、空程式要到 16 KiB 才死」當對照組。
上限值的選法（兩端夾擊、不逼近崩潰門檻、加雙向界限測試擋「調成天文數字」的假修法）一併記下。

**K-020 — 靜態斷言常常只釘住字面，沒釘住行為。** 這條是 I1 自己的（`CHG-20261117-02` 的 M6）：
釘住「必須跟 `head.sha` 比、不能跟 `HEAD` 比」的是一支靜態測試，而把關鍵那一行的
`$HEAD_SHA` 換成 `HEAD` 之後，腳本別處仍有同一個字串，斷言照樣通過，突變**存活**。
補一支真的重現 merge ref 的行為測試才殺掉。
