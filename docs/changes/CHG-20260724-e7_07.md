# CHG-20260724-e7_07 — 熱重載（E7-07）

- Date: 2026-07-24 | Branch: feat/e7_07 | Risk: low | Implemented by: I1.38

- Unit: E7-07（熱重載，engine 層 / 描述子系統 / low；相依已合併的 E7-01、E7-06）
- NFR: NFR-04「描述格式錯誤須定位到行、不得靜默」

## Motivation

宣告式格式文件在執行期會被外部修改（相位 2：真實檔案；相位 1：注入式來源）。系統需要能
**偵測來源內容變更、重新解析、以差異方式套用新設定**，而不是每次重啟。關鍵風險是：新內容
可能解析失敗——此時**絕不能以壞輸入覆蓋當前有效狀態**，而要保留上一個有效值並把錯誤清楚呈現。

**熱重載**單元把「載入→解析→成功替換 / 失敗保舊值」的生命週期封裝為一個狀態機：
- 消費 E7-01 的 `parse()` / `Document` / `ParseError`（解析與資料模型），不重造輪子；
- 失敗時用 E7-06 的 `Diagnostic` / `format_report` 把錯誤**定位到行**呈現（NFR-04：不靜默）；
- 支援成功 / 失敗回呼，讓下游可觀測重載事件。

**相位 1 平台中立**：不接任何真實檔案系統監看（無 inotify / FSEvents / `#ifdef` / `win32` /
`cocoa`）。來源以**可注入的抽象** `ReloadSource` 表示（`content()` + 單調遞增的 `revision()`
變更令牌）。真實檔案監看留待相位 2——屆時只需實作一個綁平台 API 的 `ReloadSource` 具體類別，
本狀態機一行不動。屬 engine 層（平台中立純邏輯）：可完全單元測試。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 來源抽象 | `ReloadSource`：`content()` + `revision()`（純虛） | 注入式、平台中立；`revision` 即相位 1 的「變更通知」，相位 2 由真實監看遞增 |
| 相位 1 具體來源 | `MemorySource`（純記憶體，無檔案系統） | 供狀態機驅動與測試；`set_content()` 僅在內容**確實不同**時遞增 revision（相同寫入非變更） |
| 變更偵測 | 比對 `revision()` 與上次載入所依據的令牌；`seen_` 哨兵區分「從未載入」 | 未變則 no-op（不重解析、不觸發回呼）；首次一律載入 |
| 狀態機結果 | `ReloadStatus{Unchanged, Loaded, Failed}` + `ReloadResult{status, has_document, diagnostics, report}` | 三態涵蓋 no-op / 成功 / 失敗；`has_document` 反映失敗保舊值後是否仍有效 |
| 成功路徑 | 以新 `Document` 替換當前值、清空舊診斷、觸發 `on_reload` | 差異式套用新設定；當前值恆為最新的有效解析結果 |
| 失敗路徑 | **保留** `document_` / `loaded_`（不覆寫）；以 E7-06 `from_parse_error` + `format_report` 產生診斷、觸發 `on_error` | 失敗保舊值（核心承諾）；錯誤定位到行、不靜默（NFR-04） |
| 失敗不重試 | `apply_load` 在失敗時仍更新 `last_revision_` | 持續壞掉的來源不會每次 poll 都重試 spam；內容再變（revision 再增）才重試 |
| 強制重載 | `reload()` 忽略 revision 比較、直接重解析並同步令牌 | 供呼叫端明確要求重讀（如手動觸發） |
| 回呼 | `on_reload(Document)` / `on_error(vector<Diagnostic>, report)`；各保留最新一個 | 可觀測；成功 / 失敗事件分流，僅於對應事件觸發 |
| 失敗可查 | `last_diagnostics()` / `last_report()`（成功後清空） | 事後仍能取用最近一次失敗的定位資訊 |
| 存取保護 | `document()` / `root()` 在無有效值時 throw `std::runtime_error` | 明確失敗而非回可疑預設值（NFR-04 精神）；先以 `has_document()` 查詢 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端 / 檔案監看 API，符合相位 1
（Mac/null）約束。engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。
不含能力閘控呼叫（純邏輯生命週期），無 `has()` 降級路徑需求。
