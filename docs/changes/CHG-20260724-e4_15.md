# CHG-20260724-e4_15 — 就地輸入框（E4-15）

- Date: 2026-07-24 | Branch: feat/e4_15 | Risk: low | Implemented by: I1.119
- Skill: ai-sdlc-autopilot
- Unit: E4-15（就地輸入框，module 層 / 子系統 elements / phase 1 / low，depends_on=[E4-01, E5-13]）

## Motivation

桌面外殼的角色互動（改名、輸入指令、篩選欄等）需要一個「就地(inline)文字輸入框」元件：
可編輯文字欄位，具游標位置、插入/刪除字元、選取，並能以既有排版與事件基礎設施運作。
相位 1 不做真實鍵盤 / IME（跨平台真實鍵盤輸入延後至相位 2 後端），但編輯狀態機、排版顯示、
事件轉譯三者的介面與語意本相位就應底定——真實後端上線後只需把系統鍵盤事件轉為 E5-13
的 `KeyEvent` / `TextInputEvent` 並注入既有路徑，呼叫端（本單元）邏輯一行不動。

E4-15 提供 `TextInputElement`：以 codepoint 序列維護可編輯文字、游標與選取狀態；
以上游 E4-01 `TextLayout` 排版目前內容供顯示；以（可選）附掛上游 E5-13
`KeyboardInputSource` 接收**注入式**按鍵 / 文字提交事件驅動編輯操作；`render_model()`
產出「文字排版 + 游標 + 選取矩形」的完整渲染描述，全部相對佈局（NFR-02）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 內部文字表示 | `std::vector<CodePoint>`（非 UTF-8 byte 索引） | 游標/選取以「字元」為單位而非位元組，編輯（插入/刪除/切片）直接對 codepoint 向量操作，無需位元組偏移換算；`text()` 於取出時才編碼回 UTF-8 |
| UTF-8 編解碼 | 解碼重用上游 E4-01 `decode_utf8`（含合法性驗證）；編碼為本單元新增的 `encode_utf8`（標準演算法，只需編碼已驗證過的合法碼位） | 不重複實作解碼驗證邏輯；insert/set_text 天然繼承 decode_utf8 的「非法 UTF-8 不靜默」保證 |
| 游標語意 | codepoint 索引 `[0, length()]`；`set_cursor`/`select` 越界（> length()）→ `std::out_of_range` | 對應規格「無效操作(越界游標)不靜默」；方向式 `move_cursor` 在邊界安全 no-op（屬正常編輯語意，非法索引才是「不靜默」對象，兩者於標頭明確區分） |
| 選取模型 | 錨點(anchor) + 游標(cursor)，`has_selection()` = anchor!=cursor；`select(begin,end)` 允許 begin>end（反向選取） | 對應標準編輯器 shift+方向鍵語意；`selection()` 另提供正規化 (begin<=end) 讀值 |
| 排版整合 | 內部持有一個 E4-01 `TextLayout`（綁定注入的 `FontMetrics`）；預設約束 `WrapMode::None`（單行語意，換行僅由顯式 `'\n'` 產生） | 就地輸入框直覺上單行；呼叫端可 `set_constraints()` 覆寫（含開啟自動換行，見下方「已知簡化」） |
| 游標/選取的視覺座標映射 | 以「codepoint 索引之前有幾個字符會產生 glyph（跳過 CR/LF）」映射為 E4-01 `LayoutResult` 的全域 glyph 索引，再定位所屬行與行內 x 偏移；換行邊界（游標恰接在 `'\n'` 之後）消歧義為「新行開頭」而非「前行末端」 | `WrapMode::None` 下精確（無自動折行造成的行尾空白丟棄）；見下方「已知簡化」 |
| 事件整合 | `attach(KeyboardInputSource&)` 訂閱 E5-13 按鍵 + 文字提交頻道；`handle_key`/`handle_text_input` 亦可直接呼叫（測試 / 手動驅動） | 相位 1 無真實鍵盤，一律注入式；方向鍵/Home/End/Backspace/Delete 轉譯為編輯操作，Shift 修飾鍵延伸選取，其餘鍵忽略（字元輸入經 `TextInputEvent` 到達） |
| 渲染描述 | `TextInputRenderModel`{ `LayoutResult layout`, `CursorRenderInfo cursor`, `bool has_selection`, `SelectionRange selection`, `vector<SelectionRect> selection_rects` } | 全相對偏移（NFR-02）：沿用 E4-01 的行內 x / 行頂 y / 基線語意；選取矩形逐行給出、height 取行高 |

### 已知簡化（相位 1 / low risk 範圍內）

游標與選取的視覺座標映射對本元件**預設約束**（`WrapMode::None`）精確。若呼叫端改用會
實際觸發自動換行的約束（`WrapMode::Word` 且 `max_width` 為正有限值），因 E4-01 排版層
可能於折行處丟棄行尾空白字符（不產生對應字符），字元索引→字符索引映射為近似（夾限至
可用字符範圍）。這不影響文字內容本身的正確性（`text()`/`insert`/`backspace` 等皆對
codepoint 向量精確操作），僅可能使極端自動換行情境下的游標視覺位置略有偏差。此簡化
已於標頭明確記載；完整精確映射留待後續相位視需要處理。

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支，不含任何真實鍵盤 / IME
API，不含螢幕絕對座標或數字 z-order。
