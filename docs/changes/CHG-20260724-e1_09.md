# CHG-20260724-e1_09 — 邊緣吸附（E1-09）

## Motivation

桌面外殼要讓使用者拖曳（承 E1-08）surface 時**自動吸附對齊**：當被拖曳者的邊緣靠近**螢幕（容器）
邊緣**或**其他 surface 的邊緣**到一定程度，自動貼齊那條邊——讓面板貼邊、桌寵靠角、兩個 surface
並排時邊靠邊。這牽涉三件事：(1) 「多近算靠近」如何以解析度無關的方式表達（閾值）；(2) 吸附是純幾何
計算，但結果位置要以何種形式承載；(3) 如何與既有拖曳狀態機（E1-08）整合。

相位 1（Mac / null 期）為平台中立：**沒有真實視窗 / OS 幾何 API**，吸附為**注入式**純幾何邏輯。
若閾值以絕對像素、吸附結果以 `(x, y)` 絕對座標表達，會違反 **NFR-02**（核心 API 不得絕對座標 /
數字 z-order）且無法適應不同容器尺寸。E1-09 因此：閾值以**容器尺寸的正規化分數**表達（逐軸換算為
判定距離）；吸附後位置一律以 **E1-07 anchor 定位模型**（九宮具名錨點 + 正規化偏移）再表達。本單元
不自造定位模型，純粹**組合**兩個上游：E1-07（宣告式位置 + 落地 `resolve`）、E1-08（拖曳實時位置）。

### 吸附後再表達為 AnchorSpec（round-trip 不變式）

以容器 `W×H`、元件 `w×h`、吸附後矩形左上角 `(rx, ry)`：

```
fx = (水平吸螢幕末端) ? 1 : 0            fy = (垂直吸螢幕末端) ? 1 : 0
dx = (rx - fx·(W - w)) / W               dy = (ry - fy·(H - h)) / H
anchor = 九宮(fx, fy)                    offset = {dx, dy}
```

代回 E1-07 `resolve`：`x = fx·(W-w) + dx·W = rx`（同理 y），故吸附後 `AnchorSpec` 落地必回同一矩形。
吸螢幕左 / 上 → `rx/ry = 0` 且 `fx/fy = 0` → 偏移 0（貼起始邊）；吸螢幕右 / 下 → 末端錨 + 偏移 0
（貼末端邊、隨容器縮放恆貼齊）；吸 surface 邊 / 未吸附 → 起始錨 + 正規化偏移精確承載。

## Impact

### 影響分析（medium 風險）

- **回溯相容**：純新增單元。未改任何既有 `src` / `engine` / `modules` / 上游單元（E1-07 / E1-08 及其
  傳遞相依 E1-03 / E1-24 / E1-21 / E7-12 / E7-01）/ `units.json` / 根 CMakeLists / 共用 `directory.md`；
  對既有單元零影響。
- **上游耦合（medium 的來源）**：本單元唯讀依賴兩個上游（E1-07 定位、E1-08 拖曳），並在便利層
  `snap_surface` 觸及 E1-08 服務的公開查詢介面，耦合面比純自足 low 單元廣，故評 medium。緩解：
  - 全為**組合 / 型別複用**——不觸碰上游任何符號實作、不加虛擬方法、不改上游標頭。
  - 對 E1-07 僅用 `AnchorSpec` / `Offset` / `Size` / `ResolvedPlacement` / `resolve` / `is_valid_anchor`
    / `is_finite_size` / `Spacing` / `spacing_fraction`；對 E1-08 僅用 `DraggableSurface::live_position`
    與型別 `SurfaceId`（`snap_surface` 便利層，唯讀，不改拖曳狀態）。任一上游若改介面，衝擊面侷限於本
    單元 `.cpp` 的少數呼叫點。
  - 純幾何核心 `snap_rect` / `snap` **不**依賴 E1-08，可獨立於拖曳單獨使用（E1-08 僅在便利層登場）。
- **狀態一致性**：本單元**無自有可變狀態**（`EdgeSnapping` 僅持一組值型 `SnapConfig`）。`snap_surface`
  只**讀** `DraggableSurface` 的實時位置、回傳新 `AnchorSpec`，由呼叫端自行決定是否回寫 `drag_to`——
  吸附與拖曳狀態機解耦，不引入隱藏耦合。無共享可變全域、無執行緒（相位 1 單執行緒記憶體模型）。
- **NFR-02（核心 API 不得絕對座標 / 數字 z-order）**：閾值為容器正規化分數（相對）；吸附後位置全為
  E1-07 `AnchorSpec`（具名錨點 + 正規化偏移）；邊以具名 `Edge` / `AxisSnap` 表達。具體像素只在
  `snap_rect` 的 `ResolvedPlacement` 輸入 / 輸出（resolve 邊界，呼叫端提供尺寸）出現，與 E1-07 同理。
- **幾何取捨（明確記錄非靜默）**：逐軸吸附以「最小 \|delta\|」為準——同一目標的左-左與右-右等多個候選中
  取最近者，故「靠近某邊」的直覺結果取決於哪條邊實際最近（見測試 `SnapsToSurfaceEdge`）。宣告式 `snap`
  要求容器邊長 > 0（用以把具體矩形換算回正規化偏移，除數非零）；容器 ≤0 → Invalid。
- **建置面**：新增靜態庫 `e1_09`（PUBLIC 連 `e1_07` / `e1_08`）與可執行檔 `test_e1_09` + CTest `e1_09`。
  根 CMakeLists 既有層級 GLOB（`src/*/*/CMakeLists.txt`，深度 2）已涵蓋 `src/kernel/e1_09/CMakeLists.txt`，
  **無需**改根建置檔。
- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 視窗 / 繪圖 API，
  `backend_guard`（G1b）不觸發；吸附為純幾何 + 純資料，無平台分支。

### 測試（gtest，18 案例）

純幾何核心：吸附螢幕四邊（左 / 右 / 上 / 下）；閾值邊界（等於閾值吸、超過不吸）；遠離不吸附（位置
原樣）；吸 surface 邊（最近的左-左對齊、左貼右相鄰）；多目標選最近邊；`to_screen` / `to_surfaces`
開關；無效輸入（非有限容器 / 負 / 非有限閾值 / 非有限 dragged / 無效目標）→ Invalid。宣告式：吸螢幕
角 → 具名 `BottomRight` + 零偏移且 round-trip 貼右下；吸右邊以具名錨承載、換更大容器仍貼右緣（NFR-02
縮放）；遠離位置 round-trip 不變；吸 surface target spec；無效輸入（越界 anchor / 非有限 offset /
非正容器 / 無效目標）→ Invalid。設定：`from_spacing` 閾值大小影響吸 / 不吸；`EdgeSnapping` 服務用其
設定。具名邊：`screen_edge_of` 四邊 + None/Surface 回 false 不觸碰 out。E1-08 整合：拖曳中吸實時位置
→ 回寫 `drag_to` → `end_drag` 記住吸附後（貼左緣）；對另一 surface 實時左緣吸附（含自己 → 略過）；
未註冊（無實時位置）→ Invalid。
