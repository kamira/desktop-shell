# CHG-20260724-e1_06 — 命中與繪製層序（E1-06）

- Date: 2026-07-24 | Branch: feat/e1_06 | Risk: low | Implemented by: I1.131
- Skill: ai-sdlc-autopilot
- Unit: E1-06（命中與繪製層序，platform 層 / phase=1 / risk=low / depends_on=[E1-04] / load_bearing=0）

## Motivation

桌面外殼的輸入路由要求「所見即所觸」：畫面上蓋在最上面的東西，點擊必須命中到它，不能穿透
命中到被它蓋住的下層元件。E1-04 已提供純幾何 + alpha 命中測試，也提供依**具名圖層 rank +
宣告順序**決定的 `topmost_hit`；但呼叫端真正掌握的往往是**繪製順序**本身（先畫什麼、後畫
什麼），而不是想額外再維護一套具名圖層排序。E1-06 於相位 1（Mac / null 期）交付一個薄封裝
`PaintHitOrder`：把**繪製順序**直接當作命中優先的依據——依繪製反序（最後繪製 / 視覺最上層
先）逐一以 E1-04 的 `hit_test_alpha` 判定，第一個命中者即結果。保證「命中層序」與「繪製層序」
恆一致，不需呼叫端自行同步兩套順序。不重新實作任何幾何 / alpha 邏輯，純序列邏輯。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 建構位置 | 新無狀態薄封裝 `PaintHitOrder`（`src/kernel/e1_06/`），持有一份繪製順序 + 一個 `HitTester` | 命中判定完全交給上游 E1-04；本單元只負責「用什麼順序去問」，職責單一 |
| 繪製順序表達 | `std::vector<HitSurface>`，陣列順序即繪製順序（索引 0 最先繪製 / 最底層，末端最後繪製 / 最上層） | NFR-02：不引入數字 z-order；用陣列宣告順序表達順序關係，與 E1-01/E1-04 一貫的「具名 + 宣告順序」風格一致 |
| API | `set_paint_order(surfaces)`（覆蓋既有繪製順序）+ `hit_topmost(point)`（依繪製反序判定） | 與需求列出的 API 形狀一致；`set_paint_order` 可重複呼叫即時反映新順序（見「順序變更」測試） |
| 命中判定 | 直接複用 E1-04 `HitTester::hit_test_alpha`（幾何 + alpha + `HitPolicy::Transparent` 穿透），逐一走訪，反序中第一個命中者勝出 | 不重新實作任何幾何 / alpha 邏輯；繼承 E1-04 既有的穩健性（邊界含、透明穿透、無效報錯） |
| 走訪與錯誤處理 | 反序走訪全部 surface（不因已找到命中而提前跳出）；任一 surface 無效即整體回 `Invalid` | 與 E1-04 `topmost_hit` 語意一致：無效輸入必須被偵測到，不會因為排序不同而漏檢 |
| 與具名圖層的關係 | `HitSurface.layer`（`SurfaceLayer`）維持存在（供 alpha / 命中判定需要時使用），但**不**被本單元用來重新排序——排序依據只有繪製順序本身 | 避免「兩套排序互相打架」；當呼叫端把繪製順序組成得與「具名圖層 + 宣告順序」一致時，`hit_topmost` 與 E1-04 `topmost_hit` 結果自然一致（測試 `ConsistencyWithE1_04` 已鎖定） |
| 結果型別 | 複用 E1-04 `TopmostHit`（`HitStatus` / `hit` / `id`），不新增結果型別 | 呼叫端（若同時用到 E1-04 與 E1-06）無需適配兩套結果型別 |

## Impact

### 影響分析（low 風險，load_bearing=0）

- **薄封裝、無新增狀態語意**：`PaintHitOrder` 不引入任何新的幾何 / alpha / 能力閘控邏輯，
  完全委派給已測試、已合併的 E1-04。改動面小、可覆核性高，符合 low 風險評級。
- **不影響既有單元**：本單元只讀 E1-04 標頭（`hit_test.hpp`），不修改任何上游檔案；`write_scope`
  僅 `src/kernel/e1_06/**`、`tests/e1/test_e1_06.cpp` 與本文件系列，未觸碰 root CMakeLists /
  units.json / 任何上游程式碼。
- **下游可選擇的兩套命中優先語意**：往後需要「命中依繪製順序」的呼叫端（例如已自行維護
  繪製佇列的合成器 / 視窗管理邏輯）可直接用 `PaintHitOrder`；需要「命中依具名圖層語意」的
  呼叫端可繼續用 E1-04 `topmost_hit`。兩者共用同一份 `HitSurface` / `TopmostHit` 型別，互不
  排斥、可視情境擇一或並用（測試 `ConsistencyWithE1_04` 已證明兩者在「繪製順序 = 具名圖層
  語意序」情境下結果一致，不會互相矛盾）。
- **NFR-02 合規**：繪製順序完全以陣列宣告順序表達，未引入任何數字 index / z-order 對外 API；
  `SurfaceLayer` 欄位保留但不作為本單元排序依據，避免日後有人誤用數字化的圖層 rank。
