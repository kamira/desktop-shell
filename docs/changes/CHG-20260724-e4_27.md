# CHG-20260724-e4_27 — 綁定式合成（著替）（E4-27）

- Date: 2026-07-24 | Branch: feat/e4_27 | Risk: low | Implemented by: I1.164
- Skill: ai-sdlc-autopilot v1.1
- Unit: E4-27（綁定式合成（著替），module 層 / elements / phase 1 / low，depends_on=[E4-08]）

## Motivation

「著替」（dress-up 換裝）情境需要把多個可切換部件（底圖 / 服裝 / 配件…）依固定的**具名
疊放關係**合成成一張視覺，且每個部件位置（槽）要能在執行期換綁不同的候選內容（換一套
衣服、換一款配件），而不需重寫合成邏輯。若呼叫端每次換裝都自行操作 E4-08
`LayerCompositor` 的 `add_layer`/`remove_layer`，就得自己追蹤「這個位置目前是哪個
surface」，容易在切換時忘記先移除舊層，或在多個呼叫點各自重複這套簿記邏輯。

E4-27 在 E4-08 之上加一層**具名槽位綁定**：先用 `define_slot` 宣告一個槽（如
`"outfit"`）與其候選部件集（如 `"red"`/`"blue"` 兩套服裝，各自對應一個具名 surface），
再用 `bind`/`rebind` 決定該槽目前顯示哪個候選；`compose()` 依**槽定義順序**把目前已綁定
槽位的部件交給一個暫用的 E4-08 `LayerCompositor` 產出合成計畫。本單元**不做真實像素
合成**，也**不**重造 E4-08 已有的合成 / 定址存在性判斷。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 槽與部件識別 | `SlotId`/`PartId`（皆為 `std::string`），槽內部件以 `part_id` 唯一 | 具名，非數字 handle / index，滿足 NFR-02；「槽」與「部件」是兩層獨立命名空間（不同槽可以有同名 part_id，如兩槽都有一個叫 `"none"` 的候選） |
| 上游相依 | `target_link_libraries(e4_27 PUBLIC e4_08)` | 依規格指定；`e4_08` 提供 `LayerCompositor`（進而經其 include 鏈提供 `SurfaceSwitcher`/`BlendMode`/`CompositeStatus`/`CompositionPlan`/`SurfaceId`），本單元不重造合成邏輯 |
| `compose()` 的合成器生命週期 | 每次 `compose()` 內建立一個**暫用、呼叫結束即銷毀**的 `LayerCompositor`，逐一 `add_layer` 目前已綁定槽的部件，回傳其 `compose()` 結果 | 讓 `compose()` 成為目前綁定狀態的**純函式、單次求值**：`rebind` 後直接重新呼叫 `compose()` 就會反映新綁定，不需要額外「先移除舊層」的簿記，也不會被「重複加入同一 surface 回 Invalid」這種 E4-08 既有防呆卡住 |
| 疊放順序 | **槽定義順序**（`define_slot` 呼叫先後），與 `bind`/`rebind` 呼叫順序無關 | 具名順序，非數字 z-order；换裝時只換「內容」不換「位置語意」——先定義 `"base"` 再定義 `"outfit"`，疊放關係永遠是 base 在下、outfit 在上，即使先 rebind outfit 再 rebind base 也不影響疊序 |
| `bind` 與 `rebind` 的分工 | `bind`：槽必須已定義，part 必須在候選集內；首次綁定與改綁共用同一入口。`rebind`：額外要求槽**已有既存綁定**，否則 `NotFound`（沒有舊值可換） | 對映「著替」的兩種情境：`bind` 是把角色第一次穿上某槽的裝備；`rebind` 是明確表達「正在換裝」的呼叫端意圖，對從未穿過的槽呼叫 `rebind` 是呼叫端邏輯錯誤，值得單獨的錯誤碼而非靜默等同 `bind` |
| 未綁定槽在 `compose()` 中的行為 | 明確**跳過**，不貢獻任何層；不視為錯誤 | 「這個位置暫時沒有裝備」是合法狀態（如角色還沒戴配件），比照 E4-08 `compose()` 空合成器回空計畫的精神 |
| surface 定址存在性檢查的時機 | 完全交給 `compose()` 內部呼叫的 `LayerCompositor::add_layer`（進而是 E4-06 `SurfaceSwitcher::has()`），`define_slot`/`bind`/`rebind` 皆不重複檢查 | 單一事實來源：定址存在性只在 E4-08 這一層判斷一次；也讓「先定義槽 / 先綁定，稍後才註冊 surface」這種常見初始化順序合法（`compose()` 在 surface 尚未註冊前回 `NotFound`，註冊後即成功，無需重新 `bind`） |
| 部件驗證的分層 | `define_slot`/`bind`/`rebind` 只驗證本單元自己的命名空間（槽名 / part_id / surface_id 非空、part_id 同槽內唯一、part_id 屬於候選集）；混合模式合法性 / 透明度有限性 / surface 定址存在性一律留給 `compose()` 時的 E4-08 判斷 | 單一職責：本單元管「具名綁定關係」，E4-08 管「合成計畫本身的合法性」，不重複造輪子 |
| `compose()` 失敗時的回傳 | 任一已綁定槽 `add_layer` 未回 `Ok`，立即回傳該 `CompositeStatus`，`plan` 維持預設空值 | 與 E4-08 `add_layer`「不部分套用」同精神：不回傳一份「部分著裝」的合成計畫，避免呼叫端誤以為那就是完整結果 |

介面平台中立：純記憶體邏輯 + 描述產出（透過 E4-08），無 `#ifdef _WIN32` 等平台分支、不含
任何真實繪圖 / OS API、不做真實像素合成。

## 不含（避免越界）

- 不做真實像素合成 / 繪圖，不觸碰任何 OS 或繪圖 API（那是後續相位繪製層的職責，一如
  E4-08 本身）。
- 不重造 E4-08 的合成計畫產出邏輯，也不重造 E4-06 的 surface 定址存在性判斷——`compose()`
  內部直接建立並使用 E4-08 `LayerCompositor`。
- 不提供「移除槽 / 重新定義槽」API（本相位刻意精簡，避免超出規格列出的
  `define_slot`/`bind`/`rebind`/`compose` API 面）。
- 未動根 `CMakeLists.txt`、`units.json`、`directory.md` 或任何鎖定範圍以外的檔案。
