## Motivation

C2-10「網頁」：嵌入顯示一個網頁的桌面 widget——可設定 URL、觀察載入狀態、以**注入式後端**
取得內容（相位 1 無真實瀏覽器引擎）。這是一個**組裝型 artifact 單元**（非新引擎邏輯，
lb=0，不被其他單元依賴），把兩個已合併的擴充點組成單一 widget + 行為（`configure` /
`load` / `reload` / `loading_state` / `render_model`）。相位 1：純資料 / 邏輯組裝，無真實
GUI、無真實瀏覽器引擎。

組裝的兩個擴充點：
- **C1-01**（`ds::profiles::SkinProfile`）：widget 的桌面殼層基底（圖層 / 定位 / 拖曳），
  透過 `shell()` 暴露，由呼叫端直接驅動。
- **E10-05**（`ds::ipc::WidgetHost`）：本單元的「網頁 / webview 抽象」後端——相位 1 刻意
  不含真實瀏覽器引擎，而是把「網頁內容的載入」表達為一個（模擬的）獨立行程 + 其可選的、
  能力閘控過的畫面 surface 橋接（`AlphaSurfaceService`，NFR-03）。**自查記錄**：讀其標頭
  確認 E10-05 的實際語意是「獨立行程 widget 宿主」（`ProcessLauncher::spawn/terminate/
  is_alive` + `WidgetHost::start/stop/restart` + `poll_crash`），而非文獻描述的「網頁檢視 /
  嵌入元件」——它提供的是可注入的**行程生命週期 + 能力閘控過的畫面 surface 橋接**兩項能力，
  本單元據此把「網頁內容載入」映射為「啟動一個代表內容擷取的隔離行程，並視能力可用性決定
  是否橋接畫面 surface」，內容本身則一律由呼叫端注入（`load(injected_content)`），完全不
  假設 E10-05 具備任何網路 / DOM / 排版能力。

## Impact

### 新增 `content/widgets/c2_10/`
- `web_widget.hpp` / `.cpp`：`namespace ds::widgets`。
  - `WebWidget`：注入式相依 `ds::kernel::KernelBackend&` + `ds::kernel::LayerStack&`（透傳給
    內部自持的 C1-01 `SkinProfile` 殼層）+ `ds::ipc::ProcessLauncher&` + `ds::ipc::
    MessageChannel&`（透傳給內部自持的 E10-05 `WidgetHost`）+ 選填 `ds::kernel::
    AlphaSurfaceService*`（透傳給 `WidgetHost`；`nullptr` 時一律走無後端降級路徑）。
  - `configure(config)`：消費 E7-01 宣告式 `Value`（Map，`url` 鍵字串）。非 Map / 缺 `url` /
    非字串 / 空字串 / 缺 `"://"` scheme 分隔符 / scheme 後無內容 → `Invalid`，不改動既有
    狀態。若目前行程仍在跑，換 URL 前一律先停止（不留與新 URL 不符的殘留行程）。成功 →
    `Ok`，清空既有內容、狀態轉 `Configured`。
  - `load(injected_content)`：以呼叫端提供的內容模擬一次網頁載入。首次 load（或前次已停止）
    經 `WidgetHost::start()` 啟動（模擬的）獨立行程；是否嘗試橋接畫面 surface 一律先經
    `surface_capable()`（`surface_service_ != nullptr && surface_service_->supported()`，
    NFR-03：呼叫前 `has()`/`supported()` 閘控，從不盲目呼叫再處理失敗）。空注入內容 →
    `Invalid`，狀態轉 `Failed`。未先 `configure()` → `NotConfigured`。成功依橋接結果分為
    `Loaded`（完整，含畫面 surface，回 `Ok`）或 `Degraded`（僅內容、無 surface，回
    `Unsupported`——能力不可用或未注入能力後端時的降級路徑，皆不崩潰）。行程已存活時再次
    `load()` 直接更新內容，不重啟行程。
  - `reload()`：以上次 `configure()` 的 URL 經 `WidgetHost::restart()` 重新啟動內容行程
    （沿用原本的橋接設定），成功後內容清空、狀態回到 `Configured`，等待呼叫端再次 `load()`
    注入新內容（相位 1 無真實網路擷取，故 reload 與 load 明確分開）。從未成功 load 過 →
    `NotConfigured`。
  - `loading_state()`：具名載入狀態 `LoadingState`（Idle / Configured / Loading / Loaded /
    Degraded / Failed，NFR-02）。
  - `render_model()`：純文字模型——狀態前綴 + URL（已載入 / 降級時附內容）。
  - 查詢：`shell()` / `host()` / `id()` / `url()` / `content()` / `surface_bridged()` /
    `surface_capable()`。
  - 解構：若內容行程仍在跑，強制 `WidgetHost::stop()`，不遺留孤兒行程 / 殘留橋接 surface。
  - 具名結果 `WebWidgetStatus`（Ok / Invalid / Unsupported / NotConfigured / HostError），附
    `to_string()`（NFR-02）。
- `CMakeLists.txt`：`add_library(c2_10 STATIC)` + `target_link_libraries(c2_10 PUBLIC c1_01
  e10_05)` + `test_c2_10`（`tests/c2/test_c2_10.cpp`）+ `add_test(NAME c2_10)`。

覆蓋（`LoadingState` / `WebWidgetStatus`）、解構安全（widget 銷毀後行程確實不再存活、
橋接 surface 確實已移除）。

### 相位 1 約束遵循
- 純資料 / 邏輯組裝，無真實 GUI、無真實瀏覽器引擎（不嵌入 WebView / CEF、不發真實網路
  請求，`load()` 內容完全由呼叫端注入）；無平台分支（無 `#ifdef` / win32 / cocoa，僅在
  說明註解引述禁用詞，與 C1-01 / C2-09 等既有單元慣例一致）。
- 核心 API 無絕對座標、無數字 z-order（NFR-02）：位置 / 圖層全數透傳 C1-01 `SkinProfile`
  自身的具名表達；本單元自身新增的 API 面（`LoadingState` / `WebWidgetStatus`）亦全具名。
- 能力閘控呼叫皆有 `has()`/`supported()` 保護（NFR-03）：`surface_capable()` 是所有嘗試
  橋接動作（`load()` / 間接的 `reload()`）唯一的前置閘門，從不盲目呼叫 `WidgetHost::start()`
  帶上 `surface_id` 再處理失敗；能力不可用（含完全未注入能力後端）皆走明確降級路徑，內容
  仍正常透過注入式後端載入，不影響 widget 核心可用性。
- 無效操作一律明確回具名結果，不靜默；`configure()` 失敗全有或全無（不改動既有狀態）。
