# CHG-20260803-16 — W1-06 自繪選單無障礙支援（補回 W1-05 的功能退步）

- Date: 2026-08-03 (UTC+0) | Branch: claude/feat-menu-accessibility | Risk: low | Implemented by: I1
- Unit: **W1-06**（platform / host）
- Skill: ai-sdlc-autopilot v1.1
- 前置：`CHG-20260803-15`（W1-05 自繪選單）

## Motivation

`CHG-20260803-15` 把托盤選單從原生 `HMENU` 換成自繪，並明載了一個**真實的功能退步**：
原生選單免費提供螢幕閱讀器支援，自繪之後沒了。本 CHG 補回來。

選擇先做這一項，是因為使用者指定「先做有防毒情況的項目」——
本單元**完全不需要啟動 GUI 應用**即可驗證（見下）。

## Impact

`host/menu/menu_accessible.*`：手寫 `IAccessible`，把 E11-02 的選單模型翻成 MSAA 物件樹。

| 概念 | MSAA |
|---|---|
| 選單視窗 | `ROLE_SYSTEM_MENUPOPUP` |
| 選單項 | `ROLE_SYSTEM_MENUITEM` |
| 分隔線 | `ROLE_SYSTEM_SEPARATOR` + `STATE_SYSTEM_UNAVAILABLE`（讓閱讀器跳過） |
| 勾選 / 停用 / 游標 | `STATE_SYSTEM_CHECKED` / `_UNAVAILABLE` / `_FOCUSED` |

`OwnerDrawnMenu` 回應 `WM_GETOBJECT`（`OBJID_CLIENT`）交出物件，
並在每次巡覽（`hover` / `move_next` / `move_prev`）後發 **`EVENT_OBJECT_FOCUS`**。

**不發焦點事件的話等於沒有朗讀**：螢幕閱讀器只會在使用者主動查詢時才知道游標在哪，
鍵盤使用者完全不知道自己選到第幾項。

### 為什麼是 MSAA 而不是 UI Automation

`IAccessible` 是單一介面、可手寫，且 UIA 會透過內建的 MSAA-to-UIA 橋接自動看得到它。
以本單元的規模，直接實作 UIA 供應器（多介面 + 多模式）不會換到更好的結果。

## ⚠ 施工中發現：`host_main` 漏了 `OleInitialize` 會讓無障礙安靜失效

MSAA 的 `LresultFromObject` 要求**行程已初始化 OLE**。

危險之處在於：**單元測試會綠**（測試行程自己初始化了 COM），但真實 app 裡
螢幕閱讀器什麼都讀不到。測試環境與生產環境的差異就藏在這種地方。

已在 `wWinMain` 補上 `OleInitialize` / `OleUninitialize`，並於程式碼註解寫明理由。

### 驗收走的是螢幕閱讀器的同一條路

測試以 **`AccessibleObjectFromWindow`** 取得介面——那會真的送出 `WM_GETOBJECT`，
與螢幕閱讀器完全相同，**不是**繞過去戳內部狀態。

這一點是刻意的：若只測 `MenuAccessible` 這個類別本身，就驗不到
「視窗有沒有真的接上 `WM_GETOBJECT`」——而那正是無障礙最容易安靜失效的地方。
`WindowRespondsToGetObject` 這條測試就是專門守它的。

涵蓋：角色與子項數、標籤即朗讀名稱、**分隔線無名稱**（否則會唸出無意義內容）、
勾選狀態外露（否則使用者不知道開關狀態）、越界 childId 結構化拒絕、
**尚未巡覽時不得回報焦點**（否則會宣告一個使用者沒選的項目）、
可致動項才有預設動作、空選單、螢幕座標由面板原點累加。

### 過程紀錄：兩個錯誤

1. **初版 9 個測試全紅**，因為測試行程沒初始化 COM。加上 `OleInitialize` 後
   8 個立刻轉綠——同時暴露了 `host_main` 也漏掉這件事（見上）。
2. 剩下 1 個是**測試本身寫錯**：`CHILDID_SELF` 就是 `0`，所以 `childId 0` 指的是
   視窗本身而非無效值，回 `S_OK` 才對。已改為以超出範圍的值測無效路徑。

## 已知限制

- **未以真實螢幕閱讀器（NVDA / narrator）實測**。本機防毒封鎖 GUI 應用執行，
  且真實閱讀器的驗證本就需要人工聆聽。已驗證的是 MSAA 介面本身的正確性。
- 子選單面板尚未展開（W1-05 的限制），故無障礙樹目前只有一層。
- 未實作 `accSelect` / `accDoDefaultAction`——閱讀器可朗讀與導覽，
  但無法透過無障礙介面**代為點擊**。鍵盤與滑鼠路徑不受影響。
