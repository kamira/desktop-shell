# CHG-20260724-e3_10 — 桌布設定（E3-10）

- Date: 2026-07-24 | Branch: feat/e3_10 | Risk: low | Implemented by: I1.55
- Skill: ai-sdlc-autopilot

## Motivation
E3-10「桌布設定」是 modules/actuators（動作層 / 子系統 actuators）的一個**桌面桌布致動器**：
把「設定指定顯示器 / 所有顯示器的桌布影像路徑、縮放模式（fill / fit / stretch / center）、
查詢目前桌布」這組副作用，以具名命令掛上 **E6-01 命令匯流排**（擴充點 3「動作」契約）。
呼叫端只需 命令 id + 具名參數即可觸發，**不需相依本致動器或任何 OS 桌布 API**——與已合併的
E3-05（音量設定致動器）採同一「注入式後端 + null 樣式」範式。相位 1（Mac / null 期）
**絕不呼叫真實 OS 桌布 API**（不含 NSWorkspace / setDesktopImageURL / SystemParametersInfo /
win32 / cocoa 等），只提供**平台中立介面 + null 後端（純記憶體狀態模擬）+ 契約測試**；
真實平台後端留待相位 2，屆時致動器與命令契約一行不動。

## Impact

### 新增 `modules/actuators/e3_10/`（module 層 / 子系統 actuators）
- `wallpaper_actuator.hpp` / `wallpaper_actuator.cpp`（`namespace ds::actuators`，與 e3_05 一致）：
  - 兩個具名命令 id（穩定可讀字串，不用數字 opcode）：`wallpaper.set` / `wallpaper.get`。
  - `ScaleMode` 列舉（Fill / Fit / Stretch / Center）+ `scale_mode_to_string` /
    `scale_mode_from_string`（字串 <-> 列舉雙向轉換；不使用數字魔法值；未知字串回
    `std::nullopt`，致動器據此回報無效模式）。`kDefaultScaleMode = Fill`。
  - `kAllDisplays = -1`：display 參數缺席時的語意哨兵（套用到所有顯示器）。display 為顯示器
    **相對索引**（>= 0，非絕對座標 / z-order）。
  - `WallpaperSpec` struct：`path`（不透明字串，致動器僅驗非空）+ `mode`；含相等運算子，
    供查詢 / 內省。
  - `WallpaperBackend` 抽象後端：最小介面 `display_count()` / `set(display, spec)` /
    `get(display)`。相位 2+ 由平台後端以真實桌布 API 實作；致動器只依賴此抽象。契約：
    傳入 `set()` 的 `spec.path` 已驗非空、`mode` 已合法化、`display` 已驗在 [0, display_count)。
  - `NullWallpaperBackend`（相位 1 預設後端）：**不接真實系統桌布 API**，以純記憶體狀態
    （每顯示器一份 WallpaperSpec，`std::map<int, WallpaperSpec>`）模擬；顯示器數可注入
    （預設 1，<= 0 夾為 1）；`set_count()` 內省。讓致動器在無真實後端時仍可完整跑通、
    狀態一致。
  - `WallpaperActuator`：建構綁定一個 `WallpaperBackend`（預設 NullWallpaperBackend）。
    `register_on(bus)` 把兩個具名命令註冊到 E6-01 匯流排（全成功才 true；任一失敗回滾
    已掛者、不遮蔽既有致動器；無後端回 false）；`unregister_from(bus)` 回移除數（0..2）。
    處理器亦可直接呼叫（測試不經匯流排也能驗證語意）：
    - `wallpaper.set`：必填 `path`（string，非空）；選填 `mode`（string，fill/fit/stretch/
      center，預設 fill；未知字串 → Failed）；選填 `display`（int，>= 0；**缺席 → 所有顯示器**；
      超出 [0, display_count) → Failed）。成功回 value = 實際設定的顯示器數（int），
      message = `mode=<模式>`。
    - `wallpaper.get`：選填 `display`（int，預設 0；超出範圍 → Failed）。回 value = 桌布路徑
      （string；未設定回 Null），message 帶縮放模式（未設定為 `"unset"`）。
    缺 / 型別錯 / 無效值的參數 → `CommandResult{Failed}`（以 `has()` / `get_*` 保護，不崩潰、
    **不改後端狀態**、不丟例外）。另有 `current_spec(display)` 便捷內省（不經匯流排）。
  - `wallpaper_contract_version()`：契約版本標記 `"e3_10/1.0.0"`（定義在 .cpp，使 STATIC
    程式庫非空並集中版本字串；命名加 `wallpaper_` 前綴避免與同命名空間其他致動器
    （如 e3_05 的 `volume_contract_version()`）的符號衝突）。
  - `CMakeLists.txt`：`add_library(e3_10 STATIC wallpaper_actuator.cpp)` **PUBLIC 連上游
    `e6_01`**（標頭 include `command_bus.hpp`，須傳遞 include 目錄）；
    `test_e3_10`（`tests/e3/test_e3_10.cpp`）+ `add_test(NAME e3_10)`。
- 上游相依：E6-01 命令匯流排（`ds::command::CommandBus` / `CommandArgs` / `CommandResult` /
  `CommandValue`），可讀不可改——消費擴充點 3「動作」契約，不自造匯流排或值型別。
- **無** `#ifdef` / win32 / cocoa / NSWorkspace / SystemParametersInfo 等真實桌布 API
  （backend_guard 綠燈）。致動器邏輯（路徑 / 模式 / 顯示器參數驗證、「所有顯示器」展開、
  分派、結果回報）與後端完全解耦、純邏輯、平台中立、可注入。

### 測試 `tests/e3/test_e3_10.cpp`（gtest，28 案例）
- 縮放模式字串轉換（3）：四模式往返、未知字串回 nullopt（含大小寫敏感）、預設為 fill。
- 註冊 / 反註冊（4）：兩命令全掛、重複註冊回滾且不改既有、null 後端不可註冊、
  unregister 移除全二個且再呼叫回 0。
- 設定經 E6-01 分派 + null 後端一致（2）：經匯流排 set 更新後端、get 反映先前 set（含模式）。
- 縮放模式（1）：四模式各自儲存並正確回報。
- 多顯示器 / 全部（3）：指定顯示器只設該台、缺席 display 設全部（回影響數）、
  display 超範圍 / 負值 → Failed 且不改後端狀態。
- 查詢（4）：未設定回 Ok+Null+"unset"、指定顯示器查詢、超範圍 → Failed、`current_spec` 內省。
- null 後端狀態一致（2）：顯示器數夾至 >= 1、同顯示器覆寫保留最新（非新增）。
- 無效路徑 / 模式報錯 + 參數驗證（6）：缺 path、空 path、path 型別錯、無效 mode、
  mode 型別錯、display 型別錯 → 皆 Failed 且不改後端狀態。
- 無後端 / 未知命令（2）：無後端各處理器回 Failed、匯流排未知命令回 NotFound（不崩潰）。
- 契約版本標記（1）。
