## Motivation

`backend_guard.py`（G1b）是「Mac 期不准寫真實後端」從自制力變成機器強制的那道閘門。
先前它把「相位 1 只允許 null 後端」硬編碼在腳本裡（直接讀頂層 `allowed_backends`）。
E1-26 把「**當前相位允許哪些後端**」形式化為 `docs/backlog/phase.json` 的 `phases`
區塊（相位定義 + 各相位後端白名單），並讓 `backend_guard.py` 依 phase.json 的當前相位
取該相位白名單強制之。切換相位從此是改一份宣告式資料，而非改腳本邏輯。

分工：`E1-22` 是 NFR-02/03 的 C++ lint 核心（能力閘控 / 絕對座標）；E1-26 是「後端
白名單 / 相位閘門」的治理腳本層——兩者互補，前者管 API 面形狀，後者管後端目錄相位准入。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 白名單來源 | phase.json `phases[<當前相位>].allowed_backends` | 相位驅動、宣告式；切換相位不改腳本 |
| 向後相容 | 無 `phases` 區塊時回退頂層 `allowed_backends` | 既有 phase.json 格式 `{"phase":1,"allowed_backends":["null"]}` 仍可用 |
| 未定義相位 | 當前相位不在 `phases` 中 → 紅燈並提示補白名單 | 防止相位切到白名單未覆蓋的值時「真空綠燈」 |
| 未知後端 | 白名單外任何後端目錄 → 紅燈（既有語意保留） | `found - allowed` 差集，null 放行、win32/cocoa/其他一律擋 |
| 反向檢查 | 契約測試平台分支 token 掃描（原封不動保留） | 契約一旦分平台就不是契約 |
| 可測性 | 拆函式 + `BACKEND_GUARD_ROOT` 環境變數覆寫根目錄 | 測試可對暫存樹驗證；無環境變數時 CLI 行為不變 |

## 既有行為如何被保留（low 風險關鍵）

- **CLI 介面不變**：`python scripts/backend_guard.py`（workflow `governance.yml` G1b 呼叫）
  無參數、無環境覆寫，行為與輸出一致。
- **輸出字串不變**：綠燈 `backend_guard OK — 相位 1，後端 ['null']`、紅燈
  `::error::相位 … 只允許後端 …` 與契約平台分支 annotation 皆逐字保留。
- **exit code 不變**：綠 0 / 紅 1。
- **判定不變**：對當前 repo 樹（相位 1、`src/kernel/backend/` 僅 `null/`）→ 綠燈 exit 0
  （已本機實跑驗證）。相位 1 的允許集在新舊路徑下皆為 `{null}`。
