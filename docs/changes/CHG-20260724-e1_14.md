## Motivation

四個產品共用同一 surface kernel，其中「提示 / 通知 / 召喚式臨時彈窗」這類 surface 的 profile
是**短暫（transient / ephemeral）**的——建立後只存活一小段時間，時間到即自動過期銷毀，或在
條件達成時被提早結束。E1-24 的四參數 `SurfaceProfile` 已有 `SurfaceLifecycle::Ephemeral`
這個**取值**，但沒有人管理它的**生命週期**（誰在何時讓它過期、過期時通知誰、如何清理）。

本單元補上這層管理器，把短暫 profile 的完整生命週期收斂成單一模型：

```
建立(create) → 存活(alive) → (逾時 timeout / 手動 manual) 過期(expire) → 清理(cleanup)
```

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 時間源 | **注入式** E5-10 `TimeoutTimer&`（不擁有） | 相位 1 平台中立：邏輯 tick、`advance` 注入推進，無 wall-clock。與 E1-02 注入 `KernelBackend&` 一致 |
| 每 profile 計時 | 建立時 `set_timeout(ttl)` 一次性計時器 | 到期自動移除、不漂移；`advance` 跨過 ttl 即過期 |
| 過期驅動 | 管理器 `advance(ticks)` 委派 `timer_.advance` | 到期者於計時器回呼同步自動過期；單一時間源 |
| 過期通知 | `on_expire(cb)`，攜 `TransientId` + `ExpiryReason`（Timeout / Manual） | 具名原因（NFR-02）；回呼中該 id 已不存活（收尾一致視圖） |
| 輸入行為 | `TransientProfile` 承載 E1-02 `InputStrategy` | 提示多為 `Inert` / `ClickThrough`、臨時 modal 為 `Capture`；`input_strategy()` 為整合入口，路由仍歸 E1-02 |
| 短暫語意 | `create` 強制 `surface.lifecycle = Ephemeral` | 單一資料來源，呼叫端誤設常駐亦被糾正 |
| 清理 | 過期即從記錄移除（非留死記錄） | 通知 / 提示高頻建立銷毀，避免記錄無限成長；同名可於過期後重建 |
| 具名指涉 | `TransientId = std::string` | NFR-02：不以數字 handle / index 指涉 |

## 語意保證（明確不靜默）

- `create`：空 id / `ttl == 0` / id 已存活 → 回 `false`，不覆寫既有。
- `expire`：未知 id / 已過期 → 回 `false`（**重複過期不靜默**）。手動過期先 `cancel` 其計時器，
  故其後 `advance` 不會再對它觸發一次逾時。
- 逾時過期後再手動 `expire` → 回 `false`（記錄已清理）。
- `advance(ticks)` 回傳「本次因**逾時**過期的數量」（不含手動）；`ticks == 0` 為 no-op。
- `remaining` / `profile` / `input_strategy`：未知 / 已過期分別回 `nullopt` / `nullptr` /
  `kDefaultStrategy`（保守）。

## 生命週期caveat

管理器在注入的 `TimeoutTimer` 上登記捕捉 `this` 的回呼，故該計時器須比管理器活得久；
管理器解構時主動 `cancel` 其所有未觸發計時器，避免懸置回呼。
