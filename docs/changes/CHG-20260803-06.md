## Motivation

`CHG-20260803-05` 交付的桌面 widget 有一個明講過的缺口：**沒有正常的關閉入口**，
只能靠 `--seconds N` 或工作管理員。使用者指定下一步為「托盤圖示 + 右鍵選單」，本 CHG 補上。

依 `phase2-desktop-runtime.md` §2 的對照，這些功能**全部已是現成單元**
（E11-01 系統匣 + E6-01 命令匯流排 + E1-01 圖層 + E1-02 輸入策略），
缺的只是 win32 後端與 host 端的裝配——**引擎不需要任何新抽象**。本 CHG 證實了這個判斷。

## Impact

### W1-02 — `src/host/win32/`（新目錄）

`Win32TrayBackend` 實作 E11-01 的 `ds::host::TrayBackend`：
`Shell_NotifyIcon` 建立真實匣圖示、`TrayMenu` 模型遞迴轉成原生 `HMENU`、
右鍵以 `TrackPopupMenu(TPM_RETURNCMD)` 顯示。

**兩個設計決定**：

1. **自建 message-only 視窗**，不借用 W1-01 的 HWND —— 托盤與 kernel 後端完全解耦。
2. **只回報「選了哪一項」的索引路徑，不解釋語意。** Checkbox 切換、命令分派、
   邊界情形全部留給 E11-01 `SystemTray::click(path)`——**選單邏輯一行都不重寫**。
   契約沒有「使用者選了什麼」的回呼（相位 1 的 null 後端沒有真實使用者），
   故以非虛擬的 `poll_selection()` 提供，**契約本身一個字未動**。

`build_native_menu()` 刻意抽成自由函式：不需要匣圖示、不需要使用者互動，
可離線用 `GetMenuItemCount` / `GetMenuState` / `GetSubMenu` 斷言結構與狀態。

### H1-02 — `host/tray/`（新目錄）+ `host/app/host_main.cpp` 改用之

三個選單項 = 三個 E6-01 命令：

| 選單項 | 命令 id | 處理器 |
|---|---|---|
| 最上層顯示（Checkbox） | `widget.toggle_topmost` | `set_surface_layer(Topmost / Normal)` |
| 點擊穿透（Checkbox） | `widget.toggle_passthrough` | `set_input_policy(PassThrough / Accepting)` |
| 結束（Action） | `app.quit` | 設定結束旗標 |

抽成獨立單元而非寫在 `wWinMain` 裡，是為了讓「選單項 → 命令 → 後端狀態真的改變」
這條鏈**可以被測試走完**，只留「滑鼠實際點下去」給操作驗收。
`host_main.cpp` 與測試共用同一份裝配，避免被測的那份與實際跑的那份分岔。

### W1-01 附帶修正：補上 `set_surface_layer()`

**施工中發現的契約缺口**：`KernelBackend` 只能在 `create_surface` 時指定
`SurfaceProfile.layer`，**沒有事後改圖層的方法**——而托盤的「最上層切換」正需要它。

上游 E1-24 可讀不可改，故先在 W1-01 自己的後端補一個**非虛擬**的 `set_surface_layer()`。
放後端而不是讓 host 直接呼叫 `SetWindowPos`，是因為「具名圖層 → win32 z-order」的對映
屬後端職責；散到 host 去就變成兩處各自維護同一張對照表。

**補進契約應另開 CHG**（會連帶影響 null 後端與所有呼叫端），此處不做。

### H1-02 整合測試涵蓋的鏈路

`SystemTray::click(path)` → E6-01 命令 → W1-01 後端 → **真實視窗 ex-style 改變**。
斷言一律去問 Windows（`GetWindowLongPtrW`），不問程式旗標：

- 點「最上層」→ 視窗真的失去 `WS_EX_TOPMOST`；再點一次真的加回來
- 點「穿透」→ 視窗真的取得 `WS_EX_TRANSPARENT`；再點一次真的拿掉
- **兩個開關互不干擾**（切最上層不得動到穿透）
- 分隔線 → `NotClickable` 且任何視窗狀態不得改變
- 越界 / 空路徑 → `InvalidPath`，不崩潰
- click 後選單模型的勾選狀態跟著翻面（否則下次打開會說謊）

### 操作驗收

叫出真實選單並截圖：

```

popup menu rect     = (1696,977) 158x81      （class #32768 = Windows 原生選單）
```

## ⚠ 已知限制

1. **完全不在 CI 閘門守備範圍**。`if(WIN32)` 讓 ubuntu 看不到；更甚者，
   `backend_guard` 的相位閘門**只掃 `src/kernel/backend/*`，不涵蓋 `src/host/win32/`**——
   本單元既無平台白名單保護、也無建置驗證。需 windows runner（checklist 步驟 3）。
2. **匣圖示為系統預設圖示**。`set_icon` 如實保存具名值，但具名圖示 → 實際資源的對照
   尚未建立（需圖示資源與 E9 套件格式）。
3. 尚無：拖曳移動、設定持久化、skin 套件格式、E11-02 自繪選單（目前用原生選單）。
