# CHG-20260723-07 — 分層改為三層 core / module / artifact，module 層加具名 subsystem

- Date: 2026-07-24 (UTC+0) | Branch: claude/ai-sdlc-handshake-validation-380ada | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
CHG-05 把分層做成兩層（core 152 / component 24），**那是錯的** ——
它把「掛在擴充點上的提供者」併進了 core。實際分層是三層：
平台核心 → 掛上去的模組（sysinfo 等具名子系統）→ 桌面上顯示的產出物。

連帶更正：先前我把架構草案的「平台核心 97 項」「56 個模組」判定為舊版殘留數字，
**那個判定是錯的**。97/56 正是這個三層切分的結果，只是我當時把 module 併進 core 才對不上。

## Impact

### 分層規則（機械可複算）
| 判準 | → layer / subsystem |
|---|---|
| `write_scope` 含 `content/**` 或 `apps/**`（`C1`–`C4`） | **artifact** |
| `E2` 除 `E2-01`（指標介面契約）、`E2-02`（採集頻率基礎設施） | **module / sysinfo** |
| `E3` 全部 | **module / actuators** |
| `E4` 除繪製基座 8 項（`E4-01`/`05`/`06`/`08`/`09`/`22`/`23`/`24`） | **module / elements** |
| 其餘 | **core** |

### `units.json` 欄位變更
- `layer` 值域：`{core, component}` → **`{core, module, artifact}`**
- 新增 `subsystem`（**僅 `layer=module` 的 58 筆有此欄位**）：`sysinfo` / `actuators` / `elements`
- `totals.by_layer` 改值；新增 `totals.by_subsystem`
- **既有欄位一律未動**（`module` / `group` / `stage` / `wave` / `depends_on` / `write_scope`），
  故 `plan.py`（用 `module` 組 `tests/` 路徑）、`scope_check`（用 `write_scope`）、
  `stage_check`（用 `stage`）三者皆不受影響

### 命名衝突已解
「component」先前同時指 `C1`–`C4`（架構文件）與子系統（sysinfo），語意衝突。
**兩者都改名**：`C1`–`C4` → **artifact**；module 底下的具名分群 → **subsystem**。
四份文件（`architecture` / `requirements` / `ai-guideline` / `structure/directory`）
的術語與數字全部同步，全 repo 已無殘留 `component` 字樣（歷史 CHG 除外）。

## 結構不變量（本次分層的正確性佐證）

|---|---|---|---|
| core | **29** | 0 | 65 |
| module | **0** | 34 | 24 |
| artifact | **0** | 0 | 24 |

推論：**契約定稿後，82 項與平台後端完全無關，可無限並行。**
