# CHG-20260724-e7_06 — 錯誤可見性（E7-06）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e7_06 | Risk: low | Implemented by: I1.31
- Skill: ai-sdlc-autopilot v1.1
- Unit: E7-06（錯誤可見性，engine 層 / 描述子系統 / low；相依已合併的 E7-01）
- NFR: NFR-04「描述格式錯誤須定位到行、不得靜默」

## Motivation

E7-01 的 `parse()` 失敗時回傳 `ParseError{line, message}`——這對機器友善，但對「人」不夠：
沒有把肇因來源行、指到第幾欄的視覺化呈現。NFR-04 明確要求「描述格式錯誤須定位到行、
不得靜默」。**錯誤可見性**單元補上這一層：把 E7-01 的解析/驗證錯誤轉成人類可讀、
定位到行/欄、附上下文片段與插字符的診斷輸出，並能把多筆錯誤彙整成一份報告。

本單元建構於 E7-01 之上、**消費其 `ParseError` / `ParseResult`**，不碰解析邏輯：只新增
呈現層。屬 engine 層（平台中立純邏輯）：無任何 `#ifdef` / 系統呼叫 / 真實後端，可完全單元測試。

依 NFR-04「不靜默」：格式化空集合回傳明確的 `no diagnostics`（而非空字串）；彙整 N 筆錯誤
必定在標頭載明筆數並原封輸出全部 N 筆；行號超出來源範圍時不硬造上下文，但訊息與行號絕不消失。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 呈現單位 | `Diagnostic{severity, line, column, message}` | E7-01 `ParseError` 的呈現層對應物；額外帶「欄」與「嚴重度」 |
| 由 ParseError 轉入 | `Diagnostic::from_parse_error(e[, column])` | 直接橋接上游；column 未知時預設 0（ParseError 未帶欄） |
| 嚴重度 | `Severity{Error, Warning, Note}` + `severity_label` | 首行前綴（`error:` / `warning:` / `note:`）；Error 對應 parse 失敗，其餘供呼叫端補充 |
| 定位語意 | `line`（1-based，0 = 非特定行）沿用 E7-01；`column`（1-based，0 = 未知） | 與上游 `ParseError.line` 完全一致；欄為選配、有則畫插字符 |
| 輸出風格 | Rust 式診斷：首行 `severity: message`、`--> line L:C`、側欄行號 + 來源行、`^` 插字符 | 極易讀、業界熟悉；上下文片段直接取自來源文字 |
| 上下文擷取 | 以 `'\n'` 切分取第 L 行；剝除尾端 `'\r'`（相容 CRLF）；超範圍則省略上下文 | 純字串邏輯、無相依；行號超範圍不硬造（但不吞訊息） |
| 插字符 | column - 1 個前導空白 + 單一 `^`（字元計數，1-based） | 指到欄；column == 0 或 `show_caret=false` 則不畫 |
| 彙整 | `format_report` / `format_errors`：標頭 `N diagnostic(s):` + 各筆空行分隔 | 一眼看出筆數、順序保持、全部原封輸出（不折疊） |
| 不靜默 | 空集合 → `no diagnostics`（非空字串）；訊息永遠原封呈現 | NFR-04；避免「靜默成功」假象 |
| 收集器 | `DiagnosticReport`：`add` / `add_parse_error` / `size` / `error_count` / `ok` / `render` | 邊解析邊蒐集或彙整多來源；`ok()` iff 無 Error 嚴重度，供呼叫端據以判成敗 |
| 選項 | `FormatOptions{show_context, show_caret}`（預設全開、無顏色） | 輸出決定性、易於單元測試；可關上下文 / 插字符供精簡輸出 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。不含能力閘控呼叫（純呈現邏輯），
無 `has()` 降級路徑需求。
