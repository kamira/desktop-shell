# CHG-20260724-e1_23 — 分層失敗的手動降級路徑（E1-23）

- Date: 2026-07-24 | Branch: feat/e1_23 | Risk: low | Implemented by: I1.116
- Skill: ai-sdlc-autopilot v1.116
- Unit: E1-23（分層失敗的手動降級路徑，platform 層 / kernel / 相位 1，depends_on=[E1-01, E1-21]）

## Motivation

E1-01 的 `LayerStack` 把 surface 指派到具名圖層，但所有改動狀態的操作都經
`has(kernel.surface)` 能力閘控（NFR-03）；某些平台 / 情境下這個能力本身不可用，
或 `assign()` 因其他原因（如空 id）被拒。此時呼叫端需要一條**明確的手動降級路徑**：
退回到較簡單的呈現（單層扁平化、無 overlay），而不是讓分層失敗變成靜默的「什麼
都沒發生」或未定義行為。

E1-23 提供這條降級路徑：`LayerFallback` 先嘗試正常分層，失敗時（能力不可用或
assign 被拒）自動改走扁平化；降級是否發生、發生的原因，一律透過結果與查詢介面
可見回報，不靜默吞掉。降級策略可由呼叫端注入，客製「該不該降級」與「降級後扁平化
到哪個具名圖層」。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 主要入口 | `try_layered(stack, id, requested_layer)` | 一次呼叫涵蓋「先試分層、失敗自動降級」，呼叫端不需自行判斷失敗模式 |
| 手動路徑 | `fallback_flatten(stack, id)` | 供呼叫端不經自動判定、主動要求降級（如已知情境需要降級） |
| 降級可見性 | `LayerFallbackResult{degraded, reason, assign_result, effective_layer}` + `degrade_reason()` / `last_degraded()` | 降級與否、原因、實際落地圖層一律可查，不靜默 |
| 降級原因分類 | `FallbackReason`：`None` / `CapabilityUnavailable` / `AssignRejected` / `StrategyForced` | 讓「能力不可用」與「assign 因其他原因失敗（如空 id）」可分辨，呼叫端可用不同方式應對 |
| 降級策略 | `FallbackStrategy`（虛擬介面，`layered_available()` / `flatten_target()`），可注入、可 `set_strategy()` | 決策不寫死：預設以 `has(kernel.surface)` 判斷可用性、扁平目的層固定 `Normal`；呼叫端可覆寫兩者 |
| 是否持有 LayerStack | 不持有；每次操作以參數傳入 `LayerStack&` | 降級決策應隨「當下」能力狀態而定，不綁死在建構當下；同一個 `LayerFallback` 可用於「能力不可用的 stack」與「能力恢復後的 stack」 |
| 能力矩陣完全不可用時的扁平化 assign | 仍呼叫 `stack.assign()`，可能因 `RejectedNoCapability` 而寫入失敗 | `LayerStack::assign()` 本身受 `has(kernel.surface)` 閘控，涵蓋所有圖層；如實回報「試過但寫不進去」，優於偽造成功（NFR-03 精神：不崩潰、不偽裝狀態） |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。

## Impact

### 1. `src/kernel/e1_23/layer_fallback.hpp`（新增）
- `FallbackReason`：`None` / `CapabilityUnavailable` / `AssignRejected` / `StrategyForced`。
- `FallbackStrategy`：可注入降級策略介面，預設 `layered_available()` 委由 `has(kernel.surface)`、
  `flatten_target()` 固定回 `SurfaceLayer::Normal`。
- `LayerFallbackResult`：`{ degraded, reason, assign_result, effective_layer }`。
- `LayerFallback`：`try_layered()` / `fallback_flatten()` / `set_strategy()` / `strategy()` /
  `degrade_reason()` / `last_degraded()`。

### 2. `src/kernel/e1_23/layer_fallback.cpp`（新增）
- `try_layered()`：策略判定能力不可用 → 降級（`CapabilityUnavailable`）；能力可用但
  `assign()` 失敗 → 降級（`AssignRejected`）；否則正常路徑，不降級。
- `fallback_flatten()`：直接呼叫降級，依當下能力狀態回報 `CapabilityUnavailable` 或
  `StrategyForced`（不覆蓋事實）。
- 建構子 / `set_strategy()` 對 `nullptr` 保守處理，不留空指標風險。

### 3. `src/kernel/e1_23/CMakeLists.txt`（新增）
- `add_library(e1_23 STATIC layer_fallback.cpp)` + `target_link_libraries(e1_23 PUBLIC e1_01 e1_21)`
  + `test_e1_23` executable（`tests/e1/test_e1_23.cpp`）+ `add_test(NAME e1_23)`，依 BUILD.md 樣板；
  根 CMakeLists 自動 glob 收入。

### 4. `tests/e1/test_e1_23.cpp`（新增）
- 12 個 gtest 案例：分層可用正常路徑、能力不可用降級、assign 失敗（非能力問題）降級、
  降級原因可見回報（初始狀態 / 隨最近一次呼叫更新）、`fallback_flatten()` 直接呼叫兩種
  原因分支、可注入策略（自訂扁平目的層 / 執行期切換策略 / nullptr 安全退回預設）、
  多層降級（三個不同請求圖層全部扁平化到同一具名圖層）、能力恢復後回到正常路徑。

### 5. `docs/structure/units/e1_23.md`（新增；G4 要求）
- 本單元獨立結構註記（不動共用的 `docs/structure/directory.md`）。
