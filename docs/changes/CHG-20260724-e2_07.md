# CHG-20260724-e2_07 — 儲存 IO 吞吐與佇列（E2-07）

- Date: 2026-07-24 | Branch: feat/e2_07 | Risk: low | Implemented by: I1.60
- Skill: ai-sdlc-autopilot

## Motivation
E2-07「儲存 IO 吞吐與佇列」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「磁碟 IO 指標」——讀 / 寫**吞吐率**（bytes/sec）、
讀 / 寫 **IOPS**（每秒操作數）、**佇列深度**（queue depth）——掛成一組指標，並以 **E2-02
採集頻率分級**決定採樣節奏，支援**多磁碟**（每顆磁碟一個可列舉實例）。這是「新增指標 =
新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 / E2-02 契約、
不自造指標模型或排程器**。吞吐率 / IOPS 由**累積計數差分**得出：作業系統原生磁碟統計多為
單調遞增的累積計數（累積 read/write bytes、累積操作數），速率須由「兩次取樣差分」——注入
兩份累積計數 + 各自時間戳，速率 = 計數Δ / 時間差。佇列深度為**瞬時值**，不需差分。相位 1
（Mac / null 期）**絕不接任何真實 IO API**（不含 IOKit / `/proc/diskstats` / mach /
`#ifdef` / win32 / cocoa）；改為**可注入的 IO 統計來源抽象** + null / 假來源；真實平台後端
留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_07/`（module 層 / 子系統 sysinfo）
- `disk_io.hpp` / `disk_io.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `DiskIoCounters`：單顆磁碟的**累積** read/write bytes、累積 read/write ops，加**瞬時**
      queue_depth（含相等運算子）。單一時刻累積值無意義——速率須由兩次取樣差分得出。
    - `DiskIoSnapshot`：某顆磁碟的身分（id/label）+ 累積計數（身分與數值分離，讓差分自由
      函式只對純數值運算）。
    - `DiskIoSample`：某時刻全磁碟的累積計數快照（時間戳 + 每顆磁碟一筆；磁碟數可在取樣間
      變動）。
    - `DiskIoRates`：單顆磁碟的**已差分**速率（read_bps / write_bps / read_iops /
      write_iops）+ 瞬時 queue_depth（含相等運算子）。
    - `DiskIoReading` / `DiskIoUsageSample`：身分 + 速率的列舉輸出；`unknown()` = 無讀值
      （valid==false）；含相等運算子。
  - **差分演算法**（自由函式，獨立可測、純算術）：
    - `counter_rate(prev, curr, dt)`：單一累積計數速率 = (currΔ / dt)。防護：dt<=0（無經過
      時間 / 時間戳未推進）→0、curr<prev（回繞 / 重置）→0。
    - `rates_from_delta(prev, curr, dt)`：由兩份累積計數 + 時間差算四個速率；queue_depth 為
      瞬時值，直接取當前快照（不差分）。
    - `usage_from_delta(prev, curr)`：dt = 兩份時間戳差；每顆磁碟以兩份的**共同磁碟數**
      （較小者）對齊、逐顆 `rates_from_delta`，身分取自當前快照；共同磁碟數 0 → 無讀值
      （valid==false）；dt<=0 時仍 valid（有共同磁碟），惟速率為 0、佇列深度照常帶出。
  - **累積計數來源**（列舉磁碟 + 每磁碟累積計數，提供者不直接依賴）：
    - `IoStatSource`（抽象 `read()→DiskIoSample`，給累積計數 + 時間戳，尚未差分）。
    - `NullIoStatSource`：相位 1 null / 假來源——**不接真實 IO API**，注入累積計數序列
      （模擬時間推進），`read()` 回下一份、列盡持續回最後一份；`set_sequence` /
      `push_sample` / `reset` 操作，供測試與假感測器情境。
  - **速率來源**（提供者只依賴此抽象）：
    - `IoRateSource`（抽象 `sample()→DiskIoUsageSample`；非 const，差分型來源取樣有副作用）。
    - `NullIoRateSource`：相位 1 null / 假「直接速率」來源——預設回無讀值；`set_usage` /
      `clear` 注入，供測試繞過差分直接餵速率。
    - `DifferencingIoRateSource`：把「累積計數來源」以「兩次取樣差分」轉成 `IoRateSource`
      （保存上一份、每次 sample 差分；首次 / reset 後首次回未知——差分至少需兩份）。
  - **提供者** `DiskIoProvider : ds::metrics::MetricProvider`：`register_metrics()` 掛上
    **五個指標**——`disk.io.read_bytes`（"Disk Read Throughput"，unit "B/s"）、
    `disk.io.write_bytes`（"Disk Write Throughput"，"B/s"）、`disk.io.read_iops`
    （"Disk Read IOPS"，"IOPS"）、`disk.io.write_iops`（"Disk Write IOPS"，"IOPS"）、
    `disk.io.queue`（"Disk Queue Depth"，unit ""）——每個指標 range=`at_least(0)`（上無界，
    儲存裝置速率跨度大不強設上限），可列舉實例 = **每顆磁碟**（instance_id = 磁碟識別碼、
    各保留歷史環）；`sample()` 重新讀來源更新五指標各磁碟實例（速率推入歷史，新磁碟則於
    五指標動態新增實例、本次未出現的既有磁碟設未知不污染歷史）；`sampling_tier()` 回建議
    採集分級（預設 Normal），供 `SamplingScheduler::add_demand`。
  - **核心性質**：相位 1（Mac / null 期）平台中立、**無 `#ifdef` / IOKit / /proc/diskstats /
    mach / win32 / cocoa** 等真實 IO API；無讀值時以 valid==false（未知）誠實表達、不謊報 0；
    消費者只透過 E2-01 抽象介面走訪，新增此組指標掛件一行不動。
- `CMakeLists.txt`：`add_library(e2_07 STATIC disk_io.cpp)`；**PUBLIC 連上游 `e2_01` `e2_02`**；
  `add_executable(test_e2_07 …)` + `add_test(NAME e2_07)`。
