# CHG-20260724-e1_07 — anchor 定位模型（E1-07）

- Date: 2026-07-24 | Branch: feat/e1_07 | Risk: low | Implemented by: I1.101
- Skill: ai-sdlc-autopilot
- Unit: E1-07（anchor 定位模型，platform 層 / kernel 子系統 / phase=1 / risk=low / depends_on=[E1-03] / load_bearing=5）

## Motivation

桌面外殼要把桌寵 / 面板 / 浮層等元件擺在螢幕 / 父容器的特定位置。若直接以**絕對像素座標**
`set_position(x, y)` 表達，會違反 NFR-02（核心 API 不得絕對座標與數字 z-order），且無法適應不同
解析度 / 容器尺寸——同一組像素座標在小螢幕溢出、在大螢幕縮在一角。

E1-07 提供 **anchor（錨點）定位模型**作為 NFR-02 的正解：以**九宮具名錨點**
（top-left / center / bottom-right …）搭配**相對容器邊緣的正規化偏移**（比例或具名間距）宣告位置，
再由純佈局計算 `resolve()` 在給定容器尺寸下解析為具體佈局。核心宣告式 API 內**不出現任何絕對
像素座標 / 數字 z-order**；具體數字只在 `resolve()` 這個計算邊界、由呼叫端提供的尺寸推導而得
（與 E1-03 以正規化 opacity 承載透明度、只在合成邊界化為具體值同理）。相位 1 為純邏輯，
無真實視窗 / 繪圖 API。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 具名錨點 | `enum class Anchor` 九宮（TopLeft…BottomRight）；`anchor_fraction()` → 正規化分數 [0,1]²（0/0.5/1） | NFR-02：以**具名角色**表達參考點，不以像素座標；九宮涵蓋角 / 邊 / 中 |
| 錨點語意 | 同一 anchor 同時作容器參考點與**元件自身**參考點 | 角 / 邊錨點天然產生**邊緣對齊**（元件貼齊該邊、不溢出），置中錨點置中 |
| 相對偏移 | `Offset{dx, dy}`，dx/dy 為**容器尺寸的正規化分數**（比例，非像素） | NFR-02：偏移是比例值，隨容器縮放；非絕對座標 |
| 具名間距 | `enum class Spacing`{None…Spacious} → `spacing_fraction()`；`Offset::from_spacing` / `inset_from(anchor, spacing)` | 讓「距邊緣一點點」用**具名間距**表達而非硬編像素；`inset_from` 依錨定邊自動決定內縮方向 |
| 宣告式規格 | `AnchorSpec{Anchor anchor; Offset offset}` | 取代 (x,y) 絕對座標的**核心宣告式**表達 |
| 解析 | `resolve(spec, container, element, out)` → `ResolvedPlacement{x,y,w,h}`；`resolve_point`（元件視為零尺寸點） | 純佈局計算；具體像素只在此邊界出現，由呼叫端提供的尺寸推導。公式：`x = fx*(cw-ew) + dx*cw` |
| 結果碼 | `enum class AnchorStatus`{Ok, Invalid}，與 E1-03 `AlphaStatus` 同風格 | 結構化、平台中立、不靜默 |
| 錯誤處理 | 越界 anchor（int 越界 static_cast）、非有限 offset、非有限 / 負尺寸 → Invalid 且**不寫 out** | 無效 anchor 報錯不靜默（規格硬項）；不崩潰 |
| 具名 surface 服務 | `AnchorLayout`：以具名 `SurfaceId`（承 E1-03/E1-24 模型）為鍵配對 `AnchorSpec`，`place`/`remove`/`resolve_for` | 承上游具名 surface 模型（NFR-02 具名指涉）；風格對齊 `AlphaSurfaceService` 的記錄配對；純記憶體純佈局 |

## Impact

### 影響分析（low 風險，load_bearing=5）

- **回溯相容**：純新增單元。未改任何既有 `src` / `engine` / `modules` / 上游單元（E1-03 / E1-24 /
  E1-21）/ `units.json` / 根 CMakeLists / 共用 `directory.md`；對既有單元零影響。
- **上游耦合**：僅**唯讀**依賴 E1-03（`target_link_libraries(e1_07 PUBLIC e1_03)`），透過其 include
  鏈取得 E1-24 具名 `SurfaceId` 型別供 `AnchorLayout` 以具名鍵配對。不觸碰上游任何符號實作，
  不加虛擬方法；純以組合 / 型別複用。
- **NFR-02（核心 API 不得絕對座標 / 數字 z-order）**：本單元即為此 NFR 的定位解。核心型別
  （`Anchor` / `AnchorSpec` / `Offset` / `Spacing`）**無任何像素座標欄位**；具體像素只在 `resolve()`
  的**輸入尺寸**（呼叫端提供）與**輸出佈局**（計算結果）出現，非宣告式定位 API 的一部分。
- **下游意義**：`Anchor` 九宮 / `AnchorSpec` / `Spacing` 會成為視覺 / 元件單元表達「這個元件擺哪」
  的共同詞彙；`resolve()` 是它們把宣告式定位落地到具體容器的單一計算入口。API 面保守、平台中立
  （不涉及 DPI / 多螢幕拓撲 / 座標系原點方向等平台細節，留給真實後端相位 2+）。
- **建置面**：新增靜態庫 `e1_07`（`PUBLIC` 連 `e1_03`）與可執行檔 `test_e1_07` + CTest `e1_07`。
  根 CMakeLists 既有層級 GLOB（`src/*/*/CMakeLists.txt`，深度 2）已涵蓋 `src/kernel/e1_07/CMakeLists.txt`，
  **無需**改根建置檔。
- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發；純佈局邏輯無平台分支。
