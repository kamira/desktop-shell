# CHG-20260723-10 — src/ 收斂為「只放對系統的操作」，平台中立邏輯遷至 engine/（第一批 39 項）

- Date: 2026-07-24 (UTC+0) | Branch: claude/ai-sdlc-handshake-validation-380ada | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
`src/` 只放平台還不夠。平台本身也分兩種：**對系統的操作**（需要 per-platform 後端）
與**平台中立的引擎邏輯**（換平台一行都不用動）。兩者混在一起，
「跨平台到底要改哪裡」仍然看不出來。

`core` 94 項中僅 **29 項**是對系統的操作（語意分歧），其餘 65 項平台中立。
把後者遷出 `src/`，使平台適配面最小且顯而易見 —— 這也讓 A1（Qt/QML 語言選擇）
的驗證範圍變明確：真正要驗的就是 `src/` 那些項目。

## Impact

### 本批遷移（39 項，`src/` → `engine/`）
| 目的地 | 項 | 內容 |
|---|---|---|
| `engine/format/` | 15 | 宣告式格式核心、變數、公式引擎、熱重載、錯誤可見性、設定遷移 |
| `engine/package/` | 9 | 套件格式、manifest、可互換元件組合、主題、佈局存檔、安裝器 |
| `engine/command/` | 5 | 命令匯流排與分派、動作註冊表、條件動作、延遲批次、跨 surface |
| `engine/script/` | 5 | 腳本引擎、對話直譯器、表現控制、行程內模組載入、外部模組介面 |
| `engine/ipc/` | 5 | 本機 IPC、低延遲通道、HTTP 端點、事件廣播協定、獨立行程宿主 |

前置檢查：這 5 個 `src/` 根**僅 core 層使用**（`assert set(owners)=={'core'}`），可整批搬。
`tests/`、`docs/changes/` 路徑不動；`layer`/`stage`/`module`/`depends_on` 全不動。

### 尚未遷出（分批進行）
`src/` 仍有平台中立項：`render` 8 / `sensors` 2 / `common` 2，及 `events` 中的 11 項。

**`E1-24` null 後端參考實作刻意不遷**：它雖平台中立，但它是**後端契約的第一個實作**，
存在意義就是與 win32/cocoa 後端可互換。遷走會把後端家族拆成兩棵樹，
且 `backend_guard.py` 是以 `src/kernel/backend/*` 執行相位閘門的。
`E1-25`（`tests/contract/**`）與 `E1-26`（`scripts/`）本就沒有 `src/` 路徑，無需搬移。

### G4 同步擴充（`^(src|modules)/` → `^(src|engine|modules)/`）
**必須與遷移同批進行**，否則這 39 項會靜默脫離結構同步閘門 —— 即 CHG-08 犯過、
CHG-09 才補回的同一個錯。已在 workflow 註解中留下警語：
新增程式碼頂層目錄時務必同步擴充 G4。

觸發 G4 的單元維持 **150**（core 92 + module 58），無單元漏網。

### 文件同步
- `docs/structure/directory.md`：樹狀圖改為 `src/`（對系統的操作）／`engine/`（平台中立）／
  `modules/`（提供者）三段並列；平台中立但待遷出者以 `⧗` 標記；分層對應表註明
  `core` 橫跨 `src/` 53 條 + `engine/` 39 條
- `docs/architecture.md`：新增「`src/` 再收斂為只放對系統的操作」一節與遷移狀態

## 附帶效果

分層欄位與目錄正交，機制不受影響，但「core」不再對應單一目錄。
是否把 `core` 再拆成 `platform` / `engine` 兩值，待決。
