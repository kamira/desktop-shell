## Motivation

E6-01 提供「無條件、即時」的具名命令分派。真實編排常還需要兩件事：

1. **條件動作**：某動作只在特定條件成立時才觸發（如 `count > 0` 才播放、`ready && !busy`
   才執行）。若把條件判斷寫死在每個呼叫端，條件邏輯就散落各處、無法宣告式描述。
2. **去抖 / 節流**：短時間內的大量重複觸發（手勢、輪詢、事件風暴）不該逐一執行；去抖把
   連續觸發合併成一次，節流限制執行頻率。

E6-03 在 E6-01 之上補這兩層編排，且**不重造輪子**：條件以 E7-05 公式引擎求值，命令仍經
E6-01 匯流排分派。時間一律以**注入式邏輯 tick** 表達，不碰 wall-clock / thread / sleep，
故整個單元平台中立且可決定性單元測試。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 條件求值 | 委派 E7-05 `Evaluator`（含 `VariableScope`） | 不重造運算式引擎；條件即宣告式公式，可組合 |
| 真值橋接 | `value_truthiness`：Bool→原值、Number→非零為真、其餘→型別錯誤 | 最小明確規則；非布林條件不臆測真假 |
| 求值失敗 | 明確回 `ConditionError`（帶訊息 + 欄位），**不分派、不靜默** | 對齊 NFR-04；避免「錯誤被當成 false」悄悄跳過 |
| 編排結果 | `ConditionalOutcome`{status ∈ Dispatched/Skipped/ConditionError} | 三態互斥，呼叫端無需再猜 |
| 條件動作形狀 | `ConditionalAction`{condition_expr, command, args} | 與 E6-01 `Command`（id+args）對稱：= 條件 + Command |
| 去抖語意 | `Debouncer`（尾緣 / 合併）：`trigger` 登記待決、`advance` 過靜默視窗才放行一次 | 連續觸發合併成一次（「只執行最後一次」） |
| 節流語意 | `Throttler`（前緣 / 頻率限制）：`trigger` 即時決策、距上次放行滿 interval 才再放行 | 限制放行頻率 |
| 時間模型 | 注入式邏輯 `Tick`（單調整數），倒退夾住 | 平台中立、無 wall-clock/thread、可決定性測試 |
| 契約版本 | `conditional_contract_version()` = "e6_03/1.0.0" | 沿用 E6-01 版本標記慣例 |

介面平台中立：無 `#ifdef` 等平台分支、不綁真實副作用 / OS 後端 / 系統呼叫。命名空間與
E6-01 一致（`ds::command`）。
