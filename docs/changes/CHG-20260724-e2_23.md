# CHG-20260724-e2_23 — 檔案系統列舉（E2-23）

- Date: 2026-07-24 | Branch: feat/e2_23 | Risk: low | Implemented by: I1.48
- Skill: ai-sdlc-autopilot

## Motivation
E2-23「檔案系統列舉」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一
指標介面**（擴充點 1 契約）把「某路徑下的目錄項目清單／數量」隨選掛成一個指標。它**消費
E2-01 契約、不自造指標模型**，沿用 E2-16 已安裝應用列舉的隨選列舉樣式。相位 1（Mac / null
期）**絕不接真實檔案系統**：不含 `<filesystem>` 實體存取、不 `opendir`、無 `#ifdef` / win32 /
cocoa 平台分支；列舉來源為**可注入的 `FileSystemSource` 抽象** + 一個**記憶體內假來源**
（`NullFileSystemSource`，持有記憶體目錄樹）。真實 OS 目錄掃描留待後端相位。

## Impact

### 新增 `modules/sysinfo/e2_23/`（module 層 / 子系統 sysinfo）
- `fs_enum.hpp` / `fs_enum.cpp`（`namespace ds::sysinfo`）：
  - `DirEntryType`（File / Directory / Other）+ `to_string`：類型區分（檔 / 目錄）。
  - `DirEntry` struct：平台中立子項目描述 —— `name` / `type` / `size`（位元組）/ `mtime`
    （Unix epoch 秒，平台中立整數）；`is_file()` / `is_directory()` 便利查詢 + 相等運算子。
    刻意不含平台專屬欄位（inode / ACL 等）。
  - `FsError`（None / NotFound / NotADirectory / PermissionDenied）+ `ListResult` /
    `StatResult`：**錯誤不靜默**——無效路徑 / 非目錄 / 權限錯以明確錯誤碼回報，消費者可
    分辨「空目錄」與「路徑錯誤」，而非把錯誤吞成空清單。
  - `FileSystemSource` 抽象後端：`list(path) → ListResult`、`stat(path) → StatResult`
    （決定性順序）。真實平台後端於相位 2+ 實作；提供者只依賴此抽象介面。
  - `NullFileSystemSource` 記憶體內假來源：**絕不掃描真實檔案系統**，持有記憶體目錄樹；
    `add_file` / `add_dir`（中間目錄自動建立）/ `set_permission_denied`（模擬權限錯）/
    `clear` 供測試與假感測器情境。POSIX 風格路徑切分（'/' 分段、忽略空段 / 尾端斜線、
    "" 與 "/" 皆指根），以字典序 `std::map` 保證決定性列舉。
  - `FileSystemEnumProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.fs"`；`register_metrics(registry)` 對建構時指定路徑呼叫來源
    `list()`，向 E2-01 註冊表掛上單一指標 `"fs.entries"`（name="Filesystem Entries"、
    unit=""、range=`at_least(0)`）。**每個目錄子項目 = 一個可列舉 `MetricInstance`**
    （instance_id=label=項目名、value=存在(1.0)+類型文字 "file"/"dir"、history_capacity=0）。
    於是「清單」由 `Metric` 列舉實例取得、「數量」即 `Metric::instance_count()`。列舉錯誤
    （無效路徑 / 權限 / null source）不崩：仍保守掛上「空指標」（instance_count()==0），
    並以 `last_error()` 明確回報，不靜默。
  - `CMakeLists.txt`：`add_library(e2_23)` **PUBLIC 連上游 `e2_01`**（標頭 include
    `metric.hpp`，須傳遞 include 目錄）；`test_e2_23` + `add_test(NAME e2_23)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`，可讀不可改）。
- **無** `#ifdef` / win32 / cocoa / `<filesystem>` 實體存取 / `opendir`（backend_guard 綠燈）。
  純邏輯、平台中立。

### 測試 `tests/e2/test_e2_23.cpp`（gtest，26 案例）
- 列舉目錄項目 + 決定性順序（3）：列舉子項目、路徑正規化等價、根目錄列舉。
- 檔 / 目錄類型區分（1）。
- 中繼欄位（1）：size / mtime 正確承載（目錄 size 慣例 0）。
- 巢狀路徑（2）：深入子目錄列舉、中間目錄自動建立；空目錄為 ok 非錯誤。
- 錯誤不靜默（3）：無效路徑 → NotFound、對檔案 list → NotADirectory、權限 → PermissionDenied。
- stat 中繼（3）：檔 / 目錄 / 根中繼、缺失回 NotFound。
- null / 空來源（2）：空來源根為空目錄、clear 重置樹。
- DirEntry 相等性 / to_string（1）。
- 經 E2-01 provider（10）：provider 身分、可上轉 MetricProvider、註冊為實例、值=存在+類型、
  find_instance 依名、無效路徑 / 權限 / null source 仍掛空指標且 last_error 明確回報、
  消費者只走 E2-01 抽象介面、重複註冊保守拒絕。
