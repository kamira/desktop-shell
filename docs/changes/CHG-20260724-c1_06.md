# CHG-20260724-c1_06 — 實作 C1-06 Dock profile（artifact 層 / 相位 1 純邏輯組裝）

- Date: 2026-07-24 | Branch: feat/c1_06 | Risk: low | Implemented by: I1.157
- Skill: ai-sdlc-autopilot

## Motivation
C1-06「Dock profile」（程式塢 / 工作列 / dock）：固定於螢幕某一邊緣的常駐列，可（自動隱藏
時）滑到邊緣叫出，內含可新增的固定項目。這是一個**組裝型 artifact 單元**：不新增引擎邏輯，
而是把三個已合併的擴充點（E1-16 螢幕邊緣熱區、E1-01 具名圖層堆疊、E1-02 輸入策略四態）組成
單一應用 profile + 行為（dock_to_edge / auto_hide / reveal / add_item）。相位 1：純資料 /
邏輯組裝，無真實 GUI。

## Impact

### 新增 `content/profiles/c1_06/`

- `dock_profile.hpp` / `.cpp`：`namespace ds::profiles`。
  - `DockProfile`：注入式相依 `ds::kernel::LayerStack&`（E1-01），建構時另帶
    `ds::kernel::InputStrategy`（E1-02，預設 `Interactive`）。
  - 組裝入口：`dock_to_edge(DockEdge, thickness_ratio, reveal_action)` —— 先以 E1-01
    `has(layer_capability())` 閘控（NFR-03，未過不註冊熱區、不改狀態），再委派橋接層向
    E1-16 註冊該邊熱區（無效邊 / 無效厚度回對應結果，不固定），成功後指派本 dock 至 E1-01
    `SurfaceLayer::Topmost`。`undock()` 移除頂層指派、重置自動隱藏 / 可見狀態。
  - 行為：`set_auto_hide(bool)`（未固定拒絕；開啟立即 Hidden 觸發 `on_hide`，關閉立即
    Visible 觸發 `on_reveal`）/ `reveal()`（`NotDocked` / `AlreadyVisible` / `Revealed`）/
    `hide()`（未固定或已隱藏皆拒絕，不靜默重複）/ `probe_hot_zone(DockPoint,
    DockScreenExtent)`（僅「已固定 + 自動隱藏中 + 目前隱藏」才有意義；委派橋接層 E1-16
    `test()`，命中本 dock 固定邊緣即自動 `reveal()`）。
  - `add_item(id, label)`：id 重複回 `DuplicateId`（不靜默覆寫），成功觸發 `on_item_added`。
  - E1-02 組裝驗證入口：`backend_input_policy()` / `hit_result()` 直接透傳 E1-02 純函式
    `to_backend_policy` / `hit_result`（與 C1-05 慣例一致）。
  - 具名結果 / 狀態列舉：`DockVisibility`、`DockToEdgeResult`、`RevealResult`、
    `AddItemResult`，各附 `to_string()`（NFR-02）。
  - 解構安全：dtor 若仍固定則強制 `undock()`，避免 E1-01 堆疊殘留指向已銷毀物件語意的條目。

- `dock_hot_zone_bridge.hpp` / `.cpp`：內部橋接層，把 E1-16 `EdgeHotZoneRegistry` 包在
  pimpl 之後。**已知上游命名碰撞（記錄備查，非本單元 write_scope 可修復）**：E1-02
  `input_strategy.hpp` 於 `ds::kernel` 宣告 `enum class HitResult`；E1-16
  `edge_hot_zone.hpp` transitively `#include "hit_test.hpp"`（E1-04），該檔於同一命名空間
  宣告**另一個不同型別**的 `struct HitResult`。兩者標頭若同時出現在同一翻譯單元，會因
  `ds::kernel::HitResult` 同名不同型別（enum class 對 struct）編譯失敗——已於本機以 g++
  實測重現：

  ```
  error: use of 'HitResult' with tag type that does not match previous declaration
     91 | struct HitResult {
  note: previous use is here
     43 | enum class HitResult {
  ```

  這是 E1-02 與 E1-16 兩個各自獨立、各自已合併的上游擴充點之間既有的命名碰撞，在本單元
  之前未曾被任何檔案同時引入而未被發現；不可修改上游（e1_02 / e1_16 / e1_04）解決。解法：
  `dock_hot_zone_bridge.cpp` 是本單元**唯一** `#include "edge_hot_zone.hpp"` 之處，藉此把
  兩個上游 include 樹隔離到不同翻譯單元；`dock_hot_zone_bridge.hpp` 只使用
  `dock_types.hpp` 的中立值型別（不 include 任何上游標頭），故 `dock_profile.hpp` 可安全地
  同時 `#include "input_strategy.hpp"`（E1-02）與 `dock_hot_zone_bridge.hpp`。

- `dock_types.hpp`：`DockEdge`（鏡射 E1-16 `EdgeHotZone`）/ `DockPoint`（同 E1-04
  `LocalPoint` 語意）/ `DockScreenExtent`（同 E1-16 `ScreenExtent` 語意）/
  `DockHotZoneStatus`（鏡射 `HotZoneStatus`）/ `DockTriggeredZone`（鏡射
  `TriggeredHotZone`）——橋接層對外的中立值型別，`.cpp` 內一一轉換至 / 自 E1-16 對應型別。
  `is_valid_dock_edge()`（`dock_hot_zone_bridge.cpp` 內部）沿用 E1-16 `is_named_zone` 的
  窮舉 switch 慣例，攔截無效邊（如外部 `static_cast`）。

- `CMakeLists.txt`：`add_library(c1_06 STATIC dock_profile.cpp dock_hot_zone_bridge.cpp)` +
  `target_link_libraries(c1_06 PUBLIC e1_01 e1_02 e1_16)` + `test_c1_06`
  （`tests/c1/test_c1_06.cpp`）+ `add_test(NAME c1_06)`。

### 新增 `tests/c1/test_c1_06.cpp`（gtest，27 案例）

拒絕 / 無效邊 / 無效厚度 / E1-01 能力不存在拒絕）、`undock`（成功並移除頂層指派、允許重新

重複 id 拒絕且不覆寫）、E1-02 輸入策略（`Interactive` → `Accepting`/`Solid`、
`ClickThrough` → `PassThrough`/`Transparent`）、解構安全（固定中解構移除頂層指派）。

### 相位 1 約束遵循
- 純資料 / 邏輯組裝，無真實 GUI；無平台分支（無 `#ifdef` / win32 / cocoa，僅說明註解中
  引述禁用詞，與 E5-05 / C1-05 慣例一致）。
- 核心 API 無絕對座標、無數字 z-order（NFR-02）：邊一律具名 `DockEdge`，圖層一律具名
  `SurfaceLayer::Topmost`，熱區厚度 / 探測點皆比例 / 本地座標。
- 能力閘控（`dock_to_edge`）以 `layer_stack_.has(layer_capability())` 保護（NFR-03），
  先閘控後才向 E1-16 註冊熱區，避免半成品狀態（E1-16 熱區登記無移除 API）。
- 無效操作一律明確回 false / 具名結果，不靜默：重複固定、無效邊、無效厚度、能力不存在時
  固定、未固定時解除固定 / 設定自動隱藏 / 手動收合、已可見時 reveal、已隱藏時 hide、
  未固定 / 未啟用自動隱藏 / 未命中時探測熱區、重複 id 新增項目。
