# CHG-20260724-e2_14 — HTTP 取得與結構化解析（E2-14）

- Date: 2026-07-24 | Branch: feat/e2_14 | Risk: low | Implemented by: I1.36
- Skill: ai-sdlc-autopilot

## Motivation
E2-14「HTTP 取得與結構化解析」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「一個 HTTP 端點回傳的結構化資料中的某個數值欄位」
掛成一個指標，並以 **E2-02 採集頻率分級**決定「多久重新抓取一次」的節奏（網路成本高、變動慢，
歸低頻 Low）。這正是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的一個具體實例——
它**消費 E2-01 / E2-02 契約、不自造指標模型、不自造排程**。相位 1（Mac / null 期）只提供
平台中立介面 + null 傳輸 + 純解析邏輯，**不真的發網路請求**（回注入的固定回應，或「無後端」
空回應）；真實網路後端（libcurl / socket / 平台 HTTP 堆疊）留待後端相位。結構化解析為純邏輯，
可完全單元測試。

## Impact

### 新增 `modules/sysinfo/e2_14/`（module 層 / 子系統 sysinfo）
- `http_fetch.hpp` / `http_fetch.cpp`（`namespace ds::sysinfo`）：
  - `HttpResponse` struct：平台中立回應 —— `status`（0 = 無後端 / 未請求）＋ 有序 `headers`
    ＋ `body`；`is_success()`（2xx）、大小寫不敏感 `header(name)`、`ok()`/`of()`/`none()` 工廠。
  - `HttpTransport` 抽象傳輸：`get(url) → HttpResponse`（決定性）。真實網路後端於相位 2+
    實作；提供者只依賴此抽象介面（換後端不動提供者）。
  - `NullHttpTransport` null 傳輸：**不發任何真實網路請求**，可對特定 url 注入固定回應
    （`set_response`），未注入 url 回「無後端」空回應（`set_default` / `clear`）；記錄
    `request_count()` / `last_url()`（診斷用 mutable，不影響決定性）。
  - 結構化解析（**自帶輕量 JSON 解析器**，不引入 depends_on 外相依；不消費 E7-01 縮排式
    宣告格式——那要求 format_version 且非 JSON）：
    - `JsonValue`：可查詢多型節點（Null/Bool/Number(帶 is_integer)/String/Array/Object，
      Object 保序、鍵查詢 `find`/`at`/`contains`/`keys`；型別誤用 throw `std::runtime_error`
      —NFR-04 精神）。
    - `PathSeg` / `JsonPath` + `seek(root, path)`：以「欄位鍵 / 陣列索引」段走訪樹，不匹配回
      nullptr（無歧義取值）。
    - `parse_json(text) → JsonParseResult`：遞迴下降解析（object/array/string 含 `\uXXXX`
      與代理對/number 整數與浮點/true/false/null/空白）；**失敗不靜默**，回帶字元位移 + 訊息
      的 `JsonError`（NFR-04）。尾隨非空白內容視為錯誤。
  - `HttpFetchProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.http:<metric_id>"`；`register_metrics(registry)` 向 E2-01 註冊表
    掛上單一指標（id/name/unit/range 由建構指定，單一實例）。`sample()`：經注入 `HttpTransport`
    GET url →（2xx）解析 body → 依 `value_path` 取數值欄位 → 更新實例 value（number=欄位值、
    valid=已取得）與歷史環。採集前 value 為 unknown（不把 0 誤當真實讀值）。
    `register_demand(scheduler)`（消費 **E2-02**）以建議分級 `SamplingTier::Low` 登記需求，
    除頻合併沿用 E2-02、不自造排程。診斷：`last_status()` / `last_parse_ok()` / `last_error()`
    / `last_document()`。
  - 保守設計：transport 為 null、未 register、非 2xx、解析失敗、路徑不存在或非數值時
    `sample()` 皆回 false 並把 value 設 unknown（不污染歷史）、不崩；重複 id 由 E2-01 註冊表
    保守拒絕，掛上失敗時不保留參照（`sample()` 隨即 no-op）。
  - `CMakeLists.txt`：`add_library(e2_14)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_14` + `add_test(NAME e2_14)`。
- 上游相依：E2-01 統一指標介面、E2-02 採集頻率分級（皆可讀不可改）。
- **無** `#ifdef` / win32 / cocoa / socket / 真實網路呼叫（backend_guard 綠燈）。純邏輯、平台中立。

### 測試 `tests/e2/test_e2_14.cpp`（gtest，41 案例）
- `HttpResponse`（3）：2xx 判定邊界（含 status 0）；標頭大小寫不敏感查詢；`ok()` 預設 200。
- `NullHttpTransport`（4）：預設無後端；注入回應命中/未命中；`set_default`/`clear`；抽象介面可用。
- JSON 解析成功（8）：純量與型別；整數 vs 浮點 vs 指數 vs 負數；物件保序與查詢；巢狀
  陣列/物件；字串轉義；`\uXXXX` 代理對（UTF-8）；前後空白。
- JSON 解析錯誤（7）：空輸入、未結束字串、尾隨內容、缺冒號、未結束物件/陣列、非法字面/數字、
  壞轉義——皆非靜默（`ok()==false`、訊息非空）。
- `JsonValue`（2）：型別誤用 throw；深層保序相等。
- `seek`（3）：物件+陣列走訪；空路徑回根；鍵不存在/越界/型別不符回 nullptr。
- 提供者身分（2）：`provider_id`/`kSuggestedTier`；可上轉為 E2-01 `MetricProvider`。
- 註冊（1）：`add_provider` 掛上單一實例指標、id/name/unit/range；採集前 value 為 unknown。
- 注入假回應→解析欄位（3）：首採取出 JSON 數值欄位並推歷史；多採累積歷史（時序）；巢狀路徑取值。
- 非 2xx（1）：value 保持 unknown、不解析、不污染歷史。
- 解析錯誤（2）：壞 body → value unknown 且記錄可定位錯誤；路徑不存在/非數值 → unknown。
- null / 保守（4）：null 傳輸無後端、nullptr 傳輸、未 register 就 sample、重複 id 皆 no-op 不崩。
- E2-02 排程整合（2）：`register_demand` 登記 Low 級需求（有效間隔 64 tick）；排程到期驅動採集。
- 消費者範式（1）：掛件風格消費者只走 E2-01 registry / Metric 介面（含 range 正規化），全程無
  sysinfo / JsonValue 型別。
