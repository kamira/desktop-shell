# CHG-20260724-e1_02 — 輸入策略四態（E1-02）

- Unit: E1-02（輸入策略四態，platform 層 / kernel / phase 1 / null）

## Motivation

四個產品（桌面角色 / 面板 / 啟動器 / 召喚式浮層）共用同一 surface kernel，彼此差異之一
就是「這個 surface 如何參與輸入」。需要一個具名、四態的輸入處理策略，把「正常互動」
「獨占捕捉的 modal」「點擊穿透的桌布 / 裝飾層」「顯示但完全不參與輸入的擺設」四種需求
收斂成單一模型，並定義各態的命中（hit-test）與事件路由（routing）行為、狀態轉換、預設策略。

上游 E1-24 的 K3 原語 `InputPolicy` 是**三態**（`Modal` / `Accepting` / `PassThrough`）——
後端層「吃不吃輸入 / 獨不獨占」的低階旋鈕。E1-02 在其上加一層**四態產品語意**，多出的第四態
`Inert`（實心命中但吞掉輸入、不下傳）是後端三態表達不了的態；E1-02 提供對齊 / 下推函式把四態
映回 E1-24 三態，並在路由層補足後端表達不了的細節。

## 與 E1-24 既有 `InputPolicy` 的對齊（關鍵決策）

E1-24 `InputPolicy` **只定義三態**，非四態。故本單元依規格「若上游未定義四態則對齊之」，
新增獨立的四態具名列舉 `InputStrategy`，並提供 `to_backend_policy()` 對齊下推：

| E1-02 `InputStrategy`（四態） | 語意 | 命中 | → E1-24 `InputPolicy`（三態） |
|---|---|---|---|
| `Interactive` | 正常接收輸入 | Solid | `Accepting` |
| `Capture` | 獨占捕捉（modal 全域抓取） | Solid | `Modal` |
| `ClickThrough` | 點擊穿透到其下 | Transparent | `PassThrough` |
| `Inert` | 實心命中但吞掉、不下傳 | Solid | `Accepting`（＋路由層補吞掉語意） |

`Inert` 無 E1-24 對應態：取命中相符的 `Accepting` 下推，其「吞掉不處理」由 `InputStrategyController`
路由層強制（後端記憶體狀態表達不了「吃了但不做」，屬 E1-02 的加值層）。此為唯一有損對映，已具名記錄。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 四態表達 | 具名列舉 `InputStrategy`（Interactive/Capture/ClickThrough/Inert） | NFR-02：具名非數字；四態正交涵蓋四產品需求 |
| 命中 / 路由 | 純函式 `hit_result` / `route_decision`（無狀態，可獨立測） | 決策與狀態分離；後端無關 |
| 對齊 E1-24 | `to_backend_policy()` 四態 → 三態 | 建於上游 K3 之上，不改上游 |
| 管理器 | `InputStrategyController`（持 `KernelBackend&`，記憶體維護每 surface 策略 + 具名堆疊） | 相位 1 = null 記憶體狀態；跨 surface 路由需堆疊順序 |
| Capture 閘控 | 需能力 `input.capture`（經 `backend.has()`） | NFR-03：全域獨占捕捉受平台 / 權限限制；null 預設矩陣未宣告 → 保守不可用 |
| 事件路由 | 全域 Capture 前處理 → 否則自 target 向下逐層（ClickThrough 續傳 / Inert 吞 / Interactive 遞送） | 忠實模擬四態跨 surface 行為，可斷言 |
| K3 整合 | `poll_and_route()` 走 `backend.poll_input()` | 與 E1-24 K3 輸入原語銜接（null 永遠回空） |
| 預設策略 | `kDefaultStrategy = Interactive`；未設定即回預設 | 正常互動為安全預設 |
| 邊界 | 未知 / 空 surface、落出堆疊底、再次 forget 皆結構化回 false / 空遞送，絕不崩潰 | 保守、可預期 |

平台中立：無 `#ifdef` 平台分支、無真實 OS API、無 `src/kernel/backend/win32|cocoa/`，
符合相位 1（Mac / null）約束與 `backend_guard` G1b。API 無絕對座標 / 數字 z-order（NFR-02）：
surface 一律具名指涉，堆疊順序為登記序（內部，永不以數字 index 對外暴露）。
