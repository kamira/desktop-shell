# CHG-20260724-e1_01 — 具名圖層列舉與 z-order 維持（E1-01）

- Unit: E1-01（具名圖層列舉與 z-order 維持，platform 層 / 子系統 kernel / 相位 1 null / medium）
- 上游相依（可讀不可改）：E1-24 null 後端（`SurfaceLayer` 具名圖層 / `SurfaceId`）、E1-21 能力矩陣（`CapabilityMatrix` / `has()`）。

## Motivation

桌面外殼上同時存在多種角色的元件：桌布、一般視窗、召喚式浮層、常駐最上層 HUD……它們的
**堆疊順序（stacking order）**必須可預期且穩定——桌布永遠在底、最上層永遠在頂，與它們被
建立的先後無關。傳統作法用「數字 z-index」讓呼叫端指定層級，但這正是本專案 **NFR-02 明文
禁止**的：數字 z-order 讓層級語意散落各處、易衝突、且把絕對排序耦合進呼叫端。

E1-01 以**具名圖層**（named layers）取代數字層級：元件只宣告自己屬於哪個**具名圖層**，
跨層順序由**圖層語意**唯一決定，同層內才依加入序。對外 API 完全不出現數字 z-order 或絕對
座標（NFR-02）。相位 1（Mac / null 期）只交介面 + 記憶體維護，不觸碰任何真實 OS 合成器。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 具名圖層詞彙 | 沿用上游 E1-24 `SurfaceLayer`（Wallpaper / BelowNormal / Normal / Overlay / Topmost） | 不另立列舉，與 surface 模型單一詞彙；本單元建於其上 |
| 圖層列舉 | `layers_bottom_to_top()` 回由底到頂語意序 + `layer_name()` 穩定字串 | 「列舉具名圖層」單一資料來源；跨模組以具名字串指涉圖層（NFR-02） |
| 相對順序 | `LayerRelation{Below,Same,Above}` + `compare_layers()` | 圖層間相對順序以**具名關係**表達，非數字層級（NFR-02） |
| 指派 | `LayerStack::assign(id, layer)` → `LayerAssign{Ok,Moved,RejectedEmptyId,RejectedNoCapability}` | 結果具名可分辨；改派保留加入序位置；空 id 保守拒絕 |
| 堆疊維持 | `stacking_order()` 每次由「具名圖層清單 × 加入序」重新導出 | **圖層語意優先於加入序**：不儲存數字層級，跨層依語意、同層依加入序（穩定） |
| 相對查詢 | `is_above` / `is_below`（surface）、`topmost` / `bottommost` | 以具名 surface 表達相對堆疊，未指派一律保守回 false / 空 |
| 能力閘控 | 改動狀態的 `assign` / `remove` 先 `has("kernel.surface")`（NFR-03） | 能力不可用 → 結構化拒絕、不改狀態、不崩潰；未知能力沿用 E1-21 保守回 false |

**NFR-02 遵循**：對外 API 只有具名圖層與具名關係；內部語意序（`semantic_index`）為 private，
不對外當數字層級用，堆疊順序不以整數欄位儲存而是每次由具名圖層清單導出。原始碼與測試皆
無 `z_order`/`z_index = 數字`、無座標欄位賦值（已對照 E1-22 lint 規則自查通過）。
**平台中立**：無 `#ifdef` / `win32` / `cocoa` / 真實 OS API。

## 風險與回溯（medium）

- **高影響點**：堆疊順序是所有視覺元件共享的排序契約。本單元把「順序」從呼叫端可指定的數字
  收斂為**唯一由圖層語意決定**，杜絕未來各處自行塞數字 z-index 造成的排序衝突。
- **相位邊界**：相位 1 僅記憶體維護，不映射真實合成器；真實後端（相位 2+）須把具名圖層映射到
  平台實際圖層，但**呼叫端與本 API 不變**（同 E1-24 後端家族契約精神）。
- **回溯**：純新增單元，未改任何上游 / 根 CMakeLists / units.json / 共用 directory.md；
  回溯只需移除 `src/kernel/e1_01/**` 與 `tests/e1/test_e1_01.cpp`，無連帶影響。
