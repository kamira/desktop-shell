# CHG-20260724-e2_01 — 統一指標介面（E2-01）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e2_01 | Risk: medium | Implemented by: I1.12
- Skill: ai-sdlc-autopilot v1.1
- Unit: E2-01（統一指標介面，P0 / 核心 / engine 層 / 子系統 metrics / 承重 27x / 擴充點 1 契約）

## Motivation

指標是平台五個擴充點的**第一個**（docs/architecture.md §五個擴充點）。它決定「包含但
不限於任何指標」能否成立：若掛件直接相依個別感測器，每加一個指標就要改掛件——那不是
「包含但不限於 CPU/GPU/RAM…」，是「限於當初寫進去的那幾個」。

E2-01 定義統一指標契約：消費者（約 25 個 sysinfo 提供者的下游 widget）只依賴此介面，
**不依賴任何具體感測器**。新增指標 = 新增一個 `MetricProvider`，掛件一行不動。承重 27x，
API 形狀錯了整批要改，故本單元刻意「契約優先於功能」——只放六要素所需的最小穩定面。

## 設計（可覆核可改）

契約六要素（docs/architecture.md 擴充點表第 1 列）：**名稱 / 值 / 單位 / 範圍 / 歷史 / 可列舉實例**。

| 項目 | 選擇 | 理由 |
|---|---|---|
| 契約分層 | 抽象介面（`Metric`/`MetricInstance`/`MetricProvider`）+ 記憶體內實作（`InMemory*`） | 消費者只依賴抽象；相位 1 具體提供供假感測器 / 測試，真實後端上線自行實作介面，介面不變 |
| 值(value) | `MetricValue{number, optional<text>, valid}` | 主維度數值供繪圖 / 正規化 / 歷史；可選文字表述多型值（如 "82°C"/"Charging"）；`valid=false` 表未知，不把 0 誤當讀值 |
| 單位(unit) | `Metric::unit()` 回字串 | 最小；"%"/"MB/s"/""，不引入單位型別系統（過度設計） |
| 範圍(range) | `MetricRange{optional<min>, optional<max>}` + `normalized()` | 可無界；有界才可正規化到 [0,1]，讓長條 / 直方圖在不認識感測器下畫任意指標成比例 |
| 歷史(history) | `MetricHistory` 固定容量環狀，0=最舊…size-1=最新 | 滿了覆蓋最舊；供 sparkline 直接鋪繪；`capacity==0` 合法（不留歷史） |
| 可列舉實例(instances) | `Metric` 列舉 `MetricInstance`（各有 id/label/value/history） | 單值指標 1 個實例；每核心 CPU / 每顆磁碟多個。掛件綁定到「一個實例」 |
| 提供者 | `MetricProvider::register_metrics(registry)` 可掛零或多個 | 「新增指標 = 新增提供者」的機制端 |
| 註冊表 | `MetricRegistry` 註冊順序列舉、id→指標查詢；重複 id 保守拒絕 | 消費者唯一入口，決定性列舉；兩感測器爭同 id 是 bug，不靜默勝出 |
| 未知指標 | `get()` 回 nullptr、`contains()` 回 false、`unregister` 未知回 false | 保守、不擲例外，呼叫端安全 |
| 錯誤模型 | 越界 / 空歷史 `at()`/`latest()` 擲 `std::out_of_range`；`single()` 對多實例擲例外 | 明確、可測；防止把多實例指標誤當單值用 |

平台中立：無 `#ifdef`、無系統呼叫、無真實後端，符合 engine 層「換平台一行不動」約束。

## Impact

### 1. `engine/metrics/e2_01/metric.hpp`（新增）
- 值型別：`MetricValue`（aggregate + 靜態工廠 `of`/`unknown`）、`MetricRange`（aggregate + `clamp`/`normalized`/`bounded`…）、`MetricHistory`（環狀緩衝）。
- 抽象契約：`MetricInstance`（id/label/value/history）、`Metric`（id/name/unit/range/instance_count/instance + 便利 `single`/`find_instance`/`is_single`）、`MetricProvider`（provider_id/register_metrics）。
- `MetricRegistry`：`register_metric`/`unregister`/`contains`/`get`/`size`/`all`/`ids`/`add_provider`。不可複製、可移動。
- 記憶體內實作：`InMemoryMetricInstance`（`update`/`push`/`set_value`）、`InMemoryMetric`（`add_instance` 回穩定參照）。

### 2. `engine/metrics/e2_01/metric.cpp`（新增）
- 環狀歷史索引數學、範圍正規化 / 夾值、註冊表增刪查（含 unregister 後索引修正）、記憶體內實作。

### 3. `engine/metrics/e2_01/CMakeLists.txt`（新增）
- `add_library(e2_01 STATIC metric.cpp)` + `test_e2_01` executable + `add_test(NAME e2_01)`，依 BUILD.md 樣板；根 CMakeLists 以 `engine/*/*/CMakeLists.txt` glob 自動收入。

### 4. `tests/e2/test_e2_01.cpp`（新增）
- 31 個 gtest 案例：值工廠 / 多型值、範圍正規化與夾值（含無界 / 半界 / 退化區間）、
  歷史環狀行為（填充 / 覆蓋最舊 / 越界擲例外 / clear / 0 容量）、值與歷史連動、
  單值 + 多實例列舉與 `find_instance`、`add_instance` 參照穩定性、註冊 / 查詢 / 移除 /
  重複與空 id 拒絕、提供者掛載多指標、**契約穩定性**（泛型消費者只透過抽象介面走訪 +
  `static_assert` 介面抽象性 / 子型別 / 註冊表不可複製可移動）。

### 5. `docs/structure/units/e2_01.md`（新增；G4 同步）
- 每單元獨立結構註記（不動共用 `directory.md`）。

## 不含（避免越界）

- **不實作任何真實感測器**：本單元只定義契約 + 記憶體內實作。CPU/GPU/網路等具體提供者
  屬 `modules/sysinfo/`（E2 其餘單元）職責。
- **不接真實時鐘 / 取樣排程**：`update`/`push` 由呼叫端（未來的感測器或測試）驅動。
- 不引入單位換算系統、統計聚合、告警閾值等——這些是消費者或後續單元的事，塞進契約會過度綁定。
- 未動 `units.json`、根 `CMakeLists.txt`、`docs/structure/directory.md` 或任何鎖定範圍以外檔案。
