# CHG-20260724-e2_17 — 主機板感測器（溫度 / 風扇 / 電壓）（E2-17）

- Date: 2026-07-24 | Branch: feat/e2_17 | Risk: low | Implemented by: I1.69
- Skill: ai-sdlc-autopilot

## Motivation
E2-17「主機板感測器（溫度 / 風扇 / 電壓）」是 module 層（子系統 sysinfo）的一個**指標
提供者**：透過 **E2-01 統一指標介面**（擴充點 1 契約）把「主機板 / 硬體感測器指標」——
溫度(°C，多點) / 風扇轉速(RPM) / 電壓軌(V)——掛成**三個指標**，並以 **E2-02 採集頻率分級**
決定採樣節奏。每一顆感測器（某一溫度點 / 某一風扇 / 某一電壓軌）為對應指標貢獻一個**可列舉
實例（附名稱與類型）**；三類感測器各自獨立列舉、數量可在取樣間變動。這是「新增指標 =
新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 / E2-02 契約、
不自造指標模型或排程器**。相位 1（Mac / null 期）**絕不接任何真實感測器 API**（不含 SMC /
lm-sensors / IOKit / `#ifdef` / win32 / cocoa）；改為**可注入的 BoardSensorSource 抽象**
（一次 sample() 列舉全部感測器，依類型分三組）+ null / 假來源（注入固定 / 序列資料）；真實
平台後端留待相位 2。

宣告相依 E10-01（本機 IPC 訊息投遞）經查為**行程內訊息通道（佇列 + 發布訂閱），非感測器 /
裝置列舉基礎設施**，故本單元的感測器列舉自帶可注入抽象、不依賴其公開型別；CMakeLists 仍以
PRIVATE 連結 e10_01，忠實反映 units.json 宣告的相依邊。

## Impact

### 新增 `modules/sysinfo/e2_17/`（module 層 / 子系統 sysinfo）
- `board_sensors.hpp` / `board_sensors.cpp`（`namespace ds::sysinfo`）：
  - **類型輔助**（平台中立、獨立可測）：
    - `enum class SensorType { Temperature, Fan, Voltage }`：以列舉表達每顆感測器的類型。
    - `unit_for(type)`：類型 → 單位（"°C" / "RPM" / "V"）。
    - `to_string(type)`：類型 → 診斷字串（"temperature" / "fan" / "voltage"）。
  - **值模型**（平台中立）：
    - `SensorReading`：單顆感測器的一份讀值——`name` 名稱（如 "CPU" / "+12V" / "CPU Fan"，
      可空）、`value` 數值（依類型 °C / RPM / V）、`valid` 旗標（false = 此刻無讀值）；含
      `of(name, v)`（有效）/ `unknown(name)`（具名但無讀值）工廠與相等運算子。
    - `BoardSensorSample`：某時刻全部感測器的讀值快照，依類型分三組 `temperatures` /
      `fans` / `voltages`（各為 `SensorReading` 列，各類數量可在取樣間**獨立變動**）；含
      各類 count / total_count / empty / 相等運算子。
  - **感測器讀值來源**（提供者只依賴此抽象）：
    - `BoardSensorSource`（抽象 `sample()→BoardSensorSample`，列舉全部感測器；非 const，
      序列型來源取樣有副作用）。
    - `NullBoardSensorSource`：相位 1 null / 假來源——**不接真實感測器 API**，持一列注入的
      `BoardSensorSample`（可為**固定**單份或**序列**多份），`sample()` 回下一份、列盡持續回
      最後一份、空列（預設）回空快照（誠實「無感測器 / 無讀值」）；`set_fixed` /
      `set_sequence` / `push_sample` / `reset` / `clear` 注入，供測試與假感測器情境。
  - **提供者** `BoardSensorsProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.board"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**三個**
    指標：
    - `"board.temp"`（name="Board Temperature"、unit="°C"、range=`at_least(0)`——溫度下界 0、
      上不設假界）
    - `"board.fan"`（name="Board Fan Speed"、unit="RPM"、range=`at_least(0)`——轉速 >= 0）
    - `"board.voltage"`（name="Board Voltage"、unit="V"、range=`unbounded`——電壓軌可為
      負軌如 -12V，故上下皆不設界；需正規化的消費者自處理 nullopt）
    - **每顆感測器一個可列舉實例（附名稱）**：三類各自獨立列舉，實例 id 依類型前綴
      `"temp0"` / `"fan0"` / `"volt0"` /…，label 取感測器名稱、未命名則以類型前綴 + 序號補位
      （"Temp 0" / "Fan 0" / "Voltage 0"）；各實例保留歷史環（`kDefaultHistory=64`），配合
      E2-02 週期採集鋪成序列。無感測器（如 null 期預設）時三指標皆 0 實例——誠實表達。
    - `sample()`：重新讀來源、把新讀值寫入各實例（有效值推入歷史）；某類感測器數增加則
      **動態新增**實例（既有參照不失效，unique_ptr 持有），減少則多出者設未知（不污染歷史）。
      register 尚未呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Low`——主機板
      感測器變動慢、非跟手需求；建構子可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
    - `temperature_count()` / `fan_count()` / `voltage_count()` / `sensor_count()`：各類與總計
      實例數。
  - 無讀值語意：某顆感測器無讀值以 `valid==false`（未知）誠實表達，而非塞假值 0；未知不推入
    歷史。source 為 null 亦保守不崩（三指標皆 0 實例、`sample()` no-op）。
  - `CMakeLists.txt`：`add_library(e2_17)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；**PRIVATE 連宣告相依 `e10_01`**
    （不 include 其標頭、僅反映相依邊）；`test_e2_17` + `add_test(NAME e2_17)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）＋ E2-02 採集頻率分級
  （`ds::metrics::SamplingTier` / `SamplingScheduler`）＋ E10-01 本機 IPC（宣告相依，非
  感測器列舉基礎設施），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / SMC / lm-sensors / IOKit 等真實感測器 API
  （backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_17.cpp`（gtest，27 案例）
- 提供者身分（3）：`provider_id`/三個 `kXxxId`/`kXxxName`/單位穩定；可上轉為 E2-01
  `MetricProvider`；預設採集分級 = Low（可覆寫）。
- 註冊 / 列舉（3）：`add_provider` 掛上**三個**指標；每類每感測器實例（id 前綴 temp/fan/volt、
  label 取名稱）；溫度 / 風扇 / 電壓各類讀值正確；未命名感測器以 "Temp 0"/"Fan 0"/"Voltage 0"
  補位 label。
- **多感測器**（1）：每類多顆，各自一組實例、逐顆讀值正確。
- **各類數量獨立變動**（2）：增 → 動態新增實例（既有參照不失效）；減 → 多出者設未知
  （不縮減、誠實下線）。
- **無讀值誠實 invalid**（3）：某顆有讀 / 某顆無讀逐顆表達（具名但無讀值 label 仍在）；
  未知不推入歷史；有效讀值累積歷史（最舊→最新序）。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（Low 間隔 64）登記需求、推進 tick 於到期
  時呼叫 `sample()` → 歷史累積；除頻合併多消費者（最高頻者供給、撤銷後降頻）。
- **null 來源**（5）：source 為 null → 三指標 0 實例、不崩、`sample()` no-op；
  `NullBoardSensorSource` 預設空、注入後可讀；序列列盡回最後一份；固定恆回同一份 / clear 回空；
  reset 游標回起點；`sample()` 未註冊為 no-op。
- 範圍 / 負軌 / 消費者範式 / 重複註冊（4）：temp/fan `at_least(0)`（有下界無上界）、voltage
  `unbounded`（上下皆無界）；電壓負軌 -12V 誠實承載；掛件風格消費者只走 E2-01 registry /
  Metric 抽象介面；同一組 id 第二次掛上三個皆保守拒絕、不覆寫。
- 類型輔助 / 值模型單元（3）：`unit_for` / `to_string` 各類型；`SensorReading` `of`/`unknown`
  工廠與相等；`BoardSensorSample` 計數 / 相等 / empty。

## Verification
本機無 cmake，以 scratchpad 既有之最小 gtest 墊片（不進 repo；`ASSERT_*`/`EXPECT_*` 只對引數
求值一次，含 main）`g++ -std=c++17 -Wall -Wextra` 連同上游 `metric.cpp`（E2-01）與
`sampling.cpp`（E2-02）一起編譯：

```
g++ -std=c++17 -Wall -Wextra -I <shim> \
    -I modules/sysinfo/e2_17 -I engine/metrics/e2_01 -I engine/metrics/e2_02 \
    modules/sysinfo/e2_17/board_sensors.cpp \
    engine/metrics/e2_01/metric.cpp engine/metrics/e2_02/sampling.cpp \
    tests/e2/test_e2_17.cpp -o test_e2_17_local
./test_e2_17_local
→ 27/27 cases passed，零編譯警告
```

連結它；正式 CMake 以 PRIVATE 連 `e10_01` 反映相依邊。正式 gtest/CMake 依 BUILD.md 樣板寫給
CI（G3 `ctest` 會收 `add_test(NAME e2_17)`；CMakeLists `target_link_libraries(e2_17 PUBLIC
e2_01 e2_02)` + `PRIVATE e10_01`，三上游 target 由根 CMakeLists glob 收入）。
