# CHG-20260724-e11_03 — 開機自動啟動（E11-03）

- Unit: E11-03（開機自動啟動，platform 層 / 宿主 host / low / 承重 0x）

## Motivation

「登入時自動啟動」在不同平台以完全不同的機制實作（Windows 登錄檔 Run 鍵、macOS
LaunchAgent、Linux XDG autostart…），且可能因平台或權限而**根本不存在**。E1-21 能力
矩陣已將 `host.autostart` 宣告為 optional / 相位 1 預設不可用。若呼叫端未先確認能力
是否可用便直接呼叫，換平台時會安靜失敗或宣稱了不存在的成功。

E11-03 提供一個**平台中立**的開機自啟設定介面，並在相位 1（Mac / null 期）只實作
null 後端：宣告不支援、操作為 no-op、絕不假裝成功。呼叫端以 `has()` 閘控（NFR-03
精神）即可安全撰寫，未來真實後端上線時呼叫端一行不改。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 介面 | `Autostart`：`has()` / `enable()` / `disable()` / `is_enabled()` | 能力閘控 + 最小設定面；`has()` 為 NFR-03 閘控入口 |
| 結果型別 | `AutostartStatus{ Ok, Unsupported, Failed }` | 讓「未支援」與「失敗」與「成功」在型別上可分辨，呼叫端不會誤判 |
| 相位 1 後端 | `NullAutostart`：`has()==false`、變更回 `Unsupported`、`is_enabled()==false` | Mac / null 期；不觸碰任何真實系統設定 |
| 後端選派 | 工廠 `make_default_autostart()`，相位 1 回 `NullAutostart` | 真實後端上線後只改工廠，呼叫端不變 |

介面平台中立：無 `#ifdef _WIN32` / win32 / cocoa 分支，不寫登錄檔 / LaunchAgent，符合
相位 1（Mac / null）與 `backend_guard` 約束。

## Impact

### 1. `src/host/e11_03/autostart.hpp`（新增）
- `AutostartStatus`（Ok / Unsupported / Failed）。
- `Autostart` 抽象介面：`has()` / `enable()` / `disable()` / `is_enabled()`。
- `NullAutostart`（final）：相位 1 null 後端，宣告不支援、操作 no-op、狀態恆 false。
- `make_default_autostart()`：平台預設後端工廠（相位 1 回 NullAutostart）。

### 2. `src/host/e11_03/autostart.cpp`（新增）
- `make_default_autostart()` 實作：相位 1 回 `std::make_unique<NullAutostart>()`。不含平台分支。

### 3. `src/host/e11_03/CMakeLists.txt`（新增）
- `add_library(e11_03 STATIC autostart.cpp)` + `test_e11_03` executable + `add_test(NAME e11_03)`，
  依 BUILD.md 樣板；根 CMakeLists 自動 glob 收入。

### 4. `tests/e11/test_e11_03.cpp`（新增）
- 7 個 gtest 案例：has()==false、enable/disable 不宣稱成功（回 Unsupported）、is_enabled 恆 false
  且與 has() 一致、no-op 不改狀態、has() 閘控樣式、工廠回傳可用 null 後端。

### 5. `docs/structure/directory.md`（同步；G4 要求）

## 不含（避免越界）

- **不實作任何真實平台後端**（win32 登錄檔 / cocoa LaunchAgent）；相位 1 僅介面 + null 行為。
- **不實作 `has()` 閘控 lint**（NFR-03 建置期強制）—— 那是 `E1-22` 的職責。
- 未動 `units.json`、根 `CMakeLists.txt`、E1-21 能力矩陣或任何鎖定範圍以外的檔案。
