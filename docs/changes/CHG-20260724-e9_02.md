# CHG-20260724-e9_02 — manifest（含 requires/permissions）（E9-02）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e9_02 | Risk: low | Implemented by: I1.3
- Skill: ai-sdlc-autopilot v1.1
- Unit: E9-02（manifest，P0 / 核心 / engine 層 / 子系統 package / 承重 4x / primitive K10）

## Motivation

套件與模組進場時需要一份可宣告、可解析、可驗證的中繼資料，說明「我是誰、我要哪些
能力、我要哪些權限」。`docs/ai-guideline.md` §3 Q3 明確要求：manifest **具
`requires`/`permissions`**，且**格式帶版本欄位**，以便「先自用、格式預留開放」。

E9-02 提供這份 manifest 的格式定義與解析：一個帶版本欄位的資料結構 + 從文字宣告的
解析 + 相容性/必填欄位驗證。作為後續能力閘控（`requires` 對接 E1-21 能力矩陣的
`has()`）與權限審核（`permissions`）的**單一資料來源**。平台中立、純邏輯。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 格式版本 | `format_version = major.minor`（`FormatVersion`） | Q3 要求「格式帶版本」；major 管破壞性、minor 管前向擴充 |
| 相容判定 | major 相同 **且** manifest.minor ≤ 支援上限 minor | host 只能理解不高於自身 minor 的 manifest；主版不同即拒 |
| 文字格式 | 極簡 `key: value` + `#` 註解 + 逗號清單 | 自足、無外部相依（engine 層純邏輯，不引入 JSON/YAML lib） |
| 錯誤模型 | `ParseResult`（success \| ParseError{line,message}） | **可定位、不得靜默失敗**（缺 ':'、未知/重複 key、版本無法解析、缺必填、不相容皆帶因） |
| 未知欄位 | 明確報錯並定位 | 前向擴充走 format_version 次版號，不接受安靜忽略未知 key |
| `requires` 命名 | C++ 成員名 `required_capabilities`（文字 key 仍為 `requires`） | `requires` 為 C++20 保留字；成員改名避免未來提升標準時破裂，對外契約不變 |

平台中立：無 `#ifdef`、無系統呼叫、無真實後端，符合 engine 層「換平台一行不動」約束。

## Impact

### 1. `engine/package/e9_02/manifest.hpp`（新增）
- `FormatVersion`{ major, minor } + `kSupportedFormat{1,0}`；`is_format_compatible()`。
- `Manifest`{ format_version, name, version, description, required_capabilities, permissions }。
- `ParseError`{ line, message }、`ParseResult`（success/failure 互斥存取）。
- `parse_manifest(text)`：解析即驗證。

### 2. `engine/package/e9_02/manifest.cpp`（新增）
- 逐行解析：trim、`#` 註解/空行略過、首個 ':' 切 key/value、逗號清單去空白略空項。
- 版本解析嚴格 major.minor（拒 `abc` / `1.2.3`）；重複/未知 key、缺 ':'、缺必填、
  不相容全數回帶行號（或 line=0 表非特定行）的 ParseError。

### 3. `engine/package/e9_02/CMakeLists.txt`（新增）
- `add_library(e9_02 STATIC manifest.cpp)` + `test_e9_02` executable + `add_test(NAME e9_02)`，
  依 BUILD.md 樣板；根 CMakeLists 以 `engine/*/*/CMakeLists.txt` glob 自動收入。

### 4. `tests/e9/test_e9_02.cpp`（新增）
- 16 個 gtest 案例：有效 manifest 全欄位 + requires/permissions 讀出、最小 manifest、
  缺 format_version/name 報錯、主版/次版不相容偵測、相容規則邊界、版本無法解析與
  `1.2.3` 拒收、未知 key / 缺冒號 / 重複 key 定位、清單去空白略空、空清單、value 含 ':'、
  註解與空行忽略。

### 5. `docs/structure/directory.md`（同步；G4 要求）
- 末尾「已落地單元備註」補記 `engine/package/e9_02/` 一條（不動他人內容）。

## 不含（避免越界）

- **不做能力閘控/權限強制執行**：本單元只定義並解析 manifest；`requires` 如何對接
  E1-21 `has()`、`permissions` 如何審核，屬其他單元職責。
- **不引入 JSON/YAML 外部相依**；採自足的極簡文字格式。
- 未動 `units.json`、根 `CMakeLists.txt` 或任何鎖定範圍以外的檔案。
