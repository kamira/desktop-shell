# CHG-20260723-03 — 真正修補 workflow 分支反查步驟並補上 plan.py unit-for-branch

- Date: 2026-07-23 (UTC+0) | Branch: claude/ai-sdlc-handshake-validation-380ada | Risk: low | Implemented by: I1
- Skill: ai-sdlc v1.17

## Motivation
CHG-20260723-02 宣稱已修正分支反查步驟並附自驗證據，但實際工作樹中：
- `.github/workflows/governance.yml` 仍含 `UID=$(...)`（bash 唯讀變數，在 `-eo pipefail` 下第一步即 exit 1，所有 PR 卡在反查步驟，無法進入任何閘門）
- `scripts/plan.py` 並無 `unit-for-branch` 子命令
亦即該 CHG 的驗收證據是虛假的，修補從未落地。本 CHG 真正落實。

## Impact
- `scripts/plan.py`：新增 `unit-for-branch <REF>` 子命令。接受 `feat/<slug>` 或 `refs/heads/feat/<slug>`，以 `id.lower().replace('-','_')==slug` 反查，輸出三行 `id=`/`risk=`/`phase=` 供 CI 追加至 `$GITHUB_OUTPUT`；反查不到→stderr `::error::` 並 exit 1（CI 步驟即紅燈，行為與原步驟一致）。既有 `status`/`next`/`brief`/`gate` 未動。
- `.github/workflows/governance.yml`：branch-lookup 步驟改為 `python scripts/plan.py unit-for-branch "$GITHUB_HEAD_REF" >> "$GITHUB_OUTPUT"`，移除唯讀變數 `UID` 賦值。下游 `steps.unit.outputs.id` / `steps.unit.outputs.risk` 仍照常產生。

## Status
Accepted — self-verified (low risk)：
- `python3 scripts/plan.py unit-for-branch feat/e2_01` → `id=E2-01` / `risk=medium` / `phase=1`（exit 0）
- `python3 scripts/plan.py unit-for-branch refs/heads/feat/e2_01` → 同上（相容全 ref）
- `python3 scripts/plan.py unit-for-branch feat/nonexistent` → `::error::` 且 exit 1
- `ruby -ryaml -e "YAML.load_file('.github/workflows/governance.yml')"` → YAML OK
