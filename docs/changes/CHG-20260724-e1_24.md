# CHG-20260724-e1_24 — null 後端參考實作（E1-24）

- depends_on: E1-21（能力矩陣）

## Motivation

相位 1（Mac / 平台中立期）唯一允許的 kernel 平台後端是 **null 後端**。四個產品共用同一個
surface kernel，對「系統」的操作（視窗 surface、繪製、輸入）需要一個抽象出口，讓上層邏輯
與真實平台完全解耦。E1-24 提供這個出口的兩件事：

1. `KernelBackend` —— kernel 平台後端的抽象介面（後端家族的共同契約）。
2. `NullKernelBackend` —— 相位 1 的參考實作：所有平台操作為 no-op 或以記憶體狀態承接，
   **任何平台皆可編譯執行**（不含任何真實 OS 呼叫），作為相位 1 的預設後端、契約測試組
   （E1-25）的靶、與其他後端（相位 2+ 的 win32 / cocoa）的行為基準。

由於 E1-24 的上游僅 E1-21，且相位 1 尚無獨立的「後端介面」單元被合併，介面與 null 實作
依相位 1 慣例（參見 host 層 `TrayBackend` / `NullTrayBackend`：介面 + null 實作同檔共存）
一併落在本單元的鎖定範圍 `src/kernel/backend/null/`。真實後端上線後實作同一 `KernelBackend`
即可，呼叫端一行不改。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 後端契約 | 抽象基底類別 `KernelBackend`（純虛擬） | 後端可替換；契約測試（E1-25）僅依賴介面 |
| 三組原語 | K1 surface kernel（視窗）/ K2 繪製（paint）/ K3 輸入（input） | 對應單元 primitives K1/K2/K3 與架構的視窗 + 繪製 + 輸入子系統 |
| surface 指涉 | 具名 `SurfaceId`（字串） | NFR-02：不以數字 handle / index / 座標指涉 |
| 四參數 profile | `SurfaceProfile`{ layer, input, hit, lifecycle } 皆具名列舉 | surface kernel 的核心洞見：四產品差異 = 四參數取值；具名取代數字 z-order（NFR-02） |
| 能力回報 | 持有 E1-21 `CapabilityMatrix`；`has()` 委派之 | 能力宣告單一資料來源；未知能力保守回 false（NFR-03） |
| null 能力集 | 預設即 `CapabilityMatrix::defaults()`（保守）；建構子可注入自訂矩陣 | 基礎能力可用、可選能力一律不可用；可供測試 / 未來後端覆用 |
| null 行為 | no-op / 記憶體狀態；記錄呼叫計數與 surface 表 | 契約測試可斷言「狀態一致」，且任何平台可跑 |
| 邊界情形 | 未知 / 空 / 重複 id 皆結構化回 false，絕不崩潰 | 保守、可預期，作為其他後端的行為基準 |

介面平台中立：無 `#ifdef` 平台分支、無真實 OS 視窗 API（NSWindow / CreateWindowEx…）、
無 `src/kernel/backend/win32|cocoa/`，符合相位 1（Mac / null）約束與 `backend_guard` G1b。

## Impact（medium 風險 — 詳列影響面）

### 1. `src/kernel/backend/null/null_backend.hpp`（新增）
- 平台中立型別：`SurfaceId`（具名字串別名）、具名列舉 `SurfaceLayer` / `InputPolicy` /
  `HitPolicy` / `SurfaceLifecycle`、四參數 `SurfaceProfile`、`InputEventType` / `InputEvent`。
- `KernelBackend`（抽象介面）：`name()`；生命週期 `init()` / `shutdown()` / `is_initialized()`；
  能力 `capabilities()` / `has()`；K1 `create_surface` / `destroy_surface` / `has_surface` /
  `show_surface` / `hide_surface` / `is_visible` / `surface_profile` / `surface_count`；
  K2 `begin_frame` / `end_frame`；K3 `set_input_policy` / `poll_input`。
- `NullKernelBackend`（final 實作）：建構子接受可注入的 `CapabilityMatrix`（預設 defaults()）；
  記憶體 surface 表 + 呼叫計數；測試輔助查詢 `completed_frames` / `in_frame` / `*_calls`。

### 2. `src/kernel/backend/null/null_backend.cpp`（新增）
- `NullKernelBackend` 全部方法定義。全部 no-op / 記憶體語意：
  - 生命週期：`init()` 冪等回 true；`shutdown()` 清空 surface、回未初始化、冪等。
  - K1：具名鍵線性表；空 / 重複 id 拒絕；未知 id 一律 false / nullptr（保守）。
  - K2：`begin_frame` 不可重入（已在 frame 中拒絕）；`end_frame` 需先 begin；配對計 frame 數。
  - K3：`set_input_policy` 更新 profile；`poll_input` 永遠回空並計數。
- 無任何平台分支或真實 OS API；任何平台可編譯執行。

### 3. `src/kernel/backend/null/CMakeLists.txt`（新增）
- `add_library(backend_null STATIC null_backend.cpp)` + `target_link_libraries(backend_null PUBLIC e1_21)`。
- `test_backend_null` executable（`tests/e1/test_backend_null.cpp`）+ `add_test(NAME backend_null)`。
- 根 CMakeLists 以深度 3 GLOB（`src/*/*/*/CMakeLists.txt`）自動收入。

### 4. `tests/e1/test_backend_null.cpp`（新增）
- 14 個 gtest 案例：後端身分、init/shutdown 生命週期（冪等 + 釋放 surface）、能力經 E1-21
  查詢（基礎可用 / 可選不可用 / 未知保守 false）、自訂能力矩陣注入、surface 建立與重複/空 id
  拒絕、四參數 profile 忠實保存、顯示隱藏、銷毀、繪製 frame 生命週期（不可重入 begin / 未
  begin 之 end / 計數）、set_input_policy、poll_input 永遠空、經 `KernelBackend*` 基底指標多型
  操作整組介面、預設 profile 值合理。

### 5. `docs/structure/units/e1_24.md`（新增；G4 同步）
- 本單元獨立結構註記（不動共用 `directory.md`）。
