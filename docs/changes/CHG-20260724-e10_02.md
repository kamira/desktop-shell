# CHG-20260724-e10_02 — 低延遲同機通道（E10-02）

- Date: 2026-07-24 | Branch: feat/e10_02 | Risk: low | Implemented by: I1.75
- Skill: ai-sdlc-autopilot
- Unit: E10-02（低延遲同機通道，engine 層 / ipc / low）
- 相依：E10-01 本機 IPC 訊息通道（已合併，可讀不可改）——沿用其 `Message`（酬載重用 E6-01 `CommandArgs`）。

## Motivation

E10-01 提供中立的訊息投遞語意（FIFO 佇列 + 發布訂閱）。同機（本機行程內 / 跨行程）情境還需要
**低延遲**的點對點與請求-回應通道：延遲敏感訊息要能插隊、緩衝要有界以免無限堆積、滿載時要有明確
且不阻塞的處置、並能批次攤提每則固定成本。若一開始就綁死 shared memory / socket / mmap，這些語意
會被平台傳輸細節污染，且無法以單元測試驗證。

E10-02 於相位 1 採「記憶體內佇列 + 可注入邏輯時脈」——只實現低延遲*語意*（優先、背壓、批次、
延遲量測），不綁任何真實 IPC。延遲以**邏輯 tick** 量測（非 wall-clock），可決定性測試。等真實傳輸層
（相位 2）到位時，本契約即為其上的低延遲通道抽象：傳輸換掉、優先 / 背壓 / 延遲語意不動。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 傳輸單元 | `Envelope` = E10-01 `Message` + priority + enqueued_tick + seq | 沿用上游訊息，直接承載 E6-01 具名命令；全程 std::move（零拷貝語意） |
| 優先佇列 | 三帶 `std::array<std::deque<Envelope>, 3>`（High/Normal/Low） | 高優先先出、同優先級 FIFO；出列 O(帶數)，決定性 |
| 背壓 | 有界容量（`capacity==0` = 無界）+ `BackpressurePolicy` | 滿載時明確處置，永不阻塞、不崩潰 |
| 策略 Reject | 滿載拒收新訊息回 `RejectedFull`，既有不動 | 純背壓訊號，呼叫端自行退讓 |
| 策略 DropOldestLowPriority | 汰換「優先級 <= 新訊息」帶中最低帶之最舊一則；全高於新訊息則改拒收 | 保新鮮、保護高優先，決定性可測 |
| 批次 | `send_batch` / `receive_batch(max)` | 攤提每則固定成本（批次為低延遲常見手段）；背壓下部分接受 |
| 請求-回應 | `request_response(req, responder)→optional<Message>` | 快速同機 RPC 抽象；空回應器回 nullopt |
| 延遲量測 | 可注入 `LogicalClock`（tick）；出列時 `now - enqueued_tick` | 平台中立、可決定性；last/max/total/average 統計 |
| 可注入時脈 | 建構傳 `LogicalClock*`；nullptr → 內部自有時脈 | 注入可選，未注入亦可用 |
| 契約版本 | `low_latency_contract_version()` = "e10_02/1.0.0" | 承重抽象；前綴避免與 E10-01 `contract_version()` 撞名（同 `ds::ipc`） |

介面平台中立：無 `#ifdef _WIN32` / `cocoa` / `__APPLE__` 平台分支、不綁 shared memory / socket / mmap / 任何真實 IPC。
