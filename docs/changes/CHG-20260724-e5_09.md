# CHG-20260724-e5_09 — 機率排程器（E5-09）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e5_09 | Risk: low | Implemented by: I1.32
- Skill: ai-sdlc-autopilot v1.1
- Unit: E5-09（機率排程器，engine 層 / 子系統 events / low）
- 相依：E5-04 心跳（已合併）

## Motivation

桌面角色需要「隨機行為」——例如隨機閒置動作（眨眼、伸懶腰、換姿勢），這些動作不應每拍必觸發，
而應在時間流逝中偶發地發生。因此需要一個「以機率在時間推進中觸發事件」的排程器。

engine 層要求平台中立純邏輯：時間以邏輯時間（tick）計、由呼叫端注入，且**不得依賴全域 `rand()`**——
否則測試無法決定性重現「哪一拍觸發、觸發幾次」。E5-09 把時間推進委派給已合併的 E5-04 `HeartbeatSource`，
把亂數抽象成一個**可注入 / 可替換**的 `RandomSource`，使整個觸發序列在固定種子下完全決定性、可於單元測試重現。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 亂數抽象 | `RandomSource::next_unit()` 回 [0,1)；預設 `SeededRandomSource`（SplitMix64） | 可注入種子 / 假來源；不用全域 rand，決定性可重現、跨平台同序列 |
| 時間推進 | 委派 E5-04 `HeartbeatSource`（每任務掛一心跳訂閱作為「評估機會」） | 復用已合併心跳的邏輯時間與間隔語意；`PUBLIC` 相依 e5_04 |
| 排程 | `schedule(interval, probability, cb)`：每 interval 評估一次 | interval 決定評估節奏，probability 決定每次評估的觸發機率 |
| 觸發判定 | 每次評估**固定抽一個亂數** u∈[0,1)，`u < probability` 即觸發 | 抽值次序穩定 → 決定性；p=0 永不觸發、p>=1 每次必觸發，無需特例 |
| 無效輸入 | `interval==0` 不建立回 0；probability 夾至 [0,1]（NaN 夾成 0） | 越界 / 無效輸入永遠安全 |
| 取消 | `cancel(id)` 移除任務並退訂心跳；回呼中取消安全（心跳兩階段派發保證） | 未知 id 回 false |
| 事件 | `ScheduledEvent`{ id, interval, probability, now, eval_count, fire_count } | 供消費者 / 測試斷言觸發時機與累計次數 |
| 內省 | `advance` 回傳本次總觸發數、`now()` / `task_count()` / `set_random_source()` | 供測試斷言與執行期替換亂數來源 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支、不綁真實時鐘或 OS 熵源。
