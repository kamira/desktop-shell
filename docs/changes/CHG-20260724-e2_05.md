# CHG-20260724-e2_05 — GPU 使用率 / VRAM / 溫度（E2-05）

- Date: 2026-07-24 | Branch: feat/e2_05 | Risk: low | Implemented by: I1.57
- Skill: ai-sdlc-autopilot

## Motivation
E2-05「GPU 使用率 / VRAM / 溫度」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「GPU 指標」——使用率(%)、VRAM 用量（已用/總量
bytes，主維度為 %）、溫度(°C)——掛成**三個指標**，並以 **E2-02 採集頻率分級**決定採樣節奏。
支援**多 GPU**：每張 GPU 為每個指標貢獻一個可列舉實例（gpu0 / gpu1 / …）。這是「新增指標 =
新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 / E2-02 契約、
不自造指標模型或排程器**。本單元是最終「CPU / GPU Usage Widget」的 **GPU 資料源**，故介面
刻意乾淨、易組合。相位 1（Mac / null 期）**絕不接任何真實 GPU API**（不含 Metal / IOKit /
nvml / `#ifdef` / win32 / cocoa）；改為**可注入的 GpuStatSource 抽象**（一次 sample() 列舉
所有 GPU，每張給 usage/vram/temp）+ null / 假來源（注入固定 / 序列資料）；真實平台後端留待
相位 2。

## Impact

### 新增 `modules/sysinfo/e2_05/`（module 層 / 子系統 sysinfo）
- `gpu_stats.hpp` / `gpu_stats.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `GpuStat`：單張 GPU 的一份讀值——`usage` 使用率比率 [0,1]、`vram_used`/`vram_total`
      bytes、`temperature` °C，三組**各帶獨立 valid 旗標**（`usage_valid`/`vram_valid`/
      `temp_valid`），真實硬體常有「使用率可讀但溫度感測缺」之類情形，故逐欄誠實表達；含
      `unknown()`（整張未知）/ `of()`（一次給齊）工廠與相等運算子。
    - `GpuStatSample`：某時刻全部 GPU 的讀值快照（`gpus` 每張一筆；GPU 數可在取樣間變動）。
  - **自由函式**（獨立可測、純算術 / 格式化）：
    - `vram_ratio(used, total)`：VRAM 使用率 = used / total，夾到 [0,1]。防護：total==0
      （無從判斷）→ 0（不謊報）、used>total（理論不該發生）→ 夾到 1.0。
    - `humanize_bytes(bytes)`：bytes → 人類可讀（"8.0 GiB" / "512 MiB" / "4096 B"，一位小數，
      不依賴 `<sstream>` / locale），供 VRAM 實例值的 text 顯示。
  - **GPU 讀值來源**（提供者只依賴此抽象）：
    - `GpuStatSource`（抽象 `sample()→GpuStatSample`，列舉所有 GPU；非 const，序列型來源
      取樣有副作用）。
    - `NullGpuStatSource`：相位 1 null / 假來源——**不接真實 GPU API**，持一列注入的
      `GpuStatSample`（可為**固定**單份或**序列**多份），`sample()` 回下一份、列盡持續回
      最後一份、空列（預設）回空快照（誠實「無 GPU / 無讀值」）；`set_fixed` / `set_gpus` /
      `set_sequence` / `push_sample` / `reset` / `clear` 注入，供測試與假感測器情境。
  - **提供者** `GpuStatsProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.gpu"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**三個**
    指標：
    - `"gpu.usage"`（name="GPU Usage"、unit="%"、range=`bounded(0,100)`）
    - `"gpu.vram"`（name="GPU VRAM"、unit="%"、range=`bounded(0,100)`；主維度為使用率 %
      可正規化供長條 / 直方圖，已用/總量 bytes 置於實例值的 text 供顯示）
    - `"gpu.temp"`（name="GPU Temperature"、unit="°C"、range=`at_least(0)`——溫度下界 0、
      上不設假界，寧缺勿濫；需正規化的消費者自處理 nullopt）
    - **每張 GPU 一組可列舉實例**：三指標共用同一 GPU 列舉，實例 `"gpu0"`/`"gpu1"`/…
      (label "GPU 0"/…) 依取樣 GPU 數建立，各實例保留歷史環（`kDefaultHistory=64`），配合
      E2-02 週期採集鋪成序列。無 GPU（如 null 期預設）時三指標皆 0 實例——誠實表達。
    - `sample()`：重新讀來源、把新讀值寫入各實例（usage/vram 比率*100 成 %、溫度直接寫、
      有效值推入歷史）；GPU 數增加則**動態新增**實例（既有參照不失效，unique_ptr 持有），
      減少則多出者三欄設未知（不污染歷史）。register 尚未呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Normal`，建構子
      可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
    - `gpu_count()`：目前的 GPU 實例數。
  - 無讀值語意：某欄無讀值（含 VRAM 總量 0——百分比無從計算）以 `valid==false`（未知）
    誠實表達，而非塞假值 0。source 為 null 亦保守不崩（三指標皆 0 實例、`sample()` no-op）。
  - `CMakeLists.txt`：`add_library(e2_05)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_05` + `add_test(NAME e2_05)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）＋ E2-02 採集頻率分級
  （`ds::metrics::SamplingTier` / `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / Metal / IOKit / nvml 等真實 GPU API（backend_guard 綠燈）。
  純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_05.cpp`（gtest，27 案例）
- 提供者身分（3）：`provider_id`/三個 `kXxxId`/`kXxxName`/單位穩定；可上轉為 E2-01
  `MetricProvider`；預設採集分級 = Normal（可覆寫）。
- 註冊 / 列舉（2）：`add_provider` 掛上**三個**指標；每 GPU 實例（id "gpu0"/label "GPU 0"）；
  使用率 / VRAM / 溫度各欄位讀值正確（含 VRAM % 與已用/總量文字 "4.0 GiB / 8.0 GiB"）。
- **多 GPU**（1）：每張 GPU 為各指標貢獻一實例，逐張讀值正確。
- **0% / 100% 邊界**（2）：經提供者 usage/vram 0% 與 100%；`vram_ratio` 自由函式邊界。
- **GPU 數變動**（2）：增 → 動態新增實例（既有參照不失效）；減 → 多出者三指標皆設未知
  （不縮減、誠實下線）。
- **無讀值誠實 invalid**（3）：逐欄 valid（usage 有讀 / vram / temp 無讀）；VRAM 總量 0 視為
  未知（不謊報 0）；未知不推入歷史（不污染序列）。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（Normal 間隔 8）登記需求、推進 tick 於
  到期時呼叫 `sample()` → 歷史累積；除頻合併多消費者（最高頻者供給、撤銷後降頻）。
- **null 來源**（5）：source 為 null → 三指標 0 實例、不崩、`sample()` no-op；`NullGpuStatSource`
  預設空、注入後可讀；序列列盡回最後一份；固定恆回同一份 / clear 回空；序列驅動提供者跨採樣
  前進；`sample()` 未註冊為 no-op。
- 範圍 / 消費者範式 / 重複註冊（3）：usage/vram `bounded[0,100]`（50% 正規化 0.5）、temp
  `at_least(0)`（有下界無上界）；掛件風格消費者只走 E2-01 registry / Metric 抽象介面；同一組
  id 第二次掛上三個皆保守拒絕、不覆寫。
- 自由函式 / 值模型單元（4）：`humanize_bytes` 各級距（B/KiB/MiB/GiB、一位小數）；`GpuStat`
  `unknown`/`of` 工廠與相等；`GpuStatSample` 相等 / 計數 / empty。
