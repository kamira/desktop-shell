# CHG-20260724-e2_21 — 使用者文字輸入值（E2-21）

- Date: 2026-07-24 | Branch: feat/e2_21 | Risk: low | Implemented by: I1.150
- Skill: ai-sdlc-autopilot

## Motivation
E2-21「使用者文字輸入值」是 module 層（子系統 sysinfo）的一個**指標提供者**：把使用者在
**E4-15 就地輸入框**（`TextInputElement`）目前輸入的文字，透過 **E2-01 統一指標介面**
暴露為指標——讓 widget 能把使用者輸入（如搜尋框內容、參數輸入）當成一個資料源讀取，
而不必各自認得 `TextInputElement` 這個具體型別。這是「新增指標 = 新增 `MetricProvider`、
掛件一行不動」機制的又一個具體提供者，且**本單元是 provider（讀值），非致動器**——只讀
輸入框目前的文字，不寫回、不模擬按鍵，編輯本身完全是 E4-15 的職責。

## Impact

### 新增 `modules/sysinfo/e2_21/`（module 層 / 子系統 sysinfo）
- `user_text_input.hpp` / `user_text_input.cpp`（`namespace ds::sysinfo`）：
  - `UserTextInputProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.user_text_input"`；`register_metrics(registry)` 向 E2-01
    註冊表掛上單一指標 `"input.text"`（name="User Text Input"、unit=""、
    range=`unbounded()`）。
  - `bind(key, label, element)`：把一個 E4-15 `TextInputElement`（**不取得所有權**）以穩定
    key 綁定；**每個已綁定輸入框 = 一個可列舉 `MetricInstance`**（instance_id=key、
    label=顯示名、value.text=目前文字、value.number 恆為 0.0——與 E2-12 純文字欄位同慣例；
    history_capacity=0，因目前值無時序意義）。重複 key 覆寫既有綁定（保守：以最後一次
    bind 為準）。若指標已建立，`bind` 會立即建立/更新對應實例並讀入目前文字；否則延後到
    下次 `register_metrics()` 一併建立。
  - `unbind(key)`：解除綁定；既有實例保留（供既有參照穩定走訪）但值設為
    `MetricValue::unknown()`，且不再隨 `refresh()` 更新。
  - `refresh()`：**pull 模型**——重新讀所有目前仍綁定的輸入框之目前文字、寫入對應實例
    （不推歷史）。呼叫端在判定「該讀新值」時呼叫（如 widget 重繪前），與 E2-19
    `ProcessMonitorProvider::sample()` / E2-15 `AudioLevelProvider::sample()` 的
    「register_metrics 建初值、專門方法重讀更新」節奏一致。`register_metrics()` 尚未呼叫
    時為 no-op。
  - **空值 / 無輸入框的誠實處理**：從未 `bind()` 過任何輸入框 → 指標仍掛上但
    `instance_count()==0`（保守而不崩，同 E2-12 null source）；已綁定輸入框目前文字為
    `""` → 對應實例存在、`value.valid==true`、`value.text==""`（誠實表達「使用者目前
    尚未輸入」，**不**等同「無讀值」，與「無輸入框」明確區分）。
  - `CMakeLists.txt`：`add_library(e2_21)` **PUBLIC 連上游 `e2_01` + `e4_15`**（標頭同時
    include `metric.hpp` 與 `text_input_element.hpp`，須傳遞兩者 include 目錄）；
    `test_e2_21` + `add_test(NAME e2_21)`。
- 上游相依（可讀不可改）：E2-01 統一指標介面（`ds::metrics::MetricProvider` /
  `MetricRegistry` / `InMemoryMetric` / `InMemoryMetricInstance`）、E4-15 就地輸入框
  （`ds::elements::TextInputElement::text()`）。
- **無** `#ifdef` / win32 / cocoa / 任何真實輸入裝置（backend_guard 綠燈）。純邏輯、
  平台中立；不驅動 `TextInputElement` 的編輯，只讀其 `text()`。

### 測試 `tests/e2/test_e2_21.cpp`（gtest，14 案例）
- 提供者身分（2）：`provider_id`/`kMetricId`/`kMetricName` 穩定；可上轉為 E2-01
  `MetricProvider`（以 provider 介面）。
- 無輸入框（1）：指標仍掛上但 `instance_count()==0`，不崩。
- 讀輸入框文字經 E2-01 暴露（1）：單一輸入框綁定後，文字經 registry/Metric 抽象介面讀得
  （含 `find_instance`）。
- 空值誠實處理（1）：輸入框目前文字為 `""` → `valid==true`、`text==""`，非 unknown。
- 多輸入框（1）：三個輸入框依綁定順序列舉、欄位數=實例數。
- 輸入變更更新（2）：`refresh()` 前指標維持舊值（pull 模型）、`refresh()` 後如實反映新值
  （含改為空字串）；`register_metrics` 前 `refresh()` 為 no-op。
- unbind（2）：既有實例設為 unknown 且不再隨 refresh 更新；rebind 後恢復更新；
  unbind 不存在的 key 為 no-op。
- 無時序歷史（1）：history_capacity==0。
- 範圍（1）：`unbounded`。
- 消費者範式（1）：掛件風格消費者只走 E2-01 registry / Metric 介面，全程無 sysinfo 型別。
- 重複註冊（1）：同 id 第二次掛上被保守拒絕、不覆寫既有。
