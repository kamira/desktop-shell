# CHG-20260724-e4_08 — 圖層合成（E4-08）

- Date: 2026-07-24 | Branch: feat/e4_08 | Risk: low | Implemented by: I1.129
- Skill: ai-sdlc-autopilot v1.1
- Unit: E4-08（圖層合成，engine 層 / render / phase 1 / low，depends_on=[E4-02, E4-06]）

## Motivation

多個圖片元件（E4-02）各自綁定不同具名 surface 後，仍需要一個平台中立的方式描述「這些
surface 該依什麼順序、用什麼混合模式、多少透明度疊在一起」，才能交給後續相位的繪製層
做真正的像素合成。若呼叫端各自用數字陣列索引 / 手刻的 if-else 決定疊放順序，換平台、
換場景都要重寫，也容易違反 NFR-02（禁止數字 z-order 對外暴露）。

E4-08 提供 `LayerCompositor`：依**具名圖層順序**加入 / 移除圖層（每層一個混合模式 +
透明度），並以上游 E4-06 `SurfaceSwitcher` 做圖層 surface 的定址存在性檢查，產出一份
`compose()` 合成計畫描述。本單元**不做真實像素合成**——那是後續相位的職責，本單元只
產出「該怎麼合成」的描述。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 圖層識別 | 沿用上游 `ds::kernel::SurfaceId`（字串），經 `surface_switcher.hpp` 傳遞 | 不重造一套 id 型別；與 E4-02/E4-06 既有具名 surface 慣例一致，滿足 NFR-02 |
| 上游相依 | `target_link_libraries(e4_08 PUBLIC e4_02 e4_06)` | 依規格指定；`e4_06` 提供 `SurfaceSwitcher` 定址存在性檢查，`e4_02` 的 include 鏈提供 `SurfaceId` |
| 加入前定址檢查 | `add_layer` 呼叫 `switcher.has(id)`，未註冊回 `NotFound` | 「以 E4-06 定址」的具體落地：合成計畫只描述已知的具名 surface，不重造一套存在性判斷 |
| 圖層順序 | 加入順序即層序（`vector` 尾端 append）；調順序＝移除後依新順序重新加入 | 具名順序，非數字 z-order；沒有「設定第 N 層」這種數字操作，滿足 NFR-02 |
| 混合模式 | 具名列舉 `BlendMode`（Normal/Multiply/Screen/Overlay），`add_layer` 防禦性檢查是否為已知列舉值 | 非數字係數；即使呼叫端以 `static_cast` 硬塞非法值也不靜默接受，回 `Invalid` |
| 每層透明度 | `float opacity` [0,1]，非有限值拒絕、範圍外自動 clamp | 與 E4-02 `set_opacity` 同精神：明確拒絕非法輸入，不靜默改值 |
| 重複加入同一 surface | 拒絕、回 `Invalid`，不覆蓋 | 避免同一 surface 的圖層順序產生歧義；與 E4-06 `register_surface` 拒絕重複註冊同精神 |
| 未知 id 的兩種錯誤 | `add_layer`：surface 未經定址存在 → `NotFound`；`remove_layer`：本合成器內未知圖層 → `NotFound`；空 id / 非法輸入 → `Invalid` | 精確區分「格式不合法」與「查無此 id」，與 E4-06 `SwitchStatus` 慣例一致 |
| `compose()` 語意 | 純查詢，直接回傳目前圖層清單複本；驗證全部在 `add_layer`/`remove_layer` 完成 | 與 `SurfaceSwitcher::list()`、`ImageElement::render_model()` 同慣例：查詢不做驗證，驗證在寫入路徑 |

介面平台中立：純記憶體邏輯 + 描述產出，無 `#ifdef _WIN32` 等平台分支、不含任何真實繪圖 /
OS API、不做真實像素合成。

## 不含（避免越界）

- 不做真實像素合成 / 繪圖，不觸碰任何 OS 或繪圖 API（那是後續相位繪製層的職責）。
