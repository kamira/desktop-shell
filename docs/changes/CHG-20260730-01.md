# CHG-20260730-01 — governance 閘門支援 infra/bootstrap 分支跑 G3 建置

- Date: 2026-07-30 (UTC+0) | Branch: chore/gate-infra-g3 | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
全部 176 工作單元已合併。接下來的 infra/bootstrap 變更（尤其**全庫目錄扁平化重構** CHG-20260730-02，會動整個建置結構）最需要驗證的是「**還能不能建置**」——即 G3（`cmake` + `ctest`）。

但現行 `governance.yml` 的第一步 `plan.py unit-for-branch` 對非 `feat/<slug>` 分支 `exit 1`，導致 **infra 分支的 gate 在 branch-lookup 就紅燈、後續 G3 建置根本跑不到**。歷來 infra CHG（CHG-17~24）皆因此以 `gh pr merge --admin` 繞過閘門併入——等於這些改動**從未經 CI 建置驗證**。對「純文字/單行 workflow」尚可接受，但對「動整個建置結構的全庫重構」風險過高：本機無 cmake（僅 g++），若 CI 也不跑 G3，重構將**無任何真正的建置綠燈**即合併。

本 CHG 讓 infra/bootstrap 分支也能跑 repo 級閘門（含 G3 建置），僅跳過**不適用**的 unit 專屬閘。

## Impact（`.github/workflows/governance.yml`）
1. `unit` 步驟：依分支名分流。
   - `feat/*` → 照舊 `plan.py unit-for-branch`，並設 `is_unit=true`。
   - 其餘（`chore/`、`fix/` 等）→ 不呼叫 lookup（不再 exit 1），設 `is_unit=false` + `id=`（空）+ `risk=low`，並 `::notice` 標示以 infra 處理。
2. **unit 專屬閘**改為 `if: is_unit == 'true'` 才跑：
   - G1 scope_check（infra 本就跨範圍，範圍鎖不適用）
   - G5 ACC + identity（無對應單元、無 ACC）
   - G6 halt gate（無對應單元）
   - 「單元 AUTO 合併」「HALT 標記」兩步同樣限 `is_unit == 'true'`
3. **repo 級閘門維持恆跑**（不分 unit/infra）：
   - G1b backend_guard（相位後端白名單，掃全庫——infra 也該守）
   - G1c stage_check（階段相依）
   - G2 CHG linked（PR 內文須含 `CHG-`）
   - **G3 tests（cmake + ctest）** ← 本 CHG 的核心目的：infra 也跑
   - G4 structure sync（動 src/engine/modules 就要動 docs/structure/）
4. 新增「**infra AUTO 合併**」步驟：`if: success() && is_unit == 'false'`——infra 分支前述閘門全綠（含 G3）即 `gh pr merge --auto --squash --delete-branch`。屬 low 自主，無 halt 契約。

## 明確不改
- 未改任何閘門的**判定邏輯**（scope_check.py / backend_guard.py / stage_check.py / halt_gate.py / plan.py 全未動）。
- 未改 G3 的建置指令（`cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug` + `cmake --build build -j 2` + 真空綠燈防線 + `ctest --output-on-failure`）逐字保留。
- 未改 `permissions`、未改 feat/ 單元的既有流程（feat 分支行為與合併前完全一致）。
- 未改 units.json、未動任何單元原始碼。

## 安全性論證
- infra 分支跳過 G1 scope：合理——infra 變更（root CMake、workflow、全庫重構）本質跨多單元範圍，per-unit 範圍鎖不適用；改由 CHG 影響分析 + G3/G4 + 人審把關。
- infra 分支仍過 G1b/G1c/G2/G3/G4：後端白名單、階段相依、CHG 連結、**實際建置+測試**、結構同步皆照守。
- 新 infra AUTO 合併含 `success() &&`：任一前序步驟（含 G3）失敗即不合併。
- feat/ 路徑：`is_unit=true`，所有 unit 專屬閘與原本一字不差。
