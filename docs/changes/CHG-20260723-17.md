# CHG-20260723-17 — C++ 建置骨架：root CMakeLists、BUILD 慣例、G3 改用 CMake+CTest

- Date: 2026-07-24 (UTC+0) | Branch: chore/cpp-ci | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
A1 定案 C++（CHG-16）。但 G3 測試閘門是 pytest（純 Python），**測不了 C++**，
導致任何 C++ 實作的 PR 永遠無法轉綠、自動合併不會觸發 —— 實作無法開始。
本 CHG 補上 C++ 建置骨架，讓 subagent 的 C++ 單元能被建置、測試、通過 G3。

## 基礎選擇（可覆核可改）
| 項目 | 選擇 | 理由 |
|---|---|---|
| 語言標準 | **C++17** | 現代、跨平台、CI 內建支援 |
| 建置系統 | **CMake ≥ 3.16** | 跨平台事實標準；ubuntu-latest / Windows 皆內建 |
| 測試框架 | **GoogleTest + CTest** | 事實標準；經 FetchContent 取得，無需預裝 |

## Impact

### 1. `CMakeLists.txt`（root，新增；bootstrap 基礎設施）
- C++17、`enable_testing()`、FetchContent 取 GoogleTest v1.15.2
- **自動 glob 收入各單元 CMakeLists**：`src|engine|modules/*/*/CMakeLists.txt`（含 `src` 深度 3 的後端如 `backend/null/`）
- 單元只需在自己的 write_scope 目錄放 CMakeLists，根層自動納入 —— **單元不得改本檔**（不在任何 write_scope 內）

### 2. `docs/backlog/BUILD.md`（新增；subagent 必讀）
- 規定每個單元的目錄結構、CMakeLists 樣板（`add_library` + `add_executable(test_<slug>)` + `add_test`）
- 測試檔在 `tests/<module>/test_<slug>*`（該路徑在單元 write_scope 內），CMakeLists 以相對路徑指向
- 純資料宣告型單元（如能力矩陣 JSON/YAML）：寫一個載入並驗結構的 gtest
- 重申八道閘門的硬約束與相位 1 的 null 後端限制

### 3. `governance.yml` G3 改寫
```diff
- pip install -q pytest
- python -c "...tests/**/test_*.py 存在否..."; pytest -q
+ cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
+ cmake --build build -j
+ N=$(ctest --test-dir build -N | sed -n 's/.*Total Tests: //p')
+ [ "${N:-0}" -gt 0 ] || { echo "::error::repo 沒有任何 CTest 測試"; exit 1; }
+ ctest --test-dir build --output-on-failure
```
**真空綠燈防線保留**：0 個註冊測試 = 紅燈。required check 仍為 job `gate`，其餘七道閘門不變。
