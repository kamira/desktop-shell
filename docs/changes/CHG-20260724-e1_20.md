# CHG-20260724-e1_20 — 睡眠喚醒復原（E1-20）

- Date: 2026-07-24 | Branch: feat/e1_20 | Risk: low | Implemented by: I1.115
- Skill: ai-sdlc-autopilot

## Motivation
E1-20「睡眠喚醒復原」是 platform 層（子系統 kernel）的復原邏輯：處理**系統睡眠 / 喚醒**
後的**狀態復原**——偵測 E5-08 的 `SystemSleep` / `SystemWake` 事件，睡眠前保存 E1-01
`LayerStack` 目前的具名 surface / 圖層指派與可見性快照，喚醒後還原（重建圖層指派、
恢復可見性），並處理喚醒後可能失效的資源。相位 1（Mac / null 期）**絕不接真實電源 API**
（無 IOKit / IORegisterForSystemPower / SetThreadExecutionState / cocoa / `#ifdef`），
**不建 backend/win32|cocoa**；以**已合併的 E1-01 具名圖層堆疊** + **可注入的 E5-08 系統
事件源**實作純事件驅動復原邏輯，狀態全存記憶體。真實電源事件整合留待後端相位。

## Impact

### 新增 `src/kernel/e1_20/`（platform 層 / 子系統 kernel）
- `sleep_wake_recovery.hpp` / `sleep_wake_recovery.cpp`（`namespace ds::kernel`）：
  - `SleepWakeRecovery`（非樣板類別，持有注入的 `SystemEventSource&` 與 `LayerStack&`）：
    - 建構時**訂閱**注入的 E5-08 `SystemEventSource`；解構時解除訂閱（非擁有指標，
      來源與 `LayerStack` 生命週期皆由外部管理）。
    - **事件驅動**：僅 `SystemEventType::SystemSleep` / `SystemEventType::SystemWake`
      觸發本單元邏輯，其餘系統事件（`DisplayChanged` / `SessionLocked` / ...）一律忽略。
    - `SystemSleep` 到達：走訪 `LayerStack::stacking_order()` 為每個已指派 surface 保存
      「具名圖層 + 可見性」快照（可見性經可選注入的 `VisibilityProvider` 查詢，無 provider
      保守視為可見）；此快照**取代**前一輪快照，每輪 sleep 皆是全新快照。
    - `SystemWake` 到達：若曾有快照，逐一以 `LayerStack::assign()` **重建圖層指派**——
      `assign()` 內部已對 `kernel.surface` 能力 `has()` 閘控（**NFR-03**），能力不可用時
      該筆保守略過、不改動任何狀態、絕不崩潰；對每個「仍有效」的 surface 呼叫可選
      `on_wake(SurfaceId, SurfaceLayer, bool)` 回呼，帶回其應**恢復的可見性**，供消費者
      實際呼叫 show_surface / hide_surface。若注入 `ResourceValidator` 判定某 surface 於
      喚醒當下已失效，則**不**重建其指派，改呼叫 `on_invalidated(SurfaceId)` 通知消費者
      處理殘留資源。**未曾睡眠即收到喚醒**：保守 no-op，不崩潰。
    - `has(CapabilityId)`：**NFR-03** 代理至注入的 `LayerStack::has()`。
    - 診斷 / 測試查詢：`has_snapshot` / `snapshot_count` / `snapshot_contains` /
      `snapshot_layer_of` / `snapshot_visible_of` / `sleep_count` / `wake_count`。
    - 不可複製 / 搬移（持有訂閱與外部指標，複製語意不明確故禁止，保守）。
  - `CMakeLists.txt`：`add_library(e1_20)` **PUBLIC 連上游 `e1_01` `e5_08`**（標頭對外暴露
    其型別，須傳遞 include 目錄）；`test_e1_20` + `add_test(NAME e1_20)`。
- 上游相依（已合併，可讀不可改）：E1-01 具名圖層堆疊（`LayerStack` / `SurfaceId` /
  `SurfaceLayer` / `layer_capability()`）、E5-08 系統事件（`SystemEventSource` /
  `NullSystemEventSource::inject` / `SystemSleep` / `SystemWake`）。
- **無** `#ifdef` / win32 / cocoa / IOKit / SetThreadExecutionState / 真實電源 API；**未建**
  `src/kernel/backend/win32|cocoa/`（backend_guard 綠燈）。純邏輯、平台中立、狀態存記憶體。

### 測試 `tests/e1/test_e1_20.cpp`（gtest，12 案例）
- 初始狀態（1）：未經歷任何睡眠前無快照、計數為 0。
- **睡眠事件保存狀態**（1）：SystemSleep 保存目前圖層指派 + 快照筆數 / 內容正確。
- **喚醒事件還原**（1）：睡眠後模擬指派遺失，SystemWake 依快照以 assign() 重建。
- **圖層可見性復原**（2）：on_wake 回呼帶回**睡眠當下**的可見性快照（非喚醒當下即時查詢）；
  無 VisibilityProvider 時保守預設可見。
- **非睡眠 / 喚醒事件忽略**（1）：DisplayChanged / SessionLocked / SessionUnlocked /
  PowerStatusChanged 皆不影響快照與計數。
- **經 E5-08 事件驅動**（1）：建構即訂閱（listener_count 增加）。
- **訂閱解除**（1）：解構後 listener_count 歸零，且解構後注入事件不崩潰。
- **多次睡眠喚醒循環**（1）：兩輪 sleep/wake，每輪皆全新快照、各自計數累加。
- 喚醒無先前睡眠（1）：保守 no-op，回呼不觸發，計數仍累加。
- **失效資源處理**（1）：ResourceValidator 判定失效者不重建指派、觸發 on_invalidated；
  有效者正常重建、觸發 on_wake。
- **NFR-03 能力閘控**（1）：kernel.surface 不可用時，assign 一律拒絕、快照為空、
  has() 代理正確、喚醒不崩潰。
