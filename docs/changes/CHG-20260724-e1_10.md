# CHG-20260724-e1_10 — 保持在螢幕內（E1-10）

- Date: 2026-07-24 | Branch: feat/e1_10 | Risk: low | Implemented by: I1.139
- Skill: ai-sdlc-autopilot
- Unit: E1-10（保持在螢幕內，platform 層 / kernel / low，相依已合併 E1-07 anchor 定位模型 +
  E1-18 具名螢幕與每螢幕實例）

## Motivation

元件依 anchor（E1-07 `resolve()`）定位後解析出的 `ResolvedPlacement`，可能因偏移量 /
元件尺寸而超出螢幕邊界（例如靠螢幕邊緣的彈窗、貼邊的浮動視窗）。若不做任何處理，元件會被
裁切在螢幕外、看不見或無法互動。E1-10 提供一個純計算的「夾回（clamp）」服務：把已解析的
`ResolvedPlacement` 相對某個螢幕的可視範圍夾回到範圍內，同時遵守 NFR-02（不得引入硬編絕對
座標）——夾回計算沿用 E1-07 `resolve()` 的模式：具體尺寸數字只在計算的**輸入邊界**由呼叫端
提供，核心 API 本身不寫死任何座標或尺寸。並以 E1-18 的具名 `ScreenId` 承接「多螢幕情境下要
夾回哪一個螢幕」，維持 NFR-02 對「螢幕以具名識別碼指涉，不以數字 index」的既有約束。

相位 1（Mac / null 期）：純位置計算邏輯，無真實視窗 / 螢幕查詢 API、無平台分支。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 核心計算 | 自由函式 `constrain(placement, screen, out) -> KeepOnScreenStatus` | 純函式、無狀態，與 E1-07 `resolve()` 同風格；`screen`（`Size`）由呼叫端提供，同 E1-07 container 尺寸來源模式 |
| 夾回演算法 | 每軸獨立：`x` 夾至 `[0, max(0, screen.width - width)]`，`y` 同理 | 同時涵蓋「超出右/下/左/上邊界→推回」與「完全在內→不動」；角落超出時兩軸各自夾回即等效同時處理 |
| 元件大於螢幕 | 該軸 `max(0, screen - element)` 退化為 0 → 貼齊起邊（0） | 已知不可能完全容納時，選擇不縮放、不裁切元件本身，僅讓其盡量呈現於可視範圍起點；是一個明確、可預期、不做魔法縮放的決策 |
| 多螢幕 / 具名螢幕存在性 | `KeepOnScreen` 類別綁定 E1-18 `ScreenRegistry`；`constrain_on(screen_id, screen_size, ...)` 先查 `is_known()` 再委派給 `constrain()` | E1-18 的 `ScreenRegistry` 本身不攜帶像素幾何（其幾何只以具名 `ScreenRole`/`ScreenAnchor` 表達），故螢幕的實際可用尺寸仍須由呼叫端提供；`KeepOnScreen` 用具名 `ScreenId` 做「這是哪一個已知螢幕」的查詢鍵，未知具名螢幕直接 `Invalid`，不猜測其尺寸 |
| 無效輸入語意 | 非有限 / 負值 placement 尺寸、非有限 / 負值 screen 尺寸、未知具名螢幕 → `Invalid`，不寫 `out` | 與 E1-07 `AnchorStatus` / E1-18 一致的結構化錯誤回報，不靜默 |
| 便利查詢 | `is_within_screen(placement, screen) -> bool` | 供呼叫端 / 測試判斷是否需要夾回；無效輸入保守回 `false` |

不出現絕對硬編座標 / 數字 z-order；不綁任何真實平台後端；無 `#ifdef _WIN32` / `win32` /
`cocoa` 等平台分支，符合相位 1（Mac/null）與 NFR-02 約束。
