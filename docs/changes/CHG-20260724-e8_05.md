# CHG-20260724-e8_05 — 外部模組開發介面（E8-05）

- Date: 2026-07-24 | Branch: feat/e8_05 | Risk: low | Implemented by: I1.79
- Skill: ai-sdlc-autopilot
- Unit: E8-05（外部模組開發介面，engine 層 / 子系統 script / 擴充點 5「腳本 / 模組」的**開發面**）

## Motivation

擴充點 5「腳本 / 模組」讓第三方掛上自己的能力而不改核心。E8-04 已提供**載入機制**
（validate → register → track → unload）。但「如何載入」不等於「模組長什麼樣、如何與宿主互動」——
第三方開發者需要一個**穩定的 API/SDK 介面**才能寫出可被載入 / 驅動的模組。

E8-05 定義這個開發面：第三方模組實作的抽象介面（生命週期、metadata 宣告、宿主服務存取），
以及宿主用來與模組互動的契約。建於 E8-04 之上——E8-04 負責「載入」，本單元定義「載入後」。

## 設計（可覆核可改）

**相位 1：平台中立、純邏輯。** 無 `#ifdef`、無系統呼叫、無 dlopen / 真實動態載入。
第二相位引入動態庫時，本開發介面（`IModule` 契約）不變，只換「取得 `IModule` 的方式」。

| 項目 | 選擇 | 理由 |
|---|---|---|
| 模組抽象 | `IModule` 純虛擬介面（`info` + init/start/stop/teardown + `state`） | 第三方只實作介面即可被宿主載入 / 驅動，不碰核心 |
| 生命週期 | init → start → stop（可逆，可再 start）→ teardown（終態） | 明確、可內省的狀態機；對應「載入後」的運行 / 停止 / 清理 |
| 狀態機防護 | `ModuleBase` 便利基底：公開 init/start/stop/teardown 為 final，先驗合法轉移再委派 `on_*` 鉤子 | 把錯誤處理 / 狀態一致性集中於 SDK；開發者只寫業務鉤子 |
| metadata 宣告 | `ModuleInfo`（name/version/requires/permissions/format_version）+ `to_manifest()` | 橋接 E9-02 manifest / E8-04 閘控；模組自宣告能力需求 |
| 宿主服務存取 | `HostServiceRegistry`（宿主登記）+ `ModuleContext::has_service`/`service<T>`（型別安全取用） | 模組在生命週期中借用宿主提供的服務；**存取一律以 `has()` 閘控（NFR-03）** |
| 能力登記 | `ModuleContext` 委派 E8-04 `ds::ext::ModuleContext`（provide_sensor/component/action） | 重用 E8-04 註冊面 + 跨模組衝突偵測，不另造一套 |
| 載入整合 | `make_module(IModule&, HostServiceRegistry&) → ds::ext::Module` | 轉接：on_register 驅動 init→start；on_unload 驅動 stop→teardown。現成 `ModuleLoader` 直接用 |
| 命名空間 | `ds::ext::sdk` | 與 E8-04（`ds::ext`）一致前綴；巢狀 `sdk` 避免與 E8-04 既有 `ds::ext::ModuleContext` 衝突 |

**命名空間備註**：單元任務書括註「`ds::script`」，惟已合併之 E8-04 實際命名空間為 `ds::ext`
（於 `engine/script/` 下）。為真正「與 E8-04 一致」並能連結其型別，採 `ds::ext::sdk`。

平台中立：無 `#ifdef` / `_WIN32` / `win32` / `cocoa` / `dlopen` / 真實後端（僅註解說明相位 1 刻意不用）。

## Impact

### 1. `engine/script/e8_05/module_sdk.hpp`（新增）
- `ModuleState`{Created,Initialized,Started,Stopped,TornDown} + `to_string`。
- `ModuleInfo`（metadata / requires / permissions / format_version）+ `to_manifest()`（→ E9-02）。
- `IHostService`（宿主服務基底）、`HostServiceRegistry`（`add`/`has`/`get`/`size`，只借用不擁有）。
- `ModuleContext`（SDK 面）：`has_service`/`get_service`/`service<T>` + 委派 `provide_sensor/component/action`。
- `IModule`（純虛擬契約）、`ModuleBase`（生命週期狀態機 + 合法轉移防護 + `on_*` 鉤子）。
- `make_module(IModule&, const HostServiceRegistry&) → ds::ext::Module`（SDK ↔ E8-04 整合點）。

### 2. `engine/script/e8_05/sample_module.hpp`（新增）
- `IClockService`/`FixedClock`（示範宿主服務）、`SampleSensorModule`（範例：requires 宿主能力、
  以 has() 閘控取宿主時脈服務、登記 `sample.tick` 感測器）——最小具體實作驗證契約可用。

### 3. `engine/script/e8_05/module_sdk.cpp`（新增）
- `contract_version()`（"e8_05/1.0.0"）、`to_string(ModuleState)`、`make_module`（on_register/on_unload lambda）。

### 4. `engine/script/e8_05/CMakeLists.txt`（新增）
- `add_library(e8_05 STATIC module_sdk.cpp)` + `target_link_libraries(e8_05 PUBLIC e8_04)`
  + `test_e8_05` executable + `add_test(NAME e8_05)`，依 BUILD.md 樣板。

### 5. `tests/e8/test_e8_05.cpp`（新增）
- 18 個 gtest：contract_version / ModuleState to_string、ModuleInfo→manifest 欄位、生命週期
  狀態機（happy path、stop 後可重 start、非法轉移拒絕、teardown 冪等 / 自 Created 跳過、
  on_init / on_start 失敗不前進）、宿主服務存取（has/get/型別安全轉型、錯型別回 null、
  空名 / null 略過）、能力登記委派 E8-04、SampleSensorModule 契約（含缺服務 init 失敗）、
  make_module + ModuleLoader 完整載入 / 卸載整合、錯誤處理（缺 host 能力 → MissingRequirement、
  缺服務 → RegistrationFailed 不留痕）。

### 6. `docs/structure/units/e8_05.md`（新增；G4 要求）
- 本單元獨立結構註記（不動共用 `directory.md`）。

## 不含（避免越界）

- **不做 dlopen / 動態庫載入**（相位 2 職責）；相位 1 沿用 E8-04 行程內模型。
- **不改 E8-04 載入機制**（可讀不可改）；本單元建於其上並轉接。
- **不定義 manifest 格式**（E9-02 職責）；`ModuleInfo` 產出等價 manifest 交下游。
- 不實作具體感測器 / 元件 / 動作；只定義其開發 / 生命週期 / 宿主互動介面。
- 未動 `units.json`、根 `CMakeLists.txt`、`directory.md` 或任何鎖定範圍以外的檔案。
