## Motivation

系統匣 / 選單列（system tray / menu bar）圖示與其右鍵選單，在各平台以完全不同的機制
實作（Windows `Shell_NotifyIcon`、macOS `NSStatusBar`、Linux StatusNotifierItem…）。選單的
**邏輯**（項目樹、標籤 / 分隔線 / 子選單 / 勾選、點擊分派、勾選切換）與這些平台 API 無關，
應與後端解耦，才能在相位 1（Mac / null 期）先行成形並以純單元測試驗證。

E11-01 提供一個**平台中立**的系統匣控制器：以可注入的 `TrayBackend` 抽象作為對「系統」的
唯一出口，相位 1 由 `NullTrayBackend` 承接（記憶體記錄狀態、累計呼叫）。選單項點擊經
E6-01 命令匯流排（`ds::command::CommandBus`）分派 —— 呼叫端只需命令 id + 參數，不相依任何
具體致動器。真實後端（相位 2+）實作同介面即可，控制器與選單邏輯一行不改。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 選單項 | `TrayMenuItem`：Action / Separator / Checkbox / Submenu 四型別（工廠建構） | 涵蓋標籤 / 分隔線 / 子選單 / 勾選；子選單遞迴組樹 |
| 選單模型 | `TrayMenu`：有序項目集合 + 鏈式建構 + 索引路徑定位（`at_path`） | 純資料 / 決定性遍歷；巢狀項以 `{i, j, …}` 路徑定位 |
| 後端抽象 | `TrayBackend`：`has` / `set_icon` / `set_tooltip` / `set_menu` / `show` / `hide` | 對系統的唯一出口，與平台解耦 |
| 相位 1 後端 | `NullTrayBackend`：`has()==false`、記憶體記錄狀態與呼叫次數 | Mac / null 期；不觸碰真實匣，供契約測試斷言一致性 |
| 控制器 | `SystemTray`：整合選單模型 + 注入後端 + 注入 `CommandBus`；點擊→分派、Checkbox 先切換再帶 `checked` 參數分派 | 選單邏輯集中；分派經 E6-01，不相依具體致動器 |
| 點擊結果 | `TrayClickResult{ Dispatched / InvalidPath / NotClickable / NoCommand / NoBus }` | 邊界情形結構化、絕不崩潰 |
| 後端選派 | 工廠 `make_default_tray(bus)`，相位 1 回 NullTrayBackend | 真實後端上線後只改工廠 |

平台中立：無 `#ifdef _WIN32` / win32 / cocoa / NSStatusBar / Shell_NotifyIcon 分支，未建立
`src/**/backend/win32|cocoa/`，符合相位 1 與 `backend_guard` 約束。能力閘控入口 `has()`
（NFR-03 精神）；核心 API 無絕對座標 / 數字 z-order（NFR-02）。
