## Motivation

描述子系統需要一個**宣告式格式的根契約**：一個能描述設定 / profile / 內容的資料模型，
與一套把文字宣告解析成該模型的基座。眾多格式 / 設定單元都會消費它——`E9-02` 的 manifest
就是這個更通用格式的一個特例（key/value + requires/permissions）。因此本單元的形狀必須謹慎。

依 `docs/ai-guideline.md` §3 Q3：「平台的產品就是它的 API 面」，格式與模組介面**從第一版就得
帶版本欄位與相容策略**——不是為了外人，是因為你自己的組件就是這個 API 的第一批消費者。
故本格式在根層帶 `format_version = major.minor`，並定義相容判定（相容 iff major 相同且
minor ≤ 支援上限），作為未來前向擴充的基礎。

本單元屬 engine 層（平台中立純邏輯）：無任何 `#ifdef` / 系統呼叫 / 真實後端，換平台一行不動；
可完全單元測試。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 資料模型 | `Value` 多型：Null / Bool / Number / String / List / Map | 涵蓋宣告式文件所需的最小完備型別集；List / Map 遞迴組成節點樹 |
| Number | 存 `double` + `integral` 旗標（來源是否為整數字面值） | 多數設定要整數語意（`as_int`），同時保留浮點；`is_integer()` 可查 |
| Map | 有序 `vector<pair>` + 鍵唯一（解析時查重） | 保留來源順序（可重現輸出 / 穩定測試）；鍵唯一避免歧義 |
| 誤用型別存取 | throw `std::runtime_error`（非回傳可疑預設） | NFR-04 精神「不靜默失敗」；呼叫端先以 `is_*()` 查型別 |
| 版本欄位 | `FormatVersion{major,minor}` + `kSupportedFormat{1,0}` + `is_format_compatible()` | 相容策略基礎（Q3）：major 破壞相容、minor 前向擴充 |
| 版本擺放 | 根層必填 `format_version`，解析後取出為 `Document.format_version`，**不留在 root map** | root 為純內容；且**避開數字歧義**——`1.10` 若當數字會塌成 `1.1`，故版本以原始 token 特別解析 |
| 文字格式 | 極簡、自足、無外部相依：縮排表達巢狀 map / list，`key: value` 純量，`"..."` 帶轉義字串 | 比 manifest 的平坦 key/value 更通用（manifest 是其平坦特例），仍零相依、易測 |
| 縮排 | 只允許空白，**tab 縮排明確拒絕並定位** | 避免 tab/space 混用的隱性歧義；錯誤可定位 |
| 純量型別推斷 | `null` / `true` / `false` / 數字 / 引號字串，其餘一律裸字串 | 保守可預期；裸字串保留原樣（可含空白與冒號值） |
| 錯誤模型 | `ParseResult`（成功 Document / 失敗 `ParseError{line,message}`），**一律定位到行** | 不靜默失敗（NFR-04 精神）；重複 / 未知結構 / tab / 版本錯誤皆帶行號 |
| 錯誤傳遞 | 遞迴解析內部以受控例外拋出、於 `parse()` 邊界捕捉轉 failure | 讓遞迴下降碼保持乾淨；對外介面仍為無例外的 ParseResult |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。與 `E9-02` 風格一致但更通用。
