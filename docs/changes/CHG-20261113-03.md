## 知識庫：`K-016`

`I1.1` 在施工中自查自修了一個錯誤，並依 `AGENTS.md` §2 把 K 編號留給 I1 配發。
本收尾者複核後確認其事實基礎，收為 `K-016`。

重點不是「NaN 沒擋住」（那是 `K-002` 已記的），而是**為什麼寫的人以為自己擋住了**：
他心裡有一條正確的口訣「NaN 的比較一律 false，所以只用正向比較就是 fail-closed」，
而那條口訣**只對有序比較成立**。`nan != 0.0` 為 **true**。最毒的是同一個 `return` 裡
兩種比較混用——`outer_radius > 0.0` 真的擋住了 NaN，`sweep_degrees != 0.0` 就在它旁邊放行，
讀起來像是「每一項都檢查過了」。

三道自動防線同時靜默：`-Wall -Wextra -Werror` 不警告（NaN 比較完全合法）、
ASan + UBSan 零報告（不是 UB）、**本月剛加的 `float-cast-overflow` 也零報告**（沒有溢位轉換）。
只有「拿 NaN 餵進去看會怎樣」的測試抓得到。
