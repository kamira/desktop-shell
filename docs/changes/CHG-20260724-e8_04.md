# CHG-20260724-e8_04 — 行程內模組載入（E8-04）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e8_04 | Risk: low | Implemented by: I1.25
- Skill: ai-sdlc-autopilot v1.1
- Unit: E8-04（行程內模組載入，engine 層 / 子系統 script / 擴充點 5「腳本 / 模組」的載入機制）

## Motivation

平台的第五個擴充點是「腳本 / 模組」：第三方掛上自己的能力（感測器 / 元件 / 動作）
而不需修改核心。`docs/architecture.md` 將 `E8-04`（行程內模組載入）由 `P1` 升為
`P0`——「它從輔助設施變成主要擴充機制」，因為「平台若無法在不修改自身的前提下
載入模組，它就不是平台」。

E8-04 提供這個擴充點的**載入機制**：把一個由 E9-02 manifest 描述的模組載入行程，
驗證其 `requires`/`permissions`、呼叫其註冊入口、追蹤已載入模組、並可卸載。

## 設計（可覆核可改）

**相位 1：行程內註冊模型，不用 dlopen / 動態庫。** 模組是「已連結進本行程的 C++
物件」，透過註冊介面掛上。第二相位再引入動態庫時，本契約（validate → register →
track → unload）不變，只換「取得 Module 的方式」。因此本單元純邏輯、平台中立。

| 項目 | 選擇 | 理由 |
|---|---|---|
| 相位 1 模型 | 行程內、已連結 C++ 物件（`Module` 結構 + `on_register` 入口） | 不引入 dlopen / 動態庫；平台中立、可完全單元測試 |
| 閘控依據 | `HostEnvironment`（host 提供的能力 + 授予的權限） | manifest `requires` 對 host 能力、`permissions` 對 host 權限 |
| requires 不滿足 | **明確拒絕**（`MissingRequirement`，附全部缺項清單） | 契約要求「不靜默」；缺項可定位 |
| permissions 未授予 | 拒絕（`MissingPermission`，附缺項） | 與 requires 對稱 |
| 註冊兩階段 | 先收集 `ctx.provided()`、驗無跨模組衝突才整批提交 | 失敗不部分提交、易回滾 |
| 能力衝突 | 兩模組提供同 (kind,id) → 第二個 `RegistrationFailed` | 不無聲遮蔽既有提供者 |
| 例外安全 | `on_register` 拋例外被攔為 `RegistrationFailed`，不留痕 | 載入器不崩潰 |
| format 版本 | 沿用 E9-02 `is_format_compatible` 再驗一次 | 不相容模組即拒（`IncompatibleFormat`） |
| 卸載 | 呼叫 `on_unload` + 自能力表精準移除 + 可重載 | 生命週期完整 |

平台中立：無 `#ifdef`、無系統呼叫、無真實後端、無 dlopen，符合 engine 層「換平台一行不動」。
