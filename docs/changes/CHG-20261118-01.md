## 四、`R28` 另開上游單元 `E7-18`

| 欄位 | 值 |
|---|---|
| id / branch | `E7-18` / `feat/e7_18` |
| wave / depends_on | 2 / `E7-01`、`E7-17` |
| risk / priority | **medium** / P1 |
| layer / stage / phase / platform | engine / A / 1 / `neutral` |
| write_scope | `document.cpp`、`document.hpp`、`CMakeLists.txt`、`tests/e7/test_e7_18*`、`docs/changes/CHG-*-e7_18.md` |

**缺陷**（`V1.16` 查出，I1 自行從原始碼複核）：`as_int()` 是裸
`static_cast<std::int64_t>(num_)`（`document.cpp:72`，只檢查型別、**不檢查值域**），
而整數旗標由 `numeric_token()` 依字面有沒有小數點／指數決定（`document.cpp:344`），
**同樣不檢查值域**。使用者在非幾何鍵寫 `cap: 10000000000000000000`（20 位）→
`restore` 回 `Ok`、`lost_content=0`，接著 `save()` 踩 **float-cast-overflow**
（UBSan：`1e+19 is outside the range...`）。不開 sanitizer 時是 `VerifyFailed`
——具名、不毀資料，但**那份存檔從此存不回去**。

**為什麼今天的 CI 抓不到**：`gate_sanitizers` 跑全庫 ctest，但沒有任何測試餵這種字面值。
所以驗收標準要求附一支會讓未修版本在 sanitizer 下紅的回歸測試，並以突變證明它承重。

**與 `K-017` 的關係**：`K-017` 記的是「`std::stod` 丟的 `out_of_range` 是 `logic_error`，
而它丟的值常常在範圍內」。`E7-18` 是同族的另一面——**一個不丟、不報、直接做 UB 的轉換**，
而它的名字（`as_int`）讀起來像是安全的。驗收標準也明寫不得破掉 `E7-17` 剛建立的
「`parse()` 一律回 ParseResult」契約。
