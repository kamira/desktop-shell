# CHG-20260724-e8_02 — 對話腳本直譯器（E8-02）

- Date: 2026-07-24 | Branch: feat/e8_02 | Risk: low | Implemented by: I1.39

- Unit: E8-02（對話腳本直譯器，engine 層 / 描述子系統 / low；相依已合併的 E7-05）

## Motivation

宣告式格式（E7-01）+ 變數系統（E7-02）+ 公式運算引擎（E7-05）讓設定 / profile / 版面能
宣告具名值、複用、並以既有值推導新值。但一段**對話 / 腳本**還需要**時間維度**：依序執行
步驟、依條件分支、跨步累積狀態、在該做副作用時輸出。**對話腳本直譯器**把宣告式格式撰寫
的步驟序列直譯為可逐步（`step()`）或一次跑完（`run()`）的腳本。

本單元建構於 E7-05 之上、**消費其 `evaluate()` 公式引擎**求值運算式（`set`）與條件（`if`），
並傳遞取得 E7-02 的 `VariableScope`（跨步延續的變數狀態、`say` 文字的 `${var}` 內插）與
E7-01 的 `Value`（型別 / 數值模型）。不重造求值 / 作用域 / 型別模型。

副作用（輸出 / 動作）一律走**抽象、可注入的 `OutputSink`**——直譯器本身不綁任何真實副作用，
由呼叫端決定文字真正落地何處（終端 / 紀錄 / UI）。屬 engine 層（平台中立純邏輯）：無任何
`#ifdef` / 系統呼叫 / 真實後端，可完全單元測試。

依 NFR-04 精神「不靜默失敗」：未知指令、求值 / 條件失敗、跳轉到未知標籤、條件非布林 /
數值、重複標籤、疑似無窮迴圈——一律回傳帶**步驟索引 + 訊息**的 `ScriptError`，絕不安靜略過。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 指令模型 | `Step{command, target, arg}`（command 為 opcode 字串） | 讓「未知指令」在執行期可明確報錯（腳本語意）；工廠函式維持可讀 |
| 指令集 | `set` / `say` / `if` / `goto` / `label` | 最小但完備：求值步、輸出步、條件分支、無條件跳轉、跳轉標的 |
| 運算式 / 條件求值 | 消費 E7-05 `evaluate(expr, scope)` | 不重造求值；與公式引擎一致的語法 / 型別 / 錯誤定位 |
| 條件真值 | Bool 原樣；Number 非零為真；其餘 → 型別錯誤 | 與 E7-05 `truth_of` 一致；規則最小明確 |
| 變數狀態 | 存於 `ExecutionContext` 的 `VariableScope`，`set` 就地 `define` | 跨步延續；可選父作用域供預注入；查找沿父鏈上溯 |
| 輸出 `say` | 文字模板經 E7-02 `resolve` 做 `${var}` 內插 → `value_to_text` → sink | 對話文字的直觀內插；消費上游、不重造字串化 |
| 副作用 | 抽象 `OutputSink::emit`（現成 `RecordingSink`） | 可注入、不綁真實後端；完全可測（平台中立） |
| 跳轉 | 建構時一次索引 `label` 名 → 步驟索引；`goto` / `if` 執行期查表 | O(1) 跳轉；重複標籤 → 建構期錯誤（不靜默） |
| 無窮迴圈防護 | `set_step_budget()`（預設 100000）超出 → 錯誤 | `goto` 可造成無窮迴圈；預算上限明確中止而非掛死 |
| 錯誤模型 | `ScriptError{step, message}`；`StepResult` / `RunResult`（二選一） | 對齊 E7-01 `ParseResult` / E7-05 `EvalResult` 風格；帶步驟索引定位 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。副作用走注入式 sink，
不含能力閘控呼叫（純邏輯），無 `has()` 降級路徑需求。
