## Motivation

使用者指定：**拖曳移動 + 位置記憶**。

依 `phase2-desktop-runtime.md` §2 的對照，這是既有單元 **E1-08「自由拖曳與位置記憶」**
的 win32 後端 + host 裝配。E1-08 在相位 1 就已把拖曳狀態機、記憶位置、
序列化 / 還原（`serialize_positions` / `load_positions`）全部寫完，
位置以 `AnchorSpec` 表達。**本 CHG 沒有發明任何新的狀態機或資料格式。**

## Impact

### W1-03 — `src/kernel/backend/win32/`（擴充 W1-01 的後端）

`WM_NCHITTEST` 在命中客戶區且該 surface 可拖時回 **`HTCAPTION`**——
等於告訴 Windows「整個視窗本體就是標題列」，`DefWindowProc` 隨後自行進入系統的移動迴圈。

**因此自動獲得系統既有的拖曳行為**（邊緣吸附、跨螢幕、DPI 切換），
不必自己追蹤滑鼠位移——自己寫必然比系統差。
拖曳結束由 `WM_EXITSIZEMOVE` 判定，以具名 SurfaceId 供 `poll_drag_finished()` 取走。

新增的 win32 專屬擴充（皆非契約）：`set_draggable` / `is_draggable` /
`surface_origin` / `set_surface_origin` / `surface_size` / `work_area` / `poll_drag_finished`。

**新建 surface 預設不可拖**（保守：桌面元件不該被意外拖走），由 host 明確開啟。

### H1-03 — `host/position/`（新目錄）

像素 ↔ `AnchorSpec` 換算 + 檔案存取 + `PositionPersistence`。
**本單元不含任何狀態機**——`remember_current()` 走完整的
`begin_drag` → `drag_to` → `end_drag`，讓 E1-08 是位置的唯一真相來源。

```
dx = (x - 工作區左緣) / 工作區寬        anchor 固定為 TopLeft
```

反向委由 E1-07 `resolve()`。檔案為 `%LOCALAPPDATA%\desktop-shell\positions.conf`。

## 三個設計決定

**① 位置只能是擴充，不能進契約。** `KernelBackend` 硬性禁止絕對座標（NFR-02），
契約層永遠不會有 `set_position(x, y)`。像素只在**佈局邊界**出現，
而平台實作內部與 host 的換算層正是那個邊界。

**② 固定用 `TopLeft` 錨點，不挑最近的。** 挑錨點會讓「同一個位置」有多種合法表達，
round-trip 不再唯一，測試與除錯失去依據。邊緣吸附屬更上層的產品決策。

**③ 拖完當下就寫檔**，不等關閉。這支程式沒有「正常關閉」以外的收尾機會——
工作管理員結束、當機、登出都不會走到結尾。關閉時再寫一次只是保險。

## 直接紅利：解析度無關

存的是**比例**而非像素。換螢幕、改工作列高度、改縮放之後，widget 落在對應的相對位置，
而不是跑到畫面外。這是 NFR-02 帶來的，不是額外做的工。已有測試釘住
（1920×1040 的正中央 → 1280×720 上仍是正中央）。

關鍵測試：

| 測什麼 | 為什麼要緊 |
|---|---|
| 像素 → AnchorSpec → 像素 **round-trip** | 不成立的話「拖到哪記住哪」是壞的，而且會**壞得很安靜**——每次開機漂一點點 |
| 工作區原點非 (0,0)（工作列在上 / 左） | 只存尺寸會讓位置在那些機器上整體偏移 |
| 換螢幕尺寸按比例移動 | 這是用 AnchorSpec 而非像素持久化的**理由本身** |
| 搬位置不得改變圖層 / 尺寸 | 否則還原位置會把最上層設定弄掉 |
| 壞檔不得留半套狀態、不得亂搬視窗 | 持久化失敗不該讓 widget 掛掉 |
| 預設不可拖 | 這條鬆掉，使用者滑一下就把 widget 甩出畫面 |

### 操作驗收（合成真實滑鼠拖曳，非直接呼叫 API）

直接呼叫 `SetWindowPos` 搬視窗**不會觸發 `WM_EXITSIZEMOVE`**，等於繞過要驗的東西。
故以合成滑鼠事件（`mouse_event` 按下 → 分段移動 → 放開）走完真實路徑：

```
run1 起始   : (1576,24)      後端預設幾何
run1 拖曳後 : (1056,324)     視窗確實跟著滑鼠走
positions.conf:
  format_version: 1.0
  surface.cpu_widget:
    anchor: top-left
    dx: 0.550000011920929      存的是比例，不是像素
    dy: 0.3139534890651703
run2 還原   : (1056,324)      delta dx=0 dy=0
RESULT: POSITION_REMEMBERED
```

第二次執行是**全新行程、全新後端、全新狀態機**，只有檔案是共同的。

## 已知限制

- 只驗證了單一 widget。多 widget 的位置記憶在資料結構上已支援（以具名 SurfaceId 為鍵），
  但未實測。
- 沒有「鎖定位置」的 UI 開關（後端 `set_draggable` 已具備，缺選單項）。
- 沒有邊緣吸附 / 對齊格線。
- 拖曳中途沒有即時回報（只在放開時提交），因此拖曳過程中的位置不會被記住——
  這與 E1-08 的 `end_drag` 提交語意一致，非缺陷。
