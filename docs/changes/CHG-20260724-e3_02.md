- 相依：E6-01 命令匯流排（已合併，可讀不可改）——三個具名命令掛上匯流排、參數重用其穩定值型別。

## Motivation

桌面殼需要對外界產生三種常見副作用：啟動外部程式、以預設程式開啟檔案、以搜尋引擎搜尋網頁。
若一開始就綁死 `CreateProcess` / `NSWorkspace` / `xdg-open`，動作語意會被平台細節污染、
無法以單元測試驗證，且呼叫端會被迫相依具體致動器。

E3-02 走 E6-01「擴充點 3：動作」的既定路線：把這三種副作用以具名命令
（`launch.program` / `open.file` / `web.search`）掛上命令匯流排，呼叫端只需 命令 id + 具名參數
即可觸發，不需相依本致動器或任何 OS API。相位 1（Mac / null 期）**不真的啟動**——所有請求
交由可抽換的 `LaunchBackend` 承接，預設 `NullLaunchBackend` 只把請求記錄下來供測試 / 診斷驗證。
相位 2 換上真實平台後端（win32 / cocoa）時，本致動器與命令契約一行不動。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命令 id | 具名字串 `launch.program` / `open.file` / `web.search`（非數字 opcode） | 穩定、可讀、跨邊界不變形；與 E6-01 CommandId 取捨一致 |
| 掛載方式 | `LaunchActuator::register_on(CommandBus&)` 註冊三個具名命令 | 呼叫端經 `bus.dispatch(id, args)` 觸發，零相依本型別 |
| 副作用抽象 | `LaunchBackend` 純虛介面 + `perform(LaunchRequest)→CommandResult` | 相位 1 null、相位 2 真實後端可抽換，介面不動 |
| 相位 1 後端 | `NullLaunchBackend`：不觸碰 OS，只記錄請求（有序 vector） | 讓「註冊→分派→記錄」完整跑通並可單元驗證；不真的 exec |
| 請求型別 | `LaunchRequest{kind, target, arguments, engine}`（平台中立） | 不含 OS handle / 路徑假設；承載呼叫端意圖交後端實現 |
| 參數契約 | `launch.program`: 必填 `program`(str) / 選用 `args`(str)；`open.file`: 必填 `path`(str)；`web.search`: 必填 `query`(str) / 選用 `engine`(str) | 皆以 E6-01 `CommandArgs` 承載 |
| 必填保護 | 以 `args.has()` + `get_string()` 保護，缺漏 / 空值 / 型別不符回 `CommandResult{Failed}` | 不崩潰、不丟例外、不記錄無效請求（NFR-03 has() 保護取捨一致） |
| 註冊回滾 | `register_on` 任一命令掛失敗即回滾本次成功者並回 false | 不留半掛狀態、不遮蔽既有其他致動器 |
| 契約版本 | `contract_version()` = "e3_02/1.0.0" | 承重抽象，供相位 2 換後端時相容判斷 |

介面平台中立：無 `#ifdef _WIN32` / `cocoa` / `__APPLE__` / `darwin` / 真實 exec / spawn；
唯一 `#ifndef` 為 header guard、唯一 `#ifdef` 字樣為註解說明。
