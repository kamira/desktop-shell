## Motivation

C2-05「圖片」是桌面小工具目錄裡的一個**組裝型 widget**（非新引擎邏輯）：顯示單張，或依序
切換一組圖片（如相框輪播），可宣告式設定圖片來源清單 / 縮放（fit）模式。它把兩個已合併的
擴充點組起來——

- **C1-01**（`ds::profiles::SkinProfile`）：本 widget 掛載的**基底**——所有 C2 系列 widget 皆
  以 C1-01 為共用基底（見 `docs/backlog/units.json` 各 C2 單元的 `depends_on`）。本 widget 不
  驅動其載入 / 拖曳等生命週期，僅取用其具名 `id()` 作為渲染輸出的目標 surface（NFR-02：
  具名，非數字 handle），代表這張圖片「掛」在該桌面角色 / skin 之上顯示。
- **E4-02**（`ds::elements::ImageElement`）：單張圖片本體——本 widget 內部自持一個實例。
  E4-02 本身只認識「一張」圖片（`set_source`/`set_scale_mode`/`render_model`），故 widget 層
  另外維護一份「圖片來源清單 + 目前索引」，`set_image()`/`next()` 切換所選後把該張的來源
  （具名參照 + 固有尺寸）載入 E4-02，`render_model()` 反映目前所選。

相位 1：純資料 / 邏輯組裝，無真實 GUI、無真實影像解碼（沿用 E4-02 的可注入 `ImageSource`
抽象，只需固有尺寸與具名參照）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 掛載方式 | 建構子注入 `ds::profiles::SkinProfile&`（不取得所有權），立即 `set_target(skin.id())` 綁定渲染目標 | 同 C2-06 慣例：`SkinProfile::id()` 於其生命週期內不變，僅需綁定一次；不驅動 skin 的載入 / 拖曳等生命週期，保持單一職責 |
| 多圖清單的持有層 | widget 層自持 `vector<string> refs_` + `vector<ImageDimensions> dims_` + `current_` 索引；E4-02 `ImageElement` 只持有「目前所選那一張」（經 `set_source` 載入） | E4-02 語意本就是單張圖片元件（無清單概念）；widget 是「組裝型」單元，複雜度該留在 widget 層而非改動已合併的 E4-02 |
| 設定介面 | `configure(const ds::format::Value&)`：宣告式 Map，欄位 `images`（List，必填，每項 `{ref, width, height}`）/ `fit`（選填具名縮放模式字串）| 承 BUILD.md 的宣告式設定慣例，欄位驗證規則與 C2-06 `frames`/`fps`/`loop` 同精神（先整批驗證，全數通過才提交，未給選填欄位沿用目前值） |
| 驗證順序 | 先整批驗證 `images`（每項結構 + 具名值合法性）與 `fit`（若給），全數通過才提交新清單、重置索引至第 0 張、呼叫 `ImageElement::set_source`（已預先驗證，防禦性不再檢查其回傳） | 承 E4-02 `set_source`「不部分套用」精神；widget 層驗證失敗不得使既有設定產生半套用狀態 |
| 縮放模式表達 | `fit` 欄位為具名字串（"fill"/"fit"/"stretch"/"center"/"tile"）→ E4-02 `ScaleMode`，複用 C1-02（`content/profiles/c1_02/portrait_profile.cpp`）已驗證過的 `parse_scale_mode` 慣例 | NFR-02：具名，非數字係數；與既有單元一致，不重新發明命名 |
| 切換操作 | `set_image(size_t index)`：明確索引選取，越界或空清單 → `Invalid`（不改變目前所選）。`next()`：依序前進，抵尾循環繞回第 0 張；空清單或僅一張 → 安全 no-op | 語意需求列出「set_image / next（若多圖）」；`next` 用循環繞回（相框輪播直覺行為），`set_image` 用明確結果碼（NFR-02：具名結果，非布林裸值） |
| 渲染輸出 | `render_model()` 委派 E4-02，回傳目前所選圖片的 `ImageRenderModel`；未設定（空清單）時 `has_source=false`，但 `target` 欄位仍反映已綁定的 skin id | 明確降級不靜默假裝有資料（承 E4-02 精神）；目標綁定與是否已設定圖片清單彼此獨立 |
| 錯誤處理 | `ImageWidgetStatus`（`Ok`/`Invalid`），附 `to_string()`（NFR-02：具名結果碼） | 與同子系統其餘單元同精神：明確、不靜默 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支、不做真實影像解碼 / 繪製。
**NFR-02**：圖片來源以具名參照（`ref`）承載，`render_model()` 直接回傳 E4-02 的渲染描述
（正規化裁切 [0,1]、具名 `SurfaceId` 目標、具名縮放模式列舉），本單元未新增任何絕對座標或
數字 z-order。

## 不含（避免越界）

- **不驅動所掛載 C1-01 基底的載入 / 卸載 / 拖曳等生命週期**——那是呼叫端 / C1-01 自身的職責，
  本 widget 只取用其具名 id 作為渲染目標。
- 不做真實影像解碼 / 繪製 —— 沿用 E4-02 相位 1 的「注入式 `ImageSource`」抽象，不新增解碼
  後端、不連結 libpng/libjpeg。
- 不改動已合併的 E4-02（`ImageElement` 只認識單張圖片是其既有設計）——多圖清單與切換邏輯
  完全留在本 widget 層，不修改上游。
- 未動根 `CMakeLists.txt`、`units.json`、`docs/structure/directory.md` 或任何鎖定範圍以外的
  檔案。
- 不改上游 C1-01 / E4-02（僅連結使用）。
