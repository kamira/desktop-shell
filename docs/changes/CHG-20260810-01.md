## Motivation

2026-08-10 的進場握手被 SessionStart hook 標出 5 筆「未收尾 CHG」：
`CHG-20260724-c1_07`、`-c3_01`、`-c3_03`、`-e10_01`、`-e10_02`。

逐一查證 `origin/main` 後確認：**五個單元都已經 squash merge 進 main**，
工作本身沒有任何未完成的部分。被標記的原因純粹是 CHG 文件的 Status 欄沒有跟上：

| CHG | 文件現況 | 實際狀態（origin/main） |
|---|---|---|
| `CHG-20260724-c1_07` | **完全沒有 `## Status` 段** | `85bc478` feat(profile): 全螢幕調光層 profile (#157) |
| `CHG-20260724-c3_01` | **完全沒有 `## Status` 段** | `0e46f6c` feat(content): 啟動器選單樹 (#172) |
| `CHG-20260724-c3_03` | **完全沒有 `## Status` 段** | `cbd5611` feat(content): 角色外觀組 (#184) |
| `CHG-20260724-e10_01` | `Proposed — 未 push、未開 PR。` | `9f983f2` feat(ipc): 本機 IPC 訊息投遞 (#24) |
| `CHG-20260724-e10_02` | `Proposed — 未 push、未開 PR。` | `ac7ff4f` feat(ipc): 低延遲同機通道 (#83) |

**根因**：本專案 176 個單元的施工流程是「subagent 寫 CHG（Status 寫 Proposed / 或漏寫）
→ I1 稽核 → push → 開 PR → CI 綠燈自動 squash merge」。合併發生在 PR 端，
而 CHG 文件在合併前就已凍結在分支上，**沒有任何一步會回頭改 Status**。
其餘 118 筆有 `Accepted` 是因為當時人工補過，這 5 筆漏了——是流程缺口，不是個案疏忽。

**為什麼要修**：Status 是進場握手判斷「有沒有半途而廢的階段」的唯一依據。
留著 5 筆假陽性，代價是每一次新 session 的握手都要重跑一次今天這輪查證
（查 5 個 slug 的合併 commit），而且會慢慢訓練出「hook 的警告可以略過」的習慣——
那才是真正危險的地方：下一次是真的未收尾時，沒有人會停下來看。
