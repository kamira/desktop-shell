# CHG-20260724-e9_07 — 拖放安裝（E9-07）

- Date: 2026-07-24 | Branch: feat/e9_07 | Risk: low | Implemented by: I1.41
- Skill: ai-sdlc-autopilot
- Unit: E9-07（拖放安裝 / engine 層 / 子系統 package / stage A）
- Depends on: E9-01（統一套件格式，已合併）、E5-08（系統事件，已合併）
  — `target_link_libraries(e9_07 PUBLIC e9_01 e5_08)`

## Motivation

E9-01 定義了「一個組件套件」的格式與解析/驗證；E5-08 提供平台中立的系統事件模型與 null 後端。
E9-07 把「使用者**拖放一個套件來源 → 安裝**」這個使用流程模型化：接收攜帶套件來源參照的拖放
事件，將來源解析為 E9-01 套件，並跑完安裝生命週期（解析來源 → 解析套件 → 結構驗證 → 登錄），
成功/失敗逐階段回報。相位 1 平台中立：不接任何真實 OS 拖放或檔案系統，來源以可注入抽象表達、
安裝目標為記憶體登錄。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::package`（與 E9-01 一致） | 依規格「命名空間與 E9-01 一致」 |
| 來源抽象 | `InstallSource`（`label()` + `open() -> SourceContent`）+ `MemoryInstallSource` | 可注入、平台中立；相位 2 換讀真實檔案的實作，`DropInstaller` 一行不動 |
| 無效來源 | `SourceContent.available == false` | 損毀/無法讀取的拖放來源明確報錯，不靜默 |
| 拖放事件 | `DropEvent`{ `const InstallSource*` source, `std::string` detail } | 純資料、平台中立（沿用 E5-08 事件風格）；source==null = 格式不正的拖放 |
| 安裝目標 | `InstallRegistry`（記憶體，以 manifest.name 為鍵，不覆寫） | 相位 1 平台中立目標；重複安裝可明確偵測 |
| 生命週期 | `InstallStage` Received→Resolved→Parsed→Validated→Registered + `InstallResult` + `InstallLifecycleListener` | 逐階段回報；失敗時 stage 指出失敗處、message 給原因（不靜默） |
| 解析/驗證 | 複用 E9-01 `parse_package`（解析即驗證，含 E9-02 格式相容性）+ `validate_package`（防禦性再驗） | 不重造格式邏輯；不相容套件於 Parsed 階段報錯 |
| E5-08 整合 | `DropInstaller` 建構時訂閱 `SystemEventSource`，維護「安裝閘門」 | 實際使用 E5-08 分派：`SessionLocked`/`SystemSleep` 關閉閘門（session 不在場/睡眠時拒絕安裝，合理安全姿態），`SessionUnlocked`/`SystemWake` 恢復 |

平台中立：無 `#ifdef`、無 `win32`/`cocoa`、無系統呼叫、不接真實拖放或檔案系統，符合 engine 層
「換平台一行不動」與相位 1 約束。
