# CHG-20260724-e1_21 — 能力矩陣宣告檔（E1-21）

- Unit: E1-21（能力矩陣宣告檔，P0 / 核心 / platform 層 / kernel）

## Motivation

系統的部分能力（系統匣、全域熱鍵、亮度控制、桌布、螢幕擷取、視窗背後模糊…）
在不同平台不保證存在。若呼叫端在未確認能力是否可用的情況下直接呼叫，換平台時
會安靜地崩壞或回傳未定義行為。NFR-03 要求「能力閘控呼叫必須有 `has()` 保護」，
而 `has()` 需要一份**可查詢的能力宣告**作為判斷依據。

E1-21 提供這份宣告：一份宣告式能力矩陣，明確標示每個能力是否 optional（可能在
某些平台不存在）與其預設可用性，成為後續 `has()` 閘控與降級路徑的**單一資料來源**。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 形態 | 宣告式資料（`CapabilityDecl` 表）+ 查詢介面 | 換平台時只換提供實際探測的後端，宣告不動 |
| 未知能力語意 | `has()` 一律回 `false` | 保守：未宣告即不可用，呼叫端永遠安全（NFR-03 精神） |
| 相位 1 `has()` | 回傳宣告的 `default_available` | null 期尚無真實後端；後端上線後覆寫實際探測值 |
| 重複 id | 後定義者為準 | 讓後端能覆寫先前宣告的預設可用性 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。

## Impact

### 1. `src/kernel/e1_21/capability_matrix.hpp`（新增）
- `CapabilityId`（字串識別碼別名）、`CapabilityDecl`{ id, description, optional, default_available }。
- `CapabilityMatrix`：`defaults()` 內嵌預設矩陣、`CapabilityMatrix(decls)` 由外部宣告建構；
  查詢介面 `has()` / `is_optional()` / `is_declared()` / `find()` / `all()` / `size()`。

### 2. `src/kernel/e1_21/capability_matrix.cpp`（新增）
- 內嵌預設能力矩陣（3 項保證存在 + 7 項可選能力，涵蓋 host/actuator/render 子系統）。
- 查詢邏輯：未知能力保守回 `false` / `nullptr`；相位 1 `has()` 回傳宣告的預設可用性。

### 3. `src/kernel/e1_21/CMakeLists.txt`（新增）
- `add_library(e1_21 STATIC capability_matrix.cpp)` + `test_e1_21` executable + `add_test(NAME e1_21)`，
  依 BUILD.md 樣板；根 CMakeLists 自動 glob 收入。

### 4. `tests/e1/test_e1_21.cpp`（新增）
- 8 個 gtest 案例：預設非空、保證能力可用、可選能力 null 期不可用、未知能力保守回 false、
  find 欄位、自訂宣告建構、空矩陣安全、重複 id 後定義者為準。

### 5. `docs/structure/directory.md`（同步；G4 要求）
- 於 `src/kernel/` 下補記 `e1_21/` 能力矩陣宣告檔一條。

## 不含（避免越界）

- **不實作任何真實平台後端**（win32/cocoa）；相位 1 僅介面 + null 宣告行為。
- **不實作 `has()` 閘控 lint**（NFR-03 建置期強制）—— 那是 `E1-22` 的職責。本單元只提供
  `has()` 所需的資料來源。
- 未動 `units.json`、根 `CMakeLists.txt` 或任何鎖定範圍以外的檔案。
