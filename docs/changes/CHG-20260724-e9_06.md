# CHG-20260724-e9_06 — 套件卸載流程（E9-06）

- Date: 2026-07-24 | Branch: feat/e9_06 | Risk: low | Implemented by: I1.74
- Skill: ai-sdlc-autopilot
- Unit: E9-06（套件卸載流程 / engine 層 / 子系統 package / stage A）
- Depends on: E9-01（統一套件格式，已合併）
  — `target_link_libraries(e9_06 PUBLIC e9_01)`

## Motivation

E9-07 把「拖放一個套件來源 → 安裝」模型化並登錄至記憶體。E9-06 提供其**逆操作**：把「卸載一個
已安裝套件」的流程模型化——給定記憶體套件登錄與套件識別（package_id = manifest.name），自登錄
移除該套件、清理其資源/元件、處理相依（若他人仍相依此套件則拒絕或警告），並回報卸載結果與被
移除的項目。查無套件、相依阻擋一律明確報錯、絕不靜默。相位 1 平台中立：無真實檔案系統刪除，
登錄為記憶體模型。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::package`（與 E9-01 一致） | 依規格「命名空間與 E9-01 一致」 |
| 卸載目標 | `PackageRegistry`（記憶體，以 manifest.name 為鍵、不覆寫，支援 `remove` + `dependents_of`） | E9-07 `InstallRegistry` 的對稱體；depends_on 僅 E9-01（不含 E9-07），故自帶而非改上游 |
| 相依模型 | 登錄期的圖：`add(pkg, depends_on)` 記錄本套件相依哪些其他套件 id | E9-02 `requires` 是「所需能力 id」非「相依哪個套件」；套件間相依屬登錄期關係 |
| 相依阻擋 | `dependents_of(id)` 反向查詢；有相依者 → `BlockedByDependents` 並列出全部相依者 | 「若他人仍相依此套件則拒絕」；列出相依者、明確不靜默 |
| 相依警告態 | `force=true` 仍卸載，但附警告並於 `blocked_by_dependents` 記錄被留下的懸空相依 | 滿足規格「拒絕**或警告**」二態 |
| 查無套件 | `NotFound`（stage=Located）；重複卸載第二次亦為 NotFound | 明確報錯不假裝成功、不靜默 |
| 生命週期 | `UninstallStage` Located→DependencyChecked→Cleaned→Deregistered + `UninstallLifecycleListener` | 逐階段回報；`stage` 於失敗時指出失敗處 |
| 回報被移除項目 | `UninstallResult.removed{ package_id, components[] }`，components 來自 `Package.entries` | 「回報卸載結果與被移除的項目」；反登錄前先快照 |
| 清理語意 | 相位 1 = 自記憶體登錄登出內含項目清單 | 無真實檔案刪除；相位 2 換真實資源刪除後端，介面不動 |

平台中立：無 `#ifdef`、無 `win32`/`cocoa`、無系統呼叫、**無真實檔案系統刪除**，符合 engine 層
「換平台一行不動」與相位 1 約束。
