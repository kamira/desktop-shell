## Motivation

宣告式格式從第一版就帶 `format_version`（見 E7-01 / E9-02，依 `ai-guideline.md` §3 Q3）。格式會
演進——欄位改名、結構重組、預設值變更。當一份既有設定文件的版本**落後**於實作能理解的版本時，
系統不能直接拒絕（會讓舊設定全數失效），也不能靜默假裝相容（會以新程式碼誤讀舊結構）。正確做法
是**遷移**：把舊版結構逐步升級到新版。

本單元提供一組**遷移鏈**機制：註冊「從版本 X 升級到版本 Y」的步驟，`migrate()` 依文件的
`FormatVersion` 找出一條可達目標版本的路徑並依序套用，產出升級後的 `Value` 與新版本標記。
邊界情況（無可用路徑、版本過新）一律明確報錯，不靜默（NFR-04 精神）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 步驟模型 | `Migration{from, to, transform}`；`transform: Value -> Value`（純函式，可為空） | 一步一版本、結構轉換與版本標記解耦；空 transform = 結構相容僅升版本標記 |
| 步驟約束 | 必嚴格上升（`from < to`）；`register_migration` 拒絕非法步驟回 false | 不允許降級 / 自環；契約違反不靜默登錄 |
| 版本序 | 補 `version_less`（(major,minor) 字典序）+ `version_to_string`（E7-01 `FormatVersion` 僅有 `==`/`!=`） | 路徑推進需要序關係；不改上游，於本命名空間補自由函式 |
| 路徑搜尋 | 以步驟為有向邊、`FormatVersion` 為節點，**BFS 最短鏈** | 支援多步鏈、分支鏈；存在直達捷徑時優先取最短、決定性（掃描依註冊順序） |
| 已是最新版 | `current == target` → no-op，回成功但 `migrated()==false`、值原封不動 | 冪等；重複遷移安全 |
| 版本過新 | `current > target` → `MigrateStatus::TooNew` 明確報錯 | 實作不降級；文件比實作新時明確拒絕（不靜默、不誤讀） |
| 無路徑 | 鏈斷 / 無邊抵達 target → `MigrateStatus::NoPath` 明確報錯 | 缺遷移步驟時明確失敗，附來源 / 目標版本與訊息 |
| 結果型別 | `MigrateResult`（成功持 `value`+`version`+`migrated`；失敗持 `MigrateError`），二者互斥 | 承 E7-01 `ParseResult` 風格：成功 / 失敗不混用可疑預設值 |
| Document 便捷 | `migrate(Document, target)` 以 `doc.format_version` 為來源 | 直接銜接 E7-01 `parse()` 產出的文件 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端。engine 層與平台無關
（非 `src/kernel/backend/`，不涉 backend_guard）。核心 API 不含絕對座標 / 數字 z-order（NFR-02 無涉）；
不含能力閘控呼叫（純邏輯轉換），無 `has()` 降級路徑需求（NFR-03 無涉）。
