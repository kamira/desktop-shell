# CHG-20260724-e1_19 — 顯示器熱插拔復原（E1-19）

- Date: 2026-07-24 | Branch: feat/e1_19 | Risk: low | Implemented by: I1.84
- Skill: ai-sdlc-autopilot

## Motivation
E1-19「顯示器熱插拔復原」是 platform 層（子系統 kernel）的復原邏輯：處理**顯示器熱插拔**
（接上 / 拔除螢幕、解析度 / 排列變更）後的**佈局復原**——偵測顯示器拓撲變更、以每一顯示器
組態為單位記憶各具名螢幕的視窗 / 元件佈局、拓撲恢復時還原對應佈局、新顯示器給預設佈局。
相位 1（Mac / null 期）**絕不接真實顯示器 API**（無 CGDisplay / EnumDisplayMonitors /
cocoa / `#ifdef`），**不建 backend/win32|cocoa**；以 **E1-18 的具名螢幕拓撲抽象** +
**可注入的 E5-08 系統事件源**實作純復原邏輯，狀態全存記憶體。真實顯示器列舉留待後端相位。

## Impact

### 新增 `src/kernel/e1_19/`（platform 層 / 子系統 kernel）
- `layout_recovery.hpp` / `layout_recovery.cpp`（`namespace ds::kernel`）：
  - `topology_key(const ScreenRegistry&) → std::string`：由具名 ScreenId **排序後串接**導出的
    穩定「拓撲簽章」，與後端列舉順序無關——「拔除後重接同一組螢幕」不論以何順序列舉皆導出
    相同簽章，故拓撲恢復可被辨識並據以還原對應組態佈局。空拓撲回空字串。
    NFR-02：純具名、無座標 / 數字 index / z-order。
  - `LayoutRecoveryManager<Layout>` 樣板（Layout = 呼叫端提供的平台中立佈局表示；沿用 E1-18
    `PerScreen<T>` 泛型哲學，本單元不引入任何座標型別）：
    - 建構時以注入的 `TopologyProvider`（`std::function<ScreenRegistry()>`）取一次當前拓撲，
      並**訂閱注入的 E5-08 `SystemEventSource`**；解構時解除訂閱。
    - **事件驅動**：僅 `SystemEventType::DisplayChanged` 觸發拓撲重算（其餘系統事件忽略）；
      重算後呼叫可選的 `on_recover(const ScreenRegistry&)` 回呼，消費者於回呼中對各具名螢幕
      呼叫 `layout_for()` 取回應套用的佈局。
    - `record(id, layout)`：於**當前組態**記錄某具名螢幕佈局（同組態同螢幕後記錄者為準）。
    - `layout_for(id)`：有記錄回記錄（**復原**）；無記錄（含**全新顯示器**）回**預設佈局**。
      以 find/has 保護（NFR-03），未知一律保守回預設、不崩。
    - 多組態記憶：佈局以「拓撲簽章 → `PerScreen<Layout>`」保存，各組態彼此獨立；被**拔除**的
      螢幕其記錄保留於原組態，**重接即復原**。輔以 `has_recorded` / `recorded_screen_ids` /
      `active_topology_key` / `active_screen_ids` / `is_active_screen` / `remembers_topology` /
      `topology_count` / `default_layout` / `clear`。不可複製（持有訂閱與來源指標）。
  - `CMakeLists.txt`：`add_library(e1_19)` **PUBLIC 連上游 `e1_18` `e5_08`**（標頭對外暴露其型別，
    須傳遞 include 目錄）；`test_e1_19` + `add_test(NAME e1_19)`。
- 上游相依（已合併，可讀不可改）：E1-18 具名螢幕（`ScreenRegistry` / `PerScreen<T>` / `ScreenId`）、
  E5-08 系統事件（`SystemEventSource` / `NullSystemEventSource::inject` / `DisplayChanged`）。
- **無** `#ifdef` / win32 / cocoa / CGDisplay / EnumDisplayMonitors / 真實顯示器 API；**未建**
  `src/kernel/backend/win32|cocoa/`（backend_guard 綠燈）。純邏輯、平台中立、狀態存記憶體。

### 測試 `tests/e1/test_e1_19.cpp`（gtest，13 案例）
- 拓撲簽章（1）：具名導出、與列舉順序無關、空拓撲空字串。
- 初始拓撲（1）：建構時即由 provider 取當前拓撲。
- **經 E5-08 事件驅動**（2）：DisplayChanged 觸發拓撲重算 + on_recover；非顯示器事件忽略。
- **佈局記錄 / 復原往返**（1）：組態 A 記錄 → 切 B → 反序重接回 A 還原 → 再切 B 仍在。
- **新顯示器預設佈局**（1）：全新組態的螢幕回預設。
- 保守語意（1）：無記錄 / 未知螢幕回預設（NFR-03）。
- **拔除處理**（1）：拔除螢幕記錄保留於原組態、重接還原。
- **多組態記憶**（1）：組態數量、各組態獨立列舉互不干擾。
- 記錄覆蓋（1）、clear 清空不動當前拓撲（1）、解構解除訂閱（1）、泛型結構佈局載荷（1）。
