# CHG-20260724-e1_11 — 從屬 surface 相對定位（E1-11）

- Date: 2026-07-24 | Branch: feat/e1_11 | Risk: low | Implemented by: I1.109
- Skill: ai-sdlc-autopilot
- Unit: E1-11（從屬 surface 相對定位，platform 層 / kernel 子系統 / phase=1 / risk=low / depends_on=[E1-07] / load_bearing=2）

## Motivation

桌面外殼有大量 **從屬（subordinate）surface**：tooltip、下拉選單、子面板等——它們不是獨立存在的
頂層 surface，而是**依附於某個父 surface**才有意義。父移動時（例如視窗被拖曳），子必須跟著移動；
父關閉時，子若還留著就成了孤兒 surface（畫面上飄著一個沒有主人的浮層）。若子的位置以**絕對螢幕
座標**表達並在父移動時手動同步，會違反 NFR-02，且同步邏輯容易漏寫、產生孤兒 surface 的 bug 類別。

E1-11 提供 **`SubordinateLayout`**：以 E1-07 的具名 anchor + 相對偏移表達子相對父的定位，父子
關係與定位規格皆為宣告式記錄；子的絕對佈局永遠是**當下**父矩形的即時解析結果（非快取的絕對
座標），父移動子自然跟隨；並提供 `close_parent()` 遞迴清除父關閉時的所有子孫附著，不留孤兒。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 附著記錄 | `SubordinateLayout`：以具名 `SurfaceId` 為鍵配對 `{child, parent, AnchorSpec}` | 風格對齊 E1-07 `AnchorLayout` / E1-03 `AlphaSurfaceService` 的具名鍵記錄配對 |
| 定位規格 | 直接複用 E1-07 `AnchorSpec`（具名 anchor + 正規化相對偏移），不重新發明佈局數學 | NFR-02：子相對父以具名 anchor + 相對偏移表達，無絕對座標；且與頂層 surface 定位（E1-07）共用同一套宣告式詞彙 |
| 相對定位語意 | `resolve_child(child, parent_placement, child_element, out)`：把父的**已解析矩形**當作 E1-07 `resolve()` 的 `container`，在其局部座標系解析子位置後平移 `(+parent.x, +parent.y)` | 讓子的位置永遠是「相對父」的即時計算，不快取絕對座標——父矩形換了，下次呼叫自然得到新位置（父移動子跟隨的實作方式，非事件同步機制） |
| offset 可超出父邊界 | 沿用 E1-07 `Offset` 不 clamp 到 [0,1]，故 `BottomLeft` + 正 `dy` offset 可把子推到父下緣**之外**（下拉選單貼齊按鈕下方的典型佈局） | 子（tooltip/dropdown）語意上常長在父邊界外側，非局限於父的內部子區域；沿用既有 E1-07 機制即可表達，無需新型別 |
| 父關閉連帶 | `close_parent(id)`：先清除 id 自身的附著記錄（若 id 本身也是別人的子——巢狀從屬鏈），再廣度優先遞迴清除其下所有直接 / 間接子附著；回傳實際清除筆數 | 「父關閉子連帶」的明確語意；不留孤兒附著；支援任意深度的巢狀從屬鏈（dropdown → submenu → subsubmenu） |
| 無效附著 | `attach()` 對 child/parent 空字串、child==parent（自附）、或會造成循環附著（`would_cycle`：從候選 parent 沿既有附著鏈往上追溯是否繞回 child）一律回 `AnchorStatus::Invalid`，不記錄 | 規格硬項「無效附著(自附/循環)報錯不靜默」；循環附著若放行會使 `resolve_child` 的父矩形解析陷入邏輯死結（父的父的父…繞回自己） |
| 結果碼 | 復用 E1-07 `AnchorStatus`{Ok, Invalid}，不新增列舉 | 與上游同風格；`resolve_child` 對非有限父矩形 / 子尺寸的錯誤語意直接委由 E1-07 `resolve()` 判定，不重複造輪子 |
| spec 合法性判定 | `is_valid_spec()` 以 `resolve(spec, Size{1,1}, Size{0,0}, probe)` 探測（E1-07 的判定邏輯是其 cpp 內匿名命名空間私有符號，不可直接呼叫），避免重寫一份容易與上游脫節的判定 | 只讀複用上游行為，不觸碰上游實作 |
| `reposition` | 只更新 spec，不改變 parent（換父需呼叫 `attach()`，其對同 child 的呼叫語意本就是就地更新，可換 parent） | 區分「調整同一附著的定位規格」與「重新附著到不同父」兩種操作意圖 |

## Impact

### 影響分析（low 風險，load_bearing=2）

- **回溯相容**：純新增單元。未改任何既有 `src` / `engine` / `modules` / 上游單元（E1-07 及其傳遞
  依賴 E1-03 / E1-21 / backend_null）/ `units.json` / 根 CMakeLists / 共用 `directory.md`；對既有
  單元零影響。
- **上游耦合**：僅**唯讀**依賴 E1-07（`target_link_libraries(e1_11 PUBLIC e1_07)`），透過其 include
  鏈取得 `Anchor` / `AnchorSpec` / `Size` / `ResolvedPlacement` / `AnchorStatus` / `resolve()` 及傳遞的
  `SurfaceId`。不觸碰上游任何符號實作，不加虛擬方法；純以組合複用。
- **NFR-02（核心 API 不得絕對座標 / 數字 z-order）**：`SubordinateLayout` 的附著記錄
  （`SurfaceId child/parent` + `AnchorSpec`）**不含任何像素座標欄位**；具體像素只在
  `resolve_child()` 的**輸入**（呼叫端提供的父已解析矩形 / 子元件尺寸）與**輸出**（計算結果）出現，
  非宣告式附著 API 的一部分。
- **下游意義**：`SubordinateLayout` 會成為 tooltip / 下拉選單 / 子面板等從屬 UI 的共同定位基礎設施；
  搭配 E1-07 `AnchorLayout`（頂層 surface 定位）組合使用——先以 `AnchorLayout` 解出頂層父的絕對矩形，
  再以 `SubordinateLayout::resolve_child` 逐層解出子（甚至孫、曾孫）的絕對矩形，支援任意深度的巢狀
  從屬鏈。
- **建置面**：新增靜態庫 `e1_11`（`PUBLIC` 連 `e1_07`）與可執行檔 `test_e1_11` + CTest `e1_11`。
  根 CMakeLists 既有層級 GLOB（`src/*/*/CMakeLists.txt`，深度 2）已涵蓋
  `src/kernel/e1_11/CMakeLists.txt`，**無需**改根建置檔。
- **相位閘門**：未建立 `src/kernel/backend/win32|cocoa/`，無 `#ifdef` / 真實 OS / 繪圖 API，
  `backend_guard`（G1b）不觸發；純記憶體 / 純佈局邏輯無平台分支。

### 測試（gtest，21 案例 / 120 checks）

附著子到父 + anchor（記錄 / 就地更新 / 空 id / 無效 spec 拒絕）；`resolve_child` 依父已解析矩形
正確計算並平移（含 offset 超出父邊界的下拉選單式定位）、未知 child / 非有限父矩形或子尺寸 →
Invalid 不寫 out；父移動子跟隨（同附著在不同父矩形下重新解析得到不同絕對位置，含尺寸改變的比例
重算）；`detach`（移除單一附著不影響其餘、未知 child 結構化回報）；`reposition`（更新 spec 保留
parent、未知 child / 無效 spec 拒絕且不變更既有記錄）；`close_parent`（直接子連帶、巢狀多層
子孫連帶 + 自身、無關附著不受影響、id 無附著回 0）；自附拒絕、二節點循環拒絕、三節點循環拒絕、
既有鏈重新附著造成循環拒絕；多子並存（同 parent 下多個 child 互不干擾，個別 detach 不影響其他）；
NFR-02 具名 + 相對表達（同附著套不同父矩形，相對比例一致）。
