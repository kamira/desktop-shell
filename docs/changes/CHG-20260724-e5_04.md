## Motivation

閒置動畫、定時輪詢等消費者需要一個穩定的「週期性脈衝」來源：每隔固定間隔取得一次
觸發。若直接綁真實 OS 計時器，則邏輯無法在單元測試中重現（時間不可注入、觸發次數
不可斷言），也違反 engine 層「平台中立、換平台一行不動」的分層要求。

E5-04 提供一個平台中立的心跳來源：時間以「邏輯時間 / tick」計，由呼叫端注入推進，
到期的訂閱者以事件形式被通知。時鐘的真實來源（真實計時器、frame loop、測試注入）
與心跳邏輯解耦，因此可完全以單元測試驗證。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 時間模型 | 邏輯時間 / tick（`advance(dt)` 推進），非真實時鐘 | engine 層須平台中立、可注入時間、可斷言觸發次數 |
| 到期語意 | 累計 accumulator，跨過 interval 即觸發，餘量保留 | 不丟脈衝、不漂移；單次大步推進可多次觸發 |
| 訂閱模型 | `subscribe(interval, cb)` 回配發 id；`unsubscribe(id)` | 標準發布 / 訂閱；id 單調遞增不重用 |
| 派發時機 | 先結算所有訂閱狀態、收集到期事件，再統一觸發回呼 | 回呼中訂閱 / 取消訂閱不會破壞正在進行的派發 |
| 無效輸入 | `interval == 0` 拒絕並回無效 id 0；`advance(0)` 為 no-op | 保守、可預期 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實計時器 / 後端。
