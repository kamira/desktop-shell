## Motivation

使用者需求：「依附在本 shell 的程式，並且形成出 widget 浮動在桌面上」——
不是主控台 ASCII 模擬，是真的桌面浮層。

這也是整個平台論述的最終檢驗。`docs/ai-guideline.md` §1 寫得很直接：
**「本 repo 的產品是平台，不是桌面工具。驗收條件不是能不能顯示一個 CPU 掛件，
而是能不能在不修改平台任何一行的前提下，讓外部加上一個 CPU 掛件。」**
本單元**未改 `src/` / `engine/` / `modules/` 任何一行**，純從已合併單元的公開介面組裝。

MetricRegistry/InMemoryMetric · E4-03 BarGauge · E4-01 TextLayout · E7-01 Value。

指標來源：CPU 用 `GetSystemTimes` 差分、RAM 用 `GlobalMemoryStatusEx`，皆為**真實主機數值**；
GPU 目前無跨廠商的免驅動查詢途徑，以動態 sweep 佔位（重點是證明 widget 對任意指標皆能呈現）。

### 為什麼繪製橋接在 `host/` 而不在 win32 後端裡

兩個獨立理由，任一都足以決定：

1. **分層**：它吃 E4-03 的 `ds::elements::RenderModel`（engine / module 層型別）。
   放進 platform 層會造成 **platform 反向依賴 engine**。
2. **NFR-02**：繪製必然涉及座標，而 kernel 契約硬性禁止絕對座標——
   繪製**不可能**成為契約的一部分，只能活在契約之外。

後端只管視窗 / 圖層 / 輸入，並額外提供 win32 專屬的 `hwnd_for()` 供 host 取得原生視窗。

### 可測試性設計

版面計算（`row_layout` / `fill_rect`）抽成**不碰 GDI 的純函式**；
繪製本體以**記憶體 DIB**（`CreateDIBSection`）測試，可以真的讀像素。
因此斷言的是「量表長度真的跟著 fill_ratio 走」，不只是「沒有崩潰」。


## 已知限制

- **沒有正常的關閉入口**：托盤選單屬後續單元，目前以 `--seconds N` 自動結束或由工作管理員結束。
- **不在任何 CI 閘門守備範圍**：`if(WIN32)` 讓 ubuntu 看不到本單元（否則 G3 必紅），
  正確性只有本機 Windows 證據。需 windows runner（checklist 步驟 3）。
- GPU 為模擬值，非真實 GPU 使用率。
- 尚無：拖曳移動、點擊穿透的 UI 切換、設定持久化、skin 套件格式。
