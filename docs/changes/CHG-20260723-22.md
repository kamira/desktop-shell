# CHG-20260723-22 — root CMakeLists 加收 tests/contract/，解鎖跨後端契約測試組 E1-25

- Date: 2026-07-28 (UTC+0) | Branch: chore/contract-glob | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation
工作單元 **E1-25「kernel 後端契約測試組（所有後端共用）」** 的 `write_scope` 只有
`tests/contract/**` 與其 CHG——它**沒有** `src/`、`engine/`、`modules/` 底下的單元目錄，
因此不會被 root `CMakeLists.txt` 現有的三條 GLOB（`src|engine|modules/*/*[/*]/CMakeLists.txt`）收入。
結果：E1-25 交付的契約測試無法被 CMake 加入建置，CI 的 G3（`ctest`）永遠看不到它，
等於這個 lb=3 的解鎖點無法通過。root CMakeLists 不在任何單元的 write_scope 內
（見本檔頂部註解「單元不需、也不得改本檔」），故由 I1 以 bootstrap infra 變更補上。

## Impact（`CMakeLists.txt`）
在 `file(GLOB _unit_cmakes ...)` 增加兩行，收入 `tests/contract/` 下的 CMakeLists：
```cmake
  "${CMAKE_SOURCE_DIR}/tests/contract/CMakeLists.txt"      # 深度 1：契約組總表
  "${CMAKE_SOURCE_DIR}/tests/contract/*/CMakeLists.txt"    # 深度 2：分後端/分主題子目錄（彈性）
```
- 沿用既有「明確層級 GLOB、每個 `*` = 一段路徑」的風格，不引入 `**` 遞迴 glob，穩定不誤收。
- E1-25 可於 `tests/contract/CMakeLists.txt` 放契約測試的 `add_executable`+`add_test`（或再切子目錄），
  被本 GLOB 收入後與其他單元一致經 `add_subdirectory` 納入建置。
- 既有三條 GLOB 與其餘建置邏輯（FetchContent GoogleTest、foreach add_subdirectory、計數訊息）皆未動。

## 明確不改
- 未動任何單元的 `write_scope`、未動 `units.json`、未動 8 道閘門 workflow。
- 未改 `src/kernel/backend/null/` 相關規則：E1-24 null 後端（`src/kernel/backend/null/**`）本就被既有
  `src/*/*/*/CMakeLists.txt`（深度 3）涵蓋，且 `backend_guard`（G1b）只擋 `win32|cocoa`、放行 `null`，無需改動。
- 未先建 `tests/contract/` 目錄或任何 CMakeLists——交由 E1-25 於其 write_scope 內建立；
  在 E1-25 落地前，這兩條 GLOB 命中 0 檔、不影響現有建置。

## Status
Accepted — self-verified (low risk)。

## Verification
- `file(GLOB)` 對不存在的路徑回空集合，故在 E1-25 落地前本變更對建置為 no-op（現有單元收入數不變）。
- CMake 語法：兩行為既有 GLOB 引數清單的同型延伸，括號/引號閉合正確。
- 效果：E1-25 一旦於 `tests/contract/CMakeLists.txt` 提供 `add_test(...)`，root CMake 即自動收入，
  CI 的 `ctest` 可見其測試，G3 可通過 → 解鎖 E1-25（lb=3）及其下游後端契約鏈。
- 分支 `chore/contract-glob` 非 feat/ 單元分支，`plan.py unit-for-branch` 查無對應單元，
  預期 gate 於 branch-lookup 紅燈；由 I1 以 `gh pr merge --admin` 併入（bootstrap infra 慣例，同 CHG-17~21）。
