# CHG-20260724-e4_16 — 輸入建議與補全呈現（E4-16）

- Date: 2026-07-24 | Branch: feat/e4_16 | Risk: low | Implemented by: I1.151
- Skill: ai-sdlc-autopilot
- Unit: E4-16（輸入建議與補全呈現，module 層 / 子系統 elements / phase 1 / low，
  depends_on=[E4-01, E4-15]）

## Motivation

桌面外殼的就地輸入框（E4-15）需要一個「輸入建議 / 自動補全」的呈現層：依輸入框綁定，
顯示一份候選清單(下拉/浮層)，讓使用者以鍵盤上下選取、Tab/Enter 套用。相位 1 不做真實
比對 / 過濾 / 排序演算法（候選清單由呼叫端注入），本單元專注於「呈現 + 選取邏輯 + 套用」
三件事——真實建議來源（檔名補全、指令歷史、模糊比對等）留待呼叫端或後續相位接上，
本單元介面不受影響。

E4-16 提供 `SuggestionPopupElement`：持有一份呼叫端注入的候選字串清單與目前選取索引；
以上游 E4-01 `TextLayout` 逐項排版候選文字（單行）；綁定上游 E4-15 `TextInputElement`
作為 `accept()` 套用補全的目標；`render_model()` 產出「各候選項排版 + 選取標記」的完整
渲染描述，全部相對佈局（NFR-02）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 候選清單來源 | `set_suggestions(vector<string>)` 整段取代注入；本單元不做比對/過濾/排序 | 符合規格「相位 1 建議候選由呼叫端提供(注入)」；本單元責任邊界清楚（呈現+選取），不越界猜測比對規則 |
| 選取模型 | 單一 `selected_index_`（非錨點+游標，因建議清單無「範圍選取」語意，只有單項高亮） | 與 E4-15 的錨點/游標選取模型不同語意層級：候選清單只需「目前選到哪一項」 |
| 空清單處理 | `visible()` = 清單非空；`render_model()` 於空清單回傳 `visible=false`、`items` 為空（**非例外**——「無建議」是合法呈現狀態） | 呈現查詢類 API（render_model）容許空狀態；但下方選取/套用類操作在空清單下屬呼叫端狀態錯誤 |
| 空清單下的選取/套用不靜默 | `move_selection()`/`accept()`/`selected_index()`/`selected_text()` 於空清單呼叫 → `std::logic_error` | 對應規格「空建議…處理不靜默」；這些方法表達呼叫端明確的選取/套用/讀取意圖，無候選項下屬呼叫端錯誤 |
| 越界索引不靜默 | `set_selected_index(i)`，`i >= count()`（含清單為空、`count()==0` 時任何索引）→ `std::out_of_range` | 對應規格「…越界選取處理不靜默」；不夾限、不靜默忽略 |
| 方向移動的邊界語意 | `move_selection()` 於非空清單的邊界（已在首/末項）為安全無動作(no-op) | 屬正常導覽語意，與 E4-15 `move_cursor` 邊界處理同構——no-op 不是「靜默吞錯」，而是導覽在邊界的正常行為；與上一列的「顯式索引越界」職責區分（同 E4-15 標頭「已知簡化」的區分手法） |
| 套用補全 | `accept()` 呼叫綁定 `TextInputElement::set_text(選取候選文字)` 整段取代輸入框內容；套用後清單清空、選取歸零（彈出視為關閉） | 相位 1 簡化：就地輸入框預設單行語意，整段取代最直接且無歧義；呼叫端若需要「僅取代目前字詞」可自行以 E4-15 既有 `select`+`insert` 組合，本單元不猜詞界規則（已於標頭「已知簡化」註明） |
| 候選項排版 | 每個候選字串各自呼叫 `TextLayout::layout(text, single_line_constraints())`（重用 E4-15 匯出的 `single_line_constraints()`） | 不重新發明單行約束；候選項天然是單行文字，直接複用既有語意 |
| 相對佈局 | `SuggestionItemRenderModel::y = index × row_height`（`row_height` 取自 `FontMetrics::line_height()`），無絕對座標 | NFR-02：與 E4-01 `LineBox::y`（行索引 × 行高）語意一致，僅換算層級從「排版內的行」變成「清單內的項」 |
| 鍵盤整合 | `attach(KeyboardInputSource&)` 訂閱按鍵頻道；`handle_key()` 亦可直接呼叫（測試/手動驅動）：ArrowUp/ArrowDown → `move_selection`；Tab/Enter → `accept`；其餘鍵忽略 | 對應規格「鍵盤上下選、Tab/Enter 套用補全」；沿用 E4-15 的注入式事件模式，相位 1 無真實鍵盤 |
| `handle_key` 於彈出未顯示時的行為 | 直接 return（不呼叫 `move_selection`/`accept`），不擲例外 | 事件是否到達由呼叫端狀態決定，屬正常事件分派語意——與「呼叫端顯式呼叫 move_selection/accept」的不靜默要求分屬不同責任層級（同 E4-15 `handle_key` 忽略未知鍵的精神），否則彈出關閉後任何殘留按鍵事件都會意外拋出例外，不合理 |
| E5-13 相依取得方式 | 不在 `CMakeLists.txt` 另外 `target_link_libraries` e5_13；改由 e4_15 的 `PUBLIC` 連結轉遞取得 `KeyboardInputSource`/`KeyEvent` 型別的 include 目錄與符號 | 符合硬性限制「CMakeLists 只能 `target_link_libraries(e4_16 PUBLIC e4_01 e4_15)`」；CMake `PUBLIC` 相依本就會遞移傳遞給下游，經本機 g++ 編譯驗證確實可行（見下方 Verification） |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支，不含任何真實鍵盤 / IME
API，不含螢幕絕對座標或數字 z-order。
