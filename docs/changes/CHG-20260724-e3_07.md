# CHG-20260724-e3_07 — 剪貼簿寫入（E3-07）

- Date: 2026-07-24 | Branch: feat/e3_07 | Risk: low | Implemented by: I1.52
- Skill: ai-sdlc-autopilot

## Motivation
E3-07「剪貼簿寫入」是 modules/actuators（動作層 / 子系統 actuators）的一個**系統剪貼簿寫入
致動器**：把「寫入剪貼簿（純文字 / HTML / 影像參照）／清空剪貼簿／回讀目前內容」這組副作用，
以具名命令掛上 **E6-01 命令匯流排**（擴充點 3「動作」契約）。呼叫端只需 命令 id + 具名參數
即可觸發，**不需相依本致動器或任何 OS 剪貼簿 API**——與已合併的 E3-05（音量設定致動器）
採同一「注入式後端 + null 樣式」範式。相位 1（Mac / null 期）**絕不呼叫真實 OS 剪貼簿 API**
（不含 NSPasteboard / OpenClipboard / SetClipboardData / cocoa / win32 等），只提供**平台
中立介面 + null / 假後端（純記憶體狀態模擬，可 read 驗證）+ 契約測試**；真實平台後端留待
相位 2，屆時致動器與命令契約一行不動。

## Impact

### 新增 `modules/actuators/e3_07/`（module 層 / 子系統 actuators）
- `clipboard_write_actuator.hpp` / `clipboard_write_actuator.cpp`（`namespace ds::actuators`，
  與 e3_05 一致）：
  - 三個具名命令 id（穩定可讀字串，不用數字 opcode）：`clipboard.write` /
    `clipboard.clear` / `clipboard.read`。
  - `ClipboardContentType` enum：`Empty` / `PlainText` / `Html` / `ImageRef`（多資料型別，
    平台中立，不含 OS UTI / 格式碼；相位 2 後端負責映射到平台格式）。
  - `clipboard_type_name()` / `clipboard_type_from_string()`：型別 ↔ 穩定字串轉換
    （命令 `type` 參數用 text/html/image；`empty` 不是可寫入型別，清空由 clipboard.clear
    表達，故解析時拒絕）。
  - `ClipboardData` struct：`type` + `content`（字串；影像型別時為影像參照，非位元組）；
    含相等運算子、`empty()`、`empty_data()` 工廠，供查詢 / 內省。
  - `ClipboardBackend` 抽象後端：最小介面 `write(ClipboardData)` / `clear()` /
    `read()`（可回讀供驗證 / 診斷）。相位 2+ 由平台後端以真實剪貼簿 API 實作；致動器只
    依賴此抽象。契約：傳入 `write()` 的 data 已由致動器合法化（型別非 Empty、content 非空）。
  - `NullClipboardBackend`（相位 1 預設後端）：**不接真實系統剪貼簿 API**，以純記憶體狀態
    （型別 + 內容字串）模擬；初值可注入（預設空剪貼簿）；`read()` 回目前狀態、`state()`
    內省。讓致動器在無真實後端時仍可完整跑通、狀態一致。
  - `ClipboardWriteActuator`：建構綁定一個 `ClipboardBackend`（預設 NullClipboardBackend）。
    `register_on(bus)` 把三個具名命令註冊到 E6-01 匯流排（全成功才 true；任一失敗回滾
    已掛者、不遮蔽既有致動器；無後端回 false）；`unregister_from(bus)` 回移除數（0..3）。
    處理器亦可直接呼叫（測試不經匯流排也能驗證語意）：
    - `clipboard.write`：必填 `content`（string，非空）；選填 `type`（string：
      text/html/image，預設 text）；缺 / 型別錯 / 空 content / 無效 type → Failed。
      成功回 value=寫入內容、message=型別名。
    - `clipboard.clear`：無參數；清空剪貼簿（狀態轉 Empty + 空內容）；回 Ok（message="cleared"）。
    - `clipboard.read`：無參數；回目前內容（value=內容字串、message=型別名），供驗證。
    缺 / 型別錯 / 空 / 無效的必填參數 → `CommandResult{Failed}`（以 `has()` / `get_string`
    保護，不崩潰、不改後端狀態、不丟例外）。
  - `clipboard_write_contract_version()`：契約版本標記 `"e3_07/1.0.0"`（定義在 .cpp，使
    STATIC 程式庫非空並集中版本字串；命名加 `clipboard_write_` 前綴避免與同命名空間其他
    致動器的版本函式衝突）。
  - `CMakeLists.txt`：`add_library(e3_07 STATIC clipboard_write_actuator.cpp)` **PUBLIC 連
    上游 `e6_01`**（標頭 include `command_bus.hpp`，須傳遞 include 目錄）；
    `test_e3_07`（`tests/e3/test_e3_07.cpp`）+ `add_test(NAME e3_07)`。
- 上游相依：E6-01 命令匯流排（`ds::command::CommandBus` / `CommandArgs` / `CommandResult` /
  `CommandValue`），可讀不可改——消費擴充點 3「動作」契約，不自造匯流排或值型別。
- **無** `#ifdef` / win32 / cocoa / NSPasteboard / OpenClipboard 等真實剪貼簿 API
  （backend_guard 綠燈）。致動器邏輯（型別 / 內容驗證、分派、結果回報）與後端完全解耦、
  純邏輯、平台中立、可注入。

### 測試 `tests/e3/test_e3_07.cpp`（gtest，24 案例）
- 註冊 / 反註冊（4）：三命令全掛、重複註冊回滾且不改既有、null 後端不可註冊、
  unregister 移除全三個且再呼叫回 0。
- 寫入文字 + 分派 + null 後端一致（3）：經匯流排 write 更新後端（read 驗證同值同型別）、
  read 反映先前 write、顯式 text 型別。
- 多資料型別（3）：寫 HTML、寫影像參照、後寫覆蓋前寫（型別亦更新）。
- 清空（1）：clear 後 Empty + 空內容，read 回 message="empty"，read 驗證一致。
- 參數驗證（5）：缺 content / content 型別錯 / 空 content / 無效 type / type 參數型別錯
  → Failed 且不改後端狀態。
- 未知命令（1）：匯流排回 NotFound（不崩潰）。
- null 後端狀態一致（2）：連續 write / read / clear 後一致；注入初值。
- 直接呼叫處理器（2）：write 語意等價；無後端各處理器回 Failed。
- 型別 ↔ 字串轉換（2）：name round-trip；from_string 解析已知 / 拒絕未知 / 空 / `empty`。
- 契約版本標記（1）。
