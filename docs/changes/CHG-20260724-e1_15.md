# CHG-20260724-e1_15 — 視窗級透明度與懸停淡變（E1-15）

- Date: 2026-07-24 | Branch: feat/e1_15 | Risk: low | Implemented by: I1.144
- Skill: ai-sdlc-autopilot
- Unit: E1-15（視窗級透明度與懸停淡變，platform 層 / kernel / low，相依已合併 E1-03
  逐像素 alpha surface + E5-02 懸停進出事件）

## Motivation

桌面元件 / 面板常需要「平時半透明、滑鼠靠近時淡入變不透明、離開後淡出回半透明」的互動
回饋（例如不打擾使用者的浮動工具列、桌寵資訊卡）。上游 E1-03 已提供 surface 的整體不透明
度（`AlphaProfile::opacity`）與能力閘控，E5-02 已提供懸停進出事件（Enter/Leave/Move）；
但兩者間缺一個把「懸停狀態轉換」轉譯為「隨時間平滑變化的不透明度」的服務層，也缺一個把
計算結果實際套用回 E1-03 alpha surface 的黏著點。E1-15 補上這一層：`WindowOpacity` 組合
持有 E1-03 `AlphaSurfaceService&`，設定基準（未懸停）與懸停目標不透明度，訂閱 E5-02
`HoverTracker` 的 Enter/Leave 驅動淡變起停，並以**呼叫端注入的時間**（`advance(dt)`）
推進線性插值 —— 相位 1（Mac / null 期）不綁任何真實 OS 時鐘 / 合成器，全程可測、確定性。

**NFR-02**：不透明度全程以**正規化比例** [0,1] 表達（沿用 E1-03 語意），不引入絕對座標 /
數字 z-order。無效透明度（非有限值）**不靜默**：拒絕並回結構化狀態，不悄悄套用/ 不悄悄
忽略。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 核心類別 | `WindowOpacity`（組合持有 `AlphaSurfaceService&` + `SurfaceId`） | 與 E1-03 `AlphaSurfaceService` 同風格（組合持有後端 / 服務參考，不取得所有權）；本單元只新增「基準/懸停目標 + 淡變」邏輯，套用委由既有 E1-03 API，不重造能力閘控 / opacity 正規化 |
| 淡變演算法 | 線性插值：`fade_from_` → `fade_to_`，經過時間 / `fade_seconds` 為進度，`std::clamp` 至 [0,1] | 與既有 `engine/render/e4_05` `Tween::advance(dt)` 同風格但**不依賴** e4_05（E1-15 的 `depends_on` 僅 `[E1-03, E5-02]`），保持自我完備、不越界引入未宣告的上游相依 |
| 時間推進 | 純注入式 `advance(double dt_seconds)`，dt<0 視為 0；`fade_seconds<=0` 視為瞬時切換 | 相位 1 硬約束：無真實時鐘；風格對齊既有 `Tween::advance` / `TimeoutTimer::advance` 慣例 |
| 懸停事件驅動 | `attach(HoverTracker&)` 訂閱，回呼中僅比對 `event.surface == surface_`，Enter→`start_fade(hover_opacity_)`、Leave→`start_fade(base_opacity_)`，Move/其他 surface 忽略 | 命中判定 / 事件分派完全委由已合併的 E5-02，本單元不重新實作幾何或事件序列邏輯 |
| 設定值即時性 | `set_base_opacity` 於**未懸停**時立即套用（無動畫）並同步；`set_hover_opacity` 於**懸停中**時立即套用；反向情境僅記錄目標值 | 語意上「設定整體透明度」是直接賦值（非動畫），只有懸停事件觸發的轉換才走淡變；避免「設定值」與「淡變過程」的語意混淆 |
| 無效值語意 | 非有限值（NaN/Inf）→ `Invalid`，不套用、不覆蓋既有設定值；有限但超出 [0,1] → clamp（非無效） | 與 E1-03 `AlphaProfile::opacity` 正規化規則一致；「無效透明度處理不靜默」= 非有限值必須被明確拒絕，而非被悄悄 clamp 成任意值生效 |
| 後端套用結果轉發 | `advance()` / 立即套用路徑透過 E1-03 `set_opacity()`，回傳的 `AlphaStatus` 一對一轉發為 `WindowOpacityStatus` | Unsupported（NFR-03 能力閘控）與 Invalid（surface 未於 E1-03 註冊）皆由 E1-03 單一資料來源判定，本單元不重複驗證，`current_opacity()` 仍保留內部計算值供降級路徑查詢 |

不出現絕對硬編座標 / 數字 z-order；不綁任何真實平台後端 / 時鐘；無 `#ifdef _WIN32` /
`win32` / `cocoa` 等平台分支，符合相位 1（Mac/null）與 NFR-02 約束。
