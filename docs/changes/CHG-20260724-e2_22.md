# CHG-20260724-e2_22 — 登錄檔讀取（E2-22）

- Date: 2026-07-24 | Branch: feat/e2_22 | Risk: low | Implemented by: I1.47
- Skill: ai-sdlc-autopilot

## Motivation
E2-22「登錄檔讀取」是 module 層(子系統 sysinfo)的一個**指標提供者**：讀取「系統設定
登錄／組態儲存」（Windows Registry 概念的**跨平台抽象**——鍵路徑 → 值的階層式查詢），
透過 **E2-01 統一指標介面**（擴充點 1 契約）把查得的值掛成一個指標。這正是「新增指標 =
新增 `MetricProvider`、掛件一行不動」機制的一個具體實例——它**消費 E2-01 契約、不自造
指標模型**。相位 1（Mac / null 期）**絕不接**真實 Registry / `defaults` / win32 /
`#ifdef`；改為**可注入 `RegistrySource` 抽象** + null/假來源（記憶體樹）。真實登錄後端
留待後端相位。查無鍵 / 型別錯**明確回報、不靜默**。

## Impact

### 新增 `modules/sysinfo/e2_22/`（module 層 / 子系統 sysinfo）
- `registry_read.hpp` / `registry_read.cpp`（`namespace ds::sysinfo`）：
  - `RegistryType` enum：`String` / `Integer` / `Binary`（Windows REG_* 概念的跨平台最小集）。
  - `RegistryValue`：型別標記載體。工廠 `makeString` / `makeInteger` / `makeBinary`；具型別
    存取器 `as_string` / `as_integer` / `as_binary` 在**型別不符時回 `std::nullopt`**
    （明確回報型別錯，不硬轉、不靜默）；含相等運算子。
  - `RegistrySource` 抽象後端：`read(path) → optional<RegistryValue>`（查無鍵回 `nullopt`）、
    `enumerate(path) → vector<string>`（直屬子項名稱、決定性順序）。路徑以 `/` 分段
    （跨平台一致，與具體 OS 分隔符解耦）。真實平台後端於相位 2+ 實作；提供者只依賴此抽象。
  - `NullRegistrySource` null/假來源：以記憶體內「路徑→值」映射模擬階層式儲存。**不接
    真實登錄**，預設空樹（讀任何鍵皆回 `nullopt`）；`set_value` / `remove` / `clear` 注入
    假資料供測試與假感測器情境；`enumerate` 由已存值路徑之前綴推導直屬子項（`std::set`
    去重 + 字典序，決定性）。
  - `registryValueToMetric()`：讀取結果 → E2-01 `MetricValue` 的對映——`nullopt`（查無鍵）
    → `unknown()`（valid==false）；`Integer` → `of(數值, 十進位文字)`；`String` →
    `of(0.0, 文字)`；`Binary` → `of(0.0, "<binary:N bytes>")`。
  - `RegistryReaderProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.registry"`；以 `source` + 「要暴露的鍵路徑清單」建構；
    `register_metrics(registry)` 向 E2-01 註冊表掛上單一指標 `"registry.values"`
    （name="Registry Values"、unit=""、range=`unbounded()`）。**每個選定鍵 = 一個可列舉
    `MetricInstance`**（instance_id=label=鍵路徑、value=該鍵讀值、history_capacity=0）。
    於是「清單」由 `Metric` 列舉實例取得、「數量」即 `Metric::instance_count()`。
  - source 為 null、keys 為空、或某鍵查無值 → 仍保守掛上指標（該實例為未知 / 空指標），不崩。
  - `CMakeLists.txt`：`add_library(e2_22)` **PUBLIC 連上游 `e2_01`**（標頭 include
    `metric.hpp`，須傳遞 include 目錄）；`test_e2_22` + `add_test(NAME e2_22)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`，可讀不可改）。
- **無** `#ifdef` / win32 / cocoa / RegOpenKey / `defaults` / 真實登錄 API（backend_guard
  綠燈）。純邏輯、平台中立。

### 測試 `tests/e2/test_e2_22.cpp`（gtest，24 案例）
- 型別處理（4）：String/Integer/Binary 存取器正確；**以錯型別讀回 `nullopt`**（明確回報
  型別錯）；相等性（跨型別不相等）。
- 讀取存在的鍵值（2）：預設空樹讀回 nullopt；假樹讀回 String / Integer 值。
- 查無鍵（1）：存在父鍵下的不存在葉、完全不存在路徑皆回 `nullopt`。
- null 來源注入 API（1）：`set_value` 覆寫 / `remove` / `clear`。
- 列舉子鍵（4）：直屬子鍵、葉值名、根層、未知鍵/葉回空（皆決定性字典序）。
- 值→MetricValue 對映（4）：查無鍵→未知、Integer→數值+文字、String→文字、Binary→位元組數描述。
- 提供者身分（2）：`provider_id` / `kMetricId` 穩定；可上轉為 E2-01 `MetricProvider`。
- 經 E2-01 provider 暴露（6）：註冊、清單=列舉實例/數量=實例數、查無鍵暴露為未知、
  null source 保守全未知、無選定鍵仍掛空指標、重複 id 保守拒絕。
