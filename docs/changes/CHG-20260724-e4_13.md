# CHG-20260724-e4_13 — 文字流內嵌物件（E4-13）

- Date: 2026-07-24 | Branch: feat/e4_13 | Risk: low | Implemented by: I1.137
- Skill: ai-sdlc-autopilot v1.1
- Unit: E4-13（文字流內嵌物件，module 層 / elements / phase 1 / low，depends_on=[E4-01, E4-02]）

## Motivation

聊天訊息、標籤、通知等文字內容常需要在文字排版流中插入非文字物件（emoji、行內圖示、行內
小圖），且該物件必須**跟著文字一起換行、一起對齊**——不是疊加在文字上方的獨立圖層，也不是
呼叫端自行拼接兩份互不相干的座標。若各自用絕對座標手動拼接文字位置與圖片位置，換字型、換
內容長度就要重算一次，且容易在拼接處露出縫隙或重疊，也違反 NFR-02（絕對座標）。

E4-13 提供 `InlineFlowElement`：呼叫端依序 `add_text()` / `add_inline_object()` 累積內容，
`render_model()` 對整份內容做一次排版，產出「文字 + 內嵌物件」混排的渲染描述
（`InlineFlowResult`）。排版換行/對齊/度量重用上游 **E4-01**（`FontMetrics`、
`LayoutConstraints`、`decode_utf8`），內嵌物件本身的顯示描述重用上游 **E4-02** 的
`ImageRenderModel`。本單元不做文字光柵化、不做影像解碼/繪製，只產出描述。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 換行演算法 | 把文字（拆成字符/空白/硬換行）與內嵌物件攤平成一個混合 token 序列，重用與 E4-01 `TextLayout::layout` 完全相同的貪婪詞界換行規則（泛化到 token 而非單純 CodePoint） | 內嵌物件在換行判斷上等價於「一個不可拆的字」——只在其前後空白/換行處可斷行，天然滿足「該物件佔一個排版位、與文字一起換行對齊」；不重造一套斷行邏輯 |
| 排版約束型別 | 直接重用 `ds::render::LayoutConstraints`（不新宣告一套） | 「以 E4-01 排版」的具體落地：換行寬度/最大行數/換行策略/對齊/行高覆寫/省略號全部沿用同一套語意，呼叫端不用學兩套約束 API |
| 上游相依 | `target_link_libraries(e4_13 PUBLIC e4_01 e4_02)` | 規格指定；`e4_01` 提供 `FontMetrics`/`decode_utf8`/`LayoutConstraints`，`e4_02` 提供 `ImageRenderModel` |
| 內嵌物件顯示描述 | `add_inline_object` 接收呼叫端以 `ImageElement::render_model()` 產出的 `ImageRenderModel`，原樣攜帶進 `FlowObject::image` | 「以 E4-02 顯示內嵌圖」的具體落地：不重造縮放模式/裁切/透明度等欄位，直接複用已驗證過的顯示描述 |
| 排版槽尺寸 vs 來源固有尺寸 | `add_inline_object(image, size)` 的 `size` 是流內佔用的排版尺寸，與 `image.source_dimensions`（來源固有像素尺寸）各自獨立 | emoji/圖示常需要縮放到與行高相稱的顯示尺寸，與來源圖片本身的解析度無關；兩者混為一談會限制呼叫端排版彈性 |
| 無效物件判定 | `image.has_source == false` → `Invalid`，不加入 | 與 E4-02 `ImageElement` 對「無來源」的處理同精神：明確拒絕，不部分套用、不假裝有內容 |
| 無效尺寸判定 | `size.width`/`size.height` 非正或非有限（`NaN`/`Inf`）→ `Invalid`，不加入 | 同上；避免非法尺寸靜默流入排版產生 NaN 位置或零寬度物件 |
| 文字 UTF-8 驗證 | `add_text` 直接呼叫 E4-01 `decode_utf8`，非法序列 → `std::invalid_argument` | 不重造一套 UTF-8 解碼；沿用其「結構性壞資料一律擲例外，不以替代字元靜默吞掉」的規則 |
| 逐行行高 | 每行有效行高 = `max(基礎行高, 本行內嵌物件最大 height)`；行高可因高聳圖示放大，逐行未必等高 | emoji/圖示常見尺寸大於文字行高（如 24px 圖示 vs 16px 行高）；若強制沿用固定行高會讓物件溢出行框 |
| 物件垂直/水平定位 | 水平：與文字同一套 pen 位置累加（`x` 相對偏移）；垂直：以 `FlowObject::height` + 所屬 `FlowLine::y/height` 表達，不額外提供偏移欄位（呼叫端可自行決定基線對齊或置中） | 保持最小 API 面；不過度設計「物件在行內垂直對齊模式」這種本規格未要求的選項 |
| 省略號與截斷 | 沿用 E4-01 的裁切演算法：從行尾以 token 為單位（無論文字字符或內嵌物件）逐一移除直到省略字元放得下 | 泛化後的演算法天然支援「行尾若是物件也能被裁掉讓位給省略字元」，不需為物件另寫特例 |
| `render_model()` 語意 | 純查詢，可重複以不同 `LayoutConstraints` 呼叫，不修改累積內容 | 與 `TextLayout::layout()`、`ImageElement::render_model()` 同慣例：查詢端不做狀態變更 |

介面平台中立：純記憶體邏輯 + 描述產出，無 `#ifdef _WIN32` 等平台分支、不觸碰任何真實字型 /
影像解碼 / OS 繪圖 API。

## 不含（避免越界）

- 不做真實文字光柵化、不做真實影像解碼 / 繪製，不觸碰任何 OS 字型或繪圖 API（那是後續相位
  繪製層的職責）。
- 不提供物件在行內的「垂直對齊模式」（頂/中/基線對齊）選項——本相位只用 `height` 隱含資訊，
  呼叫端自行決定；避免超出規格列出的 API 面過度設計。
- 未動根 `CMakeLists.txt`、`units.json`、`directory.md` 或任何鎖定範圍以外的檔案；未修改
  上游 `engine/render/e4_01/` 或 `modules/elements/e4_02/`。
