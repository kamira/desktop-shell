# CHG-20260724-e2_19 — 行程監看（E2-19）

- Date: 2026-07-24 | Branch: feat/e2_19 | Risk: low | Implemented by: I1.70
- Skill: ai-sdlc-autopilot

## Motivation
E2-19「行程監看」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一
指標介面**把「執行中行程列表」（每個行程的 pid / 名稱 / CPU% / 記憶體用量 / 狀態）掛成
一個指標，支援 **top-N 排序**（依 CPU 或記憶體），並以 **E2-02 採集頻率分級**決定採樣
節奏。這正是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的一個具體實例——它
**消費 E2-01 / E2-02 契約、不自造指標模型或排程器**。相位 1（Mac / null 期）只提供平台
中立介面 + 可注入來源抽象 + null / 假來源，**絕不接任何真實行程 API**（無 `sysctl` /
`/proc` / `EnumProcesses` / `#ifdef` / win32 / cocoa）；真實列舉留待後端相位。

## Impact

### 新增 `modules/sysinfo/e2_19/`（module 層 / 子系統 sysinfo）
- `process_monitor.hpp` / `process_monitor.cpp`（`namespace ds::sysinfo`）：
  - `ProcessStatus` enum（Running / Sleeping / Stopped / Zombie / Unknown）+
    `to_string(ProcessStatus)`（穩定字串）：平台中立狀態集合。
  - `ProcessSortKey` enum（Cpu / Memory）：top-N 的排序維度。
  - `ProcessInfo` struct：平台中立的行程五欄位描述 —— `pid` / `name` / `cpu_percent`
    （%）/ `memory_bytes`（bytes）/ `status`；含相等運算子。刻意不含平台專屬欄位。
  - `ProcessSample` struct：某時刻行程列表快照 + `valid`（false = 無讀值）；`unknown()`
    工廠。**「無讀值誠實 invalid」**的載體。
  - 排序自由函式（獨立可測、平台中立純邏輯）：`process_sort_value(p, key)` /
    `top_processes(procs, key, top_n)`（依維度由高到低、同值以 pid 遞增決定性、
    top_n==0=全部）。
  - `ProcessSource` 抽象後端：`sample() → ProcessSample`。真實平台後端於相位 2+ 實作；
    提供者只依賴此抽象介面（換後端不動提供者）。
  - `NullProcessSource` null 後端：**不列舉系統**，預設回「無讀值」；`set_processes` /
    `set_sequence` / `push_snapshot` / `clear` / `reset` 注入固定快照或**快照序列**
    （模擬行程起／停）。序列語意同 E2-03 `NullCpuTickSource`（列盡回最後一份、空回 unknown）。
  - `ProcessMonitorProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.proc"`；`register_metrics(registry)` 依排序維度掛上單一指標
    —— Cpu → `"proc.cpu"`（name="Process CPU"、unit="%"、range=`bounded[0,100]`）；
    Memory → `"proc.memory"`（name="Process Memory"、unit="MB"、range=`at_least(0)`，
    bytes→MB 換算 `kBytesPerMiB`）。**top-N 每個行程 = 一個可列舉 `MetricInstance`**
    （instance_id=pid、label=行程名、value.number=排序維度值、value.text=狀態字串、
    history_capacity 預設 64）。`sample()` 重讀來源、排序取 top-N、更新 / 動態新增實例
    （既有參照不失效）、缺席 pid 設未知（不縮減、不污染歷史）；`processes()` 回排序後
    top-N 完整五欄位；`has_reading()` 回最近採樣是否有讀值。建議採集分級 `Normal`。
  - source 為 null / 無讀值 → 仍保守掛上指標（instance_count()==0），不崩、不謊報 0。
  - `CMakeLists.txt`：`add_library(e2_19)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` / `sampling.hpp`，須傳遞 include 目錄）；`test_e2_19` + `add_test(NAME e2_19)`。
- 上游相依：E2-01 統一指標介面（`MetricProvider` / `MetricRegistry` / `InMemoryMetric` /
  `InMemoryMetricInstance`）、E2-02 採集頻率分級（`SamplingTier` / `SamplingScheduler`），
  皆已合併、可讀不可改。
- **無** `#ifdef` / win32 / cocoa / sysctl / /proc / EnumProcesses / 真實行程 API
  （backend_guard 綠燈）。純邏輯、平台中立。

### 測試 `tests/e2/test_e2_19.cpp`（gtest，23 案例）
- 提供者 / 指標身分（3）：`provider_id` 穩定、可上轉 `MetricProvider`；指標 id 依排序維度
  （proc.cpu / proc.memory）；採集分級預設 Normal、可覆寫。
- 註冊 + 欄位列舉（1）：每行程一實例，pid=instance_id、名稱=label、CPU%=value.number、
  狀態=value.text；`processes()` 回完整五欄位（含未排序維度的記憶體）。
- top-N 依 CPU（1）：top-2 取最高兩者、其餘不成實例。
- top-N 依記憶體（1）：top-2 取最大兩者、bytes→MB 換算、range at_least(0)。
- 排序自由函式（3）：平手以 pid 遞增；top_n==0=全部 / 超界夾住 / 空輸入；維度取值。
- 行程數變動（2）：新增行程 → 動態新增實例；行程結束 → 設未知、不縮減。
- 無讀值 invalid（1）：預設 null 來源無讀值→0 實例；注入後有讀值；再清空→設未知不崩。
- 經 E2-02 採樣（2）：Normal 間隔=8 排程觸發 sample、歷史累積；除頻合併多消費者取最高頻。
- null 來源（3）：null 指標指標仍掛上、sample 不崩；register 前 sample no-op；序列列盡/空語意。
- 範圍 / 消費者範式 / 重複註冊 / 值模型（6）：CPU range bounded[0,100] 可正規化；掛件式
  消費者只走 E2-01 抽象；同 id 重複註冊保守拒絕；狀態字串；`ProcessSample` / `ProcessInfo`
  相等性與 unknown 預設。
