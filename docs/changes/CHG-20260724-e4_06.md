# CHG-20260724-e4_06 — Surface 編號定址與切換（E4-06）

- Date: 2026-07-24 | Branch: feat/e4_06 | Risk: low | Implemented by: I1.123
- Skill: ai-sdlc-autopilot v1.1
- Unit: E4-06（Surface 編號定址與切換，engine 層 / render / phase 1 / low，depends_on=[E4-02]）

## Motivation

多頁面 / 多狀態畫面（例如設定面板的分頁、桌面元件的多視圖）需要一個平台中立的方式「以名稱
定址一組 surface，並在其間切換」。若呼叫端各自維護一份 `if/else` 或數字索引來管理目前顯示
的畫面，換平台、換元件都要重寫，也容易違反 NFR-02（禁止數字 index / z-order 對外暴露）。

E4-06 提供一個小而穩定的 `SurfaceSwitcher`：以**具名 id**註冊一組 surface、查詢 / 列舉、
`switch_to(id)` 切換「目前顯示」的是哪一個、並在切換發生時通知監聽者。純記憶體狀態機，
不建立 / 銷毀任何實體 surface（那是上游 K1 / E1-03 的職責）——本單元只管「定址與切換」。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| surface 識別 | 沿用上游 `ds::kernel::SurfaceId`（字串），經 E4-02 `image_element.hpp` 傳遞 | 不重造一套 id 型別；與既有具名 surface 慣例（E1-03/E1-24）一致，滿足 NFR-02 |
| 上游相依 | `target_link_libraries(e4_06 PUBLIC e4_02)` | 依規格指定；僅借道 e4_02 標頭的 include 鏈取得 `SurfaceId`，不使用 `ImageElement` 本身 |
| 列舉 | `list()` 回傳依註冊順序的具名 `vector<SurfaceId>` | 具名清單；順序僅表示註冊先後，不對外暴露任何數字 index / z-order（NFR-02） |
| 重複註冊 | 拒絕、回 `Invalid`，不覆蓋 | 避免既有註冊被無聲遮蔽 |
| 未知 id | `switch_to` / `unregister_surface` 回 `NotFound`，不崩潰 | 不靜默失敗（規格硬性要求） |
| 移除目前 surface | 回到「尚無目前 surface」，**不**觸發 `on_switch` | 通知語意保留給明確的 `switch_to` 呼叫，移除是另一種操作 |
| 切到目前已是的 surface | 仍回 `Ok` 且仍觸發一次通知 | 呼叫端可能需要用它來重新整理畫面；避免呼叫端得自行判斷「是否真的變了」 |
| 切換通知 | `on_switch(listener)`：`std::function<void(from, to)>`，依註冊順序依序呼叫 | 與同儕 `CommandBus`（E6-01）handler 註冊慣例一致 |

介面平台中立：純記憶體邏輯，無 `#ifdef _WIN32` 等平台分支、不綁任何真實繪圖 / OS API。
