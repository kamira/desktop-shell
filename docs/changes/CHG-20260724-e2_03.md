# CHG-20260724-e2_03 — CPU 負載（總體與每核心）（E2-03）

- Date: 2026-07-24 | Branch: feat/e2_03 | Risk: low | Implemented by: I1.56
- Skill: ai-sdlc-autopilot

## Motivation
E2-03「CPU 負載（總體與每核心）」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「CPU 使用率」（總體 %＋每個邏輯核心 %）掛成一個
指標（一個總體 metric instance + 每核心可列舉 instances），並以 **E2-02 採集頻率分級**決定
採樣節奏（CPU 負載會變動且宜跟手，屬週期高頻採集）。這是「新增指標 = 新增 `MetricProvider`、
掛件一行不動」機制的又一個具體實例——它**消費 E2-01 / E2-02 契約、不自造指標模型或排程器**。
本單元是最終「CPU / GPU Usage Widget」的核心資料來源，故介面刻意乾淨、易組合。相位 1
（Mac / null 期）**絕不接任何真實 CPU 統計 API**（不含 `host_processor_info` / `/proc/stat` /
mach / `#ifdef`）；改為**可注入的 CPU 統計來源抽象** + null / 假來源，使用率以「兩次取樣差分」
（來源給累積 tick）或直接讀（來源給比率）算出；真實平台後端留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_03/`（module 層 / 子系統 sysinfo）
- `cpu_load.hpp` / `cpu_load.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `CpuCoreTicks`：單一邏輯核心的**累積** tick（`busy` 非閒置 / `total` 全部；含相等
      運算子）。單一時刻累積值無意義——使用率須由兩次取樣差分得出。
    - `CpuTicksSample`：某時刻全 CPU 的累積 tick 快照（每核一筆；核心數可在取樣間變動）。
    - `CpuUsageSample`：統一使用率形狀（`overall` + `per_core` 使用率比率 [0,1] + `valid`；
      `unknown()` = 無讀值；含相等運算子）。比率而非百分比——提供者掛指標時再乘 100 成 %。
  - **差分演算法**（自由函式，獨立可測、純算術）：
    - `core_usage_ratio(prev, curr)`：單核使用率 = busyΔ / totalΔ，夾到 [0,1]。防護：
      計數器重置（curr<prev）→0、無經過時間（totalΔ==0）→0、busyΔ>totalΔ→夾到 1.0。
    - `usage_from_delta(prev, curr)`：每核比率 + **聚合**總體（sum busyΔ / sum totalΔ，
      以 totalΔ 加權，非各核比率的算術平均）；核心數以兩份的共同數（較小者）對齊；
      共同核心數 0 → 無讀值（valid==false）。
  - **使用率來源**（提供者只依賴此抽象）：
    - `CpuStatSource`（抽象 `sample()→CpuUsageSample`；非 const，差分型來源取樣有副作用）。
    - `NullCpuStatSource`：相位 1 null / 假「直接比率」來源——**不接真實 CPU API**，預設回
      無讀值；`set_usage` / `set_per_core`（總體=各核比率平均）/ `clear` 注入，供測試與
      假感測器情境。此即「來源直接給比率」路徑。
  - **tick 來源 + 差分轉接**（「來源給累積 tick、提供者以兩次取樣差分算使用率」路徑）：
    - `CpuTickSource`（抽象 `read()→CpuTicksSample`，給累積 tick，尚未差分）。
    - `NullCpuTickSource`：注入累積 tick 序列（模擬時間推進），`read()` 回下一份、列盡持續
      回最後一份、空列回空快照；`set_sequence` / `push_sample` / `reset` 注入。
    - `DifferencingCpuStatSource : CpuStatSource`：消費一個 `CpuTickSource`，內部保存「上一份」
      累積 tick，每次 `sample()` 讀新份與上份差分（`usage_from_delta`）；首次（或 `reset` 後
      首次）回 `unknown()`（差分至少需兩份）。乾淨可組合——提供者不必知背後是差分或直接比率。
  - **提供者** `CpuLoadProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.cpu"`；`register_metrics(registry)` 向 E2-01 註冊表掛上單一指標
    `"cpu.usage"`（name="CPU Usage"、unit="%"、range=`bounded(0,100)`）。
    - **一個總體 + 每核心可列舉實例**：總體實例 `"total"`(label "CPU Total") 恆存在（列舉
      順序第一）；每核心實例 `"cpu0"`/`"cpu1"`/…(label "Core 0"/…) 依取樣核心數建立。
      各實例保留歷史環（`kDefaultHistory=64`），配合 E2-02 週期採集鋪成負載序列。
    - `sample()`：重新讀來源、把新使用率寫入各實例（比率*100 成 %、推入歷史）；核心數增加
      則**動態新增**核心實例（既有參照不失效，unique_ptr 持有），減少則多出者設未知（不
      污染歷史）。register 尚未呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::High`，建構子
      可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
    - `core_count()`：目前的邏輯核心實例數（不含總體）。
  - 無讀值語意：指標仍掛上；總體 / 各核心以 `valid==false`（未知）誠實表達，而非塞假值。
    source 為 null 亦保守不崩（僅總體實例、未知、0 核）。
  - `CMakeLists.txt`：`add_library(e2_03)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_03` + `add_test(NAME e2_03)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）＋ E2-02 採集頻率分級
  （`ds::metrics::SamplingTier` / `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / `host_processor_info` / `/proc/stat` / mach 等真實 CPU API
  （backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_03.cpp`（gtest，26 案例）
- 提供者身分（3）：`provider_id`/`kMetricId`/`kMetricName`/`kUnit` 穩定；可上轉為 E2-01
  `MetricProvider`；預設採集分級 = High（可覆寫）。
- 註冊 / 列舉（2）：`add_provider` 掛上一個指標；總體 + 每核心實例（total 在前，順序決定性）；
  總體 %（各核平均）與每核 % 讀值正確（直接比率路徑）。
- **兩次取樣差分**（3）：注入兩份 tick → 算出 %（單核 50%）；`usage_from_delta` 多核不同負載 +
  聚合總體；聚合總體以 totalΔ 加權（!= 算術平均）。
- **0% / 100% 邊界**（2）：`core_usage_ratio` 0% / 滿載；經提供者 0% 與 100%。
- 差分邊界（1）：計數器重置 / 無經過時間 / busyΔ>totalΔ 皆保守。
- **核心數變動**（3）：tick 差分以共同核心數對齊；直接來源核心數增 → 動態新增實例（既有參照
  不失效）；核心數減 → 多出者設未知（不縮減、誠實下線）。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（High 間隔 1）登記需求、推進 tick 於到期
  時呼叫 `sample()` → 歷史累積、值前進；除頻合併多消費者（最高頻者供給、撤銷後降頻）。
- **null 來源行為**（4）：source 為 null 指標 → 僅總體實例、未知、0 核、不崩、`sample()` no-op；
  `NullCpuStatSource` 預設未知、注入後可讀；`sample()` 未註冊為 no-op；`DifferencingCpuStatSource`
  首次未知→次次有效 / 無 tick 來源未知；`NullCpuTickSource` 列盡 / 空列語意。
- 範圍 / 消費者範式 / 重複註冊（3）：`bounded[0,100]`（50% 正規化到 0.5）；掛件風格消費者只走
  E2-01 registry / Metric 抽象介面；同 id 第二次掛上保守拒絕、不覆寫。
- 值模型單元（3）：`CpuUsageSample::unknown`、`NullCpuStatSource` 注入 / clear。
