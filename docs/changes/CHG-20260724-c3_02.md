## Motivation
C3-02「角色對話本」：角色劇本 / 對話腳本——用 E8-02 對話腳本直譯器撰寫的一連串台詞（含條件
分支 / 跳轉），逐句驅動 C1-03 `BalloonProfile` 在依附角色旁顯示對話，並支援以 E8-03 表現控制
指令集在同一份腳本中夾帶舞台指示（`show` / `hide` / `switch_surface` / `transition` /
`wait`）。這是一個**組裝型 artifact 單元**：不新增引擎邏輯，而是把三個已合併的擴充點（E8-02
台詞 / 分支、E8-03 舞台指示、C1-03 逐句顯示）組成單一「對話本」應用 profile + 行為
（`load_script` / `start` / `advance` / `current_line` / `is_finished` / `reset`）。相位 1：
純資料 / 邏輯組裝，無真實 GUI，注入式 tick，平台中立。

實作前以 `ls` / 讀檔確認上游實際路徑：C1-03（`content/profiles/c1_03/balloon_profile.hpp`，
角色對話氣球，`show_balloon(character, text, ttl, spec)` 依附一個已載入的 C1-02
`PortraitProfile` 顯示逐字氣球）、E8-02（`engine/script/e8_02/interpreter.hpp`，對話腳本直譯
器，`Script`/`Step`（`set`/`say`/`if goto`/`goto`/`label`）/`Interpreter`/`OutputSink`，變數
跨步延續、條件分支 / 跳轉、不靜默的 `ScriptError`）、E8-03
（`engine/script/e8_03/presentation_commands.hpp`，表現控制指令集，`PresentationController`
把 show/hide/switch_surface/transition/wait 註冊到 E6-01 `CommandBus`，`PresentationSink`
實作 E8-02 `OutputSink` 把 `say` 文字解析為具名表現指令）。

**依任務提示自查 HitResult 命名碰撞是否波及本單元**：C1-03 `balloon_profile.hpp` 已把 E1-14
（經 `input_strategy.hpp` 宣告 `enum class ds::kernel::HitResult`）與 C1-02（經 `hit_test.hpp`
宣告 `struct ds::kernel::HitResult`）的既有碰撞以「橋接層 + pimpl」隔離乾淨——其公開標頭只
`#include` `character_bridge.hpp`（前置宣告 `PortraitProfile`）與 `subordinate_layout.hpp` /
`typewriter_element.hpp`，兩者皆不涉及 `input_strategy.hpp` / `hit_test.hpp`。以自撰腳本追蹤
`balloon_profile.hpp` / `interpreter.hpp`（E8-02）/ `presentation_commands.hpp`（E8-03）三者
遞移 `#include` 樹（結果：`e5_04` `e4_01` `e4_09` `e4_11` `e1_03` `e1_07` `e1_11` `e1_21`
`backend/null` / `e7_01` `e7_02` `e7_05` / `e6_01` `e4_06` `e4_02` 共 12 個相異上游標頭），
確認**沒有任何一個**傳遞 `input_strategy.hpp` 或 `hit_test.hpp`。因此本單元三者標頭可安全
同時 `#include` 於同一翻譯單元，**不需要**額外的 pimpl / 橋接層隔離——`speaker`
（`ds::profiles::PortraitProfile`）以 C1-03 已透過 `character_bridge.hpp` 帶入的前置宣告，
僅作為參照傳遞（不需完整型別）即可轉呼叫 `BalloonProfile::show_balloon`。

## Impact

### 新增 `content/c3_02/`
- `dialogue_book.hpp` / `.cpp`：`namespace ds::content`，`class DialogueBook`。
  - 每個實例代表**一本**對話本，自持一個 C1-03 `BalloonProfile`（surface id = 對話本自身
    id）、一份 E8-02 `Script`（`load_script` 覆寫）、一個 E8-03 `PresentationController`
    （建構時嘗試把五個舞台指示註冊到注入的 `CommandBus`；`ready()` 透傳其註冊結果）。
  - `LineSink`（`DialogueBook` 內部 pimpl 巢狀類別，實作 E8-02 `OutputSink`）：台詞 / 舞台
    指示分流——每次 `say` emit 一行文字時，先判斷第一個 token 是否為 `show`/`hide`/
    `switch_surface`/`transition`/`wait` 之一；是 → 轉交內部 E8-03 `PresentationSink` 經
    `CommandBus` 分派（不算一句台詞）；否 → 記為待顯示台詞。
  - `load_script(script)`：空腳本 → `Invalid`（不建立可跑狀態）；成功會捨棄既有播放進度。
  - `start(speaker, ttl)`：（重）建構一個綁定 `script_` 與 `LineSink` 的 E8-02 `Interpreter`，
    從 pc=0 執行到第一句台詞（跳過舞台指示 / `set`/`goto`/`if`/`label`）或腳本結束或錯誤；
    找到台詞後經 `BalloonProfile::show_balloon(speaker, line, ttl)` 顯示。未 `load_script`
    / `!ready()` / 已 `start` 且未 `Finished`（未先 `reset()`）→ `Invalid`；腳本執行期錯誤
    → `ScriptError`（見 `last_error()`，本狀態亦視為終止，`is_finished()` 轉真）；無台詞
    可顯示 → `Finished`；找到台詞但顯示失敗（如 speaker 未載入）→ `Invalid`（腳本執行位置
    仍前進，需 `reset()` 後以有效 speaker 重試——腳本推進與氣球顯示為兩個獨立失敗面，與
    `PresentationSink` 不吞失敗、忠實回報同一精神）。
  - `advance(speaker, ttl)`：先收掉目前顯示中的氣球（`dismiss()`，若有），再從目前執行位置
    續跑腳本直到下一句台詞或結束，顯示邏輯與失敗語意同 `start`。尚未 `start` 或已
    `Finished` → `Invalid`。
  - `tick(dt)`：透傳 `BalloonProfile::advance(dt)`（逐字顯示 / 存活倒數；未顯示中 no-op，
    跨過 ttl 會使氣球自動消失，但 `current_line()` / 對話本自身播放進度不受影響）。
  - `reset()`：收掉氣球（若顯示中）、丟棄 `Interpreter` 執行狀態，回到「未 start」；腳本
    定義（`script_`）保留，可重新 `start()`（無需重新 `load_script`）。
  - 查詢：`current_line()` / `is_finished()` / `is_active()` / `is_showing()` /
    `last_error()` / `presentation()`（供呼叫端 / 測試查驗腳本中的舞台指示是否真的經
    `CommandBus` 生效）/ `ready()` / `registration_error()`。
  - 具名結果列舉：`DialogueStatus`（Ok / Invalid / ScriptError / Finished），附
    `to_string()`（NFR-02）。
- `CMakeLists.txt`：`add_library(c3_02 STATIC dialogue_book.cpp)` +
  `target_link_libraries(c3_02 PUBLIC c1_03 e8_02 e8_03)` + `test_c3_02`
  （`tests/c3/test_c3_02.cpp`）+ `add_test(NAME c3_02)`。
