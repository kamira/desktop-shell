# CHG-20260803-01 — Windows day-1 首次 MSVC 全建：根 CMake 加 `/utf-8`

- Date: 2026-08-03 (UTC+0) | Branch: claude/ai-sdlc-autopilot-content-check-bdf414 | Risk: low | Implemented by: I1
- Skill: ai-sdlc-autopilot v1.1

## Motivation

執行 `docs/backlog/phase2-desktop-runtime.md` §6「Windows 接手 checklist」步驟 1–2：在 Windows 開發機裝妥工具鏈，
跑**史上第一次 MSVC 全建**。176 個單元全部以 clang/g++ 撰寫與驗證，從未在 MSVC 實編；CI 是 ubuntu + GCC，抓不到 MSVC 專屬問題。

首次全建 **69 個編譯錯誤**，集中於 C2001「常數中包含新行字元」（27 個）及其下游語法崩塌（C2143 ×23、C2146 ×8、
C2059 ×4、C2064 ×3、C1075 ×2、C2317、C2318）。

**根因不是交接文件預測的 MSVC 嚴格度，是原始碼字集。** 本庫原始碼為 **UTF-8 無 BOM** 且註解與字串大量含中文；
MSVC 在沒有 `/utf-8` 時，會以「非 Unicode 程式的系統地區設定」的 ANSI codepage 解讀原始碼（本機為 **CP932**）。
中文字的 UTF-8 位元組被誤判為雙位元組字元的前導碼，吃掉字串的結尾引號 → 字串未收尾 → C2001，其後整段語法崩塌。

GCC / Clang 預設即以 UTF-8 解讀原始碼，故此問題**在 Linux/macOS 上永遠不會出現**，
現行 ubuntu CI **結構上不可能擋下它**。這是 checklist 步驟 2 存在的意義。

## Impact

`CMakeLists.txt`（根，bootstrap 基礎設施）新增 MSVC 專屬編譯選項：

```cmake
if(MSVC)
  add_compile_options(/utf-8)
endif()
```

- 置於 `enable_testing()` 之前，故對其後所有 `add_subdirectory()` 收入的單元目標一併生效（含 FetchContent 取得的 GoogleTest）。
- `/utf-8` 同時設定來源字集與執行字集為 UTF-8。
- **以 `if(MSVC)` 包住**：GCC / Clang 路徑一個旗標都沒變，ubuntu CI 行為完全不變。
