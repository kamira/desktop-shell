## Motivation

`README.md` 原本只有兩行：標題 + 一句話定位。對一個已完成 187 個工作單元、
十一道 CI 閘門、四層分層的 repo 來說，門面與內容量差距過大：

- 新進者（人或 agent）看不出這是**平台**而不是桌面工具 —— 而這是全案最容易誤解、
  也最影響後續每一個設計判斷的一件事。
- 看不出怎麼建置、怎麼跑、Windows 與非 Windows 的差別在哪。
- 看不出治理紀律的存在。`AGENTS.md` 寫得很完整，但沒有任何入口指向它。
- 沒有任何畫面。專案的驗收條件是「擴充點真的能被外部組裝」，
  而最能一眼證明這件事的東西（`examples/cpu_gpu_validator` 的輸出）從未被收錄。

### 兩張圖都是實際建置後截圖，不是示意圖

初版曾以「把程式輸出重繪成 SVG」的方式產圖。**那不是截圖**——
數字雖然來自真實執行，但顏色與版面都是重繪時加上去的，
程式本身不輸出任何 ANSI 色彩。既然本 repo 的驗收標準一路在防「看起來對、其實不是」
的假綠燈（G0/G3 真空綠燈防線、K-002 的 `0.0` 偽裝、W1-05 的實機 `PrintWindow` 取像），
門面上的圖用重繪就自相矛盾。故改為真的建置、真的執行、真的對畫面取像。

## Verification

### 圖片產生方式（可複現）

```bash
# 1) 真的建置（GoogleTest 於離線環境改由本機來源提供，其餘一律走專案自己的 CMake）
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 3

# 2) 真的執行，於 Xvfb 上的真 xterm 內，對 X 畫面取像
Xvfb :99 -screen 0 1024x680x24 &
DISPLAY=:99 LC_ALL=C.UTF-8 xterm -u8 -geometry 82x26 \
    -fa 'DejaVu Sans Mono' -fs 13 -fd 'Noto Sans Mono CJK TC' \
    -e build/units/examples/cpu_gpu_validator/cpu_gpu_validator
DISPLAY=:99 import -window root shot.png
```

`cpu-gpu-validator.png` 內 CPU 顯示 69.1%，是取像當下真的在跑全庫建置的主機負載；
GPU / RAM 為驗證器自帶的 sweep 模擬（用途是證明 widget 對任意指標皆能組裝，見其 `main.cpp` 註解）。

### 建置與測試（ubuntu，本次實跑）

```
cmake --build build -j 3        → BUILD_EXIT=0
ctest --test-dir build          → 100% tests passed, 0 tests failed out of 176
```

176 = 187 個註冊測試扣掉 11 個 `if(WIN32)` 守衛住的 Windows 專屬測試
（`W1-01`~`W1-06`、`H1-01`~`H1-05`）。README 的測試數字據此寫成
「187 個註冊 CTest 測試（其中 11 個為 Windows 專屬）」，不混寫成一個數。
