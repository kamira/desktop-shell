### Windows host 的截圖：mingw-w64 交叉編譯 + Wine，且已在 README 標明

本次環境沒有 Windows 機器。為了不讓 README 的「桌面 runtime」只有文字描述，改以：

```bash
# 1) mingw-w64 交叉編譯（走專案自己的 CMake；if(WIN32) 區塊因此全部生效）
cmake -S . -B wbuild -DCMAKE_TOOLCHAIN_FILE=<mingw 工具鏈> \
      -DCMAKE_CXX_STANDARD_LIBRARIES="-lole32 -loleaut32 -loleacc -lgdi32 -luser32 -lshell32 -lcomctl32 -luuid"
cmake -S . -B wbuild -DCMAKE_EXE_LINKER_FLAGS="-municode -static ..."   # 偵測完才補，見下
cmake --build wbuild --target desktop_shell_host

# 2) Wine 虛擬桌面上執行 + 對 X 畫面取像
wine explorer /desktop=shell,1100x780 desktop_shell_host.exe --seconds 90
DISPLAY=:98 import -window root gui.png
```

**程式碼一行未改**，只在建置與執行環境上補了三件事：

| 問題 | 成因 | 處置 |
|---|---|---|
| `undefined reference to WinMain` | app 的入口是 `wWinMain`；mingw 要 `-municode` 才用寬字元啟動碼 | 加 `-municode`。**但不能在第一次 configure 就加**——CMake 的編譯器偵測會編一支 `main()` 的測試程式，帶著它會找不到 `wmain` 而讓 configure 失敗。偵測完成後再 `cmake -B` 補上 |
| 中文變豆腐 | Wine 替 `Segoe UI` 挑的代用字型沒有 CJK | 把 Noto Sans CJK 放進 prefix 並登記替換。**先試 Droid Sans Fallback 反而換成拉丁字變豆腐**（該字型在 Wine 下的 Latin cmap 對不上），故改用 Noto |
| 托盤選單叫不出來 | ① `FindWindowW` 找不到 message-only 視窗（`HWND_MESSAGE` 的子視窗不在桌面 z-order 裡）② 視窗查詢是 per-desktop 的，helper 跑在預設 desktop 上看不到 `explorer /desktop=shell` 裡的視窗 | 改用 `FindWindowExW(HWND_MESSAGE, ...)`，且 helper 也以 `wine explorer /desktop=shell` 進同一個 desktop 執行 |

**這條路徑不是支援的建置方式，README 已明寫**：專案本身以 MSVC 建置，由 CI 的
`gate_windows` 每個 PR 實跑；mingw + Wine 只為取像。README 的圖說也標明
「不是原生 Windows 的畫面，字型替換與視窗合成細節會與實機有出入」——
**不寫這一句，這張圖就會變成另一種假綠燈**。實機的目視驗收仍以 `HANDOFF.md` §0-B 為準。
