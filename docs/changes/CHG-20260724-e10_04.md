## Motivation

載入的模組（E8-04）之間需要一種「不直接相依彼此」的互通方式。若模組彼此以具體型別
相依，會退回硬耦合、失去「第三方模組不改核心即可掛上」的擴充點價值。E10-04 提供一個
**事件廣播協定**：模組宣告它要發布 / 訂閱哪些事件主題（topic），協定層把某主題上的事件
廣播給所有訂閱該主題的模組 —— 發布者不需知道有誰在聽、聽者不需知道是誰發的。

**相位 1：純記憶體事件匯流排，不綁真實網路 / IPC。** 實際的「依主題路由 + 依註冊序扇出 +
投遞計數」委派給 E10-01 的 `MessageChannel`（主題即通道訊息型別）；E10-04 在其上加「模組
維度」：每筆訂閱歸屬於某模組，模組卸載（E8-04 unload）時可一次清理其全部訂閱與宣告。
等真實傳輸層（相位 2）到位時，本協定即為其上的事件層：底層通道換掉、事件語意不動。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 事件主題 | `Topic`（= E10-01 `MessageType`，具名字串） | 穩定、可讀、跨邊界不變形；不用數字 topic id |
| 底層廣播 | 委派 E10-01 `MessageChannel`（主題路由 / 扇出 / 計數） | 重用已合併契約；相位 2 換傳輸時事件語意不變 |
| 模組維度 | 每筆訂閱歸屬 `ModuleId`（對接 E8-04 manifest.name） | 支援模組卸載時精準清理其全部訂閱 |
| 事件酬載 | 重用 E6-01 `CommandArgs`（經 E10-01 傳遞） | 跨模組邊界不變形；複合結構以多個具名參數表達 |
| 事件來源 | `Event.source`（選填模組 id） | 供訂閱者診斷 / 過濾自己發的事件 |
| 主題宣告 | `declare_publish/subscribe`（純內省，不影響投遞） | 對應「模組宣告它 publish/subscribe 哪些主題」 |
| 訂閱識別 | `EventSubscriberId`（= E10-01 `SubscriberId`，0 保留無效） | 可退訂、唯一、失敗回值清楚 |
| 無效訂閱輸入 | 空 module / 空 topic / 空 handler 一律拒絕回 0 | 契約邊界清楚 |
| 無訂閱者發布 | `publish` 回 0（投遞數），不視為錯誤、不崩潰 | 保守、可預期的邊界 |
| 巢狀發布 | 「當前事件」指標以存 / 還原保護 | 處理器內再發布不破壞外層事件（可重入安全） |
| 卸載清理 | `unsubscribe_module` 一次註銷該模組全部訂閱 + 宣告 | 對接 E8-04 `on_unload`，卸載後不殘留 |
| 契約版本 | `event_broadcast_contract_version()` = "e10_04/1.0.0" | 承重抽象，供相位 2 換傳輸時相容判斷 |

介面平台中立：無 `#ifdef _WIN32` / `cocoa` / `__APPLE__` 等平台分支、不綁任何真實網路 / OS IPC。
