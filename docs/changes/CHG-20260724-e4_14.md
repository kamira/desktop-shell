# CHG-20260724-e4_14 — 長文捲動與分頁（E4-14）

- Date: 2026-07-24 | Branch: feat/e4_14 | Risk: low | Implemented by: I1.121
- Skill: ai-sdlc-autopilot
- Unit: E4-14（長文捲動與分頁，module 層 / 子系統 elements / phase 1 / low）
- depends_on: E4-01（文字排版與渲染）

## Motivation

長文內容（多行排版結果）不可能整份塞進固定大小的可視區，需要一層「捲動 / 分頁」邏輯，
把 E4-01 排版出的多行文字，依可視區高度切出「目前可見的行範圍」，並提供捲動（逐行）與
分頁（逐 viewport）兩種操作、以及捲動位置指示（供例如捲軸 thumb 的比例呈現）。

相位 1 平台中立、**不做真實繪製 / 不重畫 glyph**：本單元只消費 E4-01 `LayoutResult` 的
「行數」作為捲動範圍，產出「哪些內容行目前可見、對應到 viewport 第幾行」的**索引對應**，
實際 glyph / 佈局細節仍由呼叫端回查 `LayoutResult`——避免重複儲存上游已有的像素幾何。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 核心類別 | `ScrollView`（命名空間 `ds::elements`） | 單一類別同時涵蓋逐行捲動與逐頁翻頁——分頁在語意上就是「以 viewport 行數為步進的捲動」，共用同一份 offset 狀態最一致 |
| 綁定內容 | `set_content(const LayoutResult&)` 只取 `lines.size()` | 捲動邏輯只需行數；不複製 / 不重存上游像素幾何（避免資料重複與過期風險） |
| 可視區 | `set_viewport_lines(n)`，`n==0` 為無效視窗 → 擲例外 | 明確表達「行數為單位」的可視區（NFR-02）；`0` 是無意義視窗，若靜默接受會讓後續 `visible_range()` 產生假象空窗，故不靜默 |
| 捲動 | `scroll_by(delta)` / `scroll_to(offset)`，一律夾限於 `[0, max_offset_lines()]` | 捲動越界是使用者操作的常態（滑鼠滾輪衝過頭等），夾限而非報錯才是預期行為 |
| 分頁 | `page_next()` / `page_prev()` 等價 `scroll_by(±viewport_lines())` | 與捲動共用同一狀態與夾限規則，語意單純 |
| 可見範圍 | `visible_range()` 回半開區間 `[offset, min(offset+viewport, content_lines))` | 內容短於 viewport 或捲到底部時自然收斂，不需特判 |
| 渲染描述 | `render_model()`：`VisibleLine{content_line, viewport_line}` 陣列 + `ScrollPosition`（offset / max_offset / ratio / at_top / at_bottom）+ `page_index` / `page_count` | 純索引 + 比例資料，供捲軸 / 分頁 UI 與繪製層消費；不含像素座標 |
| 分頁指示 | `page_count = ceil(content_lines / viewport_lines)`；`page_index` 在觸底（`offset==max_offset`）時回報 `page_count-1`，否則 `offset/viewport_lines` | 內容行數非 viewport 整除時，觸底捲動的偏移不會恰好落在頁邊界，仍需正確回報「最後一頁」 |

### NFR-02 遵循（無絕對座標 / 數字 z-order）

`RenderModel` / `ScrollPosition` **刻意不含任何 x/y 像素、螢幕座標、整數層級**欄位：
- 可見行對應：`content_line` / `viewport_line` 皆為**行索引**（`std::size_t`），非像素 y。
- 捲動位置：`offset_lines` / `max_offset_lines` 為行數；`ratio` 為 `[0,1]` 比例值。
- 分頁：`page_index` / `page_count` 為頁索引 / 頁數，非座標。
