# CHG-20260724-e7_10 — 字串處理（E7-10）

- Date: 2026-07-24 | Branch: feat/e7_10 | Risk: low | Implemented by: I1.46
- Skill: ai-sdlc-autopilot
- Unit: E7-10（字串處理，engine 層 / 描述子系統 / low；相依已合併的 E7-05，傳遞取得 E7-02 / E7-01）
- NFR: NFR-04「描述格式錯誤須明確、不得靜默」

## Motivation

設定 / profile / 版面等宣告式格式常需以既有字串值推導新值：拼接路徑、切分標籤、
補齊寬度、依樣板組字。E7-05 公式引擎已能對格式值做**算術 / 邏輯**運算，但缺一組
**字串運算**。E7-10 補上這一層：一組可在公式 / 格式脈絡使用的字串處理函式，
輸入 / 輸出以 E7-01 `Value` 表達、結果 / 錯誤沿用 E7-05 `EvalResult` / `EvalError`，
使字串函式可被上層（含 E7-05 公式引擎的**未來**函式呼叫擴充）以統一結果型別接入。

E7-05 當前運算式文法僅含字面量 / 變數 / 運算子，**尚未**支援函式呼叫語法；故本單元以
「獨立、可被上層接入的字串運算 API」形式提供，並額外導出一張**函式表**
（`function_table()` / `find_function()`），一旦上層加入函式呼叫即可直接查表分派、無縫接入。

屬 engine 層（平台中立純邏輯）：無任何 `#ifdef` / 系統呼叫 / 真實後端，可完全單元測試。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::format::strings` | 隸屬指定 `ds::format`；巢狀 `strings` 避免 `length` / `format` 等通用名污染 |
| 值 / 型別模型 | 沿用 E7-01 `Value`（含 `is_integer` 整數旗標、List / Map / Bool / Null） | 消費上游不重造；輸入輸出一致可組合 |
| 結果 / 錯誤模型 | 沿用 E7-05 `EvalResult` / `EvalError`（position 統一 0） | 與公式引擎同型別，利上層以函式呼叫接入；`EvalError` 帶人類可讀訊息 |
| 長度 / 子字串 / 填充單位 | **UTF-8 碼位（codepoint）** | 對多位元組字元正確、不切在字元中間；`length` / `substring` / `pad` Unicode 安全 |
| 大小寫 | 僅折疊 ASCII `A-Z` / `a-z`，非 ASCII 原樣 | 完整 Unicode 大小寫映射超出範圍；明確不做半套（文件載明） |
| `concat` / `format` | `concat` 變參拼接（各引數須字串）；`format` `{i}` 索引佔位 + `{{` / `}}` 轉義 | 覆蓋「拼接」與「依樣板組字」；`format` 可字串化 Number / Bool / Null |
| `split` / `join` | `split` 依分隔字串切（空分隔 → 逐碼位）；`join` 連接字串清單 | 標準切 / 併語意；保留空段；`split` ↔ `join` 可往返 |
| 判斷 | `contains` / `starts_with` / `ends_with` 回 Bool | 位元組子字串比對（對合法 UTF-8 等價碼位比對） |
| 錯誤（不靜默） | 非字串 / 非整數引數 → 型別錯誤；substring 起點 / 長度越界、format 佔位越界、空 `replace` 來源、空 `pad`、負寬度 → 明確錯誤 | NFR-04；絕不回可疑預設值或靜默截斷 |
| 函式表 | `function_table()`（名稱 → 變參 `StringFn`）+ `find_function()`；表項內建元數檢查 | 供 E7-05 未來函式呼叫 / 任一上層以名稱分派；元數不符亦明確報錯 |
| 內部錯誤傳遞 | 受控例外 `StrException` 承載 `EvalError`，於各公開函式 `guard()` 邊界捕捉轉 failure | 內部碼乾淨、對外無例外（沿用 E7-05 手法） |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。不含能力閘控呼叫（純字串邏輯），
無 `has()` 降級路徑需求。
