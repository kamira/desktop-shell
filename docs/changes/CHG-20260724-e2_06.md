# CHG-20260724-e2_06 — 儲存容量（E2-06）

- Date: 2026-07-24 | Branch: feat/e2_06 | Risk: low | Implemented by: I1.59
- Skill: ai-sdlc-autopilot

## Motivation
E2-06「儲存容量」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過 **E2-01 統一指標介面**
（擴充點 1 契約）把「儲存容量」（每個磁碟 / 掛載點的 總容量 / 已用 / 可用 bytes 與使用率 %）掛成
一組指標，並以 **E2-02 採集頻率分級**決定採樣節奏（容量變動慢，屬週期低頻採集——E2-02 亦以
「磁碟容量」為 Low 分級的範例）。這是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的又一個
具體實例——它**消費 E2-01 / E2-02 契約、不自造指標模型或排程器**。本單元是最終「Disk / Storage
Widget」的核心資料來源。相位 1（Mac / null 期）**絕不接任何真實檔案系統 / 磁碟 API**（不含
`statvfs` / `GetDiskFreeSpace` / `#ifdef` / win32 / cocoa / mach）；改為**可注入的 StorageStatSource
來源抽象**（列舉磁碟 + 每磁碟容量）+ null / 假來源；真實平台後端留待相位 2。

## Impact

### 新增 `modules/sysinfo/e2_06/`（module 層 / 子系統 sysinfo）
- `storage_capacity.hpp` / `storage_capacity.cpp`（`namespace ds::sysinfo`）：
  - **值模型**（平台中立）：
    - `DiskCapacity`：單一磁碟 / 掛載點的容量讀值——穩定識別碼 `id`（掛載點 / 裝置）+ 顯示名
      `name` + `total_bytes` / `used_bytes` / `free_bytes` + `valid`（false = 無讀值）。刻意不含
      平台專屬欄位。工廠 `of(...)`（有效讀值）/ `unknown(id,name)`（存在但無讀值）；含相等運算子；
      便利成員 `usage_ratio()`。真實檔案系統常保留區塊，故 used+free 未必等於 total——本層不強制此
      不變式，使用率一律由 used/total 得出。
  - **使用率演算法**（自由函式，獨立可測、純算術）：
    - `disk_usage_ratio(used, total)`：使用率比率 = used/total，夾到 [0,1]。防護：total==0（無容量）
      →0、used>total（理論不該發生）→夾到 1.0。
  - **容量來源**（提供者只依賴此抽象）：
    - `StorageStatSource`（抽象 `enumerate() const → vector<DiskCapacity>`，給目前各磁碟容量快照，
      決定性順序）。
    - `NullStorageStatSource`：相位 1 null / 假來源——**不接真實磁碟 API**，持一列注入磁碟，
      `enumerate()` 直接回該列；預設空列 = 無磁碟（誠實預設）；`set_disks` / `add_disk` / `clear`
      注入，供測試與假感測器情境。
  - **提供者** `StorageCapacityProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.storage"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**四個平行
    指標**（一個 MetricValue 只帶一個數值維度，而每磁碟要表達四個量，故拆四指標，各磁碟為其實例）：
    - `"storage.usage"`（name="Storage Usage"、unit="%"、range=`bounded(0,100)`）
    - `"storage.capacity.total"`（name="Storage Total"、unit="B"、range=`at_least(0)`）
    - `"storage.capacity.used"`（name="Storage Used"、unit="B"、range=`at_least(0)`）
    - `"storage.capacity.free"`（name="Storage Free"、unit="B"、range=`at_least(0)`）
    - **每磁碟一個可列舉實例**：四指標共用同一組實例（同 `instance_id`=磁碟 id、`label`=磁碟名），
      故掛件可對「同一顆磁碟」讀其使用率與三個容量欄位。各實例保留歷史環（`kDefaultHistory=64`），
      配合 E2-02 週期採集鋪成容量序列。磁碟以列舉順序（索引）對齊。
    - `sample()`：重新讀來源、把新容量寫入各實例（推入歷史）；磁碟數增加則**動態新增**磁碟實例
      （既有參照不失效，unique_ptr 持有），減少則多出者四槽皆設未知（不污染歷史）。register 尚未
      呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Low`，建構子可覆寫），
      供呼叫端 `SamplingScheduler::add_demand`。
    - `disk_count()`：目前的磁碟實例數。
  - 無讀值語意：指標仍掛上；磁碟 `valid==false` 時四槽皆以未知誠實表達，而非塞假值。source 為 null
    亦保守不崩（四指標皆掛上、0 磁碟）。
  - `CMakeLists.txt`：`add_library(e2_06)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_06` + `add_test(NAME e2_06)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` / `InMemoryMetric` /
  `InMemoryMetricInstance` / `MetricRange`）＋ E2-02 採集頻率分級（`ds::metrics::SamplingTier` /
  `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / `statvfs` / `GetDiskFreeSpace` / mach 等真實磁碟 API
  （backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_06.cpp`（gtest，22 案例）
- 提供者身分（3）：`provider_id` / 四個 `kMetric*` / 單位常數穩定；可上轉為 E2-01 `MetricProvider`；
  預設採集分級 = Low（可覆寫）。
- 註冊（1）：`add_provider` 掛上**四個平行指標**（`add_provider` 回 4）。
- **每磁碟容量欄位 + 使用率**（1）：四指標共用同一磁碟實例 id / label；total/used/free bytes 與
  使用率 % 讀值正確（250/500=50%）。
- **多磁碟**（1）：多顆磁碟列舉為多實例（順序決定性）、各自使用率正確。
- **磁碟數變動**（2）：掛載新磁碟 → 動態新增實例（既有參照不失效）；卸載 → 多出者四槽設未知
  （不縮減、誠實表達）。
- **0% / 滿載 / total=0 邊界**（3）：`disk_usage_ratio` 0% / 滿載 / total=0 / used>total；經提供者
  0% 與 100% 與 total=0（仍為有效讀值、使用率 0）；`DiskCapacity::usage_ratio` 成員。
- **無讀值 invalid**（4）：磁碟 `valid=false` → 四槽皆未知；source 為 null 指標 → 四指標掛上、0 磁碟、
  不崩、`sample()` no-op；`NullStorageStatSource` 預設空、注入後可讀；`sample()` 未註冊為 no-op。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（Low 間隔 64）登記需求、推進 tick 於到期時呼叫
  `sample()` → 歷史累積、值前進；除頻合併多消費者（最高頻者供給、撤銷後降頻）。
- 範圍 / 消費者範式 / 重複註冊（3）：usage `bounded[0,100]`（50% 正規化 0.5）、容量指標 `at_least(0)`
  上無界不可正規化；掛件風格消費者只走 E2-01 registry / Metric 抽象介面；同一組 id 第二次掛上四個
  皆保守拒絕、不覆寫。
- 值模型單元（2）：`DiskCapacity` 工廠 / 相等；`NullStorageStatSource` 注入 / clear。
