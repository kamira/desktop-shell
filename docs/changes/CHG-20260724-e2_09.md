# CHG-20260724-e2_09 — 電源與電池狀態（E2-09）

- Date: 2026-07-24 | Branch: feat/e2_09 | Risk: low | Implemented by: I1.62
- Skill: ai-sdlc-autopilot

## Motivation
E2-09「電源與電池狀態」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把電源 / 電池狀態掛成一組指標，並以 **E2-02 採集
頻率分級**決定採樣節奏（電源狀態變動慢，屬低頻採集）。這是「新增指標 = 新增
`MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 / E2-02 契約、不自
造指標模型或排程器**。本單元是最終「電池 / 電源 Widget」的核心資料來源。相位 1
（Mac / null 期）**絕不接任何真實電源 API**（不含 IOKit / IOPowerSources /
`GetSystemPowerStatus` / `#ifdef` / cocoa）；改為**可注入的 `PowerStatSource` 抽象** + null /
假來源（固定 / 序列，可模擬無電池桌機）；真實平台後端留待相位 2。

電源 / 電池指標（見單元規格）：電池電量(%)、充電狀態（charging / discharging / full /
no-battery）、是否接電源、剩餘時間估計(分鐘)、循環次數（可選）、健康度（可選）。無讀值
以 `valid==false`（未知）誠實表達，而非塞假值。

## Impact

### 新增 `modules/sysinfo/e2_09/`（module 層 / 子系統 sysinfo）
- `power_status.hpp` / `power_status.cpp`（`namespace ds::sysinfo`）：
  - **充電狀態列舉**（平台中立）：`ChargeState`（`NoBattery=0` / `Discharging=1` /
    `Charging=2` / `Full=3`）；`to_string`（穩定字串 "no-battery"/…）、`charge_state_label`
    （顯示標籤 "No Battery"/…）、`charge_state_code`（數值碼，供掛成 number 維度）。
  - **狀態值模型**（平台中立）：`PowerStatus`——`valid`（false = 無讀值）、`on_ac_power`、
    `state`、`percent`（電量 % [0,100]，optional）、`minutes_remaining`（剩餘分鐘，
    optional）、`cycle_count`（可選）、`health_percent`（健康度 %，可選）。各電池專屬欄位
    以 optional 表達「有無此讀值」，故無電池桌機自然表達為 `valid==true` +
    `state==NoBattery` + `on_ac_power==true` + 其餘 optional 皆 nullopt。工廠：`unknown()`、
    `no_battery(on_ac=true)`、`battery(percent, state, on_ac, minutes=nullopt)`；含相等運算子。
  - **狀態來源**（提供者只依賴此抽象）：
    - `PowerStatSource`（抽象 `sample()→PowerStatus`；非 const，序列型來源取樣有副作用）。
    - `NullPowerStatSource`：相位 1 null / 假「固定狀態」來源——**不接真實電源 API**，預設回
      無讀值；`set_status` / `clear` 注入（可以 `no_battery()` 模擬桌機），供測試與假感測器情境。
    - `SequencedPowerStatSource`：相位 1 null / 假「序列狀態」來源——注入狀態序列（模擬時間
      推進下的狀態演變，如充電狀態轉換、電量下降），`sample()` 回下一份、列盡持續回最後一份、
      空列回無讀值；`set_sequence` / `push_status` / `reset` 注入。
  - **提供者** `PowerProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.power"`；`register_metrics(registry)` 向 E2-01 註冊表掛上**六個
    單一實例指標**（各維度單位 / 值域不同，故各為獨立指標，非同一指標的多實例）：
    - `power.battery.level`（"Battery Level"，unit="%"，range=`bounded[0,100]`）
    - `power.battery.state`（"Battery State"，unit=""，range 無界；number = 狀態碼、
      text = 顯示標籤如 "Charging"）
    - `power.ac.online`（"AC Power"，unit=""，range=`bounded[0,1]`；1/0 + text "Online"/"Offline"）
    - `power.battery.time_remaining`（"Battery Time Remaining"，unit="min"，range=`at_least(0)`）
    - `power.battery.cycles`（"Battery Cycle Count"，unit=""，range=`at_least(0)`；可選）
    - `power.battery.health`（"Battery Health"，unit="%"，range=`bounded[0,100]`；可選）
    - `sample()`：重新讀來源、把新狀態寫入各指標（有效值推入歷史，各實例保留歷史環
      `kDefaultHistory=64`）；無讀值 / 缺可選欄位者設未知（不污染歷史）。register 尚未呼叫時
      為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Low`，電源變動
      慢；E2-02 註解即以「電池健康」為低頻例；建構子可覆寫），供呼叫端 `add_demand`。
  - 無讀值語意：指標仍掛上；各維度以 `valid==false`（未知）誠實表達。source 為 null 亦保守
    不崩（全部指標掛上、皆未知、`sample()` no-op）。
  - `CMakeLists.txt`：`add_library(e2_09)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_09` + `add_test(NAME e2_09)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance` / `MetricValue` / `MetricRange`）＋ E2-02 採集
  頻率分級（`ds::metrics::SamplingTier` / `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / IOKit / IOPowerSources / `GetSystemPowerStatus` 等真實電源
  API（backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_09.cpp`（gtest，27 案例）
- 提供者身分（3）：`provider_id`/六個 metric id 穩定；可上轉為 E2-01 `MetricProvider`；
  預設採集分級 = Low（可覆寫）。
- 註冊 / 列舉（1）：`add_provider` 掛上六個單一實例指標（各 `is_single`、`kSingleInstanceId`）。
- 電量 %（2）：讀值正確、unit="%"；0% / 100% 邊界。
- 充電狀態（2）：碼 + 顯示標籤 + 穩定字串；state 指標 number = 碼、text = 標籤。
- **充電狀態轉換**（1）：序列來源 放電→充電→滿，逐次 `sample()` 前進（狀態碼 / text / 電量
  同步更新）。
- 是否接電源（2）：online/offline 的 1/0 + text；AC 指標 range=`bounded[0,1]`。
- 剩餘時間（2）：分鐘讀值、unit="min"、range=`at_least(0)`；未提供估計時未知（電量 / 狀態 /
  AC 仍有讀值）。
- 循環次數 / 健康度（2）：提供時讀值正確；未提供時該指標未知（可選欄位誠實缺讀值）。
- **無電池(桌機)**（1）：狀態誠實為 no-battery、AC online，但電量 / 剩餘時間 / 循環 / 健康度
  皆未知。
- **無讀值 invalid**（1）：預設 null 來源 → 全部六指標未知。
- null 來源行為（3）：source 為 null → 六指標掛上、皆未知、`sample()` no-op；先無讀值後注入
  → 可讀、clear 後回未知；`sample()` 未註冊為 no-op。
- 序列來源列盡 / 空列（1）：列盡持續回最後一份、reset 回起點、空列回無讀值。
- **經 E2-02 頻率採樣**（2）：以 `SamplingScheduler`（Low 間隔 64）登記需求、推進 tick 於到期
  時呼叫 `sample()` → 歷史累積（初值 + 3 次採樣 = 4 筆、值遞降）；除頻合併多消費者（最高頻者
  供給、撤銷後降頻）。
- 範圍 / 消費者範式 / 重複註冊（2）：level range=`bounded[0,100]`（50% 正規化 0.5）；掛件風格
  消費者只走 E2-01 registry / Metric 抽象介面；同組 id 第二次掛上全數保守拒絕、不覆寫。
- 值模型單元（1）：`PowerStatus` 的 `unknown` / `no_battery` / `battery` 工廠與相等運算子。
