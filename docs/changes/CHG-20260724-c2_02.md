## Motivation

C2-02「系統狀態（指標可選：CPU/GPU/RAM/儲存/網路/電池/IO…）」：可選一組指標透過 **E2-01**
統一指標介面讀取，以 **E4-03** 量表 / 長條 / 進度視覺元素 + **E4-01** 文字排版呈現，經
**E7-03**（`vars:` 段落作用域）與 **E7-05**（min/max 靜態公式、每指標 transform 動態單位換算
公式）宣告式決定顯示哪些指標與如何格式化，並以 **E2-02** 除頻排程對各指標登記取樣分級需求。
掛 **C1-01**（`SkinProfile`）為桌面基底。這是一個**組裝型 artifact 單元**（非新引擎邏輯），
且是**最終 CPU/GPU Usage 驗證器的核心前身**——驗收重點是擴充點組裝正確、指標可選可組：消費者
只依賴 E2-01 的抽象介面，不寫死任何具體感測器；新增一種指標只需在宣告式設定的 `metrics:`
清單多加一筆。相位 1：純資料 / 邏輯組裝，無真實感測器讀取。

組裝的七個擴充點：
- **C1-01**（`SkinProfile`）：桌面基底——圖層 / 輸入策略 / 透明外形 / 自由拖曳，本單元不
  重造，以 `base()` 存取。
- **E2-01**（`MetricRegistry` / `Metric` / `MetricInstance`）：**唯一的指標讀取入口**——
  `refresh(source)` 只呼叫 `source.get(id)` 與其抽象 `Metric`/`MetricInstance` 介面，完全
  不觸及任何具體感測器型別；相位 1 注入式來源可為未註冊任何指標的空 `MetricRegistry`
  （null / stub provider 語意）。
- **E2-02**（`SamplingScheduler` / `SamplingTier`）：**自查結果**——本單元標頭指出其為「採集
  頻率分級與除頻」，非另一指標集。組裝為 `sync_demands(scheduler)`：對每個已設定指標依其
  宣告式 `tier` 登記一筆需求（除頻合併由 E2-02 負責），`release_demands()` 撤銷。
- **E4-01**（`TextLayout`）：把每筆「標籤: 格式化值」文字排版為渲染描述（相對佈局，NFR-02）。
- **E4-03**（`BarElement` / `GaugeElement` / `ProgressElement`）：**自查結果**——確認為長條 /
  進度 / 量表視覺元件（非文字或其他），把指標值依範圍組裝為渲染描述；`Text` 顯示種類則不掛
  E4-03 元素，只呈現文字。
- **E7-03**（`build_scope`）：由宣告式設定的 `vars:` 段落建立具名常數作用域（如 `gb:
  1073741824`），供 E7-05 公式引用。
- **E7-05**（`Evaluator` / `is_formula` / `formula_body`）：min/max 可為**靜態**公式（求值於
  `configure()` 時，作用域僅含 `vars:` 常數）；`transform` 為**動態**公式（求值於
  `refresh()` 時，作用域為 `vars:` 常數 + 當次指標原始值變數 `value`），用於單位換算等格式化。

## Impact

### 新增 `content/widgets/c2_02/`

- `system_status_widget.hpp` / `.cpp`：`namespace ds::widgets`。
  - `SystemStatusWidget`：注入式相依 `ds::kernel::KernelBackend&` + `ds::kernel::LayerStack&`
    （透傳給內部自持的 C1-01 `SkinProfile` 基底）、`const ds::render::FontMetrics&`（E4-01
    排版用，不取得所有權）。內部自持一個 E4-01 `TextLayout`（綁定 `"<id>.text"` 目標
    surface）與一份由 E7-03 `build_scope()` 建成的 E7-02 `VariableScope`。
  - `configure(const Value&)`：解讀 `vars:`（選填 Map，E7-03 段落）+ `metrics:`（**必填**
    List，可為空清單 = 「空選擇」）。每筆指標項目欄位：`id`（必填非空字串）、`label`（選填
    覆寫）、`kind`（"bar"/"gauge"/"progress"/"text"，預設 "bar"）、`min`/`max`（數字或 E7-05
    靜態公式，須成對提供、且不得退化）、`transform`（選填 E7-05 公式，語法須符合
    `is_formula()`，求值延後至 `refresh()`）、`tier`（"high"/"normal"/"low"/"on-demand"，
    預設 "normal"）。`vars:` 非 Map → `ResolveError`；min/max 靜態公式求值失敗 →
    `FormulaError`；其餘結構 / 具名值不合法 → `Invalid`；全有或全無（失敗不改既有選擇）。
  - `sync_demands(scheduler)` / `release_demands()`：依各指標 `tier` 對注入的 E2-02
    `SamplingScheduler` 登記 / 撤銷需求，冪等（重複呼叫、切換 scheduler 皆安全）。
  - `refresh(const MetricRegistry&)`：未 `configure()` → `Invalid`。逐筆指標向注入來源查詢；
    **NFR-03**：指標不存在（`get()==nullptr`）、無實例、值 `valid==false`、值非有限
    （NaN/Inf）、或 `transform` 求值失敗 / 結果非有限 → 該筆 `available=false`（降級略過，
    **不**中止其餘指標）；否則填入 `raw_value` / `unit` / `display_value`（經 transform 或
    原樣）/ 顯示範圍（宣告式覆寫 > `Metric::range()` 有界 > 保守預設 `[0,100]`）。整體回傳
    恆為 `Ok`（除非未 configure）。
  - `render()`：未 `refresh()` → `Invalid`。對每筆最近一次 `refresh()` 結果，`available` 者
    依 `kind` 組裝 E4-03 `Bar`/`Gauge`/`Progress` 渲染描述（`Text` 種類不建立元素）+ 格式化
    顯示文字（一位小數，"%" 單位緊接無空白、其餘單位以空白分隔）+ E4-01 文字排版；
    `unavailable` 者以 "—" 佔位文字呈現（仍完成 E4-01 排版，元素維持未綁定），符合
    NFR-03「降級顯示」而非整筆消失。
  - 具名列舉：`MetricElementKind`（Bar/Gauge/Progress/Text）、`SystemStatusStatus`
    （Ok/Invalid/ResolveError/FormulaError），各附 `to_string()`（NFR-02）。
- `CMakeLists.txt`：`add_library(c2_02 STATIC)` + `target_link_libraries(c2_02 PUBLIC c1_01
  e2_01 e2_02 e4_01 e4_03 e7_03 e7_05)` + `test_c2_02`（`tests/c2/test_c2_02.cpp`）+
  `add_test(NAME c2_02)`。
