## Motivation

C4-05「AI 對話面板」（聊天氣泡對話框）：顯示對話訊息串、可送出輸入。這是一個**組裝型
artifact app**：不新增引擎邏輯，而是把四個已合併的擴充點組成單一應用 + 行為
（`load_conversation` / `append_message(role, text)` / `submit_input` / `scroll`）：

- **C1-05**（`ds::profiles::SummonPanelProfile`）：本面板的召喚 / 收起生命週期——
  以參考持有，`submit_input()` 委派 `is_open()` 閘控。
- **E4-01**（`ds::render::TextLayout` / `FontMetrics`）：文字排版；本單元亦直接以它量測
  草稿輸入（`measure_draft()`）。
- **E4-11**（`ds::elements::TypewriterElement`）：對話串每則訊息的**顯示元素**——逐字顯示
  （typing effect），內部消費 E4-01 對「目前已顯示前綴」排版。
- **E2-14**（`ds::sysinfo::HttpFetchProvider`）：上下文指標來源；本單元以參考持有一個已由
  呼叫端註冊的提供者，`refresh_context()` 委派其 `sample()`。

相位 1：純資料模型 + 注入式，**無真實 LLM 呼叫**——送出輸入後的助理回應由可注入的
`ResponderFn` 產生（未設定則用內建可預期樣板 stub）。

## Impact

### 新增 `apps/c4_05/`

- `chat_panel.hpp` / `.cpp`：`namespace ds::apps`。
  - `ChatPanelApp`：以 `SummonPanelProfile&`（C1-05）+ `const FontMetrics&`（E4-01）+
    `HttpFetchProvider&`（E2-14）+ `LayoutConstraints` + `SurfaceId` 建構。
  - `load_conversation(turns)`：批次取代整段對話（清空重建，捲動歸底）。
  - `append_message(role, text)`：附加一則訊息；`auto_scroll()` 為真時捲動跟進新訊息，
    否則保留使用者目前捲動位置（不打斷回顧歷史）。非法 UTF-8 → `std::invalid_argument`
    （沿用 E4-01 `decode_utf8` 驗證，不靜默）。
  - `submit_input(text)`：面板未開啟 → `PanelClosed`；去除首尾空白後為空 → `Empty`；
    否則附加一則 `User` 訊息（原文）→ 呼叫回應器（`set_responder()`；未設定用內建
    stub，回覆內容可辨識為 stub、非真實 LLM）產生回應 → 附加一則 `Assistant` 訊息，回
    `Ok`。
  - `advance(dt)` / `attach(driver)`：對所有訊息推進逐字顯示（E4-11），或綁一個 E4-09
    `AnimationDriver`（新附加的訊息自動一併掛上）。
  - `scroll_to(index)` / `scroll_by(delta)` / `scroll_to_latest()`：依**訊息序數**捲動
    （非絕對座標，NFR-02）；越界 / 空對話明確回 `false`，`scroll_by` 夾在合法範圍。
  - `refresh_context()` / `context_value()`：委派 E2-14 採集 / 讀上下文指標快照。
  - `measure_draft(text)`：直接呼叫 E4-01 `TextLayout::measure()` 量測草稿輸入。
  - 具名結果 `MessageRole`（User/Assistant/System）、`SubmitStatus`（Ok/Empty/PanelClosed）
    附 `to_string()`（NFR-02）。
- `CMakeLists.txt`：`add_library(c4_05 STATIC)` + `target_link_libraries(c4_05 PUBLIC
  c1_05 e2_14 e4_01 e4_11)` + `test_c4_05`（`tests/c4/test_c4_05.cpp`）+
  `add_test(NAME c4_05)`。

### 新增 `tests/c4/test_c4_05.cpp`（gtest，24 案例）

涵蓋：`load_conversation`（批次多角色訊息、取代既有對話、非法 UTF-8 擲例外）、
`append_message`（auto_scroll 跟進 / 使用者往回捲後解除跟進、非法 UTF-8 不留半份訊息）、
`submit_input`（面板未開啟拒絕 / 空白 no-op / 附加使用者 + 注入 stub 助理回應 / 自訂回應器
逐輪遞增、面板收起不清空既有對話）、捲動（越界回 false 不動狀態、`scroll_by` 夾範圍與
auto_scroll 重新開啟）、E4-01（`measure_draft` 直接量測）+ E4-11（`render_message` 逐字
顯示遞增、經 E4-09 `AnimationDriver` 心跳自動推進——含新附加訊息自動一併掛上）、E2-14
上下文指標（未注入回應 → 無讀值 / 注入後成功採集）、空對話查詢（越界例外、捲動 no-op）、
`to_string()` 具名字串。

### 相位 1 約束遵循

- 純資料 / 邏輯組裝，無真實 GUI、無真實網路（E2-14 `NullHttpTransport`）、無真實 LLM 呼叫
  （`submit_input` 回應為注入式 `ResponderFn`）；無平台分支（無 `#ifdef` / win32 / cocoa）。
- 核心 API 無絕對座標、無數字 z-order（NFR-02）：捲動以訊息序數定址（沿用 E4-01
  `LineBox::line` / E2-01 `Metric::instance(i)` 同款序數慣例，非畫面座標）。
- 無效操作一律明確回具名結果，不靜默：面板未開啟即送出、空白輸入、捲動越界 / 空對話、
  訊息索引越界（`std::out_of_range`）、非法 UTF-8（`std::invalid_argument`）。

### 實作期修正一則（記錄備查）

初版 `messages_` 直接以值存於 `std::vector<MessageEntry>`；`TypewriterElement::attach()`
（E4-11/E4-09）以 lambda 捕捉 `this` 掛上動畫驅動源，而 vector 於新增訊息時的重新配置會
搬動既有元素，使已綁定動畫的捕捉位址懸空（本機驗證的 `AttachBindsAnimationDriverAnd
AutoAdvancesOnHeartbeat` 測試因而失敗——第二次心跳未能推進新訊息）。改為
`std::vector<std::unique_ptr<MessageEntry>>`：重新配置只搬動指標本身，各 `MessageEntry`
（含其 `TypewriterElement`）的堆積位址於其存活期間恆穩定。修正後全數 24 案例 PASS。
