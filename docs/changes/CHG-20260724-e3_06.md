# CHG-20260724-e3_06 — 亮度設定（E3-06）

- Date: 2026-07-24 | Branch: feat/e3_06 | Risk: low | Implemented by: I1.51
- Skill: ai-sdlc-autopilot

## Motivation
E3-06「亮度設定」是 modules/actuators（動作層 / 子系統 actuators）的一個**螢幕亮度致動器**：
把「設定螢幕亮度（0–100）／相對增減／查詢目前亮度，皆可指定顯示器索引以支援多顯示器」
這組副作用，以具名命令掛上 **E6-01 命令匯流排**（擴充點 3「動作」契約）。呼叫端只需
命令 id + 具名參數即可觸發，**不需相依本致動器或任何 OS 亮度 API**——與已合併的 E3-05
（音量設定）、E3-02（啟動 / 開檔）採同一「注入式後端 + null 樣式」範式。相位 1（Mac / null 期）
**絕不呼叫真實 OS 亮度 API**（不含 IOKit / DisplayServices / IODisplay / cocoa / win32 等），
只提供**平台中立介面 + null / 假後端（純記憶體狀態模擬）+ 契約測試**；真實平台後端留待
相位 2，屆時致動器與命令契約一行不動。

## Impact

### 新增 `modules/actuators/e3_06/`（module 層 / 子系統 actuators）
- `brightness_actuator.hpp` / `brightness_actuator.cpp`（`namespace ds::actuators`，與 e3_05 一致）：
  - 三個具名命令 id（穩定可讀字串，不用數字 opcode）：`brightness.set` / `brightness.get` /
    `brightness.adjust`。
  - `kBrightnessMin=0` / `kBrightnessMax=100` + `clamp_brightness(int)`：致動器層唯一的
    「合法化」點（亮度為相對值域 0–100，非絕對座標 / z-order）。
  - `kDisplayDefault=0`：未指定 `display` 參數時採用的預設顯示器索引（相對序號、非絕對座標）。
  - `BrightnessState` struct：`display`（恆 >= 0）+ `level`（恆在 [0,100]）；含相等運算子，
    供查詢 / 內省。
  - `BrightnessBackend` 抽象後端：最小介面 `set(display, level)` / `get(display)`（以顯示器
    索引定址）。相位 2+ 由平台後端以真實亮度 API 實作；致動器只依賴此抽象。契約：傳入
    `set()` 的 display 已驗證 >= 0、level 已由致動器夾限至 [0,100]（後端可信任）。
  - `NullBrightnessBackend`（相位 1 預設後端）：**不接真實系統亮度 API**，每個顯示器索引
    各自維護一個亮度值（`std::map<int,int>`，遍歷決定性），未曾設定過的顯示器回可注入的
    預設亮度（預設 50）；`set()` 亦自夾限；`state(display)` / `known_displays()` /
    `default_level()` 內省。讓致動器在無真實後端時仍可完整跑通、多顯示器互不干擾、狀態一致。
  - `BrightnessActuator`：建構綁定一個 `BrightnessBackend`（預設 NullBrightnessBackend）。
    `register_on(bus)` 把三個具名命令註冊到 E6-01 匯流排（全成功才 true；任一失敗回滾
    已掛者、不遮蔽既有致動器；無後端回 false）；`unregister_from(bus)` 回移除數（0..3）。
    處理器亦可直接呼叫（測試不經匯流排也能驗證語意）：
    - `brightness.set`：必填 `level`（int）；選填 `display`（int，預設 0）；level 超出
      [0,100] 自動夾限（不失敗）；回夾限後亮度。
    - `brightness.get`：選填 `display`（int，預設 0）；回該顯示器目前亮度（int）。
    - `brightness.adjust`：必填 `delta`（int，可負）；選填 `display`（int，預設 0）；以 int64
      相加後夾限至 [0,100]（防溢位）；回夾限後亮度。
    缺 / 型別錯的必填參數，或 `display` 型別錯 / 為負 → `CommandResult{Failed}`（以 `has()` /
    `get_int` 保護，不崩潰、不改後端狀態、不丟例外）。所有成功結果的 `value` 皆為夾限後目前
    亮度（int），`message` 帶 `display=<索引>` 供診斷。
  - `brightness_contract_version()`：契約版本標記 `"e3_06/1.0.0"`（定義在 .cpp，使 STATIC
    程式庫非空並集中版本字串；命名加 `brightness_` 前綴避免與同命名空間 e3_05 的
    `volume_contract_version()` / e3_02 的 `contract_version()` 衝突）。
  - `CMakeLists.txt`：`add_library(e3_06 STATIC brightness_actuator.cpp)` **PUBLIC 連上游
    `e6_01`**（標頭 include `command_bus.hpp`，須傳遞 include 目錄）；
    `test_e3_06`（`tests/e3/test_e3_06.cpp`）+ `add_test(NAME e3_06)`。
- 上游相依：E6-01 命令匯流排（`ds::command::CommandBus` / `CommandArgs` / `CommandResult` /
  `CommandValue`），可讀不可改——消費擴充點 3「動作」契約，不自造匯流排或值型別。
- **無** `#ifdef` / win32 / cocoa / IOKit / DisplayServices 等真實亮度 API（backend_guard 綠燈）。
  致動器邏輯（夾限、顯示器索引驗證、分派、結果回報）與後端完全解耦、純邏輯、平台中立、可注入。

### 測試 `tests/e3/test_e3_06.cpp`（gtest，27 案例）
- 註冊 / 反註冊（4）：三命令全掛、重複註冊回滾且不改既有、null 後端不可註冊、
  unregister 移除全三個且再呼叫回 0。
- 設定 + 分派 + null 後端一致（3）：經匯流排 set 更新後端、get 反映先前 set、
  未設定顯示器回注入預設。
- 範圍夾限（3）：超上限夾至 100、超下限夾至 0（皆不失敗）、`clamp_brightness` 邊界。
- 相對增減（2）：正負 delta、跨越邊界上下夾限。
- 多顯示器索引（4）：不同顯示器互不干擾、省略 display 預設 0、adjust 依顯示器、
  `known_displays()` 內省（有序）。
- 無效參數（5）：set 缺 level / 型別錯、adjust 缺 delta、display 型別錯、display 為負
  → Failed 且不改後端狀態。
- 未知命令（1）：匯流排回 NotFound（不崩潰）。
- null 後端序列一致（1）：連續 set / 夾限 / 多顯示器後狀態一致。
- 直接呼叫處理器（3）：set 語意等價（含顯示器）；無後端各處理器回 Failed；
  current_state 負索引回預設。
- 契約版本標記（1）。
