## Motivation

桌面外殼需要處理滑鼠按鍵事件：按下 / 放開 / 點擊（down/up/click）、左 / 中 / 右鍵、
多擊（double / triple），並以幾何命中測試（E1-04）判定事件落在哪個具名 surface，
再把事件路由（dispatch）給命中之 surface 的訂閱者。這是輸入處理的基礎積木，供上層
（如視窗拖曳、按鈕點擊、桌面圖示選取）訂閱使用。

本單元屬 engine 層（平台中立純邏輯）：**不接真實滑鼠**，事件由呼叫端 / 測試注入。
命中判定完全委由已合併的上游 E1-04 `HitTester::topmost_hit()`，本單元不重新實作任何
幾何邏輯，只負責「按鍵語意 + 多擊追蹤 + 訂閱 / 路由派發」。相位 2 接真實滑鼠後端時，
介面與分派語意一行不動，後端只需把 OS 滑鼠事件轉為本地座標並呼叫既有 inject 路徑。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 按鍵 | `enum class MouseButton { Left, Middle, Right }` | 具名鍵集合，涵蓋基本三鍵 |
| 動作 | `enum class MouseAction { Down, Up, Click }` | Down/Up 為原始注入動作；Click 為 Down→Up 配對後的合成事件 |
| 事件 | `MouseButtonEvent{ button, action, position, click_count, target }` | 純資料、平台中立；`position` 用 E1-04 `LocalPoint`（本地 / 相對座標，NFR-02）；`target` 為命中之具名 surface |
| 命中判定 | 委由 E1-04 `HitTester::topmost_hit()`，本單元只持有 `std::vector<HitSurface>` | 不重複實作幾何邏輯；具名圖層 + 宣告順序決定 topmost（NFR-02 無數字 z-order） |
| 路由 | `MouseEventRouter::subscribe(target, listener)`：訂閱者綁定**特定具名 surface**；只把命中之 surface 的事件分派給其訂閱者 | 「事件路由」語意直接對應命中結果，未命中不分派給任何人 |
| 路由結果 | `enum class RouteStatus { Hit, NoHit, Invalid }` | 報錯不靜默：呼叫端可分辨命中 / 未命中 / 上游命中測試判定形狀無效三種情形 |
| 多擊追蹤 | 單一「目前連續按鍵」游標（button + target + count）：同鍵同 surface 的 Down 遞增、Up 與游標相符則沿用該 count 並合成 Click、不符或未命中則重置為新游標 | 相位 1 無真實時間來源（無計時器），改以**注入序列**判定連續性，確定性、可測；跨鍵 / 跨 surface / 孤立 Up 皆視為序列中斷 |
| 直接注入 Click | `inject_button(button, MouseAction::Click, position)` 或 `inject_click()`（= Down 緊接 Up） | 直接指定 Click 動作不牽動多擊游標（`click_count` 固定 1），供快速注入；`inject_click()` 走正常 Down/Up 路徑，可構成多擊 |
| 分派順序 / 安全 | 依訂閱順序（`SubscriptionId` 遞增）以 `std::map` 保存；分派前取快照 | 順序穩定、可測；與 E5-13 `KeyboardInputSource` 同慣例，listener 於回呼中訂閱 / 取消訂閱安全 |
| 空 listener / 空 target / 未知 id | `subscribe()` 回 0（無效訂閱，不佔用代號）；`unsubscribe()` 未知 id 為 no-op 回 false | 呼叫端永遠安全，語意保守 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實滑鼠後端，符合相位 1（Mac/null）約束。
engine 層與平台無關（非 `src/kernel/backend/`，不涉 backend_guard）。
