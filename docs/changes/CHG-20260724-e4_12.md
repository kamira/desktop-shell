## Motivation

文字中常需標記「可點擊區段」（hyperlink span）——例如一段說明文字裡有 `[了解更多]`
`[聯絡我們]` 等可點字段，點擊需回報該字段的具名 id 供上層路由動作。已有 E4-01 文字排版
（取得每個字符的相對幾何）與 E1-04 幾何命中測試（判點是否落在某矩形），但兩者之間缺一個
「以字元範圍標記區段 → 用排版幾何 → 用命中測試判點擊落在哪個區段」的整合層。E4-12 補上
這一層，命名空間 `ds::elements`。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 區段標記 | `add_span(start, end, id)`：以原始文字**碼位索引**的半開區間 `[start, end)` + 具名 id | 呼叫端多半以字元位置（非位元組）思考「這段文字是連結」；碼位索引與 E4-01 `decode_utf8` 輸出一致 |
| 確定性字元→字符映射 | **固定要求** `LayoutConstraints.wrap == WrapMode::None` 且 `ellipsis == false`；否則建構期 `std::invalid_argument` | E4-01 的詞界換行（丟棄行尾待落地空白）與省略號裁切（移除字元）會使排版輸出字符序列與原始文字不再一一對應，`add_span` 的字元範圍將失去確定意義。限制在 `WrapMode::None` 下：換行完全由顯式 `'\n'` 決定，原始文字每個碼位（除 `'\r'`/`'\n'` 本身不產生字符）恰依序對應排版輸出一個字符，映射可證明確定 |
| 命中判定 | 對區段涵蓋的每個字元，以其字符幾何（`x` 起點、`advance` 寬、所屬行 `y`、有效行高）建構 E1-04 `Shape::Rect`，將輸入 `LocalPoint` 平移到該字符矩形的本地座標系後呼叫 `HitTester::hit_test` | 直接覆用 E1-04 既有幾何命中邏輯（含邊界判定），不重新發明點在矩形內判定；符合「用 E1-04 判點擊落在哪區段」的需求語意 |
| 越界處理 | `add_span`：`id` 為空 / `start >= end` / `end > text_length()` → `std::invalid_argument`，失敗不改變既有狀態 | 不靜默；範圍不合法沒有安全的靜默解讀 |
| 重疊處理 | 新區段字元範圍與既有任一區段重疊（不論 id 是否相同）→ `std::invalid_argument` | 一點同時屬於兩個具名區段語意不明，寧可拒絕也不悄悄以宣告順序覆蓋 |
| `set_text` 語意 | 成功設定新文字**清空**所有已標記區段 | 舊字元範圍索引到新文字內容意義不明，保留將造成呼叫端誤用；強制重新 `add_span` 更安全 |
| 無命中 | `hit_span` 找不到命中區段 → 回 `std::nullopt`（非例外） | 「沒點到任何連結」是正常結果，不是錯誤 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` 等平台分支；`render_model()` 直接沿用
E4-01 的相對佈局渲染描述，`hit_span` 的輸入點為 E1-04 的本地相對座標——全程無畫面絕對座標 /
數字 z-order（NFR-02）。

## 不含（避免越界）

- **不支援 `WrapMode::Word`（詞界換行）與 `ellipsis`（省略號裁切）**：兩者會破壞本單元依賴的
  確定性字元→字符映射，建構期直接拒絕而非嘗試容錯映射（避免日後發現映射錯位的隱性 bug）。
  若未來需要，須另設計映射策略（如記錄原始索引於排版輸出旁），非本單元 phase 1 範圍。
- 未動根 `CMakeLists.txt`、`units.json`、`docs/structure/directory.md`，或任何鎖定範圍以外的檔案。
- 未修改任何上游檔案（`engine/render/e4_01/**`、`src/kernel/e1_04/**`）。
