## 判定邏輯與兩個不明顯的設計決定

```
S=feat/ 之後的 slug → 取 ACC → 從中讀「受驗 head: <sha>」
  未寫明                       → 紅（那一句專屬訊息）
  sha 不在本倉庫歷史裡           → 紅
  sha 不是當前 head 的祖先       → 紅（那份 ACC 驗的不是這條分支）
  git diff <sha> <head.sha> 失敗 → 紅（fail-closed，不得當成「什麼都沒動」）
  期間動到 docs/acceptance/ 與 docs/worklog/ 以外的任何檔案 → 紅，並印出檔名
```

### 決定一：不是「宣告的 head == 當前 head」

**那個等式永遠不成立**——ACC 自己的提交就會改變 head。要問的是
「**驗收之後有沒有動到被驗的東西**」，所以比的是**兩者之間的檔案清單**。

### 決定二：跟 `github.event.pull_request.head.sha` 比，不跟 `HEAD` 比

`pull_request` 事件下 `actions/checkout` 取的是 **merge ref**，拿 `HEAD` 比會把 base 分支的
變更一起算成「本 PR 在驗收後動過的檔案」——那是**誤報**。漏報只是少擋一次，
而一道會誤殺的閘門很快就會被繞過去，所以這一條有專屬的靜態測試釘住
（`test_compares_against_head_sha_not_HEAD`，同時斷言腳本裡不得出現 `..HEAD`）。

### 放行清單為什麼只有兩個目錄

`docs/acceptance/`（驗收者寫 ACC 本身）與 `docs/worklog/`（驗收者的工作紀錄）。
**`docs/changes/` 刻意不在內**：ACC 也驗 CHG（`G5` 就是從 CHG 取 `Implemented by:`），
CHG 在驗收後被改，驗收者對它的陳述就不再成立。
