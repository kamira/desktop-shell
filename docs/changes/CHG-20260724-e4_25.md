# CHG-20260724-e4_25 — 背景模式（E4-25）

- Date: 2026-07-24 | Branch: feat/e4_25 | Risk: low | Implemented by: I1.140
- Skill: ai-sdlc-autopilot
- Unit: E4-25（背景模式，module 層 / 子系統 elements / phase 1 / risk=low）
- depends_on: E1-03（逐像素 alpha surface）、E4-02（圖片元件）

## Motivation

桌面 shell 的元件 / 面板需要一個共通的「背景呈現模式」描述——純色、漸層、圖片、模糊、或
完全透明，並附帶圓角與邊框。相位 1 的目標是一個**平台中立、可單元測試**的「背景渲染描述
模型」：把「用哪種模式呈現背景、純色是什麼、漸層停駐點與方向、圖片來源、模糊半徑、圓角、
邊框、整體透明度、送到哪個具名 surface」表達為一份描述，供後續相位的繪製層消費。

相位 1 **不做真實繪圖**：不連結任何影像 / 模糊函式庫、不觸碰 OS 繪圖 API。圖片背景**直接
重用上游 E4-02 `ImageElement`**（其本身已用可注入 `ImageSource` 解耦真實解碼），本單元不
重造圖片載入 / 縮放 / 裁切邏輯；模糊僅表達為一個非負「模糊半徑」描述值，真實模糊演算法留給
後續相位的繪製層決定。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 背景模式 | 具名列舉 `BackgroundMode{Solid,Gradient,Image,Blur,Transparent}` | 涵蓋純色 / 漸層(可選) / 圖片 / 模糊 / 透明五種常見背景型態；具名非數字（NFR-02） |
| 顏色 | `Color{r,g,b,a}` 四分量 [0,1] 正規化比例，非有限值拒絕、越界 clamp | 與 E1-03 `AlphaProfile.opacity` 同精神：比例值，非螢幕座標 |
| 漸層 | `GradientStop{position,color}`（position 為沿軸正規化比例 [0,1]）+ `GradientDirection{Vertical,Horizontal,Diagonal}` | NFR-02：位置為比例非像素座標；方向為具名列舉非角度數字 |
| 圖片背景 | 內嵌 `ds::elements::ImageElement`（E4-02），`set_image` 委派其 `set_source`，並開放 `image()` 可變存取器供進一步設定縮放模式 / 裁切 | 不重造圖片邏輯，直接複用已驗證的 E4-02 契約與錯誤語意 |
| 模糊 | `set_blur_radius(double)`，非負、有限 | 描述值即可，真實模糊演算法交由後續相位繪製層 |
| 圓角 | `set_corner_radius(double)`，非負、有限 | 背景自身外觀尺寸，非螢幕位置 |
| 邊框 | `BorderStyle{color,width}`，`width` 非負有限、`color` 分量有限（clamp） | 同圓角精神：外觀描述值 |
| 透明度 | 沿用上游 E1-03 `AlphaProfile.opacity`（比例 [0,1]，自動 clamp）；非有限值 → `Invalid` | 複用上游合成描述，不重造輪子 |
| 目標 | `ds::kernel::SurfaceId`（字串）具名 surface；空字串 → `Invalid` | NFR-02：目標以具名指涉，非數字 handle / index |
| 無效模式 | 未知 / 越界 `BackgroundMode` / `GradientDirection`（如 `static_cast<BackgroundMode>(99)`）→ `Invalid`，不套用 | 「無效模式不靜默」：防止未定義列舉值靜默流入渲染描述 |
| render_model | `BackgroundRenderModel{mode, color, gradient_stops, gradient_direction, image, blur_radius, corner_radius, border, alpha, target}` | 一次組裝目前完整背景狀態供繪製層消費；`image` 欄位直接是 E4-02 的 `ImageRenderModel` |

平台中立：無 `#ifdef` / `win32` / `cocoa` / 真實繪圖 API / 影像解碼 / 模糊函式庫；NFR-02
無絕對座標 / 無數字 z-order（漸層位置為比例、方向為具名列舉、目標為具名、透明度為比例、
圓角 / 邊框寬度為外觀尺寸非螢幕位置）。

## 風險與緩解（low）

- **NFR-02 誤用風險**：可能被誤加螢幕座標 / 數字 z-order → 設計上漸層位置僅接受 [0,1]
  比例、方向僅接受具名列舉、目標僅接受具名字串，圓角 / 邊框寬度為外觀尺寸而非螢幕位置；
  `Nfr02Compliance` 測試組明確守衛。
- **越界列舉靜默流入**：`set_mode`/`set_gradient_direction` 以 `static_cast<Mode>(99)` 模擬
  誤用，明確回 `Invalid` 且不改動既有值；`InvalidNotSilent` 測試組守衛。
- **與 E4-02 契約脫鉤風險**：圖片背景不重新定義任何 E4-02 型別，直接內嵌 `ImageElement`
  並透傳其 `ImageStatus` / `ImageRenderModel`，未來 E4-02 契約演進本單元自動同步。
- **靜默失敗風險**：非有限顏色 / 漸層位置 / 模糊半徑 / 圓角 / 邊框寬度 / 不透明度、負值
  尺寸、空目標名一律回 `Invalid` 且不部分套用；相關「DoesNotMutate」測試守衛。
