## Motivation

E9-04 讓一組「顏色 / 樣式 / 資源集」（宣告式資料）註冊為具名主題並於執行期整體切換。但它
**不生產配色本身**——主題屬性由呼叫端事先備妥。桌面殼層常見的需求是：從**一個種子顏色**
（或來源如桌布主色）**動態生成一整套協調配色**，再交給 E9-04 當作主題套用。

**動態配色生成**單元把色彩理論封裝為一層純函式 API：
- 依色相環關係（互補 / 類比 / 三分 / 單色）從種子色推導次色與強調色；
- 以明度 / 飽和度階生成背景與狀態色；
- 以 WCAG 對比度確保前景相對背景可讀（>= AA 4.5:1）；
- 決定性（同種子同方案 → 位元等價輸出）；
- 無效種子色（通道超界 / hex 格式錯誤）**明確報錯、不靜默**；
- 以 `to_theme_data()` 橋接 E9-04：把配色轉為 `ThemeData`（各色角色 → hex 字串的 `Value` Map）。

平台中立、純邏輯：無任何 `#ifdef` / 系統呼叫 / 真實繪圖 API / 平台分支。屬 engine 層，可完全
單元測試。

## 設計（可覆核可改）

顏色以**平台中立**表示：`RgbColor{r,g,b}`（8-bit 通道）/ `HslColor{h,s,l}`（數值）/ hex 字串；
不綁任何圖形框架型別。生成結果 `ColorPalette` 承載主 / 次 / 強調 / 背景 / 前景 + 四狀態色
（成功 / 警告 / 錯誤 / 資訊），另附所用方案與種子色以利溯源。

| 項目 | 選擇 | 理由 |
|---|---|---|
| 命名空間 | `ds::package` | 與 E9-01~E9-04 一致；`to_theme_data` 直接產出同子系統的 `ThemeData` |
| 色彩表示 | `RgbColor` / `HslColor` / hex 字串 | 平台中立數值 / 字串，不綁繪圖 API |
| 方案 | `ColorScheme{Complementary, Analogous, Triadic, Monochromatic}` | 色相環關係：+180° / ±30° / +120°+240° / 同色相變明度飽和度 |
| 生成 | `PaletteGenerator::generate(seed, scheme) -> PaletteResult` | 種子無效 → failure(帶原因)；主色恆等於種子；決定性 |
| 便捷 | `generate_from_hex(hex, scheme)` | hex 格式錯誤 → failure(帶原因) |
| 可讀性 | `ensure_readable`：前景對背景 < 4.5 則退回黑/白中對比較高者 | 保證 WCAG AA；`contrast_ratio` / `relative_luminance` 供查驗 |
| 狀態色 | 固定語意色相（綠/琥珀/紅/藍），飽和度/明度與種子協調 | 語意穩定又不脫離整體調性 |
| 轉換 | `rgb_to_hsl` / `hsl_to_rgb` / `to_hex` / `from_hex` | 皆平台中立純函式；hsl→rgb 四捨五入到 [0,255] |
| 明度階 | `lightness_scale(base, steps)` | 同色相/飽和度，明度由暗到亮線性分佈（背景/層級用） |
| 橋接 | `to_theme_data(palette, name) -> ThemeData` | attributes = 九色角色 → hex 字串的 `Value` Map；components 空組合 |

介面平台中立：無 `#ifdef _WIN32` 等平台分支、不綁任何真實後端 / 繪圖 API。engine 層與平台無關
（非 `src/kernel/backend/`，不涉 backend_guard）。API 面不出現絕對座標與數字 z-order（NFR-02）。
本單元不含能力閘控呼叫（純計算），無 `has()` 降級路徑需求（NFR-03 不適用）。無效種子色一律
明確報錯、不靜默。
