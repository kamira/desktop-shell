### workflow 的兩處修正（都是實際跑過才發現的）

#### 1. artifact 取不回來 → 產物改推進 assets 分支

`CHG-20260829-02` 的設計是 `upload-artifact`。實際要用時才發現：
**artifact 只能由人在瀏覽器上點下載**；API 端點需要另外的憑證，本執行環境取不到（HTTP 403）。
而這個 repo 是 agent 在操作的 —— **「產物要人去點一下才拿得到」等於這條路只走得完一半。**

改為：同一份產物再推進 `bot/windows-screenshots` 分支（每次 dispatch 覆寫為單一 commit，
不保留歷史；截圖沒有可回溯價值，累積只會讓 repo 長大）。`upload-artifact` 保留給人用。

代價是 `permissions` 由 `contents: read` 升為 `contents: write`，已在檔內註明理由。
該分支不是任何人的工作分支，也不會合併回 `main`。

**順帶修掉一個會直接失敗的 bug**：`git config user.name` 原本下在外層 checkout 上，
但 commit 發生在 `.assets` 這個新 `git init` 的 repo 裡，而 runner 沒有全域 git 身分 ——
身分必須設在新 repo 內。

#### 2. runner 自己的 console 蓋住大半個螢幕

第一次取像成功，但畫面上大半是 runner 的 hosted-compute-agent log 視窗，
widget 只露出右上角（且因 `SetLayeredWindowAttributes` 的 alpha 235，log 文字從 widget 底下透出來——
那是真實行為，但當門面圖太髒）。

加一行 `Shell.Application.MinimizeAll()`，**放在啟動 host 之前** ——
放在之後有把我們自己那個 topmost popup 一起縮掉的風險。

### 這次證實了什麼、沒證實什麼

**證實了**：MSVC 建置的 `desktop_shell_host.exe` 在原生 Windows 上跑得起來；
widget 以真的 Segoe UI 渲染（Wine 版的中文與 `✓` 是換了兩輪代用字型才湊齊的）；
W1-05 自繪選單在實機上正確彈出，四列 + 分隔線、勾號與反白列都正確；
H1-04 的「最上層顯示」勾選狀態確實被持久化並反映在選單上。

**沒證實**：runner 是 1024×768 的無人 VM，**不是任何人的實機桌面**。
沒有真實使用者的 DPI 縮放與多螢幕設定。托盤圖示在通知區的實際外觀、
拖曳與吸邊的手感仍需要有人用眼睛確認（`HANDOFF.md` §0-B 第 4、6 項）。
README 的圖說已據實寫明這一段 —— **省略它，這張圖就會被讀成比它實際證明的更多。**
