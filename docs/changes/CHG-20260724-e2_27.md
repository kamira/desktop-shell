# CHG-20260724-e2_27 — 螢幕像素取樣（E2-27）

- Date: 2026-07-24 (UTC+0) | Branch: feat/e2_27 | Risk: low | Implemented by: I1.29
- Skill: ai-sdlc-autopilot

## Motivation
E2-27「螢幕像素取樣」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「某個螢幕位置的像素顏色」掛成一個指標，供
**環境光（ambient light）／取色（colour picking）** 類掛件消費；取樣的**頻率性質**沿用
**E2-02 採集分級**（`SamplingTier`，預設 Low——像素／環境光變動不快）。這正是「新增指標 =
新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費 E2-01 + E2-02 契約、
不自造指標模型、不自造時鐘**。

位置以**具名 anchor 表達，絕不用絕對座標**（NFR-02）：取樣點是 `ScreenAnchor` 列舉
（`center` / `top-left` / …），核心 API 不含任何 x/y 像素座標或數字 z-order。具名 anchor 的
實際像素落點，留待真實後端相位依當時螢幕幾何解析。相位 1（Mac / null 期）只提供平台中立
介面 + null 後端，**不真的抓螢幕**（回「無讀值」，或回注入的假像素供測試）；真實螢幕擷取
（win32 / cocoa）留待後端相位。

## Impact

### 新增 `modules/sysinfo/e2_27/`（module 層 / 子系統 sysinfo）
- `screen_pixel.hpp` / `screen_pixel.cpp`（`namespace ds::sysinfo`）：
  - `PixelColor` struct：平台中立 8-bit RGBA 顏色 —— `r`/`g`/`b`/`a`；
    `luminance()`（Rec. 601 相對亮度，正規化到 [0,1]，供環境光）、`hex()`（"#RRGGBB"，
    供取色）；含相等運算子與 `rgb()` 工廠。刻意不含平台專屬色彩空間欄位。
  - `ScreenAnchor` 列舉：**九宮格具名取樣位置**（Center / TopLeft / … / BottomRight），
    **不含絕對座標**（NFR-02）。`to_string()`（穩定字串 "center" / "top-left" …，用作
    instance_id）、`to_label()`（人類可讀 "Center" / "Top-Left" …）。
  - `PixelSampleSource` 抽象後端：`sample(anchor) → optional<PixelColor>`（nullopt =
    無讀值）。真實平台後端於相位 2+ 實作；提供者只依賴此抽象介面。
  - `NullPixelSampleSource` null 後端：**不抓螢幕**，預設對任何 anchor 回 nullopt；
    `set_pixel` / `clear` / `clear_all` 注入假像素供測試與假感測器情境。
  - `ScreenPixelProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.screen.pixel"`；`register_metrics(registry)` 向 E2-01 註冊表
    掛上單一指標 `"screen.pixel"`（name="Screen Pixel Color"、unit=""、
    range=`bounded(0,1)`）。**每個具名取樣 anchor = 一個可列舉 `MetricInstance`**
    （instance_id=anchor 字串、label=人類可讀、value=相對亮度(number,[0,1])+色碼文字、
    history=近期亮度環，供 sparkline）。無讀值的 anchor 實例值為未知、不污染歷史。
    建構時 anchor **去重**（保留首次出現順序）。
  - **消費 E2-02**：`sampling_tier()`（本指標採集分級，預設 `SamplingTier::Low`、可調）；
    `register_demand(scheduler)` 把採集需求掛進 E2-02 `SamplingScheduler`（多消費者對同一
    指標的需求由排程器**除頻合併**，有效分級 = 最高頻者）。
  - source 為 null、或空 anchor 清單 → 仍保守掛上指標（實例為未知 / 0 實例），不崩。
  - `CMakeLists.txt`：`add_library(e2_27)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` / `sampling.hpp`，須傳遞 include 目錄）；`test_e2_27` + `add_test(NAME e2_27)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）+ E2-02 採集分級（`SamplingTier` /
  `SamplingScheduler` / `DemandId`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / 真實螢幕擷取（backend_guard 綠燈）。純邏輯、平台中立。
- **無絕對座標 / 數字 z-order**（NFR-02 綠燈）：取樣點以具名 `ScreenAnchor` 表達。

### 測試 `tests/e2/test_e2_27.cpp`（gtest，18 案例）
- PixelColor 工具（2）：亮度（白=1.0、黑=0.0、純綠=0.587）/ 色碼 / 相等。
- 具名 anchor（1）：`to_string` / `to_label` 穩定字串（無絕對座標）。
- 提供者身分（2）：`provider_id`/`kMetricId` 穩定；可上轉為 E2-01 `MetricProvider`。
- 註冊（1）：`add_provider` 掛上一個指標、name/unit/range=bounded(0,1) 正確。
- 注入像素驗值（2）：每 anchor 一實例、value=亮度+色碼、有讀值推入歷史；find_instance。
- null 後端（3）：無讀值→實例值未知不污染歷史、null source 保守不崩、空 anchor→0 實例。
- anchor 去重（1）：重複 anchor 去重保留首次順序。
- 採集頻率 E2-02（3）：預設 Low、可調、掛進 SamplingScheduler 且多消費者除頻合併取最高頻。
- 消費者範式（1）：掛件風格消費者只走 E2-01 registry / Metric 介面，全程無 sysinfo 型別。
- 重複註冊（1）：同 id 第二次掛上被保守拒絕、不覆寫既有。
- null 後端注入 API（1）：set_pixel（含覆寫）/ clear / clear_all。
