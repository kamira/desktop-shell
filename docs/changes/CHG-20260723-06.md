## Motivation
NFR-08「較早階段不得依賴較晚階段」先前只是條文，`stage_check.py` 不存在、CI 也沒有對應閘門。
且既有資料已有 1 筆違規：`E11-02`（階段 A）依賴 `E7-13`（階段 C）——
階段 A 宣稱「做完就能跑 CPU/GPU Widget 驗證器」，但它其實要等階段 C 的單元，該承諾是假的。

## Impact

### 1. 新增 `scripts/stage_check.py`
- 掃描整張相依圖（CI 預設）或單一單元（`--unit`）
- 違規時逐筆輸出 `::error::`，**並明示修補方向**：把被依賴者提前，而非把依賴者延後
- `stage` 欄位缺失或非法 → exit 2（與 `scope_check` 的未知單元同碼）

### 2. `E7-13` 階段錯分修正（C → A）
`E7-13`「階層式項目結構」的 `group` 是 `啟動`，故先前由 `group → stage` 機械推導得到 C。
但查證後它是**共用格式原語**，不是啟動器專屬功能：

| 證據 | 值 |
|---|---|
| module / layer | `E7`（描述子系統）／ core |
| write_scope | `src/format/e7_13/**` |
| priority / wave | **P0** / wave 1 |
| 自身相依 | 僅 `E7-01`（階段 A） |
| 被誰消費 | `E11-02`(A)、`C1-05`(C)、`C2-09`(D)、`C3-01`(C) —— **跨 A/C/D 三階段** |

依 `requirements` 硬性約束 #6 的原則「**被依賴者應提前，而非讓依賴者延後**」，
將 `E7-13.stage` 覆寫為 **A**。`group` 維持 `啟動`（它確實服務啟動器功能），
其餘欄位（`wave`/`depends_on`/`write_scope`/`priority`）一律未動。

> 附帶效益：這也讓待決事項 A3（是否砍 `啟動` 功能群）更乾淨 ——
> 砍掉啟動功能時，這個被階段 A 消費的共用原語不該跟著被砍。

**推導規則因此改為「`group` 對映為預設值 + 明示覆寫」**，已記入 `docs/architecture.md`。
