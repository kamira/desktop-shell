# CHG-20260724-e1_22 — 建置期能力閘控 lint（E1-22）

## Motivation

BUILD.md 硬性約束表列出兩條 NFR，在本單元上線前只能靠人工 code review 把關：

- **NFR-02**：核心 API 不得出現絕對座標與數字 z-order（硬編碼像素座標、`z_order = 數字`）。
- **NFR-03**：能力閘控呼叫必須有 `has()` 保護（使用能力 API 卻無先行 `has(capability)` 檢查）。

E1-22 把這兩條規則變成**建置期 / 靜態**的可執行 lint，取代「靠 code review」的脆弱防線。
本單元先交**可餵字串測試的純核心**：輸入原始碼文字，輸出可定位的違規清單（規則 id、
行號、訊息）。真正「掃整個 repo」的 CI 驅動與整合另議（見結構註記）。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 核心形狀 | `CapabilityLint::lint(source) -> vector<LintDiagnostic>` | 純函式、可重入、可餵字串單元測試 |
| 診斷 | `LintDiagnostic`{rule, rule_id("NFR-02"/"NFR-03"), line(1-based), message} | 可定位、不靜默；`==` 便於測試 |
| 規則列舉 | `LintRule`{AbsoluteCoordinate, NumericZOrder, UnguardedCapability} | 三規則對應兩條 NFR |
| NFR-02 z-order | regex 偵測 `z_order/z-index/... = 數字` | 數字層級 → 應改具名層級 |
| NFR-02 座標 | regex 偵測座標型欄位指派數字 + 定位型 API 帶數字實參 | 硬編碼像素 → 應改具名錨點 / 相對版面 |
| NFR-03 閘控 | 「能力消費呼叫」無先行 `has(` 保護即違規 | 對齊 NFR-03 語意；未閘控即不安全 |
| 閘控名單來源 | 預設由 E1-21 `CapabilityMatrix::defaults()` 的 **optional** 能力尾段導出 | 單一資料來源；亦可自訂名單求決定性 |
| 註解處理 | 掃描前剝除 `//` 與同行 `/* */` | 註解裡的反例文字不誤判 |
| 作用域近似 | 整檔一次 `has()` 即視為後續呼叫受保護；同行則須在呼叫前 | 靜態核心保守近似；精確作用域留待 CI 驅動 |

平台中立：純文字 / 規則分析，無 `#ifdef` / win32 / cocoa 分支、不建 `src/kernel/backend/`、
不綁真實後端。命名空間沿用 kernel 慣例（`ds::kernel`）。
