# CHG-20260803-07 — 知識庫收錄 K-005：squash merge 後的分支開法

- Date: 2026-08-03 (UTC+0) | Branch: claude/knowledge-squash-branching | Risk: low | Implemented by: I1

- 來源事件：`CHG-20260803-06` 的 PR #196

## Motivation

`CHG-20260803-06` 開 PR 後，`gh pr checks` 回 `no checks reported`、PR 停在 OPEN 不動。
第一直覺是 CI 設定或觸發條件有問題——實際上 workflow 完全正常，
是 PR 處於 `mergeStateStatus: DIRTY`（合併衝突），GitHub 因此不跑檢查。

根因是分支開法：托盤分支開在**前一條已被 squash 進 main 的分支**上，而非 `origin/main`。
squash merge 會把分支的多個 commit 壓成 main 上一個全新 commit，
**原 commit 永遠不會成為 main 的祖先**，於是同一份內容出現在兩條互不相干的祖先線上。

本 repo 的 governance workflow **一律用 squash merge**（`gh pr merge --squash`），
所以這不是偶發事故，是**連續交付多個相依變更時必然會踩到**的結構性陷阱。
AGENTS.md 與 HANDOFF 都沒有記載這一點。

## Impact

`docs/knowledge/errors.md` 新增 **K-005**、`docs/knowledge/INDEX.md` 加一行索引。

條目內容涵蓋：為什麼會衝突、為什麼症狀（沒有檢查）指向錯誤方向、
正確的分支開法、已開錯時的修法，以及三條通則——其中一條是
「`git log origin/main..HEAD` 會列出已被 squash 的 commit，那是正常的，不是漏推」。
