# CHG-20260724-e4_01 — 文字排版與渲染（E4-01）

- Date: 2026-07-24 | Branch: feat/e4_01 | Risk: medium | Implemented by: I1.111
- Skill: ai-sdlc-autopilot
- Unit: E4-01（文字排版與渲染，engine 層 / 子系統 render / phase 1 / risk=medium / lb=15 高影響）
- depends_on: E1-03

## Motivation

桌面外殼的每一個可視元件——面板文字、通知標題與內文、選單項、量表標籤、桌寵對話框——
最終都要把「一段字串」變成「螢幕上一個個字符的擺放」。這一步（文字排版 / text layout）是
整個 render 子系統的地基：上層元件（E4-xx）與合成層都依賴它產出的行/字符佈局來決定畫面內容。
`lb=15 高影響`即源於此——它被大量下游單元共用，介面與語意一旦定錯，波及面極廣。

相位 1 的關鍵約束：**不得**觸碰真實字型引擎（FreeType / CoreText）或任何 OS 字型 API，否則
排版邏輯將無法在單元測試中重現、且違反 engine 層「平台中立、換平台不動邏輯」。因此本單元把
「字型度量」抽象成**可注入介面** `FontMetrics`（字元→advance 寬度、行高），排版純粹是這些度量
之上的數學；真實光柵化留待相位 2 由同一介面的後端提供。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 字型抽象 | `FontMetrics` 純虛介面：`advance(cp)` / `line_height()` / `ascent()` | 排版只依度量、不依真實字型；相位 2 FreeType/CoreText 實作同介面即可，邏輯零改動 |
| 相位 1 度量 | `FixedFontMetrics`（等寬 + 固定行高，建構即驗參） | 提供可預期的預設 / 測試度量；非有限或負值於建構期即擲例外 |
| 入口 API | `TextLayout::layout(text, constraints) -> LayoutResult`、`measure(text, constraints) -> Size` | 乾淨、無狀態副作用的函式式介面；measure 為 layout 的尺寸投影 |
| 約束模型 | `LayoutConstraints`{ max_width, max_lines, wrap, align, line_height, ellipsis, ellipsis_char } | 單一資料結構承載排版盒的所有約束；預設值即「無界、詞界換行、靠左」 |
| 換行 | `WrapMode::None`（僅硬換行 `\n`）/ `WrapMode::Word`（詞界貪婪換行） | 涵蓋常見需求；過長單詞自成一行溢出（相位 1 不硬斷字，行為明確可預期） |
| 對齊 | `TextAlign` Left/Center/Right；對齊寬 = 有界盒寬，否則最寬行寬 | 具名對齊；無界時對齊到內容外框，直覺且不需外部給寬 |
| 省略 | `ellipsis` 開關 + `ellipsis_char`（預設 U+2026 '…'）；過寬裁切 / 超過 max_lines 於末端加省略字元 | 內容超界屬正常情形，非錯誤；以 `truncated` / `LineBox::ellipsized` 明示 |
| 渲染描述 | `LayoutResult`{ lines[], glyphs[], size, truncated, surface } | 純資料；`Glyph`{codepoint,x,advance,line}、`LineBox`{begin,count,x,y,width,baseline,ellipsized} |
| NFR-02 | 位置全為**相對偏移**：glyph.x（盒內）/ line.y（=行索引×行高）/ baseline（=y+ascent）；surface 以**具名 SurfaceId** 指涉 | 無任何螢幕絕對座標欄位、無數字 z-order 欄位（型別上即不提供） |
| UTF-8 | 內建 `decode_utf8`：非法起始/續接位元組、截斷、過長編碼、越界、代理區碼位 → 擲例外 | 無效輸入不靜默（不以 U+FFFD 取代）；相位 1 以碼位為排版單位 |
| 錯誤策略 | 非法 UTF-8 / 非有限（含 NaN）約束 / 度量回非有限或負值 → `std::invalid_argument`；內容超界 → 夾/裁 + 標記 | 無效輸入明確報錯不靜默；超界為正常行為 |

介面平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa` / FreeType / CoreText / 任何真實字型或 OS API。

### 對上游 E1-03 的使用（可讀不可改）

`LayoutResult::surface` 與 `TextLayout` 的目標綁定，以上游 E1-03（經 `alpha_surface.hpp` 帶入）的
**具名 `ds::kernel::SurfaceId`** 指涉排版目標 surface（NFR-02：具名、非數字 handle / z-order），
與既有 module 層元件（如 E4-03 `RenderModel::surface`）的具名指涉慣例一致。僅**讀取型別**、
不呼叫上游任何函式、不修改上游。

## Impact（medium + lb=15 高影響：完整影響分析）

### 影響範圍與風險評估

- **下游廣度**：本單元為 render 子系統地基，預期被大量 E4-xx 視覺元件與後續合成 / 繪製層消費。
  介面（`FontMetrics` / `LayoutResult` / `layout` 簽章）即公共契約，故本次刻意將型別設計得
  **最小且穩定**：值語意純資料結構、無隱藏狀態、無平台耦合，降低日後破壞式變更的機率。
- **相位邊界風險**：最大風險是「不慎把真實字型 / 平台耦合帶進 engine 層」。本單元以
  `FontMetrics` 注入點完全隔離之——排版邏輯對字型只有「advance / line_height / ascent」三個純量
  依賴，相位 2 後端接上同介面即可，**排版程式與測試零改動**。已驗證原始碼無任何平台分支或字型 API。
- **NFR-02 合規**：渲染描述在**型別層面**即不提供絕對座標與數字 z-order 欄位——所有位置皆相對
  偏移（glyph.x / line.y / baseline）、目標以具名 SurfaceId 指涉。專屬測試
  `E4_01_NFR02.*` 斷言之。待 E1-22 lint 上線後亦可機檢。
- **正確性風險（medium）**：換行 / 對齊 / 省略 / UTF-8 皆有邊界情形。以 26 個 gtest 案例覆蓋
  （含空字串、空行、過長單詞溢出、無界置中、裁切預算、過長編碼 / 代理區、壞度量），float 用
  EXPECT_NEAR，降低回歸風險。
- **可逆性**：純新增單元，無修改既有檔案；不可用時可整包移除而不影響他人（尚無下游）。低不可逆性。

## 不含（避免越界）

- **不觸碰任何真實字型引擎 / OS 字型 API**（FreeType / CoreText / win32 / cocoa）；度量一律注入。
