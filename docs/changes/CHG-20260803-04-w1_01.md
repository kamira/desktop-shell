## Motivation

相位 2 的第一個實作單元：把 E1-24 宣告的 `ds::kernel::KernelBackend` 抽象契約，
第一次接上**真實的作業系統**。相位 1 的所有 surface 語意（具名圖層、輸入策略、
不搶焦點的面板、點擊穿透）到此為止都只存在於 null 後端的記憶體狀態裡；
本單元是它們第一次真的變成桌面上的視窗行為。

## Impact

新增 `src/kernel/backend/win32/`：`win32_backend.hpp` / `.cpp` / `CMakeLists.txt`。
**未改動任何既有單元的一行原始碼。**

`Win32KernelBackend` 實作 `KernelBackend` 全部 16 個虛擬方法。契約對映：

| 契約 | win32 |
|---|---|
| `SurfaceId`（具名字串） | 一個 `HWND` |
| `SurfaceLayer::Topmost` / `Overlay` | `SetWindowPos(..., HWND_TOPMOST, ...)` |
| `SurfaceLayer::Wallpaper` / `BelowNormal` | `HWND_BOTTOM` |
| `InputPolicy::PassThrough` / `HitPolicy::Transparent` | `WS_EX_TRANSPARENT` |
| `show` / `hide` | `ShowWindow(SW_SHOWNOACTIVATE / SW_HIDE)` |
| `poll_input` | `PeekMessage` 迴圈 → 具名 `InputEvent` |
| 「不搶焦點的面板」 | `WS_EX_NOACTIVATE` |

### 三個設計決定

**① NFR-02 如何在需要座標的 API 上守住。** `CreateWindowEx` 非要 x/y/w/h 不可，
而契約禁止絕對座標。解法：座標**只存在於平台實作內部**——後端自行選定預設幾何
（工作區右上角），不經 API 傳入、不對外暴露。對外介面一個座標都沒有，圖層一律具名。

**② win32 專屬擴充放在契約之外。** kernel 契約刻意**沒有繪製 API**（繪製必然涉及座標），
所以 host 需要原生視窗才能畫。本後端額外提供**非虛擬**的 `hwnd_for()` / `pump()` /
`quit_requested()`，只有同樣是 win32 專屬的 host 會用。**契約本身一個字未動。**

**③ 狀態以 Windows 為準，不維護影子狀態。** `is_visible()` 問的是 `IsWindowVisible(hwnd)`
而非後端自記的旗標——這樣「後端說可見」等於「桌面上真的看得到」。測試也照此設計：
斷言去問 `GetWindowLongPtr` / `IsWindow`，而不是問後端自己記了什麼。

### 測試設計說明

斷言刻意去問 **Windows 本身**而非後端的自記狀態：`SurfaceLayer::Topmost` 驗
`GWL_EXSTYLE & WS_EX_TOPMOST`、`PassThrough` 驗 `WS_EX_TRANSPARENT` 的加上與拿掉、
`destroy` / `shutdown` 驗 `IsWindow()` 真的為假。後端若退化成只維護影子狀態，這些測試會紅。

另有一條反向對照：`SurfaceLayer::Normal` 斷言**不得**帶 `WS_EX_TOPMOST`——
否則「具名圖層」等於沒有區別，全部都是最上層也會過測試。
