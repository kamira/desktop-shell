# CHG-20260724-e2_04 — 記憶體使用量（實體/交換）（E2-04）

- Date: 2026-07-24 | Branch: feat/e2_04 | Risk: low | Implemented by: I1.58
- Skill: ai-sdlc-autopilot

## Motivation
E2-04「記憶體使用量（實體/交換）」是 module 層（子系統 sysinfo）的一個**指標提供者**：透過
**E2-01 統一指標介面**（擴充點 1 契約）把「記憶體使用量」——實體記憶體（總量／已用／可用
bytes、使用率 %）與交換空間 swap（總量／已用）——掛成一個指標（一個 metric、各記憶體欄位為
可列舉 instances），並以 **E2-02 採集頻率分級**決定採樣節奏（記憶體用量會變動，屬週期採集）。
這是「新增指標 = 新增 `MetricProvider`、掛件一行不動」機制的又一個具體實例——它**消費
E2-01 / E2-02 契約、不自造指標模型或排程器**。相位 1（Mac / null 期）**絕不接任何真實記憶體
API**（不含 `host_statistics` / `sysctl` / `/proc/meminfo` / mach / `#ifdef`）；改為**可注入的
記憶體統計來源抽象** `MemoryStatSource` + null / 假來源 `NullMemoryStatSource`（注入固定值或
序列，模擬時間推進下的用量變化）；真實平台後端留待相位 2。無讀值時各欄位以 `valid==false`
（未知）誠實表達，而非塞假 0。

## Impact

### 新增 `modules/sysinfo/e2_04/`（module 層 / 子系統 sysinfo）
- `memory_usage.hpp` / `memory_usage.cpp`（`namespace ds::sysinfo`）：
  - **值模型** `MemoryStats`（平台中立，皆以 bytes 表達）：`physical_total` / `physical_used` /
    `physical_available` / `swap_total` / `swap_used` + `valid`（`unknown()` = 無讀值；含相等
    運算子）。used 與 available 由來源分別給出（不自動由 total-used 推導）——真實 API 因
    buffer/cache 而未必 `used+available==total`，本層誠實承載，不臆造一致性。
    - `from_physical(total, used, swap_total=0, swap_used=0)`：便利工廠，available=total-used
      （夾到 >=0）、`valid==true`。
    - `usage_percent()`＝used/total*100，夾到 [0,100]；total==0 → 0（不謊報；欄位有效性另由
      `valid && total>0` 決定）。`swap_usage_percent()`＝swap_used/swap_total*100（除零保護）。
  - **記憶體統計來源**（提供者只依賴此抽象）：
    - `MemoryStatSource`（抽象 `read()→MemoryStats`；**非 const**，序列型來源取樣有副作用，
      與 E2-03 `CpuTickSource::read()` 同慣例）。
    - `NullMemoryStatSource`：相位 1 null / 假來源——**不接真實記憶體 API**。以一列注入快照
      表達：`read()` 回下一份、列盡持續回最後一份、空列回 `unknown()`（誠實預設）。**固定值**
      即一元素序列（`set_stats`）；**序列**模擬時間推進（`set_sequence` / `push_sample` /
      `reset` / `clear`）——即單元規格「注入固定/序列」。
  - **提供者** `MemoryProvider : public ds::metrics::MetricProvider`（消費 E2-01 契約）：
    `provider_id()=="sysinfo.memory"`；`register_metrics(registry)` 向 E2-01 註冊表掛上單一
    指標 `"memory.stats"`（name="Memory"、unit=""、range=unbounded——欄位異質 bytes 與 %，
    各欄位自帶語意）。
    - **固定欄位集為可列舉實例**（列舉順序決定性）：`memory.physical.total`(Physical Total) /
      `memory.physical.used`(Physical Used) / `memory.physical.available`(Physical Available) /
      `memory.usage.percent`(Memory Usage) / `memory.swap.total`(Swap Total) /
      `memory.swap.used`(Swap Used)。變動欄位（已用／可用／使用率 %／swap 已用）保留歷史環
      （`kDefaultHistory=64`），配合 E2-02 週期採集鋪成用量序列；靜態欄位（實體總量／swap
      總量）無歷史（capacity==0）。
    - `sample()`：重新讀來源、把新用量寫入各實例（bytes / % 值；變動欄位推入歷史）；register
      尚未呼叫時為 no-op（保守不崩）。
    - `sampling_tier()`：回建議的 E2-02 採集分級（`kDefaultTier=SamplingTier::Normal`，建構子
      可覆寫），供呼叫端 `SamplingScheduler::add_demand`。
  - 無讀值語意：指標仍掛上；各欄位以 `valid==false`（未知）誠實表達，而非塞假值。source 為
    null 亦保守不崩（6 欄位皆未知）。`total==0`（有讀值但無法算使用率）→ 使用率欄位未知、
    bytes 欄位仍有效。
  - `CMakeLists.txt`：`add_library(e2_04)` **PUBLIC 連上游 `e2_01` `e2_02`**（標頭 include
    `metric.hpp` 與 `sampling.hpp`，須傳遞 include 目錄）；`test_e2_04` + `add_test(NAME e2_04)`。
- 上游相依：E2-01 統一指標介面（`ds::metrics::MetricProvider` / `MetricRegistry` /
  `InMemoryMetric` / `InMemoryMetricInstance`）＋ E2-02 採集頻率分級（`ds::metrics::SamplingTier`
  / `SamplingScheduler`），皆可讀不可改。
- **無** `#ifdef` / win32 / cocoa / `host_statistics` / `sysctl` / `/proc/meminfo` / mach 等真實
  記憶體 API（backend_guard 綠燈）。純邏輯、平台中立、可注入。

### 測試 `tests/e2/test_e2_04.cpp`（gtest，24 案例）
- 提供者身分（3）：`provider_id`/`kMetricId`/`kMetricName`/`kProviderId` 穩定；可上轉為 E2-01
  `MetricProvider`；預設採集分級 = Normal（可覆寫）。
- 註冊 / 列舉（1）：`add_provider` 掛上一個指標；固定 6 欄位集（順序決定性）；metric 層 unit=""、
  range unbounded。
- 實體記憶體各欄位 + 使用率計算（2）：total/used/available 讀值；使用率 75%；available 由來源
  獨立給出（非必然 total-used）。
- swap 欄位（1）：swap 總量／已用讀值正確。
- **0% / 100% / 空 swap 邊界**（3）：值模型 `usage_percent` 0/100/溢位夾滿/total==0；經提供者
  0% 與 100%；空 swap（total==0）為有效讀值 0 且 swap 使用率除零保護。
- **無讀值 invalid**（2）：空序列來源 → 6 欄位皆 `valid==false`（未知，非塞假 0）；`total==0`
  有讀值 → 使用率欄位未知、bytes 欄位仍有效。
- **經 E2-02 採樣**（3）：以 `SamplingScheduler`（Normal 間隔 8）登記需求、推進 tick 於到期時
  呼叫 `sample()` → 使用率歷史累積、值前進；除頻合併多消費者（最高頻者供給、撤銷後仍追蹤）；
  靜態欄位無歷史 / 變動欄位有歷史。
- **null 來源行為**（4）：source 為 null 指標 → 6 欄位未知、不崩、`sample()` no-op；`sample()`
  未註冊為 no-op；`NullMemoryStatSource` 空序列預設未知→注入後可讀→clear 回未知；序列推進
  （列盡持續回最後一份、reset / push_sample）；提供者經序列來源反映用量變化。
- 消費者範式 / 重複註冊（2）：掛件風格消費者只走 E2-01 registry / Metric 抽象介面；同 id 第二次
  掛上保守拒絕、不覆寫。
- 值模型單元（2）：`MemoryStats::unknown` / 相等運算子；`from_physical` 推導 available（含
  used>total 夾到 0 防護）。
