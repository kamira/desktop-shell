## Motivation

C3-03「角色外觀組」：角色外觀 / 皮膚資源組合包——把一組具名外觀（不同表情 / 服裝，E4-06
具名切換）+ 各外觀對應的互動區域（E1-05 具名區域）打包成一個可整組套用的集合，其定義以
E9-01 套件格式描述（manifest + 內容清單），並可掛到一個已載入的 C1-02 立繪 profile 上生效。
這是一個**組裝型 artifact 單元**：不新增引擎邏輯，而是把四個已合併的擴充點（C1-02 立繪
profile、E1-05 具名區域圖、E4-06 具名 surface 切換、E9-01 套件格式）組成單一 appearance
set + 行為（`load_appearance_set` / `switch_look` / 具名區域 / `apply_to`）。相位 1：純資料
組合，無真實 GUI、無平台分支。

## Impact

### 新增 `content/c3_03/`

- `appearance_set.hpp` / `.cpp`：`namespace ds::content`。
  - `AppearanceSet`：內部自持一個 E4-06 `SurfaceSwitcher`（以外觀名為具名 id）+ 各外觀的
    E1-05 `NamedRegionMap`（具名鍵線性配對，順序即登記順序）+ 已驗證的 E9-01 `Package`。
  - `load_appearance_set(套件描述文字)`：委派 E9-01 `parse_package` + `validate_package`；
    內容清單中 `kind == "look"` 的項目其 `logical_path` 註冊為具名外觀，其餘 kind 不解讀、
    原樣保留於 `package()`。已載入時再次呼叫 → `AlreadyLoaded`（不靜默重載）；解析 / 驗證
    失敗 → `Invalid`，不動既有狀態（全有或全無）。
  - `clear()`：回到初始狀態；尚未載入 → false（no-op）。
  - `has_package()` / `package()`：E9-01 套件內省（manifest + 完整內容清單）。
  - `has_look` / `look_count` / `looks`：E4-06 具名外觀查詢。
  - `switch_look(name)`：純委派 E4-06 `switch_to`，直接回傳其 `SwitchStatus`（`Ok` /
    `NotFound`），不重新包一層自有列舉（保留上游精確碼，同 C1-02 對 E1-08 `DragStatus` 的
    處理慣例）。
  - `set_regions(look, NamedRegionMap)` / `has_regions` / `regions_for` /
    `current_regions`：依外觀個別登記互動區域（E1-05）；未知 look → false（不新增游離
    區域）；重複 `set_regions` 對同一外觀為**取代**而非疊加。
  - `apply_to(PortraitProfile&)`：把「目前外觀」的互動區域套用到已載入的立繪 profile
    （`profile.set_regions()`），並在該 profile 已註冊同名具名表情時**儘力而為**一併切換
    （`profile.switch_expression()`——不因表情不存在而整體失敗，表情圖片載入屬 C1-02
    自身職責）。前置條件不足時回具名結果且不動 profile：無目前外觀 → `NoCurrentLook`；
    目前外觀無互動區域 → `NoRegions`；目標 profile 未載入 → `ProfileNotLoaded`。
  - 具名結果 `AppearanceStatus`（`Ok` / `Invalid` / `AlreadyLoaded`）+ `ApplyStatus`（`Ok` /
    `NoCurrentLook` / `NoRegions` / `ProfileNotLoaded`），皆附 `to_string()`（NFR-02：具名，
    非數字）。
- `CMakeLists.txt`：`add_library(c3_03 STATIC appearance_set.cpp)` +
  `target_link_libraries(c3_03 PUBLIC c1_02 e1_05 e4_06 e9_01)` + `test_c3_03`
  （`tests/c3/test_c3_03.cpp`）+ `add_test(NAME c3_03)`。不改根 CMakeLists。

### 新增 `tests/c3/test_c3_03.cpp`

gtest 21 案例：
- `load_appearance_set`：典型多外觀（3 個 look）、混合 kind 內容清單（look 與 asset 交錯，
  僅 look 成為外觀）、僅 manifest 的合法空組（`look_count()==0`）、重複載入拒絕為
  `AlreadyLoaded`（既有狀態不受影響）、清空後可重載、套件缺 manifest / 內容清單結構不合法
  （缺 `:`）/ 重複 logical_path 三類皆拒絕為 `Invalid`。
- `switch_look`（E4-06）：成功切換並追蹤 `current_look`、未知 look 回 `NotFound` 且不改
  現狀。
- 互動區域（E1-05）：`set_regions` / `has_regions` / `regions_for`（含未知 look 不新增游離
  區域）、重複 `set_regions` 取代而非疊加、`current_regions` 隨 `switch_look` 變化（含目前
  外觀尚未登記區域時回 `nullptr`）。
- E9-01 套件內省：`package()` 曝露 manifest 欄位 + 完整內容清單（含非 look 的 asset 項目
  不因本單元只解讀 look 而遺失）、未載入時 `package() == nullptr`。
- `apply_to`（C1-02）：套用互動區域 + profile 已有同名表情時一併切換、profile 無同名表情
  時儘力而為略過表情切換但仍套用區域、以及三類前置條件失敗（`NoCurrentLook` /
  `NoRegions` / `ProfileNotLoaded`）皆不動 profile。其中一案例以 `on_region_click` +
  `inject_click` 端到端驗證：套用後的互動區域確實可經 C1-02 → E5-14 → E1-05 命中具名區域
  （`region_name == "body"`）。
- `to_string`：涵蓋 `AppearanceStatus` / `ApplyStatus` 全部列舉值。
