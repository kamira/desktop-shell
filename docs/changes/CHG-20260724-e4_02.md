# CHG-20260724-e4_02 — 圖片元件（E4-02）

- Date: 2026-07-24 | Branch: feat/e4_02 | Risk: medium | Implemented by: I1.117
- Skill: ai-sdlc-autopilot
- Unit: E4-02（圖片元件，module 層 / 子系統 elements / phase 1 / risk=medium / lb=11 高影響）
- depends_on: E1-03（逐像素 alpha surface）

## Motivation

桌面 shell 需要「圖片顯示元件」——在桌面 / 浮層上呈現圖示、桌布、縮圖、桌寵貼圖等點陣影像。
相位 1 的目標是一個**平台中立、可單元測試**的「圖片渲染描述模型」：把「要顯示哪張影像、以何種
縮放模式映射到目標、裁切哪一塊、整體多透明、送到哪個具名 surface」表達為一份描述，供後續相位的
繪製層消費。

相位 1 **不做真實影像解碼 / 繪製**：若此階段就綁 libpng/libjpeg 或平台繪圖 API，將無法在單元
測試中重現（需真實檔案 / GPU / 視窗系統），也違反 module 層「平台中立、換平台不動邏輯」與 NFR-02
（無絕對座標 / 無數字 z-order）。因此 E4-02 以**可注入的 `ImageSource` 抽象**表達影像來源——元件
只向來源索取**固有尺寸**與**具名參照**，不真正開檔 / 解碼；真實後端上線後以同介面提供真實尺寸即可，
元件邏輯不變。

## 設計（可覆核可改）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 影像來源 | `ImageSource` 抽象介面（`valid/dimensions/reference`）+ `MemoryImageSource`（固定假資料）+ `NullImageSource`（恆無效） | 相位 1 的解耦點：不解碼、可注入、可測；真實後端同介面即可替換 |
| 載入語意 | `set_source` 於呼叫當下**複製**來源的參照 + 固有尺寸進元件（值語意） | 元件不持有對 `ImageSource` 的懸空參照；來源物件可於載入後即銷毀 |
| 無效來源 | `!valid()` 或尺寸寬 / 高 <= 0 → `Invalid`，不改變既有來源 | 「無效來源 / 尺寸報錯不靜默」；不部分套用（既有有效來源不被破壞）|
| 縮放模式 | 具名列舉 `ScaleMode{Fill,Fit,Stretch,Center,Tile}` | 涵蓋 cover / contain / 拉伸 / 置中 / 平鋪五種常見映射；具名非數字（NFR-02）|
| 裁切 | `CropRect{x,y,width,height}`，**正規化比例 [0,1]**（占來源分數）；預設 `full()` | NFR-02：比例非螢幕像素座標；同一裁切可套到任意實際尺寸 |
| 裁切合法性 | 非有限值、寬 / 高非正、負起點、`x+width`/`y+height > 1` → `Invalid`，不套用 | 明確不靜默；不產出溢出來源的無意義裁切 |
| 透明度 | 沿用上游 E1-03 `AlphaProfile.opacity`（比例 [0,1]，自動 clamp）；非有限值 → `Invalid` | 複用上游合成描述，不重造輪子；opacity 為比例符合 NFR-02 |
| 目標 | `ds::kernel::SurfaceId`（字串）**具名** surface；空字串 → `Invalid` | NFR-02：目標以具名指涉，非數字 handle / index；不含螢幕 (x,y) 位置 |
| render_model | `ImageRenderModel{has_source, source_reference, source_dimensions, scale_mode, crop, alpha, target}` | 無來源 → `has_source=false`、參照空、尺寸零，明確不假裝有資料 |
| 固有尺寸 | `ImageDimensions{width,height}`（來源自身像素尺寸） | 影像自身資料（如 E4-20 本地座標系），非螢幕擺放位置；本單元不提供任何 z-order 欄位 |

平台中立：無 `#ifdef` / `win32` / `cocoa` / libpng / libjpeg / 真實繪圖 API；NFR-02 無絕對座標 /
無數字 z-order（裁切為比例、目標為具名、縮放為具名列舉、透明度為比例）。

## Impact

> risk=medium、lb=11（高影響）：本單元為 elements 子系統中會被多個桌面元件 / 佈景重用的基礎
> 顯示元件，其 API 形狀（尤其 `ImageSource` 抽象與 `ImageRenderModel` 欄位）會被後續相位的繪製層
> 與上層佈景消費，故介面契約需審慎固定。以下逐檔列出影響面。

### 1. `modules/elements/e4_02/image_element.hpp`（新增）

## 風險與緩解（medium）

- **契約穩定性**：`ImageRenderModel` 一旦被下游繪製層消費即成穩定契約 → 欄位語意在標頭以註解
  明確固定（來源參照 / 固有尺寸 / 縮放 / 正規化裁切 / 透明度 / 具名目標），並以測試鎖定。
- **NFR-02 誤用風險**：可能被誤加螢幕座標 / z-order → 設計上裁切僅接受 [0,1] 比例、目標僅接受
  具名字串、無任何 (x,y) 或層級欄位；三個 `Nfr02Compliance` 測試明確守衛。
- **懸空來源**：`set_source` 採值語意複製，來源可即銷毀 → `LoadCopiesByValueSourceMayOutliveElement`
  測試守衛。
- **靜默失敗風險**：無效來源 / 零尺寸 / 越界裁切 / 非有限不透明度 → 一律回 `Invalid` 且不部分
  套用；相關「DoesNotMutate」測試守衛。
