## 我要做什麼

### 問題

`E9-07` 的 `InstallRegistry`（`engine/package/drop_install.hpp:116`）是 `std::map<std::string,
Package>` 的**純記憶體**登錄，介面只有 `contains/add/find/size`——**重啟即失憶**。
`CHG-20260829-05` 已指名這個缺口：「有安裝即新增，即使沒打開」撐不起來，E9-10 要把它
「從記憶體升為可存可讀」。

### 做法（照 E9-05 `layout_store` 的同構先例，不另闢蹊徑）

新增 `engine/package/install_store.{hpp,cpp}`，namespace `ds::package`：

- `InstallRecord` —— 單筆已安裝紀錄：`Package`（E9-01：manifest + entries 清單）。
  **只有中繼資料，沒有套件本體**——這正是「不載入也列得出」的物理基礎。
- `InstallStorage` —— **可注入的抽象後端**（`put/get/has/erase/names`），形狀同 E9-05
  `LayoutStorage`；相位 1 預設實作 `MemoryInstallStorage`（純記憶體替身，無真實檔案 I/O）。
- `serialize_install_records` / `deserialize_install_records` —— 經 **E7-12 `serialize`**
  產出 **E7-01** 宣告式文字；`deserialize` 走 E7-01 `parse()`。自身格式版本欄位
  `kInstallRegistryFormat{1,0}`（同 E9-05 的 `kLayoutFormat` 慣例）。
- `InstalledPackageStore` —— 持久化登錄本體：建構時**即自 storage 重建**（這就是「重啟」的
  rehydrate 點）；`record/forget/contains/find/list/size/reload`。
- `mirror_into(store, InstallRegistry&)` —— 把持久化紀錄重播進一個**全新的** E9-07
  `InstallRegistry`，完成「重啟後 E9-07 登錄回填」。只讀 E9-07，不改它一行。

### 為何持久化 `InstallRegistry` 而非 E9-06 的 `PackageRegistry`

見 CHG「設計決定」段。摘要：`CHG-20260829-05` 的目標圖明寫 E9-10 = 「`InstallRegistry`
從記憶體升為可存可讀」，且下游消費者（E7-16 設定分頁、E9-11 權限狀態）要的是「安裝了什麼」
這份清單，不是 E9-06 的卸載相依圖。

### 「重啟」怎麼模擬（驗收重點，V1 會盯死）

三個獨立、名字講得出意圖的測試案例：
1. **storage 活在外層 scope、登錄物件在內層 scope**；內層結束（物件解構）後，以**新**的
   `InstalledPackageStore` 讀同一個 storage → `list()` 仍列得出。
   **絕不**對同一個還活著的物件再查一次（CHG-20260829-05 停點明指那種寫法過不了）。
2. **「不載入」可證**：以計數包裝的 `InstallSource` 安裝，重啟後列舉時 `open()` 計數**不增加**
   → 證明沒有實例化／載入套件本體。
3. **全新 `InstallRegistry` 回填**：重啟後 `mirror_into` 一個全新登錄，過程中**不存在任何
   `InstallSource`**。

誠實聲明：相位 1 後端是**記憶體替身**（`MemoryInstallStorage`），真實磁碟後端留待後續相位。
「重啟」以「後端存活、登錄物件解構後重建」模擬——不誇大成真實的行程重啟。

## 遇到的錯誤（錯誤 + 根因 + 解法）

### 1. 本機無 googletest，FetchContent 抓 GitHub tarball 403

- **錯誤**：容器內無 `/usr/include/gtest`、無 `/usr/src/googletest`；CMake 的 FetchContent
  走 GitHub tarball 會被代理回 403。
- **根因**：容器映像未預裝 googletest；代理對 GitHub tarball 不放行。
- **解法**：以 `apt-get download libgtest-dev googletest` 取得發行版套件，`dpkg-deb -x` 解到
  scratchpad 的獨立目錄，建置時以**命令列參數**指向該來源樹。該參數只存在於我的命令列，
  **未寫入 repo 任何檔案**（CMakeLists / CHG / 本檔皆無）；CI 有自己的正常取得路徑。

### 2. 其他錯誤：**無**

實作、建置、測試、閘門一次通過，無編譯錯誤、無測試紅燈、無閘門違規。沒有為了讓紀錄看起來
乾淨而省略任何失敗——上面第 1 條是本次唯一遇到的障礙，且屬環境而非程式碼問題。

一個**差點踩到但在設計階段就避開**的陷阱，記在此處供後人參考（非錯誤，故不入
`errors.md`）：E9-02 的 manifest `format_version` 若以字串 `"1.0"` 存進宣告式文件，再讀回會被
E7-01 的型別推斷變成 **Number**，且 `1.1` 與 `1.10` 無法區分。故改以 `format_major` /
`format_minor` 兩個整數存放。同族問題在 `version` 欄位上不存在，因為 E7-12 的 `needs_quote`
會把「裸寫會型別漂移」的字串自動引號化。
