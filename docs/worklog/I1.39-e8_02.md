## 我要做什麼（動工前計畫）

把一段以步驟序列表達的對話 / 腳本直譯執行。消費 E7-05 的公式引擎（`evaluate`）求值
`set` 的運算式與 `if` 的條件、E7-02 的 `VariableScope` 做跨步延續的變數狀態與 `say` 文字的
`${var}` 內插、E7-01 的 `Value` 做型別 / 數值模型，不重造輪子。未知指令 / 求值失敗 / 未知標籤 /
條件型別誤用要明確回報（NFR-04 精神，帶步驟索引、不靜默）。副作用走注入式 sink（不綁真實後端）。

設計（C++17，`namespace ds::script`）：

- `Step{command, target, arg}`（opcode 字串，讓「未知指令」可執行期報錯）+ 工廠
  `set` / `say` / `if_goto` / `goto_label` / `label`；`Script` 為有序步驟序列。
- `OutputSink` 抽象副作用接收端 + `RecordingSink`（緩衝式，測試 / 批次）。
- `ExecutionContext`（跨步 `VariableScope` + pc + 已執行步數）；`Interpreter`（`step()` / `run()`，
  可選父作用域、`set_step_budget()` 防無窮迴圈）。
- 建構期一次索引 `label` → 步驟索引（重複標籤 → 建構期錯誤）；`goto` / `if` 執行期查表跳轉。
- 錯誤模型對齊 E7-01 `ParseResult` / E7-05 `EvalResult`：`ScriptError{step, message}` + `StepResult` / `RunResult`。

參考已合併的 `engine/format/e7_05/`（`evaluate(expr, scope)`、`truth_of` 真值規則、`EvalResult`
二選一結果風格、「錯誤帶定位、不靜默」契約）與 `engine/format/e7_02/`（`VariableScope`、`resolve`
的 `${var}` 內插），推廣為腳本層的 `ScriptError` / `RunResult`。
