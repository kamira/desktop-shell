設計（C++17，`namespace ds::actuators`，與 e3_05 一致）：

- `kMediaVolumeMin/Max/Unset` + `clamp_media_volume`：致動器層唯一的音量合法化點。
- `MediaControlState`（playback 詞彙同 E2-13 + track_index + volume）供查詢 / 內省。

  `set_volume`/`volume`）+ `NullMediaControlBackend`（純記憶體模擬、初值可注入、
  prev 於 0 夾住、self-clamp）。
- `MediaControlActuator`：`register_on` / `unregister_from`（回滾語意）+ 七個處理器
  （toggle 在致動器層依 state 判定；必填參數以 `has()`/`get_int` 保護，缺 / 型別錯回
  Failed）+ `current_state()` / `playback_state()`。

## 關鍵設計取捨

- **與 E2-13 對稱、共用播放狀態詞彙**：直接 `using ds::sysinfo::PlaybackState`，控制端與讀取
  端說同一種語言（消費者可直接對照，無轉換層）。這也是 CMake `PUBLIC 連 e2_13` 的實質理由
  （非僅形式相依）：本致動器實際消費 E2-13 的 `state_rank` / `to_string`（結果回報用）。
- **toggle 語意在致動器層、不在後端**：後端只有 play/pause 原語，toggle 由致動器依
  `backend->state()` 判定後改呼，後端保持最小、不需懂「切換」概念。
- **音量夾限在致動器層**：`media.volume` 的 level 夾至 [0,100] 後才交後端，後端契約可信任
  （與 E3-05 一致）。
- **next/prev 以曲目相對索引可觀測**：null 後端保留 track_index（>=0，prev 於 0 夾住），
  讓「下一首/上一首」有可驗證的效果，且為相對序、非絕對座標（合 NFR-02）。
- **相位 1 純 null**：不接任何真實媒體控制 API；換相位 2 後端時致動器與命令契約一行不動。
