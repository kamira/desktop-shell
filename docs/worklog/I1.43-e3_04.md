## 關鍵設計決策

- **具名字串命令 id**：`power.sleep` / `power.lock` / `power.logout` / `power.restart` /
  `power.shutdown`；穩定、可讀、不耦合編號，與 E6-01 CommandId 取捨一致。呼叫端經
  `bus.dispatch(id)` 觸發，零相依本致動器。電源動作不需參數，命令 id 本身即完整表達意圖。
- **副作用抽象 `PowerBackend`**：`perform(PowerRequest)→CommandResult`。相位 1 為
  `NullPowerBackend`（**不觸碰 OS、不執行任何電源操作**，只記錄請求）；相位 2 換真實平台後端，
  介面與命令契約不動。此抽象對電源尤其重要——電源操作不可逆，相位 1 直接接 OS 有真的關機風險。
- **無效動作以哨兵 + 檢查保護**：`PowerAction::Unknown`（及無法辨識的動作字串）一律回
  `CommandResult{Failed}`，不崩潰、不丟例外、不記錄無效請求。
- **註冊回滾**：`register_on` 五命令任一掛失敗即回滾本次成功者並回 false，不留半掛、不遮蔽既有致動器。
- **契約版本欄位**：承重抽象，供相位 2 換上真實後端時相容判斷。

## 分層 / 平台中立遵循

- modules/actuators 層：透過 E6-01 契約掛命令，不綁任何真實電源 API（`shutdown` / IOKit /
  cocoa / win32 / `system()`）；相位 1 只有 null 後端記錄請求。
- 無 `_WIN32` / `win32` / `cocoa` / `__APPLE__` / `darwin` / IOKit 平台分支；唯一 `#ifndef` 為
  header guard，唯一 `#ifdef` 字樣為註解說明。
