## 我要做什麼（動工前計畫）

**自由拖曳 surface 並記憶其位置**——使用者可拖曳 surface 到任意位置，放開後記住、下次還原。
純粹**組合**三個已合併上游，不自造格式 / 定位模型：

- **拖曳狀態機**（相位 1 平台中立、注入式，無真實視窗拖曳 API）：`begin_drag` → `drag_to`
  （可多次，只更新 pending）→ `end_drag`（提交 pending 為記憶位置）/ `cancel_drag`（放棄，還原）。
- **位置以 anchor / 相對表達**（NFR-02）：位置一律為 E1-07 `AnchorSpec`（九宮具名錨點 + 容器尺寸
  正規化偏移），無 `(x,y)` 絕對座標；`resolve_live` 委由 E1-07 `resolve` 落地。
- **後端閘控**：`set_position` / `begin_drag` 以 E1-03 → E1-24 `backend.has_surface(id)` 閘控，
  只拖曳真實存在的 surface。
- **位置記憶持久化**：`serialize_positions()` 經 E7-12 `set_value`（顯式 Path 段，避免含 `.` 的
  具名 SurfaceId 被字串路徑誤拆）+ `serialize` 落回 E7-01 文字；`load_positions()` 以 E7-01 `parse`
  讀回、逐條驗證後**全有或全無**套用。
- 無效拖曳（未註冊 / 後端無此 surface / 非拖曳中操作 / 重複 begin / 無效 AnchorSpec / 無法解析文字）
  → 結構化 `DragStatus`（Invalid / NotDragging / AlreadyDragging），不靜默、不改狀態、不崩潰。

參考已合併的 E1-07 `AnchorLayout` / E1-03 `AlphaSurfaceService`：沿用其結果碼風格、具名 SurfaceId
記錄配對、「不靜默失敗」契約。位置記憶以 committed（記憶）/ pending（拖曳中）分離，使「放開才記住」
與「取消還原」自然成立。

## 設計決策記錄

- **不使用 E1-07 `AnchorLayout` 作儲存**：`AnchorLayout` 無逐項列舉介面，而序列化需走訪所有記憶
  位置；且不可改上游。故以本單元自有的具名鍵 `std::vector<Record>` 儲存 committed `AnchorSpec`
  （仍全程用 E1-07 的 `AnchorSpec` / `resolve` / `is_valid_anchor`，e1_07 連結充分正當）。
- **E7-12 用顯式 Path 段而非字串路徑**：具名 SurfaceId 常含 `.`（如 `surface.panel`），字串路徑
  以 `.` 分隔會誤拆為巢狀 map；改用 `PathSegment::of_key(id)` 使 id 恆為單一鍵段，round-trip 保留。
- **load 不經後端閘控**：記憶可在對應 surface 建立前先載入（「下次啟動還原」），對真實 surface 生效
  發生在後續 backend 閘控的拖曳 / set_position 時；已於標頭明確記錄。
