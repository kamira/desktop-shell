## 我做了什麼

一個 sysinfo 指標提供者，把電源 / 電池狀態透過 E2-01 `MetricProvider` 掛成一組**單一實例**
指標，並以 E2-02 頻率分級（預設 Low，電源變動慢）決定採樣。設計刻意分離、易組合（本單元是
最終電池 / 電源 Widget 的核心資料來源）：

- **充電狀態列舉**：`ChargeState`（NoBattery/Discharging/Charging/Full，含穩定碼）；
  `to_string`（穩定字串）、`charge_state_label`（顯示標籤）、`charge_state_code`（數值碼）。
- **狀態值模型**：`PowerStatus`（`valid` + `on_ac_power` + `state` + optional 的 `percent` /
  `minutes_remaining` / `cycle_count` / `health_percent`）。以 optional 表達電池專屬讀值有無
  ——無電池桌機自然表達為 `valid=true` + `NoBattery` + `on_ac_power=true` + 其餘 nullopt。
  工廠 `unknown` / `no_battery` / `battery`；含相等運算子。
- **注入式來源，皆平台中立、不接真實電源 API**：
  - `PowerStatSource`（抽象 `sample()→PowerStatus`）。
  - `NullPowerStatSource`（固定狀態，預設無讀值；`set_status` / `clear`）。
  - `SequencedPowerStatSource`（狀態序列，模擬狀態演變 / 轉換；列盡回最後一份、空列回無讀值）。
- **提供者** `PowerProvider : ds::metrics::MetricProvider`：`register_metrics()` 掛上六個單一
  實例指標（`power.battery.level` / `power.battery.state` / `power.ac.online` /
  `power.battery.time_remaining` / `power.battery.cycles` / `power.battery.health`，各維度
  單位 / 值域不同故各為獨立指標）；`sample()` 重新讀來源更新各指標（有效值推入歷史、無讀值 /
  缺可選欄位設未知）；`sampling_tier()` 回建議採集分級（預設 Low）。source 為 null 亦保守不崩。

## 設計要點

- **各維度 = 獨立指標，非同一指標的多實例**：E2-01 的一個 Metric 共用單一 unit / range，而電源
  各維度（% / 類別 / min / 布林）單位值域相異，故忠實映射為六個單一實例指標（提供者可註冊零到
  多個指標）。對比 E2-03 是同單位（%）多實例（每核心），此處相反。
- **無讀值誠實**：整體無讀值（未取樣 / 感測失敗）→ 六指標皆 `valid==false`；成功讀到但無電池
  桌機 → 狀態誠實 no-battery + AC online，但電量 / 剩餘時間 / 循環 / 健康度未知（不謊報 0）。
- **可選欄位**：循環次數 / 健康度以 optional 承載，缺則該指標未知——指標集合恆定，靠 valid 誠實
  表達有無，不隨來源動態增減指標。
- **採樣分級預設 Low**：E2-02 註解即以「電池健康」為低頻例；電源變動慢，直接呼應 NFR-01 idle。
