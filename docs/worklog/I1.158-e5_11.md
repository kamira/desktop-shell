## 我要做什麼（動工前計畫）

engine 層純橋接邏輯：`SpanSelectionDispatcher`（`namespace ds::events`）內部持有一個 E5-01
`MouseEventRouter` 實例（完全委派 surface 命中 / 多擊追蹤 / 底層訂閱派發），另外維護一份
`std::map<SurfaceId, const ClickableTextElement*>` 對照表（本單元新增的橋接狀態，不取得元件
所有權）。`set_surfaces()` 換手時對新清單裡每個具名 surface（去重）各訂閱一次內部橋接回呼；
僅處理 `MouseAction::Click`（Down/Up 略過，避免同一次點擊因三個事件重複判定），以
`event.target` 對照的 `ClickableTextElement`（若有綁定）呼叫 `hit_span(event.position)`；命中
才組成 `SpanSelectionEvent{ mouse, span_id }`（`span_id` 恆非空）分派給本類別自身的訂閱者。
未綁定區段來源 / 未命中任何區段 / 未命中任何 surface —— 皆不分派任何事件（規格明定：無區段
命中的點擊不發選取事件，與 E5-14 `RegionEvent` 未命中仍正常派發的語意刻意不同）。

不重新實作任何按鍵狀態機或幾何命中邏輯——兩條上游 API 皆完全委派、只加「橋接」本身。

## 遇到的錯誤

- 未遇編譯 / 邏輯錯誤，一次寫對零警告全過。
- 設計注意點（記錄備查，非錯誤）：
  - E4-12 `ClickableTextElement` 持有 `const FontMetrics&` 參照成員，隱式拷貝賦值 /
    移動賦值因而被刪除，但拷貝 / 移動**建構**仍可用（僅重新繫結參照，非重新賦值）。本單元
    的區段來源對照表因此選擇存指標（`const ClickableTextElement*`，不取得所有權）而非存值，
    呼叫端須保證綁定期間元件生命週期有效——與 E4-12 本身對外部 `FontMetrics` 的既有慣例
    一致，測試檔中直接以區域變數 `ClickableTextElement el = MakeHelloWorld(fm);` 建構並在
    同一作用域內綁定 / 使用，生命週期單純。
  - 觸發動作選擇僅 `MouseAction::Click`：E5-01 對一次 down/up 配對會分派 Down、Up、與（相符
    游標時）合成的 Click 三個獨立事件；若對三者都判定區段命中，同一次使用者點擊會被誤判為
    三次選取。選擇僅在 Click（代表一次點擊語意完整）觸發，`DownUpSequenceDispatchesExactly
    OneSelectionViaSyntheticClick` 測試明確驗證 Down+Up 序列只產生一次選取事件。
  - 未命中語意刻意與 E5-14 `RegionEvent` 不同：E5-14 未命中子區域時事件仍正常派發（帶
    `region_hit=false` 旗標）；本單元題目明定「無區段命中的點擊不發選取事件」，因此
    `bridge()` 在未綁定 / 未命中任一情形皆直接 `return`，不建構 / 不分派任何事件——不是疏漏
    E5-14 的模式，是刻意採用不同的「無結果」表達方式。
