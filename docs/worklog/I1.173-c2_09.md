## 組裝設計

`ds::widgets::CalendarTodoWidget`（`content/widgets/c2_09/calendar_todo_widget.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`KernelBackend&` + `LayerStack&`（透傳給內部自持的 C1-01
  `SkinProfile shell_`）+ `FontMetrics&`（`render_model()` 用）。widget id 即殼層的具名
  `SurfaceId`，亦作為 `render_model()` 排版目標 surface（與殼層一致，NFR-02 具名指涉）。
- **語意映射**：E7-13 森林的**頂層**節點 = 日期分組（`id` = `"day:" + date`、`label` = 日期
  字串、`value` = Null）；**子層**節點 = 事項（`id` = 呼叫端提供、`label` = 事項文字、
  `value` = `Map{done: bool}`）。`add_item` 找不到既有日期分組即建立，事項附加於分組尾端。
  `toggle_done` 對頂層節點（日期分組）呼叫視為 `Invalid`——只有子層事項有完成狀態語意。
- **load（E7-01 parse + E7-13 build_forest）**：根層 `days` 鍵選填；缺省或（E7-12 空容器
  round-trip 限制導致的）顯式 `null` 皆視為空森林，而非型別錯誤——否則「整份皆空」的 widget
  無法透過 `save()`→`load()` round-trip（自行推導並在程式碼註解記錄此已知限制的因應）。
  真正型別錯誤（如 `days: 5`）與森林建構契約違反仍回 `Invalid`，且一律不改動既有狀態。
- **save（反向重建 + E7-12 serialize）**：自寫 `to_value(Item)`（`build_node` 的反函式），
  只在 `value` 非 Null / `children` 非空時才輸出對應鍵，避免產生會在再解析時塌陷的空容器。
- **render_model（E4-01）**：拼接「日期標題行 + 各事項 `[x]`/`[ ]` 前綴行」純文字，交
  `TextLayout(metrics_, shell_.id())` 排版；空森林 → 空字串 → 空 `LayoutResult`。
- **殼層透傳**：不重複 C1-01 的完整 API 面（其自身 28 案例已覆蓋圖層 / 拖曳 / alpha /
  anchor），改以 `shell()` 存取子，由呼叫端直接驅動視覺行為；本單元測試只需證明「組裝正確」
  （殼層 id / 初始狀態一致），聚焦於六個要求行為本身。

無效操作一律明確回具名 `TodoStatus`，不靜默：空 date / item_id（`Invalid`）、item_id 與既有
任何節點 id 衝突（`DuplicateId`，含與日期分組 id 衝突）、找不到事項（`NotFound`）、對日期
分組誤用 `toggle_done`/`is_done`（`Invalid`）、`load()` 語法錯誤（`ParseError`）或森林契約
違反（`Invalid`，皆不改動既有狀態）。

  情境視同缺省 `days` 處理（空森林），並在程式碼與 CHG 中記錄理由。以
