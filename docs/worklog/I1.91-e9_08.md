## 關鍵設計決定

- **E9-07 為真委派而非空連結**：`InstallWizard` 建構時注入一個 E9-07 `DropInstaller&`；
  `begin_install(source, options)` 於「進度」步驟以使用者選項組成 `DropEvent`（選項摘要放入
  `DropEvent.detail`，E9-07 原樣攜帶）並**實際呼叫** `handle_drop`——跑完 E9-07 安裝生命週期並把
  套件登錄至 `InstallRegistry`。本機驗證亦連上游 .cpp，證明委派為真。
- **進度回報接 E9-07 生命週期**：begin_install 期間於 `DropInstaller` 掛上 E9-07
  `InstallLifecycleListener`，把每個 `InstallStage` 映射為精靈進度百分比（Received=10、Resolved=30、
  Parsed=55、Validated=80、Registered=100）與訊息，對外經 `WizardProgressListener` 回報；結束後解除
  觀察者以免懸掛回呼捕捉 this。
- **狀態機明確、失敗 / 取消不靜默**：`next()` / `back()` / `cancel()` 回傳 `StepTransition`
  （ok + step + message）。授權未接受於 License 擋下；Options 進入安裝須經 `begin_install`（以
  `next()` 前進明確報錯）；取消為終態並封鎖後續；安裝失敗停於 Progress（outcome=Failed）且可
  `back()` 退回 Options 重試（重置為進行中）；成功前進 Complete（outcome=Installed，100%）為終態。
- **非真實 GUI / 平台中立**：純記憶體狀態機，無繪圖 / 視窗 / 事件迴圈、無 `#ifdef` / win32 / cocoa、
  無檔案 I/O。相位 2 換真實 UI 時由 UI 事件驅動既有 API，狀態機一行不動。
