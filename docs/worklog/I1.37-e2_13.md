## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null/假來源 + 欄位模型 + 契約測試**，
**不接任何真實系統媒體 API**，**不得**出現 `#ifdef` / win32 / cocoa / MediaRemote /
MPNowPlayingInfoCenter 等。**消費 E2-01 契約與 E2-02 分級、不自造指標模型或排程器**。

設計（C++17，`namespace ds::sysinfo`）：

- `PlaybackState` enum（Stopped/Paused/Playing）+ `state_rank` / `to_string` 輔助。
- `MediaMetadata` struct（欄位模型）：has_media / state / title / artist / album /
  position_seconds / duration_seconds / artwork_ref；`none()` = 無播放。
- `MediaSource` 抽象來源：`snapshot() → MediaMetadata`。相位 2+ 由真實平台後端實作；
  提供者只依賴此抽象介面（換後端不動提供者）。
- `NullMediaSource` null/假來源：**不接系統媒體 API**，預設回「無播放」；
  set_metadata/set_state/set_position/clear 注入假資料供測試（狀態轉換 / 進度更新模擬）。
- `MediaMetadataProvider : public ds::metrics::MetricProvider`：`register_metrics()` 向
  E2-01 註冊表掛上單一指標 `"media.nowplaying"`；`sample()` 重新查詢更新；`sampling_tier()`
  供 E2-02 排程器登記需求。

## 指標形狀的關鍵設計（為何每個欄位 = 一個實例、為何用 E2-02 採集）

E2-01 六要素含「可列舉實例」。本單元把每個中繼資料欄位建成一個 `MetricInstance`：
- 指標身分：id=`media.nowplaying`、name=`Now Playing`、unit=``、range=`unbounded`
  （狀態/文字/秒數混雜，無統一單位、無單一值域；進度對總長的比例由消費者自算）。
- **七個欄位各一個 `MetricInstance`**（決定性順序 state/title/artist/album/position/
  duration/artwork）：狀態承載位階+文字、文字欄位讀 text、進度/總長讀秒數。
- 進度欄位保留歷史環（capacity=64），其餘 capacity=0——媒體進度會動，配合 **E2-02
  週期分級**（預設 Normal，間隔 8 tick）由呼叫端排程器驅動 `sample()`，逐次把進度推入
  歷史鋪成序列；靜態資訊型 E2-12 則隨選、無歷史。此即本單元用 E2-02 而非隨選的原因。
- 「無播放」誠實表達：狀態恆有效（stopped），其餘欄位 `valid==false`（未知），不塞假值。
