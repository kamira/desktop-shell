## 我要做什麼（動工前計畫）

消費 E7-01 契約（`Value` / `Document` / `FormatVersion` / `parse` / `parse_scalar`），
補上設定持久化的「寫」方向，不自造格式模型。相位 1（Mac / null 期）：純邏輯，
**不得**出現 `#ifdef` / win32 / cocoa / 真實後端。

設計（C++17，`namespace ds::format`）：

- 定位：`PathSegment`（Key / Index）+ `Path` + `parse_path("window.width" / "layers[0].name")`。
- 寫回：`set_value(root, path, value)` 純函式重建，回傳新 Value 樹（不就地改寫，與 E7-01
  不可變 Value 一致）；鍵存在則更新、不存在則附加（保序）；缺失中繼段自動建空 Map；
  list 索引更新，索引 == size 於最後一段則附加；契約違反 throw `std::runtime_error`。
- 序列化：`serialize_value` / `serialize(Document)` / `serialize(root, version)` 產出 E7-01
  可再解析的文字。字串是否加引號借 `parse_scalar` 反推（凡裸寫再解析 ≠ 同一字串者即引號 +
  轉義）；非整數 Number 以最短 round-trip 表示且強制帶小數點；縮排每層 2 空白。
- 核心不變式：round-trip（parse→改值→序列化→再 parse）型別化上一致。

`target_link_libraries(e7_12 PUBLIC e7_01)`。無平台分支，相位 2 換後端一行不動。
