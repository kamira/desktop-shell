## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 傳輸 + 純解析邏輯 + 契約測試**，
**不真的發網路請求**，**不得**出現 `#ifdef` / win32 / cocoa / socket / libcurl / 真實網路後端。
**消費 E2-01 / E2-02 契約、不自造指標模型、不自造排程**。

設計（C++17，`namespace ds::sysinfo`）：

- `HttpResponse`：平台中立回應（status/headers/body），status 0 = 無後端。
- `HttpTransport`：抽象傳輸 `get(url) → HttpResponse`；相位 2+ 由真實網路後端實作。
- `NullHttpTransport`：相位 1 null 傳輸——不發網路，回注入的固定回應或「無後端」空回應。
- 結構化解析：自帶輕量 JSON 解析器（`JsonValue` 可查詢樹、`seek()` 路徑取值、`parse_json()`
  錯誤可定位不靜默）。**不消費 E7-01**：E7-01 是縮排式宣告格式（要求 format_version、非 JSON），
  且 depends_on 僅列 E2-01/E2-02；自帶最小 JSON 解析較合適，也維持相依乾淨（CMake 只連 e2_01 e2_02）。
- `HttpFetchProvider : ds::metrics::MetricProvider`：掛上指標；`sample()` GET→解析→取數值欄位→
  更新 value/歷史；`register_demand()` 以 E2-02 的 `SamplingTier::Low` 登記需求。
