## 我要做什麼（動工前計畫）

在 E7-12（設定值寫回）與 E7-01（宣告式格式核心）之上補一層**設定的圖形化就地編輯資料模型**：
把每個可編輯欄位描述成「編輯控制項模型」（型別 / 當前值 / 約束 / 標籤），使用者編輯後經 E7-12
`set_value` 就地寫回並保留格式。**資料模型層，非真實 GUI**。相位 1（Mac / null）：純邏輯，
**不得**出現 `#ifdef` / win32 / cocoa / 真實 GUI 框架。

設計（C++17，`namespace ds::format`）：

- `EditKind`（Text / Integer / Number / Boolean / Enum / Color）+ `EditableField{ path, label,
  kind, current, constraints }` + `EditConstraints`（範圍 / 列舉選項）+ `FieldHint` / `EditorSchema`。
- `build_editor_model(Value/Document[, schema])`：前序走訪 Value 樹攤平為欄位清單；型別推斷
  （Bool→Boolean、整數→Integer、非整數→Number、`#RGB/#RRGGBB` 字串→Color、其餘字串→Text）；
  schema 覆寫命中路徑的型別 / 標籤 / 約束（Enum / 範圍無法由 Value 推得）。
- `validate_edit(field, new_value)`：型別 / 範圍 / 列舉驗證，違反 → throw `std::runtime_error`。
- `apply_edit(root, field 或 path, new_value)`：驗證後經 E7-12 `set_value` 寫回，回傳新樹。
- `find_field(model, path)`：由路徑回查欄位。

`target_link_libraries(e7_14 PUBLIC e7_12)`。無平台分支，相位 2 換後端一行不動。不自造格式模型。
