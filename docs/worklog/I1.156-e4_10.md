## 我要做什麼（動工前計畫）

module 層純邏輯，消費上游 E4-07（幀序列動畫）與 E5-09（機率排程器）：

- `IdleAnimationTrigger`（`idle_animation_trigger.hpp|cpp`）：持有「累計閒置時間」
  （`idle_elapsed_`，注入式 tick 累計）與一個內部 `ProbabilisticScheduler` 成員。
- `advance(dt)`：先累計 `idle_elapsed_ += dt`；**未達 `idle_threshold_` 前完全不推進內部排程
  器**（不消耗任何亂數，維持決定性可重現）；達門檻後才把 dt 轉呼排程器 `advance(dt)`，回傳
  本次觸發次數。
- `notify_activity()`：只將 `idle_elapsed_` 歸零。因排程器只在被餵 dt 時才推進評估，活動期間
  本單元天然停止餵它，不需額外清空排程器狀態。
- `register_animation(FrameAnimationElement&, eval_interval, probability)`：對內部排程器
  `schedule()` 的薄封裝，回呼捕捉 `this` 與動畫指標，機率命中時對該動畫執行 `reset()` +
  `play()`（從頭播放一次）並累計 `total_triggers_`；沿用其「id=0 為無效」慣例。
  `unregister_animation` 委派 `cancel()`。
- `set_idle_threshold(threshold)`：門檻 0 → `IdleAnimationStatus::Invalid`（不套用，維持既有
  門檻）。
- 因內部排程任務回呼閉包參照 `this`，刪除複製 / 搬移建構與賦值（承 E4-09 `AnimationDriver`
  同類自參照理由）。
- 平台中立、無 `#ifdef` / win32 / cocoa；時間 / 活動通知全注入式，不接真實時鐘 / 輸入裝置。
- **不**自行推進登記動畫的逐幀進度（不呼叫 `FrameAnimationElement::advance()`）——那是呼叫端
  另接 E4-09 驅動源的責任，本單元只決定「該不該觸發」。

## 遇到的錯誤

- 實作錯誤：無。實作與測試編譯一次過（`-Wall -Wextra` 零警告）。
- 設計時的自我修正：起初以為「單次 advance 對一個 interval=1 的任務只會評估一次」，但重讀
  E5-04/E5-09 文件才確認「單次 advance(dt) 若跨越多個間隔，同一訂閱可於該次觸發多次」——因此
  `advance(2)` 對 `eval_interval=1` 的任務是 2 次評估機會，不是 1 次。動工前就在測試草稿階段
  發現並改正相關斷言（`NotifyActivityDuringIdleStopsFurtherTriggersUntilIdleAgain`），未影響
  最終實作邏輯本身（`advance` 只是原樣把 dt 轉呼排程器，語意本就正確；修正的是測試期望值）。
- 流程摩擦：無——直接沿用 E4-07 已驗證過的 include 路徑組合（E4-02 → E1-03/E1-21 間接相依鏈；
  E4-09 → E5-04）並疊加 E5-09 → E5-04（E5-04 已由 E4-09 引入一次，未重複連結問題，g++ 多次
  編譯同一 .cpp 為多個 .o 由連結時各自獨立符號解析，無重複定義）。
