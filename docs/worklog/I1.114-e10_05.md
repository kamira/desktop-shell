## 關鍵設計決策

- **可注入 `ProcessLauncher` 抽象**：`spawn`/`terminate`/`is_alive` 三原語，`WidgetHost`
  不假設行程的實作方式；相位 2 換上真實 fork/exec 或 win32 CreateProcess 後端時，
  `WidgetHost` 本身不需改動。
- **`NullProcessLauncher` 記憶體模擬**：具名遞增 handle（`"proc.<widget_id>#<n>"`），
  額外提供 `simulate_crash()` 測試鉤子，讓「非預期終止」可被確定性地觸發與驗證。
- **一個 `WidgetHost` 對應一個 widget 行程**：狀態機清楚（NotStarted/Running/Stopped/
  Crashed），`restart()` 沿用上次 spec 重新啟動並得到全新 handle。
- **崩潰偵測為輪詢式**：`poll_crash()` 查詢 launcher 存活狀態，偵測到即轉 `Crashed`、
  廣播 `kWidgetCrashedType`、呼叫 `on_crash` 回呼——明確通知，不靜默吞掉。
- **通訊重用 E10-01 `MessageChannel`**：宿主生命週期事件（started/stopped/crashed/
  surface_attached/surface_detached）以 publish/subscribe 廣播；另提供 `channel()`
  存取點供呼叫端直接經點對點佇列與 widget 側收送，兩者互不干擾（E10-01 契約）。
- **surface 經 E1-03 協定橋接**：`spec.surface_id` 非空時，`start()` 先以
  `AlphaSurfaceService::supported()` 做能力閘控前置檢查（避免啟動一個之後得回滾的行程），
  再建立具名 alpha surface 並廣播 attach 事件（含 mode / opacity）；`stop()` / 重啟前銷毀
  並廣播 detach 事件。
- **無效 spec / 能力不可用一律明確回報**：空 id/entry → `Invalid`；能力不可用 →
  `SurfaceUnsupported`；surface id 衝突 / 未注入 `AlphaSurfaceService` → `Invalid`；
  行程啟動後 surface 建立失敗時回滾（終止剛啟動的行程），不留孤兒行程。
- **契約版本改名 `widget_host_contract_version()`**：本地編譯時發現與 E10-01 的
  `ds::ipc::contract_version()` 撞名（本單元 PUBLIC 相依 e10_01，兩者符號會落在同一連結
  單元）；沿用 E10-02 / E10-04 已有的「單元前綴」慣例改名，非重新設計。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- 首次連結出現 `duplicate symbol 'ds::ipc::contract_version()'`：根因是上游 E10-01
  已在 `ds::ipc` 命名空間定義同名 `contract_version()`，本單元 PUBLIC 相依 e10_01 導致
  兩個定義落在同一測試執行檔的連結單元。解法：確認 E10-02 / E10-04 已有相同情境並採用
  「單元前綴」命名慣例（`low_latency_contract_version` / `event_broadcast_contract_version`），
  將本單元的契約版本函式改名為 `widget_host_contract_version()`，重新編譯連結成功、
  31 tests 全 PASS，零警告。
- 測試撰寫過程中曾在 `WidgetHostCrash.PollCrashDetectsSimulatedCrashAndFiresCallback`
  誤植一組互相矛盾的 `is_alive()` 斷言（先 EXPECT_TRUE 後 EXPECT_FALSE），於本機跑驗證前
  自查修正，改為單一正確斷言（崩潰後 `is_alive()` 應即時反映為 false）。
