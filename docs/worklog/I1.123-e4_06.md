## 關鍵設計決策

- **`SurfaceId` 沿用上游型別、不重造**：透過 `e4_02` 的 `image_element.hpp` include 鏈
  （-> `alpha_surface.hpp` -> `null_backend.hpp`）取得 `ds::kernel::SurfaceId`；規格要求
  `e4_06` `PUBLIC` 連 `e4_02`，本單元也確實只需要那條鏈子傳來的具名 id 型別，不使用
  `ImageElement` 本身的任何邏輯 —— 依賴關係「合理但刻意窄」。
- **`list()` 只回具名清單**：不提供任何 `operator[](int)` / `at(int)` 式數字索引存取，
  介面上完全沒有「第 N 個 surface」的概念，滿足 NFR-02。
- **移除目前 surface 不觸發 `on_switch`**：`unregister_surface` 若移除的正是目前 surface，
  只是把狀態清空（`has_current()` 轉 false），語意是「這個 surface 不再存在了」，跟
  「切換到別的 surface」是不同事件；通知只保留給明確的 `switch_to`。
- **切到「目前已是」的 surface 仍觸發通知**：不做「相同就跳過」的隱性優化——呼叫端可能
  刻意要用 `switch_to` 來要求重新整理當前畫面，回傳 `Ok` + 觸發通知讓呼叫端自行決定要不要
  處理，比框架代為判斷「沒變化」更不容易讓呼叫端困惑。
- **未知 id 一律 `NotFound`、空 id / 重複註冊 `Invalid`**：兩種錯誤語意分開，比單一
  `Invalid` 更精確；不崩潰、不部分套用，符合「未知 id 報錯不靜默」的規格硬性要求。
