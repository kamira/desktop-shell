## 關鍵設計決策

- **具名字串命令 id**：`screen.capture.full` / `.region` / `.window`；穩定、可讀、不耦合編號，
  與 E6-01 CommandId 取捨一致。呼叫端經 `bus.dispatch(id, args)` 觸發，零相依本致動器。
- **可注入副作用抽象 `ScreenCaptureBackend`**：`capture(CaptureSpec)→CaptureResult`（尺寸 + image_ref/path）。
  相位 1 為 `NullScreenCaptureBackend`（不觸碰螢幕，回注入的假影像 + 記錄請求）；相位 2 換真實平台後端，
  介面與命令契約不動。致動器邏輯（區域/視窗參數、經 E6-01 分派、結果回報）與後端完全解耦。
- **結果尺寸回報**：`CaptureResult{width,height}`——區域擷取回請求區域寬高、全螢幕/視窗回注入假影像尺寸；
  輸出 image_ref（記憶體參照）或 path（存檔路徑）二擇一（`save_path` 有給則輸出路徑）。
- **無效區域報錯**：`width`/`height` 須為正，否則回 `CommandResult{Failed}` 且不觸及後端；x/y 可為負以
  支援多螢幕虛擬座標（由後端解讀）。缺漏 / 型別不符亦回 Failed（以 has()/getter 保護，NFR-03 一致）。
- **契約版本欄位前綴命名**：`screen_capture_contract_version()`——避免與 E3-02 同命名空間 `contract_version()`
  符號衝突。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **錯誤**：初次跑墊片時「24/24 tests passed」但總斷言數僅 34（原始碼有 106 個 EXPECT/ASSERT），
  逐測探針顯示多數測試在第一個 `ASSERT_TRUE(actuator.register_on(bus))` 後即停（僅 1 check）。
- **根因**：**墊片瑕疵，非產品缺陷**。墊片的 `ASSERT_TRUE(c)` 對引數 `c` 重複求值（一次在檢查、一次在
  `if(!(c)) return`）。`register_on(bus)` 有副作用且非幂等：第一次求值註冊三命令回 true（通過），第二次
  求值遇重複註冊回 false → `if(!false)` 提前 return，掩蓋其後所有斷言而不報失敗。真 GoogleTest 只求值一次，
  不會有此問題。
- **解法**：改墊片 `ASSERT_*` 為「先存入 local 再判斷」單次求值。重跑：106 斷言全跑、全過、零警告。
  產品程式碼一行未動（缺陷純在驗證墊片）。
- 驗證流程：scratchpad 建置採固定輸出目錄、全絕對路徑單一命令（避免觸發 worktree 隔離檢查與重導限制），
  僅動 scratchpad，未影響 repo 任何檔案。
