## 我要做什麼（動工前）

E1-18 是「具名螢幕與每螢幕實例」：以**具名 ScreenId**（非數字索引）列舉螢幕，每一螢幕
有**獨立狀態**（幾何以具名角色 / 具名相對錨點表達，**不得絕對座標 / 數字 z-order**，NFR-02），
可與 E1-17 的每螢幕縮放搭配。相位 1（Mac/null）只寫平台中立介面 + null 後端（單一具名主螢幕，
不真的查詢 OS）。

計畫產出（全部落在鎖定範圍內）：

1. `src/kernel/e1_18/named_screens.hpp`
   - `ScreenId`（具名字串，與 E1-17 同型別）；`ScreenRole`（Primary/Secondary，取代數字 z-order）；
     `ScreenAnchor`（Center/Left/Right/Above/Below，具名相對錨點，取代絕對座標）。
   - `Screen`{ id, description, role, anchor }。
   - `ScreenRegistry`：`defaults()` / 由宣告建構；`is_known` / `find` / `ids`（具名列舉）/ `screens` /
     `size` / `empty` / `primary` / `is_primary` / `anchor_of`。
   - `PerScreen<T>`（樣板）：每螢幕獨立實例狀態，以具名 ScreenId 為鍵；未知螢幕保守。
   - 平台中立：不含任何 `#ifdef _WIN32` / `win32` / `cocoa` 分支，不綁任何真實後端。
2. `src/kernel/e1_18/named_screens.cpp`：內嵌預設拓撲（單一具名主螢幕 `screen.primary`）+
   查詢邏輯（具名列舉、未知螢幕保守、主螢幕以具名角色決定、重複 id 後定義者為準）。
3. `src/kernel/e1_18/CMakeLists.txt`：依 BUILD.md 樣板，library + `test_e1_18` + `add_test`；
   `if(TARGET e1_17)` 可選 link e1_17。
4. `tests/e1/test_e1_18.cpp`：gtest，驗具名列舉、每螢幕獨立實例、未知螢幕保守、null 單螢幕、
   具名角色 / 錨點、與 E1-17 每螢幕縮放搭配。
5. `docs/changes/CHG-20260724-e1_18.md`、`docs/structure/units/e1_18.md`、本 worklog。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- 本機編譯首次 link 失敗（`Undefined symbols: _main`）：根因為 `<gtest/gtest.h>` 的 include
  路徑設成墊片目錄本身，`gtest/gtest.h` 無法解析故墊片（含 main）未被引入。解法：`-I` 指向墊片
  的**父目錄**，讓 `<gtest/gtest.h>` 正確解析。修正後全數 PASS。此純屬本機墊片路徑問題，
  與交付程式碼無關。
