設計（C++17，`namespace ds::actuators`，與 e3_05 一致）：

- 八個具名命令：`net.wifi.on/off/toggle/status`、`net.bluetooth.on/off/toggle/status`。
- `Radio`（Wifi / Bluetooth）+ `is_valid_radio` / `radio_name`：致動器層唯一的合法化點。
- `RadioOp`（On / Off / Toggle / Status）。
- `RadioState`（wifi + bluetooth）供查詢 / 內省。
- `RadioBackend` 抽象後端（`set_enabled(radio,bool)` / `is_enabled(radio)`）+
  `NullRadioBackend`（純記憶體模擬、初值可注入、每無線電一布林）。
- `RadioActuator`：`register_on` / `unregister_from`（回滾語意）+ `handle(radio, op, args)`
  （無效 radio / 無後端回 Failed）+ `current_state()`。

## 關鍵設計取捨

- **無線電合法化在致動器層、不在後端**：`handle` 先以 `is_valid_radio` 攔截越界列舉值，
  合法後才交後端，後端契約可信任傳入 radio 已合法（NullRadioBackend 仍對非法值做縱深防護、
  不改狀態）。這讓「合法化」集中一處、與後端解耦（相位 2 真實後端不必重做驗證）。
- **操作與無線電種類編碼於命令名**：八個具名命令各綁定固定 (radio, op)，命令本身無必填參數，
  呼叫端只需 id 即可觸發；避免以字串參數傳 radio 造成的耦合與驗證分散。以單一
  `radio_command_table()` 作為 register / unregister 的來源，避免兩處清單漂移。
- **冪等 vs 翻轉**：on/off 是絕對設定（重複呼叫冪等）；toggle 讀目前狀態再翻轉。兩者都回
  「操作後啟用狀態」，語意清楚可測。
- **兩無線電互不干擾**：後端以兩個獨立旗標承接，操作 Wi-Fi 不影響藍牙，反之亦然。
- **版本標記命名**：`radio_toggle_contract_version()` 前綴避免與同命名空間其他致動器
  （如 e3_05 的 `volume_contract_version()`）符號衝突（可能同時連入同一 target）。
