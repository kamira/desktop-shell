## 組裝設計

`ds::apps::ChatPanelApp`（`apps/c4_05/chat_panel.hpp/.cpp`）：

- 注入式相依：`SummonPanelProfile&`（C1-05）+ `const FontMetrics&`（E4-01，所有訊息與
  草稿量測共用）+ `HttpFetchProvider&`（E2-14）+ `LayoutConstraints` + `SurfaceId`。
- **訊息模型**：`MessageEntry{ role, text, TypewriterElement display }`，以
  `std::vector<std::unique_ptr<MessageEntry>>` 持有（見下「實作期修正」）。
- **載入 / 附加**：`load_conversation(turns)` 清空重建（捲動歸底）；`append_message
  (role, text)` 附加一則，`auto_scroll()` 為真時捲動跟進，否則保留使用者位置（典型聊天
  UX：不打斷正在回顧歷史者）。
- **送出（C1-05 生命週期 + 注入式回應）**：`submit_input(text)` 先查
  `base_.is_open()`（面板未開啟 → `PanelClosed`），再去除首尾 ASCII 空白判斷是否為空
  （`Empty`），否則附加 `User` 訊息（保留原文）→ 呼叫 `ResponderFn`（`set_responder()`
  可換；未設定用內建 `default_responder`，回覆含 `"stub#N"` 字樣以明確標示非真實 LLM）
  → 附加 `Assistant` 訊息，回 `Ok`。對話資料（`messages_`）獨立於面板顯隱：`close()`
  後既有訊息不清空，僅拒絕新的 `submit_input`。
- **顯示（E4-01 + E4-11）**：`render_message(index)` 直接回傳該則 `TypewriterElement::
  render_model()`（E4-11 內部消費 E4-01）；`measure_draft(text)` 另外直接建一個
  `TextLayout` 呼叫 `measure()`，供輸入框即時預覽草稿尺寸（不經 E4-11，示範直接使用
  E4-01）。`advance(dt)` 對所有訊息推進逐字顯示；`attach(driver)` 綁 E4-09 動畫驅動源，
  之後新附加的訊息也自動一併掛上。
- **捲動（NFR-02：序數，非座標）**：`scroll_to(index)` 越界 / 空對話回 `false`；
  `scroll_by(delta)` 夾在 `[0, count-1]`；兩者皆依「是否捲到最新一則」更新
  `auto_scroll()`。序數比照 E4-01 `LineBox::line` / E2-01 `Metric::instance(i)` 既有慣例
  （資料序列位置，非畫面座標）。
- **上下文指標（E2-14）**：`refresh_context()` 委派 `HttpFetchProvider::sample()`；
  `context_value()` 讀 `provider.metric()->single().value()`（尚未 register 或從未成功
  採集 → `MetricValue::unknown()`，不崩）。

具名結果 `MessageRole`（User/Assistant/System）、`SubmitStatus`（Ok/Empty/PanelClosed）
附 `to_string()`（NFR-02）。無效操作一律明確回具名結果或擲例外，不靜默：面板未開啟、
空白輸入、捲動越界 / 空對話、訊息索引越界（`std::out_of_range`）、非法 UTF-8
（`std::invalid_argument`，沿用 E4-01 `decode_utf8`）。

## 遇到的錯誤與修正

- **實作錯誤（已修正）**：初版把每則訊息的 `TypewriterElement` 直接以值存於
  `std::vector<MessageEntry>`。`TypewriterElement::attach()`（E4-11 委派 E4-09
  `AnimationDriver::add()`）以 lambda 捕捉 `this` 註冊回呼；但 `TypewriterElement`
  的位址並非恆穩定——`vector` 於新增訊息（`push_back` / `emplace_back`）觸發重新配置時
  會搬動既有元素，使先前已綁定動畫的捕捉位址懸空。本機首次跑測試時
  `AttachBindsAnimationDriverAndAutoAdvancesOnHeartbeat` 案例的第二次心跳斷言失敗（新
  附加訊息未被推進；更嚴重地，此為未定義行為，非僅邏輯錯誤）。改為
  `std::vector<std::unique_ptr<MessageEntry>>`：`push_message()` 先以 `make_unique`
  建構最終堆積位址，再對該位址（而非中繼區域變數）呼叫 `set_speed` / `set_text` /
  `attach`，確保 lambda 捕捉到的 `this` 於本物件存活期間恆穩定。修正後重新編譯，24
  案例全數 PASS。
- 流程摩擦（非程式錯誤，記錄備查）：Fact-Forcing Gate 對新檔（`.cpp` / `CHG.md`）要求
  先陳述事實——逐一陳述（呼叫端、去重確認、資料檔案 N/A、逐字引用指示）後重試即通過。
