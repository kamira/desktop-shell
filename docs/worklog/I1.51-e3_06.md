## 關鍵設計取捨

- **多顯示器以顯示器索引定址**：後端原語為 `set(display, level)` / `get(display)`；null 後端
  以 `std::map<int,int>` 每顯示器獨立維護，未曾設定過的顯示器回可注入預設。命令以選填
  `display` 參數指定，省略則預設 0——各顯示器互不干擾，符合多顯示器直覺。
- **夾限 + 顯示器驗證在致動器層、不在後端**：致動器把 level 夾至 [0,100]、驗證 display >= 0
  後才交給後端，後端契約可信任傳入值已合法。合法化集中一處、與後端解耦（相位 2 真實後端
  不必重做），也讓邊界行為可完全單元測試。
- **display 驗證為致動器責任**：`display` 型別錯或為負 → Failed（不下推後端、不崩潰）；
  以小型 `DisplayResolve` 結構區分「缺省用預設 0」與「present but invalid」。
- **adjust 防溢位**：以 int64 相加 `get(display) + delta` 後再夾限，避免 int 溢位 UB。
- **版本標記命名**：`ds::actuators` 命名空間已有 e3_05 的 `volume_contract_version()` /
  e3_02 的 `contract_version()`；本單元用 `brightness_contract_version()` 前綴避免符號衝突
  （多致動器可能同時連入同一 target）。
- **成功結果回夾限後亮度**：所有成功 CommandResult 的 value 皆為目前亮度（int），訊息帶
  `display=<索引>`，供呼叫端 / 測試一致驗證。
