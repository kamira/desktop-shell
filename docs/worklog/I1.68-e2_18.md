## 我要做什麼（動工前計畫）

提供**任意具名效能計數器**的泛用 sysinfo provider：外部以字串鍵註冊感興趣的計數器
（Windows PerfCounter 路徑 / macOS 統計鍵 / 任意自訂鍵），provider 透過**可注入來源**讀值、
以 **E2-01 的 MetricProvider** 掛成一個指標（**每計數器一實例**），以 **E2-02** 採樣。
支援瞬時值（Instant）與可選累積差分速率（Rate）。相位 1 = Mac/null：只寫平台中立介面 +
null/假來源，**絕不接真實計數器 API**。

- 消費 E2-01 / E2-02 契約，不自造指標模型 / 排程器（範式同 E2-03 / E2-12）。
- 因需**執行期動態新增 / 移除鍵**，而 E2-01 的 `InMemoryMetric` 不支援移除實例，故自訂
  `PerfCounterMetric` / `PerfCounterInstance`（仍嚴格實作 E2-01 抽象契約）。
- 誠實語意：查無鍵 / 無讀值 → 該實例 valid==false，不靜默當 0。

## 設計決策要點

- **一指標多實例**：id="perf.counters"，每個註冊鍵一個 `MetricInstance`（instance_id=鍵、
  label=顯示名）——直接借用 E2-01 的「可列舉實例」要素，對應「任意計數器」。
- **unit="" / range=unbounded**：計數器異質（各自語意 / 單位不同），無統一單位與值域。
- **兩種讀值模式**：`Instant` 原樣暴露；`Rate` 以兩次取樣差分算增量（首份設基準回未知、
  計數器重置 curr<prev 保守回 0），與 E2-03 的差分語意一致但泛化到任意計數器。
- **自訂 Metric/Instance 支援動態移除**：`InMemoryMetric` 只增不減；本單元需 register 後
  動態新增 / 移除鍵，故自訂實作（unique_ptr 持有，erase 移除；provider 不快取實例裸指標、
  每次 sample 以 index 走訪避免移除後懸空）。
- **待掛佇列**：`add_counter` 可在 `register_metrics` 前後呼叫；前者暫存於 `pending_`、
  後者直接掛上實例並立即讀初值。
- **來源可注入 + 序列**：`NullPerfCounterSource` 以鍵→固定值 / 序列注入；序列型模擬累積
  計數器隨時間推進，供 Rate 差分測試（與 E2-03 的 `NullCpuTickSource` 同風格）。
