## 我要做什麼（動工前）

E4-18 是視覺元件「徑向線 / 指針(needle/pointer)」（module 層 / 子系統 elements / phase 1 / low），
從中心以某角度延伸的一條線——量表指針 / 時鐘指針的核心語意，最終直接供 CPU/GPU Usage Widget
等量表 Widget 的指針部分組合使用。核心映射是值→角度（與 E4-03 Gauge 相同），但輸出聚焦於
「指針本身」的幾何：長度比例 / 粗細比例 / 顏色，而非弧 / 填充區。相位 1 **不做真實繪製**，
只產「渲染描述模型」供繪製層消費；設定以 E7-03 宣告式變數段落驅動；位置以 E1-03 具名
`SurfaceId` 指涉。

## 設計要點

- 單一元件 `RadialPointerElement` 涵蓋全部語意（不另設基底類別，因指針只有一種形態，
  不像 E4-03 需要 Bar/Progress/Gauge 三種共用基底）。
- 本單元只依賴上游 E1-03 / E7-03（write_scope 未含 E4-03），故值↔範圍 / 夾限邏輯自成一套
  獨立實作，不重用 E4-03 的 `RangedElement`（兩者語意相同但屬不同模組、互不依賴）。
- API 命名依規格採 `set_angle_span(start,sweep)`（而非 E4-03 Gauge 的 `set_arc`），語意相同：
  弧起始角 + 角度跨距，值映射後的指針角度 = start + ratio()*sweep()。
- 指針專屬幾何：`length_ratio` / `thickness_ratio`，皆為獨立設定（非隨值變動），非有限值
  報錯，否則夾限至 [0,1]（與比例類欄位一致的「超界夾限、非有限報錯」慣例）。
- `RenderModel` 為純資料渲染描述，相位 1 不繪製；繪製層後續消費。
- 設定載入器先呼叫 E7-03 `expand()` 展開變數段落（真正消費上游 E7-03），再讀欄位填入元件；
  未出現欄位沿用元件現值（缺欄非錯誤）。

## NFR-02 / 分層 / 平台中立遵循

- **NFR-02**：`RenderModel` 無 x/y / 像素尺寸 / 數字 z-order；位置以具名 surface+slot、
  長度/粗細以比例 [0,1]、角度以值→角度語意輸出表達；顏色為具名語彙。
- 錯誤不靜默：非有限值 / 退化範圍 / 退化角度跨距 / 非有限長度或粗細比例 →
  `std::invalid_argument`；設定型別不符 / 展開失敗 → `ConfigStatus`。
- module 層純邏輯：無 `#ifdef` / `win32` / `cocoa` 分支、不綁任何繪圖 API。
- 未動根 `CMakeLists.txt`、`units.json`、共用 `docs/structure/directory.md`——G4 以每單元獨立結構檔
  `docs/structure/units/e4_18.md` 滿足。
