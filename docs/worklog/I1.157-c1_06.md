## 遇到的問題：E1-02 與 E1-16 的上游既有命名碰撞

動工組裝時，嘗試在同一標頭同時 `#include "input_strategy.hpp"`（E1-02）與
`#include "edge_hot_zone.hpp"`（E1-16）驗證可行性，g++ 立即報錯：

```
src/kernel/e1_04/hit_test.hpp:91:1: error: use of 'HitResult' with tag type that does not
  match previous declaration
   91 | struct HitResult {
      | ^
src/kernel/e1_02/input_strategy.hpp:43:12: note: previous use is here
   43 | enum class HitResult {
```

原因：E1-02 於 `ds::kernel` 宣告 `enum class HitResult`（四態輸入策略的命中結果）；E1-16
`edge_hot_zone.hpp` 內部 `#include "hit_test.hpp"`（E1-04），該檔於**同一命名空間**宣告
**另一個不同型別**的 `struct HitResult`（幾何命中測試結果，含 `status` + `inside`）。這是
兩個各自獨立、各自已合併的上游擴充點之間的既有命名碰撞——本單元（C1-06）依賴規格要求
`[E1-01, E1-02, E1-16]`，是第一個需要同時組裝 E1-02 與 E1-16 的單元，因而首次觸發此問題；
在此之前沒有任何檔案同時引入兩者的標頭，故未被發現。write_scope 不含 `e1_02` / `e1_16` /
`e1_04`，不可修改上游解決。

**解法**：把 E1-16 的實際串接隔離到獨立翻譯單元——新增 `dock_hot_zone_bridge.hpp/.cpp`：
- `dock_hot_zone_bridge.hpp`：只使用本單元自有的中立值型別（`dock_types.hpp`：`DockEdge` /
  `DockPoint` / `DockScreenExtent` / `DockHotZoneStatus` / `DockTriggeredZone`，鏡射 E1-16
  對應型別但為獨立宣告），不 `#include` 任何上游標頭；內部以 `struct Impl` + `unique_ptr`
  pimpl 隱藏實作。
- `dock_hot_zone_bridge.cpp`：本單元**唯一** `#include "edge_hot_zone.hpp"` 之處，內含
  `DockEdge` ↔ `ds::kernel::EdgeHotZone`、`DockPoint` ↔ `LocalPoint`、`DockScreenExtent`
  ↔ `ScreenExtent`、`DockHotZoneStatus` ↔ `HotZoneStatus`、`DockTriggeredZone` ↔
  `TriggeredHotZone` 的一一轉換；`is_valid_dock_edge()` 沿用 E1-16 `is_named_zone` 的窮舉
  switch 慣例攔截無效邊。

如此 `dock_profile.hpp`（同時 `#include "input_strategy.hpp"` + `"dock_hot_zone_bridge.hpp"`
+ `"layer_stack.hpp"`）與 `dock_profile.cpp` 皆不會在同一翻譯單元內同時引入 E1-02 與
E1-16/E1-04 標頭，成功規避碰撞——已於本機以 g++（下方指令）重新編譯確認通過，零警告。
此問題與解法已記錄於 `dock_types.hpp` / `dock_hot_zone_bridge.hpp` 標頭註解與
`docs/changes/CHG-20260724-c1_06.md`、`docs/structure/units/c1_06.md`，供後續單元參考
（若未來仍有單元需同時組裝 E1-02 + E1-16/E1-04，建議採同一隔離手法，或由後續 CHG 提案
上游改名修復）。

## 組裝設計

`ds::profiles::DockProfile`（`content/profiles/c1_06/dock_profile.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`LayerStack&`（E1-01）。建構時另帶 `InputStrategy`
  （E1-02，預設 `Interactive`）。
- **固定邊緣（E1-16 經橋接 + E1-01）**：`dock_to_edge(edge, thickness_ratio, action)` 先
  `layer_stack_.has(layer_capability())` 閘控（NFR-03，未過不註冊熱區、不改狀態——避免
  「熱區已註冊但頂層指派被拒絕」的半成品狀態，因 E1-16 熱區登記無移除 API），再委派橋接層
  `register_zone`（無效邊 / 厚度回對應結果），成功後 `layer_stack_.assign(id_,
  SurfaceLayer::Topmost)`。`undock()` 呼叫 `layer_stack_.remove(id_)` 並重置本地狀態。
- **可見性行為**：`set_auto_hide` / `reveal` / `hide` 皆先檢查 `docked_`；狀態轉換經
  `set_visibility_and_notify()` 統一觸發 `on_reveal` / `on_hide`（僅實際變化才觸發，避免
  重複 no-op 觸發事件）。
- **E1-16 熱區叫出**：`probe_hot_zone(point, screen)` 僅在「已固定 + 自動隱藏中 + 目前
  隱藏」才委派橋接層 `test()`；命中且命中邊緣等於本 dock 固定邊緣（防禦性檢查）才自動
  `reveal()`。
- **add_item**：id 線性查重，重複回 `DuplicateId`（不靜默覆寫），成功觸發
  `on_item_added`。
- **E1-02 組裝驗證**：`backend_input_policy()` / `hit_result()` 直接呼叫 E1-02 純函式，
  與 C1-05 慣例一致。

無效操作一律明確回 false / 具名結果，不靜默：重複 `dock_to_edge`、無效邊 / 厚度、能力不
存在時固定、未固定時 `undock()` / `set_auto_hide()` / `hide()`、已可見時 `reveal()`、
已隱藏時 `hide()`、未固定 / 未啟用自動隱藏 / 未命中時 `probe_hot_zone()`、重複 id
`add_item()`。
