## 錯誤紀錄（錯誤 + 根因 + 解法）

- 本地編譯初次因 include 路徑不全連鎖失敗：`alpha_surface.hpp`（E1-03）→
  `null_backend.hpp`（E1-24）→ `capability_matrix.hpp`（E1-21）三層 include 鏈，一開始只
  給了 e1_03 的路徑。根因：E4-01 標頭為了 `ds::kernel::SurfaceId` 型別 include 了
  `alpha_surface.hpp`，而該檔又 include 更上游的 null_backend / capability_matrix 標頭
  （純為型別宣告，非本單元相依，不需連結其 .cpp）。解法：編譯指令追加
  `-I src/kernel/backend/null -I src/kernel/e1_21` 兩個 include 路徑（純標頭層級，不連結
  任何 e1_21/e1_24 的 .cpp，因本單元不實際實體化 `KernelBackend`）。修正後零錯誤零警告。
- 游標視覺定位在「多行文字、游標恰位於換行字元前後」的邊界上，若只用「glyph 索引落在
  哪個 LineBox 範圍」單一規則，會有歧義（該索引同時是前一行末端與後一行起點）。解法：
  當 `codepoints_[cursor_-1] == '\n'` 時偏好較晚（後一行）的匹配，否則偏好較早（前一行末
  端）的匹配——並各寫一條測試（`RenderModelMultilineCursorPlacementAfterNewline` /
  `...BeforeNewline`）驗證兩側行為皆符合直覺編輯器語意。
