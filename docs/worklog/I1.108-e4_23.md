## 我要做什麼（動工前）

E4-23 是「容器裁切與遮罩」：子內容裁切在容器邊界內（矩形 / 圓角矩形 / 任意路徑），並以
alpha 遮罩控制可見區域，產出**宣告式**裁切 / 遮罩描述（不綁真實繪圖 API）。先讀懂上游
E1-03（`src/kernel/e1_03/alpha_surface.hpp`）：surface / 容器一律以**具名 SurfaceId**
指涉，alpha 以「具名模式 + 正規化不透明度」表達，不含絕對座標——本單元承此精神。

NFR-02（無絕對畫面座標 / 數字 z-order）落地方式：所有幾何一律以**容器自身局部正規化
座標** [0,1]x[0,1] 表達（`NormPoint` / `NormRect`），圓角半徑以「容器短邊比例」表達；
容器以沿用上游 `ds::kernel::SurfaceId` 的具名 id（`ContainerId`）指涉；巢狀關係以
`set_parent` 具名鏈表達，無任何數字層級。

## 本機驗證方式

本機無 cmake、無 gtest。正式 gtest/CMake 檔照 BUILD.md 寫好給 CI。本地重用既有
scratchpad 最小 gtest 墊片（`EXPECT_NEAR` / `EXPECT_FLOAT_EQ` / `ASSERT_*` 等，巨集
單次求值；不進 repo），另建本單元專屬副本避免與其他並行單元共用墊片衝突：

```
g++ -std=c++17 -Wall -Wextra -O0 -g \
  -I engine/render/e4_23 -I src/kernel/backend/null -I src/kernel/e1_21 \
  -I <scratchpad>/e4_23_shim \
  engine/render/e4_23/clip_mask.cpp \
  src/kernel/backend/null/null_backend.cpp \
  src/kernel/e1_21/capability_matrix.cpp \
  tests/e4/test_e4_23.cpp \
  -o <scratchpad>/test_e4_23_local
```

→ 連上游 e1_03 鏈（null_backend + capability_matrix）編譯：零警告全過。
→ 執行：**29 tests、0 failed、29 total，全 PASS**。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **插曲（本地工具，不影響 repo）**：測試檔初版直接重用 scratchpad 既有的
  `gtest/gtest.h` 墊片路徑，但該目錄下同時存在兩份不同版本的墊片（`gtest/gtest.h` 完整版
  含 `EXPECT_FLOAT_EQ` / `EXPECT_NEAR`，`gtest/gtest/gtest.h` 精簡版缺這兩個巨集），
  `-I` 指向父目錄時 `#include <gtest/gtest.h>` 解析到缺失巨集的精簡版，導致
  `EXPECT_FLOAT_EQ` 編譯錯誤。**解法**：另建本單元專屬 `e4_23_shim/gtest/gtest.h`
  （複製自完整版），避免路徑歧義，不動共用墊片。
- 實作邏輯本身：無編譯 / 邏輯錯誤，測試一次全過。
