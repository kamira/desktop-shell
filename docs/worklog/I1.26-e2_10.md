## 指標形狀的關鍵設計（為何三個面向 = 三個實例）

E2-01 六要素含「可列舉實例」。本單元名「時間與**日期**」天然對應——時間軸的三個面向各成
一個 `MetricInstance`：
- 指標身分：id=`time.now`、name=`Current Time & Date`、unit=``、range=`unbounded`。
- 三面向實例（history_capacity=0，時間點無時序歷史）：
  * `epoch` — number = Unix epoch 秒、text = ISO-8601 "YYYY-MM-DDTHH:MM:SSZ"
  * `date`  — number = 曆日數、text = "YYYY-MM-DD"
  * `time`  — number = 日內秒、text = "HH:MM:SS"
- 於是時鐘 widget 綁 `time`、日曆 widget 綁 `date`、排序 / 繪圖用 `epoch`——各面向可分別消費，
  消費者只透過 E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，**不觸及 sysinfo 型別**。

保守設計：source 為 null → 仍掛指標，但三實例值 `unknown()`（valid=false），不崩、不謊報 0；
重複 id 由 E2-01 註冊表保守拒絕、不覆寫既有。

## 平台中立如何達成（無 `#ifdef` / 無 OS 曆法）

不用 `gmtime`/`localtime`（不可攜 / 需時區資料）。改以 Howard Hinnant 的 civil-from-days
純整數算術從 epoch 秒還原 (Y,M,D)，floor 除法切出日內秒（負 epoch 亦正確）。一律 UTC，
本地時區 / DST 涉及 OS，留待後端相位。→ `engine`/`module` 層「換平台一行不動」約束成立。
