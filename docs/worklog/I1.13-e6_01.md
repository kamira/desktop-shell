## 我要做什麼（動工前）

E6-01 是平台第三個擴充點「動作」的契約（engine 層 / command / 承重 20x）。目標：讓任意
致動器（音量、電源、任意副作用）以具名命令掛上匯流排，呼叫端以 命令 id + 參數 觸發，

## 關鍵設計決策（承重契約）

- **具名字串 id 而非數字 opcode**：穩定、可讀、不耦合編號。
- **封閉值型別集合**：跨致動器邊界不變形；複合結構以多個具名參數表達，不塞任意型別。
- **重複註冊拒絕、不覆蓋**：避免致動器被無聲遮蔽（silent shadowing）—— 承重契約的關鍵防線。
- **未知命令回 NotFound 不崩潰**：分派邊界結構化、可預期。
- **型別安全 getter 回 nullopt**：存取不 UB、不丟例外。
- **契約版本欄位**：承重 API 需相容判斷（architecture.md「Q3 的意義加重」）。

## 分層 / 平台中立遵循

- engine 層純邏輯：動作的真實副作用由呼叫端註冊的處理器實現，匯流排只管註冊表與分派。
- 無 `_WIN32` / `win32` / `cocoa` / `__APPLE__` / `#ifdef` 平台分支，不涉及任何後端。
