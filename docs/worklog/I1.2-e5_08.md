## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端 + 契約測試**，
**不得**出現 `#ifdef` / win32 / cocoa / 真實平台後端。

設計（C++17，`namespace ds::events`）：

- `SystemEventType` enum class：作業系統層級事件種類——
  睡眠 `SystemSleep`、喚醒 `SystemWake`、顯示器變更 `DisplayChanged`、
  session 鎖定 `SessionLocked` / 解鎖 `SessionUnlocked`、電源狀態變更 `PowerStatusChanged`。
- `SystemEvent` struct：`type` + 人類可讀 `detail`（平台中立 payload，不綁任何 OS 型別）。
- `SystemEventListener` = `std::function<void(const SystemEvent&)>` 回呼型別。
- `SubscriptionId`：訂閱代號，供解除訂閱。
- `SystemEventSource`：抽象介面——`subscribe()` / `unsubscribe()`。
- `NullSystemEventSource`：null 後端。不連任何真實 OS；提供 `inject(event)`
  讓測試手動注入事件驗證分派。多訂閱者皆收、解除訂閱後不再收、未知 id 解除為 no-op。

分派語意刻意平台中立：介面與 null 後端在相位 2 換 win32 後端時一行不動，
真實後端只需實作 `SystemEventSource` 並在 OS 事件到達時呼叫既有分派路徑。
