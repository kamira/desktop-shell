## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端 + 契約測試**，
**不得** `#ifdef` / win32 / cocoa / RegisterHotKey / 真實 OS 呼叫。

設計（C++17，`namespace ds::events`）：

- `Modifier`：位元旗標修飾鍵（Control / Alt=Option / Shift / Meta=Cmd/Win/Super），
  附 `operator|` `operator&` `has_modifier`——**具名而非平台掃描碼**。
- `Key`：具名鍵 enum（字母 / 數字 / F1-F12 / 常用控制鍵），`Unknown` 為無效。
- `Hotkey`：`modifiers` + `key`，附 `==` `!=` `<`（供 map 鍵與去重）、`valid()`。
- `GlobalHotkeys`：抽象介面——`has()`（NFR-03 閘控）/ `register_hotkey(Hotkey, cb)→HotkeyId` /
  `unregister(id)`。（`register` 為保留字，故命名 `register_hotkey`。）
- `NullGlobalHotkeys`：null 後端。以建構參數 `available` 模擬平台支援與否：
  - 不可用（預設，對映能力矩陣 `default_available=false`）→ has() false、register 回 0。
  - 可用 → register 正常、`inject(hotkey)` 分派給對應回呼。
  獨佔註冊（重複熱鍵衝突拒絕）、解除後不再觸發、未知 id 解除 no-op、回呼中解自己安全。

分派語意刻意平台中立：相位 2 換真實後端時介面與 null 後端一行不動，
真實後端只需實作 `GlobalHotkeys` 並在 OS 熱鍵事件到達時走既有分派路徑。
