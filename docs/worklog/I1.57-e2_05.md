## 我要做什麼（動工前計畫）

以 E2-03（CPU 負載）為同類範式，做 GPU 的 sysinfo 提供者：消費 E2-01 `MetricProvider` 契約 +
E2-02 `SamplingTier` 分級，不自造模型 / 排程器。相位 1 平台中立：只寫抽象來源 + null/假來源，
絕不接真實 GPU API。

- 值模型 `GpuStat`（單張：usage 比率 / vram used,total / temp，逐欄 valid）+ `GpuStatSample`
  （全 GPU 快照）。
- 抽象 `GpuStatSource::sample()→GpuStatSample`（列舉 GPU）+ `NullGpuStatSource`（固定/序列注入）。
- `GpuStatsProvider` 掛三指標 `gpu.usage`/`gpu.vram`/`gpu.temp`，每張 GPU 一組實例；`sample()`
  更新 + 動態增減；`sampling_tier()` 建議分級。
- 自由函式 `vram_ratio` / `humanize_bytes` 獨立可測。

## 設計決策要點

- **三個指標而非一個**：使用率 / VRAM / 溫度是三種不同量（不同單位 / 範圍），各自為一個
  E2-01 `Metric`、以每張 GPU 為可列舉實例，最自然對應六要素模型，且與 E2-03「一指標多實例」
  對稱（CPU：cpu.usage 的實例=核心；GPU：每指標的實例=GPU）。
- **VRAM 主維度取 %、bytes 置 text**：長條 / 直方圖要正規化（需有界），故主數值取使用率 %
  （bounded[0,100]）；已用/總量 bytes 以 `MetricValue::text`（E2-01 六要素之「值」的文字面向，
  範例即 "82°C"）呈現 "4.0 GiB / 8.0 GiB"。兼顧可正規化與可顯示，且不新增模型。
- **逐欄 valid 而非整張**：真實硬體可能「使用率可讀但溫度感測缺」，逐欄誠實才不因一欄缺讀而
  整張未知。VRAM 總量 0 → 百分比無從計算 → 亦視未知（不謊報 0）。
- **溫度 range=at_least(0)**：溫度無自然上限，設假上界會誤導正規化；寧缺勿濫（與 E2-01
  「有界才正規化、無界回 nullopt」一致）。
- **null 來源統一固定/序列**：以「序列 + 列盡回最後一份」統一表達——單元素序列即「固定」，
  多元素即「序列」，游標推進模擬時間，涵蓋任務要求的「注入固定/序列資料」。
- **無 GPU = 0 實例**（相對 CPU 恆有 "total"）：GPU 規格為「每 GPU 一組實例」、無總體聚合；
  null 期無 GPU 時三指標各 0 實例，誠實表達，`instance_count()>=0` 為 E2-01 允許。
