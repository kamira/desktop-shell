## 我做了什麼

一個 sysinfo 指標提供者，把 CPU 使用率（總體 + 每核心）透過 E2-01 `MetricProvider` 掛成指標
`cpu.usage`（unit="%"、range=`bounded[0,100]`），並以 E2-02 頻率分級（預設 High）決定採樣。
設計刻意分離、易組合（本單元是最終 CPU/GPU Usage Widget 的核心資料來源）：

- **值模型**：`CpuCoreTicks`（累積 busy/total）、`CpuTicksSample`（全 CPU 快照）、
  `CpuUsageSample`（overall + per_core 比率 [0,1] + valid）。
- **差分演算法**（自由函式，獨立可測）：`core_usage_ratio`＝busyΔ/totalΔ（防重置/無經過
  時間/溢位）；`usage_from_delta`＝每核比率 + **聚合**總體（以 totalΔ 加權）、核心數以共同數
  對齊。
- **兩條計算路徑，皆注入式、平台中立**：
  - 累積 tick 差分：`CpuTickSource`（抽象）+ `NullCpuTickSource`（注入序列）+
    `DifferencingCpuStatSource`（保存上一份、每次 sample 差分；首次回未知）。
  - 直接比率：`NullCpuStatSource`（注入固定/每核比率，null 期預設無讀值）。
- **提供者** `CpuLoadProvider`：總體實例 `total` 恆存在 + 每核心 `cpu0`/…（各保留歷史環）；
  `sample()` 更新（核心數增則動態新增實例、減則設未知）；`sampling_tier()` 供 add_demand。
- **絕不接真實 CPU API**（無 host_processor_info / /proc/stat / mach / #ifdef / win32 / cocoa）；
  無讀值以 valid==false 誠實表達，不謊報 0；消費者只走 E2-01 抽象介面。
