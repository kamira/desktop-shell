## 組裝設計決策

- **展開 / 收合狀態不進 E7-13 / C1-05**：`Item` 是純資料樹（無 UI 狀態概念），C1-05
  `SummonPanelProfile` 也沒有「展開」語意（它的生命週期是 `Open`/`Closed` 面板整體，非
  逐節點）。因此本單元自己以 `std::set<std::string> expanded_` 追蹤（純資料，符合相位 1
  約束），對不存在 id / 葉節點 / 重複操作一律回 false 不靜默。
- **select() vs activate() 的分工**：`select(id)` 先判斷葉 / 非葉（`NotLeaf` 對非葉節點，
  不啟動）；葉節點委派 `activate(id)`。`activate()` 亦可直接呼叫（跳過「選取」語意），
  供測試 / 呼叫端直接驗證 E3-02 組裝是否正確——語意與 `select()` 對葉節點的分支完全等價，
  避免重複邏輯（`select` 內部就是呼叫 `activate`）。
- **葉節點啟動宣告 schema**：`value: {command: <命令id>, args: {<字串鍵值對>}}`——本單元
  轉譯 `args`（E7-01 `Value` Map，值須為字串）為 E6-01 `CommandArgs`（字串鍵 + 字串值），
  再分派。刻意**不**限定 `command` 只能是 E3-02 三個 id 之一——保持與 CommandBus 一樣的
  開放性（呼叫端可能之後掛其他致動器），但提供
  `make_launch_program_value` / `make_open_file_value` / `make_web_search_value` 三個工廠
  直接对齐 E3-02 慣例，降低呼叫端記憶負擔、同時讓「本單元確實使用 E3-02」在程式碼層面
  可見（不只是 CMakeLists 連結字面）。
- **刻意不耦合 C1-05 的 Open/Closed 面板狀態**：`select()`/`activate()`/`expand()`/
  `collapse()` 皆不檢查 `base_.is_open()`，也不呼叫 `base_.select()` 觸發面板關閉。理由：
  這樣選單樹的資料操作（載入、展開、選取觸發啟動）與面板「何時顯示」兩件事保持正交，
  呼叫端可以在面板尚未叫出前就預先載入 / 展開選單。若後續 wave 需要「選取即關閉面板」
  的產品語意，屬於在此之上再組裝一層的呼叫端職責，非本單元 write_scope 內的判斷。
