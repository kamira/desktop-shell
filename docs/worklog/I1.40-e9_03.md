## 我要做什麼（動工前計畫）

以 E9-01 的元件（`Package` = manifest + 內容清單 entries）為單位，做一層「可互換組合」API：

- `ComponentSlot{id, required_kinds}`：組合中的具名可互換位置；插槽介面 = 元件須提供哪些資源 kind。
- `check_compatibility(slot, component)`：先複用 E9-01 `validate_package` 驗元件結構完整，再檢查
  元件 `entries` 是否對每個 `required_kind` 至少提供一項；不相容回帶原因的 `CompatibilityResult`。
- `Composition`：`add_slot` / `bind`（首次綁定，插槽須空）/ `swap`（替換，插槽須已綁定）/
  `unbind` / `is_bound` / `bound_component` / `compatible_candidates`（回相容候選索引）/ `validate`。
- bind/swap 不相容或狀態不符一律 failure 且**不改狀態**（swap 失敗保留原元件）。
- CMake：`target_link_libraries(e9_03 PUBLIC e9_01)`（經 E9-01 再傳遞 E9-02 manifest include）。

參考已合併的 `engine/package/e9_01/`（`Package`/`PackageEntry`/`PackageResult`/`validate_package`、
二選一結果型別、不靜默失敗）與 `engine/package/e9_02/`（`Manifest`/`ParseError`、CMake 連上游樣板）。

## 本地驗證結果

```
g++ -std=c++17 -Wall -Wextra -Werror -I <shim> -I engine/package/e9_01 -I engine/package/e9_02 \
    -I engine/package/e9_03 \
    engine/package/e9_02/manifest.cpp engine/package/e9_01/package.cpp \
    engine/package/e9_03/composition.cpp tests/e9/test_e9_03.cpp <shim>/gtest_main.cpp -o test_e9_03_local
./test_e9_03_local
→ 19 passed, 0 failed, 19 total（全 PASS），零警告
```

19 個測試涵蓋：相容性檢查（提供全部 required_kinds 相容 / 缺 kind 帶原因不相容 /
空要求接受任一有效元件 / 結構無效元件不相容且原因指出「結構無效」）、插槽註冊（空 id / 重複 id 拒絕）、
空插槽狀態（新插槽為空、未知插槽 has/is_bound/bound_component 一律安全）、綁定相容元件
（成功並可取回元件、未知插槽失敗指「不存在」、不相容失敗且插槽仍為空、已綁定再 bind 失敗且保留原綁定）、
替換（swap 換另一相容元件成功、swap 不相容保留原元件、空插槽 swap 失敗）、
unbind（回空狀態、重複 unbind 明確報錯、清空後可重新以任一相容元件綁定）、
列舉候選（回相容索引依原序、未知插槽回空清單）、組合完整性（有未綁定插槽 failure 指名該插槽、
全綁定且相容通過、空組合視為完整）。
