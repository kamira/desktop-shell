## 組裝設計

`ds::profiles::OsdOverlayProfile`（`content/profiles/c1_04/osd_overlay_profile.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`TransientProfileManager&`（E1-14）+ `LayerStack&`
  （E1-01）。建構時另帶 `InputStrategy`（E1-02，預設 `ClickThrough`——OSD 慣例：顯示提示
  但不擋下方操作）。
- **生命週期（E1-14）+ 具名頂層（E1-01）雙組裝**：`show(message, ttl)` 先
  `lifecycle_.create(id_, tp, ttl)`（`tp.input` 帶入策略、`tp.surface.layer` 強制 Overlay、
  `create()` 內再強制 lifecycle 為 Ephemeral），成功後再 `layers_.assign(id_, Overlay)`
  指派 E1-01 具名頂層——這是與 E1-14 `SurfaceProfile.layer` 欄位不同的**另一個**資料結構
  （E1-01 `LayerStack` 是獨立的堆疊維護器，非 E1-24 四參數 profile 的欄位），本單元刻意
  兩者都組裝以示範 E1-01 的整合點。若 E1-01 `assign()` 因空 id / 能力不可用而拒絕，
  `show()` 會呼叫 `lifecycle_.expire(id_)` 回滾剛建立的 E1-14 條目，回 false，避免「lifecycle
  有記錄但未歸屬任何圖層」的不一致狀態。
- **收起（E1-14 + E1-01 連動）**：`dismiss()` = `expire(id_)`，觸發到 `handle_expiry` 後
  一併 `layers_.remove(id_)`（連動移除頂層歸屬）+ 觸發 `on_dismiss(Manual)`；逾時路徑
  （`advance()` 跨過 ttl）走同一個 `handle_expiry`，故頂層歸屬移除與 `on_dismiss(Timeout)`
  對兩條路徑一致。
- **更新（`update(message)`）**：僅改變顯示中的內容並觸發 `on_update`，不觸碰 E1-14
  計時器（不重置逾時倒數）——對應「音量再按一次，數字變了但倒數計時不重來」與「倒數
  計時仍照舊、只是文字更新」兩種常見 OSD 行為中選擇後者（更簡單、無需額外重建計時器
  API）；未顯示時回 false。
- **輸入策略（E1-02）**：策略欄位隨 `show()` 傳入 E1-14 `TransientProfile.input`；另提供
  `backend_input_policy()` / `hit_result()` 直接呼叫 E1-02 純函式，供驗證組裝正確（與
  C1-05 慣例一致，不需要真的接上 `KernelBackend`）。
- **回呼狀態守衛**：`handle_expiry` 除了以 `id_` 過濾管理器共用的過期事件外，另加一道
  「僅在 `Showing` 狀態才處理」的守衛——因為 `show()` 內的回滾路徑也會呼叫
  `lifecycle_.expire(id_)`（此時本物件尚未切換進 `Showing`），若無此守衛會誤觸發使用者
  可感知的 `on_dismiss`。這是 C1-04 相較 C1-05 `SummonPanelProfile::handle_expiry` 多出的
  一道守衛（C1-05 沒有「E1-14 成功但另一擴充點組裝失敗需回滾」的情境）。
- **解構安全**：`~OsdOverlayProfile()` 若仍顯示中，強制 `dismiss()`（同 C1-05 已知限制：
  E1-14 `on_expire()` 無移除回呼 API，解構前主動收起是唯一避免懸置回呼的手段）。

無效操作一律明確回 false，不靜默：重複 `show()`、`show(ttl=0)`（委派 E1-14）、對未顯示
OSD `update()` / `dismiss()`、E1-01 圖層能力不可用時 `show()`（回滾，見上）。
