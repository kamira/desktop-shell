## 關鍵設計判斷

1. **NFR-02 下如何做需要座標的命中測試**：命中測試本質需要點座標，但 NFR-02 禁止**畫面絕對
   座標**。解法：所有座標一律**元件本地 / 相對**（`LocalPoint`，原點為元件自身本地原點），
   形狀在自身本地座標系內定義與判定；surface 於螢幕的絕對位置不進入本層，改由**具名圖層**
   `SurfaceLayer` 表達。命中優先（z-order）以具名圖層 + 宣告順序決定，**不暴露任何數字 z**。
   `layer_rank()` 為內部比較用的具名列舉序（非對外 API），符合 NFR-02。

2. **形狀模型**：單一 `Shape`（tagged struct + `ShapeKind`）承載五種形狀，配工廠函式
   （`make_rect` 等）確保欄位一致，讓 `hit_test(point, shape)` 單一入口即可。矩形 / 圓角以
   (width,height) extent（本地原點 (0,0)）表達；圓以本地圓心 + 半徑；多邊形 / path 以本地頂點
   序列。多邊形恆 even-odd；path 帶顯式 `FillRule`（EvenOdd / NonZero winding），兩者提供實質
   差異。邊界（落在邊 / 頂點上）一律視為命中（`on_segment` 容差判定）。

3. **alpha 命中如何「用 E1-03」而不引入絕對座標 / 真實像素**：E1-03 只存 `AlphaMode` + 整體
   opacity（相位 1 無逐像素資料）。故 per-pixel alpha 值由**注入式** oracle `AlphaQuery`
   （`std::function<float(LocalPoint)>`）供給——測試 / 呼叫端注入，平台中立、與真實合成器解耦。
   `hit_test_alpha` 語意：幾何未命中→不命中；`Opaque`→忽略 alpha；`PerPixel`→有效 alpha
   = oracle(point) × 整體 opacity，低於門檻（透明）不命中；`HitPolicy::Transparent`→命中穿透
   永不命中本 surface。真實後端上線後 oracle 可改由後端 surface alpha 通道供給，公開 API 不變。

4. **命中優先 topmost**：`topmost_hit(point, surfaces)` 逐一以 `hit_test_alpha` 判定，取命中中
   **最高具名圖層**者；同層以**宣告順序**後者為上（穩定順序，非數字 z）。任一 surface 形狀 /
   座標無效→整體回 `Invalid`（報錯不靜默，不悄悄略過）。

5. **無效形狀報錯不靜默**：`HitStatus`{Ok, Invalid}（與 E1-03 `AlphaStatus` 同語意，不用例外）。
   負範圍 / 負半徑 / 非有限值 / 頂點數 < 3 / 非有限查詢點 / oracle 回非有限 alpha → `Invalid`。
   corner_radius 超過 min(w,h)/2 為 clamp（非錯誤）；零面積 extent 為退化但有效。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **凹多邊形測試點取值錯誤**：首版凹多邊形（箭頭形）測試點落在頂點對齊的掃描線（y 與頂點
  重合）且方向判斷有誤，2 個斷言失敗。根因：手推凹多邊形內外時取樣點恰在退化掃描線上、
  且對凹口位置判斷相反。解法：改用**軸對齊 L 形**凹多邊形（底條 + 左柱、缺右上角），取樣點
  y=1/3 皆不與任何頂點 y 重合，內 / 外 / 凹處三點明確，重編零警告 21/21 全綠。
- 其餘：實作 / 測試首次編譯即零警告，無其他邏輯錯誤。
