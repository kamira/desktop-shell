## 我要做什麼（動工前）

E3-01 是外部命令執行致動器：把「執行外部命令 / 行程」以具名命令 `command.run` 掛上 E6-01
命令匯流排，呼叫端以 命令 id + 具名參數（program / args / cwd / env）觸發。相位 1（Mac / null 期）

比照已合併的 E3-02（啟動 / 開檔 / 網頁搜尋致動器）的「注入式後端 + null」既定樣式。

## 關鍵設計決策

- **具名字串命令 id `command.run`**：穩定、可讀、不耦合編號，與 E6-01 CommandId 取捨一致。
  呼叫端經 `bus.dispatch(id, args)` 觸發，零相依本致動器。
- **執行抽象 `CommandRunner`**：`run(CommandSpec)→RunResult`。致動器邏輯（參數組裝、經匯流排
  分派、結果回報）與後端解耦。相位 1 為 `NullCommandRunner`（不觸碰 OS，只記錄請求並回可注入
  結果，未注入時預設 exit 0 no-op 成功）；相位 2 換真實執行器，介面與命令契約不動。
- **結果對映**：執行器回 exit_code 0 → `CommandResult{Ok}`（value=exit_code、message=stdout）；
  非零 → `Failed`（value=exit_code、message=stderr）。清楚區分「執行有進行」與「命令回報失敗」——
  後者仍是一次成功的分派 + 執行，執行器已被觸及並記錄。
- **必填參數以 has()/get_string 保護**：program 缺漏 / 空值 / 型別不符（含選用 args/cwd/env 型別
  不符）一律回 `CommandResult{Failed}`，不崩潰、不丟例外、不觸及執行器（與 NFR-03「能力閘控需
  has() 保護」取捨一致）。
- **契約版本欄位具名 `command_actuator_contract_version()`**：避免與同命名空間 `ds::actuators`
  已存在的 E3-02 `contract_version()` 符號衝突（未來若同一 TU 連結兩者）。

## 分層 / 平台中立遵循

- modules/actuators 層：透過 E6-01 契約掛命令，不綁任何真實 exec / spawn / fork / system /
  CreateProcess / OS 行程 API；相位 1 只有 null 執行器記錄請求並回注入結果。
- 無 `_WIN32` / `win32` / `cocoa` / `__APPLE__` / `darwin` / 真實行程 API 平台分支；
  唯一 `#ifndef` 為 header guard。
