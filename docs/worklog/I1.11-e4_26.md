## 我要做什麼（動工前）

E4-26 是「音效播放」（module 層 / 子系統 elements / 非視覺 / low）：UI 元件需要播放短音效
（點擊、通知、錯誤提示等）。module 層要求平台中立純邏輯，**不綁真實音訊裝置**：設計音效資源
引用與播放介面，並附一個記錄呼叫、不真的出聲的 null 後端，供單元測試驗證狀態轉換。

計畫產出（全部落在鎖定範圍內）：

1. `modules/elements/e4_26/audio_player.hpp`
   - `SoundId`（0 保留無效）、`SoundClip`{ id, name }、`SoundLibrary`（register_clip / contains / find / size）。
   - `AudioPlayer` 純虛介面（play / stop / stop_all / set_volume / volume / is_playing）；
     `AudioCall` + `AudioCallRecord`；`NullAudioPlayer`（null 後端 + 測試內省 play_count / playing_count / call_log）。
2. `modules/elements/e4_26/audio_player.cpp`：登錄與 null 後端狀態機（音量夾限、重播計次、呼叫記錄）。
3. `modules/elements/e4_26/CMakeLists.txt`：依 BUILD.md 樣板，library + `test_e4_26` + `add_test`。
4. `tests/e4/test_e4_26.cpp`：gtest，涵蓋註冊、播放拒絕 / 接受、is_playing、重播計次、stop、stop_all、
   音量夾限、多音效獨立、呼叫記錄序列。
5. `docs/changes/CHG-20260724-e4_26.md`、本 worklog、`docs/structure/units/e4_26.md`。

## 分層 / 平台中立遵循

- module 層純邏輯：null 後端只維護狀態與記錄呼叫，不驅動任何真實音訊 API。
- 無 `#ifdef _WIN32` / `win32` / `cocoa` 分支，不涉及任何後端。
- 未動根 `CMakeLists.txt`、`units.json`、共用 `docs/structure/directory.md`——G4 以每單元獨立
