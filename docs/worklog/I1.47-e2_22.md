## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null/假來源 + 契約測試**，**絕不接**真實
Registry / `defaults` / win32 / `#ifdef` / RegOpenKey。**消費 E2-01 契約、不自造指標模型**。

設計（C++17，`namespace ds::sysinfo`）：

- `RegistryType`（String/Integer/Binary）+ `RegistryValue`：型別標記載體，具型別存取器在
  型別不符時回 `std::nullopt`（**明確回報型別錯**）。
- `RegistrySource` 抽象後端：`read(path)->optional<RegistryValue>`（查無鍵回 `nullopt`）、
  `enumerate(path)->vector<string>`（直屬子項名稱、決定性）。路徑以 `/` 分段。
- `NullRegistrySource` null/假來源：**記憶體樹**，不接真實登錄；`set_value`/`remove`/`clear`
  注入假資料供測試。`enumerate` 由已存值路徑之前綴推導直屬子項（`std::set` 去重 + 字典序）。
- `registryValueToMetric()`：讀取結果 → E2-01 `MetricValue`（查無鍵→未知、Integer→數值+文字、
  String→文字、Binary→位元組數描述）。
- `RegistryReaderProvider : public ds::metrics::MetricProvider`：`register_metrics()` 向
  E2-01 註冊表掛上單一指標 `"registry.values"`。

## 指標形狀的關鍵設計（為何每個選定鍵 = 一個實例）

E2-01 六要素含「可列舉實例」。登錄檔讀取天然對應此要素：
- 指標身分：id=`registry.values`、name=`Registry Values`、unit=``、range=`unbounded()`
  （登錄值多型，不強加值域）。
- **每個選定鍵建成一個 `MetricInstance`**（instance_id=label=鍵路徑、value=該鍵讀值、
  history_capacity=0，因登錄值為點查詢、無時序歷史）。
- 於是「清單」= 依序列舉實例、「數量」= `Metric::instance_count()`。消費者（掛件）只透過
  E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，**完全不觸及 sysinfo 型別**。

保守設計：source 為 null、keys 為空、或某鍵查無值 → 仍掛上指標（該實例未知 / 空指標），
不崩、不把未知誤當 0；重複 id 由 E2-01 註冊表保守拒絕、不覆寫既有。
