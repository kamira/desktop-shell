## 我要做什麼（動工前）

E1-16 是「螢幕邊緣/角落熱區」：定義螢幕四邊、四角的觸發熱區（如滑到左邊緣觸發側欄、滑到
角落觸發某動作），用上游 E1-04（幾何命中測試）判定滑鼠本地點是否進入熱區，觸發對應動作。

先讀了 `docs/backlog/BUILD.md`（NFR-02、write_scope 慣例、G4 同步規則）與
`src/kernel/e1_04/hit_test.{hpp,cpp}`（幾何命中測試：`LocalPoint` / `Shape` / `HitTester`，
含 `make_rect` 與矩形點內判定含邊界的行為）。

計畫產出（全部落在鎖定範圍內）：

1. `src/kernel/e1_16/edge_hot_zone.hpp`
   - `EdgeHotZone`：8 個具名邊/角（Left/Right/Top/Bottom/TopLeft/TopRight/BottomLeft/
     BottomRight），NFR-02 要求無數字方位。
   - `ScreenExtent{width, height}`：僅螢幕尺寸，非絕對位置。
   - `HotZoneAction`（具名動作字串）、`HotZoneStatus`（`Ok` / `InvalidZone` /
     `InvalidThickness`）、`TriggeredHotZone`。
   - `EdgeHotZoneRegistry`：`register_zone(edge, thickness_ratio, action)` /
     `test(point, screen) -> optional<TriggeredHotZone>` / `size()`。
2. `src/kernel/e1_16/edge_hot_zone.cpp`
   - 依邊/角 + ratio + 螢幕尺寸換算熱區矩形（原點 + 範圍）。
   - 用 E1-04 `HitTester::hit_test` 判定平移後的點是否落入矩形——複用既有幾何邏輯而非
     重寫比較式。
   - 角落優先於邊；同類別（皆角或皆邊）中較晚註冊者為準。
   - 無效邊（非具名列舉值）/ 無效厚度（非有限、<=0、>1）：回結構化狀態碼，不註冊、不靜默。
3. `src/kernel/e1_16/CMakeLists.txt`：`add_library(e1_16 ...)` +
   `target_link_libraries(e1_16 PUBLIC e1_04)` + `test_e1_16` executable + `add_test`。
4. `tests/e1/test_e1_16.cpp`：gtest，涵蓋四邊/四角觸發、厚度比例、邊界情形、多熱區、
   角落優先於邊、無效邊/厚度報錯、不同螢幕尺寸。

## 動工中的取捨

- **screen 表達**：只給 `depends_on=[E1-04]`，不能連上 E1-18（具名螢幕）或其他螢幕相關
  單元，故 `ScreenExtent` 只在本單元內定義，僅表達尺寸（與 E1-04 `Shape` 的 width/height
  同語意），不涉及螢幕在桌面的絕對位置排列，符合 NFR-02。
- **`test()` 的無效輸入處理**：規格明訂回傳型別為 `optional<觸發熱區>`，故點/螢幕幾何無效
  時回 `nullopt`（非額外狀態碼）；真正需要「報錯不靜默」的是**設定期**（`register_zone`
  的邊/厚度），該處回結構化 `HotZoneStatus`。
- **角落優先**：實作上先分別收集「本次落入的最後一個角落熱區」與「本次落入的最後一個邊
  熱區」，最後角落優先回傳；若無角落命中則退回邊。此邏輯以 `Priority` 測試群組驗證，含
  「未註冊對應角落時退回邊」的情境。
