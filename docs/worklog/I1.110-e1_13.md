## 關鍵發現

E1-01 已能把**單一**具名 surface 指派到具名圖層並維持 z-order，但沒有單元管理「同一份
profile 定義被同時實例化成多份」——同一 widget 開兩個視窗、各自獨立狀態、各自具名 id、
可各別列舉 / 查詢 / 銷毀。本單元即補上這層：`ProfileInstanceRegistry` 組合（非繼承）一個
E1-01 `LayerStack`，`instantiate` 內部呼叫其 `assign`，`destroy` 呼叫其 `remove`，能力矩陣
單一資料來源即該 `LayerStack`（registry 自身不另持一份矩陣，避免漂移）。

設計取捨：`instantiate(definition) -> id` 由 registry **自動生成**具名 id（格式
`<definition_id>#<n>`），而非要求呼叫端先取好唯一 id 再傳入——貼合單元規格所列的
`instantiate(profile)->id` 介面形狀，且格式仍是純字串、可回溯所屬定義，序號只用於拼字串、
從不以數字型別跨越 API 邊界（NFR-02）。每份實例另持獨立 `visible` 旗標（純本地狀態、不涉
能力），具體示範「各實例獨立狀態」——同定義兩份實例的 show/hide 互不牽連。
