## 我做了什麼

一個 sysinfo 指標提供者，把系統運行時間（uptime 秒數 + 格式化文字 + 可選開機時間戳）透過
E2-01 `MetricProvider` 掛成指標 `system.uptime`（unit="s"、range=`at_least(0)`），並以 E2-02
頻率分級（預設 Low）決定採樣。設計沿用既有 sysinfo provider 範式（e2_03 / e2_12）：

- **值模型**：`UptimeReading`（`seconds` + 可選 `boot_unix_time` + `valid`；`of`/`unknown`
  工廠 + 相等運算子）。
- **格式化**（自由函式，獨立可測）：`format_uptime(seconds)`＝"Nd HH:MM:SS"（天數任意位數、
  時/分/秒補零；負值視為 0、小數截斷）。
- **注入式來源，平台中立**：抽象 `UptimeSource::read()`；`NullUptimeSource` 可注入**固定值**
  （set_reading/set_seconds）或**遞增序列**（set_sequence/push_reading，模擬時間推進）——
  序列非空優先、列盡回最後一份；預設無讀值。
- **提供者** `UptimeProvider`：uptime 實例 `uptime` 恆存在（保留歷史環）+ 可選 `boot.time`
  實例（來源給開機時間戳時動態新增，靜態無歷史）；`sample()` 更新（uptime 推歷史、開機
  時間戳只設值，消失則設未知）；`sampling_tier()`（預設 Low）供 add_demand；`has_boot_time()`。
- **絕不接真實時間 API**（無 sysctl kern.boottime / /proc/uptime / GetTickCount / mach /
  #ifdef / win32 / cocoa）；無讀值以 valid==false 誠實表達、不謊報 0；消費者只走 E2-01
  抽象介面。
