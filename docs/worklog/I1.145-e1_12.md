## 我要做什麼（動工前計畫）

先讀懂 E1-11 `SubordinateLayout`（`src/kernel/e1_11/subordinate_layout.hpp`）的父子附著模型：
以具名 `SurfaceId` 為鍵配對 `{child, parent, AnchorSpec}`，`attach`/`detach`/`reposition`/
`close_parent`/`resolve_child` 已完整處理「單一父 → 單一子」的相對定位、就地更新、循環偵測、
父關閉子連帶。E1-12 要在其上處理「一個父同時掛多個子」的**管理層**：

- `MultiSubordinateManager`：以組合方式持有一個 `SubordinateLayout` 實例作為唯一真實來源，
  不重寫附著記錄或佈局計算。
- `attach_child(parent, child, spec, child_element)`：委由 E1-11 `attach`，成功後額外記錄
  該 child 的元件尺寸（E1-11 `resolve_child` 每次呼叫都需呼叫端傳入元件尺寸，不快取；本單元
  為了讓 `reposition_all` 只憑一個新父矩形就能批次重解析全部子，得自己記住每子的元件尺寸）。
- `children_of(parent)`：列舉 parent 目前所有直接子，依附著順序回傳（具名 vector，不用數字
  index）。
- `reposition_all(parent, new_placement)`：對 `children_of(parent)` 的每個子呼叫底層
  `resolve_child`，回傳 `{child, ResolvedPlacement}` 的批次結果——「父移動時全部跟隨」的
  便利入口。
- `detach_child(child)` / `detach_all(parent)`：分別委由 E1-11 `detach` / `close_parent`，
  成功後同步清除（或重新掃描清除）對應的元件尺寸記錄，不留孤兒資料。

18 個測試涵蓋：多子並存（同一 parent 下多個 child 各自附著、各自以 E1-11 定位互不覆寫）；
`children_of`（依附著順序列舉、未知 / 無子 parent 回空）；`reposition_all`（父移動時批次重解析
所有子、每子整體平移相同量、無子 parent 回空）；`detach_child`（個別關閉不影響其餘子、元件尺寸
記錄同步清除、未知 child 結構化回報）；`detach_all`（全部關閉 parent 底下所有直接子、遞迴清除
巢狀從屬鏈 + 自身且不影響無關附著、元件尺寸記錄同步清除、無附著回 0）；多父多子（不同 parent
各自管理各自的子，互不干擾）；無效附著（空 id、自附、循環、無效 anchor spec、非有限 / 負值元件
尺寸 → Invalid 不記錄；同 child 再次附著視為就地更新）。
