## 我要做什麼（動工前計畫）

以**父子附著 + E1-07 具名 anchor 相對定位**表達從屬（子）surface 相對父 surface 的定位
（NFR-02：無絕對座標）：

- `SubordinateLayout`：以具名 `SurfaceId` 為鍵配對 `{child, parent, AnchorSpec}` 附著記錄
  （風格對齊 E1-07 `AnchorLayout`）。
- `attach(child, parent, spec)`：建立 / 就地更新附著；child/parent 空、自附、循環附著
  （`would_cycle`：沿候選 parent 既有附著鏈往上追溯是否繞回 child）→ Invalid 不記錄。
- `resolve_child(child, parent_placement, child_element, out)`：把父的**已解析矩形**當 E1-07
  `resolve()` 的 container，在局部座標系解出子位置後平移 `(+parent.x, +parent.y)`——不快取絕對
  座標，父矩形變了重新呼叫即得新位置（父移動子跟隨的實作方式）。
- `close_parent(id)`：遞迴（廣度優先）清除 id 自身 + 其下所有直接 / 間接子附著（父關閉子連帶，
  支援任意深度巢狀從屬鏈，如 dropdown → submenu → subsubmenu）。
- `detach(child)`：僅移除單一附著；`reposition(child, spec)`：只換定位規格、parent 不變。

不重新發明佈局數學：定位規格直接複用 E1-07 `AnchorSpec`，`resolve_child` 完全委由 E1-07
`resolve()` 做實際計算，本單元只負責「父子關係管理」與「container = 父矩形」這層轉譯。

21 個測試涵蓋：附著子到父 + anchor（記錄 / 就地更新 / 空 id / 無效 spec 拒絕）；`resolve_child`
依父已解析矩形正確計算並平移（含 offset 超出父邊界的下拉選單式定位）、未知 child / 非有限父矩形
或子尺寸 → Invalid 不寫 out；父移動子跟隨（同附著在不同父矩形下重新解析得到不同絕對位置，含
尺寸改變的比例重算）；`detach`（移除單一附著不影響其餘、未知 child 結構化回報）；`reposition`
（更新 spec 保留 parent、未知 child / 無效 spec 拒絕且不變更既有記錄）；`close_parent`（直接子
連帶、巢狀多層子孫連帶 + 自身、無關附著不受影響、id 無附著回 0）；自附拒絕、二節點循環拒絕、

detach 不影響其他）；NFR-02 具名 + 相對表達（同附著套不同父矩形，相對比例一致）。
