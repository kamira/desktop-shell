## 我要做什麼（動工前計畫）

把「儲存容量」（每磁碟 總/已用/可用 bytes + 使用率%）透過 **E2-01 的 MetricProvider** 掛成指標、以
**E2-02 的頻率分級**採樣。消費 E2-01/E2-02 契約，不自造模型。以 e2_03（CPU 負載）為最近範式——
但儲存無差分（純快照）。相位 1 絕不接真實磁碟 API，改為可注入 `StorageStatSource` 抽象 + null 來源。

## 設計決策要點

- **四個平行指標而非一個**：E2-01 的 `MetricValue` 只帶一個數值維度，而每磁碟要表達四個量
  （total/used/free bytes + usage%）。故掛上四個指標 `storage.usage` / `storage.capacity.{total,used,
  free}`，四者共用同一組每磁碟實例（同 instance_id/label），讓掛件能對「同一顆磁碟」讀齊四欄。這仍
  完全在 E2-01 六要素內（每指標是名稱/值/單位/範圍/歷史/實例），不新增模型。
- **磁碟 = 可列舉實例**：借用 E2-01「可列舉實例」要素，每顆磁碟一個 `MetricInstance`（instance_id=
  掛載點/裝置、label=磁碟名）；「多磁碟」＝多實例、磁碟數＝`instance_count()`。與 e2_03 每核心實例同構。
- **使用率獨立自由函式**：`disk_usage_ratio(used,total)` 純算術、獨立可測，邊界（total==0→0、
  used>total→夾 1.0）與 e2_03 的 `core_usage_ratio` 同精神（不謊報、保守夾界）。
- **預設分級 Low**：容量變動慢；E2-02 文件本身即以「磁碟容量」為 Low 分級範例，故預設 `SamplingTier::
  Low`（建構子可覆寫）。
- **磁碟以索引對齊**：`sample()` 以列舉順序（索引）對齊既有實例；磁碟數增則四槽同步動態新增（unique_ptr
  持有，既有參照不失效），減則多出者四槽設未知（不縮減、誠實表達卸載）。與 e2_03 核心數變動處理一致。
- **無讀值誠實**：磁碟 `valid==false` / source 為 null → 未知（valid==false），不塞 0。
