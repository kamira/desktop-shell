## 我要做什麼（動工前計畫）

engine 層純邏輯：不綁真實時鐘，時間以邏輯 tick 由呼叫端注入（`advance(dt)` / `tick()`）。
沿用 E5-04 心跳的 `ds::events::Tick` 型別使 events 模組時間語意一致（PUBLIC 連 `e5_04`）。

設計（C++17，`namespace ds::events`）：

- `TimerId`（單調遞增、不重用；0 = 無效）、`TimerEvent`（id / now / count / repeating）、`TimerCallback`。
- `TimeoutTimer`：
  - `set_timeout(delay, cb)` 一次性 —— 到期觸發一次後**自動移除**。
  - `set_interval(interval, cb)` 重複 —— 每週期觸發直到 `cancel`。
  - `cancel(id)` 取消；`remaining(id)` 查剩餘（`std::optional<Tick>`）；`is_active` / `now` / `active_count`。
  - `advance(dt)` 倒數驅動，回傳本次總觸發次數；`tick()` = `advance(1)`。

關鍵設計：
- **倒數餘量模型**：每計時器持 `remaining`（距下次觸發尚需 tick）。advance 消化 dt，
  跨過即觸發並（重複者）重置為 interval 續消化 —— 餘量保留、**不漂移**。
- **一次性 vs 重複**：一次性 interval=0、觸發後入 `expired` 清單、本輪結束前移除，餘量丟棄。
- **兩階段派發**（沿用 E5-04 心跳作法）：先結算狀態 + 移除到期一次性者，**再統一觸發回呼**。
  故於回呼中 set / cancel 皆安全，不使 `timers_` 失效。移除先於回呼，使回呼中 `is_active` 已反映。
