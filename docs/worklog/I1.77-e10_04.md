## 我要做什麼（動工前）

E10-04 定義一個**事件廣播協定**，讓載入的模組（E8-04）之間以發布-訂閱互通：模組宣告
它發布 / 訂閱哪些主題（topic），協定層把某主題上的事件廣播給所有訂閱該主題的模組。
相位 1 為純記憶體事件匯流排，不綁真實網路 / IPC；實際的主題路由 / 扇出委派 E10-01 通道。

## 關鍵設計決策

- **委派 E10-01 做扇出**：`EventBroadcast` 內部持一份 `MessageChannel`，主題 = 通道訊息型別；
  主題路由 / 依註冊序投遞 / 計數全重用已合併契約。E10-04 的增值是「模組維度」。
- **模組維度**：每筆訂閱歸屬 `ModuleId`（對接 E8-04 manifest.name），以 `module → [subscriber id]`
  追蹤，使 `unsubscribe_module` 能在模組卸載時精準註銷其全部訂閱。
- **事件酬載重用 E6-01 `CommandArgs`**（經 E10-01 傳遞），跨模組邊界不變形；`Event` 另帶選填
  `source` 供訂閱者診斷 / 過濾。
- **主題宣告**：`declare_publish/subscribe` 純內省登記（不影響投遞），對應「模組宣告它 publish/
  subscribe 哪些主題」；`unsubscribe_module` 一併清除宣告。
- **巢狀發布安全**：交付 Event 以「當前事件」指標搭配存 / 還原傳遞，處理器內再 publish 不破壞外層。
- **邊界保守**：空 module/topic/handler 拒絕回 0；無訂閱者發布回 0 不崩潰；退訂錯誤模組 / 未知 id 回 false。
