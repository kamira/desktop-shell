## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端 + 契約測試**，**不真的抓螢幕**，
**不得**出現 `#ifdef` / win32 / cocoa / 真實螢幕擷取。**消費 E2-01 + E2-02 契約、不自造指標
模型、不自造時鐘**。核心 API **不用絕對座標**（NFR-02）——取樣點以具名 anchor 表達。

設計（C++17，`namespace ds::sysinfo`）：

- `PixelColor` struct：平台中立 8-bit RGBA；`luminance()`（Rec. 601 相對亮度，正規化
  [0,1]，供環境光）、`hex()`（"#RRGGBB"，供取色）。
- `ScreenAnchor` 列舉：九宮格**具名取樣位置**（center / top-left / …），**無絕對座標**。
  `to_string`（穩定字串，用作 instance_id）、`to_label`（人類可讀）。
- `PixelSampleSource` 抽象後端：`sample(anchor) → optional<PixelColor>`。相位 2+ 由真實
  平台後端實作；提供者只依賴此抽象介面（換後端不動提供者）。
- `NullPixelSampleSource` null 後端：**不抓螢幕**，預設回無讀值；`set_pixel`/`clear`/
  `clear_all` 注入假像素供測試。
- `ScreenPixelProvider : public ds::metrics::MetricProvider`：`register_metrics()` 向 E2-01
  註冊表掛上單一指標 `"screen.pixel"`，每個具名取樣 anchor 建成一個實例。

## 指標形狀的關鍵設計（為何每個 anchor = 一個實例、值為何）

E2-01 六要素含「可列舉實例」。本單元的多個具名取樣點天然對應此要素：
- 指標身分：id=`screen.pixel`、name=`Screen Pixel Color`、unit=``、range=`bounded(0,1)`
  （值為相對亮度正規化，長條 / 環境光類元件可直接畫成比例）。
- **每個具名取樣 anchor 建成一個 `MetricInstance`**（instance_id=anchor 字串、label=人類可讀、
  value=相對亮度(number,[0,1]) + 十六進位色碼文字（供取色）、history=近期亮度環，供環境光
  趨勢 / sparkline）。無讀值的 anchor 實例值為未知、不推歷史。
- 消費者（掛件）只透過 E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，
  **完全不觸及 sysinfo 型別**——新增此指標，掛件一行不用改。

## 消費 E2-02（採集頻率）

- `sampling_tier()`：本指標的採集分級（`SamplingTier`，預設 `Low`——像素 / 環境光變動不快，
  避免高頻採集吃資源，直接關係 NFR-01 idle 門檻）；可於建構時指定其他分級。
- `register_demand(SamplingScheduler&)`：把本指標的採集需求掛進 E2-02 排程器。多個消費者對
  同一指標的需求由排程器**除頻合併**（有效分級 = 最高頻者），一次採集供所有消費者。

## NFR-02（無絕對座標）

取樣位置以 `ScreenAnchor` 具名列舉表達，核心 API **不含任何 x/y 像素座標或數字 z-order**。
具名 anchor 對應的實際像素落點，留待真實後端相位依當時螢幕幾何解析（本層不碰）。
