## 我要做什麼（動工前）

E1-25 是「所有 kernel 後端都必須通過的契約測試組」：對 kernel 後端抽象介面撰寫平台中立
的行為契約，任一後端（null / 未來 win32 / cocoa）套同一批斷言驗證其符合契約。

先讀懂上游與現況：
- 上游 E1-21（`src/kernel/e1_21/`）：`CapabilityMatrix` / `has()` —— 能力查詢契約的資料來源。
- 以 grep/find 在 `src/kernel/` 搜尋 kernel 後端抽象介面：現有僅 e1_17 / e1_18 / e1_19 / e1_21
  四個平台中立介面單元，**無**任何「kernel 後端抽象介面」的現成 header；E1-24（null 後端，
  `src/kernel/backend/null/`）尚未合併。故 kernel 後端介面在相位 1 為**純抽象、無現成實作**。

依單元規格與 write_scope（僅 `tests/contract/**` + 三份 docs），決定：
- 抽象介面 `KernelBackend` 由契約組自帶於 `tests/contract/kernel_backend.hpp`（規格明示
  「介面純抽象且無現成實作時，stub 由本測試檔提供」）。
- 自帶測試本地 `StubBackend`，**不 link E1-24**，維持與 E1-24 的單元獨立（units.json 中兩者
  只相依 E1-21、不互相依）。

計畫產出（全部落在 write_scope 內）：
1. `tests/contract/kernel_backend.hpp` — 抽象介面 `KernelBackend` + `Status` / `SurfaceProfile`
   / `SurfaceHandle`；引用上游 E1-21 `CapabilityMatrix`。
2. `tests/contract/stub_backend.hpp` — 測試本地最小 `StubBackend`（純記憶體、無系統呼叫）。
3. `tests/contract/test_contract_backend.cpp` — gtest 契約組（parameterized 對任一後端跑同一
   批斷言 + stub sanity）。
4. `tests/contract/CMakeLists.txt` — `test_contract_backend` executable（link `e1_21` +
   `GTest::gtest_main`）+ `add_test(NAME contract_backend)`。
5. `docs/changes/CHG-20260724-e1_25.md`、本 worklog、`docs/structure/units/e1_25.md`。

## CMakeLists 路徑處理

本單元特殊：CMakeLists 與測試 .cpp/.hpp **同在** `tests/contract/`（與其他單元「測試在
tests/<m>/、CMakeLists 在單元目錄」不同）。故 `add_executable` 以相對本目錄的檔名
`test_contract_backend.cpp` 指向即可，並 `target_include_directories(... CMAKE_CURRENT_SOURCE_DIR)`
讓同目錄 header 可被 include。根 CMakeLists 既有 GLOB（CHG-20260723-22）已收
`tests/contract/CMakeLists.txt` 與 `tests/contract/*/CMakeLists.txt`，故本檔放此位置即被建置
收入，**未動根 CMakeLists**。

## 契約涵蓋

- 能力查詢契約：`has(id)` 與 `capabilities().has(id)` 一致；未宣告能力保守回 false（NFR-03）。
- 生命週期契約：init 前 not ready → init 後 ready → shutdown 後 not ready；init/shutdown 冪等；
  shutdown 釋放所有 surface。
- surface 前後條件：未初始化建立回 Invalid 且輸出無效 handle；成功回有效 handle 且 alive；
  銷毀後 not alive；重複銷毀 / 無效輸入回 Invalid（不崩潰）。
- 錯誤處理契約：對不可用（含未宣告）能力操作回 Unsupported、不改狀態。
- 以 stub 後端驗證契約可套用；parameterized 展示「同一批斷言可套多後端」（未來各後端加
  一 factory 即納入）。

## 相位 1 約束遵循

- 只寫契約測試 + 測試本地 stub，不寫真實平台後端、不建 `src/kernel/backend/win32|cocoa/`。
- 契約與 stub 平台中立、無平台分支；surface 以具名角色表達，無絕對座標 / 數字 z-order。

## 本機驗證方式

本機以 `g++ -std=c++17 -Wall -Wextra` 搭配 scratchpad gtest 墊片（含 TEST / TEST_P /
TestWithParam / INSTANTIATE_TEST_SUITE_P / Values 與單次求值的 EXPECT_/ASSERT_ 巨集，不進
repo），單一命令、全絕對路徑編譯**未經改動的** `tests/contract/test_contract_backend.cpp` +
上游 `src/kernel/e1_21/capability_matrix.cpp`。結果：零警告、9/9 案例全綠。正式 CTest 於 CI
以真 GoogleTest 執行。
