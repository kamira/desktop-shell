## 設計決策

- **情境即預設值表**：`DimProfileKind` 三態各配一組 `DimPreset{ intensity, color }`
  （`default_preset()` 單一資料來源）——Focus 中度調光純黑、NightShift 低度調光暖色調
  （降低藍光觀感）、PopupBackdrop 較深調光純黑（清楚區隔彈窗與背景）。
- **行為收斂三動詞**：`activate(intensity)` 套用情境預設顏色並淡入至目標強度（或
  `activate()` 無參版本用情境預設強度）；`deactivate()` 委派 `fade_to(0)`；`fade(target)`
  直接透傳 `fade_to`、不重申情境顏色（供呼叫端自訂漸變終點）。
- **狀態不重造**：`DimProfileState` 直接映射底層 `DimOverlayElement::visible()`，profile
  本身不維護獨立的影子狀態，避免兩份狀態失步。
- **挖洞 / 頂層 / 能力閘控全數透傳**：`add_cutout` / `remove_cutout` / `has_cutout` /
  `layer()` / `alpha_supported()` / `render_model()` 直接呼叫底層 E4-30 對應方法，不重新
  實作已驗證過的邏輯（純組裝，符合相位 1 定位）。
- **無效參數委派 E4-30 既有語意**：非有限強度 / 目標 → `Invalid`；空挖洞名 → `Invalid`；
  能力不可用 → `Unsupported`，皆不改狀態、不靜默。

## 已知限制

- 相位 1 為宣告式淡變（直接抵達目標強度），真實逐格動畫由後續相位承接（同 E4-30 既有
  限制，本單元組裝未新增額外限制）。
- 若多個 `DimOverlayProfile` 實例共用同一 `SurfaceId`（未各自指定不同 id），會競爭同一底層
  alpha surface；呼叫端應為每個同時可能啟用的情境指定不同 `surface_id`（如本單元測試中
  `"surface.dim.focus"` / `"surface.dim.night"` / `"surface.dim.popup"`）。
