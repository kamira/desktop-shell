## 我做了什麼

一個 sysinfo 指標提供者，把音訊峰值 / RMS / 頻譜透過 E2-01 `MetricProvider` 掛成三個指標，
並以 E2-02 頻率分級（預設 High）決定採樣。設計刻意分離、易組合（本單元是最終音訊等化器 /
電平表 Widget 的核心資料來源）：

- **值模型**：`AudioLevelSample`（peak + rms 線性 [0,1]、bands 各頻段能量 [0,1]、valid）。
- **電平計算**（自由函式，獨立可測）：`peak_of`（max|x|）、`rms_of`（均方根）、`linear_to_db`
  （線性→dB，含靜音下限 floor 避免 -∞）。皆平台中立純算術。
- **注入式來源**：抽象 `AudioLevelSource` + `NullAudioLevelSource`（持注入序列，列盡回最後、
  空列回無讀值；`set_pcm(pcm, bands)` 由 PCM 如正弦樣本算 peak / rms + 注入頻段）。
- **提供者** `AudioLevelProvider`：掛上 `audio.peak`（單一實例 peak）、`audio.rms`（單一實例
  rms）、`audio.spectrum`（每頻段可列舉實例 band0…），三者 range=`bounded[0,1]`、各保留歷史環；
  peak / rms 附 dB 文字表述；`sample()` 更新（頻段數增則動態新增實例、減則設未知）；
  `sampling_tier()` 供 add_demand。
- **絕不接真實音訊 API**（無 CoreAudio / AudioUnit / WASAPI / `#ifdef` / win32 / cocoa）；
  無讀值以 valid==false 誠實表達（與「靜音有讀值 peak=0」明確區分），不謊報 0；消費者只走
  E2-01 抽象介面。頻譜 FFT 留待相位 2+（相位 1 直接注入頻段能量）。
