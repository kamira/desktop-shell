## 組裝設計

`ds::widgets::WeatherWidget`（`content/widgets/c2_04/weather_widget.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`KernelBackend&` + `LayerStack&`（透傳給內部自持的 C1-01
  `SkinProfile base_`）、`shared_ptr<HttpTransport>`（可為 nullptr，`refresh()` 保守回
  `FetchFailed`）、端點基底 URL（`std::string`，值持有）、`const FontMetrics&`（E4-01 排版用，
  須存活於本物件之外）。內部自持一個 E4-01 `TextLayout`（建構時綁定注入 metrics 與
  `"<id>.text"` 目標 surface）。
- **設定（`configure(Value)`）**：解讀 `location`（必填非空字串）/ `unit`（選填，"celsius"
  預設 / "fahrenheit"）。非 Map / 缺 location / 空 location / 非法 unit 具名值 → `Invalid`，
  不套用（沿用 C1-01 `load_skin` 的「驗證通過才提交」精神，但本單元設定較單純，直接以區域
  變數驗證後一次寫入，等價全有或全無）。
- **刷新（`refresh()`）**：`request_url()` 以 E7-10 `strings::concat()` 組
  `endpoint_url + "?location=" + location`；未 configure → `Invalid`（不發請求）；對
  `transport_->get(url)`：`transport_` 為 nullptr 或回應非 2xx → `FetchFailed`；body 經
  `ds::sysinfo::parse_json` 失敗 → `ParseFailed`；`apply_json()` 以 `seek()` 取
  `temp_c`（須為 Number）/ `description`（須為 String，必填）/ `icon`（選填，缺失或 null
  視為無圖示，存在但非字串 → `ParseFailed`）——**任一失敗皆保留既有已知資料**（不清空
  `has_data_` / `temp_celsius_` 等），供擷取 / 解析失敗時的降級顯示（沿用上一輪成功值）。
- **顯示（`display()`）**：尚無資料（`has_data_==false`）→ `Invalid`。成功則依
  `config_.unit` 換算（攝氏 ↔ 華氏，`x*9/5+32`）、`std::lround` 四捨五入為整數字串（標準
  函式庫轉換，非重造 E7-10 職責）、以 `strings::format("{0}°{1} {2}", [temp, unit, desc])`
  組可讀文字，寫入 `model_.formatted_text`；以 `layout_.layout(text, {})` 排版寫入
  `model_.text`；以區域 `ImageElement` + `MemoryImageSource("icon/" + icon_code_,
  {kIconSize, kIconSize})` 組裝圖示（icon 代碼為空則不呼叫 `set_source`，維持
  `has_source=false`），寫入 `model_.icon`。
- **具名結果**：`WeatherStatus`（Ok / Invalid / FetchFailed / ParseFailed）、
  `TemperatureUnit`（Celsius / Fahrenheit），各附 `to_string()`（NFR-02）。

無效操作一律明確回具名結果，不靜默；擷取 / 解析失敗走降級路徑（保留既有資料而非清空），
與 E2-14 `HttpFetchProvider::sample()` 的「失敗時 value 設為 unknown、不污染歷史」同精神但
本單元反向選擇「保留舊值」——因天氣 widget 語意上顯示「最後已知讀值」優於顯示「無資料」，
此差異已於 CHG / 標頭註解說明,不與 E2-14 契約衝突（E2-14 只規範其自身 `Metric.value`
語意，不約束下游消費者如何處理擷取失敗）。
