## 我要做什麼（動工前）

E1-17 是「DPI 感知與混合 DPI」：多螢幕環境下各螢幕的邏輯縮放（scale factor）可能不同，
提供一組**平台中立介面**，讓縮放一律以「每螢幕的縮放係數」與「具名螢幕」表達，成為
DPI 感知與混合 DPI 處理的單一資料來源。

計畫產出（全部落在鎖定範圍內）：

1. `src/kernel/e1_17/dpi_awareness.hpp`
   - `ScreenId`：具名螢幕識別碼（typedef，非 index / 座標 —— NFR-02）。
   - `kDefaultScaleFactor`（1.0）：null 期與未知螢幕的中性預設。
   - `ScreenDpi`：單螢幕宣告 { id, description, scale_factor }。
   - `DpiInfo`：從內嵌預設或外部宣告建構，提供 `scale_of()` / `relative_scale()` /
     `is_mixed_dpi()` / `is_known()` / `find()` / `screens()` / `size()`。
   - 平台中立：無 `#ifdef _WIN32` / `win32` / `cocoa`，無 `setPosition(x,y)` 式絕對座標 API。
2. `src/kernel/e1_17/dpi_awareness.cpp`
   - 內嵌預設拓撲（單一具名主螢幕，縮放 1.0）。
   - 查詢邏輯：未知螢幕保守回 `kDefaultScaleFactor`；非正縮放正規化；相對縮放為純比值。
3. `src/kernel/e1_17/CMakeLists.txt`：依 BUILD.md 樣板，library target + `test_e1_17`
   executable + `add_test`。
4. `tests/e1/test_e1_17.cpp`：gtest，驗單螢幕 scale、混合 DPI 各螢幕不同 scale、未知螢幕
   保守回傳等。
5. `docs/changes/CHG-20260724-e1_17.md`、本 worklog。
6. `docs/structure/directory.md`：因動到 `src/`，依 G4 同步（COMMON 允許路徑）。

## 相位 1 約束遵循

- 只寫介面 + null（宣告式預設）行為，不寫任何真實平台後端。
- null 後端 `scale_of()` 回宣告的 `default`（1.0）；真實後端上線後由後端覆寫實際 per-monitor 探測。
- 無平台分支、無 `src/kernel/backend/win32|cocoa/`。

## NFR-02 遵循（不得絕對座標與數字 z-order）

- 螢幕一律以具名 `ScreenId` 指涉，不用 index / 位置 / (x,y)。
- 縮放一律以無單位 `scale_factor` 比值表達，不用像素尺寸。
- 無 `setPosition(x,y)` 式 API；跨螢幕搬移僅由 `relative_scale()` 的比值描述。
