## 2. 我自己踩到的錯（記下來，免得下一個人重踩）

### V-E1 — 我的突變計分程式把「程式崩潰」算成「突變存活」

- **錯誤**：第一輪 M4 報 **SURVIVED**。
- **根因**：我的計分只掃 gtest 的 `[  FAILED  ]` 行。那條突變讓 `migrations` 為 null 時
  仍走 `migrations->migrate()`，測試程序當場 SIGSEGV，**stdout 一行 `FAILED` 都沒有**，
  於是「沒有殺手」被我讀成「突變存活」。**崩潰是最強的殺死，不是存活。**
- **解法**：計分改為「非零退出碼且無 `FAILED` 行」亦計為 KILLED 並標明是崩潰；
  同時把 M4 的突變改寫成與 CHG 描述真正等價的那一個
  （`needs_migration && migrations != nullptr`，即「結構看起來一樣就收下」），
  重跑 → KILLED。**教訓：驗收者的量尺自己也要被驗。**

### V-E2 — 我的 probe 犯了 K-013 同族的錯，差點誤報成實作的 bug

- **錯誤**：`printf("... %s %s", E::to_string(s.save(...)), s.last_message().c_str())`
  印出亂碼 `��b`，我一度以為是 `last_message_` 的生命週期 bug。
- **根因**：**C++ 函式引數的求值順序未指定**。`s.last_message().c_str()` 可能先求值，
  拿到當時那個空字串的指標；接著 `s.save()` 改寫 `last_message_`、字串重新配置，
  那個指標當場懸空。K-013 記的是「const 參考綁臨時物件」，這是同族第四種形狀：
  **同一個 full-expression 裡先取指標、再呼叫會改到它的函式**。
- **解法**：拆成有順序的敘述（先 `const auto r = call();` 再讀 `last_message()`）。
  重跑後訊息正常（`往返自驗不通過（Ok）：`）。實作沒有這個 bug，是我的 probe 有。
