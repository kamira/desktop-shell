## 我要做什麼（動工前）

E1-21 是「能力矩陣宣告檔」：一份**宣告式**能力矩陣，宣告「哪些能力可能在某些
平台不存在」。它是後續 `has()` 能力閘控（NFR-03）與降級路徑的**單一資料來源**。

計畫產出（全部落在鎖定範圍內）：

1. `src/kernel/e1_21/capability_matrix.hpp`
   - `CapabilityId`：穩定字串識別碼（typedef）。
   - `CapabilityDecl`：單一能力宣告 { id, description, optional（是否可能在某些平台不
     存在）, default_available（尚無真實後端探測前的預設可用性）}。
   - `CapabilityMatrix`：從內嵌預設或外部宣告建構，提供 `has()` / `is_optional()` /
     `is_declared()` / `find()` / `all()` / `size()` 查詢介面。
   - 平台中立：不含任何 `#ifdef _WIN32` / `win32` / `cocoa` 分支，不綁任何真實後端。
2. `src/kernel/e1_21/capability_matrix.cpp`
   - 內嵌預設能力矩陣（`CapabilityMatrix::defaults()`）。
   - 查詢邏輯：未知能力一律回 `false`（保守：未知即不可用），符合 NFR-03 閘控語意。
3. `src/kernel/e1_21/CMakeLists.txt`：依 BUILD.md 樣板，library target + `test_e1_21`
   executable + `add_test`。
4. `tests/e1/test_e1_21.cpp`：gtest，驗載入、查詢、optional 標記、未知能力保守回 false、
   自訂宣告建構。
5. `docs/changes/CHG-20260724-e1_21.md`、本 worklog。
6. `docs/structure/directory.md`：因動到 `src/`，依 G4 同步（COMMON 允許路徑）。

## 相位 1 約束遵循

- 只寫介面 + null（宣告式預設）行為，不寫任何真實平台後端。
- `has()` 在相位 1 回傳宣告的 `default_available`；真實後端上線後由後端覆寫實際探測值。
- 無平台分支、無 `src/kernel/backend/win32|cocoa/`。
