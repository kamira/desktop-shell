## 我要做什麼（動工前計畫）

把宣告式格式值裡的**公式 / 運算式字串**解析並求值為一個 `Value`。消費 E7-02 的
`VariableScope` 做變數查找、E7-01 的 `Value` 做型別 / 數值模型，不重造輪子。語法 /
除零 / 未定義變數 / 型別誤用要明確回報（NFR-04 精神，帶位置、不靜默）。

設計（C++17，`namespace ds::format`）：

- Tokenizer（帶位置）→ 遞迴下降解析 + 樹走求值。文法優先序：
  `||` < `&&` < `== !=` < 比較 < `+ -` < `* / %` < 一元 < 括號 / 字面 / 變數。
- 數值字面量（整數 / 浮點 / 指數）、四則 + 取模 + 括號、一元 `+ - !`、比較、布林邏輯、
  變數引用（`VariableScope::find`，含父鏈）。整數運算保留整數、含浮點轉浮點；`/` 整除得整數。
- 錯誤模型對齊 E7-01 `ParseResult`：`EvalError{position, message}` + `EvalResult`（Value / 錯誤）。
  遞迴內部以受控例外 `EvalException` 承載、於 `evaluate()` 邊界捕捉轉 failure。
- `is_formula` / `formula_body` 辨識並去除 `=` 或 `${ }` 公式標記，讓引擎可直接吃格式字串值。
- CMake：`target_link_libraries(e7_05 PUBLIC e7_02)`。

參考已合併的 `engine/format/e7_01/`（`Value` 工廠 / 存取、`ParseResult` 二選一結果風格、
「不靜默失敗、錯誤帶定位」契約）與 `engine/format/e7_02/`（`VariableScope`、受控例外邊界手法），
推廣為公式層的 `EvalResult` / `EvalError`。
