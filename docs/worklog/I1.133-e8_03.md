## 我要做什麼（動工前計畫）

先讀了 `docs/backlog/BUILD.md`（建置慣例）與三個上游（已合併，可讀不可改）：

opcode 僅限 `set`/`say`/`if`/`goto`/`label`，未知 opcode 執行期報錯）、
`engine/render/e4_06/surface_switcher.hpp`（`SurfaceSwitcher`：具名 surface 定址簿 +
切換器，`ds::kernel::SurfaceId` 沿 `e4_02 -> e1_03 -> backend/null` 傳遞）、
`engine/command/e6_01/command_bus.hpp`（`CommandBus`：具名命令 id + `CommandArgs` /
`CommandResult`，未知命令回 `NotFound` 不崩潰）。

關鍵設計決策：**E8-02 opcode 不可擴充**（已合併不可改，也不該讓通用直譯器認識具體表現
語意），所以整合點選在它既有的擴充位置——`OutputSink`。作法：

- `PresentationController`：建構時把 `show`/`hide`/`switch_surface`/`transition`/`wait`
  五個具名命令（`ds::script.` 前綴）註冊到注入的 `CommandBus`；`switch_surface` 委派
  `SurfaceSwitcher::switch_to`，其餘四個是 phase 1 的純記憶體描述（visibility map /
  transition 紀錄 / wait 紀錄），不做真實繪製。
- `PresentationSink : OutputSink`：`emit(text)` 把一行文字（由 E8-02 的 `say` 步驟產生）
  token 化，依首 token 對應到上述五個命令 id 之一並組出具名參數分派；未知首 token 就組
  一個必然未註冊的 id 丟給 bus——直接沿用 `CommandBus` 既有的「未知命令 → NotFound」
  契約，不用另外寫「未知指令」特判邏輯。每次分派結果（含失敗）都存進
  `results()`，不吞任何錯誤。

參數驗證（不套用、不部分套用，回 `Failed`）：show/hide/switch_surface 要求非空
`target`；transition 要求非空 `kind`/`from`/`to` + 有限且 `>=0` 的 `duration`；wait
要求有限且 `>=0` 的 `seconds`。數值型參數同時接受 `Int`/`Double`（`numeric_arg` 輔助
函式），文字解析時若 token 無法整段解析為 `double` 就原樣以字串帶入，讓處理器的型別
檢查自然判 `Invalid`（不必在解析層特判「格式錯誤」）。
