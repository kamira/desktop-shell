- **E1-02**（`src/kernel/e1_02/input_strategy.hpp`）：輸入策略四態
  （Interactive / Capture / ClickThrough / Inert），純函式 `hit_result` / `route_decision` /
  `to_backend_policy`（對映至 E1-24 三態 `InputPolicy`）。
- **E1-14**（`src/kernel/e1_14/transient_profile.hpp`）：短暫 profile 生命週期
  ——`TransientProfileManager`：`create(id, profile, ttl)` 建立、`advance(ticks)` 推進（逾時自動
  過期）、`expire(id)` 手動提早過期、`on_expire(cb)` 掛勾（`ExpiryReason::Timeout|Manual`）。
  已建於 E1-02 之上（`TransientProfile.input` 欄位）。
- **E5-05**（`src/events/e5_05/global_hotkey.hpp`）：全域熱鍵註冊——`GlobalHotkeys` 抽象介面
  （`has()` NFR-03 閘控 / `register_hotkey(Hotkey, cb)→HotkeyId` / `unregister(id)`），
  `NullGlobalHotkeys` null 後端以 `inject(hotkey)` 模擬 OS 按下（測試 / 相位 1 用）。這是本單元
  的**事件驅動**入口：召喚面板的「叫出」由此熱鍵事件觸發。
- **E7-13**（`engine/format/e7_13/item_tree.hpp`）：階層式項目結構——`Item`（id / label / value /
  children 遞迴）、`build_forest(Value)` 從宣告式 `Value`（E7-01）建構多根森林、`find(id)` /
  `for_each_preorder`。這是面板內選項清單的資料模型。

## 組裝設計

`ds::profiles::SummonPanelProfile`（`content/profiles/c1_05/summon_panel_profile.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`TransientProfileManager&`（E1-14）+ `GlobalHotkeys&`（E5-05）。
  建構時另帶 `InputStrategy`（E1-02，預設 `Capture`——一般 spotlight 行為）。
- **選項清單（E7-13）**：`set_items(Value)` 呼叫 `build_forest`，失敗（結構違反）回 false 且
  保留現有選項（不靜默覆寫壞資料），細節存 `last_build_error()`；`filter(query)` 以
  `for_each_preorder` 對整座森林（含巢狀）比對 id / label 子字串；`select(id)` 以每個根的
  `find(id)` 尋址。
- **生命週期（E1-14）**：`open(ttl)` = `create(id_, tp, ttl)`（`tp.input` 帶入策略、強制
  `Ephemeral`）；`close()` / `select()` 成功時 = `expire(id_)`。建構時向管理器 `on_expire()`
  登記一個以 `id_` 過濾的回呼（管理器可與其他短暫 profile 共用，不受干擾），逾時自動觸發
  `CloseReason::Timeout`；手動 `close()` 前置設定 `CloseReason::Manual`，`select()` 成功前置
  設定 `CloseReason::Selected`，供同一個過期回呼區分收起原因。
- **輸入策略（E1-02）**：策略欄位隨 `open()` 傳入 E1-14 `TransientProfile.input`；另提供
  `backend_input_policy()` / `hit_result()` 直接呼叫 E1-02 純函式，供驗證組裝正確（不需要真的
  接上 `KernelBackend` / `InputStrategyController`——相位 1「純資料 / 邏輯組裝，無真實 GUI」，
  接上真實後端屬更上層應用組裝的範疇）。
- **召喚熱鍵（E5-05，事件驅動）**：`bind_hotkey(hotkey, ttl)` 先 `hotkeys.has()` 閘控
  （NFR-03），再 `register_hotkey`，回呼捕捉 `this` 呼叫 `open(summon_ttl_)`——熱鍵觸發
  （真實後端）或 `inject()`（null 後端 / 測試）即自動叫出面板，無需呼叫端手動呼叫 `open()`。
- **解構安全**：`~SummonPanelProfile()` 若面板仍開啟則強制 `close()`。已知限制（記錄於標頭
  註解）：E1-14 `on_expire()` 沒有移除回呼的 API，故解構前主動收起是唯一能避免懸置回呼指向
  已銷毀物件的手段；呼叫端仍不應在本物件解構後、以相同 id 於同一管理器重建新實例。

無效操作一律明確回 false / 具名結果，不靜默：重複 `open()`、對已關閉面板 `filter()` /
`select()`、`select()` 不存在 id（回 `NotFound`，面板保持開啟）、能力不存在時 `bind_hotkey()`、
重複 `bind_hotkey()`（須先 `unbind_hotkey()`）、未綁定時 `unbind_hotkey()`。
