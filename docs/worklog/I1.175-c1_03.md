## 組裝設計

`ds::profiles::BalloonProfile`（`content/profiles/c1_03/balloon_profile.hpp/.cpp`）：

- 每個實例代表**一個**具名氣球，內部自持三份純記憶體 / 純邏輯服務（不需注入後端）：
  - 本氣球**專屬**的 E5-10 `TimeoutTimer` + 綁定其上的 E1-14 `TransientProfileManager`——
    刻意不與其他 `BalloonProfile` 共用計時器，天然支援「多氣球」同時顯示、互不干擾。
  - E1-11 `SubordinateLayout`——僅記錄本氣球自身一筆附著（不需跨多氣球共用）。
  - E4-11 `TypewriterElement`——綁定注入式 `FontMetrics&`（承 E4-01 慣例，不取得其所有權）。
- `show_balloon(character, text, ttl, spec)`：前置條件驗證（空 id / 空文字 / 已顯示中 / 角色
  未載入 / ttl 為 0）全數不改狀態即可拒絕；成功依序 E4-11 設文字 → E1-11 依附角色（任一步
  失敗回滾）→ E1-14 登記存活計時 → 提交 `Showing`。`spec` 預設把氣球錨定在角色頭頂上方
  （`TopCenter` + 向上偏移），可由呼叫端覆寫。
- `advance(dt)` / `dismiss()`：逾時與手動到期共用同一條收尾路徑 `teardown_display()`（解除
  依附、逐字進度歸零、狀態轉 `Hidden`），由建構時登記的 E1-14 `on_expire` 回呼觸發。
- `resolve(character_placement, balloon_size, out)`：純委派 E1-11 `resolve_child`——不持有
  角色的即時矩形，每次呼叫都由呼叫端傳入角色「當下」的已解析矩形，藉此不引入快取即達成
  「角色移動氣球跟隨」。

## 遇到的錯誤（既有上游命名碰撞，非本單元邏輯錯誤）

本機以 g++ 編譯首版（`balloon_profile.hpp` 同時直接 `#include "transient_profile.hpp"`
（E1-14）與 `"portrait_profile.hpp"`（C1-02，作為 `show_balloon` 參數型別）時，出現：

```
error: use of 'HitResult' with tag type that does not match previous declaration
  input_strategy.hpp:43: enum class HitResult { ... }
  hit_test.hpp:91: struct HitResult { ... }
```

診斷：E1-14 `transient_profile.hpp` 經 `#include "input_strategy.hpp"`（E1-02）於
`ds::kernel` 宣告 `enum class HitResult`；C1-02 `portrait_profile.hpp` 經 E5-14 → E5-01 →
`hit_test.hpp`（E1-04）於**同一** `ds::kernel` 命名空間宣告**另一個不同型別**的
`struct HitResult`。本單元是**第一個**需要同時組裝 E1-14 與 C1-02 的合併單元——兩者標頭
過去從未在同一翻譯單元同時出現過。以 `grep -rl` 搜尋既有已合併單元，發現
`content/profiles/c1_06/`（Dock profile）已記錄並解決過**完全相同**的碰撞（其為 E1-02 對
E1-16 `edge_hot_zone.hpp` 傳遞的 `hit_test.hpp`），採用「不透明橋接層（`dock_hot_zone_bridge.*`）
+ pimpl」把其中一條上游 include 樹隔離到獨立翻譯單元，讓兩個衝突標頭永不同時出現在同一
翻譯單元。本單元沿用相同手法：

- 新增 `content/profiles/c1_03/character_bridge.hpp/.cpp`：`character_bridge.cpp` 是本單元
  **唯一** `#include "portrait_profile.hpp"` 之處，暴露中立函式
  `detail::character_snapshot(character, out_id)`；標頭只前置宣告 `PortraitProfile`。
- `balloon_profile.hpp` 因此不直接 `#include "portrait_profile.hpp"`（只透過
  `character_bridge.hpp` 的前置宣告使用 `PortraitProfile` 作為 `show_balloon` 的參數型別）。
- E1-14 `TransientProfileManager` + 專屬 `TimeoutTimer` 的實際串接改以 pimpl
  （`BalloonProfile::Impl`，巢狀類別，依標準規則可存取外層 private 成員）隔離於
  `balloon_profile.cpp`（本單元唯一 `#include "transient_profile.hpp"` 之處），讓
  `balloon_profile.hpp` 也不需引入 E1-14 標頭——僅用 `ds::events::Tick`（經 E4-11 → E4-09 →
  E5-04 標頭鏈透傳）表達 tick 與存活倒數查詢。
- `CMakeLists.txt` 的 `add_library` 因此列出兩個 `.cpp`（`target_link_libraries` 仍照任務
  規定的 `PUBLIC e1_11 e1_14 e4_11 c1_02` 不變）。

修正後重新編譯，`ds::kernel::HitResult` 的兩個定義不再同時出現在任何翻譯單元，全數通過。

無其餘實作錯誤（邏輯 / 測試撰寫一次到位）。
