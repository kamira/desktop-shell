## 4. 阻擋項 F8 的可重現步驟

```cpp
// 1) 使用者的存檔是手寫的整數寫法（不需要 reset() 後門）
ds::layout::MemoryLayoutStorage storage;
storage.put("desktop",
    "format_version: 1.0\nelements:\n  -\n    id: cpu\n    type: bar\n"
    "    properties:\n      x: 1\n      y: 2.0\n      width: 3.0\n      height: 4.0\n");
EditAssembly app(storage);
app.restore("desktop");                       // => Ok
app.drag_element("cpu", 0.5, 0);              // => RejectedByModel（掛件拖不動）
                                              //    "validate_edit: 欄位 'x' 為 Integer，但給的是非整數 Number"

// 2) 使用者在編輯器裡把 x: 1 改成 x: 1.0 ——他要的就是「能拖」
storage.put("desktop", /* 同一份，x: 1 → x: 1.0 */);
// 手改後的檔案完好：ingest => status=Ok, carries_everything=1, lost_content=0

// 3) 第 4 道閘
app.overwrite_check("desktop");               // => Ok      ← 修訂 6 是 RefusedTargetChangedSinceLoad
app.target_is_safe_to_overwrite("desktop");    // => true
app.dry_run_save("desktop");                  // => Ok
app.save("desktop");                          // => Ok      ← 寫下去了
app.last_message();                           // => ""      ← 什麼都沒說
storage.has("desktop.rejected");              // => false   ← 沒有備份
// stats: saves=1 saves_rejected=0 rejected_backups=0 saves_refused_changed=0

// 4) 後果：檔案被改回 x: 1，重新載入後掛件又拖不動
```

錨點：同一支探針、同一份輸入，在 `a10037c`（修訂 6）上 `overwrite_check` /
`save` 皆 `RefusedTargetChangedSinceLoad`，檔案維持 `x: 1.0`，`drag_element(+0.5)` = `Ok`。
⇒ **F8 是修訂 7 引進的回歸。**

反方向也成立：使用者把 `cap: 10.0` 手改成 `cap: 10`（收緊成整數）→ 第 4 道閘 `Ok` →
`save` 改回 `cap: 10.0` → `edit_property("cpu","cap", 10.5)` 從 `RejectedByModel` 變 `Ok`。

被證偽的陳述（標頭與 CHG 共用同一句）：
> 兩份文件若只差在數值字面寫法與鍵序，本層帶得走的每一個欄位都一模一樣，
> 覆寫不會丟掉任何它帶得走的東西。

`integral_` 在 `state_` 裡（註解與縮排不在），而且 `write_property()` → E7-14 `apply_edit()` →
`editor_model.cpp:27` 的 `is_integer() ? EditKind::Integer : EditKind::Number` 會據它分支。

## 7. 一條我自己的錯，記下來免得下次再犯

第一次在 sanitizer 下跑 probe 6 時吃到 `heap-use-after-free`。追下去是**我的探針自己的 bug**：
同一個 `printf` 裡同時放了 `to_string(a.set_placement(...))` 與 `a.last_message().c_str()`，
參數求值順序未定，`c_str()` 的指標在 `set_placement()` 換掉那個 string 之後就懸空。
堆疊頂端是 `printf_common` / `p6_geom.cpp:21`，不是本層的程式碼。
改成「先取狀態、再把訊息複製成 `std::string`」之後 0 命中。
**不是 H1-09 的缺陷**；但 `last_message()` 回傳 `const std::string&` 而下一次呼叫就會換掉它，
這個生命週期標頭上沒有提醒（K-013 只講 `storage` / `ReloadSource`）。記著備查。
