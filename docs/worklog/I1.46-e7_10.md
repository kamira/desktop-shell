## 我要做什麼（動工前計畫）

提供一組字串處理函式（concat / length / substring / upper / lower / trim / replace /
split / join / contains / starts_with / ends_with / pad / format），輸入輸出以 E7-01
`Value` 表達、結果 / 錯誤沿用 E7-05 `EvalResult` / `EvalError`。型別誤用、索引越界要明確
回報（NFR-04，不靜默）。

設計（C++17，`namespace ds::format::strings`）：

- length / substring / pad 以 UTF-8 碼位為單位（Unicode 安全）；upper / lower 僅折疊 ASCII；
  trim 修外緣 ASCII 空白；contains / starts_with / ends_with / replace / split / join 位元組子字串比對。
- format：`{i}` 索引佔位 + `{{` / `}}` 轉義，可字串化 Number / Bool / Null（容器 → 錯誤）。
- 錯誤模型對齊 E7-05：內部受控例外 `StrException` 承載 `EvalError`，於各公開函式 `guard()` 邊界
  捕捉轉 failure。
- 額外導出函式表 `function_table()` / `find_function()`（名稱 → 變參 `StringFn`），供 E7-05 未來
  函式呼叫擴充 / 任一上層以名稱分派接入；表項內建元數檢查。
- CMake：`target_link_libraries(e7_10 PUBLIC e7_05)`。

## E7-05 整合判斷

先讀懂 E7-05 `formula.cpp` 的遞迴下降解析器：`primary` 只支援 Number / True / False / Ident /
括號，**無函式呼叫語法**。故不強行改上游（不可改），改採「獨立 API + 函式表」形式——語意等價於
「註冊為函式表供求值時查用」，一旦 E7-05 加入函式呼叫即可直接查表分派。字串函式回 `EvalResult`
（與求值同型別），接入零阻抗。

## 遇到的錯誤

- 實作零缺陷：`strings.cpp` 首次編譯即零警告。
- 測試輔助懸空參照（自查修正）：測試 helper `ok()` 原以 `const Value&` 回傳暫存 `EvalResult` 的
  `value()`，暫存於分號處解構致 `const Value& v = ok(tmp)` 懸空（4 個 split / join 案例讀到垃圾大小）。
