## 關鍵設計決策

- **選單語意以 E7-13 `Item::value()` 宣告**：不重造樹狀結構，`kind`/`checked`/`enabled` 為
  保留鍵；`kind` 省略時依有無子項推斷（有子項→submenu，否則→action），維持宣告簡潔。
- **建構與排版分離**：`build_menu()` 只建模型（不需 FontMetrics）；`render_model()` 才逐列
  呼叫 E4-01 `TextLayout::layout()` 排版——模型可獨立測試，字型引擎可獨立替換。
- **單一游標路徑表達巡覽狀態**：`cursor_`（vector<size_t>）長度即目前展開面板數，
  免維護「開啟鏈」與「高亮列」兩份平行狀態，`render_model()` 直接從游標推導可見面板與各列
  是否高亮。
- **面板具名而非數字深度**：子層 surface 尾碼取自擁有者子選單項的具名 id
  （如 `surface.menu.root.menu:file`），符合 NFR-02（不得數字 z-order / 深度指涉）。
- **巡覽邊界結構化**：`MenuNavStatus{Moved/Entered/Exited/Selected/NotSelectable/Invalid/
  Empty}`——空選單、無效路徑、命中分隔線 / 停用項、空子選單無可進入項、滑鼠 hover 超出目前
  展開鏈範圍，皆安全回報，絕不崩潰。
- **滑鼠 hover 限定「目前可見面板」**：`path_visible()` 檢查目標路徑的祖先鏈是否與游標一致，
  避免滑鼠事件跳到尚未展開的子選單分支（那些列此刻並未渲染，命中無意義）。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- 第一次編譯失敗：`MenuModel::at_path()`（非 const）遞迴進入 `MenuNode::children()` 時，
  `MenuNode` 一開始只提供 const 版 `children()`，導致 `&current->children()` 產生
  `const vector<MenuNode>*` 無法賦值給非 const `level` 指標（型別限定詞被丟棄，編譯錯誤）。
  根因：Checkbox 致動需要透過非 const `at_path` 修改深層節點的 `checked_`，但存取路徑只有
  const 重載。解法：仿 E11-01 `TrayMenuItem::children()` 慣例，替 `MenuNode` 加一個非 const
  `std::vector<MenuNode>& children() noexcept` 重載（const 版維持不變），修正後零警告編譯通過。
