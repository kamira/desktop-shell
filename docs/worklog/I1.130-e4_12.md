## 關鍵設計決策：確定性字元→字符映射

先讀了 E4-01 `text_layout.cpp` 的實作細節：`WrapMode::Word`（詞界換行）會在換行處丟棄
「行尾待落地空白」，`ellipsis` 省略號裁切會移除字元——兩者都會使排版輸出的字符序列與原始
文字不再一一對應。而 `add_span(start, end, id)` 的字元範圍必須能確定映射到排版輸出的字符
幾何，否則區段標記會錯位（隱性 bug，比明顯報錯更危險）。

決定：本單元**固定要求** `LayoutConstraints.wrap == WrapMode::None` 且 `ellipsis == false`，
建構期違反即 `std::invalid_argument`。在此限制下可證明：換行完全由顯式 `'\n'` 決定，原始
文字每個碼位（除 `'\r'` / `'\n'` 本身不產生字符外）恰依序對應排版輸出一個字符。`set_text`
內建立此映射表（`char_to_glyph_`），並以斷言 `gi == model.glyphs.size()` 做防禦性檢查。
「跨行」需求以顯式硬換行滿足（測試 `SpanAcrossHardNewlineHitsOnBothLines`），不需要冒險
支援會破壞映射的詞界換行。

副作用：E4-01 `LayoutConstraints{}` 預設 `wrap == WrapMode::Word`，若直接沿用為本單元建構子
預設參數，`ClickableTextElement(fm)` 這種常見呼叫方式會立即拋例外。改為本單元自訂
`detail::default_clickable_constraints()`（`wrap = WrapMode::None`，其餘沿用 E4-01 預設）
作為預設參數，本機驗證時第一輪測試 `ConstructorAcceptsDefaultConstraints` 即抓到此問題
（見下方錯誤紀錄）。

## 命中判定如何用 E1-04

對區段涵蓋的每個字元：取其 E4-01 字符幾何（`Glyph.x` / `Glyph.line` / `Glyph.advance` /
所屬 `LineBox.y`）與有效行高（`constraints.line_height > 0 ? 該值 : metrics.line_height()`，
與 E4-01 內部算法一致），建構一個 E1-04 `Shape::Rect`（寬 = advance、高 = 行高），並將輸入的
`LocalPoint` 平移到「該字符矩形自身本地座標系」（減去 `Glyph.x` / `LineBox.y`）後呼叫
`HitTester::hit_test`。直接覆用既有幾何命中邏輯（含邊界判定），不重新發明點在矩形內判定。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **錯誤**：第一次本機驗證時 `ConstructorAcceptsDefaultConstraints`（`ClickableTextElement el(fm)`，
  不傳 constraints）擲出未預期的 `std::invalid_argument("...constraints.wrap 必須為
  WrapMode::None...")`，導致 `libc++abi` 因未捕捉例外而終止（exit 134）。
  **根因**：建構子預設參數原寫成 `ds::render::LayoutConstraints constraints = {}`，而 E4-01
  `LayoutConstraints` 的欄位預設值是 `wrap = WrapMode::Word`（非 `None`），與本單元自身的建構期
  驗證規則衝突——預設參數本身就不合法。
  **解法**：新增 `detail::default_clickable_constraints()`（回傳 `wrap = WrapMode::None` 的
  `LayoutConstraints`），改為建構子的預設參數值。修正後 14 個測試（含此案例）全 PASS。
- （本地墊片工具本身無插曲）scratchpad `gtest.h` 為先前單元留下的最小墊片，本次僅新增
  `EXPECT_DOUBLE_EQ` / `EXPECT_THROW` / `EXPECT_NO_THROW` 三個巨集（既有巨集與行為不變），
  純屬本機驗證工具，不影響 repo 內任何檔案。
