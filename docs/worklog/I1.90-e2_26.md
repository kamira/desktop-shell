## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立解析 + 提供者 + 契約測試**，**不真的發網路請求**，
**沿用 E2-14 的可注入 `HttpTransport` + `NullHttpTransport`**，**不得**出現 `#ifdef` / win32 /
cocoa / socket / libcurl / 真實網路後端。**消費 E2-01 / E2-14 契約、不自造指標模型、不自造傳輸**。

設計（C++17，`namespace ds::sysinfo`）：

- 結構化解析（純文字）：自帶輕量標記掃描器（tokenizer：Start/End/Text/CData，含註解 / 宣告 /
  屬性 / 實體解碼），`parse_feed()` 走 token 流組出 `FeedDocument`：
  - RSS `<item>` / Atom `<entry>` → `FeedItem{title, link, time}`（Atom `<link href>`、RSS
    `<link>` 文字；`pubDate`/`published`/`updated` 時間文字）。
  - HTML → 網頁 `<title>`。
  - **空 feed（無項目）= 成功 0 項目；malformed（未結束標籤 / 註解 / CDATA、無法辨識）= 失敗
    帶訊息不靜默**（NFR-04）。
- `FeedFetchProvider : ds::metrics::MetricProvider`：register 時預配置 **N 個 slot 實例**（最新
  N 筆）；`sample()` 經注入 `HttpTransport` GET →（2xx）`parse_feed()` → 取最新 N 筆填 slot
  （text=標題、number=slot 序位）、其餘 unknown；連結 / 時間經 `items()` 暴露。網頁 HTML 合成
  單一項目。

## 上游解讀

- 讀 `modules/sysinfo/e2_14/http_fetch.hpp/.cpp`：`HttpTransport::get(url) → HttpResponse`；
  `NullHttpTransport::set_response()` 注入固定回應、未注入回「無後端」（status 0）；`is_success()`
  判 2xx。沿用之抓內容（不自造傳輸），`sample()` 的 GET / 2xx / null 保守流程比照 e2_14。
- 讀 `engine/metrics/e2_01/metric.hpp`：`MetricProvider::register_metrics()` 掛載入口；
  `InMemoryMetric::add_instance()` 建實例（無「移除實例」API → 故預配置固定 N 個 slot、每輪
  重填 / 清空）；`InMemoryMetricInstance::set_value(unknown())` 表未知不動歷史。`MetricValue`
  的 `number` + 可選 `text` → 標題入 text、slot 序位入 number。沿用之，不自造模型。
- E2-01 實例只承載 number + 可選 text（無 link / time 欄位）→ 完整結構（連結 / 時間）由提供者側
  以 `items()` 暴露，比照 e2_14 的 `last_document()` 設計。
