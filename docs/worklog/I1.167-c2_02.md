## 組裝設計

`ds::widgets::SystemStatusWidget`（`content/widgets/c2_02/system_status_widget.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`KernelBackend&` + `LayerStack&`（透傳給內部自持的 C1-01
  `SkinProfile base_`）、`const FontMetrics&`（E4-01 排版用）。內部自持一個 E4-01
  `TextLayout`（綁定 `"<id>.text"` 目標 surface）與一份 E7-02 `VariableScope vars_`（由
  `configure()` 內 E7-03 `build_scope()` 建成）。
- **設定（`configure(Value)`）**：`vars:`（選填 Map）先建暫存作用域（不直接寫入成員，等全部
  項目解析成功才提交，維持全有或全無）；`metrics:`（**必填** List，可為空）逐筆解析：
  `id`/`label`/`kind`/`min`+`max`（成對，數字或公式，公式以暫存作用域求值）/`transform`
  （選填，僅驗證 `is_formula()` 語法，**不**在 configure 時求值——因其依賴的 `value` 變數
  僅於 `refresh()` 讀到指標當次值後才可知）/`tier`。任一項目解析失敗即整體回滾（`vars_` /
  `entries_` / `configured_` 皆不動），對應失敗原因回傳 `Invalid`/`ResolveError`/
  `FormulaError` 三種具名結果之一。
- **除頻登記（`sync_demands`/`release_demands`）**：`sync_demands()` 先 `release_demands()`
  撤銷舊需求（若有）再對給定 scheduler 依 `entries_` 逐一 `add_demand(id, tier)`，記錄票根
  供之後撤銷；冪等設計讓重複呼叫或切換 scheduler 都安全。
- **刷新（`refresh(MetricRegistry&)`）**：逐筆 `source.get(id)`；找不到、無實例、
  `value().valid==false`、或數值非有限 → 該筆 `available=false`（NFR-03 降級，continue
  處理下一筆，不擲例外、不中止）。可用者填 `raw_value`/`unit`，標籤缺省時取
  `Metric::name()`；若設定 `transform`，以（`value`=raw_value，父作用域=`vars_`）建立子
  `VariableScope` 求值——失敗或結果非有限同樣降級為該筆 `available=false`。顯示範圍解算
  優先序：宣告式覆寫 > `Metric::range()`（須有界）> 保守預設 `[0,100]`。
- **呈現（`render()`）**：對 `refresh()` 結果逐筆組裝。可用者依 `kind` 建
  `BarElement`/`GaugeElement`（以解算範圍建構、`set_value(display_value)`、
  `set_show_label(false)`——因本 widget 自行以 E4-01 排版「標籤: 值」文字，不用元件自帶
  標籤）或 `ProgressElement`（固定 `[0,100]`，`set_percent(display_value)`）；`Text` 種類
  不建立元素。格式化文字：一位小數 + 單位（`%` 緊接、其餘單位空白分隔）。不可用者以
  em dash `"—"` 佔位，仍呼叫 E4-01 排版（讓呼叫端統一走文字繪製路徑呈現「未知」）。
- **具名結果**：`MetricElementKind`（Bar/Gauge/Progress/Text）、`SystemStatusStatus`
  （Ok/Invalid/ResolveError/FormulaError），各附 `to_string()`（NFR-02）。

無效操作一律明確回具名結果，不靜默；個別指標的執行期問題（不存在 / 值無效 / transform
失敗）走降級路徑而非整體失敗，直接對應 NFR-03「能力閘控 / 優雅降級」精神——差別在於
E1-03 等單元閘控的是「後端能力是否存在」，本單元閘控的是「指標是否存在 / 目前是否有有效
讀值」，機制精神一致（不假裝有資料、不擲例外中斷整體、明確標記狀態）。

### 設計釐清（非錯誤，記錄備查）

E7-03 提供兩個入口：`expand()`（展開整份文件的 `${var}` 引用）與 `build_scope()`（只從一個
Map 段落建 `VariableScope`，不觸碰文件其餘內容）。若對整份 `configure()` 輸入呼叫
`expand()`，會與 E7-05 的公式標記語法 `${ expr }` 衝突（`expand()` 會把 `${ value / gb }`
誤當成變數插值語法去找名為 `" value / gb "` 的變數，而非公式）。故本單元只用
`build_scope()` 從 `vars:` 段落取常數，其餘欄位（含 `min`/`max`/`transform`）由本單元自行
判斷 `is_formula()` 後交給 E7-05 `Evaluator` 求值，兩者職責不重疊、不衝突。
