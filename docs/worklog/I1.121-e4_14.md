## 設計要點

- `ScrollView` 單一類別同時涵蓋逐行捲動與逐頁翻頁：分頁在語意上就是「以 viewport 行數為步進的
  捲動」，共用同一份 `offset_lines_` 狀態最一致，避免兩個類別間同步捲動位置的額外複雜度。
- `set_content` 只取用 `LayoutResult::lines.size()` 作為捲動範圍，不複製 / 不重存上游像素幾何；
  `render_model()` 只回報「哪些內容行索引可見、對應到 viewport 第幾行」，實際 glyph 由呼叫端依
  `content_line` 回查 `LayoutResult`——避免本單元越界重複上游職責。
- 分頁指示的邊界案例：內容行數非 viewport 整除時，觸底捲動的偏移（`max_offset_lines()`）不會
  恰好落在頁邊界上（例如 content=10、viewport=3 時 `max_offset=7`，非 `9`）。若單純以
  `offset/viewport_lines` 計算 `page_index`，觸底時會算出 `2` 而非直覺上的「最後一頁 `3`」。
  改為：觸底（`offset==max_offset`）時直接回報 `page_count-1`，其餘情況才用整除——確保
  `page_next()` 連續呼叫到底時 `page_index` 單調遞增且終止於 `page_count-1`。

## NFR-02 / 分層 / 平台中立遵循

- **NFR-02**：`RenderModel` / `ScrollPosition` 無 x/y 像素 / 螢幕座標 / 數字 z-order；可見行對應
  以行索引表達，捲動位置以行數 + `[0,1]` 比例表達，分頁以頁索引 / 頁數表達。
- 錯誤不靜默：`set_viewport_lines(0)` 或尚未設定 viewport 即呼叫捲動 / 分頁 / `visible_range()` /
  `render_model()` → `std::invalid_argument`。**捲動越界則夾限**（非錯誤，屬正常使用者操作）。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- （設計期間自我發現，非實測錯誤）最初 `scroll_by` 以 `std::size_t` 直接運算負位移，會在
  offset 小於 |delta| 時整數下溢成巨大正值（越界夾限失效）。改用 `long long` 中繼運算再夾限至
  `[0, max_offset_lines()]` 後才轉回 `std::size_t`，並補上 `ScrollByHugeValueDoesNotUnderflow` 極端值
  測試驗證。
- （設計期間自我發現）`page_index` 若單純用 `offset/viewport_lines` 整除計算，在內容行數非
  viewport 整除、且已捲到底（`max_offset_lines()` 未落在整除邊界）時會低估頁碼。改為觸底時直接
  回報 `page_count-1`，並在 `RenderModelPageIndexAndCount` 測試中以 content=10、viewport=3
  （`max_offset=7`，非 3 的倍數）的案例驗證。
