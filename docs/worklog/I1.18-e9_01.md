E9-01 是 engine 層 / package 子系統的「統一套件格式定義」單元：定義**一個組件套件的整體
結構**——manifest（複用 E9-02）+ 資源檔佈局 + 內含項目清單——並提供結構完整性與 manifest
有效性的解析/驗證。平台中立、純邏輯，錯誤須可定位（不得靜默）。

## engine 層 / 平台中立約束遵循

- 純邏輯：無 `#ifdef`、無系統呼叫、無真實後端、無平台分支——換平台一行不動。
- 不做打包/解包 I/O、不做檔案系統存取；只定義並解析/驗證套件「格式」。
- 不重造 manifest：一律複用 E9-02（`parse_manifest` / `is_format_compatible` / `ParseError`）。

## 格式設計要點

- manifest 區段與內容清單以 `---` 單獨一行分隔：分隔線前原樣交 E9-02（避免 E9-02 對內容清單
  的 `kind:` 行報「未知 key」）；分隔線前行號 = 絕對行號，故 manifest 錯誤行號原樣傳出即正確。
- 內容清單 `kind: logical_path`；logical_path 須相對、不得以 '/' 開頭、不含 '..' 區段、無空區段，
  且不得重複（佈局完整性 / 禁逃逸套件根）。
- 「缺 manifest」= 分隔線前無實質內容 → 明確套件級錯誤（定位分隔線；無分隔線則 line 0）。
