## 我要做什麼（動工前計畫）

描述子系統的**根契約**：宣告式文件的資料模型 + 解析基座 + **版本欄位**（Q3 相容策略基礎）。
`E9-02` manifest 是這個更通用格式的一個平坦特例；本單元設計要能被眾多格式 / 設定單元消費，
故謹慎設計，形狀對齊 manifest 但更通用。

設計（C++17，`namespace ds::format`）：

- `Value` 多型節點：Null / Bool / Number（帶整數旗標）/ String / List（有序）/ Map（有序、鍵唯一）；
  型別化存取（誤用即 throw，不靜默）、Map 便捷查詢、深層相等。
- `FormatVersion{major,minor}` + `kSupportedFormat{1,0}` + `is_format_compatible()`（major 相同且 minor ≤ 上限）。
- `Document{format_version, root}`、`ParseResult`（成功 Document / 失敗 `ParseError{line,message}`）。
- `parse(text)`：縮排式巢狀 key/value + list 的極簡自足格式 → Document，**錯誤定位到行**（NFR-04 精神）。
  版本欄位以原始 token 特別解析，避開 `1.10` 塌成數字 `1.1` 的歧義。
- `parse_scalar(token,out)`：純量型別推斷單元，供進階呼叫端 / 測試共用。

參考已合併的 `engine/package/e9_02/`（manifest 解析，同宣告式格式風格）：沿用其 FormatVersion /
ParseError / ParseResult 形狀與「不靜默失敗、錯誤定位到行」的契約，並推廣為通用節點樹 + 縮排巢狀。
