## 我要做什麼（動工前）

E1-15 是「視窗 / surface 級整體透明度 + 懸停淡變」：設定整個 surface 的透明度（用 E1-03
`AlphaProfile.opacity` 的比例語意），滑鼠懸停時淡入（變不透明）、離開時淡出（變半透明），
用 E5-02 懸停事件驅動淡變起停，注入式時間 `advance(dt)` 推進動畫。NFR-02：透明度為比例。
無效透明度處理不靜默（非有限值拒絕，不悄悄套用）。

計畫產出（全部落在鎖定範圍內）：

1. `src/kernel/e1_15/window_opacity.hpp`
   - `WindowOpacityStatus`{ Ok, Invalid, Unsupported }（轉發自 E1-03 `AlphaStatus`）。
   - `WindowOpacity`：組合持有 E1-03 `AlphaSurfaceService&` + `SurfaceId`；
     `set_base_opacity` / `set_hover_opacity` / `attach(HoverTracker&)` /
     `advance(dt_seconds)` / `current_opacity()` 等。
2. `src/kernel/e1_15/window_opacity.cpp`：線性插值淡變 + E5-02 事件回呼 + E1-03 套用。
3. `src/kernel/e1_15/CMakeLists.txt`：依 BUILD.md 樣板，library（link e1_03 + e5_02）+
   `test_e1_15` + `add_test`。
4. `tests/e1/test_e1_15.cpp`：gtest（scratchpad 墊片，`EXPECT_NEAR` 驗 float），驗設定透明度、
   懸停淡入 / 離開淡出、advance 推進淡變、當前透明度、E5-02 事件驅動、夾限、無效值拒絕。
5. `docs/changes/CHG-20260724-e1_15.md`、`docs/structure/units/e1_15.md`、本 worklog。

## 上游依賴是什麼（讀懂用）

- **E1-03 `AlphaSurfaceService`**：能力閘控（NFR-03，`supported()` = 後端
  `has(kPerPixelAlphaCapability)`）+ 建立 / 銷毀 alpha surface（K1）+ `set_opacity` /
  `set_mode` / `set_alpha`（皆先閘控、opacity 非有限值拒絕、有限值 clamp [0,1]）。E1-15
  透過既有 `set_opacity(surface, opacity)` 實際把計算出的目前不透明度套用到 surface，
  不重複驗證 / 不繞過其能力閘控。
- **E5-02 `HoverTracker`**：依注入式 `inject_move(point)` + E1-04 `HitTester::topmost_hit`
  判定命中，分派 Enter / Leave / Move。E1-15 以 `attach(hover)` 訂閱，回呼中比對
  `event.surface == surface_`，僅回應本 surface 的 Enter（觸發淡入）/ Leave（觸發淡出）。

## 設計決策：淡變演算法自我完備、不越界引入 e4_05

`depends_on` 只列 `[E1-03, E5-02]`；`engine/render/e4_05` 的 `Tween`（同樣是線性 /
easing 插值 + `advance(dt)`）風格上很接近，但**未被本單元宣告為上游依賴**，故本單元的
線性插值改為在 `window_opacity.cpp` 內自我實作（`fade_from_` / `fade_to_` /
`fade_elapsed_` / `fade_seconds_`），不 `target_link_libraries` 連結 `e4_05`，避免越界
相依（G1c stage_check / 未宣告相依）。
