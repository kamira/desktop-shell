## 我做了什麼

把腳本引擎的**嵌入契約**先立好，相位 1 以最小 / mock 後端完整驗證、不綁真實 JS 引擎：

- `ScriptEngine`（`namespace ds::script`）：可插拔純虛抽象介面——`evaluate` / `bind_function` /
  `set_global` / `get_global` / `call` / `has_function` / `backend_name`。宿主只相依此抽象，
  相位 2 的真實 QML/JS 後端掛同一介面即可替換。
- `MiniScriptEngine`：相位 1 最小內建直譯器。支援極簡逐行腳本（`set <name>=<expr>` /
  `<name>=<expr>` / `<call>` / 裸 `<expr>` / `#` 註解；字面值 int/double/string(含跳脫)/bool/null
  + 全域參照 + 具名呼叫）。足以驗證「宿主綁函式 → 腳本呼叫 → 經 E6-01 分派命令」。
- `NullScriptEngine`：null/mock 後端。實作同一介面（保存全域 / 綁定 / 可 `call` 宿主函式），
  `evaluate` 明確回 `Unsupported`（不執行腳本文字、不靜默）——示範可插拔引擎替換。
- E6-01 橋接 `make_command_binding` / `bind_command`：把命令一行式暴露為腳本函式；位置引數
  對映具名參數組 `CommandArgs`、在 `CommandBus` 上分派、`CommandResult`（Ok / NotFound / Failed）
  轉 `HostResult`（成功 / 失敗上浮為腳本執行期錯誤，不靜默）。
- 錯誤模型 `EvalResult`（二選一，帶行號）+ `ScriptError`（None/Syntax/Runtime/NotFound/Unsupported）。
  值型別沿用 E6-01 `CommandValue`（不重造），跨腳本 / 宿主 / 命令邊界不變形。

參考已合併的 `engine/command/e6_01/`（`CommandBus::dispatch`、`CommandValue` / `CommandArgs` /
`CommandResult` 值型別、重複註冊不覆蓋、未知命令回 NotFound 不崩潰、契約承重的最小 API 面）
與 `engine/script/e8_02/`（`ds::script` 命名空間、二選一結果物件風格、「錯誤帶定位、不靜默」契約）。
