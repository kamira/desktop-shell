## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端（純記憶體狀態模擬）+ 契約測試**，
**絕不呼叫真實 OS 桌布 API**，**不得**出現 `#ifdef` / win32 / cocoa / NSWorkspace /
setDesktopImageURL / SystemParametersInfo 等。**消費 E6-01 命令匯流排契約、不自造匯流排或
值型別**，範式對齊已合併的 E3-05（注入式後端 + null 樣式）。

設計（C++17，`namespace ds::actuators`，與 e3_05 一致）：

- 兩個具名命令：`wallpaper.set` / `wallpaper.get`。
- `ScaleMode`（Fill/Fit/Stretch/Center）+ 字串 <-> 列舉轉換；`kDefaultScaleMode = Fill`。
- `kAllDisplays = -1`：display 缺席 → 所有顯示器。
- `WallpaperSpec`（path + mode）供查詢 / 內省。
- `WallpaperBackend` 抽象後端（`display_count`/`set(display,spec)`/`get(display)`）+
  `NullWallpaperBackend`（每顯示器一份規格的純記憶體模擬、顯示器數可注入）。
- `WallpaperActuator`：`register_on` / `unregister_from`（回滾語意）+ 兩個處理器
  （必填 path 非空、選填 mode/display，缺 / 型別錯 / 無效值以 `has()`/`get_*` 保護回 Failed）
  + `current_spec()`。

## 關鍵設計取捨

- **合法化在致動器層、不在後端**：路徑非空檢查、模式字串解析、顯示器範圍檢查、「所有顯示器」
  展開全在致動器完成，後端契約可信任傳入已合法。相位 2 真實後端不必重做驗證，且錯誤路徑 /
  模式 / 顯示器可完全單元測試。
- **缺席 display = 所有顯示器**：以哨兵 `kAllDisplays = -1` 表達；致動器據後端 `display_count()`
  展開為逐台 `set()`，成功結果回實際影響的顯示器數，讓「單一 / 全部」語意在同一命令內表達。
- **失敗不改後端狀態**：所有參數驗證（缺 path / 空 path / 型別錯 / 無效模式 / display 超範圍）
  皆在觸碰後端前回 Failed，確保後端狀態一致（測試以 `set_count()` 驗證未變）。
- **縮放模式不用數字魔法值**：以 `ScaleMode` 列舉 + 字串雙向轉換承載；命令參數以可讀字串
  （fill/fit/stretch/center）表達，未知字串回報無效（符合 NFR-02「無數字 z-order / 絕對座標」
  精神——display 亦為相對索引，非螢幕絕對座標）。
- **版本標記命名**：`ds::actuators` 命名空間已有其他致動器的 `*_contract_version()`；本單元用
  `wallpaper_contract_version()` 前綴避免符號衝突（多致動器可能同時連入同一 target）。
