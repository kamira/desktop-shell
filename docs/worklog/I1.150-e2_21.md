設計（C++17，`namespace ds::sysinfo`）：

- `UserTextInputProvider : public ds::metrics::MetricProvider`：`bind(key, label, element)`
  以穩定 key 綁定一個（不取得所有權的）`TextInputElement`；`register_metrics()` 向 E2-01
  註冊表掛上單一指標 `"input.text"`，每個已綁定輸入框建一個 `MetricInstance`；`refresh()`
  重新讀各已綁定輸入框目前文字、更新對應實例（pull 模型，不推歷史）；`unbind(key)` 解除
  綁定、既有實例設為 unknown。

## 指標形狀的關鍵設計（為何每個輸入框 = 一個實例）

E2-01 六要素含「可列舉實例」。多輸入框（如同時有搜尋框 + 參數輸入框）天然對應此要素：
- 指標身分：id=`input.text`、name=`User Text Input`、unit=``、range=`unbounded`（文字值無
  值域）。
- **每個已綁定輸入框建成一個 `MetricInstance`**（instance_id=呼叫端指定的穩定 key、
  label=顯示名、value.text=目前文字、value.number 恆為 0.0——與 E2-12 純文字欄位同慣例、
  history_capacity=0，因目前值無時序意義）。
- 於是「輸入框集」由 `Metric` 列舉實例取得、「輸入框數」= `Metric::instance_count()`。
  消費者（掛件）只透過 E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，
  **完全不觸及 `TextInputElement` 本身**——新增此指標，掛件一行不用改。

## 更新模型：pull，非 push

刻意不訂閱 E4-15 的編輯事件（`attach()`/`KeyboardInputSource`），避免提供者與具體編輯
事件系統耦合。改採 `refresh()`：呼叫端在判定「該讀新值」時（如 widget 重繪前）呼叫，本
單元屆時重新讀各已綁定輸入框的 `text()` 並寫入對應實例——與 E2-19
`ProcessMonitorProvider::sample()` / E2-15 `AudioLevelProvider::sample()` 的
「register_metrics 建初值、專門方法重讀更新」節奏一致。

## 空值 / 無輸入框的誠實處理

- **無輸入框**（從未 `bind()` 過）：指標仍掛上，但 `instance_count()==0`（保守而不崩，
  同 E2-12 null source 語意）。
- **空值**（已綁定輸入框目前文字為 `""`）：對應實例存在、`value.valid==true`、
  `value.text==""`——這是使用者「目前尚未輸入任何字」的真實狀態，**不**等同「無讀值」；
  與「無輸入框」（指標層級無此實例）明確區分，不混為一談。
- `unbind()`：既有實例保留（供既有參照穩定走訪）但值設為 `MetricValue::unknown()`
  （「已解除綁定，目前無讀值」），且不再隨 `refresh()` 更新；`bind()` 同 key 再次呼叫可
  恢復更新。

## 實作中發現並修正的一個 bug

初版 `bind()` 以 `bindings_.find(key) == end()` 判斷「是否首次出現」以決定是否
`order_.push_back(key)`。但 `unbind()` 會把 key 從 `bindings_` 移除——若之後同 key 再次
`bind()`（rebind），該判斷會誤判為「首次」，把 key 重複塞進 `order_`，導致
`register_metrics()`/`refresh()` 走訪到重複 key（對同一 metric 建立兩個同 instance_id
的實例）。修正：改用獨立的 `seen_keys_`（`unordered_set`，只增不減）判斷「是否首次出現」，
與「目前是否仍綁定」（`bindings_`）分開追蹤。測試
`UserTextInputProvider.UnbindMarksInstanceUnknownAndStopsUpdating` 涵蓋 unbind→rebind
路徑，驗證修正後行為正確（rebind 後 `refresh()` 恢復更新、無重複實例）。
