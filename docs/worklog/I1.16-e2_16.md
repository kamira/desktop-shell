## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端 + 契約測試**，**不真的掃描系統**，
**不得**出現 `#ifdef` / win32 / cocoa / 真實平台後端。**消費 E2-01 契約、不自造指標模型**。

設計（C++17，`namespace ds::sysinfo`）：

- `InstalledApp` struct：平台中立描述 —— id / name / version（"" = 未知）。
- `InstalledAppSource` 抽象後端：`enumerate() → vector<InstalledApp>`。相位 2+ 由真實
  平台後端實作；提供者只依賴此抽象介面（換後端不動提供者）。
- `NullInstalledAppSource` null 後端：**不掃描**，預設回空清單；`set_apps`/`add_app`/`clear`
  注入假資料供測試。
- `InstalledAppsProvider : public ds::metrics::MetricProvider`：`register_metrics()` 向
  E2-01 註冊表掛上單一指標 `"apps.installed"`。

## 指標形狀的關鍵設計（為何每個應用 = 一個實例）

E2-01 六要素含「可列舉實例」。本單元名即「已安裝應用**列舉**」，天然對應此要素：
- 指標身分：id=`apps.installed`、name=`Installed Applications`、unit=``、range=`at_least(0)`。
- **每個已安裝應用建成一個 `MetricInstance`**（instance_id=應用 id、label=顯示名、
  value=存在(1.0)+版本文字、history_capacity=0，因應用無時序歷史）。
- 於是「清單」= 依序列舉實例、「數量」= `Metric::instance_count()`。消費者（掛件）只透過
  E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，**完全不觸及 sysinfo 型別**
  ——這正是「平台 vs 工具」的分野：新增此指標，掛件一行不用改。

保守設計：source 為 null 或空 → 仍掛上「空指標」（instance_count()==0），不崩；
重複 id 由 E2-01 註冊表保守拒絕、不覆寫既有。
