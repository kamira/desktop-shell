## 做了什麼

在 E8-04「載入機制」之上定義第三方模組面對的**穩定開發介面（SDK）**：

- `IModule` 抽象介面 + `ModuleBase` 便利基底（生命週期狀態機 init→start→stop⇄start→teardown，
  合法轉移防護集中於 SDK，開發者只覆寫 `on_*` 鉤子）。
- `ModuleInfo` metadata / 能力需求宣告，`to_manifest()` 橋接 E9-02 給 E8-04 閘控。
- `HostServiceRegistry` + `ModuleContext`（SDK 面）：模組於生命週期以 `has_service()` 閘控
  存取宿主服務（`service<T>` 型別安全轉型），並委派 E8-04 註冊面登記能力。
- `make_module(IModule&, HostServiceRegistry&) → ds::ext::Module`：轉接層，讓現成
  `ds::ext::ModuleLoader` 直接驅動模組生命週期（load→init/start；unload→stop/teardown）。
- `sample_module.hpp`：`SampleSensorModule` + `IClockService`/`FixedClock` 範例，驗證契約可用。

## 決策 / 偏離

- **命名空間**：任務書括註 `ds::script`，但已合併之 E8-04 實際用 `ds::ext`（在 `engine/script/` 下）。
  為真正與 E8-04 一致並能連結其型別，採巢狀 `ds::ext::sdk`（`sdk` 子命名空間避開與 E8-04 既有
  `ds::ext::ModuleContext` 的符號衝突）。已於 CHG 註記。
- E8-05 的 `ModuleContext`（宿主服務存取 + 能力登記委派）與 E8-04 的 `ModuleContext`（純能力註冊面）
  刻意分層：前者在 `ds::ext::sdk`、包裝後者，透過 `make_module` 在 on_register 內橋接。
