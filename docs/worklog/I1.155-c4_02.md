## 上游研讀（動工前）

先讀懂三個已合併、可讀不可改的擴充點/元件，理解如何組裝：

- **E3-11**（`modules/actuators/e3_11/screen_capture_actuator.hpp`）：螢幕擷取致動器——
  `CaptureKind`（FullScreen/Region/Window）、`CaptureRegion`（x/y/width/height +
  `valid()`）、`CaptureSpec`（kind/display/region/window/save_path）、`CaptureResult`
  （width/height/image_ref/path + `ok()`）、`ScreenCaptureBackend`（純虛後端）、
  `NullScreenCaptureBackend`（相位 1：Region 遵循請求尺寸回結果，絕不觸碰螢幕）。本單元
  只借 `ScreenCaptureBackend` / `CaptureSpec` / `CaptureRegion` / `CaptureResult`，未經
  `ScreenCaptureActuator` + `CommandBus`（該路徑面向具名命令分派場景；本單元的
  `capture(region)` 是直接方法呼叫，故直接持有注入式後端，風格對齊 C4-03 持有
  `PixelSampleSource` 而非經命令匯流排）。
- **E4-20**（`modules/elements/e4_20/vector_graphic.hpp`）：向量圖形——`VectorPath`
  （move_to/line_to/curve_to/close，即時驗證合法性）、`Shape` 工廠
  （`make_rect`/`make_circle`/`make_polygon`/`make_line`）、`build_shape_path`（形狀轉
  路徑，退化形狀 / 非有限值回 `Invalid` 且不部分套用）、`VectorGraphic`（持有路徑 +
  描邊 / 填色樣式，產出 `VectorRenderModel`）。座標為元件本地座標系（NFR-02）。
- **E4-30**（`modules/elements/e4_30/dim_overlay.hpp`）：全螢幕調光覆蓋——
  `DimOverlayElement`：`show()` / `hide()` 顯隱、`add_cutout(region)` /
  `remove_cutout(region)` 挖具名「不調光」洞。建立 / 改動半透明狀態經
  `AlphaSurfaceService::supported()` 閘控（NFR-03），不可用時回 `DimStatus::Unsupported`
  （降級不崩）。

## 組裝設計

`ds::apps::ScreenshotAnnotatorApp`（`apps/c4_02/screenshot_annotator.hpp/.cpp`）：

- 注入式相依：`shared_ptr<ScreenCaptureBackend>`（E3-11，可 null——每次 `capture` 回
  `NoBackend`，不崩）+ `DimOverlayElement&`（E4-30，不取得所有權，借它組出選取框覆蓋）。
- **擷取（E3-11）**：`capture(region, save_path="")` 先驗證 `region.valid()`（寬 / 高
  非正 → `InvalidRegion`，不動既有狀態），再檢查後端非 null（→ `NoBackend`，不動既有
  狀態），才組 `CaptureSpec{kind=Region}` 呼叫 `backend_->capture()`。成功
  → `Ok`，更新 `capture_`、清空既有標註（`annotations_.clear()`）、若選取框覆蓋作用中
  一併收起（挖洞名固定對應「目前擷取」，換畫面後舊挖洞不再有意義，統一收起避免殘留
  誤導，呼應 C4-03 換取樣點清舊挖洞的既有慣例）。
- **標註（E4-20 組裝）**：`annotate_arrow` / `annotate_box` 委派 `build_shape_path`
  （`Shape::make_line` / `make_rect`）建路徑，成功則包成 `VectorGraphic`（描邊啟用，
  寬度用單元常數 `kAnnotationStrokeWidth = 2.0`，恆正有限故 `set_stroke` 恆回 `Ok`，未
  另外檢查回傳值），`render_model()` 存入 `Annotation`。`annotate_text` 不建向量路徑
  （E4-20 無字形渲染能力），僅記錄位置 + 文字內容，`render` 保持 `VectorRenderModel{}`
  預設值（`empty=true`，明確表達「無路徑資料」而非假裝有）。三者皆先檢查
  `has_capture()`，未擷取即標註 → `NoCapture`（無畫面可標註的語意錯誤，優先於形狀本身
  是否有效判斷）。
- **選取框覆蓋（E4-30 組裝）**：`show_selection()` 呼叫 `selection_.show()` 後
  `add_cutout(kSelectionRegionName)`——固定具名區域（不同於 C4-03 依 anchor 命名多個
  挖洞，本單元一次擷取只對應一個選取框，故用單一固定名字，更簡單且仍符合 NFR-02）。
  尚未擷取即框選 → `DimStatus::Invalid`（複用 E4-30 既有列舉，未新造狀態碼，呼應
  C4-03 `magnify()` 的既有慣例）。`hide_selection()` 移除挖洞並 `hide()`，恆安全。
- **匯出**：`export_result()` 彙整目前擷取尺寸 / 影像參照或存檔路徑 / 標註數量為
  `ExportResult`；相位 1 明確不做真實影像合成（不疊繪標註到像素上）、不寫真實檔案——
  這是「宣告式渲染描述」的一貫精神（E4-20 `VectorRenderModel` / E4-30
  `DimRenderModel` 皆同精神：相位 1 只產出描述，交後續相位的繪製 / 匯出後端消費）。
  尚未成功擷取過 → `ok=false`，其餘欄位維持預設值（不假裝有資料）。

具名結果 `CaptureStatus`（Ok / NoBackend / InvalidRegion）、`AnnotateStatus`（Ok /
NoCapture / Invalid）附 `to_string()`（NFR-02）；`AnnotationKind`（Arrow / Box / Text）
同樣附 `to_string()`；選取框覆蓋的狀態碼直接複用 E4-30 `DimStatus`，不重複定義同義
列舉。

無效操作一律明確回具名結果，不靜默：無效區域、無後端、尚未擷取即標註 / 框選、退化
標註形狀（零長度線段 / 零負寬高矩形）、空文字標註、非有限座標。
