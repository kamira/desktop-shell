## 關鍵設計決策

- **命名空間 `ds::ipc::http`**：與 E10-01 `ds::ipc` 一致（巢狀），且避免與其 `contract_version` 等符號相撞。
- **可注入請求輸入**：`HttpRouter::handle(HttpRequest)->HttpResponse` 為純邏輯——不開真實 socket / listen / port，
  路由匹配與分派可全單元測試；相位 2 只需在 socket 迴圈做位元組↔`HttpRequest`/`HttpResponse` 轉換。
- **具名方法列舉 + 具名狀態碼常數**：避免裸字串 / 裸數字散落核心 API；相位 2 可從請求列以 `method_from_string` 解析。
- **路徑樣式 `:name`**：`/widgets/:id` 段擷取為路徑參數，以 E6-01 `CommandArgs` 承載，跨邊界不變形。
- **請求 / 回應酬載重用 E6-01 `CommandArgs`**：query / params / headers 皆具名字典，可直接轉命令參數 / 封成訊息。
- **404 / 405 明確不靜默**：路徑不符回 404；路徑相符方法不符回 405 並帶 `Allow` 標頭列允許方法（遵 HTTP 規範）。
- **註冊不覆蓋**：重複 (method,pattern) 回 false，不靜默遮蔽已註冊者——與 E6-01 / E10-01 契約一致。
- **映射通道 / 命令**：`to_command` / `command_dispatcher`（交 `CommandBus` 分派，結果 Ok→200/未知→404/失敗→400）、
  `to_message`（封成 E10-01 `Message` 供 send/publish），重用既有命令匯流排與本機 IPC，不在 HTTP 層另立副作用。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- 初版 `match()` 想以 `merge_params()` 把擷取到的路徑參數併入呼叫端字典，但上游 `CommandArgs`
  只提供 getter、無「列舉所有鍵」介面，無法通用搬運。
  根因：誤設 CommandArgs 可迭代。
  解法：改為 `match()` 於相符時直接 `params_out = std::move(captured)`；`handle()` 每條路由用新字典、
  相符且方法符時 `enriched.params = std::move(params)`。移除死碼，一次編譯零警告通過。
