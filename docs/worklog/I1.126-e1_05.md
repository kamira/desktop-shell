## 我要做什麼（動工前）

E1-05 在 E1-04 幾何命中測試之上，加一層「具名碰撞區域（named hit regions / hotspots）」：在
單一 surface 的本地座標系內登記一組具名區域（形狀 + 參數），命中某點時判定它落在哪個具名區域，
把該區域的**具名 id + 相關參數**帶出，供事件系統組裝事件負載（例如按鈕不同部位觸發不同行為、
地圖不同區塊帶不同屬性）。相位 1（Mac / null 期）不引入新幾何演算法，完全委派 E1-04
`HitTester::hit_test` 做逐一判定。

先讀懂上游與約束：
- `docs/backlog/BUILD.md`：單元 CMakeLists 樣板、NFR-02（核心 API 不得出現絕對座標與數字
  z-order）。
- 上游 E1-04 `src/kernel/e1_04/hit_test.hpp`：`LocalPoint`（本地 / 相對座標）、`Shape` +
  `ShapeKind` + 五個工廠函式、`HitStatus`{Ok, Invalid}、`HitTester::is_valid` / `hit_test`。

## 關鍵設計判斷

1. **不重造幾何演算法**：`NamedRegionMap` 內部持有一個 `HitTester` 成員，`hit()` 對每個登記
   區域呼叫既有 `hit_test(point, shape)`，本層只處理「具名登記 / 查詢 / 移除」與重疊優先，
   不新增任何點內判定邏輯。

2. **重疊優先簡化為加入序**：E1-04 `topmost_hit` 用「具名圖層主序 + 宣告序次序」處理多個
   *surface* 重疊；E1-05 的場景是單一 surface 內部的子區域，沒有圖層維度，直接用**加入序**
   （後加入者為上）即足夠，逐一判定並持續覆寫命中結果，迴圈結束時保留最後一個命中者。無數字
   z-order（NFR-02）。

3. **參數型別不依賴 `engine/command/e6_01`**：曾考慮直接複用 `CommandArgs`/`CommandValue`
   （engine/command 層既有的具名參數字典型別，型別結構與本單元需求幾乎一致），但 kernel/
   platform 層不應反向依賴 engine/command 層，且 `units.json` 的 `depends_on` 只列 `E1-04`。
   改為本層自有 `RegionParamValue`（`std::variant<monostate, bool, int64_t, double, string>`）
   + `RegionParams`（`std::map<string, RegionParamValue>`）——封閉型別集合、具名鍵，型別安全
   但物理獨立，不引入跨層耦合。

4. **「報錯不靜默」收在寫入邊界**：`add_region` 立即以 `HitTester::is_valid` 驗證形狀，空具名 /
   無效形狀 / 重複具名一律拒絕（回 `false`，不新增，呼叫端可由回傳值得知失敗）。如此一來
   `hit()` 內對已登記區域的形狀理論上必然有效；仍保留一次防禦性複查（形狀無效則整體回
   `Invalid`），呼應 E1-04 一貫的「不留死角」風格，但不視為主要防線。查詢點本身非有限值時，
   `hit()` 直接回 `status=Invalid`（這是 `hit()` 唯一預期會觸發 `Invalid` 的路徑）。

5. **結果型別沿用 E1-04 慣例**：`RegionHit{HitStatus status, bool hit, string name,
   RegionParams params}`，結構化欄位而非例外 / `std::optional`，與 E1-04 `TopmostHit` 同一
   慣例；`status=Ok且hit=false` 為「有效查詢、無命中」的結構化空結果（`name`/`params`皆空）。

6. **移除語意比照 E1-24**：`remove_region(name)` 未知具名回 `false`、不崩潰；移除後同名可
   重新新增（重複具名限制只在「同時存在」時生效）。

## 錯誤紀錄（錯誤 + 根因 + 解法）

- **測試初稿混淆「不重疊」與「加入序覆寫」語意**：首版 `MultipleNonOverlappingRegions` 用兩個
  皆以本地原點 (0,0) 起始的矩形（僅寬高不同）試圖表達「按鈕不同部位」，但形狀本地原點都固定在
  (0,0) 時只要寬高有交集就必重疊，测试查詢點 (2,5) 其實同時落在兩個區域內，結果依加入序覆寫，
  與「各自命中對應具名」的測試意圖矛盾。解法：拆成兩案例——`MultipleRegionsCarryDistinctParams`
  用空間明確分離的圓（圓心相距 18、半徑 2，不相交）驗證多區域各自攜帶不同具名參數；
  `OverlappingRegionsLaterAddedWins` 專門驗證加入序覆寫規則，兩者語意不再衝突。重編後零警告
  19/19 全綠。
