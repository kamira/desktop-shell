## 我要做什麼（動工前計畫）

相位 1（Mac / null 期）：只寫**平台中立介面 + null 後端 + 契約測試**，**不真的查系統**，
**不得**出現 `#ifdef` / win32 / cocoa / 真實平台後端。**消費 E2-01 契約、不自造指標模型**。

設計（C++17，`namespace ds::sysinfo`）：

- `SysInfoField` struct：平台中立欄位描述 —— key / label / text / number（純文字欄位為 0.0）。
- `SysInfoSource` 抽象後端：`query() → vector<SysInfoField>`（隨選查詢）。相位 2+ 由真實
  平台後端實作；提供者只依賴此抽象介面（換後端不動提供者）。
- `NullSysInfoSource` null 後端：**不查系統**，預設回空欄位集；`set_fields`/`add_field`/`clear`
  注入假資料供測試。
- `SystemInfoProvider : public ds::metrics::MetricProvider`：`register_metrics()` 向
  E2-01 註冊表掛上單一指標 `"system.static"`。

## 指標形狀的關鍵設計（為何每個欄位 = 一個實例）

E2-01 六要素含「可列舉實例」。本單元名即「系統靜態**資訊**」，天然對應此要素：
- 指標身分：id=`system.static`、name=`System Information`、unit=``、range=`unbounded`
  （靜態資訊多為異質文字，無統一單位、無值域）。
- **每個靜態欄位建成一個 `MetricInstance`**（instance_id=欄位鍵如 "os.name"、label=顯示名、
  value=文字值+可選數值維度、history_capacity=0，因靜態資訊無時序歷史）。
  - 純文字欄位（OS 名稱/版本、主機名、CPU 型號）：text 承載值、number=0。
  - 數值欄位（核心數）：number 承載數值維度、text 承載其文字表述——兩維並存。
- 於是「欄位集」= 依序列舉實例、「欄位數」= `Metric::instance_count()`。消費者（掛件）只透過
  E2-01 的 `MetricRegistry`/`Metric`/`MetricInstance` 抽象介面走訪，**完全不觸及 sysinfo 型別**
  ——這正是「平台 vs 工具」的分野：新增此指標，掛件一行不用改。

保守設計：source 為 null 或空 → 仍掛上「空指標」（instance_count()==0），不崩；
重複 id 由 E2-01 註冊表保守拒絕、不覆寫既有。
