## 我要做什麼（動工前）

E9-02 是 engine 層 / package 子系統 / 承重 4x 的「manifest」單元：套件/模組 manifest
的**格式定義與解析**。依 `docs/ai-guideline.md` §3 Q3：manifest 須具 `requires`/
`permissions`，且**格式帶版本欄位**。平台中立、純邏輯，解析錯誤須可定位（不得靜默）。

   - `FormatVersion`{ major, minor } + `kSupportedFormat{1,0}` + `is_format_compatible()`。
   - `Manifest`{ format_version, name, version, description, required_capabilities, permissions }。
   - `ParseError`{ line, message }、`ParseResult`（success/failure 互斥）。
   - `parse_manifest(text)`：解析即驗證。

   - 缺必填、未知/重複 key、缺冒號、版本無法解析、不相容 → 帶行號的 ParseError。

## engine 層 / 平台中立約束遵循

- 純邏輯：無 `#ifdef`、無系統呼叫、無真實後端、無平台分支 —— 換平台一行不動。
- 不引入 JSON/YAML 外部相依，採自足的極簡文字格式。
- 不做能力閘控/權限強制（那對接 E1-21 `has()` 與其他單元）；本單元只定義與解析格式。

## C++20 保留字處理

manifest 文字格式的 key 依 Q3 契約為 `requires`，但 `requires` 是 C++20 保留字；
C++ 成員因此命名 `required_capabilities`，避免未來提升標準時破裂，對外文字契約不變。
