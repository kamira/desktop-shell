## 2. 判定

**fail** —— 阻擋項 **F6**：來源側述詞 `source_covers()` 讀的是**歷史標記**
（`origin_` / `origin_name_` / `origin_complete_`），不是來源的**內容**；
`overwrite_check()` 從頭到尾沒有讀過 `state_`。於是「我曾經從這個名字完整載入過」
與「我手上這份模型是那份目標的內容」之間的時間窗裡，只要使用者改過那個檔案，
下一次同名 `save()` 就把他寫進去的東西全部刪掉（`Ok`、無備份、兩個預檢 API 綠燈）。
最短重現三步、不需要任何錯誤：存一次檔 → 使用者手動加一個掛件 → 自動存檔。

**封閉性論證不成立**：第三個輸入不需要 API 變動，它已經是 `overwrite_check()` 裡的
區域變數（目標解析後的 `target.state`，實測 3 個元件 vs 模型 2 個元件）。
10×4 狀態表照不出它，是因為唯一會出事的那一格把目標的位元組又塞回成載入時那一份。

**已修且經本輪實測**：F5（三條路徑）、R7 / R13（跨 profile）、R12（`discarded_values`）、
R14（`next_backup_name()`）、四個入口同述詞。

**第 12 列的裁決**：撤回 V1.9 的「可接受」，**同意修訂 4 改成預設拒絕**——
代價我逐條量過，9 種正當操作無一被擋死，逃生門門檻合理（拒絕訊息自己說出兩條路）。
