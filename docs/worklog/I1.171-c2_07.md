## 上游命名碰撞（施工中發現，非預先已知）

依派工敘述組裝 C1-01 基底 + E4-04 四顆按鈕時，`media_control_widget.hpp` 同時
`#include "skin_profile.hpp"`（C1-01，transitively 帶入 E1-02 `input_strategy.hpp`：
`enum class ds::kernel::HitResult`）與 `#include "button_element.hpp"`（E4-04，transitively
經 E5-02 `hover_tracker.hpp` 帶入 E1-04 `hit_test.hpp`：`struct ds::kernel::HitResult`），本機
g++ 編譯失敗：

```
error: use of 'HitResult' with tag type that does not match previous declaration
```

`grep -rn "HitResult"` 全庫後發現：這**不是本單元獨有**的問題——已合併的 **C1-06**
（`content/profiles/c1_06/`）標頭與 CMakeLists 已明確記載相同碰撞（E1-02 的 `enum class
HitResult` 對 E1-16 transitively 帶入的 E1-04 `struct HitResult`），並已確立解法：把「實際
`#include` 會觸碰 E1-04 的那一半」隔離到獨立翻譯單元（pimpl 橋接）——橋接層標頭只用中立值
型別、不 include 任何上游標頭，只有其 `.cpp` 才 `#include` 該上游標頭。

本單元依此**既有、已驗證**範式解決，於自身 write_scope 內新增 `media_control_button_bridge.
hpp`/`.cpp`（中立化 `MediaButtonState` / `MediaButtonRenderModel` / `MediaControlButtonBridge`，
只有 `.cpp` `#include "button_element.hpp"`），`media_control_widget.hpp` 改用該橋接層而非
直接 include `button_element.hpp`。未修改任何上游檔案。詳細分析與確認見 CHG 文件「上游命名
碰撞」段落。

## 組裝設計

`ds::widgets::MediaControlWidget`（`content/widgets/c2_07/media_control_widget.hpp/.cpp`）：

- 注入式相依（不擁有生命週期）：`KernelBackend&` + `LayerStack&`（透傳給內部自持的 C1-01
  `SkinProfile base_`）、`shared_ptr<MetricRegistry>`（可為 nullptr，`refresh()` 保守降級）、
  `shared_ptr<MediaControlActuator>`（可為 nullptr，控制方法能力閘控回 `Unavailable`）。內部
  自持四顆 `MediaControlButtonBridge`（play/pause/prev/next），建構時各自 `set_on_click`
  綁定 lambda（捕獲 `this`，於呼叫當下讀 `actuator_`，故建構後即使能力未注入也安全 no-op）。
- **刷新（`refresh()`）**：`registry_` 為 nullptr、或 `registry_->get(kMetricId)` 找不到指標
  → `apply_no_media()` 降級，回 `Ok`。找到指標後以 `find_instance` 取五個欄位實例，任一缺失
  → `Invalid`（結構性錯誤，不套用）。"media.title" 欄位 `valid==false`（沿用 E2-13「無播放」
  語意——該欄位群與 `has_media` 同步變動）→ 同上降級。否則讀 state 數值維度換算
  `PlaybackState`（`state_from_rank`：>=2 Playing、>=1 Paused、否則 Stopped）、讀
  title/artist/album/artwork 文字維度、以 `ImageElement` + `MemoryImageSource` 組裝封面渲染
  描述（空參照則不 `set_source`，維持 `has_source=false`）、`sync_buttons()` 同步四顆按鈕，
  回 `Ok`。
- **控制（`play`/`pause`/`next`/`prev`）**：皆呼叫私有 `trigger(bridge)`——先
  `has_control()`（`actuator_ != nullptr && actuator_->backend() != nullptr`）閘控，
  `false` → `Unavailable`（不觸發按鈕、不動狀態）；否則 `bridge.click()`（模擬 press+release，
  觸發其 `on_click` → 直接呼叫 `actuator_->handle_play/pause/next/prev`），`sync_buttons()`，
  回 `Ok`。
- **具名結果**：`MediaControlStatus`（Ok / Invalid / Unavailable），附 `to_string()`（NFR-02）。

無效操作一律明確回具名結果，不靜默；無媒體走降級路徑（`Ok` + `has_media()==false`，誠實表達
「目前無播放」而非錯誤，與 E2-13 自身「無播放時非狀態欄位 valid==false」的誠實預設同精神）。
