## 組裝設計

`ds::content::DialogueBook`（`content/c3_02/dialogue_book.hpp/.cpp`）：

- 每個實例代表**一本**對話本，以**單一發話角色**（`speaker`）為對象。自持一個 C1-03
  `BalloonProfile`（surface id = 對話本自身 id）、一份 E8-02 `Script`（`load_script`
  覆寫，位址穩定供 `Interpreter` 參照）、一個 E8-03 `PresentationController`（建構時嘗試
  註冊五個舞台指示到注入的 `CommandBus`；`ready()` 透傳其結果，`!ready()` 時
  `load_script`/`start` 一律 `Invalid`，不靜默用半殘的表現層）。
- **台詞 / 舞台指示分流**（`DialogueBook::LineSink`，本檔內部 pimpl 巢狀類別，實作 E8-02
  `OutputSink`）：每次 `say` emit 一行文字，先判斷第一個空白分隔 token 是否為 `show` /
  `hide` / `switch_surface` / `transition` / `wait` 之一——是 → 轉交內部 E8-03
  `PresentationSink` 經 `CommandBus` 分派（**不**算一句台詞，`run_until_next_line()` 繼續
  尋找下一個真正台詞）；否 → 記為待顯示台詞（`pending_line_`）。此設計讓同一份腳本可以
  「台詞」與「舞台指示」自然交錯撰寫，兩條路徑分別驗證於測試（`Presentation` 測試組）。
- `load_script(script)` → `start(speaker, ttl)` → `advance(speaker, ttl)` → `is_finished()`
  的播放模型：`start`/`advance` 皆呼叫內部 `run_until_next_line()`（從目前 pc 執行 E8-02
  `step()` 直到取得一句待顯示台詞、或腳本結束、或錯誤），成功取得台詞後才呼叫
  `BalloonProfile::show_balloon()` 顯示。`reset()` 收掉氣球、丟棄 `Interpreter`（腳本定義
  `script_` 保留），回到「未 start」，可重新 `start()`。
- 顯示失敗（如 `speaker` 未載入）與腳本執行推進是**兩個獨立的失敗面**：腳本位置已前進到
  找到的那句台詞之後，但回傳 `Invalid`（未真正顯示）——這點在標頭明確記載為既有取捨（與
  E8-03 `PresentationSink` 「不吞失敗、忠實回報」同一精神：腳本本身沒有錯，是下游顯示失敗）。
- 腳本執行期錯誤（`ScriptError`）與「腳本自然跑完」（`Finished`）皆設 `finished_ = true`
  （對話本自身的「已終止」旗標）——錯誤後不會被后續 `advance()` 誤判為仍可推進而靜默地回
  `Finished`；呼叫端須 `reset()` 才能重新開始 / 推進。
